Deferred lighting and reflections

The DXBC blob at 1165260 (rendering.mdunderground-shader) is one of three variants of the deferred-lighting c…

Evidence: static · Build: steam-5d11de53 · Fact ID: deferred-lighting-cs

The DXBC blob at 1165260 (rendering.md#underground-shader) is one of three variants of the deferred-lighting compute shader, the pass that turns the G-buffer into the lit picture: the variant with sun shadows is 116E780 (0x39EC bytes), the other shadowless one 1172170 (0x3374 bytes); all three are created in 5D6BD0 (lea at 5D8185, 5D8165, 5D8145). Environment reflections are applied here, per pixel, from a grid of local cubemaps (RTTI LocalCubeMap@ren@xgl). Bindings: all write uav0:g_color_out; inputs t0 g_albedoRGB, t1 g_specularRGB, t2 g_normalXYZ, t3 g_smooth_reflection_specpow, t4 g_metallic_roughness, t5 g_viewXYZ_id, t6 g_light_accumulate, t7 g_specular_accumulate, t8 g_local_cubemap_array (TextureCubeArray), t9 g_ambient_occlusion, sbuf10 g_local_cubemap_grid, point-light arrays and masks (sbuf11-14), t15 g_shadow_depth (only 116E780); cbuffers xgl_system (b0), xgl_additional_light_setting (b2), LocalCubemapWorldAABB (b10: g_min_point, g_unit_size, g_cubemap_grid_divide_count, debug flags g_debug_is_used_local_cubemap, g_debug_preview_env). Other blobs created in the same function: 1164AB0 (5D828C), 1168610 (5D80AE), 116A0B0 (5D77DE). That DarkUnderground's blob is the variant used underground is inferred, not traced.

Basis: RDEF (resource bindings) of all 260 DXBC blobs read with a small reflection script, and a scan of the code for RIP-relative lea/mov targets in 1130000-1180000; not run in game

Addresses (build-specific RVAs unless indicated): 1165260, 116E780, 1172170, 5D6BD0, 5D8145, 5D8165, 5D8185, 1164AB0, 5D828C, 1168610, 5D80AE, 116A0B0, 5D77DE

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-material-base-color-output

In EDF5's SND_MECH.SGO and SND_CHARA_2COLORCHANGE.SGO Deferred pixel shaders the base color output is o0.rgb = b (albedo x diffuse, unchanged by the reflect term), with o0..o5 written (6 targets); EDF6's same-named shaders lift it toward white (crosswalk/deferred-lighting-reflections.md). EDF5-era gold paint relies on this reflect look: the EDF5 gold paint color is (66, 48, 0).

Evidence: static · Build: steam-5d11de53 · Fact ID: dormant-ssr-shaders

EDF5.exe carries a complete screen-space-reflection (SSR) compute-shader set that no code references: a Hi-Z ray march with local-cubemap fallback (115AF80, 0x104C bytes, and 115BFD0, 0x1F14), a resolve (115AA80), two SSR blurs (115FFA0, 1161630), a reflection-over-color composite (11562F0) and a cubemap-array pass (11567D0); so SSR was most likely cut, not hidden behind a setting. The water (SND_MAP_WATER_TRANSPARENT.SGO) and glass-object (SND_MAP_OBJECT_GLASS.SGO) shaders are forward sha…

Evidence: static · Build: steam-5d11de53 · Fact ID: water-glass-forward

The water (SND_MAP_WATER_TRANSPARENT.SGO) and glass-object (SND_MAP_OBJECT_GLASS.SGO) shaders are forward shaders (techniques Forward* and ZPass*, one color target), drawn after the deferred-lighting pass; they take reflections from the single global cubemap g_xgl_environment_map, not from the local cubemap grid, so a change to the deferred-lighting shader cannot reach them. Water PS: three scrolling normal maps, three parallax maps, bubble_albedo, t9 g_xgl_environment_map (TextureCube), t10 g_xgl_viewXYZ_id_texture (scene view positions, so it can read the depth behind it), t11 g_xgl_shadow_depth, point lights; xgl_user_param (176 bytes) includes water_color @16, specular_color @32, specular_pow @44, environment_reflection @48, blend_depth @156, metallic @160, roughness @164. Glass PS: albedo, normal, param_reflect_XXX_spec_hspec, t5 g_xgl_environment_map, shadow depth, point lights; xgl_user_param (96 bytes) with metallic @64, roughness @68 and translucent_fall_off_* @84-92. Neither binds a scene-color texture, so screen-space reflections in them need extra input bound by code.

Basis: both SGOs' DXBC RDEF and technique names read with a small script; not run in game

Evidence: static · Build: steam-5d11de53 · Fact ID: window-interior-mapping

Building windows use SND_MAP_BUILD_WINDOW.SGO, an interior-mapping G-buffer shader (a 2D interior_texture drawn behind the glass with a view-dependent offset, varied per instance) that samples no cubemap itself; any reflection on the glass comes later from the deferred-lighting pass's local cubemaps, driven by the material's metallic and roughness. G-buffer PS (6 targets; plain and instanced with INSTANCING_interior_random_seed): t2 window_frame_texture, t3 interior_texture, t4 normal, t5 window_normal, t6 param_reflect_XXX_spec_hspec, all Texture2D; xgl_user_param (80 bytes): normal_amount @4, window_normal_amount @16, window_normal_uv_scale @24, specular_pow @32, specular_color @36, light_smooth @48, metallic @52, roughness @56, fall_off_amount @60, fall_off_scale @64, fall_off_offset @68, interior_wrap_count @72, interior_random_seed @76; techniques Deferred, Deferred_Instancing, Deferred_Skinning1, ZPass*. Other reflective-looking families in DX11.cpk: SND_MAP_OBJECT_GLASS, SND_MAP_WATER_TRANSPARENT, SND_MAP_LOD / _NOENV pairs. Which on-screen layer of a window (the interior picture or the cubemap) shows the city image is not settled.

Basis: the SGO's DXBC RDEF read with a small script; not compared in game; the window geometry: #window-glass-geometry

The deferred-lighting compute shader runs once per main view in 5DCAE0 (single call site 62C4D0, inside Comma…

Evidence: static · Build: steam-5d11de53 · Fact ID: deferred-lighting-dispatch

The deferred-lighting compute shader runs once per main view in 5DCAE0 (single call site 62C4D0, inside Commander command 1, models.md#umbra-commander-command): Dispatch(ceil(W/16), ceil(H/16), 1) at 5DD2FC / 5DD397 with UAV0 = scene color [[1259680]+0x638]+0x18. Variant choice: 1165260 when params byte [p+0x150] is set (scene [cmd+0x170] == 1, 62C3E6; "underground" is inferred), else 116E780 (sun shadows, t15 = [R+0x850]) when [p+0x20] and [p+0x21] are set, else 1172170. Shader objects in R = [1259680] (#renderer-object-r): R+0xA98 (1172170), R+0xAB8 (116E780), R+0xAD8 (1165260); ID3D11ComputeShader at object +0x10; created by 5F5E50; all numthreads(16,16,1). SRVs t0..t7 the G-buffer ([[R+0x6C0+0x30*k]+0x10]), t8 g_local_cubemap_array ([[R+0x610]+0x18]+0x10, or [R+0x5B0]+0x10), t9 AO, t10 grid buffer, t11..t14 light buffers, t15 shadow depth (shadow variant); CB slot 0 [R+0xB40], slot 2 [R+0xB68], slot 10 [[R+0x610]+0x78]. Between this dispatch and forward phase 2 the frame has no CopyResource / CopySubresourceRegion / resolve (none in 62BE00..62D600; the copy sites 5C5634, 5C56E7 belong to a texture loader), so no scene-color copy exists for distortion or refraction. Hook points for a screen-space pass: just after call 5DCAE0 at 62C4D0 (lit image in scene color, G-buffer and depth valid, CS state unbound), or the 5DB970 call at 62CC89 (last point before phase 2; scene color becomes the bound RTV there).

EDF5 has no water object class (the strings WATER and Water do not occur in the exe) and no wet, puddle or ra…

Evidence: static · Build: steam-5d11de53 · Fact ID: water-no-class-no-wet-shader

EDF5 has no water object class (the strings WATER and Water do not occur in the exe) and no wet, puddle or rain shader: water is the forward-only map material SND_MAP_WATER_TRANSPARENT (drawn in phase 2 by its technique, likely), and ground (snd_map_field_basic, _parallax) is G-buffer only (techniques Deferred and ZPass, 6 targets; params light_smooth, specular_pow, specular_color, texture param_XXX_XXX_spec_hspec), so any puddle shine is painted material lit with the static cubemaps. The water PS reads t0..t11 (three normal maps, three parallax maps, bubble albedo, t9 env, t10 g_xgl_viewXYZ_id_texture, t11 shadow depth); t12..t15 are structured buffers (#free-srv-slots-t16). Its t10 is a shared parameter set by the pass setup (#renderer-object-r), so a texture a replaced water PS adds must be bound by a plugin, and survives only if re-bound after the engine's SRV wipe (rendering.md#srv-wipe-before-water). EDF6 model shaders not checked.

Basis: string search of the exe; names of the 89 SGOs in DX11.cpk; shaderscan of snd_map_field_basic.sgo; novae (ajane); confirms #water-glass-forward

The water pixel shader (SND_MAP_WATER_TRANSPARENT.SGO, forward) mixes a constant share of the global-cubemap…

Evidence: static · Build: steam-5d11de53 · Fact ID: water-ps-math

The water pixel shader (SND_MAP_WATER_TRANSPARENT.SGO, forward) mixes a constant share of the global-cubemap reflection with no Fresnel term, and its alpha comes from the depth of the opaque scene behind it: color = lerp(albedo x diffuse, env x lerp(1, albedo, metallic), environment_reflection x (1 - bubble)) + specular x specular_color, then fog; alpha = water_color.w x sqrt(min(|t10.z - view z| / (1 - 0.75 (1 - N.V)), 1)) x near fade x FOG_FADE.y. The SGO holds the forward PS twice (@290 and @4500, byte-identical, 17004 bytes), referenced by 3 type-4 nodes (Forward, Forward_Instancing, Forward_Skinning1); ZPass PS are 464-byte constant shaders. VS outputs: EYE_VECTOR = world - camera (#water-vs-eye-vector), VIEW_POSITION = mul(world, g_xgl_view), FOG_FADE = (d x fog.x + fog.y scaled by g_xgl_fog_color.w, 1 - (d x fog.z + fog.w), 1) with d = |EYE_VECTOR| and fog = g_xgl_fog_fade_param; NORMAL/BINORMAL/TANGENT world space; TEXCOORD0..2 = uv x normalN_uv_scale + time-scrolled offset. PS: normal maps decoded as ((x*a, y) - 0.5) x 2, z rebuilt, xy scaled by normalN_amount, the three layers summed in tangent space (x along TANGENT, y along BINORMAL); parallax shifts the UVs by the summed heights x (E.T, -E.B) x uv scale; R = reflect(E, N) samples g_xgl_environment_map at LOD = mip count x roughness; four directional lights (light 0 shadowed by two cascades from xgl_additional_light_setting, 2x2 manual PCF) plus clustered point lights (128x128 screen cells x 128 depth slices, masks in t13..t15). Material defaults (RDEF): water_color (0.376, 0.384, 0.937, 1), environment_reflection 0.45, specular_pow 100, roughness 0, metallic 0.

Basis: D3DDisassemble of the PS blob (308 instruction slots, compiler 6.3.9600) and the plain VS @C720, read line by line; an HLSL transcription compiled with D3DCompiler_47 reproduces the signatures, cbuffer layouts and defaults exactly and renders like the original on WARP (65,536 random-input pixels per test, worst difference 5.4e-4 relative; 22 deliberately wrong constants all detected); the transcription also runs on WARP with two extra textures declared but removed from its RDEF (the engine's D3DReflect then lists exactly the original bindings); novae (ajane); confirms #water-glass-forward

In the water vertex shader (VS at file offset 0x8B10 of SND_MAP_WATER_TRANSPARENT.SGO), EYE_VECTOR (o1) is th…

Evidence: static · Build: steam-5d11de53 · Fact ID: water-vs-eye-vector

In the water vertex shader (VS at file offset 0x8B10 of SND_MAP_WATER_TRANSPARENT.SGO), EYE_VECTOR (o1) is the unnormalized world-space vector from the camera to the vertex (world position minus cb0[4..6].w, the camera position from g_xgl_view_inverse), VIEW_POSITION (o2) the view-space position (dp4 with g_xgl_view registers 0..2), and normal, binormal and tangent are rotated into world space by the per-instance transform (structured buffers t0, stride 32, and t1, stride 64; instance index = SV_InstanceID x cb2[0].x + v1.x - 1, map-objects.md#map-instanced-draw). So the PS's reflect(EYE_VECTOR, N) is the outgoing world-space reflection direction and dot(-EYE_VECTOR, N) is N.V.

Basis: novae (ajane); not run in game; confirms #water-glass-forward

In city maps, building window glass (snd_Map_Build_Window material, window-interior-mapping) sits in building…

Evidence: static · Build: steam-5d11de53 · Fact ID: window-glass-geometry

In city maps, building window glass (snd_Map_Build_Window material, #window-interior-mapping) sits in building-module models (sk_bd<size>_<1f0N|a01..|topNN>, plus ym_/yy_ variants, _hk and _lod copies), one window mesh per module, in which every window is a separate axis-aligned flat quad (4 vertices, 2 triangles, about 2.4 x 0.9 m); a mesh spans 2 to 26 distinct planes (most often 4 or 6), and its dominant plane holds a median of about 17 m^2 of glass (max 121). A facade is many stacked modules, so a whole-facade plane needs the module world placements (probably .mosb groups, not located) or the world matrix of the window draw at run time (map-objects.md#map-instanced-draw).

Evidence: static · Build: steam-5d11de53 · Fact ID: renderer-object-r

The render targets and per-frame shader constants live in one global renderer object R = [1259680] (created around 5D6BD0): xgl_system CPU copy at R+0x10 (0x240 bytes: +0x10 view, +0x50 view_inverse, +0x90 projection, +0xD0 view_projection, +0x110 vp_inverse, +0x150 target dimension (uint2), +0x158 time, +0x15C id; matches #xgl-system-cbuffer-layout; flushed to the ring cbuffer by 5D8B90; 5D9700 derives the inverses and view-projection; written per view by rendering.md#camera-writer), scene color R+0x638, depth R+0x668, the 8 G-buffer targets at R+0x6C0 + 0x30*k (k = 0..7), renderer mode R+0xFF8; targets are fixed per mode by setter functions, not passed per call. G-buffer set descriptor at R+0x6A8: 8 entries of 0x30, the target object at entry+0x18; entry 5 (R+0x798) is the view-position/id target; lighting binds them as t0..t7 (albedo, specular, normal, smooth_reflection_specpow, metallic_roughness, viewXYZ_id, light_accumulate, specular_accumulate). Shader textures are bound one slot at a time through FB8F0(ctx, stage, slot, count, srvs) (stages 0 VS, 1 HS,…

Evidence: static · Build: steam-5d11de53 · Fact ID: srv-binding-cache

Shader textures are bound one slot at a time through FB8F0(ctx, stage, slot, count, srvs) (stages 0 VS, 1 HS, 2 DS, 3 GS, 4 PS, 5 CS) with a per-slot cache at ctx+0xF10+(stage*128+slot)*8 (repeat binds skipped; with count != 1 it skips the cache test and calls D3D directly, PS at FBA3A = vtable +0x40); materials only ever bind count 1, and a reflected texture with no material value is skipped (nothing bound, not even NULL: 5CD91C, je 5CDA70 in 5CD390). All slots are wiped only by the state reset 5EF5C0 with flag bit 8 (all 128 slots of stages 0..5, loop 5EF740..5EF765; the call FB8F0 at 5EF75B is the only other caller), effect in game: rendering.md#srv-wipe-before-water. Material bind 5CDE30: nulls the cached VS/HS/DS/GS/PS (ctx+0x938..0x958), then runs the pass's apply objects (local classes of Material::internal_RecordApplyPass, 5CD390..5CDC87; BufferApply_Textures vtable EDE170, slot 1 5CDD40 -> 5CD150). Model draw 102920 -> 5B2900 -> 5B3120 (material bind, then DrawIndexedInstanced). 5EF5C0 bit-8 callers in Commander command 1: 62BF08, 62C177, 62C22B, 62C35F (all before lighting) and 5DBCD0 (5DBD1E, end of command 1); others 5E2F85, 107C12, 1084C4, 1A0D06. Between lighting and phase 2, 5DB970, 62B790 (nulls shaders only), 626480 and 62D7B0 do not wipe SRVs; the post-effect listeners (vtable +0x48, +0x50), the block 62C4D5..62CA94 and 5DA370 were not read. Other context-cache fields: RTV/DSV ctx+0x5A8..0x630, UAV ctx+0x638, rasterizer mode ctx+0x1A0. A replaced pixel shader may declare an extra texture the engine does not know (it is ignored; no crash path seen).

Basis: novae (ajane); not run in game. The finding's conclusion that a raw bind at 626480 survives to the water draw failed in game (rendering.md#srv-wipe-before-water)

Draw-utility render state: +0xFA8 dirty bits, +0xFB0 depth write, +0xFB4 blend (init 1 = SRC_ALPHA / INV_SRC_…

Evidence: static · Build: steam-5d11de53 · Fact ID: draw-utility-technique-by-mode

Draw-utility render state: +0xFA8 dirty bits, +0xFB0 depth write, +0xFB4 blend (init 1 = SRC_ALPHA / INV_SRC_ALPHA), +0xFB8 cull, +0xFBC technique. The draw's state check (5ECB29..5ECB4E) copies the renderer mode [[util+0x10]+0xFF8] into util+0x20 and sets dirty bit 0x40 when it changed; on that bit the flush 5EC340 (5EC365..5EC395) maps util+0x20 to the technique: mode 1 -> 0, modes 2 and 3 -> 2, any other -> 1. The setters fix what each mode binds (#renderer-object-r, models.md#umbra-commander-command): mode 1 5DB530 depth only (R+0x668), mode 2 5DB5C0 the 8 G-buffer targets + depth, mode 3 5DB6F0 the same minus entry 5 ([r11-0x30] = 0 at 5DB77A) with the viewXYZ_id target R+0x798 bound as a texture through B1CF0 (5DB7B9), mode 4 5DB7E0 light accumulation (2 targets, blend set), mode 6 5DB970 scene color + depth, mode 0 the reset 5DBCD0 (5DBD23). So technique 0 is the depth-only pass (phase 0, the depth pre-pass: models.md#render-phase-0-depth-prepass), 2 the G-buffer write (mode 2 for phase 1; mode 3, set at 62C19B right before phase 4 62C1DE, for draws that read the view position while writing the G-buffer), and 1 forward (mode 6, phase 2). The earlier labels "mode 1 G-buffer, 2/3 shadow" were wrong; the mapping itself stands.

Basis: 5EC340, 5ECB20, the five setters and their callers in 62BE00 re-read with fn.py (the callers by a scan of 5C0000..640000); settles the conflict with #renderer-mode-numbers-doubt

Evidence: static · Build: steam-5d11de53 · Fact ID: shaders-sgo-layout

DX11.cpk has 89 .SGO files under SHADER/DX11/ (Sandlot SGO containers; nodes are (type u32, size u32, offset u32 relative to the node), type 4 = a DXBC blob). A screen-door (dither) see-through in the model shaders only shows what is behind if the depth/shadow pixel s…

Evidence: verified · Build: steam-5d11de53 · Fact ID: dither-depth-pass-and-cell-size

A screen-door (dither) see-through in the model shaders only shows what is behind if the depth/shadow pixel shader of the same effect is dithered too; otherwise the depth pre-pass (models.md#render-phase-0-depth-prepass) stamps the whole silhouette and only the sky (drawn into empty depth) shows through the holes. The fix gives the depth PS an SV_POSITION input (its VS outputs exactly that), the file's cb2 declaration and RDEF, then the prologue; alpha-clip depth shaders (CLIP families) already have SV_POSITION and cb2. 4x4-pixel screen-fixed cells survive frame generation far better than 1x1 (Lossless Scaling: 1x1 bad, 2x2 better, 4x4 the sweet spot); cells anchored on the surface (TEXCOORD0 x 64) come out very uneven.

Evidence: static · Build: steam-5d11de53 · Fact ID: shaders-material-cbuffer-storage

Material cbuffers: material instance +0x38 = array of per-cbuffer storage objects (0x58 bytes: +0x30 data, +0x40 size, +0x48 dirty, +0x50 name), created in 5CBB50 from the effect's cbuffer table (effect +0xD8, 0x40 per entry, count +0xE8; type 0 = per-instance storage, 1 = shared, 2 = none; +0x20 init data, +0x30 size). Pack v01 (+16 bytes) had the same mismatch, probably hidden by allocator slack.

At a glance

What this page answers: This is the short current-decision layer for conflicting EDF research, supported by a separate machine-readable conflict register.

How to read it: Use each row's build, evidence class and supersession status before accepting a newer claim over an older one.

Evidence boundary: Only a high-risk subset is reconciled here. The 2,572 Knowledge Hub facts have source parity but were not all independently authenticated in-game.

This page lists current scoped decisions when independently collected EDF 4.1/5/6 research appears to disagree. It is a reader-friendly companion to the machine-readable CONFLICTS_AND_SUPERSEDED.json. Every row distinguishes exact-build evidence from mod observations and unresolved hypotheses. Reconciliation means the claims were compared by scope, not that all 2,572 contributed assertions were independently repeated.

Evidence classes

  • Exact native binary / demonstrated source route: strongest for that exact binary/build, but not a universal runtime claim.
  • Contributor verified: means the contributor reported a game test in a named build. This project did not re-run that test.
  • Contributor static: an observation from source, disassembly or documentation, potentially strong for a local data structure, but not new game-runtime proof.
  • Contributor unverified: an idea, inferred mechanism or reported pattern requiring further corroboration; do not use as a conversion implementation rule.
  • Historical/superseded: retain the older source and reason for replacement, but do not print both claims as equally current.

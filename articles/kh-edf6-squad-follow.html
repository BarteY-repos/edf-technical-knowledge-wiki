EDF 6 — Squad Follow (community source notes)

EDF 6Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Where a follower goes

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-spot

The follow state (soldier slot 90 590280, update phase 1) moves to a spot and looks at a second point: it drops to the guard state (slot 89, through the thunk 58EE94) when the soldier has no leader +0x548 or +0x380 bit 26 (ChaseLeader) is clear, asks for the engage state (58EEA0, slot 91) while the weak target +0x1CD8 lives, and calls MoveAndLook 5A2B50(soldier, 1.0, 1.0, 0.05, &anchor +0x1C40, &offset +0x1C70, &look) at 590562. 5A2B50 adds the offset to the anchor (5A2BF7) and hands that point to the path controller [soldier+0x850] (E65A0 at 5A2C6E): the move target is anchor + offset. The look point is anchor + +0x1C90 (x, z; y = the soldier's own y + +0x1C94), 1.0 = 1C36994, 0.05 = 1765A04.

Basis: fn.py reads of 590280 and the head of 5A2B50 (its stack arguments 5 to 7 at rbp+0x80 / +0x88 / +0x90)

Addresses (build-specific RVAs unless indicated): 590280, 58EE94, 58EEA0, 5A2B50, 590562, 5A2BF7, E65A0, 5A2C6E, 1C36994, 1765A04

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-anchor

The anchor +0x1C40 is written by Think 596B50 only while the soldier has a leader and ChaseLeader is set: the leader's position +0x90 (596D1B), after walking up the chain past dead leaders that have auto-revive (+0x2E8 != 0 and +0x380 bit 17, loop 596CF0); +0x1D38 = whether that leader has a route. A soldier with its own route point (+0x4A8 set and +0x4D0 valid) instead takes the route point +0x4C0 as anchor with both offsets zeroed and +0x1C50 = 420 (597431..59746D). Otherwise the anchor is left as it was. Think also keeps the leader's last position at +0x1C20 and its per-frame step, negated, at +0x1C30 (596D9B..596DED).

Basis: fn.py read of 596B50

Addresses (build-specific RVAs unless indicated): 596B50, 596D1B, 596CF0, 597431, 59746D, 596D9B, 596DED

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-path-params

The path controller's parameters set by Think each frame ([soldier+0x850], meaning not read): with a chasing leader +0x78 / +0x7C / +0x80 = 1.4 / 1.0 / 1.1 when the squad's root has +0x1A bit 3 (an AI root), else 1.0 / 1.0 / 1.0, and +0x88 = 5.0 (596C4D..596CB2); without one 4.0 / 1.0 / 1.1 and +0x88 = 10.0 (596DF9..596E2D); +0x84 = [[soldier+0x1298]+8] or 0 in both.

Basis: fn.py read of 596B50

The offset: picked at random, in world space

Joining: SetFollow 54EC50(self, leader, keepOffset) unlinks, links (+0x548, the leader's list +0x550), calls…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-join-offset

Joining: SetFollow 54EC50(self, leader, keepOffset) unlinks, links (+0x548, the leader's list +0x550), calls slot 24 598E10(self, leader, keepOffset) and, when ChaseLeader is set, clears +0x380 bit 15 (FixAiPosition) and cancels the route (5478C0). 598E10 sets the base offset +0x1C60 = self minus leader with y = 0 (the spot where the soldier stood) and +0x1D39 = 0; without keepOffset it sets the re-pick timer +0x1C50 = 300 + rand(900) frames; with it, it clamps the offset to at most the leader's slot 19 value (23F4E0) and copies it to +0x1C70.

Basis: fn.py reads of 54EC50 and 598E10 (the slot from the vtables' pointer at +0xC0, --xref 598E10)

Addresses (build-specific RVAs unless indicated): 54EC50, 598E10, 5478C0, 23F4E0

Attribution: KH chat 165 · 2026-11-14

Re-picking: Think counts +0x1C50 down and at 0 calls 5A32F0(self, 0, 0) (5971B3), which sets +0x1C50 = 900 +…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-offset-pick

Re-picking: Think counts +0x1C50 down and at 0 calls 5A32F0(self, 0, 0) (5971B3), which sets +0x1C50 = 900 + rand(900) frames (15 to 30 s at 60 fps), +0x1D39 = 1, and +0x1C60 = a random direction (4EB60: any direction around (0, 1, 0), half-angle π, constants 1C36A80, 1C369C0) with y = 0, scaled (4D940, set length) to +0x1D2C + u x (+0x1D30 - +0x1D2C), u in [0, 1); the soldier setup writes 3.0 and 10.0 there (596AF6, 596B00). With FixAiPosition (+0x380 bit 15, or the call's own arguments) the offset is zero. Online (7748F0) the draw comes from a seed kept at +0x1E50 and the host side sends 59BE00(self, kind 1) (a sync, inferred). The leader's facing is used nowhere: the offset is a world-space vector.

Basis: fn.py reads of 5A32F0, 4EB60, 4D940 and the Think loop; constants with the scratch flt.py

Addresses (build-specific RVAs unless indicated): 5A32F0, 5971B3, 4EB60, 1C36A80, 1C369C0, 4D940, 596AF6, 596B00, 7748F0, 59BE00

Attribution: KH chat 165 · 2026-11-14

Each frame Think turns the base offset into the used one: +0x1C70 = +0x1C60 x s / +0x1D30 once +0x1D39 is set…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-offset-scale

Each frame Think turns the base offset into the used one: +0x1C70 = +0x1C60 x s / +0x1D30 once +0x1D39 is set (s = the soldier's slot 20, 572770), else a plain copy (5971B8..597265); then, when the leader's slot 19 (5727B0) gives r and the offset is shorter than r (and not zero), it is lengthened to r (597275..5972F8). Slots 19 and 20 forward to the vehicle the soldier rides (56DB20, vtable +0x98), else slot 19 = +0x560 (54A510) and slot 20 = 54A4B0: for an object with +0x1A bit 3, max(slot 19, +0x568 if >= 0, else +0x56C if >= 0), else +0x564. So a leader in a vehicle keeps its followers at least the vehicle's slot-19 distance away.

Basis: fn.py reads; the slots from AssultSoldier's vtable 17CDF28 (+0x98, +0xA0)

Addresses (build-specific RVAs unless indicated): 572770, 5971B8, 597265, 5727B0, 597275, 5972F8, 56DB20, 54A510, 54A4B0

The scale fields: the GameObject setup 545670 writes +0x560 = 0, +0x564 = 10.0, +0x568 = +0x56C = -1 (545C60.…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-formation-radius

The scale fields: the GameObject setup 545670 writes +0x560 = 0, +0x564 = 10.0, +0x568 = +0x56C = -1 (545C60..545C7B), then reads game_object_formation (key 17CD778) into +0x560 / +0x564 (54634E, 546412); no friendly SGO has the key (Colonist frogs and greys carry [10, 100]), so a soldier's s is 10 and the offset stays 3 to 10 m. The script's SetAiFormationRadius(float) (1C1970, both the object and group forms) and a BVM handler (212233, 226CE6) write +0x56C; the base AI 54A000 sets +0x568 = the route's +0x24, or -1, and copies +0x568 / +0x56C from the leader (54A1D7..54A214). A formation radius R thus scales the spread to 0.3 R .. R.

Basis: fn.py reads, --str 17CD778 and 1798EE8 (the native's declaration), --writes search for +0x560..+0x56C; SGO values with obj_keys.py

Addresses (build-specific RVAs unless indicated): 545670, 545C60, 545C7B, 17CD778, 54634E, 546412, 1C1970, 212233, 226CE6, 54A000, 54A1D7, 54A214

The look offset +0x1C90 is re-picked by 5A3180 when the timer +0x1C80 runs out (Think 5972FF..59732A, after 5…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-look-point

The look offset +0x1C90 is re-picked by 5A3180 when the timer +0x1C80 runs out (Think 5972FF..59732A, after 59BE00(self, kind 2)): timer = 150 + rand(450) frames; offset = a random direction x 10 (1765C50) + the used offset normalized x 3.5 (17A0F38), set to length 10 (1765A44), y = abs(y) x 0.1. While it points away from the follow offset (dot < 0) the timer runs three times as fast (597358). In the follow state, when the soldier's horizontal speed (+0x11E0) is at least +0x1478 and the look point lies behind its way to the spot, the look point is mirrored forward (L - 2(L.d)d, d the unnormalized way, 17A3040 = 2; 590456..590534).

Basis: fn.py reads; constants with flt.py

Addresses (build-specific RVAs unless indicated): 5A3180, 5972FF, 59732A, 59BE00, 1765C50, 17A0F38, 1765A44, 597358, 17A3040, 590456, 590534

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-move-chatter

A follow-state voice line: when the leader's per-frame step +0x1C30 (x, z) is over 0.08 m a frame (squared, 0.0064 at 17D0ECC) for 90 frames in a row (+0x1D0C) and the cooldown +0x1D08 is 0, the soldier sets the cooldown to 300 + rand(600) and, if 549C60 allows, plays the talk entry at 17D2DD8 through 5DC4A0 (5905C4..590681); the state then ends in 59DAC0 (idle radio chatter).

Basis: fn.py read of 590280

Why followers run in front of a player standing still: the spot is the player's position plus an offset in a…

Evidence: unverified · Build: steam-678ccb46 · Fact ID: edf6-follow-ahead-cause

Why followers run in front of a player standing still: the spot is the player's position plus an offset in a random world direction, 3 to 10 m, re-drawn every 15 to 30 s and never turned with the player's facing (#edf6-follow-offset-pick), so about half the spots lie ahead of the player, and each re-draw sends the soldier across to a new side; the look point is likewise random around the player. The cause is inferred from the code; novae (ajane)'s sighting (the 00v request) is the in-game symptom.

Basis: reasoning over the lines above

Orders: none from the player

The player cannot order a squad: the only callers of Unfollow 54DD40 are its script native (1C4030), the obje…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-no-player-orders

The player cannot order a squad: the only callers of Unfollow 54DD40 are its script native (1C4030), the object-delete paths (547470, 54A290) and SetFollow itself; ReleaseAllFollowers 54DC60 is called only at death (479640) and deletion. The player's one act is recruiting by walking near (#squad-tree-recruit-cover, soldiers with +0x540 set). Scripts have SetAiFollow, SetAiAutoFollow (+0x540), Unfollow, SetAiChaseLeader, SetAiFormationRadius, Followers, Factor_AiFollow (declarations at 1797FC8..179AD38).

Basis: fn.py --xref of the three natives; the declarations found by a string scan of EDF.dll

Addresses (build-specific RVAs unless indicated): 54DD40, 1C4030, 547470, 54A290, 54DC60, 479640

A stay state exists in all but name: SetAiChaseLeader(bool) (native 1C1740) calls 54E700(obj, on), which sets…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-follow-chaseleader-stay

A stay state exists in all but name: SetAiChaseLeader(bool) (native 1C1740) calls 54E700(obj, on), which sets or clears +0x380 bit 26 and, on set with a leader, also clears FixAiPosition and cancels the route (5478C0); it sends nothing online. With the bit clear the follow state drops to guard (slot 89 590710), which keeps the squad link and the HUD bar but moves to anchor + +0x1C70 and looks at anchor + +0x1C90 with the anchor no longer updated, i.e. around where the leader stood when the bit dropped; engage still runs on targets; setting the bit sends guard back to follow (thunk 565FE0).

Basis: fn.py reads of 1C1740, 54E700, 590710

Addresses (build-specific RVAs unless indicated): 1C1740, 54E700, 5478C0, 590710, 565FE0

Route and open questions

Route for a follower mod (untested): (a) formation behind the player: rotate the offset into the leader's fra…

Evidence: unverified · Build: steam-678ccb46 · Fact ID: edf6-follow-route

Route for a follower mod (untested): (a) formation behind the player: rotate the offset into the leader's frame where Think forms +0x1C70 (597255 / 59725E; leader yaw +0x1244), or limit 5A32F0's draw to the rear half; keep hysteresis so a turn does not send everyone running. (b) Stay / follow hotkey: walk the player's +0x550 list and call 54E700(member, 0 / 1); add FixAiPosition (bit 15) for "stand exactly here", since re-picks then give a zero offset. (c) Dismiss: Unfollow 54DD40 (then +0x540 = 0: walking near will not re-recruit; 54EC50 does). (d) Online: the AI runs on its owner's machine and 54E700 is local, so a guest's order needs a message like slot 39's (59C3D0). Open: +0x1478, +0x850's fields, 59BE00's kinds 1 / 2 / 8, the keepOffset callers.

Basis: summary of this file

Addresses (build-specific RVAs unless indicated): 597255, 59725E, 5A32F0, 54E700, 54DD40, 54EC50, 59C3D0, 59BE00

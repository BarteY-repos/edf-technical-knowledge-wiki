EDF5 allied SoldierBase AI: guard, follow, engage and squad tree

EDF 5Game technical referencesAllied NPC AI
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5 allied soldiers execute StateMachine::Agent<SoldierBase>. The state-machine's active state and elapsed counters live in the soldier object. Its three primary state virtual functions correspond to guard, follow and engage; each receives an entry/update/exit phase.

State Native behaviour described by source
Guard Return toward the stored home point, with a formation offset; switch to follow after assigning a leader
Follow Move toward the leader's position plus a per-soldier offset; return to guard if the leader disappears
Engage Choose and act on a live target; return to follow when target reference becomes null

These states interact with a leader/follower tree. The leader pointer is SoldierBase+0x3A0, a linked-list head of followers is +0x3A8, the count is +0x3B0, and +0x398 is the may-recruit flag. Calling native SetFollow first detaches a soldier from its old leader's list, attaches it to the new leader, updates its formation offset and releases its active route explorer. Changing only the leader pointer would not reproduce this transition.

The native online follow message identifiers are 0xB for host and 0xC for guest in this EDF5 code path; the source contrasts EDF6's corresponding 12 / 13. A network message ID is not the same as the visible NPC state ID. The source also found enemy squad script natives using the same underlying follow tree.

The result is that soldier “follow” is simultaneously a state-machine behavior, a leader-tree membership and a potential networked transition. All three have to agree to understand a recruited squad's movement.

Sources: EDF Knowledge Hub edf5/soldier-ai.md, edf5-soldier-ai-classes, edf5-soldier-ai-states, edf5-squad-tree (static native code study). Build steam-5d11de53.

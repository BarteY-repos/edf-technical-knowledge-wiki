EDF4.1 audio engine: music fade, mission radio and weighted NPC voice cues

EDF 4.1Game technical referencesAudio and dialogue
Technical reference · Source-backed static analysis with explicitly scoped contributor tests; no new R125 runtime

Music playback, scripted radio speech and nearby soldiers' conversational cues are not the same EDF4.1 subsystem. The original executable uses a SoundController for playback and a TalkManager for choosing and scheduling spoken cues. This distinction matters when a cue appears in several mission scripts or a speaker's line changes between soldiers.

Music and fade logic

SoundController::PlayBgm at build-relative 0x3E7C10 receives a narrow cue name. Its three traced callers are the debug bgm command, BVM native 300, and the menu/system AngelScript PlayBgm function. A player handle stored on the controller determines whether music is currently playing.

The cross-fade path (0x3E7C80) fades out the existing handle, releases it, starts the next cue and applies a fade-in. BVM native 302 performs this transition with a fade duration; native 301 fades out the current music without starting a replacement. The stop/cross-fade debug commands use the corresponding engine routes. These function addresses apply to the examined steam-57aab039 build, not arbitrary versions.

Why NPC talk selection varies

The TalkManager reads the speaker's talk SGO and chooses entries by weights, a bit-mask filter and a permitted numeric window. A selection can use either TalkManager's random generator or a per-call seed. A weight of zero makes that entry unselectable in the examined picker, though using this as a live data override was not tested.

An NPC stores a voice-variation index. Cue placeholders such as U001E%s are resolved to variant suffixes (e.g. A–F) for the speaker, so two soldiers can select the same logical phrase but play different recorded takes. A selected line has a frame delay; the playback path chooses spatial or unplaced output, and can send an animation message to the speaker.

Radio dialogue uses a mission native

BVM native 4000 invokes the radio-voice path rather than weighted NPC chatter. The source census found 902 calls across 147 scripts, including MusenBegin and MusenEnd once each in every script. The radio route can stop the prior cue before playing a new one. This explains why a mission's radio click and ordinary soldier remarks need different interpretation, even if both ultimately use SoundController.

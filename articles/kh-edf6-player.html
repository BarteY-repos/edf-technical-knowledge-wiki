Evidence: static · Build: steam-678ccb46 · Fact ID: remote-soldier-no-controls

A remote player's soldier on this machine has the controls pointer +0x340 = 0 and the pad index +0x338 = -1, set by the remote bind 54EDB0 (mov dword [rcx+0x338],-1; mov qword [rcx+0x340],0, then it clears +0x348 through 11C1090). The network message pre-handler 774260 calls it for message 0x20105 when its payload byte +8 != 0 (7742EB-77430D). Aim, input and state (round 23, EDF6VR source)

SoldierBase aim and input: move input +0xD50 (x, unused, z), look input +0xD60 (pitch delta, yaw delta), aim…

Evidence: static · Build: steam-678ccb46 · Fact ID: soldier-aim-fields

SoldierBase aim and input: move input +0xD50 (x, unused, z), look input +0xD60 (pitch delta, yaw delta), aim +0x1230 (pitch, yaw +0x1234), smoothed aim +0x1240 (its yaw +0x1244, the one the guard and the dash use), limits +0x1250 (pitch) / +0x1254 (yaw; negative = none), smoothing coefficient +0x1260. The input read 570650 (called at 572FFB) fills the look and move input; at 573BA8 the look input is added to the aim (w lane kept), each angle clamped by its limit, then the pitch to plus or minus pi/2 (573C37..573C5A); 5705AC stores atan2(forward.x, forward.z) as the yaw. In 572DF0 the smoothed aim follows: +0x1240 += (+0x1230 - +0x1240) * +0x1260. The soldier update 59ABB0 adds each weapon's recoil (weapon +0xF00 x soldier +0x1AAC) to both aims (59B070). The world matrix is +0x60; the body model +0x860, its skeleton +0x900.

Basis: 573BA8..573C5A decoded with fn.py (2026-11-07); the rest from the source's comments

Addresses (build-specific RVAs unless indicated): 570650, 572FFB, 573BA8, 573C37, 573C5A, 5705AC, 572DF0, 59ABB0, 59B070

The aim input path in 572DF0 in order (573B72..573F77, soldier-aim-fields): 56D350 consumes the move input +0…

Evidence: static · Build: steam-678ccb46 · Fact ID: soldier-aim-input-order

The aim input path in 572DF0 in order (573B72..573F77, #soldier-aim-fields): 56D350 consumes the move input +0xD50; an invalid look input +0xD60 (650E0) is zeroed; while +0x5D0 & 2 is clear +0x1230 += +0xD60 (573BA8; the Ranger's dash, +0x5D0 = 0x29E, has the bit, so the view does not turn then and no look input is sent, 573B9F, 59FE5F); the limits +0x1250 / +0x1254 default to -1 (none; 56ACCF, 56ACD9) and only a state at 57ADF0 sets them, so the yaw +0x1234 is never wrapped; the smoothing factor +0x1260 is 0.3 from the constructor (56AD03; a NaN resets it to 0.3; the state 578680 changes it), i.e. 30% per frame, frame-rate dependent, about 6 frames to 90% (573C9B..573D6F); then the aim matrix +0x60 = RotX(+0x1240) then RotY(+0x1244) at position +0x90 (573F1F..573F77, 4CD10); +0x5E0 is the yaw-only body matrix. 570780 divides the mouse look by the zoom +0x1D0. Since all four classes run this one function (#soldier-class-slots), a hook on the input read call (572FFB -> 570650) that writes +0xD60 afterwards covers all four, and the change is replicated like real input (netcode.md#net-player-aim-sync).

Basis: the author's static reading ("H")

Evidence: static · Build: steam-678ccb46 · Fact ID: soldier-no-controller-path

The soldier pre-update 572DF0 (slot 4 of AssultSoldier, PaleWing, HeavyArmor, Engineer and the vtables 17CFD20 / 17D1868 / 17D24D8, directly or by jmp) tests +0x354 (a player) at 572EFF, then 572F0C mov rbx,[rsi+0x340]; test rbx,rbx; je 573A4D (no controller). 573A4D is vanilla's no-controller path: unless the soldier is a remote copy (+0x1A bit 3, +0x128 bit 0) 56D300 clears its input block +0xD50.. (move, look, fire, jump, ...) and, when riding, 62C120 clears the seat's input seat+0x2C0..+0x2E9 (sticks, triggers, button bits); the control mask +0x158C follows as usual. No volatile register is live across the skip (none before the code at 572F1C reads one; from 573A4D on, rbx is not read before 573C30), so diverting 572F0C to 573A4D freezes a player and its vehicle, as All Forces' map view does. A few vehicle classes read controller bits themselves (car 673AC2: pad +0xA1 / +0x70; bike 658D6D: pad +0xE4). The script's SetPlayerControlMaskFlags (1BA620 -> 1CBB00) writes human+0x158C (default 0x7FBF; 573A8F clears inputs by bit), but only the soldier's own block: the seat input is written earlier (5730EC..573592). The game has no pause a plugin can call safely. Mouse look: the ride aim reads it at 56DCED from the controller object human+0x340, record [human+0xD40] (0xA80 each, 4 records), +0x66C x / +0x684 y, then divides by 24 (1766014) and clamps to ±16; the game pulls the cursor back to the window's center every frame (1183880: GetCursorPos / SetCursorPos, the sum at 1FEEE20, taken and cleared by 11831F0), so the cursor cannot be read by a plugin.

Basis: the author's static reading ("H"; the mouse sign "L"); All Forces patches 572F0C (16 bytes)

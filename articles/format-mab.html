MAB — animation events, locators and pointer modes

File FormatsSource-scoped referenceEDF 4.1EDF 5EDF 6
Reader-oriented technical reference · Existing research only · Version-specific profiles, where documented

At a glance

What it is: MAB carries information associated with animation events, such as timed triggers, locators and attachment or sound bindings.

Where it fits: It complements CANM motion and CAS controllers rather than replacing them. The studied MAB v15 layouts differ in how internal pointers are measured.

Important distinction: When moving MAB data between EDF generations, pointer bases and event consumers matter as much as the visible bytes.

The measured MAB v15 header

For the examined EDF4.1/EDF5/EDF6 MAB v15 (0x0F) family, the validated header is 0x24 bytes. It contains four top-level block-relative directory offsets in the +0x14 through +0x20 range.

The byte at header +0x08 controls how internal pointers are interpreted:

Observed source profile Internal pointer mode Meaning
EDF4.1 and EDF5 0x03 Relative to the containing block
Examined EDF6 0x83 Relative to the owning structure

The four top-level directory offsets remain block-relative in both of these observed profiles. Do not interpret every internal value as an absolute file offset, or blindly switch all pointers when changing a version field.

Measured record families

Record Size in the documented v15 parser
Locator-list header 0x08 bytes
Locator 0x20 bytes
Event-track header 0x10 bytes
Event key 0x10 bytes

The documented streams also include vectors, optional embedded SGO parameters and strings. Sentinels and ordinary integer fields are not pointers; treating every 32-bit word as an address would corrupt the file.

What an event track and key contain

In the measured event-track profile, a 0x10-byte track carries the first-key reference, a key-end reference, a UTF-16LE track-name reference and key count. A 0x10-byte event key is interpreted as follows:

Key offset Observed field Meaning
+0x00 Event-name string reference Name used by the event consumer
+0x04 float32 time Position on the animation/event clock
+0x08 Zero in the examined source Retain the observed value; do not assume a new use
+0x0C Embedded SGO parameter reference Optional event-specific data

These are offsets within the event-key record. They do not override the separate MAB v15 pointer-base rules above. A correct reader needs both the record structure and the proper source profile before dereferencing a field.

Scope of the observed evidence

The maintained source parser validated 1,153 EDF4.1 MABs, 1,652 EDF5 MABs and 2,487 EDF6 MABs in its bounded corpus. These counts support the documented pointer-base distinction for that family. They do not prove that every unknown MAB version uses the same header.

An earlier short description used a universal absolute-offset assumption and different proposed record names/sizes. The R193 source explicitly superseded that provisional description; it must not be revived as a competing rule.

Runtime responsibilities and dependencies

MAB can carry animation event timing, locator/muzzle attachments and audio-related event information. Successfully converting its structure does not, by itself, ensure that the target animation has matching bones, that its locators are correct or that the consuming game class understands the events. Conversely, MAB should not be presented as a universal static-collision dependency.

Example of class-specific events

The original event research records names such as se and se_stop, the DragonBig401 events 火炎開始 / 火炎終了, and UfoRobo event parameters including collision, damage, quake, scale and charge_frame. These examples demonstrate why an event's name, time and optional SGO parameter block have to be considered together. They are not a list of universally supported game-wide commands.

For the researched EDF4.1 audio-event behavior, a negative sound-channel number signifies a sound without a retained channel handle. A nonnegative channel can replace and stop its prior sound; se_stop, state exit and object destruction can also end an owned handle under the documented source behavior. These details come from class-specific research and should not be indiscriminately projected onto every EDF6 MAB consumer.

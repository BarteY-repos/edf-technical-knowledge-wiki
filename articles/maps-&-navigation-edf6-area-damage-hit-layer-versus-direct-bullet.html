EDF6 area damage versus direct hits — why identical collision bodies can ignore explosions

UniversalMaps & NavigationCollision & PhysicsEDF 4.1EDF 6
Technical reference · Source-inherited area-damage broadphase RE and historical M130 direct-vs-blast observation

The two damage paths do not necessarily see the same body

A preserved EDF4.1→EDF6 experiment showed imported UfoMother301 panels were vulnerable to normal direct bullets but ignored rockets or explosions. The panel's durability was valid, the scene objects existed, and their weak-body damage condition had already been satisfied. The root cause instead lay in collision filter layers used by the area-damage broadphase query.

The exact-build target analysis found:

  • Explosion-capable bullets deliver damage through ApplyAreaDamage, not just the ordinary direct-hit queue. The examined projectile path clears its direct-hit queue for the area-damage operation.
  • The area query uses a collision-filter configuration centered on layer 13.
  • EventAnimationObject constructor placed the panel ragdoll bodies on layer 0x11 (17).
  • Native EDF6 damageable enemy objects in the examined target, including the UfoCarrier508 donor and insects, used a body layer of 7.

The broadphase only visits bodies whose filter pair is allowed; a body excluded from its query never receives a damage message. An object can therefore be destructible by direct hits yet remain unscathed by rockets without any invulnerability switch in its health code.

The historical 2026-10-17 M130 control reported zero explosion damage across 125 enabled panels despite hundreds of blast shots, while an earlier plain-bullet control destroyed 122 of 125 panels. These numbers describe those two reported runs, not universal damage rates.

Filter-info layout and safe policy

The studied Havok group-filter number packs several concepts into a 32-bit value:

bits  0..4   : collision layer (0..31)
bits  5..9   : subsystem
bits 10..14  : don't-collide-with subsystem
bits 15..30  : system group

The active layer table consists of 32 words, with a bit for whether a query on layer a may see a body on layer b. The source HitLayer helper checks the actual filter table when available: keep the current part layer if the area query sees it; otherwise select the native hull/enemy layer only if that layer is accepted. When the table cannot be read in the studied build, the target hull layer is a bounded fallback, not a claimed universal rule for every EDF6 object.

Do not globally move every object to layer 7, and do not modify collision shape or damage invulnerability to paper over a layer mismatch. Collision grouping affects physical contacts and other subsystems, so changes must be class-scoped and validated against direct bullets, explosions, melee and player collision separately.

Practical debugging order

  1. Confirm the object and its weak collision body are instantiated, and direct-hit damage works.
  2. Identify whether the bullet applies direct damage or transitions to area damage.
  3. Inspect the broadphase query layer and the body's filter-info layer, not just the object's HP.
  4. Verify the relevant filter-table pair is enabled.
  5. Test both native and ported targets, plus physics contacts, before deciding a new body layer is safe.

Scope: retained exact-build EDF.dll analysis, source-level patch policy and historical M130 runtime observations. No new game test was run while authoring this wiki guide. This issue is separate from shield SHKT damage gating and from MAP/MAD collision mesh geometry.

Source: EDF4.1 R10 HF4 R9 components/compatibility/src/edf41_hitlayer.h, with original M130 and EDF.dll evidence documented in source comments.

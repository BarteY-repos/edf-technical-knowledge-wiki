EDF5 versus EDF6 weapon-table schemas, row identity, categories and localization

ConversionGame technical referencesWeapon resource formatsEDF 5EDF 6
Technical reference · Source-scoped static analysis; no R129 gameplay test

Weapons are not identified in saves merely by a unique text name. In both generations, the loaded WEAPON/WEAPONTABLE.SGO row order is a critical identity: the row index is the weapon ID. Corresponding WEAPONTEXT.<language>.SGO entries stay in the same order. The HQ UI may sort what it displays by category or level, but that does not change the underlying save identity.

EDF5 uses eight fields; EDF6 uses nine

Position EDF5 table EDF6 table
0 Weapon identifier / name Weapon name / identifier
1 Weapon SGO path Weapon SGO path
2 Weapon category Weapon category
3 Rarity / acquisition weight Rarity / acquisition weight
4 Stored level float Stored level float
5 Acquisition class Acquisition class
6 Star-rating specification Star-rating specification
7 Content/source pack Availability/display flag for underground/wasteland
8 — Content/source pack

The EDF5 study counted 1187 table records; the examined EDF6 table contains 1564 records. Counts are build and data-set specific. The EDF6 engine reads its table as a collection of rows, with row-name lookup case-sensitive in UTF-16. Table pointers are populated when a game mode loads its configuration; callers should not assume the table exists earlier.

Categories, starting equipment and DLC

EDF5 encodes a class/category family as approximately 100 × class + kind, with classes Ranger 0, Wing Diver 1, Fencer 2 and Air Raider 3. EDF6 category numbers are also defined by DEFAULTPACKAGE/CONFIG.SGO; the category name shown on-screen comes from a localized text-table key, not from the numeric category itself.

In the EDF6 table, acquisition value 0 means a normally rollable item, 1 starting equipment and 3 DLC-granted equipment. The source-pack code 0 identifies the main-game pool, 1 DLC1 and 2 DLC2 for normal random acquisitions. The underground/wasteland cell is a display indicator, not the whole authority for whether equipment can actually be used in a given mission.

A stored weapon level is not the screen number

For EDF5, the weapon's displayed level follows approximately floor(float32(table_level × 25)). The single-precision conversion matters: the stored 2.12f can display as level 52, not 53. A comparison with Japanese community tables matched the rule in 1178 unambiguous cases. This detail should not be replaced by a simple decimal multiplication and rounding formula.

Identity and compatibility risks

Inserting a new row in the middle shifts the IDs of all later weapons. Removing a row referenced by equipped or owned save data can cause a load or menu crash. Likewise, the game does not automatically register an arbitrary weapon SGO simply because it exists in an archive. EDF6's implementation iterates up to a hard-coded 0x800 record slots in several save routines; exceeding that bound cannot be assumed safe.

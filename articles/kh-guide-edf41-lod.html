EDF4.1 Deferred Lighting, Cubemap Reflection and Character LOD

EDF 4.1Community Knowledge HubShaders
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

EDF4.1 reflection and level-of-detail behavior cannot be inferred from EDF5/EDF6 shader labels. Its studied deferred-lighting pass uses global environment reflection and its character LOD selector has its own threshold layout.

Format, API or behavior

The source distinguishes the complete deferred-lighting compute shader from a standalone “reflection shader.” It also records set_lod_distance_scale, the AnimationModel threshold loop and a debug-only LOD viewer. These are separate from asset-independent runtime animation skipping.

Evidence and exact technical details

The following selected source observations retain their original evidence level and build-specific details. Follow their links for the complete evidence method, addresses and attribution.

Lighting cs global cubemap — static

The "reflection compute shader" at C477E0 is the whole deferred-lighting compute shader (the variant with sun shadows; shadowless variants at C4A410 and C4D0A0), and its reflections come from one global environment cubemap (g_xgl_compute_environment_map); EDF 4.1 has no local cubemaps and no screen-space reflections anywhere in the exe (no blob binds Hi-Z, intersection or SSR names). Inputs t0 g_albedoRGB, t1 g_specularRGB, t2 g_normalXYZ, t3 g_smooth_reflection_specpow, t4 g_light_accumulate, t5 g_specular_accumulate, t6 g_depth, t10 g_xgl_compute_environment_map (TextureCube), point-light arrays sbuf11-14, t15 g_shadow_depth (only C477E0); outputs uav0 g_color_out, uav1 g_view_z_out; cbuffers xgl_system (b0), xgl_ren_compute_lighting_setting (b2). A full-screen PS at file offset C505D0 also samples g_xgl_environment_map with the G-buffer.

Lod distance scale command — static

EDF 4.1 keeps a debug script command set_lod_distance_scale(string kind, float s) (registered at C25B5, handler BDD40) that writes seven load-time LoD distance scales at C3F270..C3F288 as s + (1-s)*K; all seven are 1.0 in the file image and nothing else writes them. The kind "chara" writes only C3F288, which the character model loader multiplies into each squared LoD threshold (320D28), so the distance factor is its square root. K is 0.1, 0.5, 0.4, 0.2, 0.3, 0.3 for the six other globals and 0.2 for "chara"; a data patch changes the floats at file offset C3D470..C3D488. EDF5 and EDF6 do not have this command string.

Lod character selector — static

The character LoD selector is AnimationModel (vtable AA3040) slot 0 322E40: it takes the last entry of [this+0x220] (stride 0xF0) whose threshold +0xE8 is <= [this+0x1C]; 322E8B 77 0E is the loop's ja (EDF5 equivalent: edf5/models.md#animationmodel-lod-select, 3AEFAB).

Exact source: View evidence and source details · build steam-57aab039

Lod debug viewer — static

The LODModelObject / LODCaptureCamera / LODsgmUmbraObject classes are a debug LoD viewer: their only creator C6710 is reached only from the lod_mode_set handler BCAC0. No distance-based animation skip was found. 10A360 appends _lod, _lod2, ... by LoD index; 103C80 reads the per-map FarClipZ, FogBegin and FogEnd.

Version notes and limitations

A debug console command existing in the executable does not imply the shipped game normally changes seven LOD scales. No universal distance-LOD mutation rule should be copied from these specific addresses.

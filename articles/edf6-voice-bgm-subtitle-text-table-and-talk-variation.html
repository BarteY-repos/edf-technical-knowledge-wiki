EDF6 dialogue and music: NPC cue variations, voice tables and SeManager

EDF 6Game technical referencesAudio and dialogue
Technical reference · Source-backed static analysis with explicitly scoped contributor tests; no new R125 runtime

At a glance

What this page answers: EDF6 dialogue involves three distinct layers: NPC talk SGO cue selection, CRI audio banks and localized voice-caption records.

How to read it: Use the cue and table census to understand variation, then read SeManager music control and subtitle timing as separate consumers.

Evidence boundary: File-table structure and observed timing are source-specific. They do not prove every PC/PS5 subtitle delay has the same cause.

EDF6 adds a localized mission voice-caption table on top of separate dialogue cue selection and audio playback. Three closely related objects must not be conflated: the NPC talk SGO that chooses a cue, the CRI sound bank that supplies audio, and edf6_voicetable.<locale>.sgo that supplies captions for selected scripted lines.

Soldier and alien speech selection

The surveyed EDF6 game resources include 30 talk SGO files with 2257 tables (281 empty), 16,289 entries and 8625 distinct cues. Entries are now keyed dictionaries (with fields such as #0…#12 and mask) rather than EDF5's flat 13-item lists. Cue selection still uses weighted choices and speaker masks. A per-object talk variation determines which replacement letter is inserted into wildcard cue names such as AA001B*.

The English mission edf6_voicetable contains 13,869 keys, but it principally covers scripted mission speech. Only 11 keys use the observed AI-voice families; only seven of the 8625 talk-SGO cues were found with captions in that voice table. Therefore the voice table is not a complete index of all casual NPC dialogue, and the absence of a caption is not proof that a cue is unused or silent.

Music is SeManager-owned

The surveyed SeManager stores the music handle at +0x20 and has distinct operations for ordinary play, cross-fade, play from a time offset and fade-out stop. The seek-play path converts the start offset from seconds to milliseconds. The native mission AngelScript API exposes Bgm, CrossFadeBgm, StopBgm, Bgm2 and CrossFadeBgm2.

In the decompiled mission-script set, the source counted 3277 Bgm, 1165 CrossFadeBgm and 380 StopBgm calls; the two 2 forms had no calls in that corpus. These figures do not imply that every call is executed in a single playthrough.

Subtitle timing is separate from audio playback

A Voice/internal_Voice call can play through TalkManager, but caption display depends on the queued voice group's caption key and a pending state. The subtitle builder looks up localized text by key; Object.PlaySe and some internal_Voice use cases play only audio and are not general caption requests. The game can therefore correctly produce sound with no subtitle, even if a similar cue has a mission-caption entry.

Native TalkActor countdowns and the 59.94 Hz framework gate

In the examined exact EDF6 binary, two common caption actors use integer update-call countdowns, not elapsed-time subtraction:

Actor Native update function Countdown field Initialization
TalkActor_Object 0x1805DB310 actor +0x7C caption lifetime metric × 60.0
TalkActor_Voice 0x1805DB800 actor +0x40 caption lifetime metric × 60.0

Each actor decrements its field once per actor Update call. TalkActor_Wait::Update (0x1805DBA30) likewise decrements its +0x20 integer and sets completion bit 0x2 once the previous value is nonpositive. The public script API WaitVoice has not been proven to construct this particular wait actor. Do not identify them solely by name.

The application registers its TalkManager callback into the central game-system dispatch. The recovered xgs::Framework timer uses QueryPerformanceFrequency * 100 / 5994, giving a scheduler gate of 59.94 Hz. The TalkManager callback lies outside the inner loop which processes accumulated fixed ticks. Hence a processing hitch can turn multiple missed fixed ticks into one outer TalkManager update, making the subtitle countdown run slower than wall-clock speech. Merely raising render FPS is not evidence that these actor countdowns update faster.

This is a narrow, native-binary explanation for why sound, localized text lookup, caption lifetime and visible scroll timing can diverge without any missing dialogue cue. A global CONFIG.SGO/ModeList timing control was not found in this recovered call chain, but that does not eliminate abnormal runtime hooks or resource-layout effects. The later separately qualified subtitle scroll correction adjusts presentation scheduling and is distinct from lossless VOICETABLE compatibility additions.

Evidence level: static, exact-build EDF6 EDF.dll control-flow and class-layout audit (EDF6_TALKMANAGER_CAPTION_COUNTDOWN_SCHEDULER_RE_2026-09-05.md). Build-specific absolute addresses above must not be transplanted to other binaries.

PC/PS5 English subtitle timing: separate observed and suspected causes

A control test of a native EDF6 PC mission reproduced late English-caption scrolling with the whole Mods directory disabled. That rules out mod-folder-only VOICETABLE, mission AC, CONFIG and other custom mod-folder assets as necessary causes for that control. It does not demonstrate that a fully stock EDF6 PC executable and graphics environment reproduce it. The tested root still contained DXVK d3d11.dll/dxgi.dll proxy DLLs and a winmm.dll loader; canonical EDF.dll integrity and removal of those root components were identified as remaining controls.

The FPS/dispatch evidence makes cadence a plausible contributing factor, but not a proven diagnosis: 59.94 / 55.07 ≈ 1.0884, so an actor decremented only once per outer update at a sustained 55.07 Hz would run about 8.8% longer in wall-clock time than one updated at 59.94 Hz. An older FPS-unlock approach could produce the opposite effect by invoking outer-loop callbacks too often. Neither arithmetic observation proves that DXVK caused the actual observed caption fault.

Community comparisons suggested PS5 English subtitles behaved differently, but the retained record lacks a matched PC/PS5 same cue + same language + timestamped scroll/audio measurement. Consequently platform divergence is a hypothesis, not a proven universal PC-versus-PS5 fact. Do not attribute every late-scroll case to the port, DXVK, or a general Sandlot engine defect without a controlled installation-and-cue comparison. The missing-key VOICETABLE problem remains independent of these presentation-timing effects.

Evidence: vanilla control/Mods-disabled reports EDF5_EDF6_VANILLA_SUBTITLE_ENVIRONMENT_FRONTIER_R84_2026-09-06.md, EDF5_EDF6_PC_PS5_SUBTITLE_DIVERGENCE_R86_2026-09-06.md and native TalkManager analysis. The separate measured caption schedule has positive runtime tests without resolving this environmental root cause for all installations.

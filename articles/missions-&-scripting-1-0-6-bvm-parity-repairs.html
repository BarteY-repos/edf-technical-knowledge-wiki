EDF5 BVM difficulty/event semantics: seven cross-generation cases

UniversalMissions & ScriptingScriptingEDF 5EDF 6
Source-backed research / case study · Source/BVM/target-oracle qualified; runtime pending

The EDF5 bytecode emitter and the EDF6 AngelScript-facing compatibility interface differ in ways that can yield a compiling but semantically incorrect mission. These seven cases were reconstructed by comparing source BVM behavior against target scripts and, where stated, official or reference game implementations. They are source/static parity results, not seven independent end-to-end in-game passes.

Mission Recovered game behavior Corroboration
M003 WaitNC is 14 below Hard, 11 below Hardest, 8 otherwise; retains native literal factor_count = 3 EDF5 BVM + official EDF6 + comparison build
M019_5 Enemy count threshold ≤3 below Hardest, ≤5 on Hardest/Inferno EDF5 BVM + comparison build
M034_5 Wing Diver returns before Ranger-specific Sergeant dialogue EDF5 BVM + official EDF6 + comparison build
M045 Hardest/Inferno skips low-difficulty mothership idle cycle; early returns for mother_exit are preserved EDF5 BVM + comparison build and branch-counter history
M065 Func_4 event exists on all difficulties; zero-enemy factor applies only on Hardest/Inferno EDF5 BVM + comparison build
M067 Enemy count threshold ≤20 always; BigObject threshold ≤2 except Inferno EDF5 BVM + comparison build
M091 Wait 120 below Hardest and 180 on Hardest/Inferno; native literal factor_count = 2 EDF5 BVM + official EDF6 + comparison build

The source distinctions concern difficulty branches, entity thresholds, scripted returns, factor literal counts and event lifetimes. These can fail without malformed AngelScript syntax. A source-derived event can be missing on an easier difficulty while the same mission loads and plays on Inferno.

A historical cross-mission source audit statically validated the seven invariants and 29 edited mission ACs, but did not establish runtime behavior for each branch of the final combined game package. This article intentionally describes the game semantics, not the package/release procedure. See backward-layout switch conversion for the independent difficulty-switch failure family.

Complete historical 1.0.5 BVM gameplay-audit union: 27 distinct missions

A separately retained 9 October 2026 source audit compared all 141 original EDF5 MISSION.BVM scripts with the effective 1.0.5 mission conversion. Its scope is the original BVM's event-factor predicates, branch-dominated registrations/returns, stable FLAG_n identities and selected gameplay side effects. It does not report 27 separate defects still outstanding in a later 1.0.6 release.

Distinct mission set in effective 1.0.5 Count What failed and what should be preserved
Numeric flag identity mismatch 21 First-use symbolic enum order did not necessarily preserve the original FlagOn(n) / Factor_FlagOn(FLAG_n) identity
Difficulty-conditional factors and early returns 7 Five event-factor difficulty branches plus two branch/early-return cases could be flattened or lose dominant returns
Overlap (M045) −1 M045 has both a flag-identity issue and an early-return/registration issue; it must not be counted twice
Union 27 / 141 Distinct mission IDs with confirmed divergences in the audited control-flow classes, against the historical effective 1.0.5 baseline

The seven source-controlled cases are M003, M019_5, M065, M067, M091, M034_5, and M045. The 21 flag-identity mission IDs are retained in the systemic flag parity reference; the union is precisely 21 + 7 − 1. For example, M065 registers an event unconditionally but only adds an enemy-zero factor on Hardest/Inferno; an unconditional early return in the converted event builder removed the event on easier difficulties. In M034_5, the Wing Diver path must exit before Ranger-specific dialogue. In M045, missing early returns can re-arm mothership action cycles that the source would suppress.

Negative-result controls: The original audit found no extra missing reachable event registration after accounting for dead BVM functions and the deliberate DM001 helper, and zero counter-threshold/repeatability mismatches within its dedicated check. Raw counts of seemingly missing registrations and changed target API names are not proof of gameplay loss. Equally, an audit labelled NO DELTA FOUND is not proof of complete mission runtime equivalence.

Chronology matters: This is a 1.0.5 baseline defect census. Later 1.0.6 source repairs address these classes, but each corrected mission and the exact distribution still needs its own appropriate runtime evidence. It must not be read as 27 stock EDF5 defects, 27 verified unresolved bugs in the current mod, or 27 native EDF6 engine faults.

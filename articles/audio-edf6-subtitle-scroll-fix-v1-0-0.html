EDF6 Subtitle Scroll Fix v1.0.0

EDF 6Audio
Source-backed research / case study · Released / runtime-confirmed

Project status: released, closed and runtime-confirmed as public v1.0.0. This is a standalone EDF6 presentation plugin, distinct from EDF5-port VOICETABLE missing-key compatibility.

Purpose

The plugin corrects late long-caption scroll windows. Its production logic uses caption audio-duration metadata together with rendered line count to adjust when scrolling advances.

Final production timing lead:

0.75 s

Public artifact identity:

EDF6_Subtitle_Scroll_Fix_v1.0.0_PUBLIC.zip
edf6_subtitle_scroll_fix.dll

The retained production architecture is the low-overhead R11 insert-only design.

Explicit non-goals

The release does not modify:

  • TalkActor / WaitVoice mission semantics;
  • mission timing;
  • subtitle text;
  • VOICETABLE content;
  • audio playback;
  • caption lifetime/fade policy;
  • gameplay;
  • networking.

Production also omits the old per-frame subtitle Update/Render diagnostic path and synchronous diagnostic logging.

Relationship to EDF5-port generic-NPC captions

The two systems solve different defects:

  • lossless VOICETABLE composition supplies missing EDF5-derived caption keys/content;
  • Subtitle Scroll Fix adjusts late long-caption presentation windows.

Do not treat the plugin as a replacement for missing VOICETABLE entries, and do not destabilize the lossless table composer in order to solve presentation timing.

Qualification boundary

The portfolio authority marks runtime verification for release as complete; additional native cross-mission regression is optional only. Do not reopen R3-R10 subtitle diagnostics or run old caption-trace DLLs alongside the public fix unless investigating a new reproducible regression.

Why a presentation correction can work without retiming dialogue

The recovered native EDF6 TalkActor caption lifetime is an integer counter per actor update rather than direct subtraction of audio elapsed time. TalkManager runs through a framework dispatch with a 59.94 Hz nominal gate, and backlog can reduce its actual update cadence relative to wall time. A long caption may therefore scroll too late even when the text lookup and audio cue are both correct. This native path does not prove that every late-scroll symptom has the same cause; the public presentation-only correction has its own runtime evidence. See native voice/caption scheduler details.

Exact observed caption scheduling defect and bounded correction

The original PC control was a long English caption in M011, cue AE115_002: 262 caption characters (264 UI text units including delimiters), laid out as six lines of 32 px, with a four-line / 128 px viewport. The native scroll was scheduled to start at 17.875 s and end at 24.275 s, whereas the observed audio callback cleared with node age 16.800 s and scroll progress 0. The next caption arrived before this node could begin meaningful visible scrolling. This is direct runtime scheduling evidence, not an assumption based on a screenshot.

A second measured caption, AE115_003, had nine lines (288 px), the same 128 px window, an audio-duration metric of 23.523001 s, and a native 16-second scroll interval beginning at 18.506945 s. A candidate that merely moved that native 10 px/s motion earlier still lagged spoken content because a full 32 px line needed 3.2 s to reveal, while the average spoken time per nine laid-out lines was about 2.614 s.

The subsequently accepted, bounded layout/audio schedule uses the following observed 32 px line-height geometry (do not generalize it to arbitrary font sizes):

total_lines = content_height / 32
visible_lines = 4
line_time = aux_audio_duration / total_lines
base_start = (visible_lines - 1) * line_time
base_end   = (total_lines - 1) * line_time
lead       = min(0.75, base_start)
desired_start = base_start - lead
desired_end   = base_end - lead
scroll_start  = min(native_start, desired_start)
scroll_end    = min(native_end, desired_end)

The min(native, desired) rule means earlier-only scheduling; it never deliberately defers already-early native scroll. The correction changes only per-caption UI scroll-window fields +0x90 and +0x94 on the examined UiDebugMessage node. It does not alter TalkActor lifetime, the voice playback callback, caption strings or mission timing.

Runtime scope: the first hard-scoped layout/audio model made AE115_002, AE115_003, and AE115_004 readable in M011 while the next non-allowlisted long line remained bad. Later generalized testing corrected that subsequent line as well. The accepted public configuration used a 0.75 s lead; a preceding 0.60 s control had been reported visually acceptable. These were tested presentations, not a proven universal equality between every English voice and its glyph-level scroll milestones. The released implementation uses insertion-time adjustment rather than continuous per-frame UI detours. Source: M011 R7/R8/R9/R10/R11 reports and EDF6_SUBTITLE_SCROLL_FIX_PUBLIC_V1_0_0_RELEASE_LEDGER_2026-09-06.md.

What the successive native diagnostics actually eliminated

A trace of the original PC M011 subtitle path distinguishes several live candidates that should not all be preserved as competing explanations. Initial read-only diagnostics installed cleanly but were blind to the relevant caption due to a 32-character trigger threshold. Later traces identified TalkActor_Object and final caption lookup, but the sampled actor countdown was 0, so the original M011 visual defect could not be attributed to this actor's decrement rule. The generic TextField scroll counters (+0xB0/+0xC0) and StoryMessageWindow were separately rejected as active ownership paths for the tested subtitles.

The subsequent active class was UiDebugMessage. Its node+0x30 easing/offset was a real native field, but a direct runtime capture found f30=0.0 for every sampled active M011 caption, excluding that field as the cause in the tested case. The same capture rejected a lost wall-clock / scheduler-drift explanation in that run. The higher-value evidence was the exact native per-node scroll schedule at offsets +0x88, +0x8C, +0x90 and +0x94. The successful correction adjusted the start/end schedule at +0x90/+0x94, rather than globally retiming mission scripts, mutating caption strings, or changing a generic UI easing value.

The instrumentation evolved through many trace-only builds. One proposed R5 UI diagnostic was replaced before it ran by a broader R6 trace; it is not an independent successful or failed runtime experiment. Likewise, the earlier visual pass with a 0.60 s lead is a control point, whereas the public release used 0.75 s and a lower-overhead insertion-time adjustment. A slow diagnostic plugin is not evidence that the final slim implementation has the same instrumentation cost.

The separate vanilla M093 long-English-caption observation reproduced with the entire Mods directory disabled. That disproved the port's mission scripts, port VOICETABLE addition and other Mods-only overrides as necessary causes of that particular vanilla symptom; it does not prove a specific DXVK root cause. An early root-level logging/exception hypothesis was also demoted after the Mods-disabled control. Global vanilla subtitle-scroll behavior was de-scoped from the EDF5 port Patch 1.0.2, while the independent presentation plugin could still address the observed scrolling problem. This is not a contradiction: patch scope, native cause and separately distributed UI correction are different questions.

Which native captions were good controls, and what the early traces ruled out

Two original-script control censuses distinguish longest caption from earliest scripted candidate. The longest English caption actually referenced in the scanned base-game EDF6 mission scripts was BEX08_035 (534 characters) in technical M093, displayed as offline mission 109, Aliens Attack. Other strong static length controls were M063/BEX04_011 (399), M093_3/BEX08_048 (481) and M152/BE152_053_B (485). For faster testing, the later candidate census suggested M254/BEX08_041 (offline #126, 478 chars, script event 6), M207/BEX17_003 (#90, 488 chars, event 8) and M051_5/BEX06_003 (#129, 533 chars, event 10). Event ordinal is not elapsed mission time, and those lists were static test-selection evidence rather than visual runtime PASS for each cue.

The initial M011 trace lineage narrows the actual presentation class: R1 installed but its 32-character trigger could miss opening short captions; R2 reproduced a TalkActor hook with zero countdown and justified a native caption-resolver probe; R3 identified the active CaptionLookup path and rejected an ordinary generic TextField/ScrollInfo explanation; R4's later runtime test produced no StoryMessageWindow hook events despite successful installation; the active caption presentation instead constructed UiDebugMessage. R5 was only a proposed read-only UiDebugMessage diagnostic, replaced before its own runtime run by a broader R6 trace. Later evidence showed sampled node+0x30 stayed zero, so the static fixed-per-update easing formula is a real code fact but not the causal explanation of the observed long-caption delay. The accepted presentation-only timing correction and its 0.75 s lead remain documented above, not treated as an outcome of the unrun early trace candidates.

EDF6 weapon loot classes: `WEAPONTABLE.P8` and MissionPack identity

ConversionMissions & ScriptingLoot and mission identityEDF 5EDF 6
Technical reference · Source-derived static analysis and bounded modded-game runtime evidence, scoped per case

EDF6 weapon drop classification does not use custom mission-pack numbers as the loot-class values. In the retained binary/mission compatibility research, WEAPONTABLE.P8 used three native loot classes:

P8 loot class Observed native role
0 Base-game weapon drop class
1 DLC1 weapon drop class
2 DLC2 weapon drop class

For the tested EDF5 content hosted in custom EDF6 mission packs, the required correspondence was:

Custom content pack Loot class
MissionPack03 (base EDF5 content) 0
MissionPack04 (EDF5 DLC1 content) 1
MissionPack05 (EDF5 DLC2 content) 2

The pack identifier (03/04/05) and native class (0/1/2) serve different roles. The native loot class is not necessarily inferable by truncating the pack number, and this translation is not a general rule for arbitrary MissionPacks.

Observed in-game discriminator

The retained modded-game MP05/DLC2 test admitted P8=2 weapon rows at the expected late-game progression levels. That test supported the class translation for the tested installation, not the behavior of every stock/modified EDF6 build or a global mission-pack namespace policy.

When this distinction matters

A mission can compile, reach the first frame, spawn enemies and award boxes while producing the wrong weapon family. Diagnosing that case requires separating:

  1. the active game's logical mission/content pack;
  2. its associated native WEAPONTABLE.P8 loot class;
  3. the weapon level/progression conditions of the mission;
  4. any modded loader's custom mapping, which is not equivalent to stock behavior.

For MissionPack LIST/config lookup and save identity, see native MissionPack ID semantics. For resource table parity, see MissionPack LIST/TXT/image evidence.

Native candidate filter and observed DLC2 rewards

In the examined EDF6 binary, WEAPONTABLE.P8=0 passes the class check for any evaluated pack. Nonzero values must match the active logical pack ID in the original candidate path; the class gate precedes the level-range gate. As a result, a DLC1-class pool can include P8=0 and P8=1, while DLC2-class pools can include P8=0 and P8=2. The additional DLC rows are not automatically available merely because a mission's reward level overlaps their levels.

An instrumented modified EDF6 runtime running a custom MP09 test explicitly mapped to DLC2 class 2 recorded 110 P8=2 candidates, 34 newly admitted rows and two actual Lv 107 Air Raider rewards: N9 Eros Vulture ZAM and Gigantocopter 3 Delta. The source acceptance report does not demonstrate a Lv 110+ drop or native unmodified MP09 DLC2 behavior. For the exact binary path, P5/P8 decoded offsets and evidence distinctions see P8 candidate filtering and runtime test.

EDF 4.1 Genocide Cannon — static RE boundary

UniversalEngine RE & NetworkingGameplay & AIEDF 4.1EDF 6
Source-backed research / case study · Static binary RE; runtime discriminator pending

Evidence level: Static comparison against the private EDF4.1 and EDF6 binary oracles. The runtime symptom is real, but the evidence does not justify a new source-only patch yet.

Runtime symptom

The reported failure is unusually specific: the Genocide Cannon's visible beam/projectile/hitbox exists, but the expected impact explosion is not visibly reproduced.

This originally made the bridge's high-level bullet setup look suspicious. Later binary reconciliation eliminated most of those obvious candidates.

Recovered EDF4.1 FinalCannon contract

The source setup is:

  • factory: RocketBullet01_LowLight;
  • speed: 0.01;
  • life: 1800;
  • damage: 70 * s;
  • explosion radius: 60;
  • visual size: 100;
  • source color preserved;
  • source Genocide custom parameter preserved;
  • fire direction: Down() from the cannon muzzle.

The R13 bridge already preserves those high-level fields.

Contact and explosion path

Static RE shows that EDF4.1 and EDF6 Rocket/LowLight follow the same broad mechanism:

  1. the Rocket performs the physics/contact query;
  2. a contact record is stored;
  3. terminal/contact handling chooses generic explosion presentation;
  4. mode 2 selects the large-explosion branch, otherwise the normal branch.

RocketBullet01_LowLight is presentation-oriented in both generations. It does not establish a separate EDF4.1-only contact/destruction subsystem that is obviously missing in EDF6.

Config-default parity

The relevant source initializer defaults match the EDF6 parameter constructor used by the bridge:

Field EDF4.1 source EDF6 bridge/default
collision/radius factor 1.0 1.0
speed factor 1.0 1.0
hit-stop 0.5 0.5

The bridge then overwrites the same material fields the source FinalCannon overwrites.

Falsified or unsupported patch directions

The current evidence does not support fixing the symptom by:

  • replacing RocketBullet01_LowLight;
  • inventing another explosion radius or size;
  • changing direction;
  • extending the four-field source custom parameter;
  • changing collision/radius or speed factors;
  • assuming EDF6 lacks Explosion/BigExplosion primitives;
  • treating the visible beam itself as proof that the Rocket obtained a contact record.

Required runtime discriminator

The next useful runtime test must separate four questions:

  1. Did the Rocket itself obtain a contact record?
  2. Did area damage occur at the impact position?
  3. Was gameplay damage correct while only the explosion presentation was absent?
  4. Was the visible beam/hitbox a separate Lightning/beam component rather than the Rocket path under investigation?

Those outcomes lead to different fixes. Until one is observed, a broad R14 bullet patch would be speculative.

Current decision

Keep R13. No Genocide-specific R14 delta is evidence-backed.

More precise EDF6 bullet contact-state distinctions

A later source/runtime-instrumentation audit mapped additional native EDF6 states that can distinguish superficially similar outcomes. This is static engine evidence plus an unexecuted diagnostic design, not an in-game capture of the missing explosion:

State or pathway in inspected EDF6 Observed native representation What it does not prove alone
Map-ray stop/shortening BulletMtSystem path around RVA 0x234D20 sets the 0x04 bit in flags at +0xAF4 Visible explosion, actual damage or correct terrain response
Object hit query BulletControl+0x990 shape-cast collector; result count at collector +0x0C, capped by native path at 0x32 A registered shape-cast candidate is not guaranteed accepted damage
Movement / lifetime Movement type at +0xAF0; raw state +0xB04; lived frames +0xC38; lifetime +0xB48 An early terminal transition is not proof of a collision
LowLight native update Existing Rocket-native OnUpdate path (slot 5) can be observed without altering native return semantics Neither a display error nor a missing contact is proven by code presence

Consequently, map-ray stop, shape-cast candidate, terminal-before-lifetime, accepted damage and rendered explosion are five different outcomes. The port's reported missing impact effect remains open. Changing projectile size/radius, choosing another bullet class or inferring collision solely from its visible beam remains unsupported.

Source: R11_TESTER_FEEDBACK_COVERAGE_AUDIT_2026-11-15.md, carried into the later R12 source checkpoint. Offset meanings are restricted to the audited EDF6 build and have not been established as public API guarantees.

R175 three original FinalCannon SGO variants: two projectile contracts

The native EDF4.1 UFOMOTHER401_FINALCANNONPANEL{L,M,S}.SGO records were examined separately. All three report class UfoMother401_FinalCannon01 and the same two factory/parameter families:

SGO role Genocide projectile Source custom parameter Other targeted attack
Final Cannon L RocketBullet01_LowLight [2, 0, 0, 0.0005] LightningBullet01, [1.5, 1.0, 1.0, 0.15, 1]
Final Cannon M same same same
Final Cannon S same same same

The array lengths differ: the native four-element Genocide parameter is not the native five-element Lightning parameter. This matters when separating a visible lightning/beam event from the actual Rocket contact/explosion chain. The previously documented speed 0.01, lifetime 1800 and explosion radius 60 belong to the studied Genocide setup, not to every Lightning object. Per-source SGO hashes and exact parameters are in data/R175_EDF41_MOTHER401_FINAL_CANNON_THREE_NATIVE_SGO_PARAMETERS.csv.

This agrees with, rather than supersedes, the existing static LowLight reconstruction. It does not identify which physical projectile contacted the environment, whether area damage was accepted or why the converted encounter lacked the visual impact. Thus the older runtime failure remains open, and a different bullet factory or parameter retune is still unsupported. Source: R13_FUNCTIONALITY_R6_GENOCIDE_SOURCE_CONTRACT_AUDIT.json, checked against the later source-side contact diagnostics. No new gameplay measurements were performed.

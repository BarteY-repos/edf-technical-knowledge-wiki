EDF 5 — Effects (community source notes)

EDF 5Community Knowledge HubFile Formats
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-effect-classes

EffectGenUtil lives at 125ABA0 (about 95 code references): 3D94F0 (called from the scene init 3D6170) frees t…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-effectgenutil

EffectGenUtil lives at [125ABA0] (about 95 code references): 3D94F0 (called from the scene init 3D6170) frees the old one, allocates 0x50 bytes and runs the constructor 1AC850, which loads app:/Effect/basic.rab and app:/Effect/light.rab. GetTexture 1ACA80(util, out, name) looks a name up in basic.rab's Texture folder and logs EffectGenUtil::GetTexture( not found. : %ls ) on a miss; GetLightTexture 1ACB10 does the same in light.rab. EDF6's counterpart: the global [20B2980], 2E8510.

Basis: fn.py of the global's writers and the constructor; the two log strings' only references

Addresses (build-specific RVAs unless indicated): 125ABA0, 3D94F0, 3D6170, 1AC850, 1ACA80, 1ACB10

Effect textures come from five .rab archives: basic.rab and light.rab (EffectGenUtil), app:/Effect/Decal.rab…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-effect-textures

Effect textures come from five .rab archives: basic.rab and light.rab (EffectGenUtil), app:/Effect/Decal.rab (the decal manager, read in 3D7680), app:/Effect/spider.rab (read by 292740, the web code that also reads spider_net_* keys) and app:/Effect/Hud.rab. Code names textures by file name, e.g. 火炎_01.dds (flame), 煙_01.dds (smoke), spark_01.dds, ParticleAlpha_1-6.dds, Particle1_k.dds, 稲妻_01.dds (lightning), 噴射煙_01.dds (exhaust), マズルフラッシュ01.dds (muzzle flash); a few use a full path such as APP:\EFFECT\BASIC.RAB@煙_01.DDS. So replacing a texture inside basic.rab changes every effect that names it; shapes, counts and colors stay in code.

Basis: exe_strfind on Effect/ and .dds; the loaders' references read with fn.py

Addresses (build-specific RVAs unless indicated): 3D7680, 292740

EffectGenUtil calls

The dev console command effect_test (handler 59FB0, registered in 699B0) builds a name table in 59850

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-effectgenutil-calls

The dev console command effect_test (handler 59FB0, registered in 699B0) builds a name table in 59850; each entry's std::function calls one EffectGenUtil member with the position, the direction (0,1,0,1) (EE7550) and a size: Flame 1ACEB0, Flame2 1AD170, Blazing 1AD460, Explosion 1AD970 (plus 1.0), Explosion_Big 1AE7A0 (plus 1.0), ExplosionWind 1AEA40, ShockWave 1AED70 (plus 0.1 and 50), SolidBulletHit02 1B1A70, StencilLighting 1B27B0, GlassClash 1B2910, ClaySplash 1B2E60, MetalHit 1B3480, LeafHit 1B3EB0, CharacterHit 1B4120, CharacterMetalHit 1B48C0, ClaySplash2 1B55A0, DeathBlood 1B6210 (the death-pool decal, decals.md#decal-spawners). The same names and constants as EDF6's db::CreateEffectTest.

Basis: the table's names and std::function vtables (slot 2 = the call) read with fn.py and kh151_qwords.py

Addresses (build-specific RVAs unless indicated): 59FB0, 699B0, 59850, EE7550, 1ACEB0, 1AD170, 1AD460, 1AD970, 1AE7A0, 1AEA40, 1AED70, 1B1A70, 1B27B0, 1B2910, 1B2E60, 1B3480, 1B3EB0, 1B4120, 1B48C0, 1B55A0, 1B6210

A particle effect is built the same way in each EffectGenUtil call read (Flame, Explosion): an InitParam for…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-particle-spawn

A particle effect is built the same way in each EffectGenUtil call read (Flame, Explosion): an InitParam for ParticleObject (vtable E8E338) filled with 1C66B0 and then by hand, its texture from GetTexture (1ACA80), then the factory 77790(game system [125AB68], out weak ref, matrix 118C710, InitParam). Explosion makes a flame burst (火炎_01.dds), a smoke burst (煙_01.dds), and the explosion mark decal (1B0AF0). The ParticleObject InitParam is used in about 30 functions, enemy and weapon code among them.

Basis: fn.py of 1ACEB0 and 1AD970; xref of the InitParam vtable

Addresses (build-specific RVAs unless indicated): E8E338, 1C66B0, 1ACA80, 77790, 125AB68, 118C710, 1B0AF0

Factories

The effect-object factories sit together (EDF6's 842E0..84A60 block): 77790 ParticleObject (new 0x3E0, constr…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-effect-factories

The effect-object factories sit together (EDF6's 842E0..84A60 block): 77790 ParticleObject (new 0x3E0, constructor 1C7DB0, 32 callers), 779F0 LeafFallEffect (0x250, 1B9580), 77C60 LineParticleObject (0x390, 1BC690, 14 callers, most in EffectGenUtil's hit effects), 77ED0 GlassClashEffect (0x950, 1B7B10), 78140 StencilLight (0x220, 1CA180, 3 callers), 783B0 UfoRoboCanonChargeEffect (0x560, 1CA930), 78610 LineStripObject (0x380, 1BE070, its one caller the console command particle_test 5A1D0). Each takes the game system, an out weak reference, a matrix and an InitParam, like EDF6's 844C0.

Basis: each factory's allocation size and constructor call read with fn.py; the constructors named by the vtable they write

Addresses (build-specific RVAs unless indicated): 77790, 1C7DB0, 779F0, 1B9580, 77C60, 1BC690, 77ED0, 1B7B10, 78140, 1CA180, 783B0, 1CA930, 78610, 1BE070, 5A1D0

SGO keys that choose effects

Weapons (38C010, the weapon SGO reader): MuzzleFlash holds a class name, looked up with 6136C0(game system, n…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-weapon-effect-keys

Weapons (38C010, the weapon SGO reader): MuzzleFlash holds a class name, looked up with 6136C0(game system, name) (the class-factory map at +0x80; it logs a miss) and kept at weapon +0x390 (+0x3C0 the weapon, +0x3C8 0); empty means none. MuzzleFlash_CustomParameter's node goes to +0x3D0. The same reader takes ShellCase (a .shkt model) with ShellCase_CustomParameter, and the bullet's AmmoClass, AmmoColor, AmmoSize, AmmoModel and Ammo_CustomParameter.

Basis: fn.py of 38E1DD..38E285; the key strings' references

Addresses (build-specific RVAs unless indicated): 38C010, 6136C0

Weather and debug commands

Snow and rain are full-screen particle managers (FullScreenParticleManagerBase

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-weather-particles

Snow and rain are full-screen particle managers (FullScreenParticleManagerBase; SnowParticleManager with Snowflake.dds in 1AB460; rain with Raindrop.dds in 1A81F0 and RainRipple.dds), started by the console commands enviroment_snow (67E60, object name FullScreen_Snow) and enviroment_rain (68250, FullScreen_Rain); a map's weather comes through map::sync::weather_resource, not followed. Other effect console commands registered in 699B0: particle_test, effect_test, light_color, light_vector, decal_splash, decal_splash_proj, decal_bullet_mark, scene_effect_start_fade, change_enviroment_rain_param, set_light_weight_mode.

Basis: the strings' references read with fn.py

Addresses (build-specific RVAs unless indicated): 1AB460, 1A81F0, 67E60, 68250, 699B0

EDF6 Havok 2020.1 tagfile: TAG0, SDKV, DATA, TYPE and INDX

EDF 6Game technical referencesFile formats / Havok
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF6's native Havok files are Havok 2020.1 binary tagfiles, with TAG0 as the container magic and SDK version text 20200100. The physics types are primarily hknp*; navmesh types are hkai*, and animation/ragdoll data may refer to hka*. These names matter because older Havok 2014 hkp* files may be readable by a legacy parser without satisfying the data contract expected by a modern EDF6 loader.

Section header

Each section begins with eight bytes: a big-endian u32 combining two high kind bits and a 30-bit byte count including the header, followed by a four-character section tag. kind=0 describes a container that can contain subsections; kind=1 describes data. The object's serialized DATA field values are little-endian, so byte order is not uniform across the file.

Section Recorded role
TAG0 Top-level tagfile container
SDKV Havok SDK version string 20200100
DATA Serialized objects and arrays, little-endian values
TYPE Container for TST1, TNA1, FST1, TBDY, TPAD
TST1 Type-name strings
TNA1 Named type declarations and template arguments
FST1 Member-name strings
TBDY Field/layout definitions for types
INDX / ITEM Indexed object, array and string locations

The surveyed EDF6 files do not contain THSH type hashes or a PTCH patch table. That is a finding for this native corpus, not a claim that the broader Havok serialization format never uses such sections.

Body wrapper and ids

EDF6 hknp Body wrapper and size

Evidence: static · Build: steam-678ccb46 · Fact ID: havok-body-wrapper

xgs::havok::Body is EDF's wrapper of one hknp body: 0x110 bytes (11AEF00: new 0x110, then the constructor 11B0580), held by a shared_ptr (RTTI _Ref_count<VBody@havok@xgs> near 11AA979), no vtable. +0x00 / +0x08 a weak_ptr to itself (enable_shared_from_this; 11AD220 locks it), +0x10 a 0x50-byte material copy (from the material library at hknpWorld +0x920, by +0xF4; inferred), +0x60 a copy of its hknpMotionProperties (0x70 bytes), +0xD0/+0xD8 and +0xE0/+0xE8 two shared_ptrs passed to the constructor (inferred), +0xF0 the hknp body id (low 24 bits the index, 0xFFFFFF none), +0xF4 u16 material id (= hknpBody +0x8A), +0xF6 u16 motion-properties id (= hknpWorld +0x90[id & 0xFFFFFF] +4), +0xF8 u16 set to 2 by the constructor (meaning unknown), +0x100 the world wrapper W, whose +0x58 is the hknpWorld X. Agrees with corpses.md#ragdoll-body-array (+0xF0 id).

Basis: the author's static reading ("H" for the layout, "M" where marked); every wrapper function below starts with mov rax,[rcx+0x100] and reads [rax+0x58] (hub read of 11B13D0, 11B14A0, 11B1960)

Addresses (build-specific RVAs unless indicated): 11AEF00, 11B0580, 11AA979, 11AD220

Evidence: static · Build: steam-678ccb46 · Fact ID: body-id-object-maps

Ids, bodies and objects: 11AD2E0(W, id) returns the raw Body* (no reference taken; 0 when invalid, so a stale id is safe): it tests the id with the world's read slot 13 (DAC200: flags & 3 and +0x50 == id) and reads the body property key 0x8001 (8 bytes). 11AD220(W, shared_ptr* out, id) does the same and locks the self weak_ptr (throws bad_weak_ptr, B97A0, on failure). 108260(id) takes a body id (not a Body): 11AD2E0([20B2958]+0x10, id), then the property key 0 of that body, the owning `SceneObject; 0 when there is no Body or no key 0. SceneObject physics body array traversal

Evidence: static · Build: steam-678ccb46 · Fact ID: bodies-of-object

To find the bodies of any SceneObject: walk the hknp body array ([X+0x38], count [X+0x40], 0xB0 each), skip entries with flags & 3 == 0, read key 0 with DAB360(X+0x20, id, 0, 8) and keep the ids whose value is the object; 11AD2E0 then gives each Body* (O(N), once per grab).

Basis: the author's method (section 3.3.1; used by All Forces' gravity gun)

Addresses (build-specific RVAs unless indicated): DAB360, 11AD2E0

hknpWorld, bodies and motions

hknpWorld constructor and three vtables

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-world-vtables

The hknpWorld X is built by DA3140 and has three vtables: [X] = 18BC720 (main), [X+0x18] = 18BC740 (the write interface, "write slot n" below = [18BC740 + n*8]), [X+0x20] = 18BC9C0 (the read interface, which the map raycast calls, bullet-collision.md#map-raycast). Write slot 28 is E50720 (set motion properties) and slot 32 E4FBF0; a check of slot 32 against E50720 (All Forces' own jet code did that) never matches. Every write slot first posts an API command to X+0x868 (command number in 0x00XX0200).

Basis: the author's static reading ("H": q(18BC740 + 28*8) = E50720, q(... + 32*8) = E4FBF0); corrects the author's own jet notes

Addresses (build-specific RVAs unless indicated): DA3140, 18BC720, 18BC740, 18BC9C0, E50720, E4FBF0

hknpBody (0xB0 bytes

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-body-layout

hknpBody (0xB0 bytes; array [X+0x38], count [X+0x40]): +0x00..+0x2F three rotation columns (their w parts hold the local center of mass, 11B1100), +0x30 position (float4; 11B15B0 returns &body+0x30), +0x40 a low-order position correction (the position setter uses (double)+0x30 + (double)+0x40; inferred), +0x50 id, +0x54 flags (bit 0 static, bit 1 dynamic and added, bit 2 keyframed, bit 3 active (inferred); higher bits settable, #body-wrapper-functions), +0x78 shape, +0x80 motion id, +0x88 u8 nonzero = in the world (inferred), +0x8A u16 material id, +0x8C u32 collision filter info (read by 11B1240, written by write slot 35). Agrees with corpses.md#hknp-body-id-layout and character-control.md#walk-support-body.

Basis: the author's static reading ("H", except where marked)

hknpMotion (0x80 bytes

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-motion-layout

hknpMotion (0x80 bytes; [X+0x178] + motion id x 0x80): +0x00 orientation quaternion, +0x10/+0x18/+0x20 world center of mass as three doubles, +0x40 four hkHalf (the high 16 bits of a float): xyz the local inverse inertia, w the inverse mass, +0x48 the first attached body id, +0x58 u16 motion-properties id (DF76D0), +0x60 linear velocity xyz with w = the maximum linear speed (from properties +0x10), +0x70 angular velocity in local space, w = the maximum angular speed (properties +0x14). Static bodies share motion 0: never write its velocity.

Basis: the author's static reading ("H")

What the velocity and impulse write slots (20 to 26) do: nothing when the body is not added (flags & 2 == 0)

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-write-wakes

What the velocity and impulse write slots (20 to 26) do: nothing when the body is not added (flags & 2 == 0); when it is in the world (+0x88 != 0), neither static nor active (flags & 9 == 0) and the activation argument is 0, they wake it with DAFF20(X, id, 0) (E4FE46..E4FE64); then they write the velocity and clamp it to the maximum at motion +0x6C. EDF's wrappers always pass 0, so setting a velocity wakes a sleeping body.

Basis: the author's static reading ("H"; DAFF20's signature "M")

Addresses (build-specific RVAs unless indicated): DAFF20, E4FE46, E4FE64

Motion properties and gravity

Motion properties library: lib = X+0x928, entries lib+0x40, count (int)lib+0x48, 0x70 bytes each

Evidence: static · Build: steam-678ccb46 · Fact ID: motion-properties-library

Motion properties library: lib = [X+0x928], entries [lib+0x40], count (int)[lib+0x48], 0x70 bytes each. E155D0(lib, |g|) builds the five defaults, index 0 to 4 STATIC, DYNAMIC, KEYFRAMED, FROZEN, DEBRIS (a switch in DCFA10): DYNAMIC max linear speed 200, max angular 100, gravity factor 1; KEYFRAMED gravity factor 0; DEBRIS 100 / 10 with damping 0.01 / 0.5; every preset writes time factor 1.0. Layout: +0x00 isExclusive (must be 0 for de-duplication), +0x04 flags, +0x08 gravityFactor, +0x0C timeFactor, +0x10 maxLinearSpeed, +0x14 maxAngularSpeed, +0x18 linearDamping (DEA61F: v *= max(0, 1 - d x dt)), +0x1C angularDamping, +0x20 on solver and deactivation values (DEBRIS: +0x20 0.2, +0x24 |g| x a constant), +0x54 5 / maxLinear, +0x58 0.005 / maxLinear. So a thrown dynamic body is capped at 200 m/s unless its properties change. (All Forces' own HavokRelay.h had gravity at +0x24 and time at +0x20: wrong.)

Basis: the author's static reading ("H": DYNAMIC writes +8 = 1.0, KEYFRAMED +8 = 0, all +0xC = 1.0)

Addresses (build-specific RVAs unless indicated): E155D0, DCFA10, DEA61F

One body's gravity factor can be changed: copy entriesBody+0xF6, clear its +0 and set +0x08

Evidence: static · Build: steam-678ccb46 · Fact ID: per-body-gravity-factor

One body's gravity factor can be changed: copy entries[Body+0xF6], clear its +0 and set +0x08; add it with E15190(lib, u16* outId, const props*) (outId 0xFFFF when the library is full; re-read entries afterwards, it can move); switch the body with write slot 28 +0xE0 E50720(X+0x18, id, u16 propsId), which writes X+0x90[id] +4 and, for a non-static body, calls DF76D0(motion, propsId, &props) (writes motion +0x58, re-clamps +0x6C / +0x7C); then update Body+0xF6 and the copy at Body+0x60. Properties belong to the motion, so this is per body only when one body uses the motion (inferred for shared motions).

hknpWorld gravity vector and cinfo

Evidence: static · Build: steam-678ccb46 · Fact ID: world-gravity

World gravity is the float4 at hknpWorld +0x900: the constructor DA22E1 reads it from cinfo +0x70, getCinfo DAB480 writes it back there. Body quality and the helicopter body: hknp's default body-quality table is at E13BA0

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-body-quality-heli

Body quality and the helicopter body: hknp's default body-quality table is at E13BA0; the quality library's entry i has its requestedFlags at +0x40 + 0x30 x i, the library pointer at hknpWorld +0x930. Character contact impulse behaviour

Evidence: static · Build: steam-678ccb46 · Fact ID: character-contact-impulse-uncapped

Reading map

This source note combines several technical details. Its evidence grade, game build and contributor credit above still apply to the entire record. Follow these topics, then expand the complete original text for offsets, exceptions and caveats.

  1. Character proxy contact setup
  2. Impulse computation
  3. Missing or different caps
Complete original research record — expand (1,537 characters)

Character contacts with no impulse cap: the character proxy builds its vertical contact constraint in 11DDFD0 as a block at [rsp+0x40] = {0 or 1.0, maxImpulse, 1.0}, and 11DE049 (movss xmm0, [18474B0]) always loads maxImpulse with HK_REAL_HIGH (infinite). The character's maxForce at [character+0x70] (copied from cinfo +0x98 by the constructor at 11DD07F / 11DD085, default 1000) is never used on this path; EDF5's hkp character limited contacts with dynamic bodies to maxForce x dt, EDF6's hknp lost that step, so a giant (Barga, huge monsters) standing on or pressed against a moving mothership, ragdoll or debris gets an unlimited impulse (thrown, or pushed into the ground). The engine's own test when a character pushes a body (D95D38): test [body+0x54], 5 (static or keyframed: skip), then test 2 (dynamic), then push with [rdi+0x70]; so a cap belongs only on flags & 7 == 2. The other body's id is at the contact point [rbx+0x20], the body manager at [character+0x28] (read interface 18BC9C0: +0x68 = DAC200, the validity test, +0x80 = DAB170, [mgr+0x18] + index x 0xB0); 11DE0E2 calls +0x80 and drops the result. The step's dt: checkSupport (slot at 1AE4D50 -> 11DE5B0, rdx = hkStepInfo, dt at +8) runs before the contacts are built. Registered but unused mass-changer modifier

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-mass-changer-unused

hknp's mass changer is registered but unused: hknpMassChangerModifier (vtable 17E8B58) is added for the body / material flag ENABLE_MASS_CHANGER 0x800000 (E838E4, next to the 0x400000 modifier at E838CD). Its Jacobian hook DD4070 acts when one material of a pair has the category MASS_CHANGER_DEBRIS (byte +0x30 == 1) and neither body is static: with f = the other material's massChangerHeavyObjectFactor (+0x32, an hkHalf, the top 16 bits of a float) and a = (f - 1) / (f + 1), it scales the debris side's inverse mass by 1 + a and the other's by 1 - a. Every stock material is IGNORE with f = 1 (material constructor DD0270), so it never acts. Materials: the body manager (world +0x20) returns its library from vtable slot 5 ([mgr+0x900]); materials at [lib+0x48], 0x50 bytes each, indexed by the body's u16 at +0x8A (E67C24). The behavior it would fix: a tank hull (quality 7) over loose rubble (debris bodies, quality 1) wedged against static ground gets the solver's push-out and can be thrown up (5 m/s forward turned into 5 m/s up in one step, the author's launch probe).

Basis: the author's static reading and its in-game probe (the launch); E838C0..E838EB re-read with fn.py (flag 0x800000, modifier at +0x90)

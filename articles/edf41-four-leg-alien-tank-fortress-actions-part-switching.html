EDF4.1 Alien4LegTank: fortress part groups, ObjectAction commands and gait

EDF 4.1Game technical referencesEnemy state machines
Technical reference · Source-scoped static analysis; no R129 gameplay test

The original four-legged enemy fortress is the native class Alien4LegTank, not a renamed EDF6 MovingFortress. Both look like multi-part walking fortresses, but their mission commands and generators differ.

What the seven script actions do

The native action handler receives the mission's ObjectAction message and dispatches values 0–6 into a seven-entry table. Each command targets one of three part groups or the body itself:

Action Native response
0 / 1 Enable / disable part group 0 — main cannons
2 / 3 Enable / disable part group 1 — Gatlings
4 / 5 Enable / disable part group 2 — auxiliary bits
6 Enter the destruction state if the fortress is not already dead

The part enable routine walks records of 0x20 bytes beginning at the object's part table +0x920; it compares each part's group field at +0x18 to the requested group. Mission 16's original script (M117) uses all seven actions, including a roughly 35-second interval between the cannon activation and deactivation. Other missions use only subsets of this action protocol.

The same numeric ObjectAction values in EDF6's MovingFortress have different meanings. A direct one-to-one translation of script action 1, for example, can turn an EDF4.1 cannon-off command into an unrelated debris action in EDF6. Compatibility requires object-specific action translation, not a global numerical mapping.

Movement and generator layout

EDF4.1's Alien4LegTank begins standing; the original scripts do not send a separate stand-up command. It has one object generator at the belly hatch above its core (+0x1040 in the studied build). When idle and sufficiently clear of the map edge, the locomotion state makes a five-way draw: 0–2 select a walking clip, 3 turns left and 4 turns right. It moves by complete animation clips instead of freely steering in every frame.

This clarifies several familiar gameplay observations: a wandering fortress may finish a motion clip before choosing a new heading, and the central generator is a separate concern from activating its weapons. Neither behavior should be attributed to EDF6's native fortress unless that game's own object is examined.

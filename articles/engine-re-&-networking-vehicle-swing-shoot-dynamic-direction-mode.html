EDF6 vehicle-mounted weapons: dynamic `fire_model_direction` mode 2

EDF 6Engine RE & NetworkingGameplay & AI
Technical reference · Exact EDF6 binary/class-specific behavior; no fresh runtime test

The fire_model_direction parameter is not simply a constant that can be read once from a weapon's SGO/MAB record. EDF6 has a runtime override used by the VehicleSwingShoot weapon family. A model converter or weapon inspector that treats every value as static can therefore miss an active firing-direction mode.

Static configuration versus effective mode

In the qualified vanilla corpus, the recovered classic SGO fire_model_direction values embedded in DSGO extra/MAB were:

Static mode Number of configurations
0 1,708
1 125
2 0

The normal configuration parser only creates modes 0 or 1. However, the native VehicleSwingShoot code deliberately selects mode 2 at runtime, so zero mode-2 entries in the shipping configuration scan does not mean the mode is unused.

Runtime mechanism

The analyzed VehicleSwingShoot class uses the common per-shot transform/vector table:

  • table stride: 0xF0 bytes per entry;
  • entry+0xD0: dynamic override direction/basis;
  • entry+0xE0: direction selector, set to 2 by VehicleSwingShoot;
  • shared 0x6969A0: consumes the mode-2 override basis on its direction path;
  • Weapon+0x370: FireBurstCount;
  • Weapon+0xE18: remaining burst count.

The swing progress is derived from remaining shots relative to the burst count, allowing the firing basis to change through a burst. The examined class does not immediately restore selector mode 0/1 within the same instance after selecting the dynamic mode.

The exact native configuration examples are V605_BARGA_C_CANNON.SGO, its _AI counterpart, and _DLC. They are statically mode 1 but dynamically mode-2-capable.

Consequences for tools and modding

  • Read the configured mode and the effective per-shot runtime mode separately.
  • Do not validate a weapon inspector by counting only static fire_model_direction=2 records.
  • When investigating a Barga cannon's shot orientation, capture the dynamic basis and remaining burst count instead of interpreting the configuration value as the whole firing contract.
  • Do not generalize this override to every weapon with a burst counter: the exact writer evidence is class-specific.

For the rest of the firing pipeline see weapon fire transforms and Weapon RNG / batched projectile reconstruction.

Evidence: exact EDF6 native binary tracing for the analyzed EDF.dll build, plus three identified shipped VehicleSwingShoot configs. Other uninspected implementations and game revisions are not implied.

EDF6 secondary weapon actions: zoom, Fencer dash/boost, reflect and firing gates

EDF 6Game technical referencesNative weapons and controls
Technical reference · Build-specific source evidence; no new gameplay test

In the studied EDF6 native weapon system, each weapon carries a SecondaryFire_Type field and the main weapon update dispatches that value through a fixed native table. The observed types include 1 = zoom, 4 = jumpjets, 5 = dash and 6 = shield reflect. This means identical player input can perform different actions depending on the equipped weapon.

Fencer movement from a weapon action

For a Fencer dash or jet action, the weapon sends a native message (0x2003) to the character object. The dash controller projects its movement input along the player's current aim yaw, and the associated network event carries yaw information. It is not simply a global player-speed multiplier detached from the weapon and aim direction.

A shot also passes several independent gates

Native WeaponBase firing checks rounds remaining, a firing-delay flag, cooldown and a separate state bit. The source records the cooldown as a float value counted down by weapon updates, not by a wall-clock timer independent of the game's frame cadence. A successful round reduces available ammunition and selects a muzzle based on a running shot index modulo the weapon's muzzle count.

A lock-on weapon has an additional rule. Except for documented lock types 0 and 5, firing is refused when the lock list is empty. With multi-lock targeting, a single trigger action can produce a volley whose shot count derives from the number of locks; the distribution mode chooses whether it controls FireBurstCount or FireCount. Vehicle-mounted weapons can update their lock search even without an active trigger pull.

These conditions help explain two otherwise surprising behaviors: a weapon can appear ready but refuse to fire without targets, and holding a burst trigger through a cooldown does not necessarily queue unlimited bursts.

Scope

This is a source-derived description of selected native classes in EDF6 build steam-678ccb46. Not every weapon shares every vtable path or secondary type. No new gameplay input or multiplayer latency test was performed.

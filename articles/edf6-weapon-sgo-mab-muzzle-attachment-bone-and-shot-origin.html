EDF6 weapon muzzles: MAB attachment nodes, model bones and shot-origin transforms

EDF 6Game technical referencesWeapon animation and placement
Technical reference · Source-scoped static analysis; no R129 gameplay test

An EDF6 gun's firing point is not necessarily a specially named muzzle bone in its MDB mesh. The studied game reads its muzzle description from the weapon SGO's animation_model[2] MAB-related list. Each entry associates a name, a model node and a local transform. The runtime turns that into the shot-origin matrix used when firing.

Source geometry and the runtime entry

The native weapon construction code creates muzzle entries with a 0xF0-byte stride, accessed through a weapon field at +0x1D0. In a representative entry, offset +0x00 points to the node record, +0x10 stores a local matrix and +0x50 the resulting shot matrix. The data is derived from the node's transform, not simply from whatever bone pose the renderer currently shows.

Examples recovered from original EDF6 resources:

Fencer heavy cannon h_cannon_normal01.mdb nozzle (0, 0, 1.486)
Fencer Gatling h_gatling_normal01.mdb roll (0, 0, 0.956)

These values are local to the model's own coordinate frame. They should not be interpreted as absolute positions in a mission map or reused as global weapon dimensions.

Why an attachment can look right but fire wrong

The visual model can contain a node called body, roll or nozzle whose origin is not the projectile spawn origin. The MAB attachment supplies a deliberate offset. Therefore matching a screenshot of a muzzle tip does not by itself reproduce the native shot transform, and inspecting only the mesh bone table is insufficient for accurate projectile placement.

EDF5 Radar Projection, Colors and Marker Scaling

EDF 5Community Knowledge HubGameplay & AI
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

The minimap is a distinct projection and marker-rendering pipeline. Entity world positions are projected onto a 2D radar plane, clamped to its range, and classified by a color/marker dispatcher before drawing.

Format, API or behavior

In the inspected implementation the position scale defaults to 0.6, marker size scale to 1.2, and the planar range comparison uses 200.0 m. A helper computes 2D coordinates, relative height, and an inside-range flag. The source identifies where team colors are loaded and used, which is useful for HUD overlays and special markers.

Evidence and exact technical details

The following selected source observations retain their original evidence level and build-specific details. Follow their links for the complete evidence method, addresses and attribution.

Radar scales — static

The constructor sets [this+0x8E0] = 0.6 (position scale) and [this+0x8E4] = 1.2 (marker size scale, the game's normal dot size), read by the marker drawer 4CE730, the teammate-icon drawer 4CED00 and 4CF560.

Radar position helper — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (518 characters)

4CE5C0 returns radar-plane x, y, a height term and a flag at [rbp-0x14] (1 = inside range, 0 = clamped to the rim). The 2D distance is compared with 200.0 m (constant EE66FC, loaded at 4CE64E); positions are scaled by 0.6, so the rim radius is 120 radar units. Height term = scale^2 x 2.25 x dy, clamped to +-80. The radar rotates with the player's heading (object [this+0x768], rows at +0x80 / +0x90; the source called it the camera object, but it is the player soldier: #radar-own-player-object, settled 2026-11-08).

Radar colors — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (475 characters)

The six colors are static float4 globals 125B400..125B450, filled once at 4CD89C from .rdata (EE7920 white, EE7900 cyan, EE7550 green, EE7470 red, EE7560 yellow). Only the dispatcher uses them, through eight lea instructions at 4CDAEE, 4CDB29, 4CDB69, 4CDC20 (crates), 4CDC5B, 4CDCC6, 4CDD01, 4CDE0C; the drawer copies the color (16 bytes, no alignment needed). As RGB 0-255: hostile 255 0 0, team 2 0 191 255, team 4 and team 0 255 255 255, team 5 255 255 0, crates 0 255 0.

Radar marker drawer — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (357 characters)

Marker drawer 4CE730: rcx = radar object, rdx = HUD draw context, r8 = list, r9 = a rotation matrix the dispatcher builds at [rsp+0x60], [rsp+0x20] = color pointer, [rsp+0x28] = pointer to the reference (player) position built at [rsp+0x50]. List: [r8+8] data, [r8+0x18] count, 16-byte vec4 elements; list in r13, index in r15d, next-element code at 4CEC60.

Radar w lane — static

Position helper 4CE5C0 ignores the w lane of an element, so a patch can carry per-entity data there (floats such as 0..4 and 5/6/7 can be carried there).

Exact source: View evidence and source details · build steam-5d11de53

Version notes and limitations

The report that an ignored vector w lane can carry extra information is an implementation trick in the studied helper, not a guarantee that all users or future builds ignore it.

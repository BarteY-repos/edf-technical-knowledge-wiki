Render phases

Phase dispatcher 62BC70 - jmp vtable+8

Evidence: static · Build: steam-5d11de53 · Fact ID: render-phases

Phase dispatcher 62BC70 -> jmp [vtable+8]. The main Commander (frame renderer 62BE00) runs phase 1 at 62C0FC, phase 4 at 62C1DE and phase 2 at 62CE19; a second Commander type (function around 62D37B, type at +0xC4) dispatches phase 0 (62D3F9) or phase 3 (62D4AC). Phase 3 is a shadow pass, phase 1 the main opaque (G-buffer) draw, phase 2 the translucent draw.

Basis: disassembly

EDF Knowledge Hub record — original wording — expand (1,792 characters)

62BE00 is not a per-frame frame renderer but the game's Umbra::Commander::command(cmd) override (vtable EE11B0, slot EE11B8; jump table 62D71C, cmd 0..9), called by Umbra from Umbra::Camera::processVisibility (626B04, in job 626A80) once per view; one Commander object (ctor 62AF90, which calls Umbra::Commander::Commander C98060) is reused by every view (rendering.md#view-requests-queue). Commands: 0 62BE6C clear lists, depth-only targets (5DB530), clear depth; 1 62BEE0 main render, only for view kind [cmd+0xC4]==0 (G-buffer 5DB5C0, phase 1 62C0FC, phase 4 62C1DE, light accumulation 5DB7E0/5DC560, deferred lighting 62C4D0 (shaders.md#deferred-lighting-dispatch), post-effect listeners, forward targets 5DB970 at 62CC89, phase 2 62CE19, reset 5DBCD0); 2 62CF0F rebuild view and projection from Umbra's viewer (C98070, C98078, C98080) into commander+0xE0..0x15F (rendering.md#camera-writer); 3 62D1F8 sort visible Umbra objects into phase lists by obj+0x20 flag bits (bit 28 phase 1, and phase 0 if occluder; bit 29 phase 2; bit 27 phase 4); 4 62D37B phase 0 loop 62D3F9, and for view kind != 0 phase 3 (shadow) loop 62D4AC; 5 62D4FB / 6 62D5F3 occlusion queries; 9 62D66A debug lines. Fields: +0x10 render context ([ctx+8] = ID3D11DeviceContext), +0xC0 camera blob, +0xC4 view kind (0 main, 1 secondary/shadow), phase lists +0x18/+0x38/+0x58/+0x78 (phases 1/2/0/4; counts +0x30/+0x50/+0x70/+0x90). 62BC70 is the per-item phase callback: jmp [item_vtable+8] with (item, ctx, phase, camera blob). The order in which Umbra issues the commands is inside umbra_sandlot.dll (unverified). Corrects two labels of #render-phases and #models-umbra-commander ("frame renderer", "a second Commander type": 62D37B is command 4 of the same function, +0xC4 the view kind); their phase addresses stand.

Animated and rigid models

Shared AnimationModel draw entry point

Evidence: verified · Build: steam-5d11de53 · Fact ID: animationmodel-draw-callback

All animated models (enemies, soldiers, NPCs, vehicles) draw through one function: AnimationModel (vtable EA4310) slot 1 3AEF60 (rcx model, rdx render context, r8d phase, r9); slot 2 3AE990 is the translucent draw. Rigid models draw through sgmUmbraObject (vtable E8E3C0) slot 1 50780. Enemies (GiantSpider : InsectBase : GameObjectBase : SceneObject), soldiers, NPCs and vehicles own AnimationModels; 57 call sites construct one (ctor 3AC200). Humanoid enemies keep theirs around obj+0x930 (parameter-change call at 2C81C4).

Basis: RTTI and disassembly; novae (ajane); an NPC Fencer's weapons and shields are rigid models and follow the second hook

Addresses (build-specific RVAs unless indicated): 3AEF60, 3AE990, 50780, EA4310, E8E3C0, 3AC200, 2C81C4

sgmUmbraObject callback and model pose

Evidence: static · Build: steam-5d11de53 · Fact ID: models-sgmumbraobject

sgmUmbraObject's callback 50780 draws its model (struct at obj+0x60, pose [obj+0xB8]) in phases 0-3 with the same phase number and keeps no drawn-this-frame bookkeeping; created/initialized at 505D0 (identity transform). A third, unclassified path: 16 direct callers of helper 50470 (pose draw without a class callback).

Root-bone world transform and owner position

Evidence: static · Build: steam-5d11de53 · Fact ID: models-root-bone

Materials

A model's shader parameters can be set per draw: model struct +0x20 lists materials (0x18 per entry, count +0x30

Evidence: verified · Build: steam-5d11de53 · Fact ID: model-material-parameters

A model's shader parameters can be set per draw: model struct +0x20 lists materials (0x18 per entry, count +0x30; entry+8 -> record, record+8 -> instance, instance+0 -> effect); effect+0x150 is an unordered_map<std::string, index> (FNV-1a hash, buckets at +0x18, mask +0x30, end node at map+8 = effect+0x158; node value at +0x30) with find = 1C2920(map, &out_iter, &key) (pure; one memcmp call); effect+0x138 is the parameter table (0x18 each: cbuffer index, byte offset, size); instance+0x38[cbuffer] -> storage with data +0x30, size +0x40, dirty byte +0x48. Model struct = AnimationModel+0x140 or sgmUmbraObject+0x60 (same init 5ABFC0).

Basis: disassembly; novae (ajane)

Addresses (build-specific RVAs unless indicated): 1C2920, 5ABFC0

Level of detail and distant animation

Distance-based insect pose-job throttling

Evidence: static · Build: steam-5d11de53 · Fact ID: insect-pose-job-skip

The "low frame rate" of distant insects is a pose-job skip in InsectBase's update 261210 (GiantAnt, GiantSpider, GiantBee, DragonSmall): each frame the CAS pose job is queued (1CD660, queue manager [125B090]) only when [obj+0x2A0] % N == [frame ctx+0xC] % N, with N = 1 / 4 / 8 / 16 chosen by the AnimationModel's last-frame scaled squared camera distance ([model+0x470], reached through obj+0x8F0 / +0xB10) against the bands 22500 / 90000 / 360000 (150 / 300 / 600 units), and N = 16 when the model was not drawn last frame. Animation time still advances every frame (5F9150); only the pose evaluation is skipped. The block 26183A..2618EB skips only if byte [obj+0x435] != 0 (1 by default, set at 260A87; the action handlers 1EFF60 and 200935 toggle it); [obj+0x9F8]==2 bypasses it. Immediates N: 26184C 16, 261869 1, 26187E 4, 26188D 8. Changing 261841 74 6F to EB 6F means never skip.

Basis: novae (ajane)

Addresses (build-specific RVAs unless indicated): 261210, 26183A, 2618EB, 261841, 1CD660, 125B090, 5F9150, 260A87, 1EFF60, 200935, 26184C, 261869, 26187E, 26188D

Attribution: novae (ajane) · 2026-11-04

Animated mesh level-of-detail selection

Evidence: static · Build: steam-5d11de53 · Fact ID: animationmodel-lod-select

An animated model's mesh LoD is chosen only in the AnimationModel draw 3AEF60: it starts at model+0x140 (full detail) and walks the LoD array [model+0x230] (0xF0 bytes each, count [model+0x240]), keeping the last entry whose threshold +0xE8 is <= [model+0x24] (compare 3AEFA8, ja 77 0E at 3AEFAB). The thresholds are the SGO LoD distances squared at load (mulss xmm6,xmm6 at 3ACB51 in the shared model loader 3AC5F0); there is no FOV, resolution or quality factor.

Ownership: whose model is it

AnimationModel embedding offsets by owner class

Evidence: verified · Build: steam-5d11de53 · Fact ID: model-embed-offsets

Skeleton lookups and per-phase draw poses

Lookup a bone by skeleton name and index

Static, EDF5 steam-5d11de53. 5B5530(skeleton,wstring*) resolves a name in the std::map at skeleton+0xB0 and returns an index or −1; skeleton=[model+0x80]. Its world matrix is [model+0x90]+index*0x100+0xA0. Begaruta setup 35B100 stores index of head at +0xA4. Different helper 3AE660(model,out,list_index,key) resolves resource entry from [model+0x250] via 5C16F0, then uses the same name map to return an entry and bone pointer; fails when the resource name lacks a bone. The existence of 84 call sites does not mean each uses the same model layout beyond this interface.

Skinning consumes pose array rather than live bones

Static. 5AE170(inst) copies each 0x100-byte bone record's world matrix +0xA0..+0xDF into a 0x40-byte pose entry in [list+8]; AnimationModel post-update 3AE1D0 is one of 18 writers. 5AE1D0(inst,ctx,list) multiplies inverse bind matrices at bone-record +0x20 by pose entries for inst+0x20 bones, packs 3×4 rows into a 48-KB stack buffer and uploads via D3D11 UpdateSubresource (context slot +0x180) to the instance palette. For AnimationModel, instance begins model+0x80, records at [model+0x90] and draw poses at [model+0xB0]. Mesh rendering calls this upload before phases 0,1,2,3. Editing only the draw pose can alter a chosen phase's visual without moving bullet/muzzle/collision consumers of actual bones; no live hook experiment accompanies this reading.

Rigid and skinned LoD meshes share selected pose

Static. 5AC2F0(lod,ctx,phase,inst,list,flag) walks mesh list lod+0xA8 (or +0xC8 for phase 2); phase 3 returns when lod+0x60=0 (no shadow casters). A skinned mesh uses the uploaded palette [[inst+0x68]] as VS constant buffer 1 through VSSetConstantBuffers (slot +0x38, cache ctx+0xC78). A rigid mesh instead copies pose[mesh_bone] into [lod+0x78] through 97B30; then 5B2900/5B3000 draw. Rigid helmets and equipment therefore follow the same per-phase pose edits as skinned geometry.

Corrected Umbra object subclasses, including debris

Static RTTI/vtable correction. umbra::Object vtable E96650 has destructor and per-RenderPhase visibility/draw callback. It underlies stinger NeedleBullet01 (subobject +0x570, phase-2 draw callback 169A60), SpiderString, Acid/Flame bullets, ModelDebris, BulletMark decals, particle/line render objects, AnimationModel, sgmUmbraObject and crate DropItemManager::Unit (callback 19AD30). ModelDebris here means enemy/vehicle chunks, not the similarly named map-building crash-piece system; earlier wording conflating the two is superseded.

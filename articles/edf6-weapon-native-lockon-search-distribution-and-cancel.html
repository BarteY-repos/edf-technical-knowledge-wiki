EDF6 lock-on weapons: target search, multi-lock, firing and network cancellation

EDF 6Game technical referencesWeapons
Technical reference · Original source reports static binary/file analysis, with separately labelled contributor in-game tests; no new tests this release

EDF6's lock-on mechanic is a weapon-local target state machine, not just a circle drawn on the HUD. Its SGO describes target filters, cone, range, time, lock distribution and expiry. The surveyed source code tracks searching, an unfinished lock, a list of completed locks, shot assignment and network cancellation as distinct steps.

Weapon parameters

SGO key Meaning in the examined build
LockonType Chooses lock behavior; 0 and 5 are treated as no lock-on in the observed paths
LockonTargetType Determines candidate type; in a surveyed mapping 0 → search kind 3 (all), 1 → kind 2
Lockon_DistributionType 0 = target per burst shot; otherwise target per pellet
LockonAngle Horizontal and vertical half-angles, radians
LockonRange Maximum targeting range
LockonTime Duration converted to update ticks
LockonHoldTime Retention time of completed locks
LockonFailedTime Grace duration while target exits the cone, in frames
Lockon_AutoTimeOut Whether used/held locks automatically age out; internally an inverted flag
Lockon_FireEndToClear Lock list clears on a specific reload-start transition when enabled

Maximum lock count depends on distribution mode: in the surveyed computation, type 0 yields zero; distribution 0 uses min(AmmoCount, FireBurstCount) while the other path uses FireCount. Soldier equipment may apply separate multipliers for range, speed and repeated locking of the same target.

Search, progress, firing

The lock tick searches eligible registry targets only when not already locking one and the completed list is not full. The picker scores candidates in the cone. Lock progress grows in ticks; if the target leaves the cone the fail counter grows until expiry. A newly completed lock is appended to the list. This makes multi-target acquisition sequential rather than acquiring every target simultaneously.

The firing code refuses to fire a lock-required weapon if the list is empty. It then assigns locks to the created shots, taking older nodes first. In distribution mode 1 successive pellets use successive lock nodes, with excess pellets not necessarily receiving homing; in mode 0 multiple pellets in one shot can share that shot's selected target. Some lock nodes persist after firing, depending on AutoTimeOut and hold timers.

Online cancellation matters

The code sends a weapon network message type 6 when a lock fails or is cleared. The recipient clears its remote copy's active locking reference and progress. Without this notice, that remote copy can retain a ghost lock and skip the next new-target notice. This is a source-derived risk from the code paths, not a claim that every stock session suffers a visible ghost-lock bug.

EDF4.1 Queen Bee and Nephila in EDF6 — when identical class names have different attack semantics

ConversionCross-game ConversionGameplay & AIEDF 4.1EDF 6
Technical reference · Source-inherited exact-build binary RE, no new runtime execution

A class name is not a weapon contract

The retained EDF4.1 DLC insect compatibility code identifies two distinct differences that are invisible if a modder merely sees a matching EDF6 enemy class or a visually correct projectile. Its source compares native EDF41.exe routines against a particular EDF6 EDF.dll build and guards affected actors with explicit metadata keys. Unmarked native EDF6 insects are not meant to change.

Queen Bee — projectile speed depends on a small constant

In the examined EDF6 GiantBee needle setup, projectile speed is proportional to

speed6(L) = (L / 400 + 0.5) × 3

where L is the level value passed to that setup. The Queen Bee path multiplies the result by 1.5. The corresponding EDF4.1 class used +0.4, not +0.5, in the common term. When porting a DLC Queen Bee at comparable levels, preserving the same enemy model and projectile base type therefore changes how quickly and how far the needle travels.

The narrowly scoped fix scales the already computed native target speed by

factor = (L / 400 + source_base) / (L / 400 + 0.5)

with source_base=0.4 for the examined EDF4.1 queen. The source report describes observed differences around 15–23% in the DLC levels under study; this range must not be applied blindly at another level. Count, projectile life, damage and base spread were not changed in the same source comparison.

Diagnostic: if a converted Queen Bee seems to attack at the right intervals but its needles have unusual travel time/range, inspect the level-to-speed equation, not just the object or bullet SGO.

Nephila — positional and named parameters are not interchangeable

The studied Nephila02L and Nephila03L fire SpiderStringBullet01 threads. Its constructor seeds ten thread nodes with randomized velocities scaled by random_speed.

EDF4.1 read that number positionally from bullet_custom_param[0], and a DLC value of 0.01 yielded a tight, nearly straight thread. In the examined EDF6 path the constructor looks up random_speed by name in a variant supplied to the bullet. The studied Nephila passes a classic SGO node with a different tag; the lookup misses and uses the native default 0.5. The resulting thread spreads dramatically, despite keeping the old source numeric field in the enemy object.

The bridge carries the per-Nephila source value into the construction call for that one bullet type. It avoids replacing the default globally, because SpiderStringBullet02/03 also use the shared constructor but are not consumers of the same source parameter path in the inspected case.

This is an example of a deeper migration hazard: preserving the value is not sufficient when the consumer changes from an indexed lookup to a typed, named lookup.

Integration safeguards and evidence scope

The source uses exact-build guarded call sites. It applies the needle multiplier only to marked Queen Bees and the thread override only while a marked Nephila's bullet is being constructed; unrelated insects and thread types retain their native values. These are not universal patch addresses or proof of runtime compatibility on an updated game build.

Sources: EDF4.1 R10 HF4 R9 components/compatibility/src/edf41insects.cpp, with code comments citing the examined EDF41.exe and EDF6.dll routines. Findings are inherited source-backed RE, not newly executed game tests.

Weapon Parameters

EDF 6DocumentationGameplay & AIEDF 5
Technical reference · Community-provided Japanese memo; source-specific and not independently rerun

At a glance

What this page covers: EDF weapon data is spread across the weapon resource, WEAPONTABLE and localized WEAPONTEXT records; vehicles can add separate object, mounted-weapon and request records.

How to use it: Start with the resource map before editing a numeric value. A displayed statistic, an internal unit and the file that owns it may be different things.

Evidence boundary: The EDF5-to-EDF6 AmmoSpeed conversion noted below is version- and bullet-class-dependent. Do not apply it blindly to every projectile.

The game's weapon data is not stored in a single table. The weapon resource SGO, WEAPONTABLE.sgo, and localized WEAPONTEXT.??.sgo are separate layers. Vehicles add further distinction between the object, the mounted weapon and the vehicle request/weapon record.

Resource map

Resource Purpose Practical note
WEAPON/<weapon>.sgo Actual weapon and ammunition parameters Names and units are not necessarily unchanged across EDF 5 and EDF 6
WEAPON/WEAPONTABLE.sgo Internal identity, resource path, category, rarity, level, upgrade caps, restrictions Do not assume an imported weapon exists merely because its SGO was installed
WEAPON/WEAPONTEXT.??.sgo Localized display name, descriptions and formatted statistics Languages are stored separately; the exact internal mapping is not fully established in the source memo
OBJECT/<vehicle>.sgo Vehicle geometry/physics and durability Vehicle-specific durability may be defined here
WEAPON/<vehicle-mount>.sgo Weapon mounted on a vehicle, e.g. V_602HELI_GATLING01_L Similar broad form to soldier-weapon SGO
WEAPON/<vehicle-request>.sgo Vehicle call-in and multipliers Includes damage/armor multipliers and fuel-consumption rate

The notebook traces weapon names through WEAPONTABLE → weapon SGO path → localized name → WEAPONTEXT. It does not prove the internal game uses this as its sole runtime index. See also SGO/DSGO schema boundaries.

Fields and units

  • FireSpreadWidth denotes the full angular span between the outermost dispersed shots, not the angular gap between two adjacent shots (source: 解析 rows 25–26).
  • The source notes an EDF5→EDF6 difference for AmmoSpeed: EDF6 values can represent distance per frame rather than meters per second; at the observed 60 Hz convention, m/s = AmmoSpeed × 60. Check the bullet class before applying this conversion universally.
  • The sample WEAPONTABLE weapon-level value uses a ×25 scale. This is a sample interpretation in the memo, not an independently tested rule for every release/build.
  • In the sampled record, a smaller rarity parameter was reported to correspond to rarer drops; 1 is ordinary and 3 is used for DLC mission weapons. Do not assume all equipment follows the same economy table.
  • A display eligibility field can make a weapon's label red/white for underground or ruined missions. This display status is separate from the actual in-mission support/equipment restriction. See MissionPack underground support restrictions.

Compatibility pitfalls

The contributor reports that removing a weapon-adding mod while its added weapon remains equipped in a save could crash after selecting a MissionPack. Unequipped variants did not produce that observed crash. Treat this as a reproducible-case report, not a proof about every save format; avoid silently removing inventory entries or weapon definitions.

Version scope and evidence

EDF 5 / EDF 6: weapon-level and resource relationships are discussed. EDF 4.1: not independently validated by this workbook. The source is a community-authored research memo with experimental observations, not a formal Sandlot specification.

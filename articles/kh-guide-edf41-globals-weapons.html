EDF4.1 Engine Singletons, Weapon Fire and Bullet Objects

EDF 4.1Community Knowledge HubGameplay & AI
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

Native object ownership and weapon firing in EDF4.1 are distributed among game-global systems, weapon classes and bullet instances. The source’s constructor and virtual-method data helps locate lifecycles without assuming EDF6 class or allocator identity.

Format, API or behavior

The global builder constructs xgs engine services before recreating game singletons. Weapon_BasicShoot dispatches through a per-shot record and target weapon matrix; bullet objects have their own vtable/update behavior. A port must preserve the source-visible timing and ownership, not just the resource names.

Evidence and exact technical details

The following selected source observations retain their original evidence level and build-specific details. Follow their links for the complete evidence method, addresses and attribution.

Edf41 globals builder — static

3442B0 calls 341EC0, the builder of every game singleton. It first calls 5647F0 (at 3422DA), which builds the engine (xgs) systems, then for each global: calls the old object's virtual destructor (call [rax]), stores 0, allocates through the import _aligned_malloc [918698] (MSVCR120; size in ecx, alignment 0x10 in edx), calls the constructor, stores rax. The teardown functions store 0 into the same globals: 342F30 for the game singletons, 564BAA for the engine systems.

Edf41 global engine systems — static

CC89D0 xgs::umbra::System (constructor 5740A0, also stores SystemServices and GraphicsService); CC8518 xgs::debug::System (56BD20; its command table at +0x440 is the console's, sound.md#edf41-console-sound-commands); CC8528 xgs::game::System (5657B0; the object factory map, the physics world at +0x18, the four players at +0x1D8 stride 0x258, as other 4.1 lines read it); CC84A8 xgs::controller::System (55FD70). Built inline in helpers 5647F0 calls: CC8520 xgs::ui::System (565270), CC8530 xgs::havok::System (5651D0), CC8A80 xgs::user::SigninManager (565300).

Edf41 weapon shot — static

Shot (Weapon_BasicShoot slot 13 314D20) calls 30FC50(weapon, index, r8): returns for a remote copy's weapon; 30FD30 picks the per-shot record ([+0x158] + (index mod +0x168) x 0xA0) and aims it from the weapon matrix +0xE0 (311D70); online (room mode [CC84A0] +0x5C != 0, soldier-ai.md#edf41-ai-sync-message) it calls slot 23 and 311F70, which packs the shot for the network; then 30FDA0 spawns. The bullet class is the record's +0x10 when set, else the weapon's +0x5E0; the weapon's InitParam template +0x5F0 (motherships.md#edf41-bullet-initparam) is copied by 310B80 to the working block +0x720; the bullet spawns at 31052E through E6ED0([CC8528], matrix, class, block) (the block's +0x114 counts shots). The muzzle flash class +0x380 (effects.md#edf41-weapon-effect-keys) spawns at 3109DD.

Edf41 bullet update — static

BulletBase's primary vtable A93E48 has 11 slots: SceneObject's 10 plus slot 10 167C00, shared by the bullets read (online only: it returns unless room mode [CC84A0] +0x5C != 0; the network sync, unverified). Bullets override 0, 2 and 9 (SolidBullet01 A95B60: slot 0 162C10 copies the bullet's matrix to its scene node, slot 2 1A05B0 the update, slot 9 19FF30 the destructor; MissileBullet01 A948F0 likewise). SolidBullet01's update walks its hit list (+0x138, 0x50-byte entries, count +0x148): 1A00A0 per hit (hit effects through EffectGenUtil 1B6520..1B3E20), then 1A0320 (hit sounds, 3E83F0 / 3E8150 / 3E3F20); then it moves by the core's mode (core at +0xD0, mode at core +0x200: 0 16B010, 1 16B6B0, each with 10 callers in other bullet classes).

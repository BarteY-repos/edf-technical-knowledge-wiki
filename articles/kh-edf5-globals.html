Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-save-blocks

EDF5 save encryption key derivation

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-save-crypto

EDF5's save encryption: the save run builds two key strings, edf5 (DDC680) + a string from 5BBE30 + .sav (DDC670) and the same with .stm (DDC690), two Crypto++ AES ciphers (84D50, Rijndael encryption, vtable D33E80), derives with 85320 (MD5, CryptoPP::Weak1::MD5 vtable E92208 in 85800) and encrypts with 4377B0. Not read: what 5BBE30 returns, the cipher mode (4.1's is CTR, ../edf41/globals.md#edf41-save-crypto), the 0x20-byte header.

Basis: fn.py of 47F910..47FA20, 84D50, 85320, 85800; RTTI names by kh151_vtname.py

EDF5 language selection and lookup

EDF Knowledge Hub record — original wording — expand (1,301 characters)

The game's text language is the dword at 1137110 (0 ja, 1 en, 2 cn, 3 kr, the order of the locale code table DAB7C8), mirrored in the save object at [[125AB30]+0x245AC]; the voice language is a separate index at [[125AB30]+0x245A8]. 3E3100 (mov eax, [1137110]; ret) is the function registered for the script declaration int GetLanguage() (string EBE3B0, registration at 3DE513..3DE547). Writers: 69581 (mov [1137110], ebx, then mov [rax+0x245AC], ebx with rax = [125AB30]; the language change) and 89341 (copies [rsi+0x245AC] back into 1137110 right after 91E90 reads the saved config strings). About 25 readers, among them 8ABC6 and 3DF7A6, which pass it to the weapon table / weapon text loaders (file-formats.md#weapon-table-loading). 47D110 logs "ChangeLanguage %s->%s" (EC4F50) and compares the voice index [obj+0xB0] / [[125AB30]+0x245A8]; it rebuilds the voice and sound bank paths (tikyuu5_voice.%LOCALE%.awb). %LOCALE% (E8EAC0) is replaced by DAB7C8[index] (pointers to the wide strings ja en cn kr at E92F08, E92F00, E92F18, E92F10) in path templates such as app:/etc/TextTable_xbox.%LOCALE%.txt_sgo (E8FDD0), app:/Network/chat_message.%LOCALE%.sgo (E8FE30), app:/etc/EManual.%LOCALE%.sgo (EDAF68). The settings screen class is HUiHQLanguageSetting; its text keys are SystemOption_Language*.

Basis: disassembly with fn.py and a rip-relative reference scan; 3E3100 re-read with fn.py 2026-11-08. Not run in game: the value before the save's config is read is not known, and whether cn is simplified Chinese is not checked

EDF5 encrypted save header and field offsets

Per-file AES-256-CTR key and counter material

Static/offline editor verification, not in-game modified-save test. EDF5 saves use AES-256-CTR. For the file-name component, key is MD5(UTF-16LE("edf5" + filename + ".sav")) followed by fixed sixteen bytes Edf5.*_Steam_Ver; initial counter is MD5(UTF-16LE("edf5" + filename + ".stm")). This resembles EDF6 but uses different string prefixes and constants, so decrypted bytes are not cross-game interchangeable. The source editor decrypted/re-encrypted real EDF5 files offline; identifying return value from function 5BBE30 as filename remains an inference rather than a read call signature.

MDB0 header, checksum and account identity

Static/offline save comparison. Decrypted EDF5 header is 0x20 bytes with MDB0 at zero, bitwise NOT of CRC32C over data starting +0x20 at +0x0C, small counter at +0x10 (nonzero in some MAIN.GST files), and the owning account's full SteamID64 in eight bytes at +0x18. The editor/source notes say a mismatched account field presents as a corrupt save. EDF6's header is only 0x14 bytes; do not transplant EDF6 checksum coverage or identity offsets. Validation was against local EDF5 files and steam_autocloud.vdf, not a fresh account-switch experiment.

MAIN.GST, MST, TROPHY and COMMON field map

Static/editor tables; mixed direct diffs and cross-game inference. EDF5 payload offsets are generally EDF6's plus 0x0C due to the header difference. In MAIN.GST, per-class values at 0x20..0x2C, loadout slots from 0x50 (six per class, stride 0x18), armor counts at 0x140..0x14C, outfit colors from 0x168 and 2048×12-byte weapon records at 0x7D08. DEFP_M00.MST clear-byte rows begin 0x28 (second player 0xA28). TROPHY.DAT contains 39 event bytes at 0x20 and 71 named variables at 0xE8..0x200 (e.g. FrameCount 0x150, RangerArmor 0x1B8); COMMON.CFG profile name at 0x5000. Source confirms some values by save diff, but the complete trophy-event order is inferred from EDF6. This is a format map, not a warranty for arbitrary edited saves.

EDF6 Damage Event Pipeline and On-Screen Numbers

EDF 6Community Knowledge HubGameplay & AI
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

Damage numbers are presentation generated from native hit/damage events; they are not the same as the engine’s HP accounting. Some hit paths do not produce the same display event, so overlay mods can miss legitimate combat interactions.

Format, API or behavior

The source maps the built-in damage display and its option flag, event payload, style variants and missing-event cases. Separate damage-model analysis documents multipart targets and conversion paths. A mod should join these only where the event data explicitly supports it.

Native damage display — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (680 characters)

EDF6 has a native damage-number display (HUiHudDamage, one per player HUD). The options-menu setting Option_DamageUIType picks its style: 0 None, 1 HitPos (every hit at its point), 2 FixedPos (a fixed stacked list), 3 Target (one number per target); the code switches on it at 88E640 and 892463. FixedPos works almost exactly like EDF5 mods' fixed display: hits within a merge window add into the newest line, otherwise a new line is pushed; lines stack upward with the newest at the base; each line expires a set time after its last hit; a pop-in scale plays on every update; vehicles get their own size and optionally their own position, and soldier classes their own positions.

Native styles in game — verified

Vanilla's per-hit and per-target styles work with the patch's v0 red total next to them; vanilla's per-target style shows friendlies' numbers (v0 colored them red).

Damage option read — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (357 characters)

The option is stored per local player at *(int*)([20B2890] + playerIdx * 0x2800 + 0x334) (20B2890 = GameDataMgr, globals.md#global-pointers), playerIdx = character +0x338. The HUD settings routine 8224A0 re-reads it every frame into [HUD+0xC08] (the read at 8225D7); the constructor sets that cache to -1 (81DF81), so the style is set up on the first frame.

Damage event payload — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (586 characters)

After writing the target's HP, the damage function 547C30 builds the damage event on the stack (54820F-548231) and calls owner->vfunc[0xA8](&event) at 548236 (13 bytes: mov rax,[rcx]; lea rdx,[rbp]; call [rax+0xA8]; owner = the attacker, from source+0x10 through the handle converter 89D90, damage-model.md#handle-converter). Event: +00 attacker, +08 target, +10 source (the hit message), +18 float damage (negative), +20 text RGBA (white, constant 1765B90), +30 edge RGBA (black, constant 1765B30). The game's friendly-fire byte [rsp+0x20] is still valid at 54820F (re-read at 5483CD).

Damage event skips — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (328 characters)

No event for heals or the dead: when the base damage source+0x50 is below 0 (a heal), or the target's HP is already <= 0 and +0x2E9 == 0, the damage function branches to 548284, which sends no HUD event (it sends the heal credit instead, damage-model.md#heal-credit-message). So wrecks and dead targets never get native numbers.

Version notes and limitations

The presence of a hit handler is not proof that it passes through the common damage-number event. Any new overlay must be tested against armored bosses, multipart enemies, vehicles and host/client paths.

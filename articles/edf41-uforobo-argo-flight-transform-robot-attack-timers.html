EDF4.1 UfoRobo (Argo): flight, transformation, robot locomotion and attack-state timing

EDF 4.1Game technical referencesEnemy state machines
Technical reference · Source-scoped static analysis; no R129 gameplay test

The EDF4.1 giant Argo ship, internally UfoRobo, is not two unrelated NPCs swapped in a mission. The source describes one native game object and one object handle, with a body state machine and a higher-level AI state machine. Mission scripts can subscribe to the object's durability events before and after its transformation.

Script actions

ObjectAction Native meaning
0 Begin the transformation from flying ship to robot if alive; may be replayed
1 Enter the robot form immediately, using stand and approach behavior
2 Switch to approach behavior without performing the full transform

These are action IDs for EDF4.1 UfoRobo, not generic action IDs for other EDF enemies or the EDF6 MovingFortress.

Body-state sequence

State Behavior
S0–S3 Ship idle and successive small, medium and buster attacks
S4 Transforming; the cited native damage check makes this stage invulnerable
S5–S6 Falling into robot form and landing
S7 Robot main state: plan a step, turn or attack
S8–S9 Execute a step/turn or execute an attack
S10–S11 Death sequence, followed by a wreck state and deletion

In ship form, an AI steering state circles roughly 300–500 m from its target, about 250 m above it. Heading changes are constrained, and sideways slip is part of the flight behavior. The robot uses animation root motion, turned into the chosen world heading; a downward map ray keeps its feet aligned with the terrain during stepping.

Gun groups and pacing

Native gun data distinguishes the knee beam weapons (BeamBullet01), shoulder rocket volleys (RocketBullet01), large hand weapons and the annihilation cannon. Each group has idle, charging and firing phases. Source parameters include a roughly 300-frame buster charge, with subsequent shots spaced by 31 frames during the firing interval. Other guns run separate timers and have individual distance windows.

The robot's high-level state selects attacks by distance and angle windows in robo_attack_table. An attack switches the body to S9, and the AI does not return to movement planning until the body returns to S7. Consequently attack time does not count toward the ordinary movement-phase timers. The lengthy native animation clips help explain the boss's deliberate, stop-start walking tempo; they are not necessarily AI stalls.

The original static analysis also found a possible edge case: when no valid attack-table entry exists (for example a target beyond the allowed range), a fallback assigns an AI function into the body-state machine. The source author considered this a probable EDF4.1 bug; the wiki does not claim a newly reproduced crash or stuck state.

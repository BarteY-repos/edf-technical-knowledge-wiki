EDF4.1 friendly soldiers in EDF6: local spine axes, hand IK and climb-state deadlock

ConversionAnimationEDF 4.1EDF 6
Technical reference · Exact-build binary annotations and retained source conversion checks; no new two-game runtime test

A friendly Ranger, Fencer/HeavyArmor or Pale Wing from EDF4.1 may share an EDF6 native runtime class while preserving its own MDB skeleton, CAS animation and weapon model. The source investigation found three independent failure modes: a different local axis for torso aiming, an incomplete foreign-weapon IK chain, and a ledge-climb animation that can enter but never finish on older CAS assets. Those are runtime class semantics, not faults in file serialization.

Torso twist: human_direction_adjust is not an interchangeable number

The native human_direction_adjust key selects model spine bones and an axis mode for the target class to rotate toward the aim yaw. In the examined EDF6 implementation, mode 2 rotates around the bone's local X axis; the source's mode 1 rotates around local Y. The retained census found:

Studied model corpus Up-axis of spine bind matrix human_direction_adjust mode
EDF6 native soldiers, 101 sampled models local X 2
EDF4.1 native soldiers, 31 sampled models local Y 1

If a converter uses the target EDF6 default mode 2 with a preserved EDF4.1 spine, yaw aim becomes a forward/back bend instead of a torso twist. The safe source algorithm reads the bind-pose up-axis of the actual converted model and derives the matching mode rather than globally setting every imported soldier to 1. Mixed/ambiguous up-axes fail closed.

The stated 101/31 counts come from retained historical source annotations and were not independently re-censused against installed game assets in this release.

Hand grip and weapon animation form a chained transform

A source weapon's look, muzzle and hands depend on its own MDB/CAS/MAB and named IK locators. The analyzed native weapon-grip path composes transforms in the direction:

grab_frame × weapon_ik × weapon_node_world

A one-time wrist/bind correction cannot replace a per-frame, weapon-dependent animation IK producer. The retained investigations report 8–30 degrees of remaining grip mismatch when attempting that shortcut. For source-exact rendering, keep the correct weapon model and named animation/control transforms together and validate their actual class consumption.

Two target-only variables, v_vehicle_grip_l_ik_target and v_vehicle_grip_r_ik_target, are intentionally not grafted into EDF4.1 soldier CAS in this supported profile. The EDF6 native class checks whether their indices are -1 before writing them; the source CAS has no target IK consumer. Fabricating two dangling variables would not create a working IK chain, and naïvely copying donor tcontrol blocks would require correct index rebasing.

Why a soldier can freeze upright at a ledge

The target EDF6 climbing behavior can enter a ledge-climb native state for an NPC. Four named animation states are expected on the CAS main player:

common_elude_large_up
common_elude_middle_over
common_elude_middle_up
common_elude_small_up

The studied EDF4.1 soldier CAS has none of those four. If the target human_climb_settings remains active, a ledge test enters climb, tries to play a missing state (-1 index), and receives failure. The old walking/standing clip remains active, with an endless/looping end condition; the climb-state exit waits for that clip to finish. The soldier may therefore remain motionless indefinitely, apparently in an idle attention stance, while AI movements are ignored.

The bounded source fix removes human_climb_settings when all four named climb states are absent, restoring EDF4.1's non-climbing traversal. If only some states are present, it rejects the resource rather than forcing an arbitrary subset. Leaving the key absent is safe in the studied target build because the native climb readers are guarded by a null check; route exploration then reports zero climb height.

Only alias source motion to semantically equivalent target states

The retained CAS adapter synthesizes missing target state names using source animation states with matching roles: unarmed movement reuses source unarmed movement, knockout reuses down, bike rider reuses the source bike seat, and Ranger sprint uses the corresponding run clip. It does not invent ledge climbing, sword moves, jump-dash-lance actions or NPC talk gestures when EDF4.1 has no matching animation role. One-shot versus looping state types must remain coherent.

Evidence boundary: These rules are based on source code plus retained exact-build static reverse engineering and historical symptoms. This release does not contain new retail EDF6 NPC traversal or visual-IK tests. See friendly-NPC hybrid runtime, CAS and animation players, and MAB event identity.

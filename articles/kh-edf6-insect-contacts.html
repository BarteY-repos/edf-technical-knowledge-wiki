Facts

The insect contact query is 429B00 (size 0x365)

Evidence: static · Build: steam-678ccb46 · Fact ID: insect-query

The insect contact query is 429B00 (size 0x365). Its only direct caller is 431B80 (size 0x9BF), at 4322AC (mov rcx,rdi; call 429B00 with the insect in rdi); 431B80 is in no vtable and has no direct caller, and it lies just after the functions of GiantDango (vtables 17BDAC0 / 17BDCA0, whose slots run from 42A690 to 4304D0; the name suggests the pillbug, which the hub did not check). The query reads g_pCollisionFilter (20B2970, then 106030), builds a hit vector of entries 0xA0 bytes long and ends in the shared world query 542860.

Basis: direct-call scan of .text, vtable scan with RTTI, disassembly

Addresses (build-specific RVAs unless indicated): 429B00, 431B80, 4322AC, 542860, 20B2970, 106030

Attribution: EDF6SwarmPerf (call site and function prologue verified by its signatures), novae (ajane) · 2026-10-22

The world query 542860 (size 0xA7F) has five direct callers (2321B0, 429B00 at 429DD7, 542490, 542670, 5432E0)

Evidence: static · Build: steam-678ccb46 · Fact ID: world-query-loop

The world query 542860 (size 0xA7F) has five direct callers (2321B0, 429B00 at 429DD7, 542490, 542670, 5432E0). Its candidate loop (542CE0 to 543003) takes each body id from an int list, looks the body up (11AD2E0), calls a virtual function (+0x80) of the object at [r13+0x58]+0x20 with the id, gets the body's owner object with 108200, skips the candidate when the owner is null (542D22) or the querying object itself (cmp rax,[rbp+0x3b8] at 542D28, skip target 542FFC, continue target 542D35), and otherwise runs the narrow phase (11AA270) and, on a hit, appends an entry through 541FF0. The query's own object is therefore at [rbp+0x3b8] in this function.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 542860, 542CE0, 542D22, 542D28, 542D35, 542FFC, 11AD2E0, 108200, 11AA270, 541FF0

Attribution: EDF6SwarmPerf, novae (ajane) · 2026-10-22

Post-query weak object and team collision filtering

Evidence: static · Build: steam-678ccb46 · Fact ID: insect-hit-discard

After the query returns, 431B80 throws most hits away: for each 0xA0-byte entry it locks the entry's weak object, reads the team ids [insect+0x314] and [hit+0x314], and when neither is -1 keeps the hit only if the insect team's relation array holds 2 (hostile) for the hit's team (TeamManager[+0x38] + team*0x38 + 0x18, entry team*4; the compare is at 432328, the discard branch jne at 43232D). When one of the teams is -1 the entry goes on to the next check ([entry+0x98] non-zero). So hits against other insects and their corpses (same team) are computed in full and then dropped.

Basis: disassembly; relation values as in combat.md#team-relations

Addresses (build-specific RVAs unless indicated): 4322F1, 432314, 432328, 43232D, 20B2978

Attribution: EDF6SwarmPerf (verifies the bytes at 4322FB and 432314), novae (ajane) · 2026-10-22

EDF6SwarmPerf early team-filter optimization

Evidence: static · Build: steam-678ccb46 · Fact ID: swarmperf-filter

EDF6SwarmPerf's filter moves that team test in front of the narrow phase: at 542D28 it applies the same test (null team on either side: leave the candidate to the game; relation not 2: skip the candidate) and additionally skips candidates whose self-reference shared pointer (+0x28 / +0x30) is null. It acts only while the insect is inside the wrapped call at 4322AC (a plugin global holds the insect; the site is shared by the other four callers of 542860). The decoded stub is in File_Storage/Reference/EDF6_swarm_perf_mods_2026-10-22/SwarmPerf_filter_stub_decoded.txt.

Basis: the plugin's stub assembler run in an emulator and the bytes disassembled; the claim that gameplay is unchanged is the author's

Addresses (build-specific RVAs unless indicated): 542D28, 4322AC

Attribution: EDF6SwarmPerf, novae (ajane) · 2026-10-22

The speed-up (the author says a big FPS gain in large insect swarms) has not been measured by the hubSource: unverified

Evidence: unverified · Build: steam-678ccb46 · Fact ID: swarmperf-gain

The speed-up (the author says a big FPS gain in large insect swarms) has not been measured by the hub; the plugin's own counters (candidates, skipped_non_hostile, printed every 10 s at Log=2) are the way to see how many tests it saves.

Basis: the plugin README and log format

Attribution: EDF6SwarmPerf · 2026-10-22

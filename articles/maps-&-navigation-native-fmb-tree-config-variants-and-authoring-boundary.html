Native FMB tree, config variants and authoring boundary

EDF 6Maps & NavigationMaps
Source-backed research / case study · Exact native

Evidence level: Exact native read-only census + reconciled authoring boundary. The recovered native structure is stronger than older single-profile assumptions, but it is not yet a universal authored-writer/runtime-parity claim.

Native FMB is not one fixed 21-row profile

A later read-only EDF6 census compared five native HEIGEN FMB variants. The key result is that native FMB shader/config layout is family- and file-specific rather than globally fixed to one canonical table.

Observed native variants:

FMB Directory entries Geometry records Config rows Trailer
IG_HEIGEN507.FMB 511 255 type-0 + 256 type-2 27 1658 B / 54 strings
IG_HEIGEN507_ENKEIBOTTOM.FMB 239 119 type-0 + 120 type-2 21 none
IG_HEIGEN507_ENKEILEFT.FMB 235 117 type-0 + 118 type-2 21 none
IG_HEIGEN507_ENKEIRIGHT.FMB 235 117 type-0 + 118 type-2 21 none
IG_HEIGEN507_ENKEIUP.FMB 239 119 type-0 + 120 type-2 21 none

The four ENKEI directional variants can be reconciled against the 21-row ENKEIRIGHT profile only with config-index remapping in several cases. The full IG_HEIGEN507.FMB has six additional config rows and a non-empty string/resource trailer, so a strict unmodified 21-row authored parser is not a universal native parser/writer model.

Implementation rule: never hard-code “FMB has 21 shader config rows” or assume config index identity transfers between native files. Treat the config table and any dependent leaf binding as part of the exact file/family contract.

Recovered directory/tree contract

A separate native tree gate passed against CAVE503, HEIGEN ENKEIUP and full HEIGEN:

  • directory ordering is postorder;
  • tree-node anchors encode left/right subtree starts;
  • immediate child roots are derived from the node's recorded boundaries (b-1 and i-1 in the recovered contract);
  • parent AABB is the union of child AABBs;
  • tested native roots reconstruct from subtree start 0 with only float-scale AABB error.

This is useful structural authority for validation and source-owned tree generation. It supersedes treating the FMB directory as an opaque flat list or inferring the tree solely from record order without validating AABB closure.

Leaf capacity/config binding is semantic

The census found repeated leaf-capacity words bound to different config indices across native variants. For example, capacity words such as 514, 771 and 1028 recur, but their config-index assignments differ between ENKEI files.

Do not assume: a capacity word globally identifies one shader/config row. Preserve or derive the file-local binding table.

Trailer strings are not optional in every native family

The full HEIGEN file carries a 1658-byte trailer containing 54 strings (25 resource-like and 29 labels in the retained census). The directional ENKEI variants have no trailer.

Therefore a writer that always omits the trailer is only valid for profiles proven to omit it. Conversely, blindly cloning a trailer from another map family would be donor behavior, not source-derived authoring.

Authoring/runtime boundary

The R37 native census explicitly classified all five files as read-only native evidence and did not promote a new authored writer. Quickcheck coverage passed for the sampled native variants, but runtime was not tested and full parity was not claimed.

Use the recovered tree/config/trailer rules to:

  1. reject structurally impossible authored FMBs;
  2. avoid fixed-index assumptions;
  3. generate profile-aware trees/config bindings;
  4. compare authored output against the correct native family.

Do not infer from this census that arbitrary FMB authoring is runtime-closed, that all native variants are exhausted, or that one HEIGEN config table is a universal EDF6 terrain ABI.

Binary FMB envelope and compressed wrapper offsets

The independent FMB binary record reference describes the measured FMB\0 header, directory offset table, compressed CMPL wrappers and decoded +0x58 config-byte caveat. It explains why the native variant census above is incompatible with unconditional config-index copying.

Material projection indices are separately bound

The retained native ENKEIRIGHT material 0 profile directly demonstrates the (0,1) orientation pair and distinct color/detail texture-array slices. A writer or reader that normalizes both projections to orientation 0 loses information, even if the 21-row config-table family is correct.

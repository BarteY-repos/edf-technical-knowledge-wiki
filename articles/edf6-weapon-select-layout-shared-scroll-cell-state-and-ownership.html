EDF6 equipment screen: native layout, five rows, shared scrolling and weapon-cell states

EDF 6Game technical referencesNative user interface
Technical reference · Source-scoped static analysis with contributor runtime marked; no new R129 game test

The original equipment selection screen loads app:/ui/lyt_HUiHQWeaponSelect.sgo from the resource archive. Its SGO identifies the HUiHQWeaponSelect native class and contains named visual templates; the C++ constructor instantiates one column for each weapon category and fills each column with entries owned by the current player.

Why five rows appear

The viewport WeaponSelectArea has a 201-pixel height. Each WeaponSel_CellBase row is 40 pixels tall. Therefore five complete rows fit in view (201 / 40). This is an SGO layout fact, not a native loop hard-coded to render exactly five entries. A parent stencil clips overflow. The basic column is 355×201 pixels, and the level/quality subcells sit in separate 43-pixel-wide areas.

The columns scroll together

The constructor locates whichever category column has the most cells, creates the vertical scroll information on that column, and shares its ScrollInfo object with all other columns. This is why the stock equipment categories scroll in unison even when they contain different numbers of weapons. The source identifies scroll-margin fields for focus and display; the generic mouse hit test has separate clipping and does not simply apply those margins as-is.

Weapon cell status bits

Cell flag Readable behavior in the studied build
Bit 0 Online above-cap level; red text
Bit 1 Weapon already equipped in another slot; gray/disabled
Bit 2 The corresponding content pack is not owned; dark red/disabled

The confirmation handler rejects (cell+0x54 & 6), i.e. bits 1 or 2. It does not reject bit 0. Thus the red online cap mark is informational at weapon-selection time, whereas a duplicate slot or missing content entitlement disables the selection.

The source ties bit 2 to the content-pack field in WEAPONTABLE, not simply to the weapon's category. For weapons that can be equipped, the selected weapon ID is written into the current class's saved slot area; current-class and displayed-class indexes are distinct screen state.

Layout and mouse behavior are separate

The HUi generic button hit test walks the element's rectangle, parent clipping and scroll offset. The source identifies a few-pixel vertical strip that remains outside the interactive area at the edges of a scrolled cell. That is an input hit-test boundary rather than an absence of visible rows. Exact offsets are specific to steam-678ccb46.

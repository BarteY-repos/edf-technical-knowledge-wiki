Source-game audio roles identified; target playback remains unqualified

DragonBig401 source attack state reconstruction now explains which MAB fire events (火炎開始 / 火炎終了) drive FlameBullet02, the named muzzle locator and the glide-versus-hover behavior. These findings establish the gameplay-event route. Later native-source SGO/EXE analysis (R14) and exact source/target audio comparisons (R17, both 15 November 2026) did recover the source cue → preset → bank roles. Runtime equivalence of playback, timing and spatial attachment in EDF6 remains untested.

Five original EDF4.1 sound roles and their resource identity

Static native evidence: DRAGONBIG401.SGO (SHA-256 f699efd0ff65c8fb43a9a3704276bde71bc533f515601980eaec0834ab7382c1) points to shared bank app:/sound/adx/tikyuu4_en_Dragon.acb; a corresponding dragon sound bank was found in the examined EDF6 resource tree. The EDF4.1 DragonBig damage handler plays source slot 0 as the hit effect; it has no distinct small-dragon-style hurt-roar slot. An examined pass-by path includes a target-plane Y adjustment of +30.0; static reconstruction distinguishes its attack/flame activity and target-plane crossing conditions, while actual audio playback remains a separate runtime question.

Why the EDF6 DragonSmall slots are not a direct 1:1 copy

The examined EDF6 donor DragonSmall family has nine sound table slots of 0x80 bytes per entry, whereas the source role offsets above advance by 0x40. Its native timed hit/death/blood consumers use slots 1, 2, 3. Critically, the target's slot 0 is an extra small-dragon hurt-roar (ドラゴン小ｖダメージ大) reached on damage subject to an 8-frame cooldown. This target-only role has no corresponding source DragonBig401 se_table entry, so blindly copying names or leaving the donor slot 0 audible can create a false hurt sound.

The later R17 compatibility audit describes installing source hit/death/blood at target slots 1/2/3 and using a valid silent native sound-preset object in target slot 0, with the native cooldown and other target slots retained. This is source-only static reconciliation, not a confirmed EDF6 game fix. The pass-by, impact and ragdoll-contact actions use their distinct paths and must not be conflated with the target slots 1/2/3. R14 reported 44/44 static checks; R17 reported 108/108 static checks. Neither is an in-game sound test.

What remains open

Exact runtime cue audibility, simultaneous sounds, event timing and positional attachment still require a game test. Source/target identities do not prove that all native consumers are reached in the converted object. Some target-only sound slots and their reachability remain unqualified. Preserve this boundary; avoid calling the original source audio routing unknown now that R17 has resolved its static structure.

Important negative rule

The absence of a dedicated DragonBig401.ACB/AWB is not evidence that the sounds cannot be restored.

EDF objects can route named events through shared presets and shared banks. Before inventing a new bank or declaring the source sound absent, trace the preset/name lookup chain.

Relationship to Audio R5

Audio R5 establishes the broader source-only MissionBundle audio contracts: source input ownership, bank/table handling, suffix normalization and redistribution boundaries.

DragonBig401 is an object-specific audio event with statically recovered sound roles and a remaining EDF6 runtime/audio-semantic gate. It is distinct from the general voice/subtitle table pipeline.

Evidence boundary

The exact source-side sound-role mapping is statically recovered; no target gameplay playback is claimed. The historical discovery that no dedicated DragonBig401.ACB was present must not be misread as evidence of missing audio.

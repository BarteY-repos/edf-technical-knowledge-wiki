Multi-weapon parent and child weapons (key: hector_weapon / humanoid_base_weapon_ex)

  • edf41: Hector (a GameObjectBase, not a Humanoid) carries two hector_weapon records; the parent sets a one-frame request byte per child (+0xF1) and each Hector_WeaponBase child fires on its own | ref: edf41/enemies.md#hector-weapon-records, #hector-fire-arbitration, #hector-weaponbase | evidence: static
  • edf5: not researched in the hub | ref: none | evidence: unverified
  • edf6: Humanoid families (Martian, Venus) keep a humanoid_base_weapon_ex vector at Humanoid+0x1120 (count +0x1130); the update builds a per-slot bitmask and sends message 0x11; the receiver 4740B0 calls virtual +0x78 on each selected child (EDF6_MartianWeapon_Basic, EDF6_SoftBodyWeapon_Shield) | ref: edf6/enemies.md#humanoid-weapon-ex-list and #humanoid-fire-mask-message, edf6/classes.md#humanoid-weapon-ex-dispatch | evidence: static
  • Differences noticed: same idea (parent arbitrates, children fire), different mechanism: EDF 4.1 writes child request bytes directly; EDF6 routes through a message the network layer also carries. Mount nodes match (arms_l/r; EDF6's Frog uses weapon_node = "arms_r"), but EDF6 has no counterpart to Hector's driven shoulder articulation (shoulder_l1/r1).
  • Confidence in the mapping: medium (static on both sides; the port design was not run).
  • Added: 2026-10-15 src: EDF41-to-EDF6 handoff (shared by Bartey), carrier audit

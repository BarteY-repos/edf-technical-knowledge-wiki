GameObjectBase class layout (key: RTTI .?AVGameObjectBase@@)

  • edf41: GameObjectBase -> SceneObject, NetworkObject at +0xB0, 28-slot primary vtable; Hector, Monster501, Deiroi derive directly, GiantAnt via InsectBase | ref: edf41/enemies.md#gameobjectbase-hierarchy, #enemy-vtables | evidence: static
  • edf5: present in RTTI chains such as GiantSpider : InsectBase : GameObjectBase : SceneObject and SoldierBase's bases; MapObject classes show a NetworkObject vtable at +0xC0 | ref: edf5/models.md#animationmodel-draw-callback, #models-soldierbase-bases, edf5/map-objects.md#mapobject-primary-vtables, edf5/methods/recipes.md section 6 (__RTDynamicCast from GameObjectBase to SoldierBase) | evidence: static
  • edf6: GameObjectBase -> SceneObject -> IRecordable (snapshot), NetworkObject at +0x120; ctor 545670, snapshot writer 54B010 (vtable slot 0; per-frame update slot 5 54BE40); Monster501 now via MonsterBase | ref: edf6/classes.md, edf6/objects.md#gameobjectbase-functions, edf6/objects.md#fn-54b010-snapshot | evidence: static
  • Differences noticed: EDF6 adds the snapshot interface (xgs::snapshot::IRecordable, used by the DSGO world snapshot, edf6/online.md) and moves NetworkObject from +0xB0 to +0x120. Offsets inside derived classes therefore differ between games; never reuse one game's offsets in another.
  • Confidence in the mapping: high for the class identity (same RTTI names), low for any field-level correspondence.
  • Added: 2026-10-15 src: EDF41-to-EDF6 handoff (shared by Bartey), Hector RTTI audit, novae (ajane)

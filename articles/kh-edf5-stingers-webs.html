Bee stingers (NeedleBullet01)

The only needle ammo class in the exe is NeedleBullet01

Evidence: static · Build: steam-5d11de53 · Fact ID: stinger-callback

The only needle ammo class in the exe is NeedleBullet01; its Umbra subobject sits at needle+0x570 and its draw callback 169A60 (referenced only by the vtable E9AAD8) draws when phase == 2 (cmp/jne, 10 bytes). Queen stingers should go through the same callback (different AmmoSize, possibly another draw mode; unverified).

Basis: RTTI and cross-references

Addresses (build-specific RVAs unless indicated): 169A60, E9AAD8

Stinger mesh transform and impact placement

Evidence: static · Build: steam-5d11de53 · Fact ID: stinger-geometry

Stinger geometry: the draw matrix is umbra+0x1A0..+0x1DF (needle+0x710, copied from the bullet transform by 1694B0; Z axis row at umbra+0x1C0, position at umbra+0x1D0); the segment is pos +- Z25AmmoSize (AmmoSize at needle+0x374; the same 25.0 sizes the Umbra box); the model is scaled uniformly by AmmoSize (diagonal matrix built at 169B2A), and the line uses AmmoSize for both length and width, so AmmoSize scales both draw modes. Draw mode needle+0x750 comes from data (Ammo_CustomParameter[0]): 0 = stretched line 5EDBC0, 1 = model; which mode bees use is unverified.

Stinger transparency via vertex color

Evidence: verified · Build: steam-5d11de53 · Fact ID: stinger-draw-and-fade

Stingers can be faded by changing the color they load, because they draw with the alpha-blending draw-utility effects (shaders.md#shaders-draw-utility-alpha): in model mode the 16 bytes loaded at 169B36 (movaps xmm0,[rip -> EE7920 = 1,1,1,1], copied into the cbuffer at 169D5A), in line mode the ammo color alpha at needle+0x390..+0x39C. Depth write must be turned off while faded (the two 7-byte sites 169BE4 / 169C19).

Basis: novae (ajane)

Addresses (build-specific RVAs unless indicated): 169B36, EE7920, 169D5A, 169BE4, 169C19

Attribution: novae (ajane), session 2 · 2026-10-04

Model path: draw-utility slot 12 g_effect_texture_color_lighting

Evidence: static · Build: steam-5d11de53 · Fact ID: stinger-draw-paths

Model path: draw-utility slot 12 g_effect_texture_color_lighting; its forward pixel shader E40800 computes o0.a = sat(fog) * sat(tex.a * g_color.a * vcolor.a), with g_color in cbuffer xgl_user_param; depth write is on. Line path (5EDBC0, slots 21/22 ext_line): pixel alpha includes the vertex color, which is the ammo color at needle+0x390..+0x39C (umbra-0x1E0..-0x1D4); depth write is already off for lines.

Basis: disassembly and the project's dxbc.py

Stuck-stinger post-lifetime fadeout countdown

Evidence: static · Build: steam-5d11de53 · Fact ID: stinger-removal-timer

Once a stuck stinger's lifetime ([+0x3F8]) ends, it counts [+0x62C] down from 300 frames and is removed at 0 (169A12); unstuck expired stingers are still removed. TestStingersForever_v01 changes lea eax,[rdx-1] to [rdx+0] so stuck stingers stay (not tested in game).

Spider webs (SpiderStringBullet01 / 02)

SpiderStringBullet classes and draw callback

Evidence: verified · Build: steam-5d11de53 · Fact ID: web-classes-and-types

Spider webs are SpiderStringBullet01 (vtable E9C680, Umbra vtable E9C638, draw callback 18C3A0) and SpiderStringBullet02 (E9C850 / E9C808, callback 18E5B0); the Umbra object is at bullet+0x5F0. Beta (red spider) webs are type 02; Aranea webs are type 01 (the type whose stuck-to-player red blink points at the Aranea pulling you). Unlike the needle, both callbacks run in every render phase: phase 2 blended with no depth write and alpha test 0.001, the other phases opaque with depth write and alpha test 0.5 (material +0x20). Each draws one line strip with 5EE2A0, whose 7th argument is a 56-byte material (g_material); the effect is ext_line_lighting_material (slot 23); pixel alpha = tex.a * g_color.a (1,1,1,1 from 5EE419, shared by all callers) * vertex.a * fog.

Basis: static (session 2); novae (ajane)

Addresses (build-specific RVAs unless indicated): E9C680, E9C638, 18C3A0, E9C850, E9C808, 18E5B0, 5EE2A0, 5EE419

Attribution: novae (ajane), session 2 and v04-v05 results · 2026-10-04

The web's update 18BD30: with the owner gone (+0x318 expired) every grab is released (18DC20 on the list +0x650)

Web bullet head and segment collision

Registered bullet head with unchanged core fields

Static, EDF5 steam-5d11de53. Web base constructor 1894B0 calls BulletBase ctor 1411E0 with register flag r8b=1, registering the web's bullet core at +0xE0 through 142380. Base update 189C20 moves it using 144670; a write scan over web code found no modifications of core +0xE0..+0x56F (nearby writes are to grab objects). The conclusion that the head normally collides with map walls and ends at its first contact follows similarities to EDF4.1/EDF6 but is unverified in EDF5; its BulletMtSystem step was not read.

Thread body collector excludes map collision layers

Static. Web constructor 1894B0 installs a hit_query::TargetCollector at +0x570 (vtable E93A58, filter from [125AB98]+8), query kind 0xB at +0x580, callback 189A70 and web state +0x598/+0x5A0. Collector slot AB890 accepts bodies only if filter helper 7155F0 allows collision. Layer 11 can meet 5–9 and 14 but excludes static map-body layers 15, 17 and 20. This explains why a web segment's candidate set cannot itself use a map wall as an occluder.

Every-fourth rope-segment AABB and sphere cast

Static. In thread update 189C20, only node-segments i&3 == +0x5D0&3 are tested, skipping either node's stuck state at +0x30. Nodes are 0x80 apart at +0x5B8 (count +0x5C8). Each eligible segment forms an AABB and asks world query slot 0xE8 for candidates into collector +0x570; when nonempty, sphere-casts radius +0x374 using AC3F0 for closest body hit. Only bodies with property key 0 in their +0xB8/+0xC0 property list proceed to damage message 18A388..18A428, sent before virtual hit slot 11 18A503. This is distinct from the projectile-head BulletMtSystem collision.

Through-wall snag hypothesis and its unresolved branches

Source: unverified inference, not gameplay-tested. Because segment candidate collision layers exclude map geometry, a wall between thread and soldier is not an occlusion blocker for this sphere cast. No separate world query was found among 189C20's decoded calls, suggesting rope nodes may not stop at walls either, as in EDF4.1 and EDF6. However helpers 18A5C0, 18A7B0 and 189440 were not decoded; they could affect remaining boundary behavior. Do not promote this interpretation to verified in-game web penetration.

Beta spider projectile uses the same segment hit routing

Static. SpiderStringBullet02 (vtable E9C850) calls base 1894B0 in ctor 18DF30. Its update slot 2 18E580 invokes shared segment update 189C20 and destroys the object with 617B30 once +0x358 no longer exceeds +0x3F0. Its hit callback slot 11 is the do-nothing 23390, preventing grab/capture, but the shared segment routine dispatches damage before this callback. Accordingly a Beta thread can damage even without catching; the specific behind-wall case follows the unverified occlusion inference above.

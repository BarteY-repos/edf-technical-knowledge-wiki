EDF6 accessory ragdolls: cloth, hair, joint chains and simulation ownership

EDF 6Game technical referencesPhysics
Technical reference · Original source reports static binary/file analysis, with separately labelled contributor in-game tests; no new tests this release

EDF6's swaying clothes, hair and similar body attachments can use an accessory_ragdoll declaration inside the character's SGO model settings. This system is distinct from the normal animated body ragdoll: the game spawns accessory physics bodies, attaches them to a bone chain and updates them from particular character classes.

The actual data relationship

The observed SGO value is a four-part group: maximum camera distance, per-part motion table, accessory SHKT path, and an embedded bone-mapping SGO. Across 39 source SGOs declaring accessories, the declaration occupies animation_model[4], before effect and outside the inner [mrab, mdb, LOD] model-file tuple. The source corpus always uses a 20-metre max distance, not a per-file mix of lengths.

Placing the group inside the model-file tuple can make the game interpret it as LOD data instead. The source investigator observed crashes or silent omission, depending on tuple length; those are reported game experiments, not inferred from an editor's UI.

Why accessories move for some classes but not others

AnimationModel::LoadFromSGO constructs the accessory (source RVA 0x6B4FB0), but the actual AccessoryRagdoll::Update (0x6B61D0) is reached through HumanBase::OnUpdate in the examined code. This explains why human-derived soldier classes have moving accessories while a constructed accessory on an ant or frog can remain stationary or at its spawn position. The contributor reports working movement for Ranger and Wing Diver attachments; HeavyArmor/Engineer share the code path but were not separately confirmed in their game test.

The accessory loader puts its bodies on collision layer 23 at runtime. The motion table in SGO, rather than SHKT's default physics fields, supplies damping, gravity factor, friction, restitution and a collision toggle. One contributor-verified working example used linear damping 0, angular damping 0.1, gravity factor 1, friction 0.08, restitution 0.5 and collision 0. It is an example, not a universally recommended or default profile.

Root-body chains and attachment stability

An accessory SHKT must include the fixed root-side bodies that form a connected joint chain to the parts intended to sway. Adding only the moving tip bodies can leave an insect's antennae invisible while alive or stranded where the model spawned. The contributor tested a Ranger arm chain and Wing Diver booster arms with root bodies: both remained attached and moved.

The game data includes accessory SHKTs for both older and EDF6 soldier outfits. A source inventory notes all six surveyed *_ACCESSORY.SHKT bodies have motionType = 2 (dynamic). Their being dynamic in a file does not imply the same update method runs for a non-human enemy.

Interpretation boundary

An SGO declaration being parsed is not proof that the attachment will sway for every enemy class. The exact 20 m value, placement census and loader path are source data; sway/visibility examples are ktaro's in-game observations. Repeating them under another EDF.dll build, another rig or online mode has not been done here.

Classes and textures

Effect classes (RTTI): the generator EffectGenUtil (a Singleton)

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effect-classes

Effect classes (RTTI): the generator EffectGenUtil (a Singleton); effect objects ParticleObject (ParticleEmitterCore, ParticleRender), LineParticleObject (LineParticleEmitterCore, LineParticleRender), LineStripObject (LineStripEmitterCore), StencilLight, PointLight, SpotEffect, GlassClashEffect, ClaySplashEffect, LeafFallEffect, UfoRoboCanonChargeEffect, EffectShockWave, MapDestoryEffectBase / MapDestoryEffect_Test, TreeModel_Particle; EffectLimitter pools for ParticleObject, LineParticleObject, StencilLight and GlassClashEffect. No class with "effect", "particle" or "debris" in its name matches EDF5's ModelDebris, LinkLineEffect, gunbattery::ChargeEffect, EventParticle, EnemySpawnEffect, the humanoid part effects or the full-screen weather managers.

Basis: an RTTI name scan of EDF41.exe (kh151_rtti_list.py, effect / particle / emitter / light / muzzle / flash / snow / rain / debris / spark / blaze / explosion / shock: 123 names, the Havok ones aside)

EffectGenUtil lifetime and scene setup

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effectgenutil

EffectGenUtil lives at [CC8500] (239 code references): the scene init 341EC0 (called from 3442B0) frees the old one, allocates 0x40 bytes and runs the constructor 1B12B0, which writes the vtable A96180 and loads app:/Effect/basic.rab (kept at +8) and app:/Effect/light.rab (+0x18). GetTexture 1B1490(util, out, name) looks the name up in basic.rab's Texture folder and logs EffectGenUtil::GetTexture( not found. : %ls ) on a miss; GetLightTexture 1B1520 does the same in light.rab (EffectGenUtil::GetLightTexture( not found. ...). EDF5's counterpart: [125ABA0], constructor 1AC850, 1ACA80, 1ACB10.

Basis: the two .rab strings' and the log strings' only references; fn.py of 341EC0 around 342A2B (fn.py labels CC8500 with an unrelated id that merely lists it)

Addresses (build-specific RVAs unless indicated): CC8500, 341EC0, 3442B0, 1B12B0, A96180, 1B1490, 1B1520

Effect texture archives and paths

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effect-textures

Effect textures come from app:/Effect/basic.rab and light.rab (EffectGenUtil) and app:/Effect/Hud.rab (read in 3FFAB0); the string app:/Effect/spider.rab is present with no direct code reference found. EDF41.exe holds no Decal.rab and no string containing "decal": EDF5's decal manager, its explosion mark and its death-pool decal have no 4.1 counterpart. Code names textures by file name: 火炎_01.dds (flame), 煙_01.dds (smoke), spark_01.dds, Particle3_k.dds, BloodSplash_01.dds, 土砂_01.dds (earth and sand), 建物へ着弾_破片_01.DDS (fragments of a hit on a building); some use a full path such as APP:\EFFECT\BASIC.RAB@血飛沫_01.dds (blood spray). Replacing a texture inside basic.rab changes every effect that names it; shapes, counts and colors stay in code.

Basis: exe_strfind.py on Effect/, EFFECT, decal, Decal; the strings' references with fn.py --xref

Addresses (build-specific RVAs unless indicated): 3FFAB0

EDF 4.1 has no effect_test console command

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effectgenutil-calls

EDF 4.1 has no effect_test console command; its particle_test (handler B9770, registered in C07C0) calls all seven effect factories and 19 EffectGenUtil members. The members, in address order, with their textures: 1B16B0 (火炎_01, one ParticleObject), 1B1910 (火炎_01), 1B1BA0 (煙_01, 火炎_01), 1B2070 (two ParticleObjects, the first with 火炎_01 and 煙_01, the second 火炎_01), 1B2AB0 (no texture; calls 1B2D90 and 1B1BA0), 1B2D90 (煙_01), 1B3060 and 1B32E0 (BASIC.RAB@煙_01), 1B34F0 and 1B3AC0 (BASIC.RAB@血飛沫_01), 1B37C0 (BloodSplash_01, a LineParticleObject).

Basis: kh152_fnlist.py edf41 1B15A0 1B7710 (each function's textures and its calls to GetTexture and the factories); particle_test's call list

Addresses (build-specific RVAs unless indicated): B9770, C07C0, 1B16B0, 1B1910, 1B1BA0, 1B2070, 1B2AB0, 1B2D90, 1B3060, 1B32E0, 1B34F0, 1B3AC0, 1B37C0

Flame particle InitParam construction

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-particle-spawn

A particle effect is built as in EDF5: Flame (1B16B0) fills a ParticleObject InitParam with 1C1920 (EDF5's 1C66B0), sets its texture from GetTexture 1B1490, then calls the factory C5BB0(game system [CC8528], matrix C5E730, InitParam). 4.1's factories take three arguments (EDF5's 77790 four) and store the matrix pointer at the InitParam's +8. The ParticleObject InitParam vtable has 32 code references, enemy, vehicle and mothership code among them.

Basis: fn.py of 1B16B0 and C5BB0; xref of A90488

Addresses (build-specific RVAs unless indicated): 1B16B0, 1C1920, 1B1490, C5BB0, CC8528, C5E730

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effect-factories

The effect-object factories sit together (EDF5's 77790..78610, the same order): C5BB0 ParticleObject (new 0x3B0, constructor 1C2FE0, 32 callers), C5D50 LeafFallEffect (0x230, 1B93A0, 2), C5EF0 LineParticleObject (0x370, 1BBF00, 14), C6090 GlassClashEffect (0x900, 1B7710, 2), C6230 StencilLight (0x200, 1C4A20, 4), C63D0 UfoRoboCanonChargeEffect (0x540, 1C51C0) and C6570 LineStripObject (0x360, 1BD8C0), the last two called only by particle_test. Basis: each factory's allocation size and constructor call read with fn.py; caller counts by fn.py --xref

SGO keys that choose effects

Weapons: the weapon SGO reader 30AB70 (callers 3148B0, 315060, 3163F0

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weapon-effect-keys

Weapons: the weapon SGO reader 30AB70 (callers 3148B0, 315060, 3163F0; EDF5's 38C010) reads MuzzleFlash as a class name, looked up with 568560(game system [CC8528], name) (the class-factory map at +0x80, EDF5's 6136C0), kept at weapon +0x380 (+0x3B0 the weapon, +0x3B8 0; empty means none); MuzzleFlash_CustomParameter's node goes to +0x3C0. The same reader takes ShellCase (a .shkt model) with ShellCase_CustomParameter and ShellCaseDischargeSe, and the bullet's AmmoClass, AmmoColor, AmmoSize, AmmoModel and Ammo_CustomParameter, among its other keys.

Basis: fn.py of 30CBA1..30CC45 and 568560; the reader's strings listed with kh149_fnstr.py

Addresses (build-specific RVAs unless indicated): 30AB70, 3148B0, 315060, 3163F0, 568560, CC8528

Effect level, weather and debug commands

Console effect quality setting

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-effect-level-weather

The console command set_effect_level (handler BDE20, registered in C07C0) takes low, middle or high and writes 2, 1 or 0 to [CBCFC0]; fn.py finds no code that reads [CBCFC0] (a read through a register or a table would not show). The other effect commands: particle_test, light_color, light_vector. EDF 4.1 has none of EDF5's effect_test, decal_* or enviroment_snow / enviroment_rain commands, and no snow or rain manager (no Snowflake, Raindrop or full-screen particle names). A map's weather is a WeatherTable key read beside MapTable in 154960 (2 callers) and map::sync::weather_resource (in FE090, map-objects.md#edf41-mapb-record); not followed.

Basis: fn.py of BDE20 and --xref of CBCFC0; the console table's strings from kh152_fnlist.py; exe_strfind.py

Addresses (build-specific RVAs unless indicated): BDE20, C07C0, CBCFC0, 154960, FE090

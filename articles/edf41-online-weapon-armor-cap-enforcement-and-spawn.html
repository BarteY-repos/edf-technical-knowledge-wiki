EDF4.1 online weapon limits: selection refusal and armor at mission start

EDF 4.1Game technical referencesOnline caps
Technical reference · Build-scoped static analysis; original contributor evidence grades cited; no new R126 gameplay runtime

EDF4.1's weapon-level restriction and armor limit travel through different code paths. The restriction shown in the HQ weapon list is not identical to the armor value applied when the host starts an online mission. Neither should be inferred from offline mission settings.

ModeList and cap-state ownership

The original config.sgo ModeList main offline scenario carries zero for per-difficulty entries 6 and 7; its online-mode flag at node +0x5C is zero. The cap getters therefore return a no-cap condition. The cap tables for every separate offline DLC mode were not independently re-read in the source note.

For the examined Steam build, the session update at 0x377CD0 derives a weapon-cap-enabled byte from the room's weapon-limit switch and the current cap. The saved state flag is save+0xA7D5; the room's weapon and armor switches occupy distinct fields. Game notices OnlineSys_WeaponCapLock/Unlock and OnlineSys_ArmorCapLock/Unlock mirror these changes. The armor notice converts the room's armor-box limit into a displayed class-dependent HP value.

Above-cap weapons cannot be confirmed in EDF4.1

A weapon beyond the cap is marked in the equipment screen and its text is rendered red. The UiHQEquipment_SelectWeapon confirm handler checks the over-cap marker and skips the selection. This is an important cross-generation difference: EDF5 and EDF6 also color above-cap levels red, but their equipment confirmation handlers do not reject on that marker alone.

Stage Original EDF4.1 behavior in the studied build
Display weapon above cap Red text, flagged cell
Confirm that weapon Rejected by selection-handler check
Host prepares online start Serializes a per-player equipment record with a capped armor-box value
Spawn in online mode Uses the received armor count and the class's per-box coefficient
Spawn in offline mode Uses the local save's armor boxes, without online cap

The host's start-message writer chooses min(cap, boxes) if the armor cap is active. The resulting HP follows base HP + capped boxes × class HP-per-box coefficient. The offline branch reads the saved armor count instead. This confirms the cap is enforced in the launch/spawn path, not simply by changing a menu label.

What is not established

This analysis does not prove a safe general method to activate online restrictions offline, nor does it test any patch. It is specific to steam-57aab039. The underlying room-message receive code was not fully read for one record-layout inference.

RMPA — route, shape, camera and spawn resource families

File FormatsSource-scoped referenceEDF 5EDF 6
Reader-oriented technical reference · Existing research only · Version-specific profiles, where documented

RMPA is a structured resource family for routes and related spatial or mission data in the EDF corpus. Mission-owned, map-owned and MAE/weather-embedded RMPA have distinct evidence and conversion constraints. A single claimed universal RMPA layout would erase important distinctions present in the source research.

The measured mission-owned profile

The examined EDF5-to-EDF6 MISSION.RMPA work documents an EDF6 output with the \0PMR signature, version 1 and a 0x30-byte header whose primary fields are big-endian. Its four top-level sections represent routes, shapes, cameras and spawn points.

Mission record Measured footprint
File header 0x30 bytes
Group type header 0x20 bytes
Waypoint 0x30 bytes
Route group 0x18 bytes
Shape 0x24-byte header plus 0x40-byte payload; normal 0x10 metadata
Spawn point 0x34 bytes

Some descriptors within the otherwise primarily big-endian file are little-endian. The source distinguishes absolute, record-relative and field-relative offsets; one blanket byte-order or pointer-base rule is unsafe.

Waypoint identities and links

The studied mission source can number waypoints locally within routes, while the EDF6 target profile uses a flattened global sequence. In the audited MISSION.RMPA writer, global waypoint ordinal and preserved original gid are different identifiers. Outgoing route-local links are rebased by the route's cumulative starting index.

The bounded 141-mission offline audit accounted for 5,103 waypoints, 1,355 shapes, 3,387 spawn records and 6,665 literal script-to-RMPA references. These figures are validation-set counts, not binary limits or proof that every mission executes correctly in-game.

Map-owned and MAE/weather resources

The CAVE501/CAVE503 map-RMPA studies have target-profile constants and structural rules requiring their own measurements. A map-owned writer may depend on MAPB placement identity. Do not import those rules into the mission-owned MISSION.RMPA writer, which was measured without a MAPB count input.

MAE/weather RMPA is a third context. Its resource bindings must be studied independently; neither the mission nor map profile automatically defines it.

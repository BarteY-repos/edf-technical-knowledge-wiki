EDF 4.1 mission-object source-only closure

ConversionCross-game ConversionEDF 4.1EDF 6
Source-backed research / case study · Offline

Evidence level: Offline source-closure PASS. Generated game payloads depend on user-owned EDF4.1/EDF6 inputs and still require EDF6 runtime qualification.

Exact object scope

The MissionBundle object builder is intentionally narrower than a full EDF4.1 asset port:

  • 111 mission-used object roots;
  • 325 unique logical dependency files;
  • 277 files under OBJECT/;
  • 48 files under WEAPON/EDF41_NPC/;
  • zero player-weapon resource sets;
  • zero standalone playable-class model packages;
  • unrelated vehicles, outfits and test-range objects excluded.

The 48 WEAPON/ dependencies are NPC equipment/animation/model dependencies required by EDF4.1 Ranger/HeavyArmor/PaleWing NPCs.

Implementation rule: WEAPON/EDF41_NPC/ is the only allowed weapon-side dependency namespace for this mission-object closure. Any other generated WEAPON/ path is a build failure.

Reproducibility gates

The source-only build uses an exact audited allowlist and fails closed unless:

  1. generated object roots are exactly the 111-reference set;
  2. every object class/dependency path set matches the reference;
  3. logical closure is exactly 325 files;
  4. all 48 weapon dependencies remain below WEAPON/EDF41_NPC/;
  5. generated logical-file SHA-256 values match the audited reference registry;
  6. no mission root is skipped.

This also turns game/update drift into an explicit failure rather than silently generating a different port.

Runtime dependency

The generated assets depend on the EDF4.1 compatibility behavior/factory layer for EDF4.1-specific classes and fixes.

Do not assume: Asset closure proves object behavior, collision, animation, audio or network parity. Those remain runtime/plugin concerns.

Redistribution boundary

The source checkpoint contains build logic and dependency/hash metadata, not converted EDF4.1 object/model/animation/collision payloads.

The audited All Forces source archive used during research does not contain a root license file. Private project use and evidence extraction do not establish a public redistribution license.

Full source-root and dependency inventory

The 111-object SGO/class/dependency catalog lists each exact named root and its bounded target-class mapping, with a complete logical-path appendix. It is a research-derived converted-corpus inventory, not a comprehensive retail EDF 4.1 object list.

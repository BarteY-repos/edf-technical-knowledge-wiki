EDF 5 — Online Caps (community source notes)

EDF 5Community Knowledge HubNetworking
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Where the caps act

The offline modes hold no caps: in config.sgo's ModeList, modes 0, 2 and 4 (GameMode_Scenario, GameMode_Offli…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-offline-modes-no-caps

The offline modes hold no caps: in config.sgo's ModeList, modes 0, 2 and 4 (GameMode_Scenario, GameMode_Offline_MissionPack01, GameMode_Offline_MissionPack02) have integer 0 in every difficulty's value 6 and value 7, which the cap getters 90F90 / 90E60 read as "not a list", -1, no cap (file-formats.md#modelist-online-caps-code); the online modes 1, 3 and 5 hold the lists (#modelist-online-caps). Mode value 7 is the online flag (0 offline, 1 online; its node offset +0x5C), which the code tests to choose online behavior (#edf5-weaponselect-cap-predicate, #edf5-spawn-armor-paths).

Basis: config.sgo read from Root.cpk (scratch File_Storage/Logs/00v/modelist5_caps.py)

Addresses (build-specific RVAs unless indicated): 90F90, 90E60

The weapon-cap flag is the byte save+0x24571 (save object 125AB30

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-cap-flag

The weapon-cap flag is the byte save+0x24571 (save object [125AB30]; EDF6's GS+0x14FC8, ../edf6/online-caps.md#edf6-cap-flag-accesses): the online session update 411530 (called from 410130 at 4113C0) sets it to 1 at 411965 when the room's weapon switch [session+0x318] > 0 and the cap 8AFC0 > 0, with the notice OnlineSys_WeaponCapLock (EBFD48), else 0 at 411983 with OnlineSys_WeaponCapUnlock (EBFC78); the armor switch is [session+0x314]. Other writers: 56087A (from 421C10's result) and a clear at 55E0C7; readers 422E8E, 53779A, 53BC10. No offline code sets it (inferred from its writers), so every cap test below answers "no cap" offline.

Basis: fn.py --grep 0x24571 over EDF5.exe's code, reads of 411530, --str of the notice keys; the functions around 56087A and 55E0C7 not read

Addresses (build-specific RVAs unless indicated): 125AB30, 411530, 410130, 4113C0, 411965, 411983, EBFD48, EBFC78, 56087A, 421C10, 55E0C7, 422E8E, 53779A, 53BC10, 8AFC0

The weapon select HUiHQWeaponSelect (constructor 533EF0, ui-menus.mdweaponselect-layout-same) gets its over-c…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-weaponselect-cap-predicate

The weapon select HUiHQWeaponSelect (constructor 533EF0, ui-menus.md#weaponselect-layout-same) gets its over-cap predicate only online: at 53408E..5340B9 it stores a std::function at screen +0x760 (impl +0x798, vtable ED3A50, call slot ED3A60 = 53BC00) only when the current mode node's value 7 is nonzero (534083 cmp [node+0x5C], 0, 53408C je 534107, bytes 74 79). The cell update 53770C inlines it when the impl is ED3A50: if the flag save+0x24571 is set (5377DA; 5377DD je, bytes 74 13) and the cell's level [cell+0x2C] is above 90F90 (unsigned, 5377EC jbe), it sets bit 0 of the cell flags [cell+0x4C] (5377F8; cells are 0x80 bytes).

Basis: fn.py reads of the constructor, 53BC00, 53770C; --xref ED3A50, --xref 53BC00; bytes read from EDF5.exe

Addresses (build-specific RVAs unless indicated): 533EF0, 53408E, 5340B9, ED3A50, ED3A60, 53BC00, 534083, 53408C, 534107, 53770C, 5377DA, 5377DD, 5377EC, 5377F8, 90F90

The weapon select's cell colors and refusal (as EDF6's, ../edf6/online-caps.mdedf6-red-level-online-predicate…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-weaponselect-cap-colors

The weapon select's cell colors and refusal (as EDF6's, ../edf6/online-caps.md#edf6-red-level-online-predicate): cell bit 0 (over the cap) colors the text object at cell+0x14 red, RGBA (1, 0, 0, 1) from 118C470; bit 1 gray 0.5 (118C1D0), bit 2 a stack color, else white (118C1C0) (53782A..53787A). The PressButton handler 538220 (key ECA658, set at 534107) refuses only [cell+0x4C] & 6 (53828D test cl, 6, bytes F6 C1 06, jne 538532), so an over-cap weapon stays selectable even online.

Basis: fn.py reads of 53770C, 538220, --xref 538220, --str ECA658; colors read with scratch exe_floats.py; which text cell+0x14 is was not read (likely the level number, as in EDF6)

Addresses (build-specific RVAs unless indicated): 118C470, 118C1D0, 118C1C0, 53782A, 53787A, 538220, ECA658, 534107, 53828D, 538532

A room member's over-cap marks: 422F00 (from 421EA0) calls 422E70 for each of the member's 6 weapons (423560.…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-member-overcap-marks

A room member's over-cap marks: 422F00 (from 421EA0) calls 422E70 for each of the member's 6 weapons (423560..423577) and stores the answers as bytes at +0x48..; 422E70 returns 0 unless the flag save+0x24571 is set (422E8E, 422E95 je), then compares the weapon record's level (91930) with 8AFC0 unsigned (422EC4 jbe), so -1 never marks. These are the only users of 8AFC0 besides the lobby text 568290 and the notices 411530; no class-select row test was found (EDF6 has one, 95B1E0).

Basis: fn.py --xref 8AFC0, --xref 422E70, reads of 422E70, 423540..4235B0

Addresses (build-specific RVAs unless indicated): 422F00, 421EA0, 422E70, 423560, 423577, 422E8E, 422E95, 91930, 8AFC0, 422EC4, 568290, 411530

The online armor cap is applied on the host's start message: 42E1D0 takes the box cap from 8AF60 when save+0x…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-online-armor-cut

The online armor cap is applied on the host's start message: 42E1D0 takes the box cap from 8AF60 when [save+0x6AD8] > 0 and the session's call +0x18 is true (42E2DC..42E302), else -1, and sends mission [save+0x48], difficulty [save+0x4C] and the cap; for each of [save+0x2459C] players the record writer 401520 (42ED62) clamps the record's armor count +0xFC (from the save's +0x6E44, 42E928) to the cap when it is >= 0 and lower (4015B4..4015C4 cmovl). The receiver 42F480 reads each record with 401810 (401844 writes +0xFC) and copies it from +4 into save+0x14B30 + slot x 0x3E90 (42F7EE), so the count lands at +0x14C28.

Basis: fn.py reads of 42E1D0, 401520, 401810, 42F790..42F860; --xref 401520, --xref 401810; what [save+0x6AD8] holds was not read

Addresses (build-specific RVAs unless indicated): 42E1D0, 8AF60, 42E2DC, 42E302, 401520, 42ED62, 42E928, 4015B4, 4015C4, 42F480, 401810, 401844, 42F7EE

Two spawn paths set a soldier's armor: 11CE60 tests the mode node's value 7 (11CEF6 cmp node+0x5C, 0, je 11D16E)

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-spawn-armor-paths

Two spawn paths set a soldier's armor: 11CE60 tests the mode node's value 7 (11CEF6 cmp [node+0x5C], 0, je 11D16E); offline it calls 311F40 (11D174), which reads the box count from the save's +0x6E44 + (player x 0xF98 + class) x 4 (312026, player.md#armor-box-counts) with no cap; online it calls 3123A0 (11CF79), which reads the received, capped count at save+0x14C28 + slot x 0x3E90 (312422, #edf5-online-armor-cut). Both then compute HP = float(boxes) x per box + base (player.md#armor-hp-per-box).

Basis: fn.py reads of 11CE60, 311F40, 3123A0; --xref 3123A0, --grep 0x6e44 and 0x14c28

Addresses (build-specific RVAs unless indicated): 11CE60, 11CEF6, 11D16E, 311F40, 11D174, 312026, 3123A0, 11CF79, 312422

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-spawn-hp-store

In both spawns (#edf5-spawn-armor-paths) the HP goes to the soldier's +0x1F8 and +0x1FC (312074..31208C, 31263D..312654), with a minss xmm0, xmm0 between the two stores (312088, 312650, bytes F3 0F 5D C0), a min with itself that does nothing. The armor-limit editor (508810, player.md#armor-box-counts) calls no cap getter: 8AF60's only callers are 411530, 42E1D0 and 568290.

Basis: fn.py reads of 311F40, 3123A0, --xref 8AF60; bytes read from EDF5.exe

Offline: route to caps (00v topic 2)

Route for online-style caps offline in EDF5 (which has no offline hint at all, no yellow level text, novae (a…

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-offline-caps-route

Route for online-style caps offline in EDF5 (which has no offline hint at all, no yellow level text, novae (ajane), 2026-11-14): (a) data: copy the online modes' per-difficulty value 6 and 7 lists into offline modes 0, 2, 4 of config.sgo (#edf5-offline-modes-no-caps), so 8AFC0 / 8AF60 return caps offline (spread over the offline list's rows); never mode value 7, which also switches the spawn path (11CEF6); (b) set the flag save+0x24571 offline, or skip its tests (5377DD weapon select, 422E95, 53BC17); (c) skip the je at 53408C to install the predicate (red level text); (d) to refuse over-cap picks, mask byte 53828F 6 -> 7; (e) armor: clamp the count read at 312026 (offline spawn 311F40) to 8AF60(save) when >= 0, as 4015BE..4015C4 does online (a hook); the armor editor needs its own clamp to show it. Nothing here was run in game.

Basis: inferred from the lines above

Addresses (build-specific RVAs unless indicated): 8AFC0, 8AF60, 11CEF6, 5377DD, 422E95, 53BC17, 53408C, 53828F, 312026, 311F40, 4015BE, 4015C4

Attribution: KH chat 173 (curator, autorun 00v), novae (ajane) · 2026-11-14

EDF5 native generator: BVM calls 2100/2101, message 0x20100, wave pools and eight owners

EDF 5Game technical referencesMissions / spawning and engine
Technical reference · EDF5 source static analysis; no new runtime qualification

The observed EDF5 BVM uses 2100 SetGenerator to configure repeating generation, and 2101 to release a one-time batch. In the 141 shipping source BVMs, 2100 occurs 609 times across 49 scripts; 2101 occurs 270 times across 28 scripts. In the game binary their call handlers prepare a native object message 0x20100; the receiver is a generator component of a ship, hive, nest, anchor, fortress or boss.

0x20100 payload offset Meaning in the examined EDF5.exe build
+0x00 Mode: 0 repeating (2100), 1 one-shot (2101)
+0x04 Wave interval in frames; repeating script interval multiplied by 60
+0x08 Amount: wave size / live cap for repeating mode
+0x0C Gap between individual spawns in frames; script parameter ×60
+0x10 Enemy HP multiplier, already multiplied by mission script global factor
+0x14 Boolean flag
+0x18 Spawned SGO path
+0x38 Observed constant 1
+0x40 Hatch/generator index

For the repeating mode, the game keeps a standing setup and an active setup. Each update decreases wave and per-spawn delays, checks the pool slot, spawns one unit when eligible, and reduces the remaining count. After the last position in the wave, it reuses the standing setup. A pool slot still occupied by a living enemy is skipped; the amount is not the total number created in the whole encounter. A one-shot 2101 has no such persistent pool slot reservation; when it ends, it returns control to the standing setup.

Eight observed component owners are GeneratorPoll (Teleport Anchors), AntHill, BigNest, MovingFortress, Humanoid_BigGreyBoss, UfoCarrier, UfoMother511, and UfoMother511RingUnitParts. Some have generator arrays and select an element by hatch index. The source identifies additional 0x20101 signaling used as a wave gate by certain ship/ring components; it is not demonstrated to apply to all eight owner types.

A frequent cataloging error is to read the 2100 wave cap as a fixed enemy count. This miscounts missions with infinite/repeated spawning. The message fields above are native EDF5 executable reconstruction, not a universal offset map for EDF6.

Evidence: static steam-5d11de53 reverse engineering bvm-generator-calls-2100-2101, bvm-setgenerator-native, generator-message-0x20100, generator-waves-repeat, generator-owner-classes; includes game RVAs in the underlying research, but no new game session test.

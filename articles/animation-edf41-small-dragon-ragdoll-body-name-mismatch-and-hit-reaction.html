EDF4.1 small dragons in EDF6: partial-ragdoll body names and hit-reaction crash

ConversionAnimationEDF 4.1EDF 6
Technical reference · Exact-build RE comments + source-reviewed narrowly scoped compatibility hook; fresh runtime pending

Why importing the model and ragdoll is not sufficient

The EDF4.1 DLC small dragons (DragonSmall401_HS, RedSmallDragon_HS and YerrowSmallDragon_HS) may load their own model, CAS, MAB and Havok ragdoll into the EDF6 DragonSmall class yet still crash when hit. The failure comes from a class-side partial-ragdoll selection by name; it is not evidence that the ragdoll file cannot be parsed.

On the examined EDF6 binary, the hit-reaction state in EDF.dll+0x339550 builds the pair {koshi, mune} and sends it to the partial-body consumer at EDF.dll+0x4A8570. The target game's existing DragonSmall class expects those bones, as they occur in the target donor's frog-dragon ragdoll. The EDF4.1 small-dragon ragdolls instead include koshi, spine1, spine2 and have no mune. A lookup miss is subsequently dereferenced, reaching a null/sentinel case at EDF.dll+0x6E42EB. The retained source associates that path with the historical M805 hit crash.

The corresponding EDF4.1 code constructs {koshi, spine1, spine2} for this hit reaction. It is a semantic mismatch in the consumer's required body subset, not just a name mismatch in the authoring UI.

Exact, narrow repair pattern

In the source-reviewed compatibility patch, a ported object is explicitly marked with the SGO key edf41_ragdoll_bodies, a one-dimensional array of strings. The adapter substitutes those names only for the partial-ragdoll call associated with the hit reaction. Unmarked EDF6 objects retain the target class's original names.

The strict key guard requires an SGO array (type=0) of 1–8 entries, each a string node (type=3) with a nonempty name of no more than 31 UTF-16 code units. Its exact default for an absent or malformed key is to pass the original class list. The object conversion path is responsible for validating every supplied body name against the actual exported ragdoll; merely accepting a syntactically valid string is insufficient.

The class's other ragdoll path (EDF.dll+0x339DD6 → +0x4A8620) operates on all bodies and is deliberately left untouched. Do not globally rewrite body names or substitute the source list for every call in the class.

Diagnostic checklist

  1. Check whether the failure occurs on damage/hit reaction, rather than immediately on model load.
  2. Extract the source ragdoll's named bodies and compare them with the specific native method's selection list.
  3. If the target class selects bodies absent in the port, resolve per-class hit-reaction semantics before attempting geometry or physics changes.
  4. Validate the exact target binary signature and names. The RVAs above describe the retained binary, not a cross-version AOB signature.
  5. Test the actual hit transition in game; source-level guards and regression code do not independently establish runtime parity.

Evidence: retained R9 components/compatibility/src/edf41smalldragon.cpp, including explicit target and source addresses, key parsing and fail-closed call guard. This article does not claim a newly executed game test.

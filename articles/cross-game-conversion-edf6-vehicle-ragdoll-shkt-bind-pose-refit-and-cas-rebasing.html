EDF6 vehicle rig retargeting: MDB bind poses, SHKT proxy joints and absolute CAS clips

ConversionCross-game ConversionCollision & PhysicsEDF 4.1EDF 6
Technical reference · Source implementation and bounded invariants; no new EDF6 runtime test

An EDF6 vehicle has three coupled coordinate systems: its MDB's model bind pose, its SHKT's Havok physics bodies and joint pivots, and its SGO's bidirectional bone↔proxy mappings. An animation file can introduce a fourth frame: CAS/CANM stores local animation poses in the source rig's coordinates, not universal deltas from the current MDB bind pose. Replacing the MDB alone can therefore cause a turret to lock, wheels to detach, or an animation to pull the mesh back to a donor skeleton.

The retained ragdoll_fit.py and cas_pose.py provide an explicit, bounded approach to this problem. They are source implementations, not proof every new vehicle type passes game runtime.

Bone ↔ proxy offsets

The SGO ragdoll binding has two directional arrays:

ragdoll_from_animation:  proxy_frame = bone_frame ∘ offset
animation_from_ragdoll:  bone_frame  = proxy_frame ∘ offset

A rigid transform combines (translation, quaternion): A ∘ B = (A.t + rotate(A.q, B.t), A.q * B.q). The SHKT also contains body proxy world poses, each joint's child- and parent-local anchors, and a ragdoll skeleton reference pose relative to its parent. The retained validator asserts all four interpretations reproduce the same stock bind pose.

The vehicle fit is conservative. First require that stock MDB, SHKT and SGO binding already agree. For every source bone with a new translation, move its Havok proxy to where the corresponding ragdoll_from_animation mapping now puts it. The function does not rotate the proxies: if a moved bone would require changing a proxy's orientation, it rejects the case rather than silently reorienting the constraint graph.

Then re-establish the joint and pose relationships:

  1. Keep each child-local joint pivot (transformA) unchanged and move its parent-local pivot (transformB) so both refer to the same world point after the proxy shifts.
  2. Recompute each ragdoll skeleton's reference translation from the new proxy/parent pair.
  3. Recompute the animation-from-ragdoll translation offset so each model bone is still reconstructed from its dynamic proxy. Preserve valid orientation offsets.
  4. Run the same bind-pose consistency checks again on the rewritten SHKT and binding blob. Abort on any mismatch.

The implementation uses 1 mm (1e-3) for broad geometry/rotation agreement, a 10 µm (1e-5 m) small-change guard to avoid rewriting float noise, and serialization that preserves the SGO's intended depth-first structure.

CAS/CANM may move the mesh back to the old rest pose

An EDF6 CAS 0x204 with embedded CANM 0x300 stores absolute local translations for the studied clips. If a model bone moves from (x,y,z) to (x+dx,y+dy,z+dz), a source animation clip that explicitly keys its original local translation can still place it at (x,y,z) when played. Its absolute clips need a (+dx,+dy,+dz) base adjustment to their translation channels; additive animation must keep its original bytes.

The source implementation's bounded decoder covers static (kind=0) or quantized animated (kind=1) translation channels with translation = base + key_uint16 × scale, and quaternion rotation channels (kind=2 static or kind=3 float32 key sequence). The rebasing writes only the base of supported translation channels, leaving key arrays, timing, names, clip graph and file size unchanged.

There is an important aliasing condition: if two tracks refer to the same CANM channel index but require incompatible rebase deltas, the converter must reject the edit. Otherwise a single channel mutation changes an unrelated clip or bone. Tracks deliberately owned by a runtime plugin can instead be removed from selected clips while retaining their bone names for the renderer.

Root motion must have one owner

A vehicle or boss controller may use CAS root-motion curves to move the scene object itself. If that controller translates the object while the mesh also applies the same root-bone animation, displacement is counted twice. The retained strip_bone operation disables selected root translation/rotation tracks (-1 channel indices) only for the named clips, retaining the rest of CAS. A separate root_motion decoder extracts planar x/z displacement and unwrapped yaw against the first key. Unknown scale-track cases fail closed rather than being silently ignored.

Safe verification order

Start by checking stock MDB ↔ SHKT ↔ SGO internal consistency; then check moved MDB ↔ refitted SHKT ↔ updated binding; then validate absolute CAS clip rebasing and channel aliasing; then, separately, test turret movement, wheel articulation, animation transitions, damage and physics state in the actual game. A correct file-level transform graph does not prove runtime vehicle behavior.

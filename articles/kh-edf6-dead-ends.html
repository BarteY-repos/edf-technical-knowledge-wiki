EDF 6 — Dead Ends (community source notes)

EDF 6Community Knowledge HubTroubleshooting
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

From the EDF41-to-EDF6, EDF5-to-EDF6 and Network/Desync projects (drop shared by Bartey, intake round 4)

Attempt that did not work — 1

Attempt: loading an EDF 4.1 map's MAD collision directly, since EDF6 can read old Havok 2014 tagfiles

Why it failed / limitation: the reader only deserializes the file; EDF 4.1 map collision is a Physics2012 hkp* graph and EDF6 maps need hknp* graphs

Suggested direction: an explicit semantic hkp -> hknp converter (the project's MAD converter)

Source: EDF41-to-EDF6 project · Build: steam-678ccb46

Attempt that did not work — 2

Attempt: weather DSGOs without a _brightnessFog node, and weather RMPA names EnvmapArea / EnvmapCapture (in game)

Why it failed / limitation: crashes at EDF+0x52E44 and EDF+0x1135991

Suggested direction: include _brightnessFog (constructor-default semantics) and name the entries local_cubemap (file-formats.md)

Source: EDF41-to-EDF6 project · Build: steam-678ccb46

Attempt that did not work — 3

Attempt: trusting a verification step labeled "R11 sentinel" that checked compact_collision.py instead of the compressed_mesh.py serializer actually used

Why it failed / limitation: a "97/97 PASS" hid wrong inactive-lane sentinels in every compressed mesh

Suggested direction: verify the serializer that writes the shape in question, against native files

Source: EDF41-to-EDF6 project · Build: steam-678ccb46

Attempt that did not work — 4

Attempt: an extra SetGameMode / LoadPackage call to rebuild a mission shell (historical FIX14, in game)

Why it failed / limitation: corrupted progression/save state

Suggested direction: let the normal joined-room / UserSync path rebuild room, MissionPack and Package identity

Source: EDF6 Network/Desync project · Build: steam-678ccb46

Attempt that did not work — 5

Attempt: 0x8EC483 / RoomInfo+0x18 as the running-mission admission veto

Why it failed / limitation: it is difficulty-related, not the admission gate (netcode.md#net-join-refusal-gate since reads 8EC483 as one of the join button's two tests in the UI, which fits "not the admission gate" only if a later host-side check exists)

Suggested direction: trace eos::lobby::Room::Event<Event_Join> into the consumer that creates or reuses eos::User (archive/online-reconnect.md, section A; mods/network-desync-fix.md)

Source: EDF6 Network/Desync project · Build: steam-678ccb46

Attempt that did not work — 6

Attempt: MissionSync as a world snapshot for reconnecting players

Why it failed / limitation: it is roster/participant sync only (SyncGate = barrier, Generator = command queue, Event_Mission = event application)

Suggested direction: the native xgs::snapshot / DSGO (netcode.md#net-world-snapshot)

Source: EDF6 Network/Desync project · Build: steam-678ccb46

Attempt that did not work — 7

Attempt: taking local/remote player roles from the DSGO snapshot

Why it failed / limitation: Soldier+0x128 role bits are not in the snapshot; PlayerInfo is actor-reference oriented

Suggested direction: restore the world, then rebind with the local/remote bind helpers 54ED40 / 54EDB0

Source: EDF6 Network/Desync project · Build: steam-678ccb46

Attempt that did not work — 8

Attempt: using the logical slot (eos::User+0x48) as the NetworkObject ID

Why it failed / limitation: different ID spaces; the NetworkObject ID comes from the restored actor +0x314

Suggested direction: register through the NetworkObject registry 54EE70 (2026-11-07: wrong, 54EE70 is SetTeam, combat.md#setteam-full; the "try instead" does not hold)

Source: EDF6 Network/Desync project · Build: steam-678ccb46

Attempt that did not work — 9

Attempt: a high-only navmesh change removing one cross-wall streaming stitch, to stop spiders firing at enemies behind a wall (DM019, in game)

Why it failed / limitation: no change: spiders still aimed and fired through the wall, though the web hit the wall and actors could not cross it

Suggested direction: look at AI-vs-AI perception, line-of-sight and query semantics, not a missing wall

Source: EDF5-to-EDF6 mission project · Build: steam-678ccb46

Attempt that did not work — 10

Attempt: old EDF5-to-EDF6 conversion-manual rules, now superseded: merging 9201/9202 as ObjectDestroy; source Func_N numbers as event IDs; one event slot per registration; counting factors over dead compiler code; picking 2006/2008 APIs by SGO; 2009 as CreateEnemyGroup_Area(...).Spawn; direct 4000 as PlaySe; treating source-void calls as expressions; injecting SetFullLightWeightMode() / ragdoll settings everywhere; trusting stale mission-list JSON over binary LIST.SGO

Why it failed / limitation: each was disproved against the 44 official ports or the binaries

Suggested direction: the R37 rules in ../edf5/mission-vm.md and crosswalk/mission-script-api.md

Source: EDF5-to-EDF6 mission project · Build: steam-678ccb46

Attempt that did not work — 11

Attempt: mapping BVM custom call 3450 to SetEncountReportRadius (3024) or SetAiFormationRadius (3150)

Why it failed / limitation: they write different fields

Suggested direction: find the AngelScript binding of native helper 228120 (missions.md); 2026-11-07 (KH chat 55): hajisensai's All Forces names EDF6 +0x470 the encounter report radius (filled from game_object_encount[0]) and 228120 a BVM-style SetEncountReportRadius that no BVM table entry reaches (missions.md#encount-report-radius-bvm), so EDF6's custom call 3450, whose handler writes +0x470 (missions.md#bvm-dispatcher-in-edf6), may set the encounter radius after all (unverified, inferred from the shared field)

Source: EDF5-to-EDF6 mission project · Build: steam-678ccb46

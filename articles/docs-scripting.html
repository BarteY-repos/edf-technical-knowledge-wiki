Overview

EDF4.1/EDF5 mission BVM is stack-based bytecode. EDF6 mission authoring uses AngelScript (MISSION.AC). Translation therefore requires typed dataflow, stack/call ownership, control-flow rebuilding and correct engine API bindings—not only replacing numeric IDs with function names.

Important compatibility distinction

EDF4.1 table-1 3000 SetEncountReportRadius and EDF5 cuscall0 3450 SetAiSearchRadius have different call identity and ABI despite related names. 3450 changes the AI search radius of six frogs in DM006_2; the game-playable 3450-OFF port deliberately omits it. That is an accepted fidelity exception, not a blocking crash in the accepted build.

Developer checks

Preserve typed globals, event registration order, return-stack semantics, side effects and validated target signatures. A corpus-level compilation pass does not prove every mission's gameplay parity.

EDF4.1/5/6 item crates: shared drop accumulator, category weights and caps

ConversionGame technical referencesPickups and rewardsEDF 4.1EDF 5EDF 6
Technical reference · Source-declared grades; this edition does not add native game runtime testing

A defeated enemy does not independently roll a simple yes/no probability for every crate. In the source builds of EDF4.1, EDF5 and EDF6, a drop quantity from the enemy's game_object_drop_item contributes to a shared floating-point accumulator maintained by the pickup manager. The manager subtracts a fixed threshold for each crate due and then selects a crate category by weight. This explains why low-point enemies can apparently drop nothing for several kills, then one more kill produces an item.

Drop rate is a threshold

For the investigated builds, the threshold is 0.947. The source describes the following approximate progression for a single drop event:

  1. Add the enemy's configured drop amount to the manager's current accumulator.
  2. While the accumulator is above the threshold, subtract 0.947 and attempt to spawn one crate.
  3. If the map is already at the on-field limit, that attempt produces no crate, but the threshold has already been subtracted.
  4. Retain the remainder for later enemy deaths.

The formula for an ideal long-run average, before caps and other rules, is approximately expected crates = sum(enemy drop amounts) / 0.947. The accumulator is shared across kills, not a separate bucket for each enemy. A contributor compared EDF5 enemy SGO drop values with a Japanese community drop table: examples include 2.4 for a Silver Spider and 0.29 for a Black Ant, rather than 240% and 29% independent Bernoulli events.

These are conditional category shares after a crate is emitted. They are not the probability that a given enemy will drop an item. EDF4.1's category weights were found at A96060, EDF5's at E9CD00, and EDF6's at 17A6CE8, each tied to its named executable build.

All three source builds have an on-map limit of 128 crates and a mission collection limit of 1024. The latter is not the same as the former. Hitting the 128-on-map limit can permanently waste a crate that would otherwise be created because the threshold is still consumed.

What happens after pickup?

Collecting weapon or armor crates is separate from awarding a particular weapon or increasing armor. EDF5's source shows that these categories initially increment mission counters; the final selection occurs in a separate mission-result roll. EDF6 also distinguishes box pickup from result-screen weapon selection. Health boxes are handled immediately by a different path. Online EDF6 adds host arbitration for pickup ownership, described in EDF6's pickup lifecycle.

Evidence and scope

This is a synthesis of static source research, not a fresh gameplay test. The EDF6 workbook documents an expected-value calculation but does not list every enemy's drop amount, so no universal enemies-to-crates count is implied. The exact 0.947 threshold and category weights refer to the studied Steam builds; do not treat their offsets as cross-version constants.

Observations

EDF5 DragonSmall records: Tadpoles, not Dragons

Evidence: verified · Build: steam-5d11de53 · Fact ID: edf5-enemy-names

EDF5 has no dragons: the class DragonSmall (SGOs DragonSmall401, RedSmallDragon, YerrowSmallDragon, the _HS variants) is the Tadpole, as the catalog's wiki names say; only EDF 4.1 has dragons (../edf41/enemies.md#edf41-enemy-names). Nephila is the Aranea, the spider whose web can nearly immobilize a player and pull them in (Retiarius in EDF 4.1).

Basis: novae (ajane)'s knowledge of the games (2026-11-07)

Attribution: novae (ajane) · 2026-11-07

Evidence: static · Build: steam-5d11de53 · Fact ID: kill-counter-names

The game's own names for enemy kinds are the statistics labels: an enemy SGO's game_object_kill_counter (e.g. NephilaKillCount) names a counter, and etc/texttable_xbox.<lang>.txt_sgo holds StatusInfo_<counter> = its label ("Araneas Defeated:"). English labels seen: GiantAnt "Aggressive Alien Species αs", GiantSpider "Aggressive Alien Species βs", Dango "Aggressive Alien Species γs", GiantBee "Flying Aggressors", GiantAntQueen "Mother Monsters", GiantBeeQueen "Queens", BigGiantSpider "Kings", Dragon "Tadpoles", DragonAce "Giant Tadpoles", Frog "Colonists", Grey "Cosmonauts", BigGreyBoss "Silver Man", Deiroi "Deroys", GoldUfo "Drones", GoldUfoAce "Red Drones", Carrier1 "Teleportation Ships", Fortress "Outpost Bases", AntHill "Teleportation Devices". Allies, vehicles and most props have no counter, so the game names them nowhere; their names here are the radar catalog's wiki names. Every SGO with its counter, label and wiki name: catalog/objects-enemies.md, objects-npcs.md, objects-vehicles.md and objects-misc.md.

Basis: SGOs and the text table decoded from Root.cpk with _tools/catalog.py; labels not compared with the in-game statistics screen

Enemy subtype names in English mission briefings

Evidence: static · Build: steam-5d11de53 · Fact ID: briefing-subtype-names

Beyond the kill-counter labels, the game's English text names enemy sub-types only in the mission briefings (missionlist.*.txt.en.sgo, second column); the text table's other keys (loading tips Loading_Desc_* and the rest) name none. Briefing names: "Big Anchors" for the larger teleportation anchor (offline 84 City of Giant Pylons, only e505_generator_large there), "teleportation anchors", "teleportation ships", "shield bearers", "red drones" (offline 28), "new type drones" (offline 70), "battle robots" launched by Mothership no.2 (offline 49, 50, 75: Deroys), "golden aggressors" (Mission Pack 1 missions 2 and 14: goldant), "silver aggressors" (pack 1 mission 9: silverspider, silverspiderqueen), "heavy-armored aliens" (pack 1 missions 6, 8, 10: the e503_armorfrog_* Armored Colonists), "bombers" (pack 2 mission 3: e507_goldufo_big), "the flying-type" (hornets), "Monster Balls" (titles; Aggressive Alien Species γ), "War Bargas" (offline 100).

Basis: every offline, online and pack briefing searched with File_Storage/Logs/catalog/brief_terms.py (online rows repeat the offline ones), text_search.py over etc/texttable_xbox.en.txt_sgo; classes matched by the catalog's per-mission lists

Tadpole color variants in EDF5

Evidence: verified · Build: steam-5d11de53 · Fact ID: edf5-tadpole-subtypes

EDF5 has three Tadpole sub-types, named by their in-game color: the Red Tadpole (dragonsmall401, dragonsmall401_hs; durability 50; red in game, the most common, EDF 4.1's green Dragon counterpart), the Green Tadpole (yerrowsmalldragon, yerrowsmalldragon_hs; durability 20; smaller and faster, little health, EDF 4.1's Yellow Dragon counterpart), and the Blue Tadpole (RedSmallDragon: redsmalldragon, redsmalldragon_hs; durability 1200; larger, the toughest non-boss Tadpole, EDF 4.1's Red Dragon counterpart; kill counter Giant Tadpoles). The SGO names keep EDF 4.1's dragon colors, so the wiki name "Red Tadpole (Small)" in #sgo-dragonsmall-1200 is wrong; the sgo-* wiki names come from KittopiaCreator's EDF documentation wiki on GitHub (KCreator/Earth-Defence-Force-Documentation), not from game text. The JP wiki's base durabilities match: タッドポウル 50, 小型タッドポウル（仮） 20, 大型タッドポウル 1200.

Basis: novae (ajane)'s knowledge of the game (in-game colors, which is which); the English fan wiki's Tadpole page agrees (Red, Green, Blue; sizes, speeds, counterparts); atwiki edf5 pages 44 and 45 durabilities against the SGOs

Retained SGO data and scene-object identity

Constructor stores cache handle and SGO raw data

Static, EDF5 steam-5d11de53. Common scene-object constructor 617520(obj,createInfo) (61 callers including enemy, weapon, projectile, effect and decal types) retains raw SGO data at obj+0xB0 from [[info+0x18]], resource-cache entry at +0x20 and its control block at +0x28 from [info+0x10], incrementing the cache-entry reference at +0x70. The cache entry also stores raw data at +0x50. Native reader 5BDF30(&obj+0xB0,name) binary-searches SGO UTF-16 keys, returning index or −1. Factory 6138E0 resolves spawn key through 42460/84A00, checks SGO magic and version 0x102, resolves xgs_scene_object_class, prepares matrix/handle/data/output in createInfo and invokes class factory slot 2. These are EDF5 offsets, not EDF4.1's +0x10/+0xA0 layout.

Readable normalized path retained in cache entry

Static. Cache entry +0x20 contains an MSVC std::wstring key (length +0x30, capacity +0x38; inline chars under capacity eight, otherwise pointer). Builder 42460/42550 normalizes slash to backslash, calls uppercase helper 5BD010, and hashes characters into key +0x20. Therefore [[obj+0x20]+0x20] resolves the stored SGO path, in principle distinguishing objects that share an RTTI class. This supersedes a broad earlier radar-page statement that no readable SGO filename is stored, subject to a live plugin read still outstanding.

Typical enemy key text remains inferred

Unverified expected string. Mission scripts pass keys such as app:/object/GiantAnt01.sgo, whose normalization predicts APP:\OBJECT\GIANTANT01.SGO at the cache wstring. No running-game enemy cache entry was actually dereferenced, and network replicas or class-created child objects could use other keys. The predicted text is a debugging lead, not a tested stable identity API.

Shared raw SGO pointer as a subtype key

Static inference from cache construction. [obj+0xB0] points to one loaded SGO data blob per cache entry while the file is held, so distinct class-compatible subtypes can also be distinguished by comparing their SGO data pointer with known cache lookups or reading keys such as durability, kill counter, level adjustment and model through 5BDF30. Pointer identity is only stable for an active load/cache lifetime, not a persistent file ID or cross-session address.

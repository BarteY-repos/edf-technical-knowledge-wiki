MTAB v0x200 — map attribute table reference boundary

UniversalFormats & ContainersFile FormatsEDF 5EDF 6
Source-backed research / case study · Documented / conditional

MTAB is a map attribute table associated with MAC/map data. The retained raw format documentation identifies magic MTAB (4D 54 41 42) and version 0x00020000.

Documented block shapes

The historical format note describes a 0x1C header following a 16-byte prefix and several referenced tables:

  • A1 — 0x0C bytes per record; describes which material is adjusted;
  • A2 — 0x0C bytes per record; selects/identifies the parameter to adjust;
  • B1 — 0x14 bytes per record;
  • a float-group region referenced by offsets;
  • ASCII parameter-name strings and UTF-16 material-name strings.

Offsets/counts in the raw note include pointers to A1/A2/B1/float-group blocks. The note also contains uncertain field interpretations; those question-marked interpretations are not promoted to exact semantics here.

Ownership and validation

Treat MTAB as an owning-MAC/profile-dependent block, not a universal free-standing payload. Safe parsing/writing requires:

  • validating all record spans and counts;
  • confirming string offsets resolve inside the string area;
  • preserving other MAC blocks when editing one declared block;
  • retaining map-family/profile context instead of importing an MTAB from an unrelated map as a generic template.

Presence is not universal

The EDFROOM source census found no standalone MTAB block name in the audited MAC even though other expected map blocks were present. Therefore “a MAC must contain MTAB” is not an established invariant.

Likewise, the corpus does not establish one universal EDF5→EDF6 MTAB transformation. Use same-map/target-native evidence where available; otherwise preserve or rebuild only with validated references.

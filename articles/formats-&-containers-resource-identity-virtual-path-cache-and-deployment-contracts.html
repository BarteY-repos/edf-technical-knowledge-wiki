EDF virtual resource identity: CPK paths, RAB/MRAB, LIST and map suffixes

UniversalFormats & ContainersFile FormatsEDF 5EDF 6
Source-backed research / case study · Reconciled

EDF resources may have several distinct identities: an outer CPK virtual path, the archive of origin, a typed RAB/MRAB entry, an SGO internal name and a reference held by a mission LIST/CONFIG. Equality of filenames alone does not establish that two logical resources are interchangeable.

Virtual-path collisions and archive origins

The studied EDF source/catalog workflow compared virtual-path identities case-insensitively and recorded the archive of origin. Two CPKs containing normalized-equivalent paths are ambiguous without a mount/lookup precedence rule. This is a conservative source-reader finding, not a universal proof that all stock EDF game file lookups are case-insensitive. A safe conversion must identify the actual path and owning mounted archive rather than choose a binary by directory enumeration order.

EDF4.1 DLC examples demonstrate the collision: separately mounted mp01:/ (app 410780) and mp02:/ (app 411380) can contain the same names AntHill301Large.sgo, GiantAnt04SB.sgo and ari_half.rab with distinct payloads. See DLC mount namespace and collisions.

RAB/MRAB resources have inner identities

An RAB/MRAB archive's outer filename is insufficient: resource type, embedded logical name/stem, entry order and the expected MDB sampler/type relationship matter. A tested custom DDS path failed when resource layout was noncanonical despite matching the logical filename. The working tested configuration kept TEXTURE and HD-TEXTURE in their canonical contiguous type placement and the matching MDB sampler names.

Unknown opaque binaries under one virtual path must not be assumed mergeable merely because two mods can be unpacked successfully. The game-facing fact is the typed payload and reference contract, not how a particular package composer resolves conflicts.

MissionPack LIST versus mission-content lookup

A retained modded EDF6 MP07 test selected MISSIONLIST_MISSIONPACK07.OFFLINE.LIST.SGO but still black-screened because a row in that LIST referenced an obsolete loose global mission-content path. After correcting the row to the actual provider-scoped mission resource, the bounded offline run reached Mission Clear.

This distinguishes two native resource steps: (1) locating the selected LIST; (2) resolving each LIST row's mission resource. A successful LIST lookup does not prove the row targets exist. See native MissionPack identity and two-stage LIST routing.

Map suffixes and name preservation

Map suffixes such as .trb, .mdx, .mosb and .fmep distinguish source resource families and their registration/lookup roles. A global .trb -> .mdx rename is not a justified general EDF conversion rule. Preserve the exact native source and requested target profile before changing a resource suffix.

Evidence boundaries

  • Successful extraction/CPK indexing is not an in-game mission or shader result.
  • A data viewer's cache fingerprint is a utility state, not an EDF file-format field.
  • A JSON representation is not authoritative over the bytes of the game's effective binary LIST/SGO.
  • A successful host-side MissionPack selection does not establish identical resource resolution on a remote peer.

EDF5 BVM group IDs, object counts and bool query domains

ConversionMissions & ScriptingVM & APIEDF 5EDF 6
Technical reference · Exact 141-mission source/target static typing comparison, not new game runtime

Scope: decompiled EDF5 mission bytecode mapped to EDF6 AngelScript in a retained 141-mission shipping corpus. The observed source stack and target call signatures establish separate scalar domains for group identifiers, group-object counts and boolean queries. These are typed game-script semantics, not directions for a particular editor.

A group token is not an Object handle

The audited source group system uses calls such as:

Source custom call Semantic role Inferred source/target value domain
3500 AddGroupObjectBegin Starts a group transaction Group key is a scalar integer
3502 GetGroupObjectCount Queries number of group members Return is scalar integer, not an Object
9116 Factor_GroupObjectCount Factor examines group count Consumes integer group identity / count domain
9117 Factor_GroupObjectEncount Factor examines group encounter Consumes integer group identity

A decompiler that types every Object-looking BVM global as an AngelScript Object reference can therefore generate the wrong API call or even a compile-time Object&/integer error. The source context of a variable's consumers is stronger evidence of its domain than a generic placeholder type.

IsAiMoveEnd: source integer truth versus target boolean result

A separate discrepancy in M004 shows how two script generations can express the same condition using different value domains. A source-derived expression in the target script had the shape:

IsAiMoveEnd(loc_0x01) == 1

The inspected EDF6 callable returns bool, so the translated comparison must be:

IsAiMoveEnd(loc_0x01) == true

This is not license to rewrite all integer comparisons as booleans. It is specifically grounded in the target function's signature and the source numeric truth-domain comparison.

What the evidence proves

The R42 source-only audit changed 13 of 141 generated mission scripts, retaining the remaining 267 nonlisted runtime payload files byte-identically in that historical package. The focused mission engine regression suite passed 23/23, structural validation reported zero errors/warnings, and no remaining non-integer declarations were found for the audited group-consumer set.

These are static conversion and compilation qualifications. They do not independently establish that all 141 missions reproduced every source behavior at runtime. Later compatibility decisions (including deliberate mission-local omissions of unresolved custom call 3450) are separate. A source group identifier should never be silently promoted to an object reference to make a specific target expression compile.

Base502 — Barga support-object family runtime closure

UniversalMissions & ScriptingMissionsEDF 5EDF 6
Source-backed research / case study · Runtime-proven family rule

Status: FAMILY_RUNTIME_PASS__R66_MAP_PROFILE_RULE_QUALIFIED. The rectangular Base502 render+collision hole is closed as a narrow target-map compatibility problem, not a generic map-conversion failure.

Proven mechanism

On stock app:/Map/ig_Base502.mac, generated EDF5-derived missions can omit the target-side static Barga support/base object that completes the map's visible and collidable structure. The minimal compatibility addition is:

Preload("app:/object/ev605_bargabase.sgo", -1);
Object baruga_base = CreateNeutral("Mapバルガ", "app:/object/ev605_bargabase.sgo", 1);

M003 first proved the mechanism at runtime: the rectangular opening disappeared, rendering and player collision were fully restored, and no Barga vehicle or lift animation was required.

Full shipping-family qualification

The same narrow support-object addition was then tested across every shipping EDF5-port mission using stock target Base502:

  • M003 — PASS;
  • M004 — PASS;
  • M072_1 — PASS;
  • M072_3 — PASS.

The observed result across the family was normal rendering and collision with the rectangular hole gone.

M072_3 also passed while preserving its source-authentic operation:

MapObjectDestroy4("破壊01", 2);

That call is therefore not the root cause and must not be suppressed as part of the compatibility rule.

Qualified production rule

A narrow target-map compatibility profile is now justified:

  1. trigger only for generated EDF5 missions that load stock app:/Map/ig_Base502.mac;
  2. inject the support preload and inert neutral instance only when the generated mission does not already instantiate it;
  3. preserve the source mission's own operations and RMPA;
  4. do not add Barga vehicle choreography, Action2, elevator_move, or other native EDF6 event logic;
  5. do not override stock Base502 MAC/MAD/FMB/RAB/HKT/NVMD resources for this fix.

This is a target-side map-profile shim. It is not a generic CreateNeutral rule and not evidence that ordinary EDF5 map resources require a global Base502 conversion transform.

Superseded directions

Do not return to Base502 map rebuilds, FullLight/Ragdoll shell theories, Barga vehicle injection or MapObjectDestroy4 removal unless new runtime evidence contradicts the family PASS. R66/R67 treat Base502 as closed.

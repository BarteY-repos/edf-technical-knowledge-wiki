EDF5 Umbra and AnimationModel: depth, opaque, translucent and shadow phases

EDF 5Game technical referencesRendering / scene phases
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5's scene traversal combines Umbra visibility callbacks with per-object model drawing. The names of render phases cannot be assigned by guessing their index: a contributor specifically verified that phase 0 is the picture's depth pre-pass. When a model was skipped in phases 1 and 2 but still drawn in phase 0, its remaining on-screen appearance was a flat white silhouette. Skipping all phases 0–2 removed the model cleanly in that experiment. This corrects older descriptions that grouped phase 0 with the shadow pass.

AnimationModel phase behavior

Native phase Effect observed in code
0 Opaque-list depth pre-pass
1 Main opaque / G-buffer pass
2 Translucent-list draw via second model callback
3 Draw only materials marked to cast shadows (material flag +0x21 bit 0)
4 No AnimationModel draw

For phase 2, a source researcher inferred the use of the forward technique because a one-color-plus-depth render target is selected immediately beforehand. That technique mapping is unverified from a runtime shader capture, although the translucent callback is identified statically.

The game routes animated characters, soldiers, enemies and vehicles through AnimationModel slot 1 (0x3AEF60) and translucent drawing through slot 2 (0x3AE990) in the studied build. Rigid sgmUmbraObject renderables follow another callback. The renderer also updates last-drawn bookkeeping after phases 1/2; that should be distinguished from whether an object actually appeared as a visible pixel.

Evidence: EDF Knowledge Hub edf5/models.md, render-phase-0-depth-prepass (contributor-verified), models-animationmodel-phases (static), animationmodel-draw-callback (verified), render-phase-2-forward (unverified inference). Build steam-5d11de53.

EDF6 mission clear bitmasks, mission-level interpolation and script fixed-level overrides

EDF 6Game technical referencesMission progression
Technical reference · Source-scoped static analysis; no R129 gameplay test

The engine records which difficulties a player/class has completed for each mission and separately decides the current mission level, which affects scaling. A clear flag, the selected difficulty and a script's SetMissionLevelFix() are three different state variables.

Mission-clear flags

Difficulty Stored bit
Easy 0x01
Normal 0x02
Hard 0x04
Hardest 0x08
Inferno 0x10

The native completion function loops from Easy up through the just-cleared difficulty only when the difficulty is Easy, Normal or Hard. Clearing Hardest or Inferno marks their own bit, not all lower difficulties. This explains the familiar progression behavior without treating the flags as an ordered numeric level value.

Mission progress is used to interpolate enemy level

The selected difficulty comes from GameStatus +0x4C in the studied build. The current mission's row position and total row count yield a progress fraction. The per-difficulty [lvMin, lvMax] bounds in CONFIG.SGO are interpolated using that fraction, with single-precision arithmetic. For the original main campaign the source reports bounds:

Difficulty Level-factor bounds
Easy 5–15
Normal 10–24
Hard 20–60
Hardest 70–150
Inferno 160–280

DLC modes may use different bounds; DLC2, for example, has Inferno 310–350. These are parameters of the game's scaling model, not necessarily weapon-drop levels or individual enemy HP values.

A script's fixed-level flag is independent of difficulty

The scripting interfaces GetDifficulty() and SetMissionLevelFix() operate on distinct fields. The latter sets a fixed-level flag at GameStatus +0x44 and does not change the selected difficulty at +0x4C. A BVM reset clears the flag on relevant mission lifecycle transitions, so a fixed-level tutorial cannot be assumed to change the following mission.

EDF6 carries both an older BVM call and native AngelScript routes, but BVM native 20's shared mission factor is not the same operation as the AngelScript SetMissionLevel(float) enemy-team factor. These should not be translated by matching only names or arguments.

ModeList structure changed from EDF5

EDF5 uses a 12-field mode row; EDF6 uses 13 fields, adding an explicit .MST filename in field 5. As a result, the mission-list triple and the difficulty array move one slot later, with EDF6's per-difficulty values in field 7. A parser that applies EDF5 offsets to an EDF6 configuration would read the wrong data even when the visible mode name is the same.

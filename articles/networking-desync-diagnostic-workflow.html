Why a single "network problem" is not a useful diagnosis

Position drift, incorrect HP/damage, projectile divergence and peer disconnects can coexist while following different paths. A game-level record may be retained and ACKed above unreliable EOS transport; a periodic transform may instead be deliberately fire-and-forget; and a successfully delivered projectile selector can still be missing state it never serialized.

Observable symptom → first evidence to collect

Symptom First lane / evidence Mistake to avoid
Walking drifts, jumping briefly fixes other peers' view Class 3 0x3300 periodic snapshots versus class 4 0x3400 jump/action transforms Blaming all position messages on one unreliable channel
Damage/HP inconsistent while movement appears correct Class 4 0x3400 → EventController, protocol DamageObject=1 Treating internal 0x2B handler code as a network protocol ID
Bullet exists but evolves differently on peers Class 5 0x3500 NetworkBullet selector and missing RNG/motion/countdown state Assuming reliable resend reconstructs omitted fields
Peer drops after transient physical disconnect EOS Link replacement + logical UserSession / ReliableMgr retry state + READY flag Wiping reliable pending records to "reset the connection"
An oversized datagram is alleged Actual built and transmitted byte lengths, source builder path, EOS send error, mod configuration Mistaking a 1400-byte defensive check for a routine output size

Minimal trace record

Keep the same correlation key for both peers:

exact build identity / mod versions
monotonic time + frame number + peer id + object id
outer traffic class + app mode + event protocol/selector
serialize outcome + payload/record/datagram lengths
EOS send outcome + ack/retry/duplicate outcome (if retained)
receive/decode + pending queue state + game-object apply decision
final observed in-world state and time

For movement, distinguish generated, queued, flushed, received, decoded, and applied. A receiver that clears its pending flag before a false apply gate can lose an individual batch, yet that gate's simple existence is a homolog with EDF5 and is not proof of the EDF6 regression. For jump-specific corrections see player-state analysis.

Prior theories already restricted or rejected

  • Legitimate standard class-4/class-5 traffic routinely exceeding EOS's limit is rejected for the earlier qualified native envelope; see size reconciliation.
  • A supposed EDF6 downgrade of ordinary NetworkBullet traffic to unreliable delivery is contradicted by 23 inspected direct native send call sites that selected mode 0; see event protocol and bullet route.
  • A default replay/apply gate being present does not by itself prove a new EDF6-only gating defect.
  • A timeout or stuck READY state can explain a peer-level failure without explaining all position-drift or projectile-state behavior.

Next decisive qualification

An exact-build multi-peer trace should test a falsifiable single cause at a time, ideally with an EDF5 homolog and without other patches, then repeat with the applicable third-party mods separately. No live multiplayer traces were generated in this documentation pass.

Protocol-aware two-computer capture boundary

The retained two-PC SceneObject investigation is R7 runtime evidence; R8 defined the strict-stale experiment, and a later R9 static candidate adds RUDP sender-pending, retry/ACK and dedupe hooks. R9 is not an independently observed two-PC PASS. The practical combined diagnosis is in protocol-aware tracing and reconnect A/B, including precise READY-reset isolation and warnings against simultaneous transport-mutating plugins.

Preserve the observation/enforcement interval boundary: the inherited R8 source uses a 90-second OBSERVE window and a separately labeled conservative ENFORCE experiment for runtime-confirmed Soldier keys. Treating the whole run as passive would be misleading. 0x1200 retries/0x1300 ACK evidence diagnoses Sandlot delivery; it does not explain a class3 position-bearing update being overwritten after physical receipt or absent Flame/Lightning/SolidExp constructor state.

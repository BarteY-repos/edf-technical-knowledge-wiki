EDF5→EDF6 HKT: coarse graph edges, clearance caches and hkHalf16 values

ConversionMaps & NavigationHavok navigation and streamingEDF 5EDF 6
Technical reference · Source-derived and exact bounded runtime evidence separated

A source navigation graph can look valid in a high-level HKT inspector and still be misinterpreted if a parser uses the wrong element widths. The NG_DLC_EDFROOM03 / DM019 comparison is a concrete case: graph topology, narrow flags, cache arrays and Havok's 16-bit real encoding have distinct rules. These observations describe paired EDF5-to-EDF6 navigation data, not a universal reconstruction of EDF6's proprietary navmesh baking process.

Graph connectivity is independently countable

The examined DM019 low/high navmeshes retain a coarse inter-cluster graph that can be reproduced directly from current face cluster adjacency:

Graph Edges derived from face adjacency Stored edges Missing Extra Duplicates
LOW 84 84 0 0 0
HIGH 374 374 0 0 0

Both versions used 8-byte graph edge records in this particular compatibility comparison. The source DM019 record's byte2 flag and byte3 padding were zero in the audited set; native EDFROOM01's comparable flags16 fields were also zero. No “padding interpreted as active flag” defect was demonstrated here.

Consequence: rebuilding the exact same cluster graph from unchanged face adjacency cannot add missing connectivity. A real route defect may lie elsewhere: underlying faces, streaming links, agent queries, clearance, or the target selection logic. The graph check is a structural invariant, not a diagnosis of why an NPC chose a target behind a wall.

hkHalf16 is not IEEE float16 and not four-byte float32

One earlier decoder consumed four bytes when reading a two-byte hkHalf16 bEdgeCost, inadvertently incorporating the next two bytes and reporting false numeric graph differences. In the examined Havok type family, hkHalf16 represents the upper 16 bits of an IEEE float32 value; reconstruction places the stored 16 bits in the high half and zeroes the lower 16 bits. It is not an IEEE binary16 conversion.

For example, a stored high-half word 0x3F4C reconstructed as 0x3F4C0000 is a float32 value, not the number obtained by decoding 0x3F4C as IEEE half precision. A byte-exact round-trip and a semantic decoder must implement their respective roles independently.

Correctly decoding this field removed false numerical mismatches during the DM019 comparison. It did not repair EDF6 gameplay, because the affected source serialization already retained the relevant raw data.

Clearance arrays: element ABI versus generated semantics

The audited EDF5→EDF6 pair included these physical arrays:

Array Inspected element type Important interpretation
faceOffsets uint32 Index/range lookup, not real-valued clearance
edgePairClearances uint8 Per-edge-pair clearance byte
mcpData 2-byte record First byte: interpolant, second: clearance
vertexClearances uint8 Per-vertex clearance byte

Those element widths are compatible in this bounded pair, even though the enclosing cache structures and target generation behavior may differ. A precomputed EDF5 clearance value can be syntactically valid yet semantically stale for an EDF6 navmesh or agent profile.

A controlled source-only experiment omitted clearance seed datasets and initial cache objects while retaining 10 LOW / 10 HIGH navmesh records. The resulting HKT remained structurally comparable outside that intentional omission. This proves a feasible wire-level subtraction; it is not a positive in-game fix for AI targeting or route selection.

Evidence hierarchy

  • Static: graph edge counts matched source face adjacency (84/374); no extra/missing/duplicate coarse edges; correct hkHalf16 decoding; 2-byte mcpData and documented array widths.
  • Runtime-negative in the broader room test: changing faceData/NVMD section identity did not correct spiders' wall-targeting symptom.
  • Unresolved: whether a particular cache, query filter or hkaiNavMesh variant changes AI line of sight. Structural HKT validity is not evidence for one specific perception mechanism.

CAS / CANM versions (key: file header versions)

  • edf41: CAS 0x200 (common records 9 u32), embedded CANM 0x200 | ref: edf41/file-formats.md#cas-canm-versions | evidence: static
  • edf5: CAS 0x203 (common records 13 u32), embedded and standalone CANM 0x200 | ref: edf5/file-formats.md#cas-canm-versions | evidence: static
  • edf6: CAS 0x204 (common records 13 u32), embedded and standalone CANM 0x300 | ref: edf6/file-formats.md#cas-canm-versions | evidence: static
  • Differences noticed: not a version-byte patch; record layouts and key references change. Mapping of EDF 4.1 common tags to EDF6 common tags, as qualified by the source on aligned records: 0->0, 1->1, 4->8, 7->11, 9->13, 12->16, 13->17, 14->18 (target fields 9..12 zero; source tag 0 drops legacy field 6). VEHICLE502_GROUNDROBO.CAS and VEHICLE407_BIGBEGARUTA.CAS carry byte-identical CANM in EDF 4.1 and EDF5. EDF5 -> EDF6 CANM conversion of seven shared families reproduced the native target header exactly and the data from AnmData onward byte-exact after key remapping (rotations within about 0.0115 degrees). Public tools: Smileynator's Blender MDB/CANM addon reads EDF5 CANM (512 = 0x200) and EDF6 CANM (768 = 0x300); AUK233 edf-tools converts CAS/CANM to XML (ops/community-tools.md).
  • Full EDF6 format (container, state-machine VM, CANM6 channels) and the v512 reference layout: edf6/animation-cas.md (CAS 516 / CANM 768 there are 0x204 / 0x300 here).
  • Confidence in the mapping: high for versions (header census of native files); tag map qualified offline only, no in-game animation test.
  • Added: 2026-10-15 src: EDF41-to-EDF6 handoff (shared by Bartey), CAS/CANM three-generation checkpoint and header matrix

Map prop SGO: CrashType, resource ownership and safe schema translation

UniversalMaps & NavigationMapsEDF 5EDF 6
Technical reference · Scoped: 30/30 paired prop SGO + runtime exception

A map placement's resource identity is not the same as the binary schema of the prop's configuration. In the inspected EDF5→EDF6 map family, a MAPB T1 record can correctly point to a UTF-16LE resource name and embedded SGO while the game still interprets the prop's configuration incorrectly.

What the paired prop comparison established

A paired EDFROOM set of 30 matching T1-linked prop SGOs demonstrated an EDF6-side CrashType field with int32(0) in the studied target family. This is a semantic schema extension of the prop configuration, not proof that every SGO in the game requires an inserted field.

The older Desert508 regression package was observed running with the field absent for its specific set of objects. That negative/positive pairing matters: CrashType cannot be inserted globally as a magic positional patch merely because one native comparison found it.

A known unsuccessful conversion attempted to insert a supposed 16-byte SGO variable at a fixed index. The classical SGO variable-node structure in this path is 12 bytes. The incorrect insertion displaced relative references and strings and caused corruption. Correct conversion needs to parse the named variable graph and transform only the relevant object schema.

MAPB pointer integrity and prop semantics are separate

For the measured source/target pair, MAPB T1 resource descriptors widen 56→60 B, inserting a zero dword at T1+0x20. T2 instance descriptors widen 68→72 B. Pointer rebasing then must preserve all resource identities. A successful structural MAPB conversion proves neither that the embedded prop SGO has the target schema nor that its collision body is registered in the relevant MAD or MAPO resource.

The actual model, visual placement and collision object can be held in different resource registries. A model missing from a map's RAB inventory is not evidence that the corresponding physical body does not exist: source MAD can retain named collision bodies that have no matching visual RAB entry. Conversely, having an MDB visual in a RAB is not proof the MAD registered its collision shape.

Diagnostics for a missing or misbehaving prop

  1. Parse MAPB/MARC and validate T2→T1 references and UTF-16LE names.
  2. Resolve the T1 embedded SGO and inspect its actual graph, not an assumed fixed property index.
  3. Compare the same prop class with a paired native target; document which fields are target-only and which default values have evidence.
  4. Independently inspect the referenced MDB/RAB visual identity and the map's MAPO/MAD collision identity.
  5. Distinguish loader success, visible rendering, destructible response and physical collision; none follows automatically from the others.
  6. Refuse unrelated SGO transformations when the target schema is not known. Preserve unknown values losslessly when the codec permits.

See MAPB record reference and SGO/DSGO schema semantics.

Evidence provenance: maintained MAPB/embedded-SGO graph converter, 30/30 EDFROOM prop paired comparison, runtime-positive Desert exception and negative positional SGO writer tests. This is a scoped example of target-only schema synthesis, not a universal SGO rule.

CrashType is consumed by the building preload path

The audited EDF6 native code contains a CrashType SGO lookup in the Preload_Base family and a separate Preload_Structure path for structure-type .mosb resources. This proves that the target property participates in real engine preload behavior, not just a serializer-side naming convention. It still does not make fixed-index CrashType insertion valid for every SGO. Map collapse topology itself is separately held in MAPO's T50 table.

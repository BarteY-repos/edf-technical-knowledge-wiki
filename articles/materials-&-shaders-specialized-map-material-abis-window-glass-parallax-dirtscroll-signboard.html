Specialized map-material ABIs: Window, Object Glass, Parallax, DirtScroll and Signboard

EDF 6Materials & ShadersShaders
Source-backed research / case study · Exact native

Evidence level: Exact native MDB ABI census + source-owned offline writer qualification. Representative EDF6 rendering/runtime remains pending for these specialized authored profiles.

The retained NW_EUROPE01.RAB native corpus closes an important research gap: these specialized map-model families are not shader-name guesses. Their material ABI, sampler order, flags and vertex declarations were recovered from native MDBs and then reproduced by bounded source-owned writers.

These are ordinary MDB material profiles used by map models. They must not be confused with FMEP/FieldRender terrain.

Type-4 raw integer correction

interior_wrap_count is a material parameter with type=4. For the audited native profile its value lane is raw u32 bits, not floating-point numeric 4.0.

Correct native representation for value 4:

0x00000004

Incorrect float-serialization interpretation:

float 4.0 -> 0x40800000

This distinction applies to the audited type-4 fields generally: the six value lanes occupy float-sized storage, but selected type-4 values are integer bit patterns.

Legacy snd_Map_Build_Window

Legacy Build Window is a separate ABI from BRDF Window. R43 retains three mesh-backed forms:

Profile Structural contract Native evidence
legacy_build_window_68 canonical 68-byte layout 23 structural occurrences; modal full-value defaults observed in 9/23
legacy_build_window_84 84-byte layout with float3 form 2 occurrences
legacy_build_window_uv_swapped_68 68-byte layout with TEXCOORD stream identities swapped 1 occurrence

Two additional native snd_Map_Build_Window material records were LOD records without a mesh signature tied to that material. Their material ABI is represented, but no new geometry declaration should be invented for them.

Implementation rule: never alias legacy Build Window to BRDF Building Window merely because both represent windows.

snd_Map_Object_Glass

Object Glass is another independent translucent family. Three observed source-owned/native-matched profiles were retained:

Profile Priority Layer Flags Parameter count Native evidence
object_glass_full_flags2 10 2 2 13 1 occurrence
object_glass_light_flags2 1 2 2 11 1 occurrence
object_glass_full_flags3 10 2 3 13 1 occurrence

All three were kept distinct because shader name alone does not determine the full material contract.

Do not collapse the three Object Glass profiles into one generic “glass” profile. The exact blending/transparency appearance remains an EDF6 runtime/rendering gate even though offline ABI/value parity is closed.

LOD / FarMap is not one shader replacement

Native evidence includes multiple LOD families. Important examples include:

snd_BRDF_Map_LOD_CC
snd_FarMap_Simple

snd_FarMap_Simple is a separate 64-byte profile. Manual geometry LOD can also retain the base material shader.

Therefore:

LOD != replace shader with one universal LOD shader

LOD authoring must preserve asset linkage, geometry/material pairing and the specific target profile.

Source-owned writer qualification

R41 qualified four bounded BRDF profiles offline:

BRDF Window
BRDF Parallax
BRDF DirtScroll
Signboard Pattern

Checks included:

  • deterministic double build;
  • MDB version 0x20 parse;
  • exact shader/priority/layer/flags;
  • exact parameter ABI/order;
  • exact sampler ABI/order;
  • exact vertex declaration/stride/topology/skinning flags;
  • raw-u32 type-4 handling;
  • fail-closed unknown/missing/extra parameter and sampler validation;
  • RAB → literal-CMPL → MDB round-trip.

Result: 21/21 PASS for R41.

R43 then qualified six bounded legacy Window/Object Glass profiles with exact parameter values, sampler state and mesh declarations against selected native exemplars.

Result: 54/54 PASS, including a source-owned ten-profile RAB round-trip.

Runtime boundary

Offline native ABI equality does not prove:

  • correct translucent blending/order for Object Glass;
  • exact legacy reflection behavior;
  • parallax depth appearance;
  • DirtScroll animation/UV speed;
  • Signboard animation/switching timing;
  • BRDF Window interior appearance;
  • generalizing the profiles beyond their audited native MDB vertex/material contracts.

These profiles are ready for bounded runtime qualification, not for unrestricted shader-family synthesis.

Specialized map-material ABIs: Window, Object Glass, Parallax, DirtScroll and Signboard

EDF 6Materials & ShadersShaders
Source-backed research / case study · Exact native

At a glance

What it is: EDF6 map models use several specialized material families, including glass, windows, parallax, scrolling dirt, signboards, water and LOD.

Where it fits: The surveyed native RAB/MDB corpus supports multiple concrete ABI profiles, sampler orders and integer-bit parameters.

Important distinction: A successful native-data writer check is not yet a complete rendering/runtime qualification; Glass/Window and LOD are not single interchangeable shader presets.

Evidence level: Exact native MDB ABI census + source-owned offline writer qualification. Representative EDF6 rendering/runtime remains pending for these specialized authored profiles.

The retained NW_EUROPE01.RAB native corpus closes an important research gap: these specialized map-model families are not shader-name guesses. Their material ABI, sampler order, flags and vertex declarations were recovered from native MDBs and then reproduced by bounded source-owned writers.

These are ordinary MDB material profiles used by map models. They must not be confused with FMEP/FieldRender terrain.

Type-4 raw integer correction

interior_wrap_count is a material parameter with type=4. For the audited native profile its value lane is raw u32 bits, not floating-point numeric 4.0.

Correct native representation for value 4:

0x00000004

Incorrect float-serialization interpretation:

float 4.0 -> 0x40800000

This distinction applies to the audited type-4 fields generally: a type=4, size=1 lane occupies four bytes, but its stored value is an integer bit pattern. The six such controls in the sampled Signboard profile are listed below.

Legacy snd_Map_Build_Window

Legacy Build Window is a separate ABI from BRDF Window. R43 retains three mesh-backed forms:

Profile Structural contract Native evidence
legacy_build_window_68 canonical 68-byte layout 23 structural occurrences; modal full-value defaults observed in 9/23
legacy_build_window_84 84-byte layout with float3 form 2 occurrences
legacy_build_window_uv_swapped_68 68-byte layout with TEXCOORD stream identities swapped 1 occurrence

Two additional native snd_Map_Build_Window material records were LOD records without a mesh signature tied to that material. Their material ABI is represented, but no new geometry declaration should be invented for them.

Implementation rule: never alias legacy Build Window to BRDF Building Window merely because both represent windows.

Why this is more than a serialization difference: static inspection of the EDF5 SND_MAP_BUILD_WINDOW.SGO found a six-target Deferred shader which projects a view-dependent interior image behind the pane. It binds window_frame_texture, interior_texture, two normal sources and a packed reflect/spec texture; it does not directly sample a cubemap, because environment reflection is added in the deferred combine. Its 80-byte material constant buffer contains interior_wrap_count at offset +72 and interior_random_seed at +76. That is a measured EDF5 GPU contract, not a shader-output or layout proof for the EDF6 legacy or BRDF Window profiles above. See the three-way EDF5 surface/pass comparison.

snd_Map_Object_Glass

Object Glass is another independent translucent family. Three observed source-owned/native-matched profiles were retained:

Profile Priority Layer Flags Parameter count Native evidence
object_glass_full_flags2 10 2 2 13 1 occurrence
object_glass_light_flags2 1 2 2 11 1 occurrence
object_glass_full_flags3 10 2 3 13 1 occurrence

All three were kept distinct because shader name alone does not determine the full material contract.

Do not collapse the three Object Glass profiles into one generic “glass” profile. The exact blending/transparency appearance remains an EDF6 runtime/rendering gate even though offline ABI/value parity is closed.

The EDF5 SND_MAP_OBJECT_GLASS.SGO offers a useful compatibility warning: its reflected shader draws in a forward path with one color target, takes a global environment cubemap at t5, and uses a 96-byte xgl_user_param buffer (including metallic at +64, roughness at +68 and translucent fall-off values from +84). This establishes the EDF5 native shader's capabilities but does not prove that all three independently observed EDF6 MDB Object Glass profiles select identical passes or states. A correct field list alone cannot decide transparency sorting, blend state, depth writes or final light response.

Legacy Parallax and DirtScroll: distinct EDF6-native profiles

The 14 Parallax-family occurrences in this corpus are not all snd_BRDF_Map_Build_Para_NC: the other five comprise snd_Map_Build_Basic_Parallax_NC (3 materials) and snd_Map_Field_Parallax (2). Likewise, the 9 DirtScroll-family materials include two snd_Map_Build_DirtScroll records in addition to the seven BRDF records above. All are observed inside EDF6; the word “legacy” here identifies their snd_Map_* shader families, not a claim that these files were converted from EDF5.

Native vertex declarations: 76-byte versus 68-byte map mesh

The retained NW_EUROPE01 structural census provides the semantic byte offsets in the selected native mesh declarations. Parallax and DirtScroll both use a 76-byte declaration containing three TEXCOORD streams; the sampled BRDF Window and Signboard 68-byte declarations omit TEXCOORD2. This is a measurable layout difference independent of how the corresponding shaders interpolate the coordinates:

SemanticParallax / DirtScroll (stride 0x4C)BRDF Window / Signboard (stride 0x44)
BINORMAL+0x00+0x00
TEXCOORD1+0x08+0x08
TANGENT+0x10+0x10
NORMAL+0x18+0x18
POSITION+0x20+0x20
TEXCOORD0+0x28+0x28
TEXCOORD2+0x30absent
BLENDWEIGHT+0x38+0x30
BLENDINDICES+0x48+0x40

The native census records additional declaration-format codes and stream properties; this compact table gives offsets, not invented float-component types for compressed/packed lanes. A common incorrect conversion would copy a 68-byte Signboard declaration into a 76-byte DirtScroll mesh, changing all following attribute positions. Even equal stride does not guarantee equal declaration: the separately observed legacy 68-byte Window variant swaps TEXCOORD identities. The source-owned writer's declaration equality check provides offline structural evidence, not proof of a correct GPU draw or animation.

Legacy Parallax/DirtScroll use a different vertex order

The 76-byte legacy snd_Map_Build_Basic_Parallax_NC and mesh-backed snd_Map_Build_DirtScroll declarations are not the 76-byte BRDF declarations in the preceding table. The native recorded offsets are:

SemanticLegacy Build Parallax / DirtScroll, 76 BField Parallax, 72 B
POSITION+0x00+0x20 (12-byte lane)
NORMAL+0x08+0x18
BINORMAL+0x10+0x00
TANGENT+0x18+0x10

Thus two different 76-byte layouts occur even in the same specialized families. The source's one legacy DirtScroll record without a mesh signature supplies its material ABI, but it cannot establish the exact vertex declaration for that separate occurrence.

LOD vertex declarations: same stride, different semantics

SemanticLegacy LOD, 44 BBRDF LOD, 44 BLegacy LOD_CC, 52 B
POSITION+0x00+0x08+0x00 (12 B)
NORMAL+0x08+0x00+0x0C (12 B)
TEXCOORD0+0x10+0x10+0x18
BLENDWEIGHT+0x18+0x18+0x20
BLENDINDICES+0x28+0x28+0x30

The 64-byte snd_FarMap_Simple layout instead begins with BINORMAL +0x00, TANGENT +0x08, NORMAL +0x10, POSITION +0x18 (12 B), TEXCOORD0 +0x24, BLENDWEIGHT +0x2C and BLENDINDICES +0x3C. Even for the two 44-byte groups, POSITION and NORMAL exchange places between legacy and BRDF. Reusing a stride-matched declaration without checking semantics can therefore corrupt an otherwise valid native model.

Manual geometry LOD can also retain the original material shader. The game-side distance selection, archive linkage and visual fade are separate issues; these native MDB samples do not prove their complete runtime rules.

Conclusion: LOD != replace shader with one universal LOD shader. Preserve the paired geometry, complete parameter ABI, sampler order and the specific target family.

Result: 54/54 PASS, including a source-owned ten-profile RAB round-trip.

Runtime boundary

Offline native ABI equality does not prove:

  • correct translucent blending/order for Object Glass;
  • exact legacy reflection behavior;
  • parallax depth appearance;
  • DirtScroll animation/UV speed;
  • Signboard animation/switching timing;
  • BRDF Window interior appearance;
  • generalizing the profiles beyond their audited native MDB vertex/material contracts.

These profiles are ready for bounded runtime qualification, not for unrestricted shader-family synthesis.

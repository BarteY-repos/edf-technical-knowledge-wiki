EDF4.1 / EDF5 / EDF6 — Technical quick reference

UniversalStart / Quick ReferenceTroubleshootingEDF 4.1EDF 5EDF 6
Source-backed research / case study · Reconciled

This reference explains what is known about the games, where to read the underlying research and why conclusions from one version cannot automatically be used for another. It is not a history of tool development.

First decide which data layer you are reading

Layer Typical native resources Main question
Game archives CPK, RAB, CMPL, MARC How is an asset stored, compressed and found?
Models MDB, MDX, MAB, CAS, CANM What are geometry, materials, bones and animations?
Maps MAC, MAPB, MAPO, FMB, FMEP What objects, terrain and visual features are placed?
Physics and navigation MAD, SHKT, HKT, NVMD What is solid, what moves, and where can AI travel?
Missions BVM, AC, mission RMPA, SGO/DSGO What events, spawns and script operations occur?
Multiplayer and progress GameStatus, MissionMgr, mode LIST, MST, protocol data Which state belongs to a player, session or game mode?

A file that parses does not necessarily behave correctly in the game. Similarly, correctly rendered geometry does not establish collision, and a valid collision mesh does not establish AI navigation.

Where to begin

  • Native archive and resource formats, models and MDB and material/shader systems.
  • Map containers and world placement, collision and navigation.
  • Missions, scripting and mission RMPA.
  • Native gameplay and enemy AI, weapon parameters and weapon upgrades.
  • Network architecture and native progress/ModeList identity.

High-value differences across generations

  1. MDB and CANM: familiar names do not imply a byte-identical on-disk ABI; vertex declarations, channels, materials and sampling differ.
  2. Havok and NAV: geometry, collision and route graphs are separate. EDF4.1 navigation cannot safely be inferred from an EDF6 donor mesh.
  3. BVM and AngelScript: event registration, API types, branch semantics and RMPA route names must be interpreted, not text-substituted.
  4. MissionPack: selecting a mode, resolving its resource request, loading LIST/TXT and updating its save namespace occur at different stages.
  5. Gameplay rules: HP factors, kill merit, equipment ownership and vehicle/object action IDs differ between titles; use the exact game's sources.
  6. Rendering: shader names alone cannot reconstruct sampler order, packed texture channels or the special FieldRender path.

Evidence and confidence

Contributor verified means the cited researcher reported a runtime test; it does not mean this wiki ran the test. Native binary/static refers to files or disassembly for a specified build; an address is not a universal constant. Open/unverified means a proposed interpretation still needs proof. Source-conversion or binary-serialization success is not equivalent to gameplay parity.

For difficult discrepancies see the cross-source reconciliation, the negative findings, and the original attributed Knowledge Hub appendices.

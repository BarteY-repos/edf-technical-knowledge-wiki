EDF6 bullet contact: stop/hit filters and full native collision layers

EDF 6Game technical referencesCollision & Physics
Technical reference · Static/source-backed community evidence; verified test results identified separately; no R117 native runtime tests

Evidence: A combination of reported in-game filter tests and exact native steam-678ccb46 binary inspection from the EDF Knowledge Hub (2026-11-14, revision 54f89cd; original tests credited there). The full matrix in the optional CSV is derived from the source's 32-layer table; it is not newly measured in this release.

Two filters answer different questions

In the studied EDF6 build, a bullet has two collision-filter values:

Field Default low-five-bit layer What it does
Flag 1 (BulletControl+0x890, bullet +0x9D0) 12 Sweeps a thin ray along the projectile's trajectory. A blocking result shortens the path and stops motion.
Flag 2 (BulletControl+0x894, bullet +0x9D4) 11 Runs a projectile-sized sphere/shape cast over that already-shortened path to find damageable targets. A piercing shot can continue through these targets.

A Flag-2 hit is not necessarily a Flag-1 stop. A shield is a documented special case: a hit in the damage-query route can stop the bullet. An object matching neither query is ignored by that bullet path.

That difference explains why a target may block a shot but take no damage, or take damage without ending a piercing shot. The order also matters: Flag 2 is evaluated over a path potentially shortened by Flag 1.

Layer comparisons are not naive integer equality

The basic layer is filterInfo & 31. More complex filterInfo values may additionally contain subsystem and system-group information. When query and body belong to the same non-zero system group, the native filter may use sub-ID and exclusion fields rather than the ordinary collision table. The matrix below therefore applies to the zero-group ordinary game-layer policy examined in the source, not every possible fabricated filter value.

The community's numeric experiments verified that, for the tested zero-group cases, values 32, 64 and 128 behave like layer 0, and 255, 32767 and 0xFFFFFFFF like layer 31 because their low five bits match.

Frequently encountered body layers

5 Live small enemies and allied infantry in the examined mode-1 family Alive enemy's direct-hit body can differ from its corpse

27/29 Certain ModelDebris bodies Layer 29 has no ordinary collisions except with layer 0

The evidence includes direct game tests for many target-layer assignments, but several layer labels are still unresolved. A layer number is not an entity class identifier. Multiple unrelated objects can use the same layer.

Explosion queries do not use the same filter as ordinary bullet contact

The studied explosion/area-damage query uses layer 13. In the ordinary collision table it collides with layers 5, 6, 7, 8, 9, 14, 15, 16, 19 and 20 (and the universal layer 0). Terrain layer 17 does not appear in that list. It is therefore possible for a body to be contacted by one bullet route but excluded from an explosion query.

This distinction is especially important for source-to-target SHKT collision mismatches and for diagnostic reports like “the beam touches the object, but the explosion does nothing.” It does not by itself prove the cause of any specific Genocide Cannon problem; the accepted damage handler and visual effect also matter.

Data reference: complete ordinary collision table

The optional 32×32 collision matrix CSV is distributed as data/EDF6_NATIVE_COLLISION_LAYERS_32X32_R117.csv in the public ZIP. Rows are the queried filter layer; columns 0–31 are body layers; 1 means the ordinary table allows contact, 0 means it does not. It deliberately omits the nonzero-system-group special case. The reconstructed matrix is also checked for symmetry before packaging.

Notable properties of the recovered matrix: layer 0 matches all 32 layers; layers 30 and 31 match only 0, 30 and 31; layer 29 matches layer 0 only. These statements are about the native filter table, not about whether a body is present in the game world or whether its class can take damage.

Provenance and limitations

The code's two-phase bullet query and the reported collision experiments are distinct evidence grades. Recovered layer positions and addresses are valid for the cited build, not a guarantee for all EDF6 updates. No in-game physics test was performed for R117.

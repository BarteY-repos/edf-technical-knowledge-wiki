EDF 4.1 — Pickups (community source notes)

EDF 4.1Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Observations

Pickup limits are immediates: on the map at once 128 (mov dword rsp+0x28,0x80, imm32 at 1AE0D7), per mission…

Evidence: static · Build: steam-57aab039 · Fact ID: pickup-limits

Pickup limits are immediates: on the map at once 128 (mov dword [rsp+0x28],0x80, imm32 at 1AE0D7), per mission 1024 (cmp eax,0x400 / jae, imm32 at 1AF13D and 1AF165; keep both equal).

Basis: the patch's fixed addresses; original bytes decoded

Addresses (build-specific RVAs unless indicated): 1AE0D7, 1AF13D, 1AF165

Attribution: FevGrave, Stafern (ChangePickupLimits), novae (ajane)'s EDF 4.1 outside set · 2026-10-16

Enemy item drop chance is a float at AB6610, default 0.947 (lower = more drops).

Evidence: static · Build: steam-57aab039 · Fact ID: drop-rate

Enemy item drop chance is a float at AB6610, default 0.947 (lower = more drops).

Basis: the patch's fixed address; 98 6E 72 3F (0.947) is there

Addresses (build-specific RVAs unless indicated): AB6610

Attribution: ChangePickupLimits (FevGrave, Stafern; this value credited to Kittopia in the file), novae (ajane)'s EDF 4.1 outside set · 2026-10-16

How many crates a kill drops is a running total, as in EDF5 (../edf5/drop-items.mddrop-rate-accumulator): the…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-drop-accumulator

How many crates a kill drops is a running total, as in EDF5 (../edf5/drop-items.md#drop-rate-accumulator): the wrapper 1AE060(mgr, pos, ..., drop value) steps the manager's own generator [mgr+0xA78] (the LCG x 0x5D588B656C078965 + 0x269EC3) once and passes bits 32-47 of it as a 16-bit seed, the field cap 128 (#pickup-limits) and the drop value to the spawn method 1AE160, which adds the value (game_object_drop_item's third value) to the float [mgr+0xA70] (1AE1CC) and, while that total exceeds 0.947 (AB6610, #drop-rate), takes 0.947 off and spawns one crate unless the field already holds the cap (count [mgr+0xA68], 1AE276): the subtraction comes first, so a crate due at the cap is lost, as in EDF5. One total for the whole manager, shared by every kill. Online (the save row's +0x5C nonzero, as #edf41-loot-roll-entry) the wrapper then calls 1AF1D0 with the same seed, the total before the kill and the spawn serial [mgr+0xA80], likely the message that makes the other players' games spawn the same crates (unverified; 1AF1D0 not read; 1AFA10 is 1AE160's other caller).

Basis: fn.py reads of 1AE060 and 1AE160 (found from 0.947's only code reference)

Addresses (build-specific RVAs unless indicated): 1AE060, 1AE160, 1AE1CC, 1AE219, 1AE276, AB6610, 1AF1D0, 1AFA10

Attribution: KH chat 82 (curator) · 2026-11-10

Each crate's kind is a weighted pick (1AE160, the loop at 1AE442

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-crate-kind-weights

Each crate's kind is a weighted pick (1AE160, the loop at 1AE442; weights at A96060, four dwords {5, 18, 12, 3}, total 38): kind 0 weapon box (13.2%), 1 armor box (47.4%), 2 small health (31.6%), 3 large health (7.9%). The kinds as the collect 1AF070(mgr, player, kind, flag) uses them: 0 adds to the player slot's weapon-box count [mgr+0xA88 + 4 x slot] and 1 to the armor-box count [mgr+0xA90 + 4 x slot] (slot [player+0x1A0]; both only while the mission total [mgr+0xA84] is under 0x400, #pickup-limits), the counts #edf41-loot-roll-entry rolls at the mission's end; 2 heals 0.15 (AB64F0) and 3 heals 0.3 (AB6530) of the player's [+0x168] (max health, unverified). EDF5's table (E9CD00, read at 1989C3 in 198640) is {6, 15, 14, 3}, also 38: EDF 4.1 gives fewer weapon boxes (5 against 6) and more armor (18 against 15).

Basis: fn.py reads of 1AE160 and 1AF070; the tables read as raw dwords (scratch File_Storage/Logs/catalog/exe_find.py qwords prints each qword minus the image base 0x140000000: add it back before decoding)

Addresses (build-specific RVAs unless indicated): 1AE442, A96060, 1AF070, 1AF0B2, 1AF136, 1AF15E, AB64F0, AB6530

Attribution: KH chat 82 (curator) · 2026-11-10

The pickup range test is addss xmm2,xmm1 / comiss xmm0,xmm2 / jbe at 1AE9DB

Evidence: static · Build: steam-57aab039 · Fact ID: pickup-range-check

The pickup range test is addss xmm2,xmm1 / comiss xmm0,xmm2 / jbe at 1AE9DB; the item's type dword is [rdi+0x98] (0 and 1 = weapon and armor crates). metoxys's autoloot skips the range test for those, on foot or in a vehicle, but not while the player is down (K.O.).

Basis: the patch's anchor and code (cmp dword [rdi+0x98],1 / jbe)

Addresses (build-specific RVAs unless indicated): 1AE9DB

Attribution: novae (ajane), novae (ajane)'s EDF 4.1 outside set · 2026-10-16

Whether picking up health also heals ally NPCs comes from soldier_config: cmp dword rcx+rax+0x14,0 / setg al…

Evidence: static · Build: steam-57aab039 · Fact ID: heal-ally-npcs

Whether picking up health also heals ally NPCs comes from soldier_config: cmp dword [rcx+rax+0x14],0 / setg al / mov [rdi+0x12F8],al at 2ADD1D (metoxys's name: SoldierConfig_IntB); vanilla it is set for the Ranger only. metoxys's AllClassesHealAllyNPCs replaces the setg with mov al,1.

Basis: the patch's anchor, decoded

Addresses (build-specific RVAs unless indicated): 2ADD1D

Attribution: metoxys (AllClassesHealAllyNPCs), novae (ajane)'s EDF 4.1 outside set · 2026-10-16

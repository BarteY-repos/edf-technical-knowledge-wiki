CONFIG.SGO three-way semantic merge: Air Raider and EDF5 mission port

UniversalFormats & ContainersFile FormatsEDF 5EDF 6
Source-backed research / case study · Observed

Evidence: September 1, 2026 offline merge audit. Status OFFLINE_THREE_WAY_SEMANTIC_MERGE_PASS__RUNTIME_TEST_RECOMMENDED. This is a reproducible case study, not a universal SGO conflict-resolution algorithm or successful game-runtime qualification.

Inputs, identity and output

File role Size Evidence
Baseline recompiled 27,826 B JSON-level canonical baseline
Air Raider original/recompiled 27,938 B Exact sgott round-trip; binary identity preserved
EDF5-missions port 41,592 B Adds mission pack modes while retaining baseline weapon-category scopes
Merged SGO 41,704 B Port + 112 B, the same independent Air Raider delta

The observed Air Raider delta and port delta occupy disjoint semantic scopes. The merger reported zero conflicts and zero warnings, exact JSON round-trip, and preservation of top-level field ordering from the port.

Field ownership: do not blindly pick one whole file

Port-owned ModeList: six additions: offline and online modes for MissionPack03, MissionPack04 and MissionPack05.

Air Raider-owned SoldierInit: appends class/weapon category values to its existing arrays:

  • eLimpetGun01, eDrone_attacker01 and eDrone_airstrike01: add 302, 331 after the original 310, 311, 312, 313, 314, 303, 305.
  • eVehicleNone: add 8, 9, 10 after the original 306, 307, 308, 309, 320.

The audit confirms that PackageName, SoldierWeaponCategory, WeaponTable and WeaponText agree with both inputs. ModeList is exactly the port version and SoldierInit exactly the Air Raider version.

Merge algorithm contract demonstrated by this case

  1. Parse baseline, feature A, feature B as the same known SGO schema; validate exact structural round-trip before transformation.
  2. Compute semantic deltas relative to baseline, not whole-file byte differences.
  3. Detect field ownership conflicts at record and array level. No generic append/union rule is justified for arbitrary SGO arrays.
  4. Apply nonoverlapping deltas in a deterministic order; retain target port's ordered names and mode list where documented.
  5. Recompile, reparse and assert exact expected fields, order and delta. Preserve the source and output hashes in the evidence ledger.
  6. Run EDF6 game tests separately; successful parse/round-trip is not gameplay qualification.

Why this matters

Replacing the target CONFIG.SGO wholesale with either mod's file would lose the other feature. Conversely, treating all SGO arrays as commutative merges could produce syntactically valid but semantically wrong output. The observed +112 B exact difference is evidence for this specific pair of changes, not a size-based merge technique.

EDF5 weapon and armor pickup counters: 1024 cap, host authority and result tally

EDF 5Game technical referencesLoot / mission results
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R133 test

A crate visually disappearing is not by itself proof that a player's final reward counter increased. EDF5 performs item collection, checks authority/session state, then credits health, weapons or armor through different paths. The end-of-mission result subsequently applies a difficulty/mode-dependent retention factor.

Counted categories and native limits

In the examined DropItemManager the relevant fields include:

Field Recorded meaning
+0xA84 Total counted weapon + armor pickups
+0xA88 Weapon pickup count
+0xA8C Armor pickup count
+0xA90/+0xA94 Additional result components included in the end tally

For a weapon or armor pickup, the code increments category and total counters only when the authority test succeeds and the total counter is below 0x400 (1024). Health categories instead heal the player via the collect path. This cap belongs to the inspected EDF5 executable; the results of mods that change those immediates are not the game's stock behavior.

Mission result calculation

The result routine reads the weapon and armor counters, multiplies by a retention factor indexed through the current mode/difficulty state, and adds the separate result components. One branch has a zero retention factor. The source inferred the index was difficulty, but did not prove every mode's displayed output via an in-game experiment.

In multiplayer, do not assume every non-host copy's counters match: the same source left the non-host semantics of the session authority callback unresolved. Confirmed shared item awards are a different claim from perfectly identical intermediate counters on every machine.

Local-control gate and result-sync uncertainty (consolidated)

The per-frame pickup check is local-controller gated: in the audited EDF5 build, the player controller pointer at SoldierBase+0x240 identifies local control. Remote soldier avatars do not independently run the local pickup contact test on every peer. A confirmed pickup references a player network ID (audited SoldierBase+0xF8), not the crate creator or the last attacker.

The 0x400 total limit is an audited stock executable counter threshold, not a statement about guaranteed result-screen rewards or equality of all intermediate peer counters. The code processes confirmed pickups locally, but non-host counter equality and a request arriving after result synchronization remained unresolved in the source study. The presence of a debug-console command named drop_item is not evidence that it runs during ordinary missions.

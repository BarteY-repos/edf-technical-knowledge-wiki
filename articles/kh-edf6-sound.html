Facts

AngelScript Object.PlaySe positional audio

Evidence: static · Build: steam-678ccb46 · Fact ID: object-playse

The AngelScript method Object.PlaySe(const string & in) plays a sound effect at the object: its callback 1C10F0 resolves the script Object (19E420), and when it exists calls PlayPresetSE 7B2A80(soundController [20B2950], &position [obj+0x90], cue, 0) (objects.md#sound-helpers). It never calls the Talk caption renderer. The audit gave 1C00F0 and 7B1A80, neither a function start in this build.

Basis: the audit's description (script binding traced to native code); the curator decoded 1C10F0 (add rdx,0x90, mov rcx,[20B2950], call 7B2A80)

Addresses (build-specific RVAs unless indicated): 1C10F0, 19E420, 7B2A80, 20B2950

Attribution: EDF5-to-EDF6 mission transpiler audit M020_5 R96 (EDF41-to-EDF6 handoff, Bartey), novae (ajane), KH chat 36 · 2026-11-06

Talk variation from object SGO settings

Evidence: static · Build: steam-678ccb46 · Fact ID: talk-variation-pick

An object's SGO key game_object_talk_setting (a Talk SGO path and three numbers) sets its variation at initialization: a native PRNG picks TalkVariationID = floor(random32 * variation_count / 2^32) (the same form as the object RNG's ranged pick, objects.md#object-rng; whether it is that RNG was not checked), the second number feeding the variation count. The E503 leader frog (e503_frog_sg_leader.sgo) has app:/sound/Alien_frog_leader_talk.sgo, 1, 3, 0, so it picks 0 to 2 and its cues are FR_AE065BA, FR_AE065BB, FR_AE065BC.

Basis: the audit's read of E503 initialization and the retained SGO

Attribution: EDF5-to-EDF6 mission transpiler audit M020_5 R96 (EDF41-to-EDF6 handoff, Bartey), novae (ajane), KH chat 36 (audit) · 2026-09-06

Talk-line audio dispatch and EDF5 comparison

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-line-start

A talk line reaches the audio in 5DB310(line, ..), the same design as EDF5's 327BB0 (../edf5/sound.md#edf5-talk-line-start): the frame countdown line+0x70 runs out, the cue (line+0x20, wide) is made narrow (405E0) and played on the SeManager [20B2950]: 7B2B00(SeManager, cue, position block from the speaker's +0x90, handle line+0x10, -1, 2, 0, ..) when line+0x74 is 0 (placed in the world, inferred), else 7B2C00 (5DB641, unplaced, inferred); the caption comes from 7B17F0 (5DB6A7). One hook at 5DB310, or on its two play calls, sees every NPC talk cue by name before it plays (untested).

Basis: fn.py read of 5DB310..5DB4D0; the play calls' names from #sound-cue-lookup-voice-banks

TalkManager NPC voice-line selection

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-line-pick

NPC voice lines, the pick: 5D7480(TalkManager, out {doc, entry}, out int, object, table name, candidate vector, seed), the twin of EDF5's 325820 (../edf5/sound.md#edf5-talk-line-pick), finds the table in the object's talk SGO (object+0x408, 55A30; none: out = {0, -1}) and collects the entries that pass three filters into the vector: element 3, when 0 or more, must share a bit with the byte TalkManager+0x5D+[object+0x460]; the entry's named value mask (17B66E0) must share a bit with the 32-bit TalkManager+0x60; the float TalkManager+0x64 must lie in [element 11, element 12]. Then a weighted pick over the survivors (element 2, the weight; the value (r x 10000 >> 32) x [1C3698C] x the summed weight, walked down to 0); a table whose element 2 is 1 draws from TalkManager's generator +0x70, else from the seed argument (the same LCG, 0x5d588b656c078965, +0x269ec3); the picked entry's element 3 goes to the out int. Weight 0 never plays (the data route to silence a line; untested).

Basis: fn.py read of 5D7480..5D7CB1; found by the imul 0x2710 near the line start; the argument slots from the frame offsets

Addresses (build-specific RVAs unless indicated): 5D7480, 55A30, 17B66E0, 1C3698C

EDF6 talk SGO inventory and added voices

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-sgo-entries

EDF6 has 30 talk SGOs in sound/ (EDF5's 20 plus colonel, corporal, lieutenant, professor, alien_martian, alien_venus, mob_dirty_man / _woman, n601_common_ranger(_leader)); all hold 2257 tables (281 empty), 16289 entries, 8625 distinct cues. A table is [speaker, a float, 0, 0, [entries]] as in EDF5, but each entry is a dictionary {'#0'..'#12', 'mask'} (EDF5's entries are plain 13-element lists, without mask): #0 cue (AA001B*, * replaced by the speaker's variation letter, #talk-wildcard-resolver), #1 animation, #2 weight, #3 the byte mask (-1 = always), #6 reply table or 0, #11 / #12 the window, mask e.g. 8 (ranger_talk.sgo 平常時, idle chat) or 65535.

Basis: Root.cpk read with File_Storage/Logs/catalog/kh154_talk_lines.py edf6 (scratch; one row per entry in kh154_talk_lines_edf6.txt beside it)

Attribution: KH chat 154 (autorun) · 2026-11-13

Mission voice-table SGO and chatter text limits

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-no-captions

The words of NPC chatter are in no text table: the voice table mission/edf6_voicetable.<ja|en|kr|cn|sc>.sgo ({table: {key: {name, caption}}}, 13869 keys in English) holds mission dialogue (BE 6858, AE 4907, AEX 802, BEX 664, DLC_BE 408, DLC_BEX 136, BEE 82) and only 11 AI-voice keys (AL, AM, AT, AF, AD, BU, e.g. AT301BA "Thanks for saving me!"); of the talk SGOs' 8625 cues, 7 have a caption. A bad-cue list therefore cannot come from text: it needs the audio (the voice banks) or novae (ajane)'s report of a heard line plus its situation (the table names say the situation in Japanese: 平常時 idle, 走り出す starting to run, ...). The line start calls 7B17F0 with the cue (5DB6A7) only when the sound is not playing and line+0xC bit 2 is set, and stores a frame count from the result at line+0x7C (meaning not read).

Basis: the voice table and talk SGOs read with kh154_talk_lines.py (scratch); fn.py read of 5DB680..5DB6D2

Addresses (build-specific RVAs unless indicated): 7B17F0, 5DB6A7

Music (BGM)

SeManager music handles and entry functions

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-bgm-play-paths

EDF6's music lives on the SeManager [20B2950] (bank ref +8, the music handle +0x20), with four entry functions, each taking the cue as a narrow const char* in rdx: 7B27B0(SeManager, cue) plays (cue id from 7AA150; if that cue is already playing on the handle (7A8920) it returns 1 without a restart, else it stops the group [+0x18] (7AF260 on the SoundSystem [20B2948]) and plays through 7AA7B0(+8, cue, 1.0, 1.0, handle, 0)); 7B15E0(SeManager, cue, frames) cross-fades (fade out 7A8CD0, play 7AA7B0, fade in 7A8860); 7B2EF0(SeManager, cue, frames, start seconds) seek-plays (stops the group, plays by cue id through 7AA700 with the start in ms (x 1000), then fades in); 7B2E30 is the seek-play's cross-fade form (fade out, 7AA700, fade in). The stop is 7B2FF0(SeManager, frames) = 7A8CD0 on the handle.

Basis: fn.py reads and --xref of each; [1765A80] = 1000.0 read from EDF.dll

Addresses (build-specific RVAs unless indicated): 20B2950, 7B27B0, 7AA150, 7A8920, 7AF260, 20B2948, 7AA7B0, 7B15E0, 7A8CD0, 7A8860, 7B2EF0, 7AA700, 7B2E30, 7B2FF0

The sound system, presets and vehicle sounds (round 24, All Forces)

CRI ADX2 middleware and listener configuration

Evidence: static · Build: steam-678ccb46 · Fact ID: sound-system-listeners

Middleware and listeners: CRI ADX2 is statically linked (CRI AtomEx/PCx64 Ver.2.22.5, CRI Atom/PCx64 Ver.2.22.89); the init 7AE100 loads APP:/SOUND/ADX/TIKYUUX.ACF, TIKYUUX_SE.ACB (resident) and SOUND/SEPRESET.SGO (7B0690). The game does not use ADX2's 3D positioning: none of the 146 CRI functions it calls is a 3D source, listener or velocity call; each frame it computes the volume itself from the nearest listener (1/r beyond the reference distance), the pan angle and an interior distance (7ACD20), so there is no Doppler and a listener is only a position. Globals: SeManager [20B2950], SoundSystem [20B2948] (705950 calls 7AF3E0 with it every frame). 7AF3E0 takes the matrices +0x220..+0x250 of the four cameras (1195BE0([20B2958], i)) and stores the listeners at SoundSystem +0x58 (count +0x68, 0x50 each: the position, then the four rows of the camera's inverse matrix); listener 0 is the player's camera (camera-space x = p.x R1 + p.y R2 + p.z R3 + R4, +x the camera's left: "L" until heard in game). Master and effects volume: GameStatus+0x2E8 x +0x2F0.

Basis: the author's static reading ("H"; the listener axis "L")

Addresses (build-specific RVAs unless indicated): 7AE100, 7B0690, 7ACD20, 20B2950, 20B2948, 705950, 7AF3E0, 1195BE0, 20B2958

Complete original research record — expand (1,659 characters)

SePreset (0x80 bytes, initialized by 7B3200): +0x00 position, +0x10 interior radius, +0x14 reference distance (beyond it volume = ref / distance), +0x18 cull multiplier (a sound is not started when the distance exceeds ref x multiplier; checked only at the start), +0x20 five ground-material slots {bank, cue index}, +0x70 pitch, +0x74 volume; a SEPRESET entry is [cue, volume, pitch, interior, ref, cull multiplier] (written by 7B3840). SoundHandle (16 bytes, zeroed) = {ctrl, inst}; the instance (0x70): +0 dirty flag, +0x28 pitch, +0x2C volume, +0x40 position; the system's list holds its own reference, so destroying a handle does not stop the sound and loops must be stopped. Calls: `bool 7B16F0(SeManager, SePreset* out, const wchar_t* name, bool)fills a preset by name (an unknown name gives an empty preset, bank null, and returns false without any error path);bool 7B2A80(SeManager, const Vec4 pos, const wchar_t* name, SoundHandle* out)plays by name;7B4510(SePreset, const Vec4 pos, SoundHandle* out)plays a preset (returns at once when the bank is null, so zeroing the {bank, cue} slots silences a preset);7A8C20(h, const float[3])/7A8BF0(h, float)/7A8C70(h, float)set position / pitch / volume (they only write the instance and mark it dirty;7AF3E0applies them next frame); pitch in cents = clamp(p x 0.5, 0, 1) x 2400 - 1200 (p = 1 unchanged, 0..2 one octave down / up);bool 7A8A20(h)playing;7A8CD0(h, int fadeFrames)stop (<= 0 at once);7A8730(h) release. Vanilla use: MissileBullet01 (26A880) plays with 7B4510at ignition, moves the sound with7A8C20each frame and stops it with7A8CD0(h, 4); the bombing plane BombingPlaneplays7B2A80(L"空爆機体通過")`.

Weapon lock-on search and confirmation beeps

Evidence: static · Build: steam-678ccb46 · Fact ID: lockon-beep-presets

Lock-on beeps: every weapon's init (68A920) loads two SEPRESETs by name whatever the weapon: 68E90B ロックオンサーチ -> weapon +0xCC0, 68E928 ロックオン完了 -> +0xD40 (names at 17E3148 / 17E3160, loaded with 7B16F0([20B2950], ...); cues weapon_Common_lockonSearch / _lockonLocked, reference distance 10000 m, so full volume within 10 km); no weapon SGO has a lock-sound key. The lock tick 6963A0 plays them (69656F / 6965D9 -> 7B4510) unless the holder (weapon +0x120) has +0x1A bit 3 (the object runs AI: vanilla NPC soldiers do, players do not); vehicles never have the bit, so an NPC-driven vehicle's lock beeps sound in the player's ear ("H" / "M"). These two are the only cockpit-style cues in TIKYUUX_SE.ACB: the game has no warning voices or stall horn.

Basis: the author's static reading ("H"; the vehicle consequence "M"); 68E90B..68E928 and the first name re-read with fn.py

Addresses (build-specific RVAs unless indicated): 68A920, 68E90B, 68E928, 17E3148, 17E3160, 7B16F0, 6963A0, 69656F, 6965D9, 7B4510

Vehicle sound tables: a vehicle SGO has only game_sound (an ACB) and SEPRESET name tables, no engine parameters. The engine sound 676370 (slot 74, +0x250, of 402, 403, 404, 503, 505, 510, 511, 601, 603, Car, CarBase, TankBase, ...) per frame: the throttle (virtual +0x258, mapped and eased) to +0x1A80 (0..1); with a driver (virtual +0x270) the idle loop +0x1A40 plays [0] at volume 1 - throttle, +0x1A50 plays [1] at volume = throttle and pitch = virtual +0x260, +0x1A60 plays [2] with the volume eased by the steering (+0x268) into +0x1A84, +0x1A70 the water sound [10]; each "updates while playing, else plays the preset". BOMBER401 / 501.SGO have no sound keys. Proteus's per-frame input is 648F70.

Sound files under Mods: the path converter maps app:/sound/adx and APP:/SOUND/ADX to ./sound/pc / ./SOUND/PC and app:/ to /cri_bind/ (mod-loading.md#io-funnel), and BlueAmulet's EDFModLoader, which hooks the CRI stream Open (741C0, vtable 175F0F0 slot 1), retries only a path that starts /cri_bind/ as ./Mods/<rest>.

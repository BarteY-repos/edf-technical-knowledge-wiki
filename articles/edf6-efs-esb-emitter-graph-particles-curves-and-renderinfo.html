EDF6 EFS/ESB effects: effect roots, emitters, particles, animation curves and renderers

EDF 6Game technical referencesEffects and rendering
Technical reference · Source-declared grades; this edition does not add native game runtime testing

EDF6 has an EFS effect graph that is distinct from ordinary model materials and audio. In the source's native examples, effect definitions are .esb resources inside .efarc archives whose layout resembles RAB. An .efarc can hold its model, texture and sprite-setting resources alongside the effect definitions. The graph dispatches components, not one monolithic particle object.

Hierarchy and timing

Node Role
Effect Root References the effect to dispatch, an integer start delay in frames and an unknown field
Effect Owns an array of components, a system lifetime and additional unresolved fields
Singleton One model, glow, quad or other renderer with transform and color
Emitter Repeatedly creates moving particle instances from a shape and emission rule
NodeParticle_Particle2D Defines lifetime, color, scalar curves and 2D-oriented particle rendering
NodeParticle_Particle3D Defines 3D particle movement/scale/rotation evolution and lifetime

The source observes Effect Root with the child effect reference before its timing/unknown values in the raw binary order. A third-party XML tool may present a different field order. Tool output ordering is not proof of a different EDF6 wire format.

Emitter anatomy

The observed 17-field emitter includes NodeTransform, emission NodeShape, a particle definition, color, initial rotation/scale, initial-speed curve, an EmissionRate curve and a MaxParticle limit. One field is labelled IsRelative: in the source's interpretation, relative particles continue moving with the parent emitter, whereas non-relative particles can trail behind. Several unclassified integer and float fields remain unknown and should not be given invented enum names.

AnimationCurve contains a type/flags region of uncertain meaning, a float variance, a keyframe count and seven floats per keyframe. The source identifies keyframe time and value; the other five floats are not decoded conclusively. A time value is usually frames, but the source explicitly notes exceptions.

Rendering a particle

RenderInfo_Texture uses a referenced texture, scalar size, a render-mode field and optional geometry such as a ring mesh. RenderInfo_Model uses an embedded .mdb model and can carry animation-driven shader parameter changes. RenderInfo_LocusExtendLine creates a trail whose length/lifetime and width can evolve over time; RenderInfo_ExtLine stretches a line between an earlier location and the particle's current position.

Some texture render flags appear to affect blend mode, screen-depth interaction or rotation, but their exact semantics are not settled. Different language pages and experiments disagree on one rotation flag. A reader should preserve native values rather than normalizing everything into a guessed universal material type.

Evidence limits

The node families, archive relationship and selected fields come from static inspections and documented community experiments. This edition neither generated new effects in EDF6 nor tested every emitter type. EFS and regular .mdb materials have independent lifetime and rendering contracts, even when an effect renderer references an MDB asset.

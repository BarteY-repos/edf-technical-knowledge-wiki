EDF 4.1 Earth Eater panel physics lifecycle

UniversalMissions & ScriptingCollision & PhysicsEDF 4.1EDF 6
Source-backed research / case study · Static root cause + source patch audit; runtime pending

Root cause: physical ownership begins too early

EDF4.1 PanelBase does not own its physical shell immediately after object construction. The source binary reaches the panel shell builder only after the panel has been triggered and its fly-in delay has expired.

The EDF6 bridge uses EventAnimationObject. That target object eagerly constructs the SGO ragdoll. Before the R13 reconciliation, an Earth Eater panel could therefore exist physically during a source lifecycle interval where EDF4.1 had only the controller/visual object.

This explains a concrete gameplay divergence: enemies can already obtain ground/spawn/leg interaction against panels that should not yet physically exist.

Damage rejection alone does not solve this; a body can still participate in physics queries while rejecting damage.

Native EDF6 mechanism

The bridge does not invent a new collision filter. It uses native ragdoll world-membership control from the canonical EDF6 binary:

  • Ragdoll::Disable RVA 0x6E97C0;
  • Ragdoll::Enable RVA 0x6E9840.

Disable removes ragdoll bodies from the physics world while preserving their previous body mode. Enable restores the same bodies using the saved mode.

R13 reconciliation behavior

For MotherShip401 panels, the WIP does the following:

  1. construct/register the EDF6 EventAnimationObject;
  2. immediately disable the panel ragdoll before online attach;
  3. retain a first-update fail-safe while the panel is untriggered or delayed;
  4. once triggered && delay <= 0, restore the same ragdoll before fly-in motion;
  5. leave batteries untouched.

The focused offline audit reports 12 PASS, including PE/RVA/prolog validation against the canonical EDF6 binary.

What this fixes

This specifically repairs the pre-activation shell divergence between EDF4.1 and the EDF6 bridge.

It is intended to prevent inactive Earth Eater panels from acting as premature physical surfaces for spawning, grounding and movement queries.

What remains open

This does not prove active-panel collision fidelity.

The targeted source-input package contains 13 MOTHERSHIP401_*.SHKT files. The remaining active-state work is to compare:

  • source rigid bodies;
  • collision/filter layers;
  • materials;
  • query semantics;
  • the current EventAnimationObject shell.

Only evidence-backed active-state differences should be changed.

Implementation rule

Do not replace this lifecycle fix with blanket invulnerability, damage filtering or guessed collision layers. Lifecycle ownership and active collision semantics are separate problems and must remain separately testable.

Later source-runtime collision-layer result (November 15, 2026)

A separate active-state source audit resolved the previously unknown layer distinction. All 13 retained EDF4.1 MotherShip401 SHKTs (29 bodies) author layer 0. Among 18 part SGOs, only UFOMOTHER401_COREPANEL.SGO has is_keyframe_ragdoll=1: EDF4.1's PanelBase then sets its ragdoll to layer 7. The regular branch retains the ragdoll's SHKT-authored layer 0; its independent object+0x3F0 helper uses layer 13, not the ragdoll. The examined EDF6 EventAnimationObject forced its ragdoll to layer 17. Source-aligned 0/7 restoration before Disable is now a bounded candidate, not a runtime-proven fix. See full original Mother401 ragdoll layer evidence.

This new finding supersedes the older suggestion that no evidence-backed active-panel layer rule had yet been recovered. It does not change the requirement to test panel activation and actual enemy interaction in EDF6. Source: R13_FUNCTIONALITY_WIP_R12_MOTHER401_SOURCE_RUNTIME_LAYER_EVIDENCE.json.

R175 active-panel query visibility is a third independent state

The original pre-activation world-membership rule above is unchanged. A later exact-build source comparison adds a third, independent constraint after activation: the ordinary EDF4.1 panel's main ragdoll rigid bodies remain on authored layer 0, while a separate internal query container uses layer 13. The keyframed core uses main ragdoll layer 7. Merely calling Enable() at the correct time does not reconstruct this query configuration, and merely changing the target ragdoll's layer does not prove the correct activation timing.

The examined EDF6 area-damage query also operates on layer 13. Whether it sees an ordinary layer-0 target rigid body depends on the actual deserialized group-filter table, not on layer numbers alone. The later static translation is therefore conditional: preserve 0 when query 13 sees 0, choose 7 only if it cannot see 0 but can see 7, and otherwise keep 0 with visibility unresolved. This candidate cannot be called a runtime repair for spiders, Deroye, flying units or the reported premature panel contacts.

See the exact source and target layer/query matrix. Evidence: the later R13_FUNCTIONALITY_WIP_R13_MOTHER401_QUERY_PROXY_EVIDENCE.json, which refines the older R12 discussion; it does not supersede the already-verified source activation-boundary finding.

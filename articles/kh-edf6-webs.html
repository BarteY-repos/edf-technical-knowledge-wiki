EDF 6 — Webs (community source notes)

EDF 6Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

The web bullet

SpiderStringBullet01 (TD 2025B78, vtable 17A31E0

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-bullet-slots

SpiderStringBullet01 (TD 2025B78, vtable 17A31E0; NetworkObject part at +0x120, vtable 17A3260): slot 3 27FD90 rebuilds the draw vertices +0x1040 (0x30 each) from the thread nodes +0xF20 (0x90 each, count +0xF30) and copies +0xFED to +0x1058 and the timer +0xFE8 to +0x105C; slot 5 27FEA0 is the update (#edf6-web-reel); slot 14 27FC30 the hit callback (#edf6-web-attach); slot 19 27F270 the online receive, which attaches with the flag set (27F85C mov r8b,1, 27F869).

Basis: RTTI (scratch rtti.py); fn.py reads

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-anchor

A web's anchor is a matrix pointer at web +0xB20 (bullet base parameters +0x40; the base parameters sit at web +0xAE0, objects.md#bulletbase-params, and at Nephila +0x1100, passed at 4E36C2): the Nephila sets +0x1140 = its own +0x1070 (4E275A) and the owner pair +0x1108 / +0x1110 to itself (4E2780), and its slot 5 4E0870 copies the world matrix of its locator +0x1060 (6BB5A0) into +0x1070..+0x10AF every frame (4E08E3..4E0904). So the anchor's position [[web+0xB20]+0x30] is the Aranea's +0x10A0, the web's shot origin (4E37BB); thread node 0 is pinned to it each step (27D058..27D06A, skipped once the weak holder +0xB30 / +0xB38 has expired). The owner (the Aranea) is the weak pair +0xAE8 (object) / +0xAF0 (control block).

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): 4E36C2, 4E275A, 4E2780, 4E0870, 6BB5A0, 4E08E3, 4E0904, 4E37BB, 27D058, 27D06A

Catching: the shared grab object

The hit callback 27FC30(web, target) returns at once on an online copy (a session test on 20B2890, then byte…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-attach

The hit callback 27FC30(web, target) returns at once on an online copy (a session test on [20B2890], then byte +0x1070 set), resolves the target and the owner (+0xAE8), lets the target filter the owner (549DE0 -> target slot 0x110) and calls the attach 280F70(web, target, 0), then 280990(web, target, node index, attached) (inferred: sticks the thread node that hit). 280F70 allocates a 0x2E0-byte grab object (constructor 6C90E0) and initializes it with 6C9840(grab, kind 2, holder = the owner, 0, 1.0); it sets the grab's +0x178 (first-hit damage, default 10.0) to 0 and +0x17C (default 1.0) to the web's damage +0xB4C x 0.5 (1C36990; the reader of +0x17C not followed).

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): 27FC30, 20B2890, 549DE0, 280F70, 280990, 6C90E0, 6C9840, 1C36990

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-grab-object

The grab object is shared with jaw grabs: 6C9840(grab, kind, holder, r9, float) stores kind +0x138, holder +0x168 (and +0xE0), +0xC0 / +0x170 = r9, +0x160 = the float, +0x174 = 0 (active flag), +0x178 = 10.0, +0x17C = 1.0, +0x180 / +0x184 = 0.5. Kinds by caller: the ant's grab 4057C0 and 433EC0 pass 1, the Tadpole's 32E260 a variable, webs 2 (280F70), the Aranea's own grab 4E8BA0 3. An ant's bite damages its held target through the same object (6C9FE0 -> 6CA920, enemy-attacks.md#ant-bite-damage-level).

Basis: fn.py reads of 6C9840 and its five callers

Addresses (build-specific RVAs unless indicated): 6C9840, 4057C0, 433EC0, 32E260, 280F70, 4E8BA0, 6C9FE0, 6CA920

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-grab-capture-messages

The capture 6C92F0(grab, target, hit part, flag) first releases any old target (6C9E90), then sends the target ObjectMessage 0x10000009 through its slots 0x50 / 0x48 / 0x58 with the payload {+0 kind, +8 holder, +0x20 hit part, +0x28 flag}; the reply decides. Accepted: grab +0 / +8 hold the target's shared reference, +0x10 the hit part's index (-1 none, -2 not found), +0x174 = 1, and kinds other than 2 deal +0x178 at once (6CA920, type 1). Refused: +0x178 x 4 (1765A34) once per target (a set at +0x290). While held, 6CA190 sends 0x1000000A each frame (6CA80D) with the hold point; the release 6C9E90 sends 0x1000000B (6C9F18).

Basis: fn.py reads; the message ids found by a whole-module search for the constants (three hits)

Addresses (build-specific RVAs unless indicated): 6C92F0, 6C9E90, 1765A34, 6CA190, 6CA80D, 6C9F18

The target's side: GameObjectBase's message handler 54A530 (jump table 54A928 over 0x10000000..0x1000000F) ta…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-capture-state-39c

The target's side: GameObjectBase's message handler 54A530 (jump table 54A928 over 0x10000000..0x1000000F) takes 0x10000009 at 54A763 ("GameObjectBase::OnCapture", log strings 17CDB10; with the payload flag "OnlineOnCapture", 17CDB60): without the flag it needs +0x380 bit 1 set, bit 11 clear, +0x39C == 0 and slot 0xE0 to accept; with it, slot 0x160 must answer false and slot 0xE0 accept. It then writes +0x39C = the kind. 0x1000000A calls slot 0xE8 (54A8CC); 0x1000000B calls slot 0xF0 and clears +0x39C (54A8DF). So +0x39C is the captured-by kind: 0 free, 1 jaws, 2 web, 3 the Aranea's grab (player.md#soldier-jump-request-dismount: non-zero while attached).

Basis: fn.py reads; the jump table read as dwords

Addresses (build-specific RVAs unless indicated): 54A530, 54A928, 54A763, 17CDB10, 17CDB60, 54A8CC, 54A8DF

The pull and the release

The web's update 27FEA0: with the owner gone (+0xAE8 expired) every grab is released and the list +0xFC0 (cou…

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-reel

The web's update 27FEA0: with the owner gone (+0xAE8 expired) every grab is released and the list +0xFC0 (count +0xFC8) emptied; the timer +0xFE8 gains 0.01 (1765A00) and +0xFED is cleared. Per held target (list node +0x18 = the grab; grab +0x2C0 target, +0x2C8 rope length, +0x2CC best distance, +0x2D0 stall frames, set at 280F70): a target gone or with +0x39C != 2 is dropped; d = target +0x90 - anchor; L = max(0, +0x2C8 - 0.05 (1765A04)); a longer d is cut to L; +0x2C8 = |d|; the hold point anchor + d goes to 6CA190 (280274). So once taut the rope shortens 0.05 m a frame (3 m/s at 60 fps).

Basis: fn.py read; constants by scratch flt.py

Addresses (build-specific RVAs unless indicated): 27FEA0, 1765A00, 1765A04, 280F70, 6CA190, 280274

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-update-more

More of 27FEA0: when the held target is player-controlled (slot 0x108) the web's sound +0x1060 plays at the target's position (7A8A20 / 7B2A80 / 7A8C20, 2803B2..280426); when it has a local pad (+0x340 non-null) +0xFED = 1 (280347, 7 bytes mov byte [rsi+0xFED],1, with rsi = the web, r15 = the held soldier, rdi = the grab). Stall rule: when the distance to thread node 0 does not beat +0x2CC by 1.0 (1C36994), +0x2D0 counts up; past 600 frames (0x258, 10 s) a local target (+0x128 bit 0 clear) is let go (280D50, then 6C9E90, 280408).

Basis: fn.py read

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-web-pull

The soldier's held update 571540, kind 2: v = (hold point (payload +0x30) - +0x90) x 0.1 (176C230) x 60 (1768E20), i.e. 6 x the gap per second, stored at +0x1070; above 30 m/s (|v|² > 900, 17D0EDC) the walk controller is detached (11B9880) and 11B9470 gets v's direction (character-control.md#walk-launch). The pre-update adds +0x1070 to the move velocity only while +0x39C == 2 (57597E..5759B7), before the hit push +0x11F0 and the walk push +0x1210. Kind 1 instead moves the held ragdoll part (11B18F0, 11B1760, 11B1A00, 6E4EF0); kind 3 sets the walk controller's position (11B9850) and zeroes the velocity +0x6B0..+0x6B8.

Basis: fn.py reads; constants by scratch flt.py

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-aranea-web-list

The Aranea keeps its webs in a list at Nephila +0x12B0 (count +0x12B8; node +0x18 control block, +0x20 the web) and its slot 5 calls 27F080(web) for each live one (4E0940): a held target within 1 m of the anchor (|d|² < 1.0) is let go from the web (280D50, 6C9E90) and returned, and the Aranea hands it to 4E6040 through the handle at +0x1040 (4DBA40); inferred, unverified: that starts its own kind-3 grab (4E8BA0), the bite. Expired list entries are removed (4E09B7).

Route and open questions

Route for an on-screen arrow to the Aranea holding the player (untested): (1) caught = the local soldier's +0…

Evidence: unverified · Build: steam-678ccb46 · Fact ID: edf6-web-arrow-route

Route for an on-screen arrow to the Aranea holding the player (untested): (1) caught = the local soldier's +0x39C == 2 (#edf6-capture-state-39c); (2) the holder: hook 280347 (#edf6-web-update-more), which runs only for a target with a local pad, and each frame keep every web seen with its anchor [[rsi+0xB20]+0x30] (= the Aranea's +0x10A0, #edf6-web-anchor) and owner +0xAE8 (live while [+0xAF0]+8 != 0); several webs can hold one soldier. Without a hook, the soldier's +0x1070 points from the soldier toward the anchor, but it is zero while the rope is slack (#edf6-web-pull). (3) Draw: project the anchor with 81EC50 and the HUD camera (damage-numbers.md#damage-projection-helper, #damage-drawer-camera; 1920 x 1080 UI space, #damage-ui-coordinates) and turn an off-screen or behind-camera point (w <= 0) into an arrow at the screen edge.

Basis: built from the lines above

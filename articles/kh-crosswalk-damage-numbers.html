Technical reference · Community crosswalk, source-reported classifications

Native damage-number display

  • edf6: native, data-driven display (HUiHudDamage, styles from lyt_HudDamage.sgo, digit drawer DamageNumberDrawTexture), fed by the damage function's event through the player cameras | ref: edf6/damage-numbers.md#native-damage-display, #damage-event-payload | evidence: static (parts verified in game)
  • edf5: no native display: EDF5.exe has no DamageNumber or HudDamage classes (RTTI search, done from the EDF6 side). EDF5 damage numbers come from mods: Eiton's EDF5-Damage-Number-Display (a D3D11 / Dear ImGui overlay plugin, MIT) | ref: edf6/damage-numbers.md#damage-display-edf6-only, edf5/mods/damage-number-display.md | evidence: static
  • edf41: not looked at.
  • Differences noticed: EDF6's FixedPos style follows the same rules as the EDF5 mod's fixed list (merge window, stack upward, expiry after the last hit, pop), and both work in 1920 x 1080 UI pixels with y down, so EDF5 Pos_X / Pos_Y values carry over (edf6/damage-numbers.md#damage-ui-coordinates). The EDF5 plugin counts its windows in Present frames (frame-rate dependent); the EDF6 merge window's unit: edf6/damage-numbers.md#damage-number-merge.

Where the damage is caught

  • edf6: the damage function's own event to the attacker | ref: edf6/damage-numbers.md#damage-event-dispatch | evidence: static
  • edf5: Eiton's plugin hooks the HP add inside the damage function 2DB370 at 2DB641 (every hit on every object; record, target and final damage in registers) | ref: edf5/combat.md#damage-hp-apply | evidence: static
  • Differences noticed: both games route hits through one damage function per object; EDF5 has no event to listen to, so its mods patch the HP write.

Damage event and hit message

  • edf6: the damage function 547C30 sends one event per hit to the attacker's vfunc 0xA8; hit message 0x10000000 | ref: edf6/damage-numbers.md#damage-event-dispatch, edf6/damage-model.md#hit-handler-coverage | evidence: static
  • edf5: hit message 0x80000000 | ref: edf5/combat.md#lethal-damage-message, crosswalk/player-combat-fields.md | evidence: verified in game
  • Differences noticed: message ids and message vfunc slots differ (edf6/combat.md#message-vfuncs); whether EDF5's damage function has the same event call is not recorded.
  • Confidence in the mapping: high that EDF5 has no native display (RTTI); medium for the hook-site comparison (both sides static).
  • Added: 2026-10-28 src: novae (ajane), RE notes rev 7, EDF5 side from Eiton's plugin source (KH chat 20, 2026-10-28)

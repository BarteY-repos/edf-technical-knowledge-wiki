EDF6 weapon drop eligibility: P8 filtering, level window and DLC2 test

EDF 6Missions & ScriptingWeapon rewards and DLC classes
Technical reference · Source-derived; separates static evidence and the limited modded-runtime results

EDF6's weapon candidate selection checks more than a mission's difficulty and nominal reward-level range. Binary analysis and a limited test in a modified EDF6 runtime identify a class filter driven by WEAPONTABLE source property P8. It is a loot-family discriminator, separate from the mission's ModeList or MissionPack number.

Candidate-filter sequence observed in one EDF6 binary

In the examined EDF.dll (SHA-256 0d5092393a1b9d8f1b75b0c93d8a8f65615a36a92c46e40349c2b66c733d0916), the trace is:

  1. ResolveResult() at EDF+0x2C92E0 derives the eligible weapon-level interval.
  2. A downstream candidate-builder entry near EDF+0xD81E0 reads decoded weapon rows; the analyzed source fields include P5 and P8.
  3. The P8 filter is applied before the level-range filter. In the observed native rule, P8=0 passes this classification check; nonzero P8 must equal the active logical MissionPack ID.
  4. Eligible rows then continue through their level checks and the remaining game-selected reward steps.

The decoded runtime structure at this stage included source P5 at +0x1C and P8 at +0x28; these are runtime decoded record offsets, not asserted bytes within raw file storage. The symbol names and RVA observations apply only to the cited binary build.

P8 is not the MissionPack number

This table describes the class gate, before considering level ranges or other downstream conditions. DLC1 and DLC2 classes each include common/base P8=0 rows; P8=1 and P8=2 are not interchangeable. In the observed custom port, MissionPack03, 04, 05 represented native content classes 0, 1, 2; that relationship was created deliberately and is not an automatic stock EDF6 rule.

Actual DLC2 discrimination test

The retained 5 October 2026 test used a modified MissionPack09, explicitly assigned DLC2 class 2, with EDF6's native IG_TEST_BLUEFLD map. Five SilverSpiders were placed in a simple mission to supply boxes. The offline preflight validated the source and binary signatures; a separate later game run reported:

Runtime observation Recorded value
Class resolution packEntry=9, desired class 2
Candidate level calculation lo=81.25, hi=106.25, extra=1.25
Scanned P8=2 rows 110
Newly admitted rows (FIX_ADD) 34
Added candidates' levels 106.25–107.50
Sample added row index 1451, level 107.50, P8=2
Visible result-screen drops N9 Eros Vulture ZAM and Gigantocopter 3 Delta, both Lv 107, Air Raider

This test is runtime-positive evidence that the patched candidate builder can admit and reward DLC2-exclusive weapons for a custom MissionPack that the native ID-to-P8 comparison would otherwise exclude. It is not evidence that unmodified MissionPack09 naturally selects DLC2 loot, that higher than Lv 107 rewards were observed, or that every row in the 110-row class was awarded. The high-end hi+extra behavior was recorded in the test interval; it should not be generalized into an undocumented global reward formula.

Why some older negative tests are not evidence

Earlier experimental runs labeled R1 and R2 failed their binary signature validators before the required game hooks could run. Their apparent no-op behavior therefore cannot falsify the loot-class hypothesis. In R1 the caller signature was anchored at an incorrect instruction boundary; R2 expected an incorrect ResolveResult() prologue. The later runtime observation comes from a distinct, validated test candidate. This section concerns confidence in the findings, not instructions to install any of those loaders.

Follow-up: original EDF5 DLC2 port mission in MP05

A separate, later game run used the actual EDF5 DLC2 mission content in a customized EDF6 MissionPack05, rather than the earlier instrumented MissionPack09 demonstration. The validated diagnostic log reported four true MP05 scans (n=2…5), with packEntry=5 translated to loot class 2. Its recorded eligibility interval was lo100=8798, hi100=11298, extra100=125 (hundredth-unit values). The log contained 392 FIX_ADD records across the MP05 scan output. The newly admitted DLC2 P8=2 candidate levels included 106.25, 110.00, 111.25, 112.00 and 112.50.

This is stronger evidence for class-2 candidate admission in real EDF5 DLC2 port content, rather than only the deliberately assigned MP09 test fixture. The number 392 is a count of logged additions, not a proven count of 392 distinct weapon identities or awarded items. Nor is a candidate of level 112.50 proof of an on-screen Lv112 reward: the earlier MP09 run separately showed two awarded Lv107 weapons, while the later MP05 evidence establishes admission to the scanned pool.

What remains unproven

The MP09 runtime acceptance confirms DLC2-exclusive Lv 107 rewards in one instrumented game session. A separate real-MP05 DLC2 session confirms additional eligible candidates up to 112.50, not on-screen 110+ awards. Together they still do not qualify all DLC1/DLC2 or arbitrary packs, all difficulties, every weapon level, or the distribution of high-level rewards. No new game run was performed for this wiki article.

M008 black screen — compile root cause and later runtime closure

UniversalMissions & ScriptingMissionsEDF 5EDF 6
Source-backed research / case study · Root cause proven; compile/load runtime PASS

Current status: the old black-screen/AngelScript compile blocker is closed at the compile/load runtime level. The root-cause analysis remains useful because it explains exactly what was wrong in the obsolete generated lineage. The later R65 runtime sweep confirmed that freshly maintained output loads successfully offline. This is not, by itself, a claim of full deep gameplay parity for every M008 event.

Original direct error evidence

Canonical errordbg reached compilation of __0006_game_event_usercode() and failed with:

Can't implicitly convert from 'bool' to 'int&'.

The observed black screen therefore occurred before normal mission runtime: generated AngelScript failed to compile.

Malformed lowering in the obsolete output

The old generated M008 AC contained two broken carrier-polling loops. Defects included:

  • IsAiMoveEnd(carrier01/2/3) query results emitted as discarded statements;
  • a boolean expression written into Func_1___Counter;
  • loc_0x02 used as an int while also receiving boolean expressions;
  • a while(true) loop with conditional continue paths but no valid terminating break path.

The same pattern affected arrival and departure waits. The working semantic shape is one boolean "still moving" flag, OR-composed from !IsAiMoveEnd(...) for the relevant carriers, with the HARDEST+ fourth carrier included when applicable, yielding until all required actors report completion.

Why the early diagnostic still matters

M008_R50_BOOL_POLLING_COMPILE_FIX_2026-09-04.zip was a narrow discriminator that rebuilt only the malformed polling logic and kept map, weather, RMPA, preloads and spawns stable. It demonstrated the intended oracle-equivalent control flow without requiring a mission-wide workaround.

Later maintained mission_ac_engine.py protections address this class generically: pending query results survive boolean/test opcodes and reconstructed polling loops require a real exit path. That generic direction supersedes an M008-name-specific patch.

Later runtime authority

The broad R65 runtime sweep was performed with full game restarts, primarily offline. In that sweep:

M008 #12 — PASS

The user-defined meaning of PASS in this sweep was mission loads successfully. The old black-screen/compile blocker no longer reproduced. R67 retained M008 in the PASS/load set.

Therefore the correct evidence statement is:

  • historical malformed bool/dataflow lowering: root cause proven;
  • current maintained output: compile/load runtime PASS;
  • deep content/gameplay parity beyond the load gate: a separate question, not implied by this PASS.

Negative hypotheses retained

An uppercase duplicate preload for E508_CARRIER.SGO did not fix the old black screen. Case-insensitive preload dedupe and compound-preload emission remain legitimate generator-quality concerns, but they were not the sufficient root cause of this M008 blocker.

Do not regress

Do not reopen the old preload hypothesis merely because the historical error is remembered, and do not downgrade M008 back to "runtime fix pending" unless new contradictory runtime evidence appears. Conversely, do not inflate the R65 load PASS into a mission-wide gameplay-parity certification.

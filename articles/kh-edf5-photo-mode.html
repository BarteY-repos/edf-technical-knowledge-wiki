EDF 5 — Internal debug camera and pause system (source notes)

EDF 5Community Knowledge HubNative UI & Input
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Terminology and availability: The upstream EDF Knowledge Hub organized this source page under the historical label "Photo Mode". In this wiki it means internal debug free-camera and pause/post-process code observed by static inspection of a specified retail executable, not an established player-accessible photo mode. The identified class and controls do not by themselves prove a retail menu entry, supported activation sequence or in-game usage. Keep the original fact IDs and build-specific RVAs for source traceability. No new live-game test was performed.

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

The pause bits (the world freeze)

The game system xgs::game::System (125AB68) holds the pause bits at +0x9B0 and the mask of bits allowed to pa…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-pause-bits

The game system xgs::game::System ([125AB68]) holds the pause bits at +0x9B0 and the mask of bits allowed to pause at +0x9B4; the game is paused while +0x9B0 & +0x9B4 is non-zero (tests at A887E, C730F and others). The constructor sets bits 0 and mask 0xFFFFFFFF (610850, 610857). The setter 614C90(system, bits, set) (or / and-not, then 614C10, the pause listeners' notify, when the paused state flips) has one caller, the free camera's constructor; every other user inlines the same and / and-not plus 614C10.

Basis: a .text grep for 0x9b0 / 0x9b4 (fn.py --grep), then each site read

Addresses (build-specific RVAs unless indicated): 125AB68, A887E, C730F, 610850, 610857, 614C90, 614C10

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-pause-bit-users

Who sets which pause bit, by value: 1 the debug free camera (set in its constructor at A772C, toggled in its update at A8B8C / A8B91, cleared in its slot 7 A9140 at A9195); 2 the pause menu (set at 586880 in 585FC0, cleared at 586A60 in 586A20; both reached only from function pointers at EDB0B8 and EDB318, beside the HUiPause names at EDB0C0..EDB3E0, so the pause menu is inferred); 0x10 three debug commands (cubemap_mode_set and create_cubemap_parts through 5DDE0, set 5DEE3, clear 5DFA9; lod_capture through 61D60, set 61FA3); all bits written 0 at 3D8774 (in 3D86A0, which also makes the ai::System) and 3D87C0 (in 3D87A0). Values 4 and 8 have no setter.

Basis: fn.py reads of each writer; the command names from the debug table 699B0 (wstr.py); --xref of 614C10, 585F10, 5869E0

Which bits may pause is decided per mode, as in EDF6: the mode setter 8ABB0 (GameDataMgr

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-pause-mask-offline

Which bits may pause is decided per mode, as in EDF6: the mode setter 8ABB0 (GameDataMgr; stores the mode at +0x38) clears bits 0xE (values 2, 4 and 8) from the mask +0x9B4 when the mode node's value 7, the online flag ([node+0x5C], #edf5-offline-modes-no-caps), is non-zero, and sets them back for an offline mode or mode -1 (8AC02..8AC4A). So online the pause menu (2) and the unused values 4 and 8 stop nothing, while 1 (the debug free camera) and 0x10 still freeze the local game.

Basis: fn.py read of 8ABB0; the mask writer is its only +0x9B4 store besides the constructor

Addresses (build-specific RVAs unless indicated): 8ABB0, 8AC02, 8AC4A

The built-in debug free camera (FreeViewCamera)

The retail EDF5.exe keeps the debug free camera FreeViewCamera (RTTI 11A4788, vtable E93768, size 0x510

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-free-view-camera

The retail EDF5.exe keeps the debug free camera FreeViewCamera (RTTI 11A4788, vtable E93768, size 0x510; InitParam, CdPointPinter and a CreateUnity callback type beside it): constructor A6D80 (base A9E40), update slot 4 A79D0, slot 7 A9140 (clears pause bit 1). The constructor binds 18 named controller inputs on the device from the init block's +0x80 (kept at +0x460), sets the start pose with A9530 (eye from row +0x1D0 to +0x440, angles from the forward row to +0x450), builds its own character controller at +0x468 (map layer 0x1E, 624DC0), sets +0x466 = 1 and turns pause bit 1 on (A772C), so the world is frozen from the first frame; FOV +0x24 = π/4, +0x30 = 1. Its two TargetCollectors at +0x488 and +0x4D0 (A6F71, A6F90) serve the B + Y ray (#edf5-free-camera-buttons; camera.md#edf5-free-camera-collectors).

Basis: rtti.py; fn.py reads of A6D80, A9530, A9A30 (mov ecx, 0x510 at A9ABC); --xref of the vtable (constructor and destructor only)

Addresses (build-specific RVAs unless indicated): 11A4788, E93768, A6D80, A9E40, A79D0, A9140, A9530, 624DC0, A772C, A6F71, A6F90

The free camera's inputs: 60A760(controller system 125AB28, binding, device, name) binds each by its UTF-16 name

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-free-camera-bindings

The free camera's inputs: 60A760(controller system [125AB28], binding, device, name) binds each by its UTF-16 name; the bindings are 0x18 bytes, updated inline at the top of the update (+0 source node, +8 repeat counter, +0xC analog value from node +0x48, +0x10 held from node +0x4C, +0x11 pressed this frame, +0x12 released, +0x13 repeat pulse, on press and then every 2 frames after 16, as in EDF6). Offsets: +0x290 LeftStickX, +0x2A8 LeftStickY, +0x2C0 RightStickX, +0x2D8 RightStickY, +0x2F0 RightTrigger, +0x308 LeftTrigger, +0x320 RightThumb, +0x338 LeftThumb, +0x350 RB, +0x368 LB, +0x380 Up, +0x398 B, +0x3B0 Down, +0x3C8 Start, +0x3E0 Back, +0x3F8 A, +0x410 X, +0x428 Y (EDF6 also binds Right). Whether a keyboard and mouse device carries these names was not read.

Basis: fn.py read of A6D80 (each lea rdx name with its lea rdx, [rsi + off]); names at E8C950 (X) and E8D3D0..E8D500 (wstr.py)

Addresses (build-specific RVAs unless indicated): 60A760, 125AB28

What the free camera's update A79D0 does each step (constants the same as EDF6's): the left stick moves (dead…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-free-camera-update

What the free camera's update A79D0 does each step (constants the same as EDF6's): the left stick moves (dead zone 0.08 EE624C, rescaled by 1.08696 EE6448), the triggers move up and down (RT minus LT), speed x0.25 or x1.5 while X is held (EE7210 / EE7CD0); the move is turned by the yaw; when the controller's state is 7 and the game is not paused it goes through the controller at velocity x60 (7DBB00, 7DBC80), otherwise the point +0x440 moves directly; A toggles the controller's layer between 0x16 and 0x1E (+0x464, A8506..A853F); the right stick turns: pitch +0x450 from RightStickY, clamped to ±π/2 (A8805..A8827), yaw +0x454 from RightStickX, both slowed by tan(FOV/2) / tan(+0x20/2) x 0.1; roll +0x458; rows built at +0x1A0..+0x1D0 (7CC70, 7CBA0), then multiplied by the 3x3 at +0x200 (A5900).

Basis: fn.py read of A79D0 (1161 lines, t7e5_A79D0.txt); flt.py

Addresses (build-specific RVAs unless indicated): A79D0, EE624C, EE6448, EE7210, EE7CD0, 7DBB00, 7DBC80, A8506, A853F, A8805, A8827, 7CC70, 7CBA0, A5900

The free camera's buttons, in its update A79D0: Start toggles the pause (+0x466, bit 1, written at A8B94)

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-free-camera-buttons

The free camera's buttons, in its update A79D0: Start toggles the pause (+0x466, bit 1, written at A8B94); Back's repeat pulse sets +0x465, which unpauses for one step and pauses again (a frame step); both thumb buttons reset the pose and FOV (A8496..A84E4); Y without B fires a RocketBullet01 from the camera (A9670; name at E93858); B + Y casts a ray from the eye (world vtable +0xE8, collector +0x4D0) and hands the hit to AC960 (not read).

Basis: fn.py read of A79D0 (t7e5_A79D0.txt); --xref E93858

Addresses (build-specific RVAs unless indicated): A79D0, A8B94, A8496, A84E4, A9670, E93858, AC960

How the free camera is made: the debug command table 699B0 (registered on the debug system 125AB78) holds fre…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-free-camera-create

How the free camera is made: the debug command table 699B0 (registered on the debug system [125AB78]) holds free_camera (5B690, string E90560), next_camera (5B800, E90578), stereo_camera (5B430, E90540), MapPreview / map_preview (53E20) and MapPreview_NoCollision (54180). free_camera takes two ints below 4 (view slot, input device) and calls A9320(&pose, slot, device, 1) with the pose copied from view slot 0's camera rows +0x1A0..+0x1D0 (views at system +0x238), then 6141C0, 613FF0 and 613D90(system, 1) (the system's object lists; not read in detail). A9320 first walks the four views (system +0x248, 0x188 apart, visitor vtable E93720) and stops if one already has a free camera, then A9A30 allocates 0x510 bytes, runs A6D80 and queues the camera on system +0x220 (lock +0xC0). How a view slot then switches to it was not traced.

Basis: fn.py reads of 5B690, A9320, A9A30; --xref of the command strings (each used once, in 699B0)

Post effects: what exists (bloom, auto exposure, AO) and what does not (depth of field)

EDF5.exe's 260 DXBC blobs hold no depth-of-field, bokeh, focus, motion-blur or vignette shader (no such resou…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-post-chain-shaders

EDF5.exe's 260 DXBC blobs hold no depth-of-field, bokeh, focus, motion-blur or vignette shader (no such resource or constant name). The post chain is compute shaders, named as in EDF6: resize 117F050 / 117F630 (ComputeResizeSetting), bright pass 117FE20 (ComputeHighPassSetting, with the tone buffer g_tone), blur 1180520 (ComputeGaussBlurSetting), exposure 117DDD0 (ComputeToneLerpSetting), combine 1164AB0 (ComputePostCombineSetting), plus depth helpers (ComputeDepthToViewZSetting 117E3C0, CalLinearDepthParam 1183A50) and the AO set (SceneParam 1184310 / 1185BA0, AOBlurParam 1181EC0 / 1187590, AOCompositeParam 11833E0); the dormant SSR set is separate (shaders.md#dormant-ssr-shaders). A linear depth therefore exists on the GPU already (for AO). The material shaders in DX11.cpk were not searched.

Basis: RDEF of every blob (t7_dxbc_all.py edf5, t7e5_dxbc.txt)

Addresses (build-specific RVAs unless indicated): 117F050, 117F630, 117FE20, 1180520, 117DDD0, 1164AB0, 117E3C0, 1183A50, 1184310, 1185BA0, 1181EC0, 1187590, 11833E0

The final combine 1164AB0 is the same as EDF6's (16x16 threads): out.rgb = scene (t0, loaded per pixel) x ton…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-post-combine-formula

The final combine 1164AB0 is the same as EDF6's (16x16 threads): out.rgb = scene (t0, loaded per pixel) x tone + blur0 (t1) x cb2[1].x + blur1 (t2) x cb2[3].x, alpha 1; tone is the one float of the structured buffer t3 (g_tone_data); the blurs are sampled at uv x cb2[0].zw / cb2[2].zw clamped to cb2[0].xy / cb2[2].xy. So exposure is one multiplier on the whole scene before bloom is added.

Basis: D3DDisassemble (t7e5_post_dis.txt)

Addresses (build-specific RVAs unless indicated): 1164AB0

EDF5's auto exposure 117DDD0 (one thread) has three settings, not EDF6's four: it reads texel (0,0) of t0 (th…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-auto-exposure-formula

EDF5's auto exposure 117DDD0 (one thread) has three settings, not EDF6's four: it reads texel (0,0) of t0 (the scene shrunk to its average, inferred), L = max(Y, 0.0001) with Y = 0.298912 R + 0.586611 G + 0.114478 B; with t = g_tone_lerp_brightness_target, k = g_tone_lerp_brightness_lerp, p = saturate(g_tone_power): goal = t / (p x (L - t) + t), then tone += k x (goal - tone), stored back to u0. So p = 1 maps the scene average to t, p = 0 gives a fixed tone of 1 (EDF6's center term is absent), and k = 0 freezes the tone where it is.

Basis: D3DDisassemble (t7e5_post_dis.txt)

Addresses (build-specific RVAs unless indicated): 117DDD0

Route and open questions

Photo-mode route for EDF5 (untested), the same as EDF6's: (1) freeze: set bit 8 in system +0x9B0 (or 4

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-photo-mode-route

Photo-mode route for EDF5 (untested), the same as EDF6's: (1) freeze: set bit 8 in system +0x9B0 (or 4; neither has a setter, both are masked out online, #edf5-pause-mask-offline) from the game thread, then call 614C10(system) when the paused state flips, as 614C90(system, 8, true) does; clear it to resume. (2) camera: either make the stock free camera with A9320(&pose, 0, device, 1) (it pauses by itself, flies, zooms and steps frames, but reads named controller inputs, #edf5-free-camera-bindings), or keep the player camera and overwrite its rows +0x1A0..+0x1D0 and FOV +0x24 at the camera's tail (camera.md#camera-tail-hook-site, #camera-final-matrix; the eye is lerped from +0x1D0 next frame, #camera-eye-lerp-and-view-source). (3) HUD: EDF5's counterpart of EDF6's camera +0x200 switch was not looked for. Steps (4) to (6): #edf5-photo-mode-route-2.

Basis: assembled from the lines above; nothing run

Photo-mode route for EDF5, continued (untested): (4) focal length: +0x24 is the vertical FOV in radians, f =…

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-photo-mode-route-2

Photo-mode route for EDF5, continued (untested): (4) focal length: +0x24 is the vertical FOV in radians, f = 12 mm / tan(FOV/2) on a 24 mm-high frame; the free camera allows 0.001..2.0. (5) exposure: tone multiplies the scene (#edf5-post-combine-formula): set system +0x6C (lerp) to 0 and write the tone through 5F05C0, or set +0x70 (power) to 0 for a fixed tone of 1. (6) depth of field: none in the game; a new compute pass between the scene and the combine (1164AB0), fed by the AO's linear depth (#edf5-post-chain-shaders).

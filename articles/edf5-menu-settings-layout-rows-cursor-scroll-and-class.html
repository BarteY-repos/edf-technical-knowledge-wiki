EDF5 settings menus: SGO class factories, row types and focus scrolling

EDF 5Game technical referencesNative user interface
Technical reference · Source-scoped static analysis with contributor runtime marked; no new R129 game test

The original EDF5 HQ menu uses subclasses of ui::HUiLayout. A screen's SGO declares xgs_ui_object_class, identifies layout elements and connects named callbacks to functions registered by that native class. This separates visual layout from the screen's application-specific settings logic.

Game Settings structure

HUiHQGameSetting constructs its rows from a fixed set of setting IDs 0–11. Dedicated switch functions interpret each ID as a name, range, current stored value, write destination or display label. Unknown IDs do not automatically become new supported settings: every relevant switch has an explicit case set.

The normal constructor creates 11 visible setting rows, with a 12th row in the observed second-player/gamepad-specific variants. The class stores the player index separately, and some buttons are hidden depending on player/activation context. Registered callbacks include initialization, key-configuration selection, chat-shortcut customization and opening the manual.

Visible rows versus full list capacity

The settings-screen CursorArea has 631×630 pixels and each row is 45 pixels tall, so 14 rows fit in the viewport. This is not a maximum count enforced by the native setting-ID logic. A layout flag 0x800 keeps focused child entries in view by adjusting the parent's scroll position, even when the scrollbar is not drawn; other flags control horizontal/vertical cursor behavior.

This also explains the relationship to the weapon-selection UI: EDF5 and EDF6 share the same 201-pixel-high five-row list geometry for equipment screens. EDF5's original SGO uses the misspelled Scrool in some scrollbar element names, so those resource identifiers should be quoted literally if comparing the files.

Boundaries

The source does not demonstrate that adding another arbitrary row to the SGO automatically installs its save/read/write logic, nor that the two Game Settings columns scroll together for rows beyond their native set. That behavior remains unverified rather than silently inferred.

EDF 5 — Ui Menus (community source notes)

EDF 5Community Knowledge HubNative UI & Input
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Facts

EDF5 menu screens are ui::HUiLayout subclasses created from layout files

Evidence: static · Build: steam-5d11de53 · Fact ID: hui-layout-framework

EDF5 menu screens are ui::HUiLayout subclasses created from layout files. The .sgo names the C++ class (xgs_ui_object_class) and the callback names its buttons use; the class registers handlers for those names; the HQ main menu opens its submenus from paths stored in its layout data.

Basis: disassembly: HUiLayout constructor 4DB8A0, register-callback 4E9610, element clone 4DF280, find-by-name 4D8790/4D86D0; layout strings of lyt_HUiHQGameSetting.sgo and lyt_HUiHQMain.sgo read from Root.cpk in place; the HUiHQMain handler 526C50 passes the callback arguments to 4E2780 once per local player, and no HUiHQMain code names the Game Settings path; not run in game

Addresses (build-specific RVAs unless indicated): 4DB8A0, 4E9610, 4DF280, 4D8790, 526C50, 4E2780

Attribution: novae (ajane) · 2026-10-14

Shared game-settings screen across menu contexts

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-three-callers

The HQ menu, the in-mission pause menu and the online lobby all create the same HUiHQGameSetting screen, so a hook on its row functions applies in all three places: the pause menu (HUiPause callback cbCallOption) creates app:/ui/lyt_HUiHQGameSetting.sgo at 587150 with an InitParam whose byte +E8 is 1; the lobby room does so at 5634A0; the HQ main menu opens it from its layout data through 526C50.

Basis: disassembly; not run in game

Addresses (build-specific RVAs unless indicated): 587150, 5634A0, 526C50

Each Game Settings row is an Item with an id 0..11

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-rows

Each Game Settings row is an Item with an id 0..11; five switch functions on that id give its name (5183F0), range (518770), stored value (read 518800, write 518B20) and value text (5189D0). The constructor 516110 creates 11 rows (12 for player 2, or in gamepad mode: byte [114126F], set by 546250 from the title screen's Sys_UseGamepad/Sys_UseKeyboard choice); ids above 11 fall through every switch as no-ops. Every call site of the five functions: only 516110, 5172A0 (update) and 518170 (left/right).

Basis: dumpbin disassembly of the constructor, the five functions and their jump tables; not run in game

Addresses (build-specific RVAs unless indicated): 516110, 5167D8, 5183F0, 518770, 518800, 5189D0, 518B20, 518170

Attribution: novae (ajane) · 2026-10-14

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-item

Settings screen cursor region dimensions

Evidence: static · Build: steam-5d11de53 · Fact ID: settings-row-capacity

Every settings screen layout (Game, KeyConfig, System, Display, Language) puts its rows in a 631x630 px CursorArea with 45 px rows, so a list holds at most 14 rows (Game Settings uses 11, System Settings 3).

Basis: decoded lyt_HUiHQGameSetting.sgo and the other HQ settings layouts (CursorArea = Layout at (-438, 138), size 631x630, flags 1, 2048, 256, 32768; Cusror01 = Button 442x45; ButtonArea at y 749); not run in game (the project's tests T1, 13 rows, and T2, 16 rows, check it)

Attribution: novae (ajane) · 2026-10-14

Scrolling container flags and focus behavior

Evidence: static · Build: steam-5d11de53 · Fact ID: settings-scroll-by-focus

Menu layout flag 800h makes a container scroll to keep its focused child in view, flags 80h/100h attach horizontal/vertical cursor behavior, and flag 8000h only suppresses the scroll bar. The settings lists (CursorArea flags 1, 800h, 100h, 8000h) therefore scroll by focus without a scroll bar; the 14-row capacity (#settings-row-capacity) is what fits in view, not a limit. Game Settings uses two containers (CursorArea names, CursorArea2 values); whether both scroll in step past 14 rows is unverified (the project's tests T1/T2). novae (ajane) reports that EDF6's equivalent lists scroll and that EDF5's Manual topics scroll.

Basis: disassembly: 4E01AF (shr ecx,0Bh / and cl,1) stores bit 11 of the OR'ed layout flags in ui::Layout::InitParam+D0 (built at rbp+1D0h, vtable ECBA28); 4AADEA copies it to the element's +260h; 4AB180 runs only when +260h is set and moves the vertical (+C0h) and horizontal (+B0h) scroll positions, clamped 0..1, so the focused child fits the viewport shrunk by scroll_mergin (+1C0h..+1CCh, read at 4E1107); flags 80h/100h create ui::Behavior_Horizon (4E7190) / ui::Behavior_Vertical (4E7210) at 4E0391/4E04E1; 8000h skips the scroll_bar_info lookup at 4E0396 and 4E04E6. Layouts decoded from Root.cpk: lyt_manual LeftButtonsBase [256, 2048] with scroll_bar_info; lyt_HUiHQWeaponSelect WeaponSelectArea [2048, 32768] with scroll_mergin [200, 0, 200, 0] and stencil 1, WeaponColumns [256, 2048, 4] with scroll_bar_info. The earlier reading of 4F2D19 (in 4F2CD0) was wrong: that code tests another object's flags. Not run in game

Addresses (build-specific RVAs unless indicated): 4E01AF, 4AADEA, 4AB180, 4E7190, 4E7210, 4E0396, 4E04E6

UI singleton, input layers and per-frame screen pass

SystemCore singleton offset and four screen/input queues

Static RTTI/constructor read. EDF5 4CA550 allocates the UI System object, initializes xgs::ui::SystemCore at 61D840 (vtable EE0A50), and stores the object's +0x88 secondary subobject in [125AB70], so its core begins at [125AB70]−0x88. The core contains pending insert list +0x18, live screen list +0x28, operations list +0x38 and input list +0x48, each head plus count, and a critical section at +0x60 absent from the compared EDF6 core. Earlier attempts to locate the EDF5 frame pass by the EDF6 code-byte signatures gave no match; the more specific EDF5 pass 61DC70 below resolves that research gap. Do not interpret the older negative AOB search as proof no frame pass exists.

Input group masks, layer modes and ui_type table

Static. EDF5 uses 0x14-byte input layers with group, channel mask, rank, active/registered bytes and mode. Controller system [125AB28] holds the sorted layer list at +0x38 (count +0x40, lock +0x48); 60A910 inserts by group after same-ranked peers, 628FA0 unregisters, and 60AAE0 arbitrates top-down with the same four mode semantics found in EDF6. Screen group setter 620430 writes screen +0x30 and reinserts its layer at +0x1C. Layout ui_type mapping at 4A1710 is 1→5, 2→3, 3→4, 4→2, 5→6, 6→7, 7→2, 8→8: unlike EDF6, types 5/6 swap groups. EDF5 chat (type 5) maps to group 6. Player layer at +0x248 registers group 0, mask 1<<pad (all channels for −1) and mode 0.

UI frame 61DC70: insert, sort, cover and pre-update

Static native callchain. UI pass 61DC70(core,input,dt) is called once per frame from 3D7D30 at 3D7FCD with core [125AB70]−0x88 and input [125AB38]+0x5428 (virtual pad identity inferred). It moves pending screen inserts +0x18 to live list +0x28 under the core lock and clears state bit 0x20; executes queued operations +0x38; runs input arbitration 60AAE0, sorts via 61ED50, and performs the channel-cover pass setting state bit 8 beneath a screen with bit 4 unless bit 0x10 exempts it. It then invokes every screen's slot 0 pre-update with context {input,0,dt} and unlinks screens with state bit 1.

UI frame: input callbacks, update and draw queue

Static continuation. Core input objects at +0x48 are matched to screens (screen virtual slot 6, input virtual slot 0 and 61D750) and receive input slot 2. Each screen then receives virtual slot 1 update with a context input pointer only when its layer active byte screen+0x28 is set; input objects receive slot 3. Screens not destroyed/hidden by state bits 0x41 are queued for draw through 620290. This confirms EDF5 screen fields +0x18 state, +0x1C layer, +0x28 active, +0x30 group and +0x34 channel, while still requiring a per-game code path instead of copying EDF6 bytes.

EDF5 HQ mission-select row states and presentation

HUiHQMissionSelect class, layout and buttons

Static. ui::HUiHQMissionSelect (vtable ED2FD0, constructor 527690, OnUpdate slot 1 528CA0) uses app:/UI/lyt_HUiHQMissionSelect.sgo. InitParam local-player field +0x28 is retained at UI object +0x7C4; init byte +0xE8 can disable row buttons via +0x7C1 and button +0x2AA. Each row clones ButtonMission; layout also has TextureWindow, DescText, MedalLine, RotationMark and guide keys. Selecting a closed row runs 529970 and MissionSelectNotOpen sound. Difficulty selection is separate HUiHQDifficultySelect (vtable ECF7C0), not another state of the same row widget.

Row list length and cleared/open/closed transitions

Static constructor algorithm. Row state vector at +0x788 stores integers: 0 cleared, 1 open, 2 shown but closed; other cases are handled conservatively. The initial row count is highest mission row cleared by any class/difficulty plus one, limited by the mission list. First row begins open; subsequent rows begin hidden/late and become 0 if any clear bit among bits 0–4 for any class is present. The next uncleared row after a cleared one becomes 1, rows after an open/closed one 2. If all listed rows are cleared and more exist, one more row is added; current mission row [save+0x48] is included and can be promoted from closed to open. This is a specific EDF5 availability rule, not the EDF6 timeline/remake mission logic.

Mission thumbnail, briefing and row label data

Static. 52B4B0 fills vector +0x808 with 0x40-byte entries per mission-list row [save+0x178], including thumbnail name +0 (helper 91270 appends .dds and replaces slash with underscore; exact row field unread) and briefing +0x20 from the text list's second column [save+0x198]. Class is read from [save+player×0x3E60+0x6D4C]. Row label function 528A10 formats state 0/1 via MissionSelect_Format, substituting %NUM% (row+1) and %TITLE% (text-list first column); state 2 uses MissionSelect_NotOpenMissionTitle. There is no EDF6-style ??? variant in this path.

Description and thumbnail switch by row state

Static. Cursor row lives at +0x7C8; 528A80 formats its description into +0x7D0. For states 0/1 it shows the briefing, replacing %dq% with quotation mark; for state 2 it uses MissionSelect_NotOpenMissionDesc, otherwise blank. Thumbnail code 528770 selects the stored art for state 0/1 (falling back to layout unlocked_mission_thumb if missing), or default art for state 2. 52A470 creates a class row of medals and 52B870 checks per-difficulty clear bytes to display ClearMedal marks. This is a UI display contract, not a new mission-clear gameplay test.

Mission-select state and panel open questions

Source: unverified. Object byte +0x7C0 was 1 in the examined build; when 0 it suppresses bits for rows beyond the first two under some modes and causes RotationMark. The author suspected an old console download/PlayGo state from PlayGoDownload_MissionSelect but did not establish it. Which row input 91270 uses, difficulty medal artwork, online room mission panel and DescTextArea line capacity were also not determined. Do not treat those guesses as established field names.

Stock layout census, pause and Game Settings text

86 EDF5 SGO layouts and cross-game class differences

Static Root.cpk inventory. EDF5 contains 86 ui/lyt_*.sgo layouts, covering title, mode/player-count/slot selection, HQ main/mission/difficulty/soldier/weapon/history, color and armor-limit screens, five settings screens, pause/background, mission results/failure, loading, lobby/room, chat and mouse pointer. Many class names and ui_type entries match EDF6, but EDF6 adds lyt_HudDamage, three alerts, story text, opening, Steam Deck text box and sign-in screen. EDF5's lyt_bg/lyt_titlebg remain plain HUiLayout while EDF6 uses specialized HUiBG/HUiTitleBG. A familiar SGO filename or class name is not proof of identical native layout offsets.

Pause button groups and System Settings differences

Static SGO read. ui/lyt_PauseMenu.sgo has EDF6-like offline, on_host, on_member button groups, corresponding Return/Retry/Exit/Option/Return-to-lobby callbacks and render mode 2. EDF5 spells the focus field pause_forcus_start (HQ main: forcus_start), and its description panel is at (510,794), compared with EDF6's (510,752). EDF5 System Settings ButtonArea contains ButtonDisplaySetting and ButtonLangaugeSetting (original spelling), whereas EDF6 replaces the latter with an Epic sign-in button. Option callback cbCallOption opens Game Settings. These are asset differences, not proof of identical online pause handling.

Twelve Game Settings row names and no HUD switch

Static name switch 5183F0. Row IDs 0..11 map respectively to Option_SE, Option_BGM, Option_Voice, Option_PanSpeakerMode, Option_ShakeScreen, OptionPlayer_RotateSpeed, OptionPlayer_RotateLerp, OptionPlayer_ViewUD, OptionPlayer_ViewLR, OptionPlayer_Vibration, OptionPlayer_CameraEffect, OptionPlayer_DisplayIdTag. None of these is a HUD-visibility toggle; a plugin seeking to hide HUD cannot simply reuse a stock Game Settings row for that purpose. EDF6's larger 23-row table and ID numbering must not be transposed onto EDF5.

EDF5 weapon-select structure, columns and input

HUiHQWeaponSelect class, callbacks and focus refresh

Static. ui::HUiHQWeaponSelect (vtable ED3AE8, constructor 533EF0, size 0x2544) has per-frame slot 1 5379F0 and slot 2 538110. It registers PressButton to 538220, CancelCallback to 537560, and WeaponSel_CellBase focus to 536F60. Focus refreshes weapon name, level, description and statistic lines. Control help key is Sys_Control_Description_WeaponSelect. Callback registrations do not establish the unevaluated equip/save writes.

One column per class weapon category

Static. Constructor loads class category set via 91710, stores number of categories at screen+0xE4D8, builds 0x20-byte per-column records at +0xE4F0 and longest column count at +0xE4E0; category IDs are also stored at +0xE540/+0xE548. It instantiates WeaponSel_IndexBase, level/quality indices, WeaponColumns, WeaponSel_CellBase, level/quality cells and new/upgrade labels. Category builder is shared with drop-item candidate selection; class/category identity should not be inferred from display position alone.

Five visible rows, forty-pixel cells and cursor dimensions

Static. Flag screen+0xE57C becomes one when the longest column has six or more entries, a code-level “more than five visible rows” threshold. +0xE5C8 stores cell count times 40 px; +0xE5D0 is set to 1000.0 with unread use. Selection cursor is 355×40 px (536B50); child cell width 250 px (5352D4/53585D). These corroborate the SGO geometry without proving pixel-perfect scaling in all resolutions.

All category columns share one vertical ScrollInfo object

Static. 4A8180(longest-column, 1, 3000.0) creates a shared scroll controller (535AF3). Constructor loop 535B20..535BC7 passes its shared pointer to every other column through 512D70(column, 1, &shared_ptr) rather than copying coordinate fields. This is EDF6-like behavior through a distinct setup route; no new controller-input test.

Four-pixel drag threshold and 25/5 scroll scales

Static. Drag handler 539D90 begins panning after mouse motion exceeds 4 px from press (53A065..53A0A3). If focused list exceeds five rows, vertical displacement changes that column's scroll by pixel delta / 25 (539ED2); horizontal displacement changes WeaponSelectArea scroll by delta / 5 (539FA3). Both use 53A330; source matches EDF6's mathematical constants without asserting identical input devices.

Description panel scroll clamps to its text extent

Static. The WeaponDescArea scroll value at [[screen+0xE5E8]+0xC0] advances by input times 300.0 / [screen+0xE5E4] each update and clamps to 0..[screen+0xE5DC] (537D75..537E17). Source did not identify whether buttons or the right stick provide this input.

Weapon cell colors, clip tests and unknown handlers

Cell flag bits choose red, gray and white text states

Static. In 0x80-byte cells, flags +0x4C drive 5376C0: bit 2 uses dark red (0.4, 0.2, 0.2, 1), else bit 1 gray (0.5), else white. Weapon name at cell+4 and third text at +0x24 use base color; level text at +0x14 turns red under bit 0. Bit 0 comes from online weapon-cap predicate, so EDF5 has no equivalent offline level cap coloring. Bit 2's upstream setter remains unread; EDF6's content-ownership interpretation is not established for EDF5.

Generic HUi rectangular hit test handles two coordinate conventions

Static, untested. EDF5 clip test 59C7F0 treats rect x/y as top-left when r9d=0, with vertical center adjusted by +5 and height reduced by 18; nonzero r9d interprets a centered box. A special-size rectangle is replaced by a fixed box using constants near EE6774/EE679C. This matches a decoded EDF6 control path but has not been exercised with EDF5 click coordinates.

Equip commit, cancel and navigation remain unread

Unverified. PressButton 538220's save-write path, cancel 537560, horizontal focus navigation, New!/Up flash handling, slot 2 538110, rect/scroll helper 539680 and column x-layout calculations are not decoded. EDF6's working-copy equip commit is a research lead, not evidence that EDF5 writes the same save area on the same event.

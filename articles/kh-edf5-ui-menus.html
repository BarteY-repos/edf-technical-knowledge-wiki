EDF 5 — Ui Menus (community source notes)

EDF 5Community Knowledge HubNative UI & Input
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Facts

EDF5 menu screens are ui::HUiLayout subclasses created from layout files

Evidence: static · Build: steam-5d11de53 · Fact ID: hui-layout-framework

EDF5 menu screens are ui::HUiLayout subclasses created from layout files. The .sgo names the C++ class (xgs_ui_object_class) and the callback names its buttons use; the class registers handlers for those names; the HQ main menu opens its submenus from paths stored in its layout data.

Basis: disassembly: HUiLayout constructor 4DB8A0, register-callback 4E9610, element clone 4DF280, find-by-name 4D8790/4D86D0; layout strings of lyt_HUiHQGameSetting.sgo and lyt_HUiHQMain.sgo read from Root.cpk in place; the HUiHQMain handler 526C50 passes the callback arguments to 4E2780 once per local player, and no HUiHQMain code names the Game Settings path; not run in game

Addresses (build-specific RVAs unless indicated): 4DB8A0, 4E9610, 4DF280, 4D8790, 526C50, 4E2780

Attribution: novae (ajane) · 2026-10-14

The HQ menu, the in-mission pause menu and the online lobby all create the same HUiHQGameSetting screen, so a…

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-three-callers

The HQ menu, the in-mission pause menu and the online lobby all create the same HUiHQGameSetting screen, so a hook on its row functions applies in all three places: the pause menu (HUiPause callback cbCallOption) creates app:/ui/lyt_HUiHQGameSetting.sgo at 587150 with an InitParam whose byte +E8 is 1; the lobby room does so at 5634A0; the HQ main menu opens it from its layout data through 526C50.

Basis: disassembly; not run in game

Addresses (build-specific RVAs unless indicated): 587150, 5634A0, 526C50

Each Game Settings row is an Item with an id 0..11

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-rows

Each Game Settings row is an Item with an id 0..11; five switch functions on that id give its name (5183F0), range (518770), stored value (read 518800, write 518B20) and value text (5189D0). The constructor 516110 creates 11 rows (12 for player 2, or in gamepad mode: byte [114126F], set by 546250 from the title screen's Sys_UseGamepad/Sys_UseKeyboard choice); ids above 11 fall through every switch as no-ops. Every call site of the five functions: only 516110, 5172A0 (update) and 518170 (left/right).

Basis: dumpbin disassembly of the constructor, the five functions and their jump tables; not run in game

Addresses (build-specific RVAs unless indicated): 516110, 5167D8, 5183F0, 518770, 518800, 5189D0, 518B20, 518170

Attribution: novae (ajane) · 2026-10-14

Evidence: static · Build: steam-5d11de53 · Fact ID: gamesetting-item

Item is 0x50 bytes, zero-filled by make_shared 51A770: +0 id, +8 name (std::wstring), +28 value, +2C last drawn value, +30 min, +34 max, +3C/+40/+44/+48/+4C element indices (name, value, left arrow, right arrow, cursor). Left/right 518170: value +-1, clamped with unsigned compares, no wrap, then write and redraw. Ids: 0 SE, 1 BGM, 2 Voice, 3 speaker mode, 4 screen shake, 5 rotate speed, 6 rotate lerp, 7 look up/down, 8 look left/right, 9 vibration (skipped for player 1 unless [114126F]), 10 camera effect, 11 display Steam IDs. The layout holds one row template (Cusror01, CusroButon, ItemName, ItemValue, ArrowLeft, ArrowRight) that 4DF280 clones count-1 times.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 51A770, 518170, 4DF280

Every settings screen layout (Game, KeyConfig, System, Display, Language) puts its rows in a 631x630 px Curso…

Evidence: static · Build: steam-5d11de53 · Fact ID: settings-row-capacity

Every settings screen layout (Game, KeyConfig, System, Display, Language) puts its rows in a 631x630 px CursorArea with 45 px rows, so a list holds at most 14 rows (Game Settings uses 11, System Settings 3).

Basis: decoded lyt_HUiHQGameSetting.sgo and the other HQ settings layouts (CursorArea = Layout at (-438, 138), size 631x630, flags 1, 2048, 256, 32768; Cusror01 = Button 442x45; ButtonArea at y 749); not run in game (the project's tests T1, 13 rows, and T2, 16 rows, check it)

Attribution: novae (ajane) · 2026-10-14

Menu layout flag 800h makes a container scroll to keep its focused child in view, flags 80h/100h attach horiz…

Evidence: static · Build: steam-5d11de53 · Fact ID: settings-scroll-by-focus

Menu layout flag 800h makes a container scroll to keep its focused child in view, flags 80h/100h attach horizontal/vertical cursor behavior, and flag 8000h only suppresses the scroll bar. The settings lists (CursorArea flags 1, 800h, 100h, 8000h) therefore scroll by focus without a scroll bar; the 14-row capacity (#settings-row-capacity) is what fits in view, not a limit. Game Settings uses two containers (CursorArea names, CursorArea2 values); whether both scroll in step past 14 rows is unverified (the project's tests T1/T2). novae (ajane) reports that EDF6's equivalent lists scroll and that EDF5's Manual topics scroll.

Basis: disassembly: 4E01AF (shr ecx,0Bh / and cl,1) stores bit 11 of the OR'ed layout flags in ui::Layout::InitParam+D0 (built at rbp+1D0h, vtable ECBA28); 4AADEA copies it to the element's +260h; 4AB180 runs only when +260h is set and moves the vertical (+C0h) and horizontal (+B0h) scroll positions, clamped 0..1, so the focused child fits the viewport shrunk by scroll_mergin (+1C0h..+1CCh, read at 4E1107); flags 80h/100h create ui::Behavior_Horizon (4E7190) / ui::Behavior_Vertical (4E7210) at 4E0391/4E04E1; 8000h skips the scroll_bar_info lookup at 4E0396 and 4E04E6. Layouts decoded from Root.cpk: lyt_manual LeftButtonsBase [256, 2048] with scroll_bar_info; lyt_HUiHQWeaponSelect WeaponSelectArea [2048, 32768] with scroll_mergin [200, 0, 200, 0] and stencil 1, WeaponColumns [256, 2048, 4] with scroll_bar_info. The earlier reading of 4F2D19 (in 4F2CD0) was wrong: that code tests another object's flags. Not run in game

Addresses (build-specific RVAs unless indicated): 4E01AF, 4AADEA, 4AB180, 4E7190, 4E7210, 4E0396, 4E04E6

EDF5's ui/lyt_huihqweaponselect.sgo has the same weapon-list geometry as EDF6's (edf6/ui-weapon-select.mdui-w…

Evidence: static · Build: steam-5d11de53 · Fact ID: weaponselect-layout-same

EDF5's ui/lyt_huihqweaponselect.sgo has the same weapon-list geometry as EDF6's (edf6/ui-weapon-select.md#ui-weaponselect-layout): WeaponSelectArea (18, 67) 1162 x 201 with scroll_mergin [200, 0, 200, 0] and stencil 1; WeaponColumns 355 x 201 [256, 2048, 4] with scroll_mergin [0, 22, 0, 22]; WeaponSel_CellBase 355 x 40, font 24; WeaponNew / WeaponUp 45 x 15 at (204, 1); WindowUpper (191, 147) 1187 x 302; WindowLower (256, 468) 1130 x 498. So 5 rows (201 / 40) is a layout value in both games. The only difference seen: EDF5 spells its scroll bar names LeftScroolBarBase / UnderScroolBarBase ("Scrool"). The class anchors (vtable ED3AE8, constructor 533EF0, update 5379F0) are in edf6/ui-weapon-select.md#ui-weaponselect-class.

Basis: layout variables decoded from Root.cpk in place and compared with EDF6's; not tested in game

Addresses (build-specific RVAs unless indicated): ED3AE8, 533EF0, 5379F0

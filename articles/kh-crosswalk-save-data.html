Save files and the GameDataMgr blocks (key: GameDataMgr)

  • edf41: My Games\EDF4.1\SAVE_DATA\, saveslot%02d; five blocks of GameDataMgr [CC84A0] back to back (SYSTEM.CFG, COMMON.CFG, DEFP_M<nn>.MST, MAIN.GST, TROPHY.DAT) | ref: edf41/globals.md#edf41-save-files, edf41/globals.md#edf41-save-file-names, edf41/globals.md#edf41-save-blocks, edf41/globals.md#edf41-save-blocks-fields | evidence: static
  • edf5: My Games\EDF5\SAVE_DATA\, the same five files (both games also keep a SYSTEMWIN32.CFG); blocks of GameDataMgr [125AB30] back to back | ref: edf5/globals.md#save-cfg-files, edf5/globals.md#edf5-save-blocks, edf5/globals.md#edf5-save-file-names, edf5/globals.md#save-timing | evidence: static (file sizes verified from a game log)
  • edf6: %LOCALAPPDATA%\EarthDefenceForce6\SAVE_DATA\<SteamID64>\saveslotNN\; blocks of the GameDataMgr [20B2890] (the mode file is named by ModeList member 5 instead of a format string) | ref: edf6/mission-packs.md#mode-save-layout, edf6/mission-packs.md#mode-save-keys-format, edf6/battle-record.md#trophy-dat-layout | evidence: static
  • Differences noticed: the same design in all three games: one fixed-size block per file, the big blocks passed to the save job as raw memory (only the trophy store is packed first), config.sgo's ModeList item 4 names MAIN.GST, and PackageName "DEFP" with the mode number names the mode file in 4.1 and EDF5. Block sizes grow by game (MAIN.GST 0x4060 in 4.1, 0xDCE8 in EDF5 and EDF6; the mode file 0x1710, 0x16C0, 0x16C4). The folder moved from Documents' My Games (4.1, EDF5; the base folder not read) to %LOCALAPPDATA% with a Steam id level (EDF6).
  • Confidence in the mapping: high (names, block structure); offsets are per game and never carry over.
  • Added: 2026-11-13 src: novae (ajane), KH chat 159 (00u save data)

Save jobs and encryption (key: JobSaveDataSave, CryptoPP Rijndael, Weak1::MD5)

  • EDF4.1: JobSaveDataSave and JobSaveDataLoad use Crypto++ AES-CTR; MD5 derives a fixed key from edf4.1_save and edf4.1. Its MDB0 header is 0x18 bytes, with ordinary CRC-32 and the owner's SteamID64 (low 32 bits at +0x10). Source: edf41/globals.md#edf41-save-key-fixed and #edf41-save-header, static.
  • EDF5: analogous job classes use AES and an MD5-derived, file-dependent key involving edf5, the filename and .sav/.stm identifiers. The MDB0 header is 0x20 bytes, CRC32C rather than CRC-32, with owner's SteamID64 at +0x18. Source: edf5/globals.md#edf5-save-key-derivation and #edf5-save-header, static.
  • EDF6: JobSaveData uses AES-256-CTR and a 0x14-byte MDB0 header with CRC32C, but no owner's SteamID64 in that header. Source: edf6/file-formats.md#save-file-encryption and #edf6-save-no-owner-id, static.
  • Compatibility boundary: the three headers differ in size, checksum and owner identity, while key derivation differs by game. These are source-reported static findings, not a tested one-format conversion recipe. FevGrave's EDFSaveEditor is cited as cross-game prior art, not a license to assume interchangeability.

GameStatus and achievement file offsets

The added cross-game census separates file offsets from in-memory GameStatus offsets. The offsets below are per game and include that game's save header; copying offsets or weapon records across games without conversion corrupts their meaning.

GameMAIN.GST layout landmarks (file offsets)TROPHY.DAT
EDF4.1Loadout 0x44 (4 per class), armor boxes 0xE4, colors 0x10C, owned-weapon dwords 0x2078; second player +0x101C.70 variables from 0xE0.
EDF5EDF6-compatible field arrangement in the referenced census, shifted by the 0xC header-size difference; separate source offsets remain authoritative.71 variables from 0xE8.
EDF6Loadout 0x44 (6 per class), armor pickups 0x134, colors 0x15C, 12-byte weapon records 0x7CFC; second player +0x3E60.91 variables from 0xDC.

TROPHY.DAT stores a 0xC8-byte event-state region followed by the per-title Achievement.sgo variables in name order. The equivalent design does not imply identical variable offsets. Source: the Knowledge Hub crosswalk/save-data.md, edf41/globals.md#edf41-save-file-offsets, edf5/globals.md#edf5-save-file-offsets, edf6/file-formats.md#edf6-save-file-offsets; static and source-scoped.

EDF 6 — Mission Spawns (community source notes)

EDF 6Community Knowledge HubMissions
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Script shape (E2DtoMissionScript output): Main() preloads, then calls Main_usercode()

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-script-shape

Script shape (E2DtoMissionScript output): Main() preloads, then calls Main_usercode(); each editor event N is __000N_game_event() plus __000N_game_event_usercode(), whose body sits in if (IsBoolState(N, m_is_pass, ...) == false) { ... }. Events are armed by blocks internal_CreateEvent("<function>", "<name>", ..., EVENT_TYPE_SYNC or _ASYNC, EVENT_CHECK_AND, n) followed by trigger conditions e.Factor_* (Wait, WaitNC, TeamObjectCount, AllEnemyDestroy, DifficultyOverEqu, DifficultyLessEqu, IsOnlineMode, ...). Some handlers exit unless their run counter equals 1 (if (m_counter != 1) return;), as EDF5's (../edf5/mission-vm.md#bvm-handler-counter-guard). Difficulty tests are GetDifficulty() against MISSION_DIFFICULTY_* names (500 calls in 176 files).

Basis: M022_5 read in full; the census's call and keyword counts

Attribution: KH chat 94 · 2026-11-11

Spawns in the 549 .AC scripts are engine natives called with literal app:/object/name.sgo strings, or methods…

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-spawn-calls-2

Spawns in the 549 .AC scripts are engine natives called with literal app:/object/<name>.sgo strings, or methods on an object handle (#ac-spawn-methods). AsCommon.h, the one header every script includes, holds mob and map-material helpers and the story characters' spawn wrappers (#ac-ascommon-friend-wrappers). Calls (in files): CreateEnemy 2344 (295), CreateNeutral 2048 (210), CreateFriend 1298 (194), SetEnemyGenerator 1255 (136; 1158 of them the method form), CreateEnemyGroup_Area 1208 (205), CreateFriendSquad 847 (282), CreateEnemy2 799 (91), SetInstantEnemyGenerator 641 (93; 516 methods), CreateEnemyGroup 629 (119), CreateEnemyGroupUG 399 (37), CreateFlyingEnemyGroup_Area 393 (108), CreateEnemySquad 185 (49), and about 30 rarer ones.

Basis: census of every .AC in the archives, comments stripped (scratch File_Storage/Logs/catalog/ac6_census.py; functions against methods by ac6_natives.py, output ac6_natives.txt)

A Time Ship drops its anchor with .EDF6_TimeShip_DropAnchor(point) or .EDF6_TimeShip_DropAnchor2() (the nativ…

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-timeship-anchor-drop

A Time Ship drops its anchor with .EDF6_TimeShip_DropAnchor(<point>) or .EDF6_TimeShip_DropAnchor2() (the natives 1CB300 / 1CB280, enemies.md#timeship-anchor-capsules); the anchor is the ship SGO's own EDF6_TimeShip/Anchor object: e611_timeship -> e612_anchor, e611_timeship_light -> e612_anchor_light, e611_timeship_full_light -> e612_anchor_full_light (whose resource list preloads e612_anchor_light instead). _tools/ac_eval.py records each drop as a spawn of that anchor with the ship's level argument, health factor and repeat mark (KH chat 133).

Basis: the three E611 SGOs read (scratch File_Storage/Logs/catalog/anchor6.py); fn.py read of 3ED3C0; the dumped scripts grepped

Addresses (build-specific RVAs unless indicated): 1CB300, 1CB280

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-timeship-anchor-level

Script health factors in the ACs: SetMissionLevel(x) 61 calls in 32 scripts, set inside difficulty branches (…

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-script-health-factors

Script health factors in the ACs: SetMissionLevel(x) 61 calls in 32 scripts, set inside difficulty branches (M001: x 0.8 when GetDifficulty() <= MISSION_DIFFICULTY_HARD, commented as added 2024-05-07; M029_2: x 0.9 on Hardest and up; M049: x 0.9 on Normal and below); it sets enemy team 1's factor, which AS CreateEnemy multiplies into its level (missions.md#difficulty-mission-level, damage-model.md#level-durability-natives). Per-object percents: .SetDurability(pct) 459 calls in 74 scripts (chained on a Create call or on a stored handle, often commented ％), SetObjectDurability(obj, x) 49 in 15, .SetDurabilityMin(pct) 51 in 17, SetObjectDurabilityMin(obj, x) 19 in 10.

Basis: ac6_natives.py counts, ac6_samples.py samples with context

The script method Object& SetDurability(float) (declaration 17987F0, registered at 1F0B5A in 1E31F0) is 1C2C3…

Evidence: static · Build: steam-678ccb46 · Fact ID: ac-setdurability-read

The script method Object& SetDurability(float) (declaration 17987F0, registered at 1F0B5A in 1E31F0) is 1C2C30: it resolves the object and sets max HP +0x2F4 x= pct / 100.0 (1765A68), +0x484 = max x +0x480 / durability +0x2EC, and HP +0x2F8 = min(HP x pct / 100, max): BVM native 3019's effect (damage-model.md#level-durability-natives), confirming the first part of #ac-durability-as-3019. ObjectGroup& SetDurability(float) (179A130), SetObjectDurability and the SetDurabilityMin pair are not traced.

Basis: string RVAs by scratch File_Storage/Logs/catalog/findstr6.py, fn.py --xref 17987F0, fn.py of 1C2C30; 1765A68 read as 100.0

Addresses (build-specific RVAs unless indicated): 17987F0, 1F0B5A, 1E31F0, 1C2C30, 1765A68, 179A130

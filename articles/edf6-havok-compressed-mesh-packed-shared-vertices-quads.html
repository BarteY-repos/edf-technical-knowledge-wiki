EDF6 hknpCompressedMeshShape: packed/shared vertices, triangles and quads

EDF 6Game technical referencesPhysics / geometry
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

A hknpCompressedMeshShapeData.meshTree contains one or more sections. Each section supplies packed-vertex and primitive index ranges, a shared-vertex reference range and a local coordinate codec. In the source corpus, two vertex encodings coexist:

Vertex kind Encoded width Axis allocation Reconstruction
Section packed vertex 32 bits X 11, Y 11, Z 10 offset_xyz + scale_xyz × integer_xyz
Mesh-wide shared vertex 64 bits X 21, Y 21, Z 22 domain.min + (domain.max-domain.min) × integer/(2^bits-1)

A primitive is a 4-byte four-index record referring first to the section's own packed vertices, otherwise through an indexed mesh-wide shared-vertex table. If the third and fourth values match, the record is a triangle. Otherwise it is a quad split into two triangles, (0,1,2) and (0,2,3). The first equals second sentinel is used in the separate convex-hull compressed-mesh family.

The source census identifies two nonmixed classes of compressed mesh in object/weapon files: 82 convex-only and 214 triangle-only (296 total). EDF6 maps contribute many more compressed-mesh sections in the separate map corpus. In triangle-kind sections the observed maxima are 127 primitives, 107 packed vertices and 198 shared-vertex references per section. Mesh-wide shared vertices are frequently reused across sections and support boundaries without duplicating their coordinates independently.

The source reports 174,419 quad records and 23,318 triangle records within the inspected triangle-kind corpus. Those are encoded primitive counts, not a count of distinct physical bodies or on-screen graphics triangles.

Source: edf6/havok-format.md, compressed-mesh-encoding, compressed-mesh-kinds, compressed-mesh-triangle-kind. This is serialized collision geometry, not the EDF6 visible FMB render model.

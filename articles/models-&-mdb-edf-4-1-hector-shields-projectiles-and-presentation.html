EDF 4.1 Hector and shield fidelity contracts

UniversalModels & MDBModelsEDF 4.1EDF 6
Source-backed research / case study · Mixed static/source closure; runtime gates remain

This area contains three different problems that must not be conflated: Hector projectile semantics, AlienTrailer/Shield Bearer collision, and Hector401's own physical shield.

Hector projectile custom parameters

The retained bridge now preserves the exact EDF4.1 RocketBullet01 custom-parameter arrays:

  • Hector301 Launcher: [0, 10, 0, 0];
  • Hector401 Cannon: [0, 40, 0, 0];
  • Hector401 Launcher: [0, 10, 0, 0].

The EDF6 Grandmother donor array [2, 120, 0, 0, 0.5] must not leak into these EDF4.1 weapons.

Level scale V11

An older builder comment called the EDF6 donor V11 mapping an assumption for source s = level / 10.

Binary RE closes that uncertainty:

  1. EDF6 computes/stores the difficulty-scaled raw level;
  2. the engine divides it by 10.0;
  3. the result is stored as game_object_level;
  4. the Berserker donor node used by the bridge is exactly that value.

Therefore V11 is semantically the EDF4.1 s = level / 10 scale. No gameplay patch is required for that mapping.

Projectile size/blast and salvo timing

The later EDF4.1 R13 functionality source line reports that the canonical EDF41.exe projectile speed, size and blast formulas have been implemented and audited in the converted Hector classes (70/70 substantive source/formula checks). Those source-aware expressions supersede the historical assumed launcher/cannon/plasma tuning; they do not prove the projectile size or impact visuals have passed a real EDF6 mission test. No new universal constants are inferred from the test count. Do not retune them by eye.

Source Hector salvo interval is:

max(4, 31 - floor(s))

R13's interval 30 is exact at s=1, but no proven exact floor/trunc primitive was identified in the target Calc surface. Do not replace the source formula with a continuous approximation merely to make it expressible.

AlienTrailer401 / Shield Bearer bridge

This is the separate EDF4.1 Shield Bearer family, not Hector401's arm shield.

R12 retains EDF4.1 object/gameplay semantics while using native EDF6 E513 shield collision SHKT:

  • S → e513_Barrier_S.shkt;
  • L → e513_Barrier_L.shkt;
  • LL → e513_Barrier_LL.shkt;
  • XL → e513_Barrier_XL.shkt.

Source and target shield geometry are equivalent within centimetre/sub-centimetre deltas, while EDF6's SHKT uses its current hknp collision representation.

No HP, blanket invulnerability, airstrike immunity or generic damage filter is invented by this bridge. M015 scripted-airstrike behavior still requires runtime qualification.

Hector401 physical shield

Historical state: an older compatibility version had only a visual graft. It lowered Hector401's shield to a Berserker gun-battery presentation node and discarded the source physical child. In that older build, a visible shield did not block projectiles as a real source shield.

Later source-state correction (November 15, 2026): the retained R13 functionality lineage now contains a hidden source-backed physical shield proxy for each shield arm. The proxy follows the reconstructed arm-world transform and is deliberately non-targetable and not an additional HP-bearing actor. This was introduced to restore the source's separate shield interception surface while retaining the EDF6-compatible visual graft. It does not reinstate the entire old source object hierarchy as a normal independent actor.

The EDF4.1 source HECTOR401_SHIELD.SGO references RAGDOLL_HECTOR401SHIELD_HAS_HKA.SHKT, which has separate gun_arms and gun_shield bodies and collision/filter semantics. EDF6's legacy object-SHKT capability provides supporting binary compatibility, but the source proxy's exact gameplay effect still has to be observed.

Status: R4/R5 reported 18/18 source implementation and 6/6 closure checks PASS offline; later R12 retains the physical proxy. Real EDF6 collision interception, arm tracking, lifetime cleanup and restart behavior remain RUNTIME PENDING. It is incorrect both to say the latest source has no physical shield and to claim the tester's shield issue is already runtime-fixed.

Presentation fixes already present

The R12 lineage already suppresses known donor-presentation leakage:

  • donor DamageBloodColor suppressed;
  • DeadBloodScale = 0;
  • DeadBloodColor suppressed;
  • DeadExplosionColor neutralized to white while keeping the mechanical explosion;
  • EDF4.1 death material block retained;
  • Particle3_k.dds used for charge presentation;
  • source MuzzleFlash01 used for muzzle flash.

The static presentation audit is 8/8 PASS, but runtime retest remains the final evidence gate.

Rule

Treat object visuals, projectile semantics, shield collision and damage policy as separate surfaces. A visually correct shield is not proof of a physical shield, and a valid target collision donor is not permission to invent EDF4.1 damage behavior.

Hector AI is separate from projectile and shield fidelity

The projectile and shield findings above do not restore the original Hector's range-aware dual-arm attack selection, stop/retreat timers, bone aiming or turning gait. For the exact examined actor-class semantics, read Hector AI, gait and arm aiming. The donor Berserker's gun target is not equivalent to updating the Hector's weapon-carrying arm bones and dependent muzzle matrices.

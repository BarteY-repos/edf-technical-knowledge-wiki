Menu script routines and a mission without menus (round 24)

Evidence: verified · Build: steam-678ccb46 · Fact ID: createcoroutine-menu-routines

12946F0 is the script function coRoutine createCoRoutine(const string &in) (registered at 129463E with the declaration string at 1AF3118; 1294B00 is the (string, any@) overload). MAINSCRIPT.AS runs its menu routines through it by declaration: string StartToTitle(), string HQMain(), string PlayMission_Offline(); the script also keeps a leftover string Debug_StartOffline() that skips the logos, title, Epic login and slot choice. A hook that swaps the declaration (StartToTitle to Debug_StartOffline, then the first HQMain to PlayMission_Offline with row and difficulty set) starts an offline mission with no menu at all.

Basis: registration and string re-read with fn.py here; the routine names and the swap from autopilot.cpp (its prologue signature checked by the plugin at load); novae (ajane)

Addresses (build-specific RVAs unless indicated): 12946F0, 129463E, 1AF3118, 1294B00

Attribution: EDF6Autopilot (hajisensai, edf6-all-forces, round 24), hub check, novae (ajane) · 2026-11-13

Evidence: verified · Build: steam-678ccb46 · Fact ID: gamedata-mission-row-difficulty

GameDataMgr [20B2890] holds the offline mission row at +0x48 (0-based: M001 is 1, RM015 is 13) and the difficulty at +0x4C (0-4); PlayMission_Offline plays what they name.

Basis: autopilot.cpp's kMissionRow, kDifficulty and its notes on the offline list; not traced in EDF.dll here; novae (ajane)

Addresses (build-specific RVAs unless indicated): 20B2890

Attribution: EDF6Autopilot (hajisensai, round 24), novae (ajane) · 2026-11-13

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-debug-start-offline-flow

In MAINSCRIPT.AS (mainscript/mainscript.as in Root.cpk, 56,786 bytes) Debug_StartOffline() (line 1865) runs InitializeAll(), Network_SetLocation(BOOT_COMPLETE), titleSaveDataLoad(true), WaitSearchUpdateAddon(), WaitSaveLoad(), SetMode(GetModeNo(GAME_OFFLINE_SCENARIO,0)), LoadSaveData_ModeSelect() (on failure a Sys_LoadFailed_ToTitle dialog and return "StartToTitle"), UnlockDownloadContents(), then return "HQMain", with no slot choice (the slot is the engine's current slot index; the normal flow sets it in SlotSelect(), line 746, through CreateSlotSelectUi2).

Basis: the script read from Root.cpk in place

Attribution: novae (ajane) · 2026-11-13

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-offline-mission-chain

PlayMission_Offline() (line 1087) ends with Result_Common(g_is_mission_clear) and return "HQMain" (line 1303), so after every offline mission the script creates HQMain again: a hook that swaps HQMain for PlayMission_Offline (#createcoroutine-menu-routines) can chain missions, each HQMain a fresh swap point. Other lines: StartToTitle() 442 (calls LoadSystemSaveData() then Title() 675; returns "HQMain" at 481 in one branch), HQMain() 894 (returns "PlayMission_Offline" at 968), LoadSaveData_ModeSelect() 21 (calls ModeSelectLoadSaveData()), ApplyModeNo(int) 1895.

Basis: the script read from Root.cpk in place; the chaining not run

Attribution: novae (ajane) · 2026-11-13

Evidence: verified · Build: steam-678ccb46 · Fact ID: edf6-debug-start-pad-mode

A start through the leftover Debug_StartOffline() leaves the game in gamepad mode: in the mission, keyboard movement and mouse look do nothing (Esc, arrows, WASD and Enter still work in menus; the key-config screen shows the pad bindings), even with no pad present. A start that keeps the title (StartToTitle() -> Title(), "Press Start") and a key press there gives keyboard and mouse, and [1FEEE1C] then reads 0. The cause is in the code: only the title's Press Start sets the input mode (system.md#edf6-input-mode-bytes); a debug start could write 0 there itself (untested).

Basis: novae (ajane); the byte during the debug start not read

Addresses (build-specific RVAs unless indicated): 1FEEE1C, 12946F0

Attribution: novae (ajane) · 2026-11-14

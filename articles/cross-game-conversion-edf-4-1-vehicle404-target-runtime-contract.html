Vehicle402 player launcher, Vehicle403 AI cannon, and remaining qualified Vehicle404 secondary weapons did not require such a material patch. The differing Vehicle402 Ammo_CustomParameter tail was classified as audio/presentation, not a gameplay ammunition change.

The candidate uses private, namespaced vehicle and weapon SGO resources for converted EDF4.1 missions. It does not globally overwrite EDF6 objects or copy legacy CarBase movement coefficients. Vehicle403/404 driver masks revert from target 15 to source 9 only in the private compatibility copies (9 = Ranger + Air Raider). DLC1 M416 is the strongest shared-vehicle runtime discriminator in the retained mission census.

Important: this is exact source-pair evidence and an offline-qualified compatibility candidate, not a runtime-positive mod. The later HF4 R9 candidate still lacked a real Windows/MSVC build, installed EDF6 gameplay, restart and multiplayer qualification. The R10 HF3 product baseline remains separate authority. The older “weapon comparison pending” statement in this article applies only to the earlier R1 object-level stage.

Evidence level: Exact raw EDF4.1/EDF6 AI-vehicle SGO corpus plus cross-generation R13 reconciliation. This is evidence, not a new product authority; R10 HF3 remains source/product authority.

Raw corpus result

The retained R1 corpus contains exact raw EDF4.1 and EDF6 AI vehicle SGOs, parser-normalized JSON and a hash-backed report for Vehicle402/403/404.

At object level the important result is conservative:

  • core durability contracts match;
  • camera contracts match;
  • sound contracts match;
  • mount contracts match;
  • EDF6 runtime schema differs substantially and should remain EDF6-native;
  • movement-coefficient differences are not promoted to patches without runtime evidence;
  • weapon parity required a separate asset-level comparison because weapon SGOs are separate resources; the later source-only R2 comparison above identifies material weapon deltas.

Proven capability divergence

For Vehicle403/404, the driver class mask differs:

  • EDF4.1: 9;
  • EDF6: 15.

This is the one object-level divergence in the R1 corpus explicitly classified as gameplay-capability material. Preserve the evidence-backed class-mask/driver compatibility patch where required; do not extrapolate every numeric difference into a source-value override.

Vehicle404 mission_setup delta

A notable main-cannon control tuple differs:

  • EDF4.1 Vehicle404: [0.2, 2.0];
  • EDF5/EDF6: [0.0, 2.0].

The adjacent [10, 0.01, 0.1] tuple remains unchanged.

Cross-generation context shows this is part of a broader runtime migration:

Vehicle EDF4.1 global tuple EDF5/EDF6 global tuple
Vehicle402 [1, 5, 0.02, 3, 0.04, 1] [1, 5, 0.02, 0.91, 0.18, 0.4]
Vehicle403 [0.15, 14, 0.015, 1.5, 0.02, 1.2] [0.15, 14, 0.015, 0.537, 0.02, 1.2]
Vehicle404 [0.05, 6, 0.025, 2, 0.025, 0.5] [0.05, 6, 0.025, 0.29, 0.15, 0.5]

The Vehicle404 main-cannon nested tuple likewise changes from [0.2,2] to [0,2] and remains [0,2] in both EDF5 and EDF6.

Runtime class migration

Vehicle404 also changes runtime class:

  • EDF4.1: VehicleTank404;
  • EDF5/EDF6: Vehicle404_Tank.

The private object layout grows substantially. That is consistent with a rewritten control schema, not a one-field typo.

Decision: keep EDF5/EDF6 [0,2] as target-runtime authority.

Source gameplay fidelity is enforced through narrower evidence-backed patches such as:

  • AI main-cannon damage/speed/life/reload;
  • player main-cannon damage/speed/life;
  • proven driver/class-mask compatibility.

Mission exposure

An earlier 142-script census found these friendly vehicle families frequently enough to require deliberate testing rather than assumption:

  • Vehicle402: about 8 mission records;
  • Vehicle403: about 13 mission records;
  • Vehicle404: about 4 mission records.

Runtime qualification should focus on role/voice/icon/loadout/AI, driver compatibility, scripted transitions and mission restart rather than pixel-identical tuning.

General conversion rule

A source number is not automatically portable when the owning runtime class and surrounding schema changed. Prefer target-runtime semantics where EDF5 and EDF6 agree, then patch only material source gameplay differences proven by direct evidence.

Bounded mission-script calls for friendly vehicles 402, 403 and 404

The earlier R1 source audit also preserved 25 vehicle-by-script records from its conversion-era mission corpus. The counted call IDs reflect static appearances in that corpus, not proven native in-game execution or the number of vehicles spawned. These scripts were drawn from the audited research/All Forces-derived collection and must not be mistaken for an independently verified, untouched retail EDF 4.1 script census.

This explains why copying old drive coefficients byte-for-byte is not a reliable shortcut: most inspected scripts also set AI speed explicitly. The Vehicle402 M602 record has zero observed 3100 calls, and Vehicle403 MP501 has zero observed 3040 calls; neither exception proves the AI cannot move or attack by any other route. The reported 3113 call count is zero across these 25 records, which similarly is not a universal claim about original EDF 4.1 boarding.

The complete 25-row research table is retained as data/EDF41_VEHICLE_402_404_MISSION_NATIVE_CALLS_25_R146.csv in the archive. Its campaign/dlc1/dlc2 section tags and mission IDs are research-corpus identifiers, not independent retail shipping ordinals. This static census is complementary to — and does not override — the later R2 weapon-SGO parity findings above.

R147 decoded-weapon reference and role-aware identity

The 402 AI AmmoCount 100/200 comparison above is role-aware: original V_402ROCKET_ROCKETCANNON.SGO is compared with EDF6 V_402ROCKET_ROCKETCANNON_AI.SGO. The same-named EDF4.1/EDF6 V_402ROCKET_AI_ROCKETCANNON.SGO files instead each declare 50; these are distinct pairing questions. The R2 role comparison remains correct. A separate 19-pair native weapon field atlas documents 14 decoded gameplay fields per same-name variant, all 11 role-based R2 comparisons and the five target-only names in the research sample. The R2 patch list is narrower than this static field inventory, and neither establishes game-runtime qualification.

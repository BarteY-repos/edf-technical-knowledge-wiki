EDF5 notice messages: event 12, UI listeners and loading-scene boundaries

EDF 5Game technical referencesNative user interface
Technical reference · Source-scoped static analysis with contributor runtime marked; no new R129 game test

EDF5's message-log/notification route is a UI event dispatch, not a console print. A native poster builds a wide-string payload paired with an optional game-object context, then emits manager event 12. The UI manager forwards that event to registered listeners; the in-game notice screen interprets it through its own handler.

Native event route

460BE0 (build-relative) prepares the text and object context, then invokes 61E950(uiManager, 12, payload). The manager locks its critical section and iterates listener lists, calling a virtual handler for each. The notice listener is an UiNotice object; its event-12 handler consumes the text rather than interpreting it as a HUD draw command.

A separate listener can be present in offline missions. Thus the route is not exclusively tied to a multiplayer room: messages can appear during offline play as long as the receiving UI is initialized and its active listener exists.

Initialization is not equivalent to listener readiness

Source analysis shows a lazily created UI manager held in a global pointer. The UiNotice listener, however, is constructed and attached as part of the current UI/scene lifecycle. Those two lifetimes should not be conflated.

One earlier contributor test posted a message from a first-frame radar draw hook during mission loading and observed an immediate crash, while a corresponding action-triggered post worked after the mission had started. That first-frame result was not independently isolated or repeated. It is evidence that initialization timing matters, not proof that all loading-screen notices crash or that a stable runtime bug has been identified.

What a log entry proves

If an entry appears in the message log, the active listener and event-dispatch route handled it. If a line does not appear, the absence alone cannot tell whether the producer never sent it, the manager was unavailable, or the correct listener was not active. No additional EDF5 runtime testing was carried out in R127.

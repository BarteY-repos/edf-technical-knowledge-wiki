EDF6 fire-sync: four controlled weapon discriminators

EDF 6Engine RE & NetworkingGameplay & AI
Technical reference · Exact native static / shipped WEAPONTABLE evaluation; read-only live tests proposed, not recorded

EDF6 can use direct subtype0 or deferred, receiver-reconstructed subtype1 for a weapon shot. The decisive variable is the evaluated runtime policy, not simply the weapon name or its base SGO. The following four-weapon matrix comes from exact binary inspection and correlated shipped-weapon star evaluation. It is a read-only test design, not a claim that the probe has passed on two live PCs.

Build scope: canonical EDF6 EDF.dll SHA-256 0d5092393a1b9d8f1b75b0c93d8a8f65615a36a92c46e40349c2b66c733d0916. RVAs must not be transplanted blindly to another game build.

Four high-value comparisons

Weapon / source asset Static policy prediction Why this case isolates a failure
M2 Raven — AWEAPON016.SGO Always batched subtype1; sync_level=-1, bit4=1; SolidBullet01, spread type 0 Baseline for receiver-local projectile construction without random initial spread
MR114 Fang — AWEAPON108.SGO Always direct subtype0, full sender transform (sync_level=1, bit4=0); spread type 0 Control for direct sender transform authority
Penetrator F — AWEAPON104.SGO Can be subtype1, direct sync0 or direct sync1 solely as correlated upgrade stars change Strongest same-weapon three-state test of policy selection
Wide Acid Gun — AWEAPON194.SGO Always subtype1 (sync_level=-1, bit4=1); AcidBullet01, spread type 1 Tests receiver-local random spread when the subtype1 packet lacks pre-spread seed restoration

Exact Penetrator F star discriminators

The source evaluation identified these three representative correlated star states (key = star slot index):

Star slots Expected network path Transform authority
{0:0, 2:0, 4:0, 5:3} subtype1; sync -1, bit4 set deferred receiver-local
{0:0, 2:0, 4:0, 5:0} direct subtype0; sync 0, bit4 clear sender orientation, receiver-local translation
{0:0, 2:1, 4:0, 5:0} direct subtype0; sync 1, bit4 clear full sender transform

These are derived source-config states, not a guarantee that a tester can select each exact combination with a standard in-game inventory UI. The relevant state must be established and read back before comparing traffic.

Read-only trace checkpoints

The historical probe kit was built and statically checked but had runtime pending. Its entry probes are observational: it was not designed to edit fields, packet bytes or scheduling. Record at least:

Function RVA Event Distinguishing observation
0x767150 Policy synthesis Weapon+0x153C flags, +0x1540 sync level, star-evaluated parameters
0x694910 Direct sender Bit4 early suppression vs actual subtype0 packet
0x695F20 Batched sender +0x1544 target count, +0x154C delay, +0x1550 dirty state
0x690420 Batched receiver Accepted target and owner/proxy role
0x6947E0 Deferred remote realization local count, target, cadence, count catch-up
0x698500 / 0x6969A0 Shot selection/transform named-node transform provenance and selected muzzle/source entry

Optional short timing samples: SoldierBase::OnUpdate 0x59ABB0 and common Weapon OnUpdate 0x6934F0. Do not turn a short ordering comparison into a permanent per-frame logging load.

The read-only probe instructions use F8 to arm and lock the next weapon event, F9 to reset/unlock and F10 to toggle a short Soldier/Weapon ordering sample. These are tool controls, not EDF gameplay mechanics.

Expected interpretation

  • M2 Raven: direct-sender function may execute but should take the bit4 suppression path; eventual subtype1 TX and later remote count-based reconstruction are expected.
  • MR114 Fang: the direct packet should contain the full sender transform; ordinary shots should not follow the delayed subtype1 realization path.
  • Penetrator F: one source weapon should demonstrate all three effective policies if the exact source star states can be reproduced and logged. This is an explicit counterexample to a static “one weapon → one network policy” mapping.
  • Wide Acid Gun: a later cumulative count can repair the number of reconstructed shots without reconstructing the sender's original per-shot random spread.

Keep initial fire and later NetworkBullet selector0/1/2 records separate: Sandlot can retransmit the latter while subtype1 initial creation still lacks historical RNG/charge/class-internal state. A matching shot count, player orientation or ACK does not establish full projectile equivalence.

Qualification boundary: The historical source documents static/linked/cold-extract probe qualification; no corresponding successful paired runtime trace is contained in the reviewed material. For the underlying formula, RNG progression and individual projectile classes, see Weapon RNG and batched fire and star-dependent policy evaluation.

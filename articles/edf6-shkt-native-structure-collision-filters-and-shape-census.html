EDF6 SHKT: Havok system layout, collision filters and measured shapes

EDF 6Game technical referencesPhysics
Technical reference · Original source reports static binary/file analysis, with separately labelled contributor in-game tests; no new tests this release

A native EDF6 .SHKT contains Havok Physics 2020 objects for character and vehicle hitboxes, joints and rigid bodies. Its class format differs from the legacy hkp structures used in EDF4.1/EDF5: the studied EDF6 files use an hknpPhysicsSystemData, or a hknpRagdollData wrapper where a skeleton field is present but not shown to drive the game's binding.

Core records

Area Native meaning
bodyCinfos Body transforms, masses, motion and material references
constraintCinfos Joint relationships, with bodyA the child and bodyB its parent
Materials Friction and restitution; their encoded hkHalf16 is the upper half of an IEEE float32
Motion properties Limits, damping and related rigid-body simulation fields
Shapes Spheres, capsules, boxes, cylinders, convex hulls, compounds and compressed meshes

motionType values observed: 0 static, 1 keyframed, 2 dynamic. materialId and motionPropertiesId refer to local tables; 65535 can mean absent/none (including static-body cases). A source census found one physics system per SHKT in all 316 files in that survey. The largest surveyed system had 111 bodies; a ragdoll example had 94 bodies and 93 constraints.

Packed collision filter field

The body-side collisionFilterInfo encodes subsystem exclusions separately from the runtime collision layer:

Bits Field
0–4 Layer slot (game can override)
5–9 Subsystem ID
10–14 Subsystem ID to exclude
15–30 System group

The game derives the effective layer during registration; the source found the serialized layer slot 0 for all 4,954 surveyed bodies, though actual player, enemy and map layers differ at runtime. Ragdoll body exclusions commonly refer to the parent body's subsystem ID; when the character contains over 31 bodies, 5-bit subsystem IDs are necessarily reused. Do not interpret a serialized layer zero as “this body collides with nothing.”

The code's CollisionFilter::CollisionFilter path uses a fixed layer-pair matrix. Some examples from the investigator's table: player/vehicle layer 1 collides with map-prop layer 20; enemy layer 2 collides with terrain layer 17, but not generally with prop layer 20. Layer 26 is a special bullet-penetrable map category: it collides with several character/query layers, not the listed bullet layers 10–13. These statements refer to code and surveyed modded-runtime observations; see the separate 32×32 collision matrix if available in the published edition.

Across that same census: 4,954 bodies, 4,444 materials, 4,230 motion-property entries and 3,059 constraints. All values are corpus counts, not global limits for arbitrary expansions. The source identifies simdTree in compound shapes as a four-way BVH; aabbTree is empty in the examined files. The largest source-observed convex hull has 252 vertices; up to 250 were separately reported working in the game, while 253–256 remained unqualified. Do not confuse the maximum observed size with a universally validated engine limit.

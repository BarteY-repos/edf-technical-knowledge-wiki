EDF6 appearance variants: outfit IDs, saved colors and asynchronous HQ 3D models

EDF 6Game technical referencesPlayer and UI
Technical reference · Source-backed static analysis with explicitly scoped contributor tests; no new R125 runtime

EDF6 does not treat the currently drawn soldier model as the sole authority for an outfit. The investigated game-state structure stores one outfit value per local player, while 3D room/HQ previews build models from a description containing class, two colors, outfit variant and equipped weapons.

Outfit identity and variants

The source identifies an appearance field with permitted values −1 through 3. A soldier-screen choice is converted into a saved outfit ID, not simply a filename swapped at render time. The popup's five entries include ModelIndexMission, Trainee, Soldier, EDF5Trainee, EDF5Soldier. Their callback values in the examined build are respectively −1, 2, 3, 1, 0. These IDs are game-state values and must not be confused with the on-screen order of the popup or with another class's independent customization fields.

Room and HQ preview models

HUiHQ3DModel creates a view for each local player. Its description carries class code, outfit value, two color values and weapon entries. The source shows a message-driven update path rather than a new model being built synchronously on every UI click. Messages distinguish full model rebuilds, single-weapon updates, recolor and outfit changes. An asynchronous job performs the actual model update and tracks a completion flag.

For the surveyed Fencer example the description includes a left-hand shield entry before the main weapon, matching a weapon-slot convention rather than a generic two-gun visualization. Other UI messages can temporarily lock and unlock rebuilds during a transition. A remote online participant is not automatically another local HQ preview slot: its model description is derived through separate multiplayer state.

Boundaries

Those internal values and message IDs describe source build steam-678ccb46. The source does not establish that every character class exposes each outfit variant in the same menu or that a custom model can be substituted without additional resource work. No UI gameplay observation was made in R125.

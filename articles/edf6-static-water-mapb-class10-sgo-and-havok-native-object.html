EDF6 static water: MAPB class 10, SGO fields and MAD collision structure

EDF 6Maps & NavigationNative water object graph
Technical reference · Native EDF6 source game resource graph, runtime acceptance not implied for new assets

The examined native EDF6 NW_EUROPE01 water surface is not merely a blue texture on a terrain plane. Its MAPB object class, object SGO, MAPO resource companions, render MDB and static MAD/Havok body form a distinct map resource family. The measured example is eu1_nw_field01_water.mdx; the geometry and material values here are scoped to that native object rather than all water in the game.

The material's four observed sampler names are bubble_albedo, normal_map1, normal_map2, normal_map3. Its other parameters concern water colour/specular/roughness, bubble/normal-layer controls and UV behaviour, but the exact shader equations are not recovered from the object graph alone.

How to interpret these values

  • Class 10 is the observed water T1 role, not proof that every resource with class 10 must be a water plane.
  • Type="水" (Japanese water) is a named SGO value on the native object. Collision_Enable=-1 and Durability=0 are stored values; they do not by themselves define the full water physics or damage model.
  • The MAD body is a static compressed mesh, not a simulated fluid volume. Its special mass/motion fields must not be copied indiscriminately to ordinary destructible props.
  • Absence of p58/T50 fits this non-destructible water exemplar; it does not prove that all aquatic objects in EDF6 have no destruction support.
  • The retained native geometry is planar with a shared visual/collision footprint. This is distinct from assuming a generic actor can swim, drown or collide with a volumetric fluid.

Binary-format consistency versus rendered water

A controlled experiment recreated a different, simple two-triangle horizontal visual/collision water surface with the same kind of class-10/SGO/MAPO/MAD graph. Its wire, first-primitive and compressed-broadphase checks passed offline. That establishes that the investigated structure can be serialized in a bounded authored case. It does not establish accurate in-game water draw, near/depth fading, texture scrolling, collision, culling or performance for a new map.

Across the four retained map-family RAB scans (NW_EUROPE01, HEIGEN507, CAVE503, DESERT508) exactly one snd_BRDF_Map_Water material was observed. No separately named universal River or Ocean material family appeared in that finite sample. This is not a global statement that EDF6 lacks rivers or oceans.

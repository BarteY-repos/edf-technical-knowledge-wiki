Effects (EFS / ESB / EFARC)

EDF 6DocumentationFile Formats
Technical reference · Community-provided Japanese memo; source-specific and not independently rerun

EDF6 effects are assembled from effect definitions, models and textures. They should not be confused with ordinary model materials or audio banks.

File and node hierarchy

Format/name Role
.efarc Archive resembling RAB; contains EFFECT, MODEL, TEXTURE folders in the tested examples
.esb Binary definition of an individual effect, typically referenced under EFFECT
EFS Effect-system graph/description; some weapon classes are EfsBullet or EfsMuzzleFlush
Singleton Contains a set of NodeTransform, RenderInfo and NodeColor components in the documented profile
Emitter A separate sibling component with emission geometry and timing

The workbook reports extraction/repacking through EDF Tools (repacking could produce .rab, then be renamed to .efarc) and XML conversion through EFS Tool. Tool support is incomplete. Specifically, the note says that EFS Tool cannot handle NodeShape_Plane in some cases and may crash during conversion; do not assume the game itself crashes simply because the tool does.

RenderInfo_Texture: experiment-backed fields

Source sample: E609_JORMUNGAND.efarc, head_large_laser_fire.esb, Singleton1. The author changed fields one at a time.

Field Observation Confidence
Texture Referenced DDS path, e.g. FLASHRING10.DDS Direct sample
3rd element, scale Overall effect scale; reducing 8 to 1 made it smaller Experiment
4th, rendermode Modes 0–3 change rendering; precise blend formula unresolved Tentative
7th (unk4) Setting 1 stopped a particular rotation Sample-specific
9th, candidate pixelType Values 0/1 change appearance; meaning is hypothesized Unverified semantics
11th float (sample −4) Changing toward positive altered occlusion/depth ordering relative to camera/weapon Experiment; exact unit unresolved

Do not replace unk* values with invented enum names. The XML tool labels are partial, and many observations are subjective comparisons.

Interpolation and emission geometry

NodeCIScale_All / scale > type was tested with these interpretations:

  • 0 and 4: the tested object was invisible;
  • 1: smooth-looking interpolation with potential overshoot;
  • 2: linear interpolation;
  • 3: step / no interpolation.

For NodeShape_Plane, the contributor observed that a rotation node changes emission direction; two float dimensions controlled rectangle width/height. In the tested setup, setting ID1 from 0 to 1 caused a crash. Other field meanings remain unverified.

RenderInfo_Model can reference an MDB and contains ChangeParams, including time-varying shader parameter channels such as diffuse RGBA. See Shaders for the ordinary MDB material path, which is not interchangeable with an ESB effect node.

Space/orientation caveat

The normal vector at an impact generally affects how an impact effect is oriented. In the DEMOMISSILE_VSRING.EFARC examples, certain NodeParticle_Particle3D > NodeVector_XYZ and NodeParticle_Particle2D > XScale/YScale values behaved relative to world axes. The workbook did not establish a universal world-space override for all nodes.

Workbook's 19 EFS-root timing probes (source-bounded)

The original workbook contains 19 named source-parameter combinations for root EFS unk1 and anim_frames, tested using a Tempest Final Option projectile (efs!B87:D112). In the author's observations: three combinations remained visible until impact; six lost the entire effect after about one second; six lost only the emitter plus point light; and four lost only the emitter. Examples:

unk1 anim_frames Contributor observation
−1 0 or 600 Elements remained visible until impact
0 0 Elements remained visible until impact
0 60 Emitter and point light disappeared after ~1 s
0 600 Whole effect disappeared after ~1 s
1 0 Only emitter disappeared after ~1 s
1 60 or 600 Whole effect disappeared after ~1 s

These observations are not monotonic in anim_frames; nearby configurations exhibit different lifetime outcomes. Thus there is no evidence for one universal “frame count = lifetime” equation covering every effect subcomponent. The author tentatively suspected interaction with another Effect unk2 field, without proving it. The full 19-case ledger, including negative results, is reference/R154_EFS_TIMING_19_SOURCE_EXPERIMENTS.csv. This is an original contributor gameplay experiment, not a new game run in the current wiki edition.

The NodeShape_Plane warning above is also historical and superseded within the original workbook: efs!T12 says the noted unsupported-case tool issue was subsequently fixed. The workbook still reports an in-game crash in a specific modified NodeShape_Plane ID1 test at efs!B132:D133, which must not be conflated with that XML tool bug.

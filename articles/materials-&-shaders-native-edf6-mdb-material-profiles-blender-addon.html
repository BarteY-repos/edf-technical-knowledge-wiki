LOD is not a single material substitution

The native corpus contains several LOD/FarMap shader families. Some explicit _lod.mdb companions retain the same base material shaders. Therefore an _lod.mdb source name alone does not determine a material family.

Legacy and BRDF families coexist in EDF6

Examples in the same native corpus include both:

  • BRDF-style snd_BRDF_Map_* materials with roughness, metallic, specular_diffuse_blend;
  • older snd_Map_* materials with specular_pow, light_smooth, reflect/spec packed textures and other legacy fields.

A shader-name-only migration is unsafe. Runtime testing showed that blindly switching legacy reflect/spec families does not fix a material-contract mismatch; the shader, parameter ABI, sampler meanings and vertex layout have to move coherently.

EDF5 distant insect and humanoid animation frame skipping is not a simulation slowdown

EDF 5Game technical referencesRendering / animation timing
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5's animation pipeline can skip pose evaluation for distant insects and some humanoids. It does not necessarily skip AI logic, movement, damage or animation time. The InsectBase code advances animation time each frame, but queues a CAS pose-evaluation job only on frames selected by an object-specific modulo rule.

Source distance-metric band (not calibrated real metres) InsectBase pose-job cadence
Near band, up to nominal 150 Every frame (N=1)
Next nominal 150–300 Every fourth frame (N=4)
Next nominal 300–600 Every eighth frame (N=8)
Beyond nominal 600 / not drawn previously Every sixteenth frame (N=16)

The source chooses these bands from a renderer-scaled squared-distance metric; they should not be interpreted as calibrated metres without resolving that scale. The numeric thresholds are 22500 / 90000 / 360000 and an animation/model visibility bookkeeping field. Eligible insect classes include GiantAnt, GiantSpider, GiantBee and DragonSmall (Tadpole in EDF5). The skip also has an SGO/controller flag and a state bypass; not every insect performs the same skip under every condition.

For HumanBase, the corresponding code has closer nominal metric bands 30 / 60 / 120 (squared 900 / 3600 / 14400), but the configuration human_frame_skip_enable defaults to 0 in the examined SGO loading path. Therefore the presence of this branch in native code is not proof that all soldiers ordinarily render at the reduced pose rate.

The study found this explicit pose-job skip in two update functions, InsectBase and HumanBase, and did not find it in the named Nephila/fortress/robot/UFO families. Such a negative code-scan result is bounded to the inspected classes; it is not a claim that every other effect in EDF5 updates each frame.

Source: edf5/models.md, facts insect-pose-job-skip, human-pose-job-skip, pose-job-skip-scope (static disassembly, no fresh runtime A/B). This is distinct from the engine's fixed simulation step and actual display refresh.

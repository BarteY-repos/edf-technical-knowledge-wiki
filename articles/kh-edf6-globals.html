Evidence: static · Build: steam-678ccb46 · Fact ID: text-language-global

The text language is the int at 20B2B30 (confirms misc-globals' first part): getter E4000 (mov eax,[20B2B30]; ret), setter E4030 (mov [20B2B30],ecx; ret); E4010 reads the neighbor 20B2B34 (the voice language, per the author). Values: 0 ja, 1 en, 2 kr, 3 cn (traditional, font B5), 4 sc (simplified, font G30), the order of the option strings Option_Language_ja / en / kr / cn / sc (from 1802638, listed by 88F6E0); at start 706EF0 maps Steam's language names english / japanese / koreana / tchinese / schinese to 1 / 0 / 2 / 3 / 4 (compared in D62C0 / D90D0, which call E4030). Other writers: the options screen (9457DE: option data +0x310 -> E4030, then the fonts are rebuilt, 94580D call 963830, hud.md#hud-fonts) and ABFCF (also followed by a font rebuild); readers: the font loader's caller (963724 call E4000, 96372E call 963830) and about 20 others (text tables).

Basis: E4000..E4036 re-read with fn.py; the rest the author's reading ("H"; the callers' purposes "M")

Voice language setter and Chinese language mapping

Evidence: static · Build: steam-678ccb46 · Fact ID: voice-language-global

EDF6 MoveAreaManager and play-area boundaries

Evidence: static · Build: steam-678ccb46 · Fact ID: move-area-manager

Reading map

This source note combines several technical details. Its evidence grade, game build and contributor credit above still apply to the entire record. Follow these topics, then expand the complete original text for offsets, exceptions and caveats.

  1. Manager singleton and object fields
  2. Move-area checks
  3. Helicopter and actor consumers
EDF Knowledge Hub record — original wording — expand (2,239 characters)

MoveAreaManager (the map's move area): singleton [20B2998] holds the object's address + 8 (its second vtable); readers subtract 8 (getter 11BD90, also 654441). Created at 7014CD in 7004F0 (new 0x50, constructor 5A9810); vtables 17D3970 / 17D39D8. Fields from the object start: +0x10 box min (default (-500, -1000, -500)), +0x20 box max (default (500, 500, 500)), +0x30 a list head, +0x40 hard Y limit (10000), +0x44 ceiling (300). KittopiaCreator's table offsets (#game-system-fields) count from the stored pointer, so its +8 X_MIN is +0x10 here. The box writer 5AA5C0(m, {center, half}) sets min = c - h with min.y forced to -1000 and max = c + h with max.y raised to at least 500; callers: map load 121470 at 1229DF (the first Rectangle (1762AC8) shape of the map's shape set named move_limit (1769C78); no set = the ±500 default), additional_map_param 11BDC0 at 11C4A3 (height_limit {min,max} for Y, then ceiling +0x44 = max.y; only ig_terracemountain, ig_steepcoast, ig_plateau have one, all {-1000, 500}), the script's SetMoveArea(string) 1BA1B0 (at 1BA2A7; registered at 1E838E) and 228610 (at 2287A1; "SetMoveArea( not found : %ls )", mission points [20B28A8]+0x10); 5A9D80 reads the box back as center / half. Clamp 5A9E50(m, float4* pos, float r, int mask) (17 callers): box shrunk by r (lo = min - r, hi = max + r with r passed negative); mask 1 clamps x and z, mask 2 y (below lo.y it writes hi.y; above min(+0x40, hi.y) it clamps). Helicopters' slot 55 base 6543A0 (called by 506 61B8F0, 409 64C020, 410 64E080) clamps the body each frame by r = -veh+0xE00 and the ceiling +0x44, then teleports it with 11B1A00 (hknp setBodyPosition, velocity kept); veh+0xE00 (written only at 629D81 in the VehicleBase init 629450: the largest seat distance from the center) is read only by the four vehicle clamps 645790, 6543A0, 6636E0, 673A60. Example: ig_Heigen601's move_limit is center 0, half (999, 200, 999). The BombingPlane update 5AB240 (pos += vel) never clamps. Beyond the move area, the hknp broad phase spans ±3000 m on each axis (11AD395, constant 17BE0E0; hknpWorldCinfo DD2A80, world built by DA2020 in 11AD340, bounds kept at world+0x4F0 / +0x500; gravity (0, -14.7, 0)); what hknp does with a body leaving it was not found.

Basis: 11AD395 re-read with fn.py; the rest the author's reading ("H"; the map's RMPA read from MAP/IG_HEIGEN601.MAC)

Addresses (build-specific RVAs unless indicated): 20B2998, 11BD90, 654441, 7014CD, 7004F0, 5A9810, 17D3970, 17D39D8, 5AA5C0, 121470, 1229DF, 1762AC8, 1769C78, 11BDC0, 11C4A3, 1BA1B0, 1BA2A7, 1E838E, 228610, 2287A1, 20B28A8, 5A9D80, 5A9E50, 6543A0, 61B8F0, 64C020, 64E080, 11B1A00, 629D81, 629450, 645790, 6636E0, 673A60, 5AB240, 11AD395, 17BE0E0, DD2A80, DA2020, 11AD340

EDF Knowledge Hub record — original wording — expand (1,233 characters)

Inside the helicopter clamp 6543A0 (#move-area-manager): 6543C9 keeps the vehicle in rdi; 6543CC r = -[veh+0xE00]; 6543E1..654437 copy the body's world matrix to veh+0x60..+0x9F; 654463 clamps y to the ceiling; 654478 / 65448E call 5A9E50(11BD90(), &pos, r, 3); on any change 65449B calls 11B1A00(body [veh+0x1650], &pos) and sets veh+0x90 = pos; 65450E clears the input block from +0x1540 and tail-jumps to vfunc 0x1C0 (slot 56). 506's slot 55 61B8F0 calls it and then tail-jumps to 64FFD0. 654230 is a variant taking the body from this+0xD0, with no direct caller (unread). A patch can skip only the area clamp by redirecting the call 5A9E50 at 65448E (5 bytes; rdi = vehicle there). No 16-byte vector access touches +0xDF0..+0xE00 in the vehicle code (5F0000..690000); the one other +0xE00 there, a pointer write at 68E94E, is another structure. The map-load reader takes the shape's +0x00 as center and +0x10 as half-size (1220DE..12213D). The physics world's creator 11AD340 is called from 1193400; DA2020 copies the ±3000 broad-phase corners (cinfo +0x90 / +0xA0) to world+0x4F0 / +0x500 at DA2A5C..DA2A71; 42C7A0 also references the constant 17BE0E0. The script's SetMoveArea declaration string is at 17956F8 (used at 1E83AF).

EDF6 water triggers and MoveAreaManager

Evidence: static · Build: steam-678ccb46 · Fact ID: water-trigger-areas

Reading map

This source note combines several technical details. Its evidence grade, game build and contributor credit above still apply to the entire record. Follow these topics, then expand the complete original text for offsets, exceptions and caveats.

  1. Map loader registration
  2. Trigger body list
  3. Water contact events
EDF Knowledge Hub record — original wording — expand (1,487 characters)

Water is a set of trigger bodies kept by the MoveAreaManager: the map loader 121470 passes each entry of map+0x160 (count +0x170, stride 0x30: +0 shape ref, +0x10 quaternion, +0x20 position) to 5A9B20(manager, transform, &shape) (at 122987), which builds a trigger-body wrapper (0x78 bytes, constructor 100350, vtable 179F218), creates the body (11B88D0), sets layer 25 (106140 -> D929F0(0x19), applied by 11B1840(body, filter, 1)), calls 11B0940(body) and appends the area to the list at manager +0x30 (size +0x38). Manager slot 4 5AA140 each frame: for each body overlapping an area (ids at area +0x08, count +0x10), the object (108260(id), cast to GameObjectBase) gets a vertical ray at its x / z from AABB top + 0.1 to bottom - 0.1 cast only against the water body (11A7480(wrapper, collector, input with filter 0, &bodyId, 1), body id [[area+0x58]+0xF0]); on a hit it sends message 0x10000025 with the hit y (collector +0x34, the water surface). HumanBase's handler 572810 (at 5728FE) stores +0x118C = surface y and +0x1187 = 1; 572DF0 copies it to +0x1188 (in water this frame), plays the splash (7B4510) on a falling entry and, when surface y - +0x94 > 1.5 (1769100), enters swimming (HumanBase slot 73 57B470, +0x5D0 = 0xC); helicopters (652E70), cars (673850) and monsters (3A4940) also take 0x10000025. Layer 25 collides with layers 1, 2, 3, 6 and 7 only, and the map-ray layer 22 does not see water (a map ray over the sea hits the seabed). EDF.dll has no water-height string.

Basis: the author's static reading ("H")

Addresses (build-specific RVAs unless indicated): 121470, 5A9B20, 122987, 100350, 179F218, 11B88D0, 106140, D929F0, 11B1840, 11B0940, 5AA140, 108260, 11A7480, 572810, 5728FE, 572DF0, 7B4510, 1769100, 57B470, 652E70, 673850, 3A4940

Text-table key lookup contract

Manager key search, fallback and language binding

Static EDF6 disassembly. 7A3500(rcx=[20B29A8],rdx=wide_key) iterates text table list at manager +0x130; each node's table at +0x38 is searched by 52790 (index or −1). A found string is loaded from table+[table+0xC]+index*12 using record data offset +8; missing keys return the shared empty wide string 1762240 without logging. Roughly 300 xrefs exist, with fixed-key wrappers 7BF420/7BF460/7BF4A0 and a std::wstring call at 1CCB40. Lookup follows the current text-language state; analogous native readers are EDF5 4738B0 and EDF4.1 3DFD00. No localization table was switched in a fresh runtime test.

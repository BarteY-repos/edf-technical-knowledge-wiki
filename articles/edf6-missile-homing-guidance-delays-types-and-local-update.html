EDF6 homing projectiles: steering modes, delay parameters and local simulation

EDF 6Game technical referencesWeapons
Technical reference · Original source reports static binary/file analysis, with separately labelled contributor in-game tests; no new tests this release

An EDF6 homing bullet does not necessarily rotate directly toward its target as soon as it spawns. The native bullet classes use separate ignition/steering gates and at least two distinct guidance models. Mislabeling their custom-parameter positions can invert the meaning of a missile's early trajectory.

Which classes are involved?

The surveyed code identifies MissileBullet01, MissileBullet02 and HomingLaserBullet01 as distinct homing families, with separate constructors and updates. Their exact custom-parameter contract is class-specific. A missile class whose numeric type selects a rocket/non-homing mode must not be treated as having the same steering rules as type 1 or type 2.

For MissileBullet01 and MissileBullet02, the source corrected an older interpretation of custom parameter CP[9]. It is not a generic homing-duration timeout: it can function as a second delay before steering, after the initial CP[8] gate. In the examined vanilla weapon data only the Ranger MLRA (AWEAPON143) had a nonzero CP[9], of 5. HomingLaserBullet01 has a different, genuine duration check; the MLRA finding must not be extended to it.

Two guidance models in MissileBullet01

Steering mode Observed mechanism Important consequence
Type 1 — pursuit Own velocity gains acceleration up to a speed cap, then rotates toward line of sight by a clamped angular step Direction of own velocity is turned; inherited velocity is added separately
Type 2 — thrust/inertia Thrust is applied along current nose; the nose rotates toward line of sight within its angular limit Momentum is not rotated instantly; trajectory curves from acceleration and inertia

For both types, propulsion/velocity maintenance can occur even while the guidance gate is closed. Type 2 in particular accelerates forward before it begins turning; when the nose rotates, the velocity follows indirectly. The source estimates an approximate maximum lateral acceleration from thrust magnitude, not from the nose turn-rate parameter alone.

Target loss and spread

The code checks whether the lock record and its target/control block are still valid. When it is absent or expired, the missile can fall back to an ahead-of-itself aim point rather than inventing a new target. A MissileBullet01 optional CP[12] mode arms an overshoot/give-up behavior; no surveyed vanilla weapon enabled it.

Some guided variants sample randomness when constructed, modifying live speed/turn parameters via interpolation from CP[10]. That means identical SGO constants do not necessarily produce identical per-shot values. The source also reports that homing bullets are simulated locally on peers; this should not be confused with full replication of every intermediate steering vector.

Evidence and boundaries

These are static RE findings with contributor calculations, not new trajectory captures. The shape of custom-parameter arrays and numbered slots must be checked per class and per build; these are not universal commands for every EDF weapon. Source code RVAs: type 1 around 0x269AF0, type 2 around 0x269EE0, and the shared MissileBullet01 update around 0x26A880, scoped to the studied EDF.dll build.

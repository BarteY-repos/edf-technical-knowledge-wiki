EDF6 60 Hz simulation, DXGI Present pacing and refresh-rate mismatch

EDF 6Game technical referencesRendering and performance
Technical reference · Source-backed static analysis with explicitly scoped contributor tests; no new R125 runtime

An uneven-looking EDF6 frame does not always mean the game simulated its movement unevenly. The source distinguishes its approximately 60 Hz update cadence, its presentation call, and the external display compositor. In the studied build the internal timing loop counts elapsed 1/60-second periods and performs at most three catch-up update steps in one loop, dropping further excess time rather than accumulating unlimited simulation debt.

What was actually observed

A contributor captured the game at approximately 60 FPS during missions and reported one gameplay step per Present in roughly 99.5% of displayed frames, with occasional adjacent two-step and zero-step frames. It also reported 47–51 FPS when a never-focused game window was held offscreen: disabling the present synchronization for that specific test restored approximately 59–60 FPS, supporting a presentation wait rather than a wholesale slowdown of the internal clock.

Borderless window and refresh mismatch

The contributor's PresentMon captures at 2560×1440, 165 Hz identified borderless EDF6 as a legacy composed copy path using SyncInterval=1, not a demonstrated variable-refresh direct-flip path. A 60 FPS sequence displayed on a fixed 165 Hz interval must distribute frames unevenly across 2 and 3 desktop refresh intervals. In the source's two one-minute traces, the displayed-frame timings clustered near 12.1 ms and 18.2 ms, rather than uniform 16.7 ms.

Thus a visual 60→165 Hz unevenness can occur even if game simulation updates are stable. A refresh rate that is an integer multiple of 60 avoids that particular 2/3-interval pattern, but is not a universal solution for stutter, GPU stalls, shader compilation or online delays.

External presentation changes are different evidence

Separate contributor tests with Special K reported a flip-model presentation path at 120 Hz but still showed timing outliers; a different Latent Sync configuration reduced variance in that test. These are observations on a named test system, not native EDF6 settings, stock behavior or a generally verified optimization recommendation. They do not establish that an uncapped EDF6 game loop would run animation correctly above 60 Hz.

EDF4.1 mission content: offline, DLC, online-only and BEFORE.BVM

Source-backed research / case study · Bounded original-source classification, native BVM/RMPA readings; 147 reported vs 138 previously converted; nine online-only source IDs not yet directly enumerated

Evidence level: Source-file classification, original script/container observations and scoped conversion comparisons. The numbers describe distinct content sets; they do not certify complete EDF6 gameplay behavior. See the original-versus-converted mission coverage explanation.

How many EDF4.1 missions belong to each set?

The retained original-source comparison distinguishes 147 reported distinct EDF4.1 missions from the 138-mission conversion subset documented in earlier research:

Content scope Mission count In earlier 138-mission subset?
Main campaign, offline 89 Yes
Main campaign, online-only stages 9 No
DLC1 26 Yes
DLC2 23 Yes

The nine online-only stages are based on the retained original-source scope comparison; their complete IDs and placement in the original online MISSIONLIST.SGO have not been independently verified by a full original list census. Consequently, 147 is a bounded content-accounting result, not a new direct list-file enumeration. Conversely, the converted set's 138/138 source test does not establish that original EDF4.1 contains only 138 missions.

Original DLC mission identities include DM101 and DM202. Their numeric IDs are not evidence that DLC and online-only contents share one simple sequential numbering scheme.

Native source roles and cross-generation script differences

EDF4.1 original mission logic is stored in .BVM scripts, while EDF6 normally consumes AngelScript .AC mission scripts. A converter can pass source syntax and reference checks while still missing original gameplay effects, events or NPC behavior. This is a distinction between native file semantics and converted content, not a description of a required editor workflow.

Observed EDF4.1 BVM container elements include a 0x50-byte header, 16-byte function-table records, packed opcode/operand widths, relative branches and a UTF-16LE string pool. The native BVM structure reference explains these measurements and what is known to survive a cross-generation representation change.

Mission-specific .RMPA data and map .RMPA data have distinct source roles even if the filename extension is shared. A valid resource graph depends on preserving that context.

One historical conversion corpus reported 138/138 passing offline checks, but those were source/link/build checks, not 138 successful EDF6 mission playthroughs. The omitted online-only set remains outside that denominator.

Runtime and evidence boundaries

The historical offline source check included a compatibility implementation for EDF4.1 enemy/boss logic, pre-mission scenes, audio and a current-HP-only mission command. These are cross-generation implementation observations, not evidence that EDF6 natively provides every EDF4.1 behavior or that NPC movement is correct on EDF4.1 geometry.

There are three distinct checks:

  1. Original content: establish the correct .BVM/.RMPA files, campaign/online/DLC scope and original source identities.
  2. Structural translation: check whether the target representation retains the same intended events, values and resource references.
  3. Gameplay: observe the mission, allied recruitment and pathfinding, bosses, BEFORE presentation, sound and multiplayer under a matching EDF6 runtime.

Only the first two were meaningfully addressed by the earlier 138-mission source verification; the third was not established for the complete campaign. A structurally valid converted mission can still fail because the native map NAV, asset binding or game-specific API behavior differs.

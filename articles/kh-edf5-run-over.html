This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

The vehicle's contact component (map props only)

Every vehicle embeds a contact component at veh+0x490 (constructor 3CD720, called from VehicleBase's construc…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-contact-component

Every vehicle embeds a contact component at veh+0x490 (constructor 3CD720, called from VehicleBase's constructor at 352C30; vtable EBCB28, slot 1 the contact callback 3CDC60): +0x30 the owner, +0x38 the subscribed bodies (data +0x40, count +0x50), +0x60 a hit record (team +0x84, position +0x90, impulse +0xA0, damage +0xB0 = 0, flags +0xBC = 4, blast +0xB8, hit points +0xD0), +0xF0 a per-target hit queue, +0x138 the mode (0 off), +0x13C a once-per-contact flag (1), +0x140 the impulse scale (1.0), +0x144 the blast value (1.0). No contact threshold field (EDF6's +0x114). Three other classes build one (3CDAB0 is also called from 1E635F, 2C11FE and 33A9D5).

Basis: fn.py reads of the constructor and the subscriber; vtable by scratch flt.py

Addresses (build-specific RVAs unless indicated): 3CD720, 352C30, EBCB28, 3CDC60, 3CDAB0, 1E635F, 2C11FE, 33A9D5

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-contact-setup

CarBase's setup 379790 reads car_base_contact_map (EB8010) [mode, b, scale, flag]: the flag goes to veh+0x14C8, the scale to veh+0x5D0 (= component +0x140, 379C36); part bodies come from the ragdoll part records (veh+0x1130, 0xC0 each, body +0x58), skipping keyframed bodies (motion type +0x160 == 4) and those named in car_base_disable_contact_lisner (EB7FD0, 3C8A50 finds them by name in veh+0x10F0). Then 3CDAB0(comp, bodies, count, veh, mode, b) stores the owner, mode and b, and adds the component as a contact listener to each body (755F00; Physics2012's per-body listener, so no world event id as in EDF6).

Basis: fn.py reads (dump t6e5_379790.txt)

Addresses (build-specific RVAs unless indicated): 379790, EB8010, 379C36, EB7FD0, 3C8A50, 3CDAB0, 755F00

The callback 3CDC60(comp, contact event) sends hits only to map props: it returns when the mode is 0 or the e…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-contact-callback

The callback 3CDC60(comp, contact event) sends hits only to map props: it returns when the mode is 0 or the event's properties ([event+0x30]) have byte +0x13 bit 3 (already handled); it takes the other body (event +0x10 when +8 is one of its own, then the normal is flipped), finds the body's property key 0 ([body+0xB8], count +0xC0) and casts its object from SceneObject (TD 11A49C0) to MapObject_Base (TD 11A4830) with 9C8228 (3CDD38), stopping when that fails (3CDD43). Mode 2 takes any prop, mode 1 only props whose category ([[obj+0x150]]) is 2, 4, 5 or 6 (mask 0x74); the prop's check CF2A0 (passes for flag 0x04 unless slot 15 says it cannot be damaged) and its NetworkObject (+0xC0 slot 2, the default CF3A0 tested inline) gate the hit. No velocity test (EDF6 skips bodies moving apart). With b set the contact is marked handled (3CDEA1), so each contact point hits once.

Basis: fn.py read (dump t6e5_3CDC60.txt); TD names read at +0x10

Addresses (build-specific RVAs unless indicated): 3CDC60, 11A49C0, 11A4830, 9C8228, 3CDD38, 3CDD43, CF2A0, CF3A0, 3CDEA1

3CE170(comp, point and normal, {body, prop}, blast flag) fills the record as EDF6's 6F1640 does: team = the v…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-contact-hit

3CE170(comp, point and normal, {body, prop}, blast flag) fills the record as EDF6's 6F1640 does: team = the vehicle's +0x218, position, impulse = the normal x the scale +0x140, blast = +0x144 (1.0) only for a mode-2 prop outside categories 2, 4, 5 and 6, else 0, one hit point (body and contact), then queues it per target with 2D9420(comp+0xF0, target, record) (an entry of 0xA0 bytes; a second hit on the same target is merged by 2D9600). VehicleBase's update 354000 flushes the queue first thing every frame (2D9720 at 35403F), sending each entry as message 0x80000000 through the target's slots +0x38 / +0x30 / +0x40. So a vehicle pushes and breaks props through hits, and characters never get one.

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): 3CE170, 2D9420, 2D9600, 354000, 2D9720, 35403F

What a civilian meets

A civilian meets a vehicle only through physics, as in EDF6 (../edf6/run-over.mdedf6-civilian-no-run-over-hit…

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-civilian-no-run-over-hit

A civilian meets a vehicle only through physics, as in EDF6 (../edf6/run-over.md#edf6-civilian-no-run-over-hit): the contact component casts to MapObject_Base only (#edf5-vehicle-contact-callback), the ragdoll-contact listener sends no hit (#edf5-ragdoll-contact-key), and no other code was found that turns a vehicle contact into a hit. So a civilian in the way is shoved by the solver, without damage or knock-down. Inferred; the walk body's collision layer against vehicle parts was not read for EDF5 (character-control.md#edf5-moving-ground-open).

The knock-down hit (soldiers, NPCs and civilians alike)

A hit reaches a human's OnDamaged (slot 15, +0x78) at the end of the damage function (2DB9EE in 2DB370), afte…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-human-hit-path

A hit reaches a human's OnDamaged (slot 15, +0x78) at the end of the damage function (2DB9EE in 2DB370), after the friendly-fire test (combat.md#edf5-friendly-fire-factor) and HumanBase's accept test (slot 13 2EE160: for an enemy or teamless hit it refuses while +0xD54 > 0; any hit with a blast above 1e-6 sets +0xD58, 1 for a friend, 0 otherwise; it refuses while the action state machine +0xD90 is in state 2F6CCC). Flag 0x200 skips both.

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): 2DB9EE, 2DB370, 2EE160, 2F6CCC

Attribution: KH chat 177 (autorun) · 2026-11-14

HumanBase's OnDamaged 2EE220 (EDF6 5717D0, fields 0x3C0 lower) returns at once unless the damage +0x50 0 (2E…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-human-knockdown-gate

HumanBase's OnDamaged 2EE220 (EDF6 5717D0, fields 0x3C0 lower) returns at once unless the damage +0x50 > 0 (2EE2B7). A blast +0x58 above 1e-6 (EE6168) knocks the human down when +0xDC1, +0x29C, +0xDC2 and +0xDC3 are all 0 (2EE6D7..2EE705): it enters the down state 2E1FF8 on +0xD90 (2E1C10, 2EE7ED) unless it is in it already. For a player-controlled human (slot +0xD0) hit by a friend's team (table value 1) that is not itself, the per-difficulty byte table E92AA4 decides instead: 0, 0, 0, 1, 1 (2EE75C), so friends' blasts knock players down only on Hardest and Inferno (the table the loot work discarded, dead_ends.md). Otherwise (no blast, or already down) it starts a 30-frame flinch timer +0xE00 (2EEC8F).

Basis: fn.py read (dump t6e5_2EE220.txt); table bytes read

Addresses (build-specific RVAs unless indicated): 2EE220, 2EE2B7, EE6168, 2EE6D7, 2EE705, 2E1FF8, 2E1C10, 2EE7ED, E92AA4, 2EE75C, 2EEC8F

The launch, with the ragdoll active (+0xDC0

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-human-knockdown-velocity

The launch, with the ragdoll active (+0xDC0; ragdoll at +0xB70): c = a point of the ragdoll's box (3CAC90), d = c - the blast center +0x30, t = (R - |d|) / R with R the blast value; direction = d/|d| + (up - d/|d|) x t x 0.5 (EE633C, up EE7550); speed = max(8 x ln(R), 0) (EE65D4 = 8, logf thunk 9C826A), set as the ragdoll's velocity (3C99E0), plus a random spin (3C9CC0); each hit point's body gets an impulse along its offset of max(8 x ln(max(R - distance, 0)), 0) (the object at body+0x150, its slot +0xB8, 2EEC24). As EDF6: R 1 gives 0 m/s, 2.72 gives 8, 6.5 gives 15, 20 gives 24; unlike EDF6 a blast below 1 gives 0, never a pull back. A hit on a human with an active ragdoll and no blast (or already down) adds max(10 x ln(|impulse +0x40| x 0.0125), 0) m/s along the impulse (2EECB6..2EED5F, EE61F0, 3CA1B0).

Basis: fn.py read; constants by scratch flt.py; 9C826A jumps through the import of logf (C97B70)

Addresses (build-specific RVAs unless indicated): 3CAC90, EE633C, EE7550, EE65D4, 9C826A, 3C99E0, 3C9CC0, 2EEC24, 2EECB6, 2EED5F, EE61F0, 3CA1B0

Route and open questions

Route to send civilians flying when a vehicle hits them in EDF5 (00v topic 6): (a) find the contact: in the v…

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-run-over-route

Route to send civilians flying when a vehicle hits them in EDF5 (00v topic 6): (a) find the contact: in the vehicle's callback, replace the cast call at 3CDD38 (17 bytes E8 EB A4 5F 00 48 8B E8 48 85 C0 0F 84 5C 01 00 00, once in the file; rcx = the other body's object) with a stub that, when the MapObject_Base cast fails, casts to People (TD 11B2050) and handles it; it runs only for vehicles with a mode (#edf5-contact-map-values) and only on bodies the vehicle subscribed; or query near the bumper each frame. (b) Build a hit as 3CE170 does, with the vehicle as attacker, team -1 or flag 0x20 (a friend's hit is dropped otherwise, combat.md#edf5-friendly-fire-factor), damage above 0 (#edf5-human-knockdown-gate), blast R = e^(speed / 8) from the vehicle's speed, its center behind the civilian along the travel and nearer than R so the throw tilts up (#edf5-human-knockdown-velocity). (c) Queue it with 2D9420(veh+0x580, ...); the vehicle's update sends it the next frame. Untested.

Basis: from the lines above; bytes by bytes_at.py

Addresses (build-specific RVAs unless indicated): 3CDD38, 11B2050, 3CE170, 2D9420

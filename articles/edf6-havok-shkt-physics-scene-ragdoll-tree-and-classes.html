EDF6 SHKT physics scenes: hknp systems, ragdolls and the native class census

EDF 6Game technical referencesPhysics / object files
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

The typical EDF6 object/weapon SHKT file has an hkRootLevelContainer with a named variant called “Physics Data” or “Physics Scene Data”. Its class is hknpPhysicsSceneData, which points to one or more system data nodes. Those nodes hold material tables, motion properties, body CInfos, attachment relations, constraints and the overall physics-system name.

The system node is either ordinary hknpPhysicsSystemData or, for ragdolls, hknpRagdollData with additional skeleton, bone-to-body mapping and body-tag arrays. hknpBodyCinfo properties are not identical to authored render-mesh metadata. Some shape graphs use hknpConvexShape, hknpConvexHull, hknpCompoundShape, hknpCapsuleShape, hknpCompressedMeshShape and simple primitives.

Survey sizes

The source enumerated 316 SHKT/HKT physics scene files and over 100 native type classes (108 in the reported census). Examples of files containing types:

The class list also contains legacy-named hkpRagdollConstraintData and hkpLimitedHingeConstraintData embedded as constraint schemas. Their presence does not imply that the file's entire physics scene uses an old hkpPhysicsData root.

A particularly useful negative finding: _HAS_HKA in a filename does not guarantee an hkaSkeleton. None of the eleven suffix-matched files in this census had one, while 78 other files did. Only the actual tagfile type graph establishes this.

EDF6 HUD internals: recursive follower bars, multilingual glyph fallback and Spot marks

EDF 6Game technical referencesNative user interface
Technical reference · Source-scoped static analysis with contributor runtime marked; no new R129 game test

The original EDF6 HUD does not draw every on-screen indicator from one central list. Follower durability bars, text glyphs and the contextual Spot/Q marker come from different source objects and update paths.

Follower health bars

HudPlayer_FollowerDurability obtains the HUD's live player owner and walks that player's linked follower list. For each follower it projects the object's position raised 2 meters, skips offscreen entries, draws a frame and fills the bar according to the follower's current and maximum HP. The same draw routine recursively visits each follower's own list. A vehicle that is not in anyone's follower list therefore does not get a vanilla follower-style health bar through this path.

Glyph and font fallback

The examined resource manager loads four original UI TrueType resources, covering Japanese, Korean, traditional Chinese and simplified Chinese. The font-chain order varies with the selected language. For each character, the rasterizer tries fonts until GetGlyphIndicesW indicates a glyph is present, otherwise falling back to the first font. This is why embedded CJK glyphs can appear in interface strings outside the primary UI locale.

This is a font fallback strategy, not a guarantee that every Japanese/Chinese symbol has identical metrics. The source notes distinguish monospaced Latin advances in the Japanese font from proportional Latin advances in the Chinese font variants.

Spot and player-name labels

The player's Spot (Q) action takes its input from a soldier flag and follows a dedicated marker/effect and online-message path. A separate function looks up player names for labels. These should not be treated as a generic text-notice system: Spot identity, follower bars and HUD text all have different owners.

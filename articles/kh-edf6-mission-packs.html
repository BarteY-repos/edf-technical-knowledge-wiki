MissionMgr and the mode list

MissionMgr's mode list: outer array mgr+0x20, count mgr+0x30, current index mgr+0x38

Evidence: static · Build: steam-678ccb46 · Fact ID: mode-list-layout

MissionMgr's mode list: outer array [mgr+0x20], count [mgr+0x30], current index [mgr+0x38]. Each outer entry holds a mode object at +0x10; [mode+8] is a byte offset to the active row, and from there +0x74 is the pack and +0x80 the mode type. DBD00(mgr, type, pack) walks the list comparing both fields and returns the index.

Basis: ModeIdentityForOuterIndex in lobbySafetyV0H.hpp, its comment on DBD00; DBD00 and DC460 disassembled here (the 0x74 and 0x80 compares are in the code)

Addresses (build-specific RVAs unless indicated): DBD00

Attribution: EDF6 Mod Platform HF5.48, novae (ajane) · 2026-11-01

Mission mode record online flag

Evidence: static · Build: steam-678ccb46 · Fact ID: mode-row-online-flag

More of a mode row (values at cfg + [cfg+8], cfg = [mode+0x10]): +0x68 (item 8) is the online flag (read at 8A2379), +0x74 (item 9) the content id, i.e. the pack, +0x80 (item 10) the type; 8C4CE3 walks the modes and 8C4CA0 compares id and type. A pack's online and offline modes carry the same content id, so the offline mode is the one with online 0 and type 0. The object holding the list is the one at [20B2890] (GameDataMgr in globals.md#global-pointers).

Basis: autopilot.cpp's FindRangeMode and comments; with mode-list-layout

Addresses (build-specific RVAs unless indicated): 8A2379, 8C4CE3, 8C4CA0, 20B2890

Attribution: EDF6Autopilot (hajisensai, edf6-all-forces, round 24) · 2026-11-07

DC460 is MissionMgr::SetMode(index): it stores the index at mgr+0x38 and fires its update (DB580 with 0x1C)

Evidence: static · Build: steam-678ccb46 · Fact ID: missionmgr-setmode

DC460 is MissionMgr::SetMode(index): it stores the index at [mgr+0x38] and fires its update (DB580 with 0x1C). Direct callers: AC21A, D6722, DB6BF, and 70FAC9 inside the script-facing bool SetMode(int) wrapper, which checks the slot in [mgr+0x20] at 70FABE.

DA8E0 loads the mode list's config (LoadConfig)

Evidence: static · Build: steam-678ccb46 · Fact ID: loadconfig-sites

DA8E0 loads the mode list's config (LoadConfig); it is called at D66CA on init (rcx=r14, rdx=rsp+0x58) and at DB65B on reload (rcx=rdi, rdx=rsp+0x20). A loader can add its modes right after either call, so no config file needs replacing.

Basis: configless_hooks.S, signatures match

Addresses (build-specific RVAs unless indicated): DA8E0, D66CA, DB65B

Attribution: EDF6 Mod Platform HF5.48 · 2026-11-01

Mission packs are numbered 0-2 for the official set

Evidence: static · Build: steam-678ccb46 · Fact ID: pack-numbers-names

Mission packs are numbered 0-2 for the official set; custom packs use 3-99 in EDF6ML. E3F80(pack) returns the name key only below 3: null, MissionPackName1, MissionPackName2 (strings at 1768368, 1768390); callers 8EC6BE, 9007D2, 958F0E. Pack 3 and up return null, so a custom pack needs its own name path.

Basis: E3F80 disassembled, strings read, callers from a rel32 scan; slot range from native_mission_bundle.hpp

Addresses (build-specific RVAs unless indicated): E3F80, 1768368, 1768390, 8EC6BE, 9007D2, 958F0E

Attribution: EDF6 Mod Platform HF5.48, novae (ajane) · 2026-11-01

A custom pack's DefaultPackage/CONFIG.SGO has a root ModeList of rows

Evidence: static · Build: steam-678ccb46 · Fact ID: modelist-row

A custom pack's DefaultPackage/CONFIG.SGO has a root ModeList of rows; a row name is GameMode_Offline_MissionPackNN or GameMode_Online_MissionPackNN, child 0 is that name and child 9 an integer equal to NN. The platform refuses a row where the two differ.

Basis: native_mission_bundle.hpp (the flat-config reader)

  2. Mode progress fields

Complete original research record — expand (1,410 characters)

GameDataMgr [20B2890] is 0x150A0 bytes (new at 7C0C4A, constructor D62C0); +0x130 the current mode (filled by LoadPackage E2AD0: +0x18 the ModeList node, +0x20 SoldierInit, +0xF0 / +0xF8 the mission list table document, +0x118 the text list SGO). Save blocks: system +0x2E8..+0x310 (0x28, SYSTEM.CFG 60 bytes), common +0x318..+0x57A4 (0x548C, COMMON.CFG 21664), ModeSave +0x57A4..+0x6E68 (0x16C4, one per mode, DEFP_<MST>.MST 5848 bytes, fixed size whatever the mission count), main +0x6E68..+0x14B50 (0xDCE8, MAIN.GST 56572); file size = block + a 0x14-byte header (the files are encrypted). Both save functions pass 0x16C4 (7BC438, 7BD1CD). ModeSave (init DF790, reset DBA00): +0 current mission row (copied to mgr+0x48 by DBCE0), +4 difficulty (mgr+0x4C), +8 clear[10][0x200] (byte per class and row, bit d = cleared on difficulty d, Easy..Inferno), +0x1408 a 0x98-byte block (DFDD0), +0x14A0 seen[0x200] (bits 1 / 2 = before.bvm played), +0x16A0 misc. So each mode holds at most 512 missions, indexed by row with no bound check (DFA40 read, DFAB0 write; DF950 counts over 0x200 x 10); a longer list spills into the next class's row and past +0x16A0. Clearing (ApplyResult part at 70D879): row [mgr+0x48] (70D884, written at 70F103), the player's class [mgr+0x6E90] (70D8C5), below Hardest the lower difficulties are marked too (70D8CC), DFAB0 at 70D8EF. The offline and online scenario modes share M00.MST.

Basis: DFA40 and 7BC438 re-read with fn.py; block-to-file mapping by file sizes ("M"); the rest the author's reading ("H")

Addresses (build-specific RVAs unless indicated): 20B2890, 7C0C4A, D62C0, E2AD0, 7BC438, 7BD1CD, DF790, DBA00, DBCE0, DFDD0, DFA40, DFAB0, DF950, 70D879, 70D884, 70F103, 70D8C5, 70D8CC, 70D8EF

Mission select build (8A1530; a vector of 0x14-byte rows {row, number, state, field 5, byte} at [rsp+0x48], resized by the row count at 8A2155): row 0 state 1, all others 4 (8A2160..8A219D); scanning from row 0, a row cleared by any class on any difficulty (8A4C00 -> DFA40) gets state 0 and unlocks its successors still at 4 to 1 (2 if their field 5 is 1; 8A2209 / 8A2222..8A2262); an uncleared row still at 4 is the stop row (8A2330..8A2344), and an offline mode (+0x68 = 0) stops after it (8A2355..8A237E); finally rows still 4 before the stop become 3 and states 0..3 are listed (8A23C1..8A241A). Clearing advances the current mission when the row has exactly one successor below the count (ProceedNextMission 70F660, row count at 70F6CC). Last mission IsLastMission 70EDA0 = mgr+0x48 == count - 1 (count at 70EDB7); the first clear of the last row sets the all-difficulty unlock mgr+0x300 (system block; 70D901 -> DF990, count at DF9B8; skipped when set, 70D90D). What a mode's progress is keyed by (from All Forces' pack work, 2026-10-18): the content id persists nowhere. A mode's save file is named by its ModeList member 5 (DEFP_<name>), read and written at GS+0x57A4 (7C0C72 -> 7BC310, 7C3542 -> 7BD0A0, 0x16C4 bytes); MAIN.GST (GS+0x6E68..0x14B50) and COMMON.CFG (GS+0x318..0x57A4) hold no mode id; the 36 reads of a mode node's +0x74 (DCA47, 708A02, 70C32D, 70CC47, 74836E, 787922, 78BC48, 78F27C, 8A2114, 8BEB79, 8BEF3D, 8C3D7F, 8C4693 / 8C4CFF (compares 8C46AC / 8C4D1C), 8C4CBC, 8EBFC2, 8ED9D9, 8F649D, 8F651A, 8FD942, 8FE3AC, 900697 / 9006DB / 9007CC / 900906, 9017BF, 904DE0, 913BB2, 9158A3, 916577, 91A64E / 91A6CB, 91DC4E, 925CB4, 92671E, 926A30, compares D841F, 789288, 905F8B) keep it in a register, a local, a UI object or GS+0x14FD0 (runtime, past the saved blocks; read once at 747F2B), and none shifts, bit-tests or indexes by it (78F293 is a vector size's sar, 8C4D10 a mode-pointer index); 78F27C hands it to the stream writer 12B5580, which encodes any int. Ownership is the std::set<int> at mgr+0xE0 (D92B0, weapons.md#has-content-set), the weapon drop filter D81E0 compares a weapon row's column 8 with the mode's id, and the achievements and clear ratio count content 0 only (DC9E0). The row is what the save is keyed by: clear[class][row] (DFA40 / DFAB0), a byte per row at +0x14A0, the current row at +0; the only writer of the row bytes is DFA90 (70DB63, the current row), and nothing clears rows past the list's end. The mode save file: the write job (7BD0A0 -> 7BD910, run by 7C1CB0) writes a 0x14-byte header (MDB0, version 3, length, the checksum 7C1270 over the live block) and then GS+0x57A4 whole (0x16C4 bytes); the read job (7BC310 -> 7BD720, run by 7C1670) accepts only a file of exactly that length with that magic, version and checksum; the load's apply 7BE970 (from the save screen's completion 945680 at 945741) copies the whole block over GS+0x57A4 or nothing on any failure, and DBCE0 then copies the current row and difficulty out; the reset (DF790's template, DBA00, inline in DB580 bit 4) zeroes the block at every SetMode and the mode select's Reset; the file I/O is 7B9990 / 7B8DE0. The script's UnlockDownloadContents (70FF87) runs only after SetMode and a successful LoadSaveData_ModeSelect (MAINSCRIPT.AS lines 363, 852, 1691, 1801, 1851, 1889, 1913), so GS+0x57A4 is then the new mode's save and GS+0x38 that mode; DC550's other entry, the reset's call at DC348 (DB580 bit 8 via DB920 -> DC170), runs inside SetMode (DC4B8) before DC4C5 sets GS+0x38, when the mode is still the old one and the block a blank.

Basis: the author's static reading ("H"; a list made with its disassembler) and its native test, which runs the game's save-cycle code in a private mapping (32 checks; not the file I/O)

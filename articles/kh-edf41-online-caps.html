EDF 4.1 — Online Caps (community source notes)

EDF 4.1Community Knowledge HubNetworking
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Where the caps act

The offline main mode holds no caps: in config.sgo's ModeList, mode 0 (GameMode_Scenario) has integer 0 in ev…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-offline-modes-no-caps

The offline main mode holds no caps: in config.sgo's ModeList, mode 0 (GameMode_Scenario) has integer 0 in every difficulty's value 6 and value 7, which the cap getters D99F0 / D9990 read as no list, no cap (as EDF5's, ../edf5/online-caps.md#edf5-offline-modes-no-caps); its mode value 7 (node +0x5C, the online flag) is 0 as well. The Mission Packs' offline modes have value 7 = 0 too (file-formats.md#edf41-dlc-modelist); their value 6 and 7 lists were not re-read here.

Basis: scratch File_Storage/Logs/catalog/modeprobe2.py edf41 0 (config.sgo read in place)

Addresses (build-specific RVAs unless indicated): D99F0, D9990

The weapon-cap flag is the byte save+0xA7D5 (save object CC84A0

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-cap-flag

The weapon-cap flag is the byte save+0xA7D5 (save object [CC84A0]; EDF5's save+0x24571, ../edf5/online-caps.md#edf5-cap-flag): the online session update 377CD0 sets it to 1 at 37929B when the room's weapon switch [session+0x284] > 0 and the cap D99F0 > 0, with the notice OnlineSys_WeaponCapLock (A195F0), else 0 at 379322 with OnlineSys_WeaponCapUnlock (A19688). The armor switch is [session+0x280], notices OnlineSys_ArmorCapLock (A19658, 37948E) / OnlineSys_ArmorCapUnlock (A19580, 3794BD); the lock notice carries the cap as HP for the player's class, trunc(float(boxes) x per box + base) (379462..379472).

Basis: fn.py --xref of the four notice strings (found by scratch File_Storage/Logs/00v/findstr.py), read of 378F80..379520

Addresses (build-specific RVAs unless indicated): CC84A0, 377CD0, 37929B, 379322, A195F0, A19688, A19658, 37948E, A19580, 3794BD, 379462, 379472, D99F0

Attribution: KH chat 182 (curator, autorun 00v) · 2026-11-14

The flag save+0xA7D5 has six accesses in EDF41.exe's code: the two in 377CD0 (edf41-cap-flag)

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-cap-flag-accesses

The flag save+0xA7D5 has six accesses in EDF41.exe's code: the two in 377CD0 (#edf41-cap-flag); UiOnlineRoom_Main's slot 0 4C0D90 (vtable entry AACE18) sets it from the room's weapon-cap attribute read by 388390 (4C115A, flag = attribute != 0); a clear at 4C062A (function not read); readers 389454 (in 389440, #edf41-member-overcap-marks) and 43A088 (in 43A040, #edf41-weaponselect-cap-marks). No offline code sets it (inferred from its writers), so every cap test below answers "no cap" offline.

Basis: fn.py --grep "0xa7d5\b" over 1000..7A0000; class by scratch File_Storage/Logs/catalog/vt_name.py

Addresses (build-specific RVAs unless indicated): 4C0D90, AACE18, 388390, 4C115A, 4C062A, 389454, 389440, 43A088, 43A040

A room member's over-cap marks: 389440(weapon id) returns 1 when the flag save+0xA7D5 is set, the id is = 0,…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-member-overcap-marks

A room member's over-cap marks: 389440(weapon id) returns 1 when the flag save+0xA7D5 is set, the id is >= 0, and the weapon's level trunc(row +0x38 x 0.25 (AB6524) x 100 (AB6884)) in the weapon table [save+0x150] (12-byte rows) is above the cap from DCB90 (3894EE cmp ecx, eax, 3894F0 jbe, unsigned, so -1 never marks). Its only caller 389510 (from 388610, twice) builds a member record from the room keys st (+0x28), dr (+0x2C), w0..w3 (+0x30..+0x3C) and vc (+0x44), and stores the marks of the 4 weapons at +0x40..+0x43 (389860..389876); EDF5 marks 6 (../edf5/online-caps.md#edf5-member-overcap-marks).

Basis: fn.py reads of 389440, 3897B7..389900; key strings from the pointers at A184D0.. (rd.py bytes, fn.py --str)

Addresses (build-specific RVAs unless indicated): 389440, AB6524, AB6884, DCB90, 3894EE, 3894F0, 389510, 388610, 389860, 389876

The weapon select UiHQEquipment_SelectWeapon (vtable AAABD8) has no installed predicate as EDF5's does: its s…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weaponselect-cap-marks

The weapon select UiHQEquipment_SelectWeapon (vtable AAABD8) has no installed predicate as EDF5's does: its slot 0 43A1B0 (the per-frame update) calls 43A040 (43A1F3), which returns unless the current mode node's value 7 is nonzero (43A072 cmp d[rax+r8+0x5C], 0, setne al, test al, al, je 43A19E; bytes 42 83 7C 00 5C 00 0F 95 C0 84 C0 0F 84), then for every cell (0x40 bytes, in groups of 0x20 bytes at screen +0x1928, count +0x1938) sets byte +0x3C = flag set (43A088) and level above the cap (43A13B..43A179, the same test as 389440). So the marks are recomputed every frame, online only.

Basis: fn.py reads of 43A040, 43A1B0; --xref 43A040, --xref 43A1B0; vtable by vt_name.py / vt_dump.py; bytes by rd.py

Addresses (build-specific RVAs unless indicated): AAABD8, 43A1B0, 43A040, 43A1F3, 43A072, 43A19E, 43A088, 43A13B, 43A179

What a mark does in 4.1's weapon select: the draw slot 1 43A5D0 draws a marked cell's text (the weapon's stri…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weaponselect-cap-refusal

What a mark does in 4.1's weapon select: the draw slot 1 43A5D0 draws a marked cell's text (the weapon's string from the screen's text_table, its name by inference) red, RGBA (1, 0, 0, 1) from AB7770, else white (AB7F00) (43A92A..43A93C, 43A9EA cmp b[rcx+rdi+0x3C], 0, cmove). Unlike EDF5 (../edf5/online-caps.md#edf5-weaponselect-cap-colors) a marked weapon cannot be picked: on confirm (input bit 0x40, 43A347) 43A35B cmp b[r9+0x3C], r15b (r15 = 0), jne 43A40D (bytes 45 38 79 3C 0F 85 A8 00 00 00) skips the pick silently. An accepted pick writes the weapon id to save+0x261C + 4 x (0x407 k + 4 class + slot) (43A39A; k [screen+0x18C0], slot [screen+0x1944]), sends message 4 through 56E740 and plays the cue 決定.

Basis: fn.py reads of 43A5D0..43AB40, 43A300..43A480; colors by scratch File_Storage/Logs/00v/flt.py; bytes by rd.py

Addresses (build-specific RVAs unless indicated): 43A5D0, AB7770, AB7F00, 43A92A, 43A93C, 43A9EA, 43A347, 43A35B, 43A40D, 43A39A, 56E740

The online armor cap is applied on the host's start message 390BF0: the cap comes from D9990 when save+0x23B4…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-online-armor-cut

The online armor cap is applied on the host's start message 390BF0: the cap comes from D9990 when [save+0x23B4] > 0 and the session's call +0x18 is true (390D0D..390D3D), else -1; the message carries mission [save+0x40], difficulty [save+0x44] and, for each of [save+0xA800] players k, a record with the class (+4, from [save+0x2618 + 0x101C k]), that class's 4 weapons and the armor boxes (+0xA8, from [save+0x26BC + 0x101C k + 4 class], 391212). The record writer 36A200 (39153A; also called from 390220 at 3909EC, not read) sends min(cap, boxes) when cap >= 0 (36A293..36A2AE, cmovge; bytes from 36A293 85 FF 78 1F 41 8B 86 A8 00 00 00).

Basis: fn.py --xref D9990, reads of 390C90..390E40, 391150..391260, 36A200; --xref 36A200

Addresses (build-specific RVAs unless indicated): 390BF0, D9990, 390D0D, 390D3D, 391212, 36A200, 39153A, 390220, 3909EC, 36A293, 36A2AE

Two spawn paths set a player soldier's armor: 14FE30 (from 150610 and 150B70) tests the mode node's value 7 (…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-spawn-armor-paths

Two spawn paths set a player soldier's armor: 14FE30 (from 150610 and 150B70) tests the mode node's value 7 (14FEB6 cmp d[rdx+rax+0x5C], edi with edi = 0, 14FEBA je 15000A; bytes 39 7C 02 5C 0F 84 4A 01 00 00); online it calls 2B9560 (14FF2F; its log text CreateOnlinePlayerObject(%ls)(%d) ::, A01AD0), which reads the class [save+0x6764 + 0x101C slot] and the received, capped boxes [save+0x6808 + 0x101C slot] (2B95DB; slot = the player's +0xF8); offline it calls 2B9260 (150010), which reads the save's own boxes at 2B9357 with no cap (file-formats.md#edf41-soldierinit-armor-applied). Both set HP = float(boxes) x per box + base (2B976B..2B9783, 2B939C..2B93B4). That +0x6764 holds the received record from its +4 (0x6808 - 0x6764 = 0xA8 - 4) is inferred; the receiver was not read.

Basis: fn.py reads of 14FE30, 2B9560, 2B9320..2B93C0; --xref 2B9560, --xref 2B9260, --xref 14FE30

The save byte save+0x25E1 is 4.1's counterpart of EDF6's room-switch lock GS+0x6E58 (../edf6/online-caps.mded…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-cap-switch-lock

The save byte save+0x25E1 is 4.1's counterpart of EDF6's room-switch lock GS+0x6E58 (../edf6/online-caps.md#edf6-cap-flag-accesses): the mission-script native void CheckUnlockArmorWeaponLimit() (34AB50, registered in 345270 at 346430) acts only online (mode value 7, 34ABA9); when +0x25E1 is set and the AllClearRatio record (from the save's +0x6650, CFA90) has +0x44 >= 0.7 (AB65C4, 34ACC8..34ACD4), it clears the byte (34ACE1) and shows Sys_UnlockArmorWeaponLimit (A0C560). Other accesses: a clear at BE587, readers 4AA6E2 and 4CB9AB (room screens, not read: that they lock the room's cap switches as in EDF6 is inferred). So the lock is lifted by 70% of the online missions cleared (unverified reading of the ratio).

Basis: fn.py --xref of A0BF10 / A0C560, read of 34AB50, --grep "0x25e1\b" over the code; float by flt.py

Addresses (build-specific RVAs unless indicated): 34AB50, 345270, 346430, 34ABA9, CFA90, AB65C4, 34ACC8, 34ACD4, 34ACE1, A0C560, BE587, 4AA6E2, 4CB9AB

Offline: route to caps (00v topic 2)

Route for online-style caps offline in EDF 4.1: (a) data: copy the online mode's per-difficulty value 6 and 7…

Evidence: unverified · Build: steam-57aab039 · Fact ID: edf41-offline-caps-route

Route for online-style caps offline in EDF 4.1: (a) data: copy the online mode's per-difficulty value 6 and 7 lists (file-formats.md#edf41-online-caps) into offline mode 0 (and the packs' offline modes) of config.sgo (#edf41-offline-modes-no-caps), so D99F0 / D9990 return caps offline; never the mode value 7, which also switches the spawn path (14FEBA) and the online natives; (b) marks and red text: 43A040 must run offline, so skip its gate (43A07D je, 6 bytes) and make it see the flag (set save+0xA7D5 offline, or patch 43A088 to load 1); the refusal of marked picks then follows from stock code (43A35B); (c) armor: clamp the count read at 2B9357 (offline spawn 2B9260) to D9990(save) when >= 0, as 36A2A8..36A2AE does online (a hook). Nothing here was run in game.

Basis: inferred from the lines above

Addresses (build-specific RVAs unless indicated): D99F0, D9990, 14FEBA, 43A07D, 43A088, 43A35B, 2B9357, 2B9260, 36A2A8, 36A2AE

Attribution: KH chat 182 (curator, autorun 00v), novae (ajane) · 2026-11-14

Evidence: unverified · Build: steam-57aab039 · Fact ID: edf41-offline-caps-open

Open questions of #edf41-offline-caps-route: weapons already equipped over the cap at departure (the start message copies the 4 weapon ids with no level test seen, 3911BF..3911FB; not followed further), the Mission Packs' offline value 6 and 7, the receiver of the start record and the other caller 390220, [save+0x23B4], the function around 4C062A, the room screens reading +0x25E1, and whether the flag set offline upsets later online play.

EDF5 NPC route explorers, mission wait factors and 60-second stuck watchdog

EDF 5Game technical referencesNavigation / AI
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5 keeps an AiRouteExplorerBase shared pointer in the game object. The per-frame update lets the explorer supply a next point, destination validity and speed; completion clears the explorer pointer. The AI can also receive a separate facing-order target and direction timer.

Mission script conditions test this state through three different native event factors:

Script condition Studied field meaning
EventFactor_AiMoveEnd (9300) Route explorer has been released/completed
EventFactor_AiMoveEndOrDie (9301) Completion or qualifying death
EventFactor_AiFollow (9310) A leader link exists

The same research maps the EDF5 native SetAiRoute to 3101. These distinctions matter when a mission waits on a squad: a follower can have a leader without a specific route having reached its final node.

When an AI stops making progress

A watchdog records the last best distance to the current waypoint. When a soldier fails to get 2 m closer for approximately 3600 frames (60 seconds), while the route point has not moved over 1 m and several safety/ownership conditions are satisfied, it invokes native position-related helpers using that waypoint. The source infers that the result is teleporting or repositioning the soldier, based on corresponding EDF6 logic; the physical effect was not verified in an EDF5 runtime trace.

This is not a generic claim that EDF5 NPCs never get stuck. Pathfinding routes, collision against map geometry, follower formation and the watchdog are separate mechanisms, and a single 60-second rule cannot repair an incompatible navigation mesh.

Source: edf5/soldier-ai.md, edf5-ai-route-fields, edf5-route-watchdog (static; watchdog effect inferred).

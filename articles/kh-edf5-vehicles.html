This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

VehicleBase

The VehicleBase constructor 352B70 (sole writer of the VehicleBase vtable EB5B18, at 352BB6

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehiclebase-ctor-keys

The VehicleBase constructor 352B70 (sole writer of the VehicleBase vtable EB5B18, at 352BB6; secondary vtable EB5C90) reads the SGO keys animation_model (E9ED98), ragdoll (E9EE08), vehicle_riding_position (EB57C0), vehicle_weapon_setting (EB57F0) and vehicle_damage_effect (EB5910); a missing weapon node logs VehicleBase::VehicleBase( weapon node not found. %ls) (EB58A0). Seats: one call of the seat builder 3535B0 per vehicle_riding_position entry (loop 352ED0..352EEF), which appends a 0x340-byte seat (35396C, the same size as EDF6's) to the vector at +0x410 (data +0x418, capacity +0x420, count +0x428; 353943..353980); then the seat count goes to +0x430 and the all-seats mask (1 << count) - 1 to +0x434 (352EF1..352F0A), and 3539D0's float result to +0xC40. The weapon list is reserved to the entry count of vehicle_weapon_setting in the vector at +0x440 (capacity +0x450, 352F9E..352FC1). EDF6 keeps the same layout 0x1F0 bytes later (seats +0x600, count +0x620; edf6/vehicles.md#seat-class-masks).

Basis: fn.py reads of 352B70 and 3535B0, strings by fn.py --str

Addresses (build-specific RVAs unless indicated): 352B70, EB5B18, 352BB6, EB5C90, E9ED98, E9EE08, EB57C0, EB57F0, EB5910, EB58A0, 3535B0, 352ED0, 352EEF, 35396C, 353943, 353980, 352EF1, 352F0A, 3539D0, 352F9E, 352FC1

The VehicleBase vtable EB5B18 has 46 slots (0..45

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-vtable-slots

The VehicleBase vtable EB5B18 has 46 slots (0..45; slot 46 holds the next table's RTTI pointer), so EDF5's slot numbers are not EDF6's (edf6/vehicles.md#vehicle-vtables-slot55). Slots read: 2 the update (354000, #edf5-vehicle-update), 39 SetUp(setup list) (base 354810, #edf5-vehicle-setup-hp; every class overrides it, e.g. 502 3474F0, 503 34B5B0, 506 34E570, 409 369830), 40 FireWeapon(index) 337500 (common to all classes: sets weapon +0xD9 = 1 when the entry's weapon is alive), 41 the per-shot reaction (base 353AF0, overridden by 402, 403 and others), 47 controls and firing (402 337FF0, which first calls TankBase's 388C80; slot 47 sits in the subclass tables). 402's slot 47 fires weapon 0 when the driver seat's +0x2E4 reaches the constant at EE63C4 and copies seat +0x2D0 (negated) and +0x2D4 to +0x2590 / +0x2594: the seat's stick block.

Basis: vtables read side by side (scratch File_Storage/Logs/catalog/rvaval.py vt), slots read with fn.py

Addresses (build-specific RVAs unless indicated): EB5B18, 354000, 354810, 3474F0, 34B5B0, 34E570, 369830, 337500, 353AF0, 337FF0, 388C80, EE63C4

SetUp's base 354810 sets HP and the weapon damage factor from the setup list: max and current HP (+0x1F8, +0x…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-setup-hp

SetUp's base 354810 sets HP and the weapon damage factor from the setup list: max and current HP (+0x1F8, +0x1FC) = durability +0x1F0 x setup[0][0] x a, and +0x488 = setup[0][1] x b. When the object's flags byte +0x32 has bit 3, a = f / 10 x ModeList[mode][6][difficulty][5][0] and b = f / 10 x [5][1] (f the level factor +0x2FC of combat.md#hp-formula-modelist; [5] = [vehicle HP, vehicle damage]: 1.0 / 1.0 in every offline mode; online Easy 1.8 / 1.8, Normal 2.0 / 1.5, Hard 2.0 / 1.5, Hardest 1.75 / 1.5, Inferno 1.5 / 1.5 (main online; the packs' online modes match, Hardest and Inferno alike)); otherwise a = b = +0x48C (1.0 from the constructor, 352CDE). The damage factor goes to every weapon (SetWeaponObject's fourth argument, #edf5-vehicle-setweaponobject). Which vehicles carry bit 3 was not read.

Basis: fn.py read of 354810; ModeList values from Root.cpk (scratch modelist_hp.py)

Addresses (build-specific RVAs unless indicated): 354810, 352CDE

A call-in's setup list is its weapon SGO's Ammo_CustomParameter43: 4 = transport SGO, container SGO, vehicle…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-callin-setup

A call-in's setup list is its weapon SGO's Ammo_CustomParameter[4][3]: [4] = [transport SGO, container SGO, vehicle SGO, setup] (e.g. Free Bike 1: v508_transport, v509_transportbox, v503_bike, setup [[2.2, 1.1], [handling ...], [20000.0, 1.666], [[gun_l, ['BodyRecoil', [0, 0]]], [gun_r, ...], [v_fuel01]]]). The placing call-in path 182740 reads the bullet's parameter block [bullet+0x3A8], creates the vehicle through the factory 6138E0, puts it on team 5 (+0x218 and +0x21C = 5, +0x280 bit 6, 1828FE..182912) and calls SetUp (slot 39, 182932) with [4][3]. setup[0] is [HP factor, damage factor] in every class; where the weapon list sits differs by class (bikes [3], the Depth Crawler [2], three entries of [weapon SGO, recoil]). A second spawner, 322C10 (a vtable entry at EB1F30), takes a mode argument: with 0 it stores its factor in +0x48C (322D80); with 1 it runs the level factor 2DBCC0, sets the vehicle's team to 2 (argument + 1) and seats an NPC driver created there (322D02..322D75).

Basis: fn.py reads; call-in data from Root.cpk (scratch callin_params.py)

Addresses (build-specific RVAs unless indicated): 182740, 6138E0, 1828FE, 182912, 182932, 322C10, EB1F30, 322D80, 322D02, 322D75, 2DBCC0

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-vehicle-update

The update 354000 also sets the vehicle's team from its riders: while HP +0x1FC > 0 and flags +0x32 bit 3 is clear, it walks the seats (+0x418, 0x340 each), takes each live rider's team (seat+0x260, team +0x218; default 5) and calls 2DBE20(vehicle, team, 1) (35426F); then it clears the seat change bits, +0x438 &= +0x434 (354274), as EDF6 does at +0x628 (edf6/vehicles.md#vehicle-seat-change-bits).

Basis: fn.py read of 354000

Addresses (build-specific RVAs unless indicated): 354000, 2DBE20, 35426F, 354274

CarBase gear table (EDF6's vehicle-gear-table, fields 0x3D0 lower): the CarBase constructor 375E30 calls 37FA…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-carbase-gear-table

CarBase gear table (EDF6's #vehicle-gear-table, fields 0x3D0 lower): the CarBase constructor 375E30 calls 37FAB0 (3760E9), which loads car_base_engine_gear (EB8138, 37FB40) or else car_base_engine_simple_gear (EB8100, 37FCA0) into a vector of 16-byte rows {speed, upshift, downshift, force} at +0x1388 (data +0x1390, count +0x13A0), the reverse row +0x13B8, a neutral row +0x13A8 (the reverse speed, 0, 0, 1.0) and +0x1380 = 1.1, +0x1384 = [2][0]. The full form reads each SGO row as [speed, force, downshift ratio, upshift ratio] (37FBEA..37FC11: [1] to +0xC, [3] to +4, [2] to +8); the simple form makes one row from [0][0] speed and [0][1] force with ratios 1.0 and 0.025 (37FD4C..37FD67), reverse = -speed. 37FD90(speed factor, force factor) scales speeds and turns the ratios into speeds; the SetUps of BikeBase 372DB0, Car 374220 and TankBase 388820 call it with setup[1][1] and setup[1][2]. Current gear +0x1714 (-1 reverse, -2 neutral); gear choice slot 50 (CarBase 37FE40, TankBase 3897A0), drive target slot 52 (380060, TankBase 389930).

Basis: fn.py reads; vtables side by side (scratch rvaval.py vt)

Addresses (build-specific RVAs unless indicated): 375E30, 37FAB0, 3760E9, EB8138, 37FB40, EB8100, 37FCA0, 37FBEA, 37FC11, 37FD4C, 37FD67, 37FD90, 372DB0, 374220, 388820, 37FE40, 3897A0, 380060, 389930

EDF5 gear data (Root.cpk object SGOs, scratch veh5_keys.py): car_base_engine_gear in the bikes (v503_bike, _o…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-gear-data

EDF5 gear data (Root.cpk object SGOs, scratch veh5_keys.py): car_base_engine_gear in the bikes (v503_bike, _omegaz) and the Car class (vehicle401_striker, v512_keitruck(_bgp), v513_trailertruck01cab); every tank-like class (402, 403, 404, 505, 507, 510) has the simple form [[1.0, 1.0], [0.03]]. Row speeds are fractions of the top row's 1.0, so a vehicle's top speed is its setup[1][1]: the call-ins' handling lists give e.g. Blacker E1 10, Blacker E4 21, B651 Titan 6 to 16, the railguns (Epsilon, Menace) 10 to 16, EMC 10, Naegling XEM 20, Caliban 25, Free Bike 1 30 to Type-Z 60, Grape RZ 80. Striker rows: speed 0.1827 to 1.0 over six gears, [1] 1.0 falling to 0.039 (force, highest in first gear), [2] 0.125 then 0.5, [3] 0.75 then 1.0 in top gear (shift up at 75% of a gear's speed). The EDF6 line's SGO order ([speed, up, down, force]) does not match this reading; EDF6's loader was not re-read.

Basis: Root.cpk read with scratch veh5_keys.py and callin_speed.py; meanings from 37FB40 and 37FD90

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-boarding-checks

Who may ride (EDF6's #boarding-checks and #seat-class-masks, same tests): GameObject init 2D9A10 reads game_object_vehicle_mask (EACAE0, 2D9E47) into +0x220 (0 when absent, 2D9F72..2D9F90; EDF6 +0x31C). CanRideSeat 355BE0(vehicle, human, seat): when the teams (+0x218) differ and the vehicle's team is not 5, bit 7 of seat+0x34 & seat+0x30 is needed (355BF7..355C01); then human+0x220 & seat+0x34 & seat+0x30 must be non-zero (355C0A..355C14), the seat's rider control +0x268 empty or dead, and the human (position +0xA0) within the riding point's radius + 0.5 (EE633C) of the point built from the MAB record seat+0x1E0 and the bone matrix seat+0x1E8. CanRide 355D00(vehicle, human) runs the same tests over every seat (+0x418, count +0x428); its one caller is 2EF990 (inferred: the boarding prompt's visitor, EDF6 5725A0). FindSeat is vtable slot 42 (356000: the first seat CanRideSeat passes, then 355E70; EDF6 slot 49), overridden by Car 374DB0 and 507 Caliban 34F880; 356060 is a variant that skips seats whose entry in a caller's int list is negative.

Boarding by the ride button (EDF6 boarding-checks and its seat-change line, same steps, soldier fields 0x3E0…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-ride-button-path

Boarding by the ride button (EDF6 #boarding-checks and its seat-change line, same steps, soldier fields 0x3E0 lower): the per-player update 3091B3 calls 2EFA00(human) when the ride byte +0xB58 is set (309266; EDF6 +0xD78, 56D700). It returns when the ride link +0x1170 is live, +0xD8 bit 0 (a remote copy), +0x420 bit 2 or +0x29C != 0; otherwise it walks team 5 (32C5F0) and then the human's own team (32CB90) with the visitor vtable EAECA0, whose slot 1 2EFB00 casts each object to VehicleBase and asks FindSeat (slot 42, call [r8+0x150] at 2EFB64), then sets +0x1160 = the seat, the weak vehicle pointer at +0x1168 / +0x1170 (2EFBAC), +0x11F0 = 0, +0x11F8 = 0, +0x11FC = 1.0. After a ride 2EFA00 sends the ride event (2F3620), starts an action on +0xD90 (2E1C10) and sets +0x2B0 = 1 when the seat's +0x2B4 is 3. The prompt's test is a second visitor (vtable EAE888, slot 1 2EF990, CanRide 355D00) run by 2EF870 from the human update 2EBD30 (inferred).

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-seat-sounds

Boarding and leaving sounds (EDF6 #vehicle-seat-change-bits, same scheme): 355630(vehicle, board preset, leave preset) walks the seats (+0x428) and, for each seat i whose change bit (1 << i) << +0x430 is set in +0x438 (355695..3556A8), plays the board preset when the seat is occupied (9DE60) and the leave preset otherwise, at the seat's riding point (3AF840 from seat+0x1E0; play 47D950). With flags +0x32 bit 3 set it skips seat 0 and every seat whose +0x30 lacks bit 7 (355665..355693). Callers: CarBase's update (slot 2, 376F60, vtable entry EB85C8, called by the subclasses' updates) with presets at [+0x1618]+0x200 / +0x240 (entries 8 and 9 of car_base_se_table, EB8380, if a preset is 0x40 bytes as EDF6's [8] / [9] suggest); slot 38 of VehicleBegaruta (360770, presets [+0x1680]+0x2A0 / +0x310) and of the helicopters 506, 409 and 410 (36F560, [+0x1400]+0x3F0 / +0x460; heli_se_table EB71A8). The change bits are cleared by the base update at 35427B (#edf5-vehicle-update) and set by the seat scan (353F8E..353FC1) and seat changes (355FA0, 3562AF).

Localization ownership and lossless locale-native merging

UniversalAudioEDF 5EDF 6
Source-backed research / case study · Mixed runtime + static locale-safe authority

EDF6 has at least two distinct localization ownership surfaces that must not be merged conceptually or physically.

Global menu/UI text

Global menu and UI localization lives in:

ETC/TEXTTABLE_STEAM.<locale>.TXT_SGO

Mission voice/caption lookup

Mission captions and voice playback-key lookup live in:

MISSION/EDF6_VOICETABLE.<locale>.SGO

A fix for one surface does not automatically repair the other.

Locale-native baseline rule

The correct production model is:

  1. start from the target-native table for that locale;
  2. preserve it losslessly;
  3. add only provider-owned compatibility rows;
  4. fail closed on conflicting claims;
  5. never copy one language wholesale into another locale.

Historical provider material violated this boundary: some EN/JA/KR/CN global tables were byte-identical English data and SC was absent. That is not a lawful localization strategy.

In particular:

  • do not synthesize Simplified Chinese by copying CN or EN;
  • do not use an EN VOICETABLE donor as the baseline for JA/SC/KR;
  • do not treat historical CS aliases as proof that CN and SC are interchangeable.

Patch 1.0.6 locale-safe compatibility additions

The 1.0.6 line carries lossless compatibility work across the retained BASE/EN/JA/CN/SC/KR VOICETABLE set. Important cue families include:

AL001B*

Used by M023/M052. The retained solution uses a lossless locale-native donor alias. Static preservation is qualified; exact locale runtime smoke remained pending.

AM035D*

Used by M017_5/M074. The EN path had direct runtime-positive evidence (Yes, sir!); broader locale coverage was statically qualified and still needed locale-specific smoke where not already tested.

AL009B*

Used by M054_5/M057/M078. The compatibility row is based on a native EDF6 donor (BE001_308) per locale, not an invented English stage direction. Static donor proof exists; final runtime remained pending in the 1.0.6 ledger.

AB001B*

M060 remains unresolved because no authoritative caption donor/equivalent has been established. Do not fabricate one merely to suppress an unknown-key message.

Simplified Chinese boundary

The vanilla game tree proves ETC/TEXTTABLE_STEAM.SC.TXT_SGO exists. If an authoritative retained SC payload is unavailable, the safe action is to obtain the user's own vanilla SC baseline and perform an additions-only merge. Copying CN or EN into SC would destroy locale authority.

Caption lookup vs presentation timing

Locale-safe VOICETABLE content is still separate from long-caption scroll timing. The standalone Subtitle Scroll Fix operates on presentation windows; it does not authorize rewriting locale tables or inventing missing keys.

Evidence discipline

A caption can be:

  • semantically identified;
  • losslessly inserted into every target locale;
  • statically byte-preserved;

and still lack a runtime result for one particular locale/build. Preserve those distinctions instead of declaring global localization PASS from an EN-only test.

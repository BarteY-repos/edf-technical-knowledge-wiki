EDF5 ground vegetation: FMEX/SHF cell grids, TRB trees and MLB props

EDF 5Game technical referencesVegetation and environment
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R132 test

Trees, grass and certain small props on an EDF5 map need not have one ordinary MAPB record per plant. The ground controllers read cell grids, identify plant type and jitter records, then create individual scenery objects at positions derived from the ground. FMEX and SHF ground use different grid layouts and height computations.

FMEX grid

In the studied MapObject_Fmex path, one plant group has an 0x88-byte description. It includes cell size, column/row counts, X/Z origin, a jitter-index grid and a type grid; 0xFF in the type grid is empty. Type records are 0xC8 bytes; a separate jitter record is 16 bytes (rotation, two planar offsets and size). The visitor combines cell index, jitter, size and ground elevation with the ground transform.

Visitor implementations treat kind 0 as grass and kind 1 as generated objects. This is not a promise that all FMEX resource kinds are understood, only what the recorded dispatcher actually branches on.

SHF heightfield grid

MapObject_Shf visits a different grow block with a compact two-byte cell (type and jitter index), 0x28-byte type records, and a jitter table. It does not pass jitter size into its tree visitor. Its Y-coordinate is obtained by casting downward from 505 units over 800 units at the chosen X/Z; the ray results and the type record's vertical offset decide the placement altitude. FMEX instead uses the ground cell's stored height.

What .trb and .mlb do

Resource Generated owner Main behavior
.trb MapObject_Tree Weighted tree/stump model, deterministic yaw, optional collision capsule
.mlb MapObject_AnyObject Weighted small model, rotation/offset/color/scale attributes from rules

Tree selection uses a 64-bit LCG (state = state × 0x5D588B656C078965 + 0x269EC3), seeded by the placement or cell-derived index. A reload of the same seed can therefore reconstruct the same model choice and orientation. Its yaw and model choice are randomized; the inspected tree visitor does not use jitter size to scale the tree. Small .mlb objects have a scale branch, but the source's examples left that scale at 1.

The source also distinguishes grown MapObject_Tree from map-level MapObject_Trees. These are not interchangeable names or the same damage handler; the independent tree-damage study is here.

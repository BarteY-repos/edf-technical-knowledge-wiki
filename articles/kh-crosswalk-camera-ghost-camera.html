Player camera (CharacterGhostCamera) and the vehicle ride camera (key: CharacterGhostCamera)

  • edf5: Update copies the target position and look block into the camera, then calls a follow or ride mode object that writes the final matrix | ref: edf5/camera.md#camera-update-target-and-look-block, edf5/camera.md#camera-mode-state-machine, edf5/camera.md#camera-final-matrix | evidence: static (some camera lines in that file are verified in game; see each line)
  • edf6: same design: Update F86A0, follow FAF20, ride FB9F0, final matrix at camera+0x220..0x250 | ref: edf6/camera.md#ghost-camera-update-fields, edf6/camera.md#ghost-camera-follow-ride-modes, edf6/camera.md#ghost-camera-final-matrix | evidence: static (compared instruction by instruction with EDF5, not run)
  • Differences noticed: camera offsets are EDF5's + 0x80 for the final matrix but different elsewhere (look block +0x2F0..+0x350 vs +0x3B0..+0x450, mode object +0xAE0 vs +0xB58, state slot +0xAE8 vs +0xBF0); soldier ride-link offsets are EDF5's + 0x3E0 but the class layout grew. EDF6's ride mode reads the seat record, not the look block (edf6/camera.md#ghost-camera-ride-seat-camera): check this before assuming an EDF5 camera-distance hook reaches vehicles.
  • Confidence in the mapping: high (mechanism and order of operations), low (offsets: look each one up in the game's own file)
  • Added: 2026-10-26 src: novae (ajane)

Online weapon and armor cap tables

  2. Cap thresholds

Complete original research record — expand (1,226 characters)

The online weapon-level and armor caps are data: each mode of the ModeList holds in member 7 one row per difficulty; element 6 is the weapon cap and element 7 the armor cap, and each machine computes them from its own local config (not sent by the host). Weapon: D8850(GS = [20B2890]) takes the difficulty [GS+0x4C] and the progress D7B60 (= mission index GS+0x48 / (mission count - 1), 0 for a single mission) and tail-jumps (D887B) to E2710(GS+0x130, difficulty, progress), which reads the current mode node [cfg+0x18] (= GS+0x148), member 7 (+0x54), the difficulty's row, element 6 (+0x48); not a list (E274E..E2752) or a negative value (E27C2) gives -1 (no cap, E2800), else it interpolates by progress and multiplies by 0.25 x 100 into a level. Armor: D8130 -> E06B0 (element 7, +0x54). CONFIG.SGO: offline modes have integer 0 (no cap); online scenario: Easy / Normal [0.1, 1.1], Hard [0.2, 2.1], Hardest [1.4, 3.1], Inferno [2.4, 3.2, 4.0, 4.0] (armor [358, 2322] .. [8572, 22500]); online mission pack 2 Inferno [-1.0, -1.0] (vanilla's "no cap"), armor [20000, 25000]. GS+0x148 is &ModeList[current] (written at E2C09); content id = [[GS+0x148] + [[GS+0x148]+8] + 0x74], which the script's GetContentID (70E5D0) reads.

Basis: the author's reading of E2710 instruction by instruction and of CONFIG.SGO; D8130 agrees with combat.md#armor-limit

Addresses (build-specific RVAs unless indicated): D8850, 20B2890, D7B60, D887B, E2710, E274E, E2752, E27C2, E2800, D8130, E06B0, E2C09, 70E5D0

Online equipment cap enforcement

Evidence: static · Build: steam-678ccb46 · Fact ID: online-level-cap-enforcement

This source note combines several technical details. Its evidence grade, game build and contributor credit above still apply to the entire record. Follow these topics, then expand the complete original text for offsets, exceptions and caveats.

  1. GameStatus restriction flag
  2. Restriction decision path
  3. Weapon or armor consumers
Complete original research record — expand (1,401 characters)

Where the caps act: the flag GS+0x14FC8 (byte) is set each frame by 7865A0 (Application 705530 -> 788460) when the room's weapon limit switch [session+0x1678] > 0 and the cap > 0 (786A4E), with notices OnlineSys_WeaponCapLock / OnlineSys_WeaponCapUnlock; room switches weapon GS+0x14C4C = [session+0x1678], armor GS+0x14C50 = [session+0x1674] (guests receive them at 7893F4 / 789466). Room creation 8FBBC0 forces both switches on when GS+0x6E58 != 0, and the room settings screen (91D465) lets them change only when it is 0; the script's UnlockArmorWeaponLimit (70FF30) writes GS+0x6E58 = 0 online when it was set, so GS+0x6E58 locks the switch, it is not the cap. The weapon select screen HUiHQWeaponSelect (constructor 8B4280) installs the predicate 8BC850 only online (8B43D3..8B43F6): flag set and level > D8850(GS) (8BC873 cmp edi,eax; jbe, unsigned, so -1 never limits); the same comparison in 95B1E0 (HUiHQCurrentStatus, called by 8ACD20), 74568D in 744AB0 (room members' over-cap marks on their 6 weapons) and 747380. At departure weapons are not lowered (773840 writes the 6 weapons as they are, 7738F6..773912); armor is cut on the sender (773871: min with the cap when the cap >= 0, the cap from D8130 at 78EA9C..78EAC0); the receiver 790600 reads the cap from the record header at 7907F5 and drops it. The room info shows "no limit" (Room_Weapon_Level_NoLimit) for a negative cap (957ED0).

Basis: 8BC86A..8BC875 re-read with fn.py; the rest the author's reading (marked verified by their static checks; how screen items call the predicate is their inference); mod-loading.md#missionmgr-active-pack names a neighboring +0x14FD0

Addresses (build-specific RVAs unless indicated): 7865A0, 705530, 788460, 786A4E, 7893F4, 789466, 8FBBC0, 91D465, 70FF30, 8B4280, 8BC850, 8B43D3, 8B43F6, 8BC873, 95B1E0, 8ACD20, 74568D, 744AB0, 747380, 773840, 7738F6, 773912, 773871, 78EA9C, 78EAC0, 790600, 7907F5, 957ED0

Online cap arithmetic shared with EDF5

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-online-caps-code

EDF6 applies the online caps with EDF5's float32 steps (../edf5/file-formats.md#modelist-online-caps-code): E2710 (weapon) and E06B0 (armor) take the difficulty's value 6 / 7 (not a list: -1), clamp t to 0..1 (1C36994 = 1.0), x = float32(knots - 1) x t, i = floor(x) (12DA8EE); past the last segment the last knot, else -1 if either knot of the segment is below 0, else a + (x - i) x (b - a). Weapon: trunc(v x 0.25 (1765A14) x 100 (1765A68)), the shown cap level; armor knots are ints, the result trunc(boxes). One difference: the weapon's last-knot path has no sign test, so knots [-1, -1] at t = 1 give -25 instead of -1, still negative, so no cap (#online-level-cap-enforcement).

Basis: fn.py read of both functions; constants read from EDF.dll

Addresses (build-specific RVAs unless indicated): E2710, E06B0, 1C36994, 12DA8EE, 1765A14, 1765A68

Attribution: KH chat 133 (curator) · 2026-11-12

SoldierInit armor growth per class

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-armor-per-box

Armor per class is CONFIG.SGO SoldierInit[class][3] = [base, per armor box], as in EDF5 (../edf5/player.md#armor-hp-per-box): Ranger 200 / 0.56, Wing Diver 150 / 0.35, Air Raider 200 / 0.56, Fencer 250 / 0.595 (EDF5: 0.64, 0.4, 0.64, 0.8). DE250(GS, player, boxes) returns float32(boxes) x E34A0 (per box) + E3470 (base), the pair netcode.md#net-armor-count names; the JP wiki's online armor caps follow from these with truncation (358 boxes: Ranger 400, Wing Diver 275, Fencer 463 at online M1 Easy).

Basis: config.sgo read from Root.cpk; fn.py read of DE250; the wiki caps as the check (#edf6-online-caps-check)

Addresses (build-specific RVAs unless indicated): DE250, E34A0, E3470

Yellow weapon-select level does not mean online cap

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-yellow-level-drop-window

The weapon select's yellow level text works in every mode, offline too, and is not the online cap: the constructor calls D7C40(GS, rbp+0x628) at 8B4D25 with no mode test. D7C40 takes [low, high, spread] from ModeList field 7, the difficulty's row, value 2 (the drop level; E26C0 returns element 2's first three floats) and t = D7B60 (story progress), and writes +0 low, +4 high, +0xC = low + (high - low) x t, +8 = that minus spread, at least 0. A cell is yellow (8B5116 seta; color #ui-weaponselect-colors) when the weapon's WEAPONTABLE level (D8A90 out +0, rbp+0x100, weapons.md#weapon-info-record) is above +0xC plus 0.05 (1765A04): above the top of this mission's drop window.

Basis: fn.py reads of D7C40, E26C0 and the constructor 8B4280 (8B4D17..8B4D47, 8B50FF..8B5116)

Addresses (build-specific RVAs unless indicated): 8B4D25, D7C40, E26C0, D7B60, 8B5116, D8A90, 1765A04

Difficulty drop-window values and spread

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-yellow-vs-online-cap

Drop-window value 2 [low, high, spread] by difficulty, Easy to Inferno, the same offline and online: main [0, 0.95, 0.2], [0, 1, 0.2], [0.1, 2, 0.25], [1.3, 3, 0.3], [2, 4, 1]; Mission Pack 1 [1.05, 1.3, 0.2] twice, [2.05, 2.3, 0.25], [3.05, 3.3, 0.3], [4, 4.5, 1]. In shown levels (x 25, ../edf5/file-formats.md#modelist-drop-level-values) yellow starts above 25 x (low + (high - low) x t + 0.05). The main campaign's online weapon cap (#edf6-online-caps-knots) sits 0.75 to 1.25 levels above that on Easy to Hard (Hard: above 3.75 at the start, cap 5; above 51.25 at the end, cap 52), on Hardest 33.75 vs 35 at the start and 76.25 vs 77 at the end, at Inferno's start 51.25 vs 60; at Inferno's end yellow starts above 101.25, the cap is 99. So offline, a weapon an online room would allow can show yellow.

Basis: config.sgo values from scratch File_Storage/Logs/catalog/modelist6.txt (KH chat 98); arithmetic by the curator, not compared in game; fits novae (ajane)'s impression (2026-11-14) that numbers sometimes turn yellow below the online limits

Red weapon-select level indicates online cap

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-red-level-online-predicate

The weapon select's red level text is the online cap: the predicate 8BC850 (#online-level-cap-enforcement) is a std::function at screen +0x770, so [screen+0x7A8] (its impl pointer, +0x770 + 0x38) is what ui-weapon-select.md#ui-weaponselect-cell-bits-content's bit 0 calls (8BC450..8BC476); that line's unknown setter is the install at 8B43F8..8B4444 (8B74B0). It is installed only when the current mode's ModeList field 8 ([node+0x68], the online flag) is nonzero (8B43F2 / 8B43F6 je 8B4447). The predicate gets the cell's int at +0x2C (the shown level; [rdi-0x44], rdi = cell + 0x70). PressButton refuses only cell+0x54 & 6 (8BD75D..8BD765 test al,6; jne 8BDA66), so an over-cap weapon (bit 0) stays selectable. Class Select colors a slot row's level red (1F77730) when 95B1E0(row+0x44) is true (8AD1F7..8AD213, in 8ACD20).

Basis: fn.py reads of 8BC850, 8BC440, 8BD6F0, 8AD1E0..8AD240 and the constructor dump

Addresses (build-specific RVAs unless indicated): 8BC850, 8BC450, 8BC476, 8B43F8, 8B4444, 8B74B0, 8B43F2, 8B43F6, 8BD75D, 8BD765, 8BDA66, 95B1E0, 8AD1F7, 8AD213, 8ACD20, 1F77730

Online cap enabled flag read and write sites

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-cap-flag-accesses

Every code access to the cap flag GS+0x14FC8 (byte): written at 786A62 / 786A80 (the online session update 7865A0) and 9016FF (a room screen, from 747420's result), cleared at 8F2747; read at 74564B, 74739E, 8BC863, 95B1F3. Room switches: GS+0x14C4C written at 78941E, 8FBBD3; GS+0x14C50 written at 789494, 8FBBC9, read at 78EA9C, and moved as 16 bytes at 70CCBC, 78BCBE, 904BF8, 917DE7, 91DD4A, 92460A, 925AC5, 9266E0. No offline code sets the flag (inferred from its writers), so 95B1E0 and 8BC850 return false offline even with a cap. D8850 and D8130 have no online test of their own: they read the current mode's row, so caps written into an offline mode's value 6 / 7 (now integer 0, read as -1) would be returned offline.

Basis: fn.py --grep over EDF.dll's code for the three offsets; the functions around 8F2747 and 9016FF not read

Armor offline: the Adjust Armor screen ui::HUiHQArmorLimit (vtable 18005C8, factory vtable 1800560

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-adjust-armor-screen

Local-player spawn record assembly

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-offline-armor-spawn

The local player's spawn record is built by 595C80: +0 player, +8 class (GS+0x6E90 + p x 0x3E60), +0x10 the armor count (595CD9..595CE1), +0xC from D8700; player creation 5A3F90 takes +0x10 at 5A40BD and sets max HP +0x2F4 from DE250 (5A40CB / 5A40D0). KittopiaCreator's OfflineArmourLimit (combat.md#armor-limit) hooks 5A40CB and the status text at 88482F; after D8130 it clamps with minss xmm8, xmm1 and in the menu with cmp ecx, eax, both comparing the HP with the cap's box count (E06B0 returns the boxes in eax and leaves them as a float in xmm1, E0744..E074D, E0786..E07A5), not with the HP those boxes give: with a cap of 358 boxes a Ranger would get 358 HP instead of 400. With stock data the offline cap is -1 and the patch does nothing.

Basis: fn.py reads of 595C80, 5A3F90, E06B0; the patch text in File_Storage/Reference/OutsidePatches/edf6_research_2026-10-28/ (Patches/OfflineArmourLimit.txt)

Addresses (build-specific RVAs unless indicated): 595C80, 595CD9, 595CE1, D8700, 5A3F90, 5A40BD, 5A40CB, 5A40D0, 88482F, D8130, E06B0, E0744, E074D, E0786, E07A5

Proposed offline implementation of online-style capsSource: unverified

Evidence: unverified · Build: steam-678ccb46 · Fact ID: edf6-offline-caps-route

Route for online-style caps in the offline menus (00v topic 2): (a) data: give the offline modes' value 6 and 7 the online lists (config.sgo), so D8850 / D8130 return caps offline (#edf6-cap-flag-accesses); (b) set GS+0x14FC8 to 1 offline (a patch), so 95B1E0 (Class Select's red level) and 8BC850 answer; (c) install the predicate offline by skipping the je at 8B43F6 (red level text in the weapon select); (d) to refuse over-cap picks, widen PressButton's mask at 8BD763 from 6 to 7; (e) armor: clamp the spawn record's +0x10 to D8130 in 595C80 (the offline local player), or clamp boxes before DE250 in OfflineArmourLimit's place; the Adjust Armor screen needs its own clamp to show it. Without (a) to (e), the yellow text (#edf6-yellow-level-drop-window) is the only offline hint. Open: weapons already equipped over the cap (departure checks no level, #online-level-cap-enforcement), what 8F2747 and 9016FF belong to, the armor byte, and whether the flag set offline upsets later online play. Nothing here was run in game.

Basis: inferred from the lines above

Addresses (build-specific RVAs unless indicated): 8B43F6, 8BD763, 595C80, D8850, D8130, 95B1E0, 8BC850

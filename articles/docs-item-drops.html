Item Drops

EDF 6DocumentationGameplay & AI
Technical reference · Community-provided Japanese memo; source-specific and not independently rerun

At a glance

What this page covers: The contributor's drop experiment separates the threshold that triggers a pickup from the weights used to choose the pickup category.

How to use it: Lowering the tested DropRate threshold makes pickups more frequent in that setup, but it does not itself establish the balance of item types or a universal drop probability.

Evidence boundary: The numbers describe a community memory-patch experiment, not independently verified rules for every enemy, difficulty or game version.

EDF6 item drops have at least two separable parameters in the contributor's memory-patch experiment: how frequently a drop is emitted and how an emitted pickup is distributed among item types.

Threshold and weights

The note describes each defeated enemy contributing points; once accumulated points exceed a DropRate threshold, a pickup is emitted. Smaller thresholds yield more pickups. Setting the threshold to zero or extremely small values is explicitly discouraged in the original note.

A second array controls the relative category weights:

Category Source default Example edit
Weapon 6 22
Armor 15 21
Small healing 14 14
Large healing 3 3
Total weights 38 60

The workbook's example changes threshold from 0.947 to 0.600.

For a simplified expected-value approximation matching the sheet:

[\operatorname{share}(i)=\frac{w_i}{\sum_j w_j}, \qquad \operatorname{drops\ per\ 100\ points}\approx\frac{100}{T}.]

Category count per 100 points is then 100/T × share(i). The sheet reports 105.60 total drops per 100 points at default threshold and 166.67 for the example edit. Weapons rise from ~16.67 to ~61.11 per 100 points. These are spreadsheet rates; actual random outcomes and point quantization may differ.

Implementation boundary

The workbook notes two approaches:

  • Memory patch: changes a threshold and category-weight table globally, in the tested game build.
  • Resource replacement: changing all relevant per-enemy resource settings may require a much larger asset edit.

The sample AOB/memory patch is version-sensitive and is not presented here as a universal signature. Validate against the exact executable before using any offsets or byte patterns.

Scope and evidence

Source アイテムドロップレート!B1:S31 contains the Japanese explanation, default and example weights, formulas and one patch example (attributed in that sheet to redone). The statistical model and editable values are reproduced from the sheet; native implementation beyond that experiment remains unverified here.

EDF6 walk controller: 60 Hz support queries, velocity channels and character ownership

EDF 6Game technical referencesCharacter motion
Technical reference · Build-scoped static analysis; original contributor evidence grades cited; no new R126 gameplay runtime

In the examined EDF6 build, walking actors use xgs::havok::CharacterControl_Walk. It is separate from Havok's general rigid-body solver and from the CharacterControl_Cling used by crawling insects and some robots. Understanding the distinction explains why a generic knockback impulse does not necessarily reproduce player movement or wall-clinging movement.

Support detection and ground-state representation

Walk_CheckSupport invokes Havok's character rigid body checkSupport, which fills an hknpCharacterSurfaceInfo. The record contains:

Relative offset Native field Interpretation
+0x00 isSurfaceDynamic Contact/support classification
+0x01 supportedState 0 unsupported, 1 sliding, 2 supported
+0x10 surfaceNormal World-space normal
+0x20 surfaceVelocity Reported surface linear velocity
+0x30 surfaceAngularVelocity Reported angular velocity

The source identifies a 1/60-second support-check step. The walk-controller path uses its own cached support state and motion channels; it does not simply hand the final position to a physics body and wait for the solver.

Final velocity has several sources

The Walk_Step path combines the internally maintained velocity channel (+0x30), projected movement input (+0x20), a step-scoped external contribution (+0x60) and the additional +0x1C0 channel, then publishes the result to the character body. The source also distinguishes a measured airborne velocity from the launch/accumulation velocity — these fields must not be interchanged.

The support state controls whether a character is grounded, sliding or falling; the airborne path updates gravity-related motion. This system is used by playable soldier classes and the NPC/civilian human controllers, though their higher-level input and animation behaviors differ.

Scope and limitations

The values are not an API promise for another EDF build. Source paths were traced from CharacterControl_Walk and original Havok callbacks; they are static disassembly, not a new motion test. The separate article Moving platforms explains why a valid support velocity is not necessarily incorporated into soldier movement.

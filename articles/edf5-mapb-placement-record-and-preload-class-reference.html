EDF5 MAPB: 0x44-byte placements, transform construction and preload classes

ConversionGame technical referencesMaps / formatsEDF 5EDF 6
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R132 test

A map's visible objects are not simply stored as complete models at their world positions. EDF5's map.mapb associates placement records with object definitions; the loader constructs a world matrix, chooses an object class by the definition's resource extension, and hands the resulting parameters to that class. EDF6 uses a closely related format, but not the same placement record size.

The placement record

The studied EDF5 loader walks the entries with 0x44 bytes per record. The corresponding EDF6 record is 0x48 bytes. For a record at address r the source identified:

Offset from r EDF5 meaning
+0x00 Relative offset to the object definition
+0x04, +0x08, +0x0C Translation X, Y, Z as 32-bit floats
+0x10, +0x14, +0x18 Euler rotation X, Y, Z in degrees

The native function converts degrees to radians, applies the X, then Y, then Z rotations, and builds a matrix with the translation and homogeneous W=1. It does not read a per-record scale in this path. That does not mean no object in EDF5 can have scale: generated foliage and MDB model internals use other sources of scale and pose data.

An object definition includes a type (+0x00), a self-relative parameter SGO pointer (+0x04), a name (+0x0C) and other display/damage fields. The parameter SGO is checked against SGO and version 0x102. The corresponding MAPO record, when present, is at base mapo+0x08 + placement_index*0x1C.

Which native class loads which resource?

File-name ending EDF5 preload owner What makes it special
.mosb Preload_Structure Composite building or structure, often with individual parts
.fmep Preload_Fmex Ground/field scene and its associated FMB and grass resources
.mdx Preload_AnimationModel or Preload_Model HAS_ANIMATION in parameter SGO selects the animated branch
.shfb Preload_Shf Heightfield terrain, with .cols.sgo and .norm.sgo
.trb, .mlb Not spawned by this ordinary dispatcher Generated through the grow-object visitors of the ground/heightfield

The original notes also identify a build-specific global that can skip certain definition categories; the exact conditions were recovered statically. They should not be interpreted as universal EDF5 authoring rules without the same executable.

How the constructed matrix travels

Preload_Base::InitParam receives the object's world matrix alongside the parent loader, embedded parameter SGO, record, definition, MAPO entry and original placement index. This establishes why resource-name identity, placement index, world transform and model part data are different pieces of the map format.

Evidence: static reading of EDF5 Steam build steam-5d11de53 (C3650 and its preload dispatch). The researcher explicitly did not independently compare every decoded byte to an untouched raw map.mapb; these offsets are engine-read semantics rather than a complete published binary grammar.

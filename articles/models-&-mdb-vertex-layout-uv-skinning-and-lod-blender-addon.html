EDF6 MDB vertex formats: UV identity, rigid skinning, BC1 foliage and LOD

UniversalModels & MDBModelsEDF 5EDF 6
Source-backed research / case study · Reconciled

This reference summarizes measured MDB and texture data, not a particular model import/export plugin's implementation.

Vertex declarations and mesh strides

Native EDF6 profiles in the examined map-model corpus include 60-, 68- and 76-byte mesh strides with one, two or three UV streams. Visually static objects can still carry rigid BLENDWEIGHT and BLENDINDICES lanes. Removing those streams changes the vertex declaration and stride; do not infer from visual stillness that the game data lacks skin attributes.

The physical declaration order and repeated TEXCOORD occurrence can differ between native files. This is evidence of multiple valid source profiles; there is no general proof that every semantically equivalent alternative declaration ordering is a runtime error. The EDF5→EDF6 paired conversion shows that normal/tangent/UV discontinuities can require splitting vertices while preserving the triangle index count.

Observed mesh serialization boundaries

  • MDB mesh indices are 16-bit. Any index greater than 0xFFFF cannot be represented in that field without restructuring the mesh.
  • In sampled native EDF6 multi-mesh MDBs, the start of each mesh vertex buffer was aligned to a 16-byte boundary. This is an observed native convention, not a demonstrated universal loader-crash condition for unaligned samples.
  • Blend indices in the studied profiles used the uint8 ×4 format. It should not be widened or narrowed solely because an asset happens to be stationary.
  • Full polygon-corner identity matters when vertices differ in UVs, normal, tangent or binormal sign. The target game does not recover those discontinuities from an averaged source control point.

Native foliage BC1 cutout example

The sk_pShrub003-df.dds sample used by a Common_Clip material was DXT1/BC1 with 1-bit transparency at the top mip level. In the retained audit all 32,768 top-mip blocks had color0 ≤ color1, selecting BC1 transparent mode; 427,079 top-mip pixels had palette index 3 (transparent). This is positive evidence for BC1 transparent foliage in EDF6, not a rule that every EDF cutout texture uses this pattern.

LOD materials are not one universal shader family

Some explicit _lod.mdb companions retained the same base shader family as their higher-resolution models. Other native assets used snd_BRDF_Map_LOD, snd_BRDF_Map_LOD_CC, snd_Map_LOD_CC or FarMap families. The presence of a _lod filename therefore does not establish a specific material ABI. Consult native LOD cases and profile matrix.

Evidence boundary

The corpus proves these sampled structural patterns. A separate exact-build game test would be needed to determine whether every observed alignment, order or rigid skin field is an absolute runtime acceptance requirement.

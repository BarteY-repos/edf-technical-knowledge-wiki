EDF5 BVM stack: source-void calls, cvtstore and execution order

UniversalMissions & ScriptingMissionsEDF 5EDF 6
Source-backed research / case study · Source BVM, matched API and byte-exact mission parity; runtime qualification separate

Evidence: source BVM/AngelScript exact-pair analysis of the inspected EDF5 shipping mission corpus, reconciled with the native API inventory. These rules concern how the game's VM executes and orders operations. A correct-looking AngelScript call is not sufficient if it changes when a side effect occurs.

Side-effect-only group calls do not leave a result on the VM stack

Source custom calls 2002, 2003, 2004, 2005, 2006, 2007, 2008, 2009, 2010, 2020, 2021 and 2022 form a source-void group-transaction family in the audited BVM source set. Across 145 source missions, none was immediately followed by a result-consuming store, storeabs, storerel, cvtstore or pop for that operation. The native source stack contract is thus statement/side effect, even if a corresponding target AngelScript factory might return an object.

902 CreateMob_Path is another statement-like effect. Delaying it past a subsequent team-encounter notification changes the mission's event order. Historical exact-pair failures included a missing second UFO group in M020, a lost GOLDUFO group in M080, and reordered CreateMob_Path/SendTeamEncount in M008.

This is a source-VM execution distinction, not a general rule that target API calls never return objects.

cvtstore: stored lvalue remains available

The recovered VM semantics of cvtstore retain the stored lvalue on the operand stack. An expression with side effects must be evaluated once, not recomputed when the returned/stored value is used later. The same rule must be observed when interpreting compiler-generated switch/dispatch lowering, not only ordinary straight-line BVM.

In the 141-mission source-only parity audit, an earlier flawed translation produced 43 duplicate calls of the DM012 op2001 family because of this value-flow mistake. Correcting cvtstore removed those duplicates. This is an exact historical source-vs-output mismatch; it is not evidence that the original EDF5 game performs the actions twice.

Source transaction conservation

The full reconciled audit counted 3,471 source spawn-related transactions and zero source-order failures after the final source-value-flow corrections. The six source/target literal differences at DM006_2 were from deliberate object-SGO specialization for custom call 3450, not extra enemy spawns or an alternate order. Later game testing rejected that specialization and accepted a narrower mission-specific 3450 omission; it must not be promoted as a generally correct runtime implementation of search-radius semantics.

For the exact R44 source reconstruction, 141/141 MISSION.AC outputs matched the historical reference bytes, with 722/722 CreateEnemy2 occurrences. These are offline exact-parity findings. The entire gameplay campaign was not freshly runtime-qualified by that result.

Provenance markers versus source semantics

When an output contains compound helper code, a comment such as EDF5_CUSCALL:bank:id can help an auditor distinguish direct 3152 SetAiFollow from the distinct compound 1013 follower transaction. The comment is a research provenance mechanism, not itself a feature of EDF5's native script format.

See BVM bytecode and custom calls, decoded call reference and event registration for the associated VM and runtime contracts.

Native backward switches and direct Voice call (consolidated)

The BVM compiler may place switch-case bodies before their dispatch ladder. A ladder can use pushtop, case comparison and jmpne followed by a backward jump to the selected body. The runtime stack must be reconstructed from control-flow predecessors, not physically preceding bytes. M015, M059, M065 provide original source examples where a linear interpretation can select the wrong difficulty branch.

In the inspected source corpus, direct one-argument cuscall0 4000 is Voice(string), not generic PlaySe. M015_2 has five direct AE... voice calls, with corresponding official Voice operations. Wrapped radio helpers need separate context. The event-order example in M008 is two friendly squads → three 902 CreateMob_Path operations → encounter notification; moving the path operations changes source semantics. Evidence: EDF5 edf5/mission-vm.md, bvm-switch-form, cuscall-4000-voice, bvm-902-void, bvm-source-void-group-ops (source static).

EDF5 mission vehicles: parked boardable objects versus AI-controlled variants

EDF 5Game technical referencesVehicles / missions
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5 scripts can spawn empty, boardable vehicles with special *_mission or *_fw SGOs. These are distinct from a separately configured *_ai vehicle driven by an NPC. The static inventory was cross-checked against Japanese mission tables marking vehicles 搭乗可能 (“boardable”).

Mission SGO Model or role Mission placement from source
v505_tank_mission Blacker tank Offline 80 (three), 81 (one)
v504_begaruta_mission Gray Nix (“blue” in community table) Offline 80 (two), 92
v504_begaruta_g_mission Standard/green Nix Offline 81
v504_begaruta_fw Yellow Nix with Combat Burners Offline 96, 105
v513_trailertruck01cab Tractor head Offline 92, 96
v512_keitruck Small/light truck Present in source mission catalogue
v515_retrobalam_mission Barga Mission-prop-like in offline 81; boardable later in 82

A coarse catalogue called v505_tank_mission a “Scripted Maser Tank”; its model and mounted weapon identity show Blacker. Some raw rows marked _mission vehicles “AI Controlled” simply because their class is shared with AI forms. The SGO setup and placement determine the role, not the class name.

The original contributor separately reported a verified gameplay constraint: NPCs do not share a vehicle with a player as driver or passenger. This is an observation for ordinary game play, not a claim that modified code could never implement it.

Sources: edf5/object-classes.md, facts edf5-mission-vehicles-boardable (static mission/wiki pairing), edf5-npc-vehicle-variants (static) and edf5-npc-vehicles-not-shared (contributor-verified).

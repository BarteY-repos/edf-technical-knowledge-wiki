EDF5 MAPO: parts, structure LOD and `_gr` rubble resource pairs

EDF 5Game technical referencesMaps / formats
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R132 test

map.mapo accompanies MAPB placements. In the studied EDF5 corpus each MAPO entry is 0x1C bytes, and a part list uses self-relative pointers, distinct from the MAPB object's own placement transform. This matters for destructible buildings and compound pieces: a single placed .mosb can contain many model components with their own transforms.

Record fields and measured corpus

MAPO offset Observed role
+0x00 FMEP-specific piece pair
+0x04/+0x08 Pointer to and number of parts
+0x0C Distance-like float, often 1000 on .mosb and 0 on .mdx
+0x10/+0x14 Model/collision name pair; often names ending _gr
+0x18 Optional second part list, seen on some building entries

The source counted 69,931 entries across 24 map MACs; 16,771 entries contained model/collision names at +0x10/+0x14, consistently paired _gr names such as sk_bd1020_gr01.mdb / .hkt. The name suggests gareki, Japanese for rubble, but the exact native reader of these name fields was not located. Do not equate their presence with a proven break-to-rubble game event.

In the sample, ordinary .mdx entries commonly had one part. .mosb entries ranged from one to 127 parts. One class of category-1 structure used the second +0x18 list for additional parts. These observations apply to the inspected files, not every EDF5 stage or possible DLC.

Structure parts and local transforms

A part record contains offsets to a quaternion, a position, an optional vec4 (default 1,1,1,1), and the MDB model name. Preload_Structure reads these values and constructs part transforms under the placed structure's world matrix. LOD model-name/distance pairs and the definition's draw distance further control visibility. The structure's Havok shapes are likewise assembled at part-local pose and combined into one fixed rigid body, rather than all being at the base placement origin.

This distinction prevents three common mistakes: using a model's local origin as its world collision position, mistaking _gr paths for proof of runtime debris behavior, and assuming that 127 parts require 127 independent top-level MAPB placements.

Source and scope: edf5/map-placement.md, edf5-mapo-entry and edf5-mapo-parts, static EDF5 build analysis. This is structural RE, not a fresh collision or destruction test.

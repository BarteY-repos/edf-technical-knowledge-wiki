Mission script custom calls (key: BVM cuscall number -> AngelScript function)

  • edf5: missions are MISSION.BVM bytecode; natives are called by number through the interpreter 114F38 | ref: edf5/mission-flow.md, edf5/mission-vm.md | evidence: static
  • edf6: missions are AngelScript MISSION.AC; event model and the fields behind some calls | ref: edf6/missions.md | evidence: static
  • edf41: EDF 4.1 missions use the same old VM family (the EDF5 game tree the source examined holds an EDF 4.1 subtree of 126 MISSION.BVM files; the EDF41-to-EDF6 project mapped some EDF 4.1 missions, with one unresolved cuscall0 901 family) | ref: edf41/missions.md | evidence: static
  • Differences noticed: the scheduler policy flag maps exactly (multi == 1 -> EVENT_TYPE_ASYNC, else SYNC); end-event delay 100.0 -> 100000000.00; object fields move between games (3450: EDF5 +0x2E0 -> EDF6 +0x470; 3150: EDF5 +0x3C4 -> EDF6 +0x56C); 3450 has no known EDF6 script binding.
  • Confidence in the mapping: high for the table below (checked against EDF6's 44 official ports of EDF5 missions and both binaries), except where a row says otherwise.
  • Added: 2026-10-15 src: EDF5-to-EDF6 mission transpiler R37 handoff (2026-08-26), in the drop shared by Bartey

Also in the sources, outside the table

  • 3300 -> object.GetPartsObject(part, group) and 3301 -> GetPartsObjectCount(object, flags) (edf6/archive/engine-abi.md, "Parts-object script interface"; the native messages are edf6/objects.md#object-messages, 0x10000017 / 0x10000018).
  • 3024 -> SetEncountReportRadius (EDF5 field +0x2E4); 3450 -> no EDF6 binding found (edf5/mission-vm.md#cuscall-3450-edf5).
  • The source names several compound helpers in the official ports: CreateMonster(...) = CreateEnemy + SetAiRoute + SetAiMoveSpeed; CREATE_TANK(...) = CreateFriend(v505_tank_ai) + vehicle attack setup + route + straight mode; CreateSergentSquad[_OMG...] = leader + follower group; MoveEndAndDeleteSquad(obj); CreateBaram(...) = transporter + parts-object setup.

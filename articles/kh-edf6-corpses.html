EDF 6 — Corpses (community source notes)

EDF 6Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

The manager

The class RagdollManager (vtable 17E7F78, slot 0 = destructor 6EECC0) has one global instance pointer at 20B3…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-manager-global

The class RagdollManager (vtable 17E7F78, slot 0 = destructor 6EECC0) has one global instance pointer at 20B30E0 (null until the game creates it). The per-frame Application update (vtable 17E91A8, slot 1 = 705530) calls the manager's update 6EF0E0 at 7059FF after mov rcx,[20B30E0]; test rcx,rcx; je (7059F3).

Basis: RTTI of both vtables; disassembly of the call site; both plugins read or hook these

Addresses (build-specific RVAs unless indicated): 20B30E0, 17E7F78, 6EECC0, 17E91A8, 705530, 7059F3, 7059FF, 6EF0E0

Attribution: EDF6CorpseCleanup and EDF6GeneratorBodyBudget (decoded by the hub) · 2026-10-22

Manager layout: +0x08 list sentinel of an MSVC-style circular doubly linked list (node +0 next, +8 previous),…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-manager-layout

Manager layout: +0x08 list sentinel of an MSVC-style circular doubly linked list (node +0 next, +8 previous), +0x10 node count, +0x18 a u32 of flags (bit 0: see ragdoll-generator-gate). A node is 0x30 bytes: +0x10 the corpse's parts object, +0x18 / +0x20 the entity's shared pointer (object pointer, control block: use count at control block +8, weak count at +0xC), +0x28 the node's cost.

Basis: disassembly of Register (node allocation and insert at 6EEE61-6EEEF6), of the cost sum 6EF090 and of the update 6EF0E0

Addresses (build-specific RVAs unless indicated): 6EED10, 6EF090, 6EF0E0

Attribution: EDF6CorpseCleanup (walks manager+8, node +0x10, +0x18, +0x20), EDF6GeneratorBodyBudget (flags at +0x18), novae (ajane) · 2026-10-22

Register 6EED10 (rcx = manager, r8 = pointer to the entity's {pointer, control block}, the parts object as a…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-register

Register 6EED10 (rcx = manager, r8 = pointer to the entity's {pointer, control block}, the parts object as a stack argument; 13 direct callers, among them 339BE0, 345570, 3C2380, 3D88B0, 3E4EC0, 40EBF0, 423530, 432A00, 43C2C0, 479640, 4E2CD0, 531BF0) appends a node at the tail, sets the node's cost from [parts+0x88], then evicts: while the total cost (6EF090 = sum of every node's +0x28) is at least the budget and more than one node exists, it takes the oldest node, calls 118A1B0(entity) and unlinks it.

Basis: disassembly; EDF6GeneratorBodyBudget hooks this function

Addresses (build-specific RVAs unless indicated): 6EED10, 6EF090, 118A1B0

Attribution: EDF6GeneratorBodyBudget, EDF6CorpseCleanup, novae (ajane) · 2026-10-22

The budget is 0x100 (256) when 20B2890+0x40 is 1 or 2, else 0x200 (512)

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-budget

The budget is 0x100 (256) when [[20B2890]+0x40] is 1 or 2, else 0x200 (512). The constant is an imm32 in four places: 6EEF0D and 6EEF15 (inside Register) and 6EF0C0, 6EF0CA (the getter 6EF0B0, which returns it). 20B2890 is g_pGameDataMgr (globals.md#global-pointers); what field +0x40 is (a graphics or quality setting?) is not known. CorpseCleanup's RagdollBudget writes these four imm32s.

Basis: decoded mov rcx,[20B2890]; mov edx,[rcx+0x40]; sub edx,1; je ...; mov r14d,0x200; ...; mov r14d,0x100; CorpseCleanup writes those four offsets

Addresses (build-specific RVAs unless indicated): 6EEF0D, 6EEF15, 6EF0C0, 6EF0CA, 6EF0B0, 20B2890

Attribution: EDF6CorpseCleanup, novae (ajane) · 2026-10-22

The cost of a node is the parts object's +0x88, which the plugin also reads as the number of body entries (so…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-body-array

The cost of a node is the parts object's +0x88, which the plugin also reads as the number of body entries (so the budget counts the physics bodies of live corpses): the parts object holds at +0x78 a pointer to an array of entries 0xC0 bytes apart, the first pointer at array +0x50, each pointing to a game body object whose +0xF0 is the Havok body id (FFFFFFFF = none). CorpseCleanup accepts 1 to 0x200 entries.

Basis: the plugin's walker reads [parts+0x88] as the count and [[parts+0x78]+0x50 + n*0xC0] -> +0xF0; Register copies [parts+0x88] into the node cost; not seen in game

Addresses (build-specific RVAs unless indicated): 6EED10

Attribution: EDF6CorpseCleanup, novae (ajane) · 2026-10-22

The update 6EF0E0 only cleans the list: it walks every node and, for those whose control block is null or has…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-update

The update 6EF0E0 only cleans the list: it walks every node and, for those whose control block is null or has use count [ctrl+8] = 0 (the entity is gone), unlinks the node, drops the weak reference and frees it. It never destroys a live corpse, so a corpse stays until its own timer ends or the budget evicts it.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 6EF0E0

Attribution: novae (ajane) · 2026-10-22

118A1B0(entity) is the generic "destroy this game object" function (282 direct call sites): it returns at onc…

Evidence: static · Build: steam-678ccb46 · Fact ID: object-destroy

118A1B0(entity) is the generic "destroy this game object" function (282 direct call sites): it returns at once if bit 4 of [obj+0x18] is set, calls virtual +0x40, clears byte +0x1A, sets bit 4 of [obj+0x18] and uses the object's own shared pointer at +0x28 / +0x30 (an enable_shared_from_this-style self reference, also read by SwarmPerf). Register uses it to evict; CorpseCleanup calls it when a corpse's age passes CorpseSeconds.

Basis: disassembly of the first 0x100 bytes; three plugins verify its prologue

Addresses (build-specific RVAs unless indicated): 118A1B0

Attribution: EDF6CorpseCleanup, EDF6GeneratorBodyBudget, novae (ajane) · 2026-10-22

A ragdoll component's body records (array r+0x78, count u64 r+0x88, 0xC0 each): +0x50 the xgs::havok::Body (a…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-component-records

A ragdoll component's body records (array [r+0x78], count u64 [r+0x88], 0xC0 each): +0x50 the xgs::havok::Body* (a shared_ptr's pointer; havok-runtime.md#havok-body-wrapper), +0x68 the body's mass, +0x9C mode, +0xA0 previous mode, +0xA4 enabled, +0xB0 / +0xB8 an attached object whose +0x10 is a second Body* (the id lookup compares it too). Lookups: 6EA430(r, bodyId) returns the record index (fingerprint 4c 8b 41 78 45 33 c9 48 8b 81 88 00 00 00 4c 8d; objects.md calls it the is-part check), 6EA670(r, L"RagDollProxys.<name>") by name (the prefix is required). Modes, applied by 6ED480: 0 removed from the world; 1 removed, then 6EC230; 2 and 3 keyframed (SetMotionType 1) and added; 4 dynamic (SetMotionType 2), SetMass(+0x68), constraints on. A living character's or vehicle's ragdoll is keyframed; activation 6E40B0 turns every record to mode 4. Whole-ragdoll velocity: 6ECF20(r, const float4* v) (world lock DAC5B0, 11B18F0 on every body in the world, unlock DB04B0) and 6E6110(r, dv) (adds dv to each body's current velocity); their first 16 bytes are equal (fingerprints ... 41 56 48 83 ec 20 4c 8b f1 48 8b ea 48 8b 89 c0 00 and ... 41 56 48 83 ec 30 48 8b e9 4c 8b f2 48 8b 89 c0 00). The ragdoll's bounding box: 6E9F90(r, float out[8]) (min / max or center / half size, inferred). Agrees with #ragdoll-body-array and damage-model.md#hit-points-bodies.

Basis: the author's static reading ("H"; 6E9F90 "M"); All Forces' gravity gun moves corpses and wrecks with 6ECF20

Addresses (build-specific RVAs unless indicated): 6EA430, 6EA670, 6ED480, 6EC230, 6E40B0, 6ECF20, DAC5B0, 11B18F0, DB04B0, 6E6110, 6E9F90

Generator corpses

Register skips an entity whose obj+0x380 has bit 0x08000000 set (after a runtime-type cast of the entity poin…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-generator-gate

Register skips an entity whose [obj+0x380] has bit 0x08000000 set (after a runtime-type cast of the entity pointer: the call at 6EED8E goes to 12DA7AA, the __RTDynamicCast of combat.md#object-target-fields; the target class is not read) unless bit 0 of the manager's flags ([manager+0x18]) is set (6EEDBD, 6EEDC9). So by default corpses of that kind of enemy never enter the list, are not counted against the budget and are not touched by the update. The setter 1BAA20 (dl = on or off; it ignores rcx and uses [20B30E0]) sets or clears that bit 0. The plugins call the object bit "spawned by teleport anchors or generators" (the README says the game sets the manager bit only in a couple of missions; which, the hub does not know).

Basis: disassembly; 1BAA20 bytes 4c 8b 05 .. 41 8b 48 18 8b c1 83 e0 fe 83 c9 01 84 d2 0f 44 c8 41 89 48 18 c3

Addresses (build-specific RVAs unless indicated): 6EED79, 6EEDBD, 6EEDC9, 1BAA20

Attribution: EDF6GeneratorBodyBudget and EDF6CorpseCleanup (AcceptGeneratorCorpses), novae (ajane), unverified · 2026-10-22

Corpse hitboxes (collision filter)

Three Havok collision-filter vtables share slot 6 (+0x30) as a function (this, edx, r8, r9): hknpGroupCollisi…

Evidence: static · Build: steam-678ccb46 · Fact ID: collision-filter-slot6

Three Havok collision-filter vtables share slot 6 (+0x30) as a function (this, edx, r8, r9): hknpGroupCollisionFilter (vtable 18BBFC0) and hknpGroupCollisionFilterBase<Config<4,4,4,...>> (1761BA8) hold D93700, hknpGroupCollisionFilterBase<Config<5,4,4,...>> (18BC010) holds D93800. The slots are at 18BBFF0, 1761BD8, 18BC040. CorpseCleanup replaces all three with wrappers that return 0 ("no collision") when the body passed as the fourth argument has a flagged id and otherwise jump to the saved original; the plugin author states bullets, explosions and line-of-sight checks then pass through corpses while they still fall and rest on the ground.

Basis: RTTI of the vtables, slot contents, the plugin's wrappers disassembled; the behavior claim is the author's

Addresses (build-specific RVAs unless indicated): 18BBFF0, 1761BD8, 18BC040, D93700, D93800

Attribution: EDF6CorpseCleanup, novae (ajane) · 2026-10-22

Evidence: static · Build: steam-678ccb46 · Fact ID: hknp-body-id-layout

In those wrappers the id is read as [r9+0x50] (a Havok hknpBody: id at +0x50), the index is id & 0xFFFFFF (must be below 0x40000) and the body counts as a corpse when the plugin's table holds id + 1 for that index. The function DAC200 is the body lookup the same layout implies: and eax,0FFFFFFh, compare with 0FFFFFFh, bound [world+0x20], entries of 0xB0 bytes from [world+0x18], flags at entry +0x54 (test 3), id at +0x50.

Basis: decoded signature bytes 8b c2 25 ff ff ff 00 3d ff ff ff 00 74 23 3b 41 20 73 1e 4c 69 c0 b0 00 00 00 4c 03 41 18 41 f6 40 54 03 74 0c 41 39 50 50 and the wrapper code

Addresses (build-specific RVAs unless indicated): DAC200

Attribution: EDF6CorpseCleanup, novae (ajane) · 2026-10-22

Ragdoll layers and a stock death: LoadRagdoll puts the bodies on ragdoll layer 6 (106160 at 6EB9A7), but the…

Evidence: static · Build: steam-678ccb46 · Fact ID: ragdoll-layers-death-contact

Ragdoll layers and a stock death: LoadRagdoll puts the bodies on ragdoll layer 6 (106160 at 6EB9A7), but the EventAnimationObject constructor then moves them all to layer 0x11 (5B6401), which only bullets and rays touch: an EAO ragdoll activated as is falls through the map, so a death first resets layer 6 with 6E9320(ragdoll, 6) (EDF 4.1 does the same filter change on death), then activates (6E40B0: every body mode 4, dynamic, constraints on). ShootingTarget's death (its slot 18 5CB220, at 5CB297) works this way on the same layout (ragdoll +0xAA0, model +0x5C0, skeleton +0x660) and pushes the hit bodies with 11B0CB0(handle, impulse, point) (blasts away from the center by max(r - distance, 0.1) x 100, bullets by the impulse x 2 x 0.5) and the rest with 11B0C80(handle, impulse); the ragdoll's bodies are at [ragdoll+0x78], count [+0x88], 0xC0 bytes each, body handle at +0x50, and 11B15B0(handle) gives a body's position (float[4]); the main CAS player's rate set to 0 (116DF20) freezes the animation, as EDF6_Martian's death does (479677). Body velocity calls through the world part's vtable: setLinear +0xA8, setAngular +0xB0 (11B1760(body, vector)), applyLinear +0xC0, applyAngular +0xC8, applyAt +0xD0. The ragdoll_contact component (6EBBC0; HumanBase builds one at +0xF70): 0x90 bytes {+0 quake strength, +4 radius, +8 impulse threshold, +0x10 a SePreset, +0x90 cooldown frames, +0x94 frames to wait after playing}; its callback 6EC450 is registered on each body's contact signal with 6E3A60(signal, component, callback) (signal = DAB920(world, 2, body id), after enabling the body's contact events through world slot +0x158 with flag 0x80); on an impulse at or over the threshold it plays the preset at the contact, quakes (104C00) and sets the cooldown; the ragdoll's update counts the cooldown down.

Basis: the author's static reading ("H") and its in-game runs (a robot fell through the map until the layer was reset; contact callbacks fired on 45 of 45 bodies)

Addresses (build-specific RVAs unless indicated): 106160, 6EB9A7, 5B6401, 6E9320, 6E40B0, 5CB220, 5CB297, 11B0CB0, 11B0C80, 11B15B0, 116DF20, 479677, 11B1760, 6EBBC0, 6EC450, 6E3A60, DAB920, 104C00

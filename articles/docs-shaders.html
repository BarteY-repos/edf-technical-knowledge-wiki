Overview

A shader is only one part of an EDF material. The model's vertex declaration, shader family, ordered parameter records and ordered sampler bindings must agree. An MDB material reconstructed from a shader's reflected variable list is not necessarily a valid native material: the serialized order can differ.

Example: snd_BRDF_Map_Common

The audited ordinary EDF6 MDB profile serializes parameters in the order diffuse, metallic, normal_amount, roughness, specular_color, specular_diffuse_blend. This is not a promise that the shader's reflection returns the same order. Preserve sampler order and storage types, including exceptions where a numeric-looking field is stored as raw integer bits.

Version notes

  • EDF 4.1: use source shader family and asset-specific evidence; do not assume EDF6 Common/BRDF storage.
  • EDF 5: conversion must map known source material semantics and target sampler bindings; a copied shader name is insufficient.
  • EDF 6: detailed native material and parameter examples exist for ordinary MDB resources; FieldRender terrain follows a different path.

Implementation checklist

Validate vertex semantics and strides; select the shader family; write parameters in native order with validated types; bind textures in the correct sampler order; inspect blend/alpha/cutout rules; then test in the target renderer. An offline parser PASS does not prove that the material looks right.

Native terrain DDS versus object-material packing

EDF6 FieldRender DDS arrays and FMB leaf materials documents native terrain-mip and slice-array evidence, including a corrected DXGI 71 vs 72 distinction. This is a different resource path from the static MDB R/M/O-vs-reflect/spec bindings and must not be treated as a model shader sampler profile.

Captured static MDB pixel-shader lanes on Island4

The Island4 RenderDoc material audit distinguishes shader resource names param_reflect_*_spec_hspec from the artist's packed R/M/O family, including four distinct pixel-shader hashes and R5B/R5C/R6A/R6B negative/diagnostic tests. Those are ordinary static MDB observations; they do not establish the separate FMEP texture-array ABI or a finished artist-faithful shader translation.

Static shader evidence versus the final image

The retained EDF6 shader oracle reports 485 native DX11 archive entries and 3,449 compiled DXBC programs, but source and bytecode counts alone cannot certify frame rendering. The five bounded analysis groups are Common, Common Clip, Common Light, Water and FieldRender. See the five-family static/runtime evidence matrix, which distinguishes material serialization, shader writes, bound render state and final compositor output.

For implementation, treat these as separate questions: is the MDB/FMB data valid; does the correct pixel shader read it; are slots/constants and targets correctly bound; and does the final native frame match? A PASS in an earlier stage does not imply a PASS in the next. In particular, Water and FieldRender cannot safely inherit ordinary snd_BRDF_Map_Common texture conventions.

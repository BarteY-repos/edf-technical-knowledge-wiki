EDF 5 — Talk Subtitles (community source notes)

EDF 5Community Knowledge HubAudio
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Facts

EDF5 lacks native dialogue subtitle tables

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-no-subtitle-system

EDF5 has no subtitle system: the archives hold no voice table (EDF6's mission/edf6_voicetable.<lang>.sgo has no EDF5 counterpart; the only localized .sgo files are mission lists, network chat texts, weapontext, emanual and texttable_*), the Game Settings list has no subtitle item (ui-menus.md#gamesetting-item), the voice native and the talk path below call no caption lookup, and MODESAVEDATA_SUBTITLE / SYSTEMSAVEDATA_SUBTITLE (EC5468 / EC5570) are text keys of the save-data screen, picked in 4821F0 by [rdi+0xAC] = -1 and looked up with 4738B0, not a subtitle switch.

Basis: findstr.py edf5 for subtitle / caption / voice strings, cpkls.py edf5 for text tables, fn.py --xref of the two keys and a read of 482300..4823A0

Addresses (build-specific RVAs unless indicated): EC5468, EC5570, 4821F0, 4738B0

Attribution: KH chat 179 (autorun) · 2026-11-14

BVM scripted voice native call numbers

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-voice-natives

BVM voice natives (cases from the byte table, t8e5_natnum.py): 4000 Voice(cue) (case 116670) calls 127C70(script, cue), which does nothing while the script's talk list is open (script+0x408), waits ([script+0x40]+0x68 = 1) while 327240(TalkManager) reports a line playing, else plays the cue unplaced on TalkManager's handle +0x48 through 3243C0 (sound.md#edf5-talk-update-duck), with no speaker and no caption; 570 calls in 141 scripts, among them MusenBegin and MusenEnd 141 each (無線 "radio": the radio open and close sounds, inferred from the names). 4002 (1166FC) only waits while a line plays (2022 calls). 4003 calls 127D50(script, int, string, float) (not read). 4004 / 4005 set / clear TalkManager +0x58, the switch NPC chatter needs (soldier-ai.md#edf5-npc-talk-lines; 59 and 71 calls; they share their case with 420 / 421).

Basis: fn.py reads of 116670..1167F3 and 127C70; call counts and arguments from kh155_bvm_sound.py edf5 (t8e5_bvm_talk.txt)

Addresses (build-specific RVAs unless indicated): 116670, 127C70, 327240, 3243C0, 1166FC, 127D50, 125ABB0

BVM talk-list start, add and end natives

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-talk-script-natives

BVM talk-list natives, EDF6's TalkBegin / Talk_Add* / TalkEnd design (../edf6/talk-subtitles.md#edf6-talk-script-natives): 4100 (case 11500D) 127EB0(script) waits while a line plays, else clears the list script+0x3B0 (1280C0), sets a position from the first live player of four weak slots at script+0xA0 (327EF0(list, player+0xA0, 0xF)) and opens the list (script+0x408 = 1); 4102 (1150C2) 128270(script, object id, cue, animation, delay s) resolves the object (12CA60) and calls 3285D0(list, object, frames, frames, cue, animation) with delay x 60, which resolves the * letter (325A60), draws the frame count with the list's generator +0x50 and appends a 0x68-byte entry; 4101 (11507E) 128150(script) hands the list to 326A60(TalkManager, list, params {100.0, 0, 2, 400.0, 1.0, 0, 1}), clears it and closes it. Other adds by argument shape (handlers not read): 4103 128400, 4104 128590, 4105 128730, 4106 1288E0, 4107 128AA0, 4108 128C70, 4110 128E50. Calls: 4100 / 4101 1628 each in 111 scripts, 4102 1580, 4105 649. Unlike EDF6, no entry or group carries a caption key.

Basis: fn.py reads of the cases 11500D..11534D, 127EB0, 128150, 128270, 3285D0; constants EE66D0 = 100, EE6730 = 400, EE6430 = 1 read with flt.py; counts from t8e5_bvm_talk.txt

Addresses (build-specific RVAs unless indicated): 11500D, 127EB0, 1280C0, 327EF0, 1150C2, 128270, 12CA60, 3285D0, 325A60, 11507E, 128150, 326A60, 128400, 128590, 128730, 1288E0, 128AA0, 128C70, 128E50

The playing line record (one per line in a TalkManager channel

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-talk-line-record

The playing line record (one per line in a TalkManager channel; built by 326A60 for script lines and by 3250D0 for NPC chatter): +0x00 / +0x08 the sound handle (shared pointer; sound.md#edf5-talk-line-start's "handle line+8"), +0x10 the cue, +0x30 the animation name (wide strings), +0x50 / +0x58 the speaker as a weak reference (pointer, control block), +0x60 frames before it starts (at least 1), +0x64 frames played, +0x68 the mode: script lines always 0 (placed at the speaker), chatter lines take it from the pick 325820's out value. EDF5 has no TalkActor_* classes (RTTI holds only TalkManager and net::Event_TalkManager): a line is this plain record.

Basis: the record built at 326C91..326DB6 and 3253DD..3253F6, its use in 327BB0; rtti.py / findstr.py for talk classes

Addresses (build-specific RVAs unless indicated): 326A60, 3250D0, 325820

Attribution: KH chat 179 (autorun) · 2026-11-14

Talk-line countdown and sound playback

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-talk-line-step

The line step 327BB0(line, params) locks the speaker (line+0x50, 741C0), counts +0x60 down and at 0 plays the cue (mode 0: at the speaker's +0xA0 with 47CBA0; else unplaced with 47C9D0); if the cue is not found (status 3 from 92B148) it formats TalkManager::Actor( (EB1FF0) for the empty log stub 27680; when the animation is not empty it sends the speaker message 0x8000001A {style 1, or 3 when params+8 is above 100000.0, animation name} through its vtable slots +0x38, +0x30, +0x40. While the sound plays, a mode-0 line copies the speaker's +0xA0..+0xA8 into the playback's +0x40..+0x48 every frame (the voice follows the speaker) and sets the volume +0x2C from params+4; it counts +0x64 and returns 1 once the playback reports status 3 or has no handle (the line is done), else 0.

Basis: fn.py read of 327BB0..327E7F; EE6814 = 100000.0

Addresses (build-specific RVAs unless indicated): 327BB0, 741C0, 47CBA0, 47C9D0, 92B148, EB1FF0, 27680

Attribution: KH chat 179 (autorun) · 2026-11-14

Radio dialogue and NPC speaker distinction

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-talk-who-speaks

Who speaks, for a subtitle mod: radio dialogue (HQ, the operators, mission lines AE...) mostly goes through Voice (4000), unplaced and with no speaker object; lines said in person (squad leaders, civilians) go through the talk list with a speaker and play placed at it; NPC chatter reaches the same line record from 324570 -> 325820 -> 3250D0. So a speaker to draw over exists only for talk-list and chatter lines.

Basis: the lines above; mode always 0 on the script path (326DB6)

Addresses (build-specific RVAs unless indicated): 127C70, 3285D0, 324570, 325820, 3250D0

Attribution: KH chat 179 (autorun) · 2026-11-14

EDF6 English voice table overlap with EDF5 cues

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-subtitle-coverage

EDF6's English voice table captions about half of EDF5's scripted dialogue: of 4579 cue-like strings pushed in EDF5's mission scripts, 2094 (all AE / AEX) have a caption there and 2485 are absent (AE 2370, AEX 112); of 3889 cues in the 20 talk SGOs, 6 have one. EDF6 reuses EDF5's cue names for the dialogue it shares (its early missions), so the rest needs new text.

Basis: t8e5_subcover.py (every Root.cpk mission.bvm disassembled with bvm_eval.py; talk SGO strings by pattern) against the plugin's table, which equals EDF6's mission/edf6_voicetable.en.sgo key for key (13869 keys, every caption identical)

Attribution: KH chat 179 (autorun), the table as shipped by EPIC1DEFENSEF1ORCE (EDF5 Subtitles) · 2026-11-14

EDF5's own world-anchored HUD: HudPlayer_FollowerDurability (follower health bars

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follower-bar-projection

EDF5's own world-anchored HUD: HudPlayer_FollowerDurability (follower health bars; vtable EC92F8, slot 3 4B9D30) draws only while the player's byte +0xDC6 is set, builds view x projection from the HUD camera this+0x18 (624730; perspective 5BE600 with fov +0x24, aspect = render size +0x118 / +0x11C, near +0x28, far +0x2C) and calls 4B9EB0(hud, view-projection, player, ...), which walks the player's follower list +0x3A8 (node +0x10 = soldier), projects each soldier's +0xA0 raised 2.0 m (EE6504), skips it when w = 0, |x| or |y| > 1 or z outside [0, 1], and maps it to a 1920 x 1080 layout (EE67BC, EE6798; x0.5 / -0.5) before drawing with the utility draw calls (5EC340, 97B30). The same chain serves text over a speaker. Other HUD classes there: HudPlayer_MultiPlayStatus (EC9390), HudPlayer_RescueMessage (EC9500), HudPlayer_Chat, HudPlayer_CrossHair (not read).

Basis: rtti.py edf5; fn.py reads of 4B9D30 and 4B9EB0 (first 150 lines); constants with flt.py

Addresses (build-specific RVAs unless indicated): EC92F8, 4B9D30, 624730, 5BE600, 4B9EB0, EE6504, EE67BC, EE6798, 5EC340, 97B30, EC9390, EC9500

EDF5 Subtitles plugin intercept points

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-subtitles-plugin-sites

EPIC1DEFENSEF1ORCE's EDF5 Subtitles plugin (v1.2, mods/subtitles-epic1.md) hooks, besides Present: the voice plays 47C9D0 (unplaced) and 47CBA0 (placed), each detour setting a thread-local capture before calling the original; 477C50, inside the play, where the detour records the CRI playback ids the capture is waiting for; 92B148 (playback status, called directly) to see each playback end; and the pause menu's constructor 585FC0 and deleting destructor 5869E0 (photo-mode.md#edf5-pause-bit-users; an outside mod treating them as the pause menu, so captions can wait while it is open, inferred). 477C50(owner, request) tests the request's type ([[rdx]] & 0xFFFF0000 = 0x10000) and calls 477E70 or 477D20 between two 92D4D0 calls (a lock, inferred).

Basis: the plugin's address table (subtitles.dll 5617..569D) and the Detours attach list (44DB..4580), read with t8e5_dllrva.py / t8e5_dlldis.py; fn.py reads of 477C50, 585FC0, 5869E0

Addresses (build-specific RVAs unless indicated): 47C9D0, 47CBA0, 477C50, 92B148, 585FC0, 5869E0, 477E70, 477D20, 92D4D0

Attribution: EPIC1DEFENSEF1ORCE (EDF5 Subtitles v1.2), KH chat 179 (autorun) · 2026-11-14

EDF6 subtitle scroll bug not shared by EDF5

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-no-scroll-bug

EDF6's subtitle scroll bug cannot occur in EDF5 in the same form: Subtitle Scroll Fix (../edf6/mods/subtitle-scroll-fix.md) corrects a timing float of the game's own subtitle box, read through the caption lookup EDF.dll+7B17F0 (../edf6/talk-subtitles.md#edf6-scroll-fix-site), and EDF5 has no such box or lookup. The EDF5 plugin draws its own text and times it by the voice's real playback (shown from the play until 92B148 says it ended, then post_voice_hold_seconds 1.0 and fade_out_seconds 1.0); it reads only name and caption from the table (any other record field is an error) and has no scroll or line setting. How it lays out a caption too long for the screen (wrap, cut or overflow) was not read: an in-game look at a long line would settle it.

Basis: the plugin's strings and settings (subtitles.toml, t8e5_dllscan.txt), its DSGO parser messages; the EDF6 fix's card

Attribution: KH chat 179 (autorun), novae (ajane)'s question · 2026-11-14

EDF5 speech subtitle rendering route

EDF Knowledge Hub record — original wording — expand (1,359 characters)

Route to text over a speaking soldier in EDF5 (untested): (1) prior art covers the bottom-of-screen subtitles: EPIC1DEFENSEF1ORCE's plugin (#edf5-subtitles-plugin-sites) with EDF6's table (#edf5-subtitle-coverage); build on it or ask its author rather than start over. (2) For text over the speaker, hook the line step 327BB0 (rcx = line): at the play (+0x60 reaching 0) take the cue +0x10 and the speaker +0x50 / +0x58, look the caption up, keep {caption, weak speaker} until the step returns 1 (plus a hold). Radio lines from Voice have no speaker and stay at the bottom. (3) Each frame, project the speaker's +0xA0 plus about 2.0 m with the follower-bar chain (#edf5-follower-bar-projection) or Eiton's view chain (camera.md#camera-eiton-view-chain), and draw from a Present hook with an own font (Eiton's method, mods/damage-number-display.md; the plugin above does the same). (4) Captions: EDF6's table for half the radio; the rest and all chatter need new text (the vgmstream + Whisper grant, STATUS "Waiting on novae (ajane)"). Open: what natives 4003 and 4103-4110 add (radio-style lines with a speaker?), HudPlayer_MultiPlayStatus's name tags as a ready text-over-head path, the debug module debug_3d_message_drawer (looked up by name at 642C0, 64320, 64430; never registered in the code read), and the line's speaker when that soldier dies mid-line.

Basis: the lines above

Addresses (build-specific RVAs unless indicated): 327BB0, 642C0, 64320, 64430

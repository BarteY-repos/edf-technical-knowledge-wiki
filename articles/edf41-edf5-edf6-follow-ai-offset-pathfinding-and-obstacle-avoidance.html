EDF4.1 to EDF6: friendly follower movement, random formation offsets and route handling

ConversionGame technical referencesAI and navigationEDF 4.1EDF 5EDF 6
Technical reference · Attribution and grade per source fact; this edition adds no game runtime test

A friendly soldier's follow behavior is not equivalent to finding a globally optimal walkable path to the player. Across EDF4.1, EDF5 and EDF6, the source builds a target from the leader's position plus a random, world-space formation offset. How the soldier then steers toward that target changed significantly between generations.

Three generations at a glance

Game Following movement Follow anchor / formation Obstacle strategy
EDF4.1 Direct virtual-stick movement written by SoldierBase Leader position + world-space offset Local contact normal and periodic short forward box sweep; sidestep/jump-like response
EDF5 Target handed to a movement/path controller on the soldier Same leader-plus-offset concept Controller-based pathing; some controller fields updated while following
EDF6 Think and AiRouteExplorerBase/path controller cooperate Leader anchor + world-space offset, with ChaseLeader state Scripted route, navigation route and path-mesh branches exist separately

These are descriptions of the examined code paths, not comparative performance benchmarks. A different navmesh or missing map collision may still make the newer controller fail.

EDF4.1: immediate steering and contact probes

The EDF4.1 follower state is SoldierBase virtual slot 58, while guard is 57 and engage 59. move-and-look writes a virtual move stick into the soldier's movement-input fields and a separate pitch/yaw request toward a look target. Unlike EDF5, this call does not delegate its follow target to a persistent path-controller object.

When touching an obstacle whose surface normal opposes the desired direction, the code periodically sweeps a box about 3 m forward. If it finds a free path it can request a jump-like response; otherwise it retains a sidestep direction for a bounded interval. The jump flag's exact behavioral interpretation was inferred from the write, not observed afresh in this edition.

Formation offsets across the series

In the EDF4.1 code, normal followers eventually redraw a random horizontal offset with radius about 3–10 m at a timer of 900–1799 frames (approximately 15–30 seconds at 60 updates/s), seeded from a local AI random source and synchronized through a dedicated AI message online. The offset is expressed in world coordinates: turning in place does not rotate it behind the player. A soldier can therefore appear in front of a stationary leader after a redraw without deliberately choosing to block the player.

EDF5 and EDF6 retain the broadly similar world-space offset and timed redraw model, but have distinct object fields, path controller and route management. The EDF4.1 mission-native formation spread can enlarge this radius for scripted squads; a Balam leader can impose a minimum separation. The 3–10 m range is not a universal distance for every mission-controlled formation.

Navigational and script consequences

A mission's SetAiRoute, SetAiRouteNavigate and following-leader states are not synonymous. EDF6's AiRouteExplorerBase is also used by vehicles and enemies; the native IsAiMoveEnd family checks whether the explorer pointer is gone, which can leave mission events waiting if pathing never completes. An NPC already under a leader can ignore some route commands until its follow state changes. These distinctions explain why fixing a 4.1 map's physical geometry does not automatically fix the EDF6 AI route assigned to it.

Evidence boundary

The three source appendices provide static decompilation, not a newly executed comparison run. Relative RVAs (4.1 0x2B48E0, EDF5 0x30B610, EDF6 0x596B50) refer to their individually studied binaries. We do not claim the 4.1 virtual-stick branch solves navigation or that a path-controller's presence guarantees correct traversal.

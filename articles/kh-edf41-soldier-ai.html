EDF 4.1 — Soldier Ai (community source notes)

EDF 4.1Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Classes and the state machine

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-soldier-ai-classes

EDF 4.1's AI parts by RTTI, as in EDF5 (../edf5/soldier-ai.md#edf5-soldier-ai-classes): StateMachine::Agent<SoldierBase> (vtable A9E128) sits in a block at soldier +0x13B0 built by 2AE090 from the SoldierBase part constructor 2ADA90 (2ADBA7; called by four class constructors); StateMachineTable::Agent<SoldierBase> (A9E110) at +0x1308, with ActionTable::Function<SoldierBase> (A9E0A8) and a weapon-set table (Agent<SoldierBase::WeaponSet> A9E0F8, Function A9E0D0). SoldierBase's primary vtable A9E170 has 61 slots (EDF5 more).

Basis: RTTI names to vtables (scratch kh149_rtti.py), fn.py --xref to their builders

The AI states are SoldierBase slots 57 guard 2B5780, 58 follow 2B5920, 59 engage 2B5D10 (EDF5 74-76), each st…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-soldier-ai-states

The AI states are SoldierBase slots 57 guard 2B5780, 58 follow 2B5920, 59 engage 2B5D10 (EDF5 74-76), each state(soldier, phase) (0 enter, 1 update, 2 exit), entered through the thunks 2BB5F8 (jmp [vtable+0x1C8]), 2BB5D4 (+0x1D0) and 2BB604 (+0x1D8). The machine: elapsed time f32 +0x13B0 (+= dt), frame count +0x13B4, current state object +0x13B8 (slot 1 called each frame from 2B487E). SetUp (slot 3 2B3690) starts guard (2B393D). Switches as in EDF5: guard -> follow when the leader +0x2C0 is set, guard or follow -> engage when the target +0x14A0 is live, engage -> follow when the target getter 2AD9E0 returns null, follow -> guard when the leader is gone. Guard and follow move to +0x1410 plus the offset +0x1440 (and the jitter +0x1460) through 2B48E0; guard and follow end with 2B52B0, engage with 2B5460.

Basis: fn.py reads of the three states, the thunks and SetUp

Addresses (build-specific RVAs unless indicated): 2B5780, 2B5920, 2B5D10, 2BB5F8, 2BB5D4, 2BB604, 2B487E, 2B3690, 2B393D, 2AD9E0, 2B48E0, 2B52B0, 2B5460

The per-frame AI is SoldierBase slot 4 2B3C30 (EDF5 slot 4 30B610): it counts frames in +0x152C, runs 299C60…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-soldier-ai-update

The per-frame AI is SoldierBase slot 4 2B3C30 (EDF5 slot 4 30B610): it counts frames in +0x152C, runs 299C60 on +0x970 and the base step 28DA80, returns for a dead soldier (HP +0x16C <= 0), then does recruiting (#edf41-recruit-near-player), the leader's death, the offsets, the route watchdog (#edf41-route-watchdog), the target search and fire bursts (#edf41-target-and-fire), the voice lines (#edf41-npc-talk-triggers) and finally the state machine. Its random numbers come from a per-soldier generator at +0x250 (LCG multiplier 5D588B656C078965, increment 269EC3).

Basis: fn.py read of the whole function (kh150_2B3C30.txt)

Addresses (build-specific RVAs unless indicated): 2B3C30, 299C60, 28DA80

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-ai-sync-message

Online, the host sends the AI's random choices: 2B8150(soldier, code) (host only: room mode [CC84A0] +0x5C != 0, not a remote copy +0xC8 bit 0, slot 20 false) packs message 0xE with the generator state +0x250 and per code: 0 the offset +0x1430, 1 the jitter +0x1460, 2 the search timer +0x14A8 and the target's id, 3 the fire timers +0x14B0 / +0x14AC. The AI update calls it after each such pick. EDF5's counterpart not read.

Basis: fn.py read of 2B8150 (its code switch 2B83A0)

Addresses (build-specific RVAs unless indicated): 2B8150, CC84A0

Squads and recruiting

Squads are the base-object tree, as in EDF5 (../edf5/soldier-ai.mdedf5-squad-tree): +0x2C0 the leader, +0x2C8…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-squad-tree

Squads are the base-object tree, as in EDF5 (../edf5/soldier-ai.md#edf5-squad-tree): +0x2C0 the leader, +0x2C8 the followers' list head, +0x2D0 its size, byte +0x2B8 "may join a player". SetFollow B31A0(self, leader, keepOffset) calls Unfollow 28EF10, links in, calls slot 14 (+0x70, 2B2B90) and releases the route (C8020(+0x268)). Slot 23 (+0xB8, 2B76A0) syncs it online; the host's message is 9 (2B7770; EDF5 0xB).

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): B31A0, 28EF10, 2B2B90, C8020, 2B76A0, 2B7770

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-friend-natives-join-flag

The script interpreter 14B413 picks a native's case by the number's low 7 bits (byte table 14C9F8[number & 0x7F], offsets 14C8A8), then tells numbers apart by cmp edx, <number> (EDF5 uses the low 8 bits, ../edf5/soldier-ai.md#edf5-native-dispatch-low-byte). The friend natives set the join flag +0x2B8 as in EDF5: 1010 (14C60F) 1510F0 from an argument (151286), 1011 (14C691) 1513C0 the leader from an argument (151582) and each follower 1 (151703) with SetFollow (151713), 1012 (14C721) 151770 from an argument (151903). 3112 (14BDD2, EDF5's RecruitObject 3152) 154340(leader id, follower id) calls SetFollow with keepOffset 0 (EDF5 1) and, online, slot 23; M119's script calls it on several pairs.

Basis: fn.py reads of the dispatch and the natives; the script use with scratch find_call.py edf41 3112

Addresses (build-specific RVAs unless indicated): 14B413, 14C9F8, 14C8A8, 14C60F, 1510F0, 151286, 14C691, 1513C0, 151582, 151703, 151713, 14C721, 151770, 151903, 14BDD2, 154340

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-recruit-near-player

Recruiting by walking up (2B3CCB..2B3EE6), as in EDF5: a soldier with no leader and +0x2B8 set runs SearchNearPlayer over team 0 (2C9740([CC8510], 0, visitor)): the nearest HumanBase (dynamic cast) that is alive and within 10 m (AB6790); online a remote copy (+0xC8 bit 0) is skipped. Then SetFollow(self, player, 0), slot 23, the talk table 合流 (join), the offset +0x1440 = the direction from the player x (2 + rand x 3) m (AB6700, AB6744), +0x1450 = 180 + rand(120) frames. When the leader dies (2B3F21..2B3F70; no auto-revive test, EDF5 has one): +0x14E4 = 300, Unfollow, route released, slot 23 with no leader, the cover budget +0x1524 capped at 600.

Basis: fn.py reads of 2B3C30 and 2B3AB0; constants with scratch vt_dump.py f32

Addresses (build-specific RVAs unless indicated): 2B3CCB, 2B3EE6, 2C9740, CC8510, AB6790, AB6700, AB6744, 2B3F21, 2B3F70

Targets, fire and routes

Target and fire: every 60-119 frames (+0x14A8) SearchAttackTarget walks the teams hostile to the soldier's te…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-target-and-fire

Target and fire: every 60-119 frames (+0x14A8) SearchAttackTarget walks the teams hostile to the soldier's team +0x180 (2C9920), counts them (+0x1520) and keeps the nearest whose byte +0x260 is set, with no distance limit and no line of sight, as a weak pointer at +0x14A0. Fire comes in bursts of 30-44 frames (+0x14B0) with pauses of 60-89 (+0x14AC), the burst byte +0x14B4 (cleared while +0x204 != 0); unlike EDF5 (../edf5/soldier-ai.md#edf5-target-and-fire) no ray is cast, so NPCs fire through walls (untested in game). The engage state copies +0x14B4 to the fire byte +0x990 when the target is ahead (dot > 0.8, AB65E8) and within max(25 m, 0.5 x the first weapon's range +0x1A8) (2B5FBB..2B6010).

Basis: fn.py reads of 2B3C30 (2B44A8..2B4669), 2B3B90 and the engage state

Addresses (build-specific RVAs unless indicated): 2C9920, AB65E8, 2B5FBB, 2B6010

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-route-watchdog

The route watchdog (2B4339..2B4499), as in EDF5 (../edf5/soldier-ai.md#edf5-route-watchdog): while a route gives a point, +0x1410 = it and the offsets are zeroed; when the soldier has not come 2 m (AB6700) closer than its best distance +0x1530 within 3600 frames (+0x1534), the point moved under 1 m, the soldier is alive, +0x320 bit 0 is clear and it is not a remote copy, it calls 609EF0(658360([+0x3B8]), point) and 2B8680(soldier, point), inferred to place it there (unverified).

Basis: fn.py read; the effect inferred from EDF6's watchdog

Voice lines

NPC voice lines: TalkManager::RandomTalk 2C2890(TalkManager CC84F0, object, table name) (no params argument,…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-npc-talk-lines

NPC voice lines: TalkManager::RandomTalk 2C2890(TalkManager [CC84F0], object, table name) (no params argument, unlike EDF5's 324570) looks the name up (51AD10) in the talk SGO at object+0x228, loaded from the object SGO's game_object_talk_setting (28D2E2, stored 28D3F9); it does nothing for team -1, without a talk SGO or for a remote copy (+0xC8 bit 0), logs A03A30 for an unknown table, sends it online (2C57F0), returns when the nearest of the four players ([CC8528]+0x1D8, stride 0x258) is beyond 100 m (A8C7A8 10000.0 squared), and plays through 2C2A90. The soldier AI calls it only while TalkManager +0x38 is set; 43 call sites.

Basis: fn.py reads; strings with scratch kh149_fnstr.py edf41

Addresses (build-specific RVAs unless indicated): 2C2890, CC84F0, 51AD10, 28D2E2, 28D3F9, A03A30, 2C57F0, CC8528, A8C7A8, 2C2A90

The soldier AI's talk triggers (2B3C30), as in EDF5 (../edf5/soldier-ai.mdedf5-npc-talk-triggers) except two…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-npc-talk-triggers

The soldier AI's talk triggers (2B3C30), as in EDF5 (../edf5/soldier-ai.md#edf5-npc-talk-triggers) except two timings: 合流 on joining; 体力低下 once below half HP (AB656C); ダメージ when HP fell, not while +0x204 is 2 or 3 (+0x14D8 = 300-599 after); リロード once while a weapon is empty and reloading; 増援出現 when the hostile count rose by over 10 or from 0 after 900 frames of life; else 気付かれた on a new target after 60 frames; 勝利 5 frames after the target is gone (+0x14D0; EDF5 120); the follow state plays 走り出す (2B5CB4) when the squad's root leader is a player.

Basis: fn.py reads of 2B3C30 and the follow state

Addresses (build-specific RVAs unless indicated): 2B3C30, AB656C, 2B5CB4

EDF 4.1 has 9 talk SGOs in Root.cpk sound/: fencer(_leader), mob_man, mob_woman, ranger(_leader), support_uni…

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-talk-sgo-tables

EDF 4.1 has 9 talk SGOs in Root.cpk sound/: fencer(_leader), mob_man, mob_woman, ranger(_leader), support_unit, wingdiver(_leader) _talk.sgo (EDF5 20, ../edf5/soldier-ai.md#edf5-talk-sgo-tables); the soldier files hold 130 tables, the civilians 8, support_unit 103. Each table is [speaker ("レンジャー"), a float, an int, an int, [entries]], each entry 13 values: [voice cue with a %s slot (U001E%s), animation or "", weight, -1, two floats (delays, inferred), reply table name or 0, 0, a float, two ints, two floats]; some tables are empty (チャット励ます []). Who fills %s is not read (for 00u (d)).

Basis: scratch cpksurvey.py edf41 ls sound/ _talk.sgo and peek_sgo.py edf41 sound/ranger_talk.sgo

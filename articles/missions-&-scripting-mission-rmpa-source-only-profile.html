Mission RMPA — source-only EDF5 → EDF6 profile

ConversionMissions & ScriptingMissionsEDF 5EDF 6
Source-backed research / case study · Reconciled

Evidence level: Exact paired native corpus + reconciled source-only tooling; runtime qualification remains pending.

Observed native behavior

Mission RMPA is a mission-owned route/shape/spawn container and is structurally distinct from map RMPA. The shipping141 source/target corpus establishes a dedicated EDF6 target profile rather than a generic version-bump transformation.

The retained corpus contains 5,103 waypoints, 1,355 shapes and 3,387 spawn records. AC-to-RMPA closure resolves 6,665 literal references with no missing target in the source-only gate.

The EDF6 target form uses \0PMR, version 1. Route, shape, camera and spawn groups are represented independently. Route records use a 0x30 type header; waypoint records use 0x50 with a 0x30 waypoint body. EDF5 route-local waypoint numbering is rebased to a global target index while preserving GIDs and translating next links through the route base. Width values are preserved. Variable next-link regions are followed by 16-byte alignment. Shape and spawn records likewise have their own target headers and payload layouts, with strings published through the shared string table.

Type-header correction

The reconciled type-header layout uses +0x18 as the string pointer. There is no type-header field at +0x1C; +0x1C belongs to Enumeration Sub-Headers. Older diagrams/notes that placed an additional type-header member at 0x1C are superseded. This distinction matters when writing offsets: a file can remain parseable while silently shifting the wrong record family.

Implementation rule

Use the dedicated mission-RMPA converter/profile. Preserve the semantic graph, IDs, widths, references, grouping and target alignment rules demonstrated by the paired corpus. Conversion is not complete merely because the file parses or carries the EDF6 version marker.

SetAiPath(obj, "navigationmap") is not evidence for a mission-RMPA route. navigationmap belongs to native NAV/pathing semantics and is intentionally excluded from mission-RMPA route resolution.

Known exception

Reference-specific tuning is sparse. A single observed M061 shape-metadata exception is not source-distinguishable enough to become a generic conversion rule. Do not hardcode it across the corpus without a stronger discriminator.

Do not assume

  • Mission RMPA is not map RMPA and must not reuse the map-RMPA converter.
  • Stress fixtures prove serializer robustness, not release-corpus runtime parity.
  • Source-only 141/141 structural, semantic and deterministic closure does not establish in-game acceptance.
  • Unknown local tuning values must not be invented merely to resemble one reference file.

Evidence status

The current retained standalone mission-RMPA authority is R1 source-only. Build/parse/semantic/determinism/target-profile gates pass across the 141-mission corpus, but representative runtime qualification is still required before claiming runtime parity.

Binary record reference

The retained source writer provides more than a generic format label: the studied EDF6 variant begins with \0PMR version 1, a 0x30-byte big-endian header, independent route/shape/camera/spawn groups, 0x30-byte waypoint records, and file-global waypoint.no numbering rebased from EDF5 route-group-local indices; MAPB placement count is not involved. There are mixed-endian secondary descriptors and the observed shared UTF-16BE string table with its two-byte zero anchor (no universal eight-byte route prefix). See Mission RMPA binary records and global identities for the concrete layout and its constraints.

The converter's profile-specific binary details are not general proof that arbitrary EDF5 route bytes can be copied or that a mission RMPA and a map/weather RMPA share identical semantics.

Reproducible historical 141-mission BVM + RMPA pipeline

A preserved source-only converter accepts a mission directory with the original EDF5 MISSION.BVM and MISSION.RMPA. It decompiles BVM to MISSION.asm, transpiles to EDF6-oriented MISSION.AC with the historical R44-era compiler, and separately writes the mission-specific EDF6 MISSION.RMPA. The converter checks target RMPA structure and source-semantic equivalence. The output is an AC, mission RMPA, optional source-derived object variants and a per-mission PIPELINE_REPORT.json; no EDF6 donor mission files are consulted.

The original 27 August 2026 audit reported 141/141 shipping missions passing, 141/141 ACs byte-identical to the historical R43 candidate and 141/141 RMPAs identical to R1. A portable recovery on 4 September independently reproduced 141/141 per-mission historical outputs with zero canonical converter modifications. The historical checkpoint as a whole was not literally 100% byte-present: the recovery accepted one absent zero-byte mission_util/__init__.py; it was declared compatible, with checkpoint_manifest_byte_exact=false. Do not describe that as an entirely byte-exact recovered source tree.

This is an exact historical artifact reproduction result, not a current-converter promotion or a 141-mission gameplay-runtime PASS. The preserved recovery code must not replace /EDF5_EDF6_RESEARCH/converter/mission/mission_ac_engine.py. The mission counts split across MissionPack03/04/05 are 112 / 15 / 14. The only audited optional object specialization belongs to DM006_2 and cuscall0 3450: one mission, three original EDF5 frog SGOs and four generated variants. It is important to distinguish that offline-specialization proof from the later playable compatibility choice to omit six search-radius calls, discussed in SetAiSearchRadius 3450 compatibility policy.

Reference-port differences: what the source-only writer must not copy

The paired target-reference corpus is not byte-identical to EDF5 source semantics everywhere, even though the converter can represent the source faithfully. Recorded exact matches versus the independently authored reference port:

Semantic property Exact records Meaning
Global waypoint number, GID, next-link topology and width 5,103/5,103 each Strong source-backed profile rules
Waypoint kind/name 5,058/5,103 Some local reference-side zeroing
Waypoint position bits 5,072/5,103 Local coordinate tuning exists
Shape type/GID 1,355/1,355 Strong source-backed identity
Shape payload bytes 1,349/1,355 Six local payload differences
Spawn GID 3,386/3,387 One DM018 reference-side player ID change
Spawn coordinate bits 3,340/3,387 Local positional adjustments

The reference port also contains 21 additional empty route/shape/spawn groups; none is referenced by the compared R43 AC within the same RMPA namespace. That supports omitting these empty groups in the source-only profile, but does not prove the coordinate/payload changes are irrelevant at runtime. Source-preserved names and group membership should not be zeroed merely to reproduce an external reference editor's choices.

Five prepared, not executed, runtime discriminators

A source-owned qualification matrix covers M004 (159 spawn records, 28 waypoints), M009 (two target-only empty route groups), M015_3 (542 waypoints and 27 shapes), M061 (single missing reference shape metadata descriptor) and DM003_3 (DLC mixed route/shape/spawn case). Its explicit status is PREPARED_NOT_RUNTIME_TESTED. Candidate packages and installation paths are not themselves evidence of successful gameplay; each probe should be isolated from others and restored after testing.

Native EDF6 EDF5_OLD_SCRIPT is a pre-existing target-side RMPA corpus

The source-vs-native inventory of the two original mission trees contains 146 MISSION.RMPA files in EDF5 and 146 in EDF6's EDF5_OLD_SCRIPT, with 146/146 matching mission identifiers but 0/146 byte-identical files. It also contains 44 native EDF5_NEW_SCRIPT RMPAs: all 44/44 are byte-for-byte identical to their corresponding EDF5_OLD_SCRIPT RMPAs. In this sample, the OLD/NEW split changes script/AC identity, not a second mission-RMPA conversion. This result is about mission RMPA, and says nothing about the separate EDF5-versus-EDF6 BVM byte differences.

Across the 141 active shipping mission comparison, stock EDF6 OLD_SCRIPT retains the 5,103 route waypoints, 1,355 shapes and 3,387 spawns, while adding empty target groups: route groups 506→511, shape groups 300→305, and spawn groups 674→685. Five route groups, five shape groups, and eleven spawn groups were target-only empty groups; those empties are not extra enemy waves.

The stock target files also include selective author-side tuning, rather than only repacking the source bytes:

Measured source→stock target comparison Result in the 141-mission sample
Waypoint kind/name locally zeroed 45 of 5,103
Waypoint position bit-different 31; 26 have a nonzero numerical displacement
Shape payload edits 6 of 1,355
Shape-name edits 2 of 1,355
Spawn p1 bit-different 25; 22 numerically meaningful
Spawn p2 bit-different 21; 13 numerically meaningful
Spawn records with any nonzero positional adjustment 34
Missions with meaningful route/spawn coordinate tuning 46 of 141

These numbers describe native target-side RMPA samples, not a universal algorithm or a requirement to modify every converted mission. A faithful source-only serializer built all 146 sampled RMPAs but matched 0/146 stock target files byte-for-byte (even though 123/146 matched target file length). Therefore source semantics preserved and identical to Sandlot's existing target-side data are different success conditions.

The native stock RMPA provides a stronger target-layout and explicit target-tuning comparison than any speculative source-only default. If using native stock resources is legally/technically permitted in a local analysis, inspect their exact mission identity first; this is not permission to redistribute proprietary mission files or to blindly replace independently runtime-qualified compatibility exceptions. The known earlier 138/141 current-versus-stock match was a dated release snapshot: it listed DM001, DM018, and DM021. Subsequent work corrected DM018; a later DLC-only 27/29 snapshot retains DM001 and DM021 as deliberate compatibility differences. Do not report the old DM018 discrepancy as an active defect.

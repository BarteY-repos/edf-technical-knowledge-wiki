EDF5 Mission VM, Script States and ShowLayout

EDF 5Community Knowledge HubScripting
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

Mission bytecode does not execute as a list of human-readable commands. A native interpreter dispatches opcodes into game systems, and UI instructions such as ShowLayout have both interpreter and layout-manager lifecycles.

Format, API or behavior

The source follows the EDF5 BVM opcode dispatcher and the MissionScript state transition from created to started, playing and ended. It also identifies opcode 0x27 as a ShowLayout path. Such details matter when transpiling mission scripts or testing when a UI element is safe to create.

The following selected source observations retain their original evidence level and build-specific details. Follow their links for the complete evidence method, addresses and attribution.

Bvm interpreter dispatch — static

The BVM interpreter 114F38 dispatches with movzx eax,dl; movzx eax,[base+0x117968+rax]; jmp [base+0x1176E8+rax*4] (dl = the opcode's low byte; each case re-checks the full opcode).

Missionscript state values — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (489 characters)

The MissionScript state at [[125AB40]+28]+F8 takes 0 = created, 1 = started (set at 1148F8), 2 = playing (set at 126614 by the native behind interpreter op sub-id 0xB, called at 115261), 3 = ended (EndMission). The 16 timers at MissionScript +36C count only in state 2 (114D16). Whether state 1 covers the loading screen is not settled, so only the transitions to 2 (start) and 3 (end) are certain; a once-per-frame poll of this field answers methods/unexplored.md's "Mission start event".

Showlayout native — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (343 characters)

Opcode 0x27's case 1158C3 calls ShowLayout(MissionScript*, const wchar_t* path) 126EE0, which creates the UI through 61E560(uiMgr, &out, path, params) with uiMgr = [125AB70]-0x88 (globals.md#global-ui-manager). The MISSION CLEAR banner (verified in game, dead_ends.md) and the MISSION FAILED banner (failed-banner-signal) are shown through it.

Showlayout r11 frame — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (260 characters)

ShowLayout 126EE0 keeps its entry rsp in r11 (mov r11,rsp at entry) and still addresses its frame through it after 126F0D (+0x2D, mov rbx,rdx; mov rsi,rcx): lea rcx,[r11-0x38] at 126F13. Code run in place of the instructions at 126F0D must leave r11 unchanged.

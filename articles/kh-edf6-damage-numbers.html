EDF 6 — Damage Numbers (community source notes)

EDF 6Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

The display and its option

EDF6 has a native damage-number display (HUiHudDamage, one per player HUD)

Evidence: static · Build: steam-678ccb46 · Fact ID: native-damage-display

EDF6 has a native damage-number display (HUiHudDamage, one per player HUD). The options-menu setting Option_DamageUIType picks its style: 0 None, 1 HitPos (every hit at its point), 2 FixedPos (a fixed stacked list), 3 Target (one number per target); the code switches on it at 88E640 and 892463. FixedPos works almost exactly like EDF5 mods' fixed display: hits within a merge window add into the newest line, otherwise a new line is pushed; lines stack upward with the newest at the base; each line expires a set time after its last hit; a pop-in scale plays on every update; vehicles get their own size and optionally their own position, and soldier classes their own positions.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 88E640, 892463

Attribution: novae (ajane) · 2026-10-11

The display-on byte HUD+0xC0C is 0 while the Damage display option is Off (option entry 0, an int in the styl…

Evidence: static · Build: steam-678ccb46 · Fact ID: hud-damage-display-flag

The display-on byte HUD+0xC0C is 0 while the Damage display option is Off (option entry 0, an int in the style table) and 1 for every style row: the style reload 8224A0 stores the option value at HUD+0xC08 (re-read each frame from the player's option slot), then writes HUD+0xC0C = 0 at 822715 when the table entry's type field is 1, else 1 at 822721. The receiver (cmp byte [rbx+0xc0c], 0 at 820264), the per-frame update (8204E0) and the expiry and layout calls (cmp byte [rbx+0xc0c], 1 / jne at 82066E, layout at 8206D8) are all skipped while it is 0, so nothing is spawned, expired or drawn. The layout manager passed to the layout routine is HUD+0xA58, which reads the flag as manager+0x1B4; HUD+0x798 is the second-player flag in split-screen.

Basis: disassembly of 8224A0 and the three tests; not tested in game

Event path: who gets a number

After writing the target's HP, the damage function 547C30 builds the damage event on the stack (54820F-548231…

Evidence: static · Build: steam-678ccb46 · Fact ID: damage-event-payload

After writing the target's HP, the damage function 547C30 builds the damage event on the stack (54820F-548231) and calls owner->vfunc[0xA8](&event) at 548236 (13 bytes: mov rax,[rcx]; lea rdx,[rbp]; call [rax+0xA8]; owner = the attacker, from source+0x10 through the handle converter 89D90, damage-model.md#handle-converter). Event: +00 attacker, +08 target, +10 source (the hit message), +18 float damage (negative), +20 text RGBA (white, constant 1765B90), +30 edge RGBA (black, constant 1765B30). The game's friendly-fire byte [rsp+0x20] is still valid at 54820F (re-read at 5483CD).

Basis: disassembly; decoded: 1765B90 = (1, 1, 1, 1), 1765B30 = (0, 0, 0, 1)

Addresses (build-specific RVAs unless indicated): 547C30, 54820F, 548231, 548236, 89D90, 1765B90, 1765B30, 5483CD

Vehicles hand damage to their riders: vfunc 0xA8 is 62F4F0 (VehicleBase on-dealt-damage) for every vehicle cl…

Evidence: static · Build: steam-678ccb46 · Fact ID: vehicle-damage-handover

Vehicles hand damage to their riders: vfunc 0xA8 is 62F4F0 (VehicleBase on-dealt-damage) for every vehicle class (27 classes: Vehicle402..612, the Bike, Car, Tank and Helicopter bases, Begaruta) and for no other game-object class. It copies the event, replaces the attacker with each seat occupant that has +0x340, and sends each copy straight to the 4 camera slots via vfunc[0x40] (the mov rdi,[20B2958] at 62F62B), then returns; it takes no stack arguments. The game credits vehicle damage to the rider; a vehicle with no player aboard hands nothing on. Sentry-gun shots carry owner = the player.

Basis: vtable scan of all classes; disassembly; 62F4F0 run in the emulator with fake cameras; 62F62B decoded

Addresses (build-specific RVAs unless indicated): 62F4F0, 62F62B, 20B2958

The store is a std::unordered_map (FNV-1a over the 8 key bytes) from key to group

Evidence: static · Build: steam-678ccb46 · Fact ID: damage-number-store

The store is a std::unordered_map (FNV-1a over the 8 key bytes) from key to group; key = 0 when type == 2, else the target pointer (type-1 key set at 820945: mov r8,[rbx+8]; mov [rsp+0x20],r8; type 2 at 820950). Keys are only hashed and compared, never dereferenced, so tagged keys (target+1, target+2) are safe. Group (0x40 bytes): +0x10 key, +0x18 small vector of lines (data +0x20, count +0x30), +0x38 lastTime (double). Line (0x40 bytes): +00 text RGBA, +10 edge RGBA, +20 position vec4, +30 time (double), +38 value.

Basis: disassembly; the real spawner, map insert and rehash run in the emulator (12 targets)

Addresses (build-specific RVAs unless indicated): 820945, 820950

Evidence: static · Build: steam-678ccb46 · Fact ID: digit-text-format

Number text (823F30): "%.2f" if the value is below 10 and its fraction >= 0.01; "%.1f " (one trailing space) if below 100 and the fraction >= 0.1; else "%d " (three trailing spaces) of the truncated value, so every number is its digits plus 3 characters. Alignment offset = wcslen x [1F778A8] (0.6, loaded at 824090) x cell width (drawer +0xF0): 0 for left, -1 x width for right, -0.5 x width centered (the alignment argument: 0 left, 2 right, else center). Basis: disassembly; decoded (1F778A8 = 0.6); rev 5 replaced the rougher reading of rev 2 ("%d" if >= 100 or the fraction < 0.1, else "%.1f")

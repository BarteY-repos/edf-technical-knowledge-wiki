EDF5 vs EDF6 radar: scale, player colors and native HUD layers

ConversionGame technical referencesGameplay & AIEDF 5EDF 6
Technical reference · Static/source-backed community evidence; verified test results identified separately; no R117 native runtime tests

Evidence: Build-specific native HUD research in the EDF Knowledge Hub (EDF5 steam-5d11de53, EDF6 steam-678ccb46, snapshot 2026-11-14). This article separates the game's observed drawing logic from third-party changes to HUD palettes. No new runtime validation was performed.

EDF5 world position → radar position

The studied EDF5 HUiHudRader stores these defaults:

Field Native value Interpreted function
Position scale 0.6 Multiplies planar displacement from the player before drawing
Marker-size scale 1.2 Normal dot/icon size multiplier
World-distance limit 200 m Planar range comparison and rim clamp
Nominal resulting rim radius 120 radar units 200 × 0.6; not a claim that all modes share the same HUD pixel dimension

The native position helper rotates relative positions with the player's heading. It returns planar x/y, a separate relative-height quantity, and an inside-range flag. A point outside 200 m is clamped to the rim rather than simply disappearing in the examined helper. Height is calculated separately and clamped to approximately ±80 in the source rule.

EDF5 reads these sprite resources from app:/Effect/Hud.rab: Radar_item.dds, HudRaderPoint.dds, HudRaderArea.dds. HUD layout is app:/ui/lyt_HudRader01.sgo. Sprite identity and position conversion are different components.

EDF5 team colors and drawing order

The native dispatcher creates per-category lists and renders them in an observed order: team 4, item crates, team 2, hostiles, team 5, teammate icons, team-0 entities, mission points and area circles. Because the source pathway has no depth test for these markers, later categories may visually cover earlier ones.

The examined native palette includes red hostiles, green crates, cyan team 2 and yellow team 5; teams 0/4 have white entries. The color associated with one game team is not necessarily a unique player slot color.

EDF6 HUD colors are a different table

EDF6 has a set of native RGBA float constants for neutral, allied, item, enemy and vehicle categories. The community's patch research found the color table and the item-class loop, but the colors written by those patches are custom choices, not evidence of EDF6's original defaults.

The EDF6 player-icon path selects from four player-id entries, independent of the player's soldier class:

Player id in the studied icon path Native icon RGBA
0 Yellow (1,1,0,1)
1 Green (0,1,0,1)
2 Blue (0,0,1,1)
3 Red (1,0,0,1)

The class can affect the icon's rotation/shape path, but color selection is by ID. It is not proven that IDs always equal lobby list order or that the host always occupies a specific id.

EDF6 distinguishes item categories in the HUD loop: category 0 weapon, 1 armor, 2/3 health. The exact native drawing and optional per-category color override belong to separate stages.

What the radar cannot tell you alone

A changed dot color does not establish a changed game-object team relation, and a radar bearing does not guarantee AI line of sight. HUD projection, TeamManager relations, physics collision and target visibility use different source systems. Do not merge their ownership logic simply because all can refer to the same object.

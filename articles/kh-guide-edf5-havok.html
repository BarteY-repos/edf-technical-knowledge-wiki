EDF5 Havok Body Properties and Motion Operations

EDF 5Community Knowledge HubCollision & Physics
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

The studied EDF5 runtime uses the Havok Physics2012-style hkp* body/motion system, with native wrappers and collision filter layers. This is not the same runtime body layout as EDF6’s hknp* path.

Format, API or behavior

The source identifies body wrapper, collision filter field +0x4C (low five bits as layer), and virtual setters for linear/angular velocity and linear impulse. These operations belong to the motion interface and need correct object alignment and lifetime.

Evidence and exact technical details

The following selected source observations retain their original evidence level and build-specific details. Follow their links for the complete evidence method, addresses and attribution.

Havok body wrapper — static

The game's Havok body wrapper is 0x2C0 bytes: hkpEntity vtable CDE138, with an embedded hkpMaxSizeMotion (the concrete motion) at +0x150. Crates point to it from Unit +0xA0 (drop-items.md#crate-unit-body).

Havok body filter info — static

Body +0x4C is collisionFilterInfo; the collision layer is value & 0x1F.

Havok motion vtable slots — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (354 characters)

Motion vtable slots, called as call [vtable+off] with rcx = body+0x150 and rdx a 16-byte-aligned vector: +0x90 setLinearVelocity (a plain store to motion +0xE0), +0x98 setAngularVelocity (+0xF0), +0xB0 applyLinearImpulse (v += imp × invMass, invMass = [motion+0xD0].w), +0xC0 applyAngularImpulse. For keyframed and fixed motions +0xB0 / +0xC0 are no-ops.

Version notes and limitations

Do not use EDF5 body/motion offsets against EDF6 hknp bodies. Format-level deserialization is not collision-semantic parity; require real host and physics tests.

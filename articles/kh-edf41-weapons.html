EDF 4.1 — Weapons (community source notes)

EDF 4.1Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Fourteen WeaponBase-derived weapon classes

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weapon-class-tree

Weapons: 14 classes under WeaponBase (itself a xgs::game::SceneObject): Weapon_BasicShoot, Weapon_Gatling, Weapon_HomingShoot, Weapon_ImpactHammer, Weapon_LaserMarker, Weapon_LaserMarkerCallFire, Weapon_PileBanker, Weapon_Shield, Weapon_Swing, Weapon_Throw, Weapon_VehicleShoot directly; Weapon_HeavyShoot and Weapon_MarkerShooter under Weapon_BasicShoot; Weapon_VehicleRailGun under Weapon_VehicleShoot. WeaponBase's primary vtable is AA2200, 24 slots (xgs::game::SceneObject's AB0C18 has 10

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weaponbase-vtable

WeaponBase's primary vtable is AA2200, 24 slots (xgs::game::SceneObject's AB0C18 has 10; slot 9 is the scalar deleting destructor, 1848C0 there). Slots 0 and 2 are the stub 666546 in WeaponBase (pure virtual, unverified). Slot 2 is the update (Weapon_BasicShoot 314CC0: the common weapon update 30E540, then adds the frame time [ctx] to +0x1030 and counts frames in +0x1034); slot 13 is Shot(weapon, shot index) (edf41-weapon-shot); slot 15 30F1B0 starts a reload (empties the magazine, +0x870 = 0, when it is not full and +0x194 >= 0, then 311820); slot 18 takes a command node (314BD0: its name 発射 "fire" goes to the try-fire 30FB50, キャンセル "cancel" to 311B90(w, 1)).

Basis: fn.py reads of the slots; vtables found by RTTI (scratch File_Storage/Logs/catalog/kh158_vt.py edf41 <regex> --diff WeaponBase); strings by fn.py --str (A07F04, A07EF8)

Weapon try-fire state conditions

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weapon-tryfire

The try-fire 30FB50(weapon) fires only when ammo +0x870 > 0, +0xD4 == 0, the shot timer +0xAB0 <= 0, bit 0 of +0xFEC is clear and the owner (+0xB0, its interface slot 8) is not a remote copy (bit 0 of +0x18 of what that returns). It sets the burst: count +0x2F0 (taken from +0x8F8 when +0x500 is set), shots still to come +0xAB4 = count - 1; then calls slot 13 with the shot index AmmoCount +0x1C0 - ammo +0x870. With byte +0xAB8 set the magazine is emptied after the burst (30FC3C). The weapon update fires the rest of a burst at 30ECE7 (while +0xAB4 > 0 and +0xAB0 <= 0). Callers: 11 sites in the weapon classes' command handlers and updates; which code sends the "fire" command node was not read.

Basis: fn.py reads of 30FB50 and 30EC80..30ECE7; fn.py --xref 30FB50

Addresses (build-specific RVAs unless indicated): 30FB50, 30FC3C, 30ECE7

Attribution: novae (ajane), KH chat 158 (autorun) · 2026-11-13

Shot (Weapon_BasicShoot slot 13 314D20) calls 30FC50(weapon, index, r8): returns for a remote copy's weapon

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-weapon-shot

Shot (Weapon_BasicShoot slot 13 314D20) calls 30FC50(weapon, index, r8): returns for a remote copy's weapon; 30FD30 picks the per-shot record ([+0x158] + (index mod +0x168) x 0xA0) and aims it from the weapon matrix +0xE0 (311D70); online (room mode [CC84A0] +0x5C != 0, soldier-ai.md#edf41-ai-sync-message) it calls slot 23 and 311F70, which packs the shot for the network; then 30FDA0 spawns. The bullet class is the record's +0x10 when set, else the weapon's +0x5E0; the weapon's InitParam template +0x5F0 (motherships.md#edf41-bullet-initparam) is copied by 310B80 to the working block +0x720; the bullet spawns at 31052E through E6ED0([CC8528], matrix, class, block) (the block's +0x114 counts shots). The muzzle flash class +0x380 (effects.md#edf41-weapon-effect-keys) spawns at 3109DD.

Basis: fn.py reads of each; fn.py --xref E6ED0 (38 callers, 3 in weapon code 30FDA0 / 311236)

Addresses (build-specific RVAs unless indicated): 314D20, 30FC50, 30FD30, 311D70, 311F70, 30FDA0, 310B80, 31052E, E6ED0, 3109DD

BulletBase shared vtable slots

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-bullet-update

BulletBase's primary vtable A93E48 has 11 slots: SceneObject's 10 plus slot 10 167C00, shared by the bullets read (online only: it returns unless room mode [CC84A0] +0x5C != 0; the network sync, unverified). Bullets override 0, 2 and 9 (SolidBullet01 A95B60: slot 0 162C10 copies the bullet's matrix to its scene node, slot 2 1A05B0 the update, slot 9 19FF30 the destructor; MissileBullet01 A948F0 likewise). SolidBullet01's update walks its hit list (+0x138, 0x50-byte entries, count +0x148): 1A00A0 per hit (hit effects through EffectGenUtil 1B6520..1B3E20), then 1A0320 (hit sounds, 3E83F0 / 3E8150 / 3E3F20); then it moves by the core's mode (core at +0xD0, mode at core +0x200: 0 16B010, 1 16B6B0, each with 10 callers in other bullet classes).

Basis: kh158_vt.py; fn.py reads of the slots and --xref counts

Addresses (build-specific RVAs unless indicated): A93E48, 167C00, A95B60, 162C10, 1A05B0, 19FF30, A948F0, 1A00A0, 1A0320, 16B010, 16B6B0

BulletMtSystem per-frame projectile update

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-bullet-mt-system

Bullets are stepped by BulletMtSystem ([CC89D8], globals.md#edf41-global-singletons-2): the bullet core 168B90 registers each bullet with it (168FC1); the frame update 343A90 calls 16D7B0([CC89D8], ...), which splits the bullets into worker jobs (bullets per job = count / workers, held to 1..20, 16D93B..16D959) and runs 169740 / 16A1F0; their collision queries go through EC970 (from 16A0B0 with kinds 0xB and 0xA, and from 169A50), which reads CollisionFilter [CC85A0]. 343D40 ends the frame's bullet work with 16DEF0. Where a hit's damage reaches the target was not read.

Basis: fn.py --xref CC89D8; fn.py reads of 16D7B0, 169740, 16A0B0 (calls only). The hit-dispatch addition below answers the previously unread target-damage step.

Addresses (build-specific RVAs unless indicated): CC89D8, 168B90, 168FC1, 343A90, 16D7B0, 16D93B, 16D959, 169740, 16A1F0, EC970, 16A0B0, 169A50, CC85A0, 343D40, 16DEF0

Soldier command to weapon fire

Current weapon in Soldier weapon sets

Static, EDF4.1 steam-57aab039. Soldier holds weapon array +0x1290 (count +0x12A0) and 0xA0-byte weapon sets at +0x12B0 (count +0x12C0). Within a set: +8 weapon list, +0x28 selected index and +0x30 current weapon-entry pointer. The held weapon is [[[soldier+0x12B0]+0x30]]. 2B08B0 changes the index, 2B04E0 advances/wraps, 2B0630 and 2B0780 select other slots. Set-zero name is passed to 299760. This layout differs from EDF5.

Controller input-to-Soldier byte map

Static. Controller copy in 29B850 writes soldier command bytes +0x990 fire, +0x992 secondary, +0x994 next, +0x995 previous, +0x996 reload, and +0x997..+0x99E for related actions. With soldier+0x370=1, it also writes second-set fire +0x991 and secondary +0x993. Connecting mode 1 specifically to Fencer hands remains unverified. Other command writers found at 2AAF6A, 2AB0B5, 2AB05E, 2AB0AC and 2B6010 were not read.

Soldier update dispatches fire, secondary and reload

Static. Per-set loop 2B1BA0, with soldier+0x320 bits 4 and 0x80 clear and +0x12CC <= 0, maps +0x990+i to current weapon request +0xC9 and +0x992+i to secondary +0xCB when soldier HP +0x16C > 0. An extra secondary condition at +0x4F0=6/+0xF60 was not decoded. Reload +0x996 calls weapon vtable slot 15 and 2B7D70. EDF5's +0x11A8 request flags do not occur in this EDF4.1 path.

Direct slot keys and switch guard

Static. Direct slot bytes +0x99C..+0x99E invoke 2B0780(soldier,i); next byte +0x994 calls 2B04E0, previous +0x995 calls 2B0630 (the latter inferred from EDF5 layout, not separately read). Only while +0x12E0 <= 0 and +0x320 & 0x80 clear. EDF5's override bit 0x400 and its +0x11A8 |= 0x80 request are absent. The controller input copy above resolves some, not all, previously unread input writers.

Common weapon trigger edge and BasicShoot callback

Static. Update 30E540 transfers fire request +0xC9 to held +0xCA and pressed edge +0xCD, then clears +0xC9; secondary request +0xCB similarly feeds +0xCC and its edge. BasicShoot callback 314DC0 on command 1 reads edge when burst count +0x2F0 > 1, else held; then checks ammo +0x870 > 0, +0xD4=0, timer +0xAB0 <= 0 and clear +0xFEC bit 0 before 311B90(w,1) chooses try-fire 30FB50 or 310DD0. EDF4.1 has no EDF5 semi-auto +0xE3 byte. This refines the earlier try-fire description without claiming a live firing test.

EDF4.1 lock-on parameters and search

Lockon SGO keys and native fields

Static. WeaponBase constructor 30AB70 reads LockonType +0x500, LockonTargetType +0x504, Lockon_DistributionType +0x508, +0x50C as the inversion of AutoTimeOut, +0x50D FireEndToClear, 16-byte LockonAngle +0x510, LockonRange +0x520, LockonTime +0x524, LockonHoldTime +0x528 (both integer inputs stored as floats), and LockonFailedTime +0x530 (integer). Maximum lock count +0x52C comes from FireBurstCount +0x2F0 for distribution zero or FireCount +0x2E8 otherwise. The examined EDF4.1 path has no additional lock-speed/range multiplier or EDF5/EDF6 AmmoCount bound.

Target progress, failure counter and update gates

Static. Tick 30F280 checks LockonType +0x500, drawn byte +0xCE, +0xAB4, +0xAD4 and ready predicate 30AA30; it searches AttackTargetManager [CC8538] up to max +0x52C. Target handle +0x900 increments progress +0x908 by target entry +0x24 each frame, alongside failure +0x920 versus +0x530, 30-frame sound timer +0x938, list +0x8F0 and count +0x8F8, accepted after LockonTime. Called from weapon update 30E540 for types 3/4 and homing callbacks 3168D0/3169C0 while held trigger +0xCA is set; shot-level allocation not read.

Lock cone, duplicate policy and try-fire

Static. 30F1E0 builds matrix +0x890..+0x8CF from weapon +0xE0, angle +0x8D0, unmultiplied range +0x8E0, owner team +0x8E4 and eligible kinds +0x8E8 (3 for type 0, 2 for type 1). Picker 30F670 skips already-listed targets unless their +0x28 is set; there is no EDF5 weapon-side +0x5AD override. 30FB50 refuses an empty lock list and copies lock count into burst +0x2F0 or shot count +0x2E8 based on distribution. Actual per-bullet handout remains unread.

Projectile damage preparation and hit routing

Bullet core's prebuilt damage record

Static. Bullet core 168B90 constructs its hit record at core +0xD0 via B3020 and installs callback 169550 at +0x178/0x180. Core-relative fields: impulse +0x100, damage +0x110 (InitParam +0x24C times multiplier +0x210), blast radius +0x114 from +0x250, value +0x11C from +0x268, flags +0x118: 0x20 when +0x255 set; 2 when radius exceeds 1e-6, marking explosive +0x2DC; 1 when radius at least 3. Core offset displacement from InitParam is +0x1E0. The decoded path does not adjust damage for distance.

Contact queue, target damage message and explosion

Static, resolves an earlier unread segment. Hit step 16A580 puts contacts into queue core+0x80 via 16B740/28C410. Normal flush 28C820 sends hit message 0x80000000 to each target's damage callback (GameObjectBase 28E1F0). Explosive byte +0x2DC instead calls 16BB20 unless +0x2DD prevents it, then clears the queue through 16CEB0. Modes +0x2E0=2 without +0x2F8, or 3, skip both. Explosion optionally scales damage by integer +0x2D4 when +0x2FD, updates record position +0xF0 from bullet +0x330 and calls area hit 28B930(record,out,core+0x140,radius,mask 9). A second 169A50 flush was not decoded; no new in-game damage test.

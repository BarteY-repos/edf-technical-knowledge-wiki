EDF4.1 audio in EDF6 — SE cue names, bank priority, voice playback and shutdown

ConversionAudioEDF 4.1EDF 6
Technical reference · Exact-build RE and source/diagnostic results; no new per-cue runtime verification

One cue name may belong to multiple banks

The documented EDF4.1→EDF6 sound port faced 1,469 EDF4.1 weapon-effect cue names. 1,087 names already appeared in EDF6, while 332 did not. A naive “merge every source cue into the active stock bank” strategy changes the meaning of common names. A naive “load an additional bank and search all banks equally” can also shadow native EDF6 effects.

The inspected EDF6 sound system looks up a cue by name and bank type, returning a (bank pointer, cue index) pair from the first eligible matching bank. In the examined implementation, SE callers request type 0, while voices use a distinct bank category. The source-only compatibility design therefore registers the EDF4.1 SE bank under a private bank type and uses this priority:

1. Native EDF6 SE bank (normal type-0 lookup)
2. Imported EDF4.1 SE bank (private-type lookup when stock misses)
3. Finite resident fallback for selected source cues if the imported bank is absent

For source objects that explicitly need their EDF4.1 identity, the retained implementation has source-aware exception handling; this is not a universal native-first policy for every sound in every mod. In particular, the finite fallback table avoids substituting an indefinitely looping cue where no caller can stop it.

ACB identity is not just the file name

The EDF4.1 weapon SE bank (TIKYUUX_SE.ACB) carried a name/GUID that collided with EDF6's own bank identity. Its AcfMd5Hash also belonged to a different ACF configuration. The documented converter patches fixed-width identity fields to form EDF41_WEAPON_SE.ACB, using a distinct bank name/GUID and the target ACF hash, without moving the @UTF tables. These are bounded observations about the exact studied CRI ACB 1.23 and EDF6 runtime, not instructions for arbitrary ACB rewrite.

Why the same Mods path works for ACB but fails for AWB

The examined engine has two file-access paths:

  • An ACB may be read through the game's hooked/redirected stream layer. An app:/sound/pc/... request can reach a virtual /cri_bind/... path and be redirected under Mods/SOUND/PC.
  • The AWB audio table of contents can be opened by CRI's own filesystem, bypassing the game stream hook. A seemingly successful AWB existence test and accepted _LIST.AWE are therefore insufficient: the CRI TOC load can still return null.

In the documented fix, voice loading requests an actual readable path such as ./Mods/SOUND/PC/EDF41_VOICE.JA.AWB. With a raw virtual /cri_bind/... path, the game-level existence probe and AWE reader succeeded but CRI's TOC load did not. This explains the otherwise misleading symptom “bank exists, no voice plays.”

Do not automatically transfer this exact directory convention to every loader version; the principle is to find which subsystem performs the final physical open.

Voice AWB / AWE and subtitles

EDF4.1 provides JA and EN source voice audio. The investigated converter promotes the source AWB version byte to 2 for the target-compatible bank and writes an AWE v2 list containing names, wave IDs and cue duration derived from each HCA wave's header. Subtitles use EDF6's voice table rather than replacing its native rows.

The game looks up the caption using the voice cue name after stripping one trailing _E or _S, never an embedded substring. When extra caption data is unavailable, the documented source-only approach retains the cue identity and falls back to available language text rather than deleting a cue.

The audio source intentionally includes only two recorded language banks. A locale without a matching EDF4.1 recording may fall back to JA and then EN, but subtitle language and recording language remain separate decisions.

Bank lifetime can cause a crash on exit

The sound system uses a reference-counted bank cache. The loaded SE bank must return its cache reference before the game destroys the sound system. If a mod retains its final reference until a later atexit destructor, cleanup can attempt to unregister a bank from a null sound-system pointer. The researched failure manifested as a shutdown crash rather than a gameplay sound failure.

The maintained adapter releases its cache reference at the application's normal shutdown boundary, while the sound system still exists. This is a broader lesson for native mod loaders: successful sound playback does not prove correct resource lifetime.

Status and verification boundaries

The retained evidence combines target-binary path analysis, historical runtime diagnosis and source implementation. It does not prove every cue in every user installation plays correctly. Verify bank identity, cue hit/miss counts, CRI TOC success, playback, voice-text lookup, locale switching and shutdown separately. Offsets and hook locations are build-specific, not public API contracts.

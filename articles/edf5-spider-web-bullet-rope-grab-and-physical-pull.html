EDF5 spider webs: ten rope nodes, capture state, reel-in and release

EDF 5Game technical referencesEnemy mechanics
Technical reference · Source-declared grades; this edition does not add native game runtime testing

An Aranea's web is not just a line sprite with damage. In the examined EDF5 code, SpiderStringBullet01 and SpiderStringBullet02 own rope-node arrays and render their strands through the game's line-strip path. A successful hit can create a separate grab object, modify the soldier's capture state and pull the target toward an anchor.

The rope, graphics and warning color

Each constructed spider-web bullet receives exactly ten rope nodes. For the inspected type-01 path, 0x30-byte rendering vertices are rebuilt from the rope nodes every update, with position, RGBA color, longitudinal texture coordinate and strand width. Type-02 also has a separate vertex vector and draw path. Consequently a strand's line is geometry updated by the bullet, not a static MDB pasted between two endpoints.

Type-01 webs attached to a locally controlled player can switch to a warning state: the renderer alternates ammo color and red with a phase advancing at approximately 10 Hz. The source investigator observed that flashing when an Aranea held and reeled in the player. Not every white spider strand in a scene was successfully identified with one of these two callbacks; a level-placed SpiderNet object remains a possible separate source.

Capture requires a grab object

On a qualifying web hit, a native callback tests the hit rope node and candidate target, constructs a 0x150-byte grab object and links it to the web's active capture list. The grab records the node, initial target–anchor length, stall/best-distance state and owner. Capture messages travel through the soldier's game-object handler and transition it to a held state, rather than simply applying damage or changing an animation.

The source notes that some shield and online conditions can refuse an attach. A particular SpiderStringBullet01 online flag skips an attach path; do not generalize that into “spider webs never capture online.” The source also has a distinct kind-1 grab/guard condition.

How the web reels in the player

The type-01 held-target update reduces the rope's permitted length by about 0.05 metres per 60-Hz frame, approximately 3 m/s, once taut. It updates a hold point; the held soldier then receives an additional velocity equivalent to roughly six times the gap per second between itself and that hold point. At sufficiently high pull speeds, the walk state is altered to prevent opposing movement from counteracting the pull in the same way.

The web releases captures when the owner disappears, the target no longer exists, or the target's capture state no longer matches. It can play a reeling sound for a local player's target; release messages have their own talk-line logic. These interactions are separate from the drawing of the visible strand.

Evidence boundary

The ten-node layout, grab structure and pull math are static reverse engineering of steam-5d11de53. The flashing appearance and some rendering changes are source-reported gameplay observations; no new capture test was performed here. Some SpiderStringBullet02 behavior and a universal on-screen direction arrow remain open.

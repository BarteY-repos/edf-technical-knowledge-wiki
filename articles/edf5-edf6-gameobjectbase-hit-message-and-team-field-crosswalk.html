EDF5 versus EDF6 GameObjectBase: object fields, teams and hit-message IDs

ConversionGame technical referencesEngine / cross-generationEDF 5EDF 6
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R133 test

GameObjectBase, SoldierBase and TeamManager are recognizable by RTTI across these two games, but field offsets and message identifiers changed. A value that means team or HP in one executable cannot be copied to the same offset in the other.

Selected game-object fields

Concept EDF5 offset EDF6 offset
World-position matrix row +0xA0 +0x90
Maximum HP +0x1F8 +0x2F4
Current HP +0x1FC +0x2F8
Team ID +0x218 +0x314
Local-pad index +0x23C +0x338
Local-player link / controller +0x240 +0x340
Object flag word +0x280 +0x380

The values are valid only for the versions and class contexts described in the native studies, not all arbitrary derived classes. In EDF5, a dead-state bit appears in the flags word; EDF6 also exposes a dedicated dead byte at +0x2E8.

Team membership and logical identity

Both games store team-member sets in an MSVC tree with similar record sizes. EDF6's native TeamManager still uses 0x38-byte team rows, a lock and a relation table. Its default constructor initializes seven teams, while the class's address and many surrounding object fields moved relative to EDF5. A numeric team ID also has relations (friendly, hostile or neutral) rather than representing a simple boolean enemy flag.

Hit records and lethality

The original code sends lethal/damage-related messages through virtual handlers with different message IDs: EDF5 uses 0x80000000 in the studied object-hit path, whereas EDF6 uses 0x10000000 for its corresponding path. That is an important ABI boundary: a message tag is not a cross-generation serial format unless its handler and record structure match. EDF6 also distinguishes forced hits that bypass immunity/spot-damage conditions.

Evidence: static field-by-field source RE, historical EDF5 contributor tests of invincibility/team-state changes, and native message-handler comparison. Do not transplant offsets or hit-record byte layouts wholesale across versions.

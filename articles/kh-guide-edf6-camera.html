EDF6 Camera View Matrix and Ride Mode

EDF 6Community Knowledge HubGameplay & AI
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

EDF6 inherits the broad idea of follow-versus-ride camera behavior but uses different native offsets and function sites from EDF5. Reusing an EDF5 tail patch byte-for-byte is not valid.

Format, API or behavior

The contributor locates EDF6 follow and ride mode routines and the final camera rotation rows at +0x220/+0x230/+0x240 with eye at +0x250. It also records camera and vehicle-related vtables for precise source-to-target comparisons.

Ghost camera follow ride modes — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (417 characters)

Follow mode is FAF20 and ride (vehicle) mode is FB9F0. Follow switches to ride at FB93E-FB97C when the target's ride control block [target+0x1550] has users; ride switches back at FBBF3-FBC33. The mode state slot is camera+0xBF0, set by FADF0. The riding predicate F7210(camera) -> bool (camera+0x358 users, +0x360 non-null, [[+0x360]+0x1550] users) has no direct callers; the same test is inside vtable slot 9 F7500.

Ghost camera final matrix — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (283 characters)

The final camera matrix is camera+0x220 / +0x230 / +0x240 (rotation rows) and +0x250 (eye). The ride mode writes it at FC0DB-FC106 and the follow mode writes the rows at FB907-FB919. After the mode call, Update multiplies the rows by the shake matrix +0x280..+0x2A8 when shake is on.

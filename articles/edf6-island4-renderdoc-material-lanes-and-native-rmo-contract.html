EDF6 Island4 RenderDoc material evidence: reflect/spec vs artist RMO

EDF 6Materials & ShadersShaders
Technical reference · 3 modified-run captures + 2 control captures; exact shader resource strings; final shader translation pending

Evidence: Three preserved modified-runtime R6B captures, two control captures, the 11 September 2026 RenderDoc material report and a separate 9-entry capture SHA-256 ledger. This is a bounded investigation of ordinary static MDB material rendering on Island4. It is not a generic FieldRender/FMEP texture contract, nor an in-game confirmation of a finished replacement shader.

Why a loaded texture can still appear chrome-like

The artist's source packed mask is R = roughness, G = metallic, B = ambient occlusion, used with the artist-side snd_BRDF_Common_Basic group and param_r_m_occ_hr slot. In the R4C/R6B static-MDB control, a reflect/spec-style mask contract received that artist RMO texture instead. This is an interpretation/binding mismatch, not equivalent to missing ss_island4-rmo.dds.

R6B runtime logging admitted ss_island4-df.dds, ss_island4-nm.dds, ss_island4-rmo.dds and ss_island4_00001.mdb. Its 2,048-byte MDB0 runtime dump prefix matched the expected package prefix byte for byte, SHA-256 b915c7431e9d210a8ec0a19c62b378712cfa8ed8dcccb81b9c05474c3f359e22. That rules out stale RAB/wrong package/early MDB corruption for this run, not every possible late material or shader bug.

The full hashes and string sets are in data/R158_EDF6_ISLAND4_RENDERDOC_FOUR_SHADER_OBSERVATIONS.csv. The control/R6B shader reflections each list three samplers aligned to their three reflected resource lanes. These captured DXBC strings are compiled runtime evidence, but they do not prove a specific snd_* source shader filename or the final exact mathematical channel interpretation for all families.

What the native map corpus actually supports

The sampled native IG_HEIGEN507.RAB and NW_EUROPE01.RAB contain 52 and 49 snd_BRDF_Map_Common materials, respectively, with native samplers albedo, normal, param_r_m_xxx_hr. There are 29 and 15 snd_BRDF_Map_Common_Clip samples across those same areas. The Europe sample also contains five snd_BRDF_Map_Common_Light profiles with param_r_m_light_hr and one signboard-pattern sample with param_r_m_occ_light in its samplers.

The artist's exact snd_BRDF_Common_Basic shader family was not found in the audited native map corpus. A proposed R7 material using that identity and RMO slot conserved the recorded geometry bytes offline, but was not packaged or runtime-qualified by this report. Its parameter ordering/type choices therefore remained partially inferred rather than copied from an exact native profile for the artist shader.

Negative tests narrow the cause, not the final answer

Temporary roughness=1 and native-no-AO mask candidates reduced the shine in earlier R5B/R5C runtime checks, but were not artist-faithful solutions. Later R6A/R6B modifications using Build Simple / Object no-CCAO did not repair the chrome-like response. These outcomes argue against more blind swapping of reflect/spec shader names and for exact R/M/O semantics with an ABI-qualified material.

Three separate quality axes

  • Material: RMO mask read as reflect/spec causes wrong response despite valid resource load.
  • Texture resolution: the x20 static map still uses a 4096² atlas; area-weighted density and anisotropy remain problematic even if roughness is correct.
  • Terrain backend: static MDB shaders and their parameters are independent from FMEP/FieldRender projected texture arrays, leaf wrappers and MAC resource registration.

Neither a valid source DDS nor a byte-exact MDB model is a visual-compositing PASS. A completed, artist-faithful material translation would require the actual shader family, parameter type/order, sampler bindings, render state and a matched runtime visual test.

How this case should be read beside the broader shader corpus

The EDF6 shader inventory's 485 DX11 archive entries / 3,449 DXBC programs is an offline census. Island4's four retained pixel-shader observations, in contrast, identify compiled paths seen in bounded captured runs. Those are different sample populations and must not be numerically combined or presented as four newly proven shader families.

The Island4 evidence establishes a particularly useful diagnostic separation:

Stage Observed result Still not established
Asset admission MDB/texture records were accepted and the tested prefix matched Every later material command and its final visual interpretation
Reflected resource contract Reflect/spec and R/M/O pixel-shader samples expose distinct parameter names Automatic equivalence between the artist R/M/O texture and an unrelated reflect/spec binding
Captured shader Specific DXBC hashes identify the programs Complete scene-wide equivalence for every model/material
Final image Diagnostic material changes reduced shine in some runs An artist-faithful native pixel/compositor reproduction

This is why texture presence, shader presence and attractive final pixels are separate claims. See the five-family proof matrix for the state/binding/pixel evidence required to promote a material rule.

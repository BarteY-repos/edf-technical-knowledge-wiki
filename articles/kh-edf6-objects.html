Evidence: static · Build: steam-678ccb46 · Fact ID: factory-map

The scene-object factories live in an MSVC std::unordered_map<std::wstring, std::shared_ptr<factory>> at game system +0x2C8 (list head +0x2D0, bucket vector +0x2E0, mask +0x2F8; key hash FNV-1a): GetSceneObjectFactory 1195C50 hashes the name and walks those fields, so the "EntityFactory array" at +0x2E0 of globals.md#game-system-fields is this map's bucket vector. GameObjectBase snapshot vtable entry

Evidence: static · Build: steam-678ccb46 · Fact ID: fn-54b010-snapshot

54B010 (slot 0 of the GameObjectBase vtable and of more than 20 derived ones, the xgs::snapshot::IRecordable base of classes.md#gameobjectbase-hierarchy) writes the object's state as named keys, not a per-frame update: it first calls 118A620 (the SceneObject part), then for each field builds a wide-string key and passes the field's address to a writer (11B3B80, 11B3BE0, 11B3F20, 544D90): m_flags +0x380, m_base_level +0x498, m_is_encount +0x4A0, m_route_explorer +0x4A8, m_move_speed +0x4B8, m_way_point_update_distasnce (the game's spelling) +0x4BC, m_way_point +0x4C0, ...; an ai group is written only when 11B38B0 returns nonzero. These are the game's own member names for the fields of gameobjectbase-layout. KittopiaCreator's name OnSnapshot fits; the engine-abi table's "GameObjectBase update" (archive/engine-abi.md) does not, though its prologue check stands. The per-frame update is slot 5 54BE40. Settles the conflict of fn-54b010-name.

Basis: decoded the first 300 instructions (fn.py); key strings read from EDF.dll at 17B5C2C, 17929D0, 17929B0, 17CD838, 17CD858, 17CD880, 17CD8A0, 17CD8E0

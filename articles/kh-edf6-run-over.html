The vehicle's contact component (map props only)

Vehicle contact component embedded offset

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-vehicle-contact-component

Every vehicle embeds a contact component at veh+0x680 (constructor 6F0B70, called from VehicleBase's constructor at 62952A; vtable 17E8028): +0x08 the owner, +0x18 / +0x28 the subscribed bodies (0x10 each), +0x30 a hit record (+0x80 its damage, 0; +0x90 its flags, 0x04; +0xA0 its point vector), +0xC0 a queue, +0x108 the mode (0 off), +0x10C the impulse scale (1.0), +0x110 the blast value (1.0), +0x114 a contact threshold (FLT_MAX). The same class is built by 16 other constructors (among them MonsterBase 4B5230, UfoSmall507 5284F0, Barga 601420, the insects' 4164C0, 4253F0, 43DE70, DeiroiFootParts 329000), all subscribing through 6F0F70 or 6F0EA0 to the same callback.

Basis: fn.py read of the constructor; --xref of 6F0B70 and 6F0EA0

Addresses (build-specific RVAs unless indicated): 6F0B70, 62952A, 17E8028, 4B5230, 5284F0, 601420, 4164C0, 4253F0, 43DE70, 329000, 6F0EA0

Vehicle contact callback restricted to map props

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-vehicle-contact-callback

The callback 6F1220 (and its sister 6F1480, which takes a body record) sends hits only to map props: it returns when the mode is 0 or the event's byte +0x10 is not 2 or 4; reads the contact with DD2480 and needs its +0x14 below +0x114; skips when the own body's velocity (11B1300) dotted with the contact normal is above 0 (6F12FD, moving apart); casts the other body's owner (key 0, 108200) to MapObject_Base (TD 200F080) in 6F1840, and stops when that fails (6F1336). Mode 2 takes any prop; mode 1 only props whose map definition category ([obj+0x1C8], map-collision.md#map-object-durability) is 2, 4, 5 or 6 (127130, mask 0x74). Then 126E50 (it passes for the record's flag 0x04) and a NetworkObject test ([obj+0x120] slot 3) gate 6F1640.

Basis: fn.py reads

Addresses (build-specific RVAs unless indicated): 6F1220, 6F1480, DD2480, 11B1300, 6F12FD, 108200, 200F080, 6F1840, 6F1336, 127130, 126E50, 6F1640

Contact record team, position and normal

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-vehicle-contact-hit

6F1640(comp, point and normal, contact, blast?) fills the component's record: team = the vehicle's +0x314, position, impulse +0x40 = the contact normal x the scale +0x10C, damage 0 (zeroed by 6F0F70; no vehicle code writes veh+0x700), flags 0x04, blast +0x58 = 1.0 only for a mode-2 prop outside categories 2, 4, 5 and 6, else 0 (the flag is 127130 == 0, 6F13FF), one hit point (body id), then queues it for the prop with 541FF0; the vehicle's slot 3 function (630220) sends the queue every frame (6F15B0 -> 543920, at 63027E). So a vehicle pushes and breaks map props (cars, poles, small objects) through hits, and characters never get one.

Basis: fn.py reads; corrects the older reading "a vehicle running someone over" (now damage-model.md#non-bullet-hit-senders-2)

Addresses (build-specific RVAs unless indicated): 6F1640, 6F13FF, 541FF0, 630220, 6F15B0, 543920, 63027E

Vehicle component does not damage civilians

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-civilian-no-run-over-hit

No code turns that contact into a hit: the vehicle's component casts to MapObject_Base only (#edf6-vehicle-contact-callback), car_base_ragdoll_contact (Blacker: ["戦車衝突" (tank collision), 3000.0, 0.15, 7.0, 8]) only plays a sound and shakes the camera (corpses.md#ragdoll-layers-death-contact), and there is no impact damage (havok-runtime.md#no-native-impact-damage-2). So a civilian in the way is shoved by the solver, without damage or knock-down (inferred; not seen in game).

Basis: the lines named; the shove inferred from the layers and the absent code

PeopleGenerator (TD 2015CF0, vtable 17D1FD0

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-people-generator

PeopleGenerator (TD 2015CF0, vtable 17D1FD0; snapshot-recorded) keeps a list (+0x1E8, count +0x1F0) of MobObject nodes (object +0x10, control block +0x18, state +0x20); its slot 5 58BC30 drops the nodes whose object has expired. The knock-down hit (soldiers, NPCs and civilians alike)

HumanBase's OnDamaged 5717D0 returns at once unless the damage +0x50 0 (571850)

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-human-knockdown-gate

HumanBase's OnDamaged 5717D0 returns at once unless the damage +0x50 > 0 (571850). A blast +0x58 above 1e-6 (17659F8) knocks the human down when +0x1181, +0x39C, +0x1182 and +0x1183 are all 0 (571D4B..571D8C): it enters the down state (56C9B4, the object's vtable slot +0x250) through 551C30 unless it is in it already; for a player (slot +0x108) D9230 on the hit's team decides first. Otherwise (no blast, or already down) it starts a 30-frame flinch timer +0x11B8 (572303). 577470(self, n) acts only with a pad (+0x340): entry n of the vector +0x11A0 (0x80 each; 0 flinch, 1 knock-down, 3 death) goes to 7B4510 (pad feedback, inferred).

Basis: fn.py read of 5717D0 (dump t6_5717D0.txt)

Addresses (build-specific RVAs unless indicated): 5717D0, 571850, 17659F8, 571D4B, 571D8C, 56C9B4, 551C30, D9230, 572303, 577470, 7B4510

Ragdoll launch impulse construction

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-human-knockdown-velocity

The launch, with the ragdoll active (+0x1180): c = a point of the ragdoll's box (6E9B50), d = c - the blast center +0x30, t = (R - |d|) / R with R the blast value; direction = d/|d| + (up - d/|d|) x t x 0.5 (1C36990 = 0.5, up 1C36A80 = (0, 1, 0)); speed = 8 x ln(R) (176614C = 8; 12DA93C is logf), set as the ragdoll's velocity (4D940, 6ECF20), plus a random spin (6E6300); each hit point's body also gets an impulse along its own offset of 8 x ln(max(R - distance, 0)) (11B0CB0 at 5722AF). So the speed depends on R alone: R 1 gives 0 m/s, 2.72 gives 8, 6.5 gives 15, 20 gives 24; below 1 it points back at the center. A hit without blast on a human already down adds 10 x ln(|impulse +0x40| x 0.0125) m/s along the impulse (57232A..572398, 17A8818, 6E6110).

Basis: fn.py read; constants by scratch flt.py; 12DA93C jumps through the import of logf

Addresses (build-specific RVAs unless indicated): 6E9B50, 1C36990, 1C36A80, 176614C, 12DA93C, 4D940, 6ECF20, 6E6300, 11B0CB0, 5722AF, 57232A, 572398, 17A8818, 6E6110

Route and open questions

Proposed civilian impact and launch routeSource: unverified

Evidence: unverified · Build: steam-678ccb46 · Fact ID: edf6-run-over-route

Route to send civilians flying when a vehicle hits them (00v topic 6): (a) find the contact: in the vehicle's own callback, where 6F1840 returns 0 (6F1336), cast the owner from 108200 to People (TD 2046590); it runs only for vehicles with a mode (#edf6-contact-map-values) and only for bodies moving into the contact; or query a box at the bumper each frame (11A70B0, layer 13 meets 5, the human hit bodies; keep only People). (b) Build a hit as 6F1640 does, with the vehicle as attacker, team -1 or flag 0x20 (a friend test returns before OnDamaged, damage-model.md#apply-damage-order), damage above 0 (a token amount if no harm is wanted), blast R = e^(speed / 8) from the vehicle's speed and its center behind the civilian along the vehicle's travel, nearer than R so the throw tilts up (#edf6-human-knockdown-velocity). (c) Queue it with 541FF0 and let the vehicle's per-frame send (630220 -> 6F15B0) deliver it. Untested.

Basis: from the lines above

Addresses (build-specific RVAs unless indicated): 6F1840, 6F1336, 108200, 2046590, 11A70B0, 6F1640, 541FF0, 630220, 6F15B0

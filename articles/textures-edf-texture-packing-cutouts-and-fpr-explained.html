EDF texture observations: DDS, packed masks, BC1 cutouts and FPR

UniversalTexturesEDF 5EDF 6
Technical reference · Reconciled source and sampled runtime research

EDF materials often put multiple logical values into different channels of one texture, and the channels have meaning only in combination with the chosen shader family. A texture can be valid DDS and still be wrong for the material that reads it.

Packed channels for ordinary MDB BRDF materials

In the studied param_r_m_* Common-family materials, G modulates metallic and R modulates roughness. For _hr textures, alpha is another roughness multiplier. Normal textures in the studied Common/Water-like path decode X using R×A, Y from G and reconstruct Z. See MDB shader equations.

Do not generalize these rules into universal FPR channel conversion or FieldRender normal decoding. Older reflect/spec textures, _hr material masks, change-color masks and true field terrain arrays are different semantic families.

BC1/DXT1 cutout textures are a real native path

An observed EDF6 foliage texture sk_pShrub003-df.dds used BC1/DXT1 one-bit transparency. In its top mip, all 32,768 blocks were in the transparent (color0 ≤ color1) mode, and 427,079 pixels selected the transparent palette entry. This proves one native cutout example, not a requirement for all EDF textures.

The mipmap coverage problem

An offline source-owned 64×64 test retained 50% transparent coverage down to 8×8, but a naive majority downsampler produced 0% transparency at 4×4, 2×2 and 1×1. That can make distant cutout foliage look opaque. A tested deterministic, optional coverage-preserving BC1 mip policy retained 8 transparent pixels at 4×4 and 2 at 2×2, while 1×1 cannot represent a 50% fractional pixel.

This is a useful authored-texture repair strategy, not a recovered universal native Sandlot mip-generation algorithm or proof of in-game visual parity for all assets.

Resource binding is separate from image content

In a runtime-positive custom-texture case, logical MDB texture identities, authored HD/LOD DDS payloads and canonical archive insertion worked as a coherent chain. The identity and reference metadata are not interchangeable with the DDS bytes. A converter that writes valid mipmaps but leaves the material bound to the wrong resource has not finished the conversion.

For detailed FPR/mask exceptions and native tests see DDS, FPR and texture-binding research, native material ABIs and FieldRender texture arrays.

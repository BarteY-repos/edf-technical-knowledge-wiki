EDF5/EDF6 native camera: projection, zoom, ride locators and collision

ConversionGame technical referencesGameplay & AIEDF 5EDF 6
Technical reference · Source-corpus/static reverse-engineering; no new game runtime test

Evidence: source-attributed reverse engineering and contributor-reported experiments from EDF Knowledge Hub (snapshot 14 November 2026). Offset and routine names belong to the named builds; the wiki has not independently repeated every disassembly or executed new gameplay tests.

Vertical field of view and native projection

Both games use the CharacterGhostCamera / SceneCamera family. The base vertical FOV is approximately π/4 radians (45°). In the examined EDF6 build (steam-678ccb46), a normal scope update computes:

live_vertical_FOV = (π/4) / camera_zoom

The calculation in CharacterGhostCamera::Update F86A0 writes camera +0x24 from camera+0x410 (F890E–F8916). Therefore, for zoom 1×, 2× and 4×, the mathematical camera values are approximately 45°, 22.5° and 11.25°. These are FOV values, not a claim about the actual number of zoom settings of every weapon. A separate state transition may blend FOV; observed mode-dependent behavior must not be flattened into a universal one-line rule.

The EDF6 projection builder 118D9F0 uses:

EDF6 camera member Meaning Evidence
+0x20 Reference/base vertical FOV Static
+0x24 Live vertical FOV, radians Static
+0x28 Near plane, normally 0.1 m Static constructor
+0x2C Far plane Static; scene FarClipZ varies
+0x198 / +0x19C Width/height used for aspect in the projection path Static; exact ownership of dimensions inferred
+0x410 Current target-derived zoom in ordinary follow update Static

EDF5 steam-5d11de53 uses the same +0x24/+0x28/+0x2C SceneCamera projection fields, with the examined constructor values FOV ≈ 0.785, near 0.1 and far 1000. The surviving field locations do not imply that entire camera class layouts are interchangeable between games. The final camera matrix is at +0x1A0…+0x1D0 in the studied EDF5 build but +0x220…+0x250 in EDF6.

Zoom reaches the camera through the weapon and soldier

EDF6's weapon resource fields SecondaryFire_Type and SecondaryFire_Parameter are loaded into weapon state. A supported scope toggle changes a per-weapon zoom value from 1.0 to the configured magnification and back. Soldier update collects the maximum active weapon zoom into human+0x1D0; the camera's target/look block then supplies camera+0x410. This chain explains why weapon zoom is not a blanket camera setting shared by every vehicle or seat.

In the examined EDF6 code, the ride input path is distinct from infantry aim input, and the investigators did not find a seat/vehicle writer of the scope-toggle input bit in the inspected range. Some vehicle weapon SGO resources contain a SecondaryFire_Type value, but that alone does not demonstrate a functioning native vehicular scope toggle. The native ride state also does not simply repeat every follow-state FOV update.

Zoom, view-distance scaling and culling

EDF6's projection / far-view code uses a zoom-related view-distance ratio of the form:

distance_ratio = tan(live_FOV / 2) / tan(reference_FOV / 2)

The reported routine 118DCD0 computes this ratio and view-submission paths 1197F31 / 1197FBD pass it to later distance tests. A zoomed image and the range at which models are submitted are therefore related in the examined renderer. Do not treat a FOV-only modification as proof that every form of object culling and far drawing remains unchanged. The exact view variants and special byte-state paths still matter.

Native vehicle ride camera and model-authored locators

EDF6's ride camera uses vehicle_riding_position and locator records in the vehicle animation model (MAB). Its seat constructor can record an eye locator, a look-target locator, parent bones, easing parameters and XAngleAdjust. The frame's camera view is constructed from these locations and the current vehicle bone transforms. The relevant examined seat fields include:

Seat field Native interpretation
+0x200 Ride camera Type; 0 for missing specialized mode
+0x208/+0x210 Eye locator and parent bone
+0x218/+0x220 Look-target locator and parent bone
+0x228 Camera easing parameters
+0x230 Pitch adjustment factor XAngleAdjust, default 1.0

Selected values reported from vehicle MAB game assets (positions are local to the relevant parent bone, not global scene coordinates):

This explains the reported behavior where raising the gun can move a gun-bone-attached eye behind a vehicle component and allow the hull to obstruct the view. It is a model/seat/animation interaction, not evidence that EDF6 supports a universal hardcoded first-person optical sight.

Camera collision and obstruction

The EDF6 ride camera routine identified as F6760 uses collision queries between the desired look point, final look point and camera eye. A hit can move a point to the contact point plus the contact normal multiplied by the current camera offset (reported as 0.1 m for one initialization). The EDF5 follow-camera investigation separately reported Havok shape sweeps used to bring the eye closer to the character when a building obstructs it.

Camera collision, projectile collision and enemy AI line-of-sight are not the same test. An obstructed vehicle camera does not prove that the vehicle's gun or AI is blocked by the same surface.

Reported frame/input behavior

One contributor's EDF6 offline gameplay test observed uneven mouse-look steps despite even frame pacing: the right stick produced equal angular steps at the tested deflection, while mouse yaw changes were quantized to cursor pixels and intermittently larger. That is a specific observed run and input configuration, not a universal performance diagnosis. It does not establish which internal stage caused the irregular steps.

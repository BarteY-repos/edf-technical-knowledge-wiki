Wing Diver Plasma Cores: energy budgets and CustomParameter entries

ConversionCommunity Japanese WorkbookGameplay & AIEDF 5EDF 6
Technical reference · Translated contributed workbook notes; sample data, negative experiments and explicitly labeled inferences

What the workbook actually describes

The Japanese EDF research workbook compares displayed plasma-core energy statistics with resource values and traces several CustomParameter numbers to behavior. Its examples appear to concern the EDF5/EDF6-style Wing Diver core system, but the workbook does not provide a complete, cross-build parameter registry. A parameter number observed in one core is not necessarily an engine-wide enumeration.

Directly annotated parameters

Number Workbook observation Confidence
204 Post-takeoff vertical lift. In the example 0.5 allows takeoff but gradually loses altitude while holding flight; 0.6 gives slight ascent. Big Bang Core's unusual altitude behavior is associated with 204=0.4. Contributor's experiment/interpretation; source 解析!B292:D295
210 Possible recoil reduction; the Big Bang Core example uses 4. The author explicitly says this is not the cause of Big Bang's altitude restriction. Hypothesis; 解析!C294:D294
201 Boost energy-consumption multiplier. The author lists specific changes for custom cores, such as 2.25 for VM Jet and 0.55 for Assault; not a universal baseline for every core. Workbook configuration notes, 解析!A836:K855
205 Flight energy-consumption multiplier, e.g. 0.9/0.8 in two experimental Surface cores. Workbook configuration notes
209 Emergency recharge multiplier in selected examples; effect direction depends on the consumer, not just the numeric label. Workbook configuration notes
206 Normal recharge multiplier noted in the EXAM Reverse example. Workbook configuration notes

Keep 210 tentative: its Japanese annotation includes “thought to be recoil reduction” (反動軽減と思われる). Do not relabel it as an independently verified native symbol.

Ratios and capacity calculations

The workbook's core stat table lists maximum energy, absolute consumption, and percentage of maximum energy for charging, emergency recharge, flight and boost. The percentage columns are calculated as:

percent = absolute value / max energy × 100

For the workbook's example VZ core (解析!A840:J840), maximum energy is approximately 1405.5222; displayed rows contain normal charge 84.3, emergency 210.8283, flight 210.8, and boost 63.2. Those yield roughly 6.0%, 15.0%, 15.0%, 4.5% of capacity respectively. This is a reconstruction of the workbook's example, not proof that every gameplay subsystem consumes energy using these exact per-action values.

The author hypothesizes that base percentage relationships are hardcoded and that a core's custom parameters then multiply them (解析!A845). In the experimental “Jailbreak” core, a flight multiplier of 10 and boost multiplier of 25 give very large displayed costs (解析!A854:K854), but the workbook does not establish how every resulting edge case is clamped in-game.

Editing and validation rules

  1. Treat CustomParameter identifiers as measured source annotations. Retain them numerically until the binary consumer and data path are validated.
  2. Distinguish takeoff impulse from sustained hover ascent: 204 can permit lift-off and still result in a gradual fall afterward.
  3. Test flight, hover, boost, recharge and weapon recoil independently. A visible change in one does not imply the others share the same parameter.
  4. Do not extrapolate EDF5/EDF6 semantics to EDF4.1 without a paired native case.

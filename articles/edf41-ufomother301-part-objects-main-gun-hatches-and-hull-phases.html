EDF4.1 UfoMother301 mothership: separate parts, generator hatches and phases

EDF 4.1Game technical referencesBosses and objects
Technical reference · Attribution and grade per source fact; this edition adds no game runtime test

The classic EDF4.1 mothership UfoMother301 is not one static mesh with a single monolithic weapon script. Native research identifies a hull, a shared parts base and separate hatch, panel, cannon and BigCannon classes, all derived from GameObjectBase. Each part is a game object with its own durability, state machine and, where applicable, scripted handle.

Hierarchy and source data

The hull's UfoMother301.sgo references the body MRAB/MDB, a CAS animation, a ragdoll SHKT, damage data, effects and named groups of child SGOs. The observed assembly includes:

Part group Source inventory Role
mp_BigCannon 1 Primary heavy gun
mp_Cannon 10 Secondary gun array
mp_Panel 125, arranged in four groups Shield/armor-panel ring with weapons
mp_HatchLow 4 Enemy-generating hatches
mp_HatchMiddle 4 covers Covers sharing the hatch part class

Part placements use an SGO-relative Euler rotation plus offset against the parent waist node. The independent parts lists permit an ObjectAction command to enable, disable or trigger attacks by type without respawning the whole hull. GetPartsObject (mission native 3300) returns a handle to a named main-gun or medium-gun part; it is therefore wrong to model every gun as decorative geometry only.

State machines and timed changes

Part state updates receive a phase 0 enter, 1 update, 2 exit and track elapsed time/frames. The source notes distinguish dt in seconds from 60-Hz update-frame counters. Selected sounds are throttled via shared hull counters (approximately 16-frame windows), preventing every panel from playing the same cue on one frame.

The main BigCannon has closed, opening, ready, charging, firing and closing states. Its ordinary direct bullet uses LaserBullet02, with special parameters on every eighth shot; the source's recorded direct base damage is 5000, not a generic value scaled with the mission-level factor. The ten medium cannon objects have a separate rocket/beam cycle and projectiles. Panels are a third family with type-specific laser or plasma fire.

mp_HatchLow is not simply an SGO name for a spawn position. Each real hatch owns an ObjectGenerator, and mission messages can configure its resident or one-shot waves. A named MAB locator (発生位置) supplies its actual spawn transform. Enemy creation is under host control in the analyzed network path.

The hull's exposed weak point and fall

The hull has a state machine separate from its parts. Following the opening and loss of the main gun, its weak section can be exposed, then hide after a delay and reopen. The source finds a 540-frame hit-related countdown before a hide and a 30-second hidden interval in a particular state sequence. These are state-specific timers, not a promise that every scripted mission shows the same choreography.

On hull death, the code changes glow, stops attacks and produces staged explosions before a falling phase with Havok ground probing. The death choreography can extend well beyond the instant the durability reaches zero.

Evidence boundary: This is static analysis of EDF4.1 native code and source SGO/mission data, not a new boss fight. Exact native addresses such as 0x24ECE0 (hull constructor) and 0x250870 (hull messages) are tied to the studied EDF4.1 build. Some mission-specific behavior depends on ObjectAction, object durability events and difficulty/level multipliers.

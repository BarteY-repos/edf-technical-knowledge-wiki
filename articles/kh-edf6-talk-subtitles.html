EDF 6 — Talk Subtitles (community source notes)

EDF 6Community Knowledge HubAudio
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Facts

The talk system is the singleton TalkManager at 20B29C8 (RTTI TalkManager, ut::sgs::SingletonTalkManager)

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-classes

The talk system is the singleton TalkManager at [20B29C8] (RTTI TalkManager, ut::sgs::Singleton<TalkManager>). A spoken line is a TalkActorBase subclass: TalkActor_Object (a line spoken by an object; vtable 17D6E90: 0 destructor 5D2A30, 1 update 5DB310 (sound.md#edf6-talk-line-start), 2 speaker 5DAFC0, 3 still talking 5DB040, 4 radio style 5DB0A0), TalkActor_Voice (a voice with no speaker; 17D6EC0: 5D2A70, update 5DB800, 5DAFA0 returns an empty pointer, 5DB060, 5DB0B0 returns 1), and TalkActor_Wait, TalkActor_Appeal, TalkActor_AppealEnd (vtables not read). Lines are grouped in a TalkManager::ActorGroup; the manager's group walk 5DE580 is called from 5DE8E0, a twin walk 5DE450 has no direct caller (reached through a pointer, not traced).

Basis: RTTI type descriptors (_Logs/00v/rtti.py, findstr.py), the vtables' slots read with fn.py

Addresses (build-specific RVAs unless indicated): 20B29C8, 17D6E90, 5D2A30, 5DB310, 5DAFC0, 5DB040, 5DB0A0, 17D6EC0, 5D2A70, 5DB800, 5DAFA0, 5DB060, 5DB0B0, 5DE580, 5DE8E0, 5DE450

TalkActor_Object speaker and cue fields

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-actor-fields

TalkActor_Object's fields, from its setter 5D9660(actor, speaker ref, cue, animation, delay, mode): +0x10 the sound handle, +0x20 the cue (wide string), +0x40 the animation name, +0x60 / +0x68 the speaker as a weak reference (pointer, control block; the setter takes the object's own +0x28 / +0x30 reference, 5D525A), +0x70 frames before it starts (at least 1), +0x74 the mode (0: played at the speaker's position with 7B2B00; else unplaced with 7B2C00, sound.md#edf6-talk-line-start), +0x78 a byte cleared, +0x7C a length in frames taken from the voice table (the caption record's seconds x 60.0 (1765A58), stored only while the sound is not yet playing and +0xC bit 2 is set, 5DB6AC); +0xC bits 0 and 1 mark a finished actor (the update sets bit 1). Slot 3 answers "still talking": +0x7C above 0 or the handle still playing (TalkActor_Voice: its +0x40 and handle).

Basis: fn.py reads of 5D9660, 5D51C0, 5DB660..5DB6D2, 5DB800 and the slot functions 5DAFA0..5DB0B0

Addresses (build-specific RVAs unless indicated): 5D9660, 5D525A, 7B2B00, 7B2C00, 1765A58, 5DB6AC

Mission talk natives (registration 1E31F0): TalkBegin() / TalkEnd() frame a list of Talk_Add calls

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-talk-script-natives

Mission talk natives (registration 1E31F0): TalkBegin() / TalkEnd() frame a list of Talk_Add* calls; TalkEnd 1BADF0 hands the script's list (context +0x60) to 5DCB80(TalkManager, list, parameters) (the call at 1BAE72 that MoistGoat's STFU removes, missions.md#npc-dialogue-call); Talk_AddSingle(Object, cue, animation, float delay) 1BB720 -> 5D51C0(list, speaker, min frames, max frames, cue, animation, mode 0, 1) with the delay seconds x 60 (min = max); 5D51C0 resolves the * letter (sound.md#talk-wildcard-resolver), draws the frame count between min and max with TalkManager's generator +0x70, and fills a new TalkActor_Object through 5D9660. Other natives by declaration (handlers not read): Talk_AddSingleSoldier(2), Talk_AddSoldiers(2), Talk_AddSingleFollower, Talk_AddFollowers, Talk_AddSingleAuto(Object, cue, animation, uint32 flags, float) (flags SPK_AUTO_RADIO, SPK_FAR_AUTO_RADIO), Talk_AddMulti, Talk_AddVoice(cue, bool), Talk_AddRadio(cue), Talk_AddEnemies, Talk_AddWait, Talk_AddAppeal(End), TalkFromTable, WaitVoice.

Basis: declaration strings 1797060..1797680, each handler the lea rcx before its string; fn.py reads of 1BADF0, 1BB720, 5D51C0

Addresses (build-specific RVAs unless indicated): 1E31F0, 1BADF0, 5DCB80, 1BAE72, 1BB720, 5D51C0, 5D9660

AngelScript Voice and internal_Voice natives

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-voice-natives

Voice(const string &in) 1BC150 and internal_Voice(const string &in, bool) 1BDE10 both call 5DEA60(TalkManager, cue, subtitle) (RTTI: TalkManager::Voice(const wstring&, bool)), Voice with subtitle 1; while 5D9F70(TalkManager) reports busy (the voice handle +0x48 playing, the countdown +0x58 above 0, or one of the four slots at +8 (0x10 apart) with its float +0x18 at or above [17B90D0]) the native waits instead (1D7200). 5DEA60 stops the old handle, plays the cue unplaced (7B2C00, handle TalkManager+0x48) and, when subtitle is set, shows the subtitle with the radio style (5DEB5B).

Basis: fn.py reads of the two natives, 5D9F70 and 5DEA60; names from the declaration strings 1797010 / 1797040 and the RTTI of its lambda

Addresses (build-specific RVAs unless indicated): 1BC150, 1BDE10, 5DEA60, 5D9F70, 17B90D0, 1D7200, 7B2C00, 5DEB5B

When a subtitle shows: a group carries a caption key (+0x10, wide string) and a pending byte +0x30

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-subtitle-when

When a subtitle shows: a group carries a caption key (+0x10, wide string) and a pending byte +0x30; TalkEnd's 5DCB80 sets the byte to 1 only when the script entry's key (+0x20, length +0x30) is not empty (5DCC81..5DCC8C). The group walk updates each live actor (slot 1) and, while +0x30 is set and an actor says it is talking (slot 3), calls 5DD3E0(group, shared_ptr actor) (RTTI TalkManager::ActorGroup::ShowSubtitle; at 5DE4EB and 5DE79F), which clears +0x30 (one box per group) and calls 5DD580(group key, style = actor slot 4, callback). The NPC chatter builder 5D7F00 (the only caller of the line pick 5D7480, sound.md#edf6-talk-line-pick) leaves its group's key empty and the byte 0 (5D7FF8, 5D8000), so random NPC chatter never gets a subtitle box, whatever the voice table holds.

Basis: fn.py reads of 5DE450, 5DD3E0, 5DCB80 (first 120 lines) and 5D7F00's group set-up

Addresses (build-specific RVAs unless indicated): 5DCB80, 5DCC81, 5DCC8C, 5DD3E0, 5DE4EB, 5DE79F, 5DD580, 5D7F00, 5D7480, 5D7FF8, 5D8000

Subtitle text-table lookup and UI builder

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-subtitle-builder

The subtitle builder 5DD580(key, style, callback): looks the key up in the voice table (7B17F0 on [20B2950] at 5DD5C5; the record is {name +0x00, caption +0x20, both wide strings, seconds +0x40 float}); a caption equal to ***no_subtitle*** (17D7010) shows nothing; style 0 (an object speaking in person, actor +0x74 = 0) wraps the caption in 「 」 (U+300C / U+300D), style 1 (radio mode, and every Voice) in 『 』 (U+300E / U+300F) (hud.md#subtitle-ui-object names only 「 」); it then makes the box, a UiDebugMessage (0x100 bytes, 7D7C20) owned by [20B2960] - 0x88, with the text, 1.0 and the callback. The box's font renderer is its own (+0x80, from the font manager [20B29C0] + 8, scale set by 113A3E0 / 113A3F0). The callback, ShowSubtitle's lambda (call slot 5DEDC0), locks the actor and returns its slot 3, so the box stays while the line is talking.

Basis: fn.py reads of 5DD580 (to 5DDA72), 7D7C20's first 90 lines and 5DEDC0; the bracket characters read at 17D7034 and in the code (0x300c, 0x300e)

Addresses (build-specific RVAs unless indicated): 5DD580, 7B17F0, 20B2950, 5DD5C5, 17D7010, 7D7C20, 20B2960, 20B29C0, 113A3E0, 113A3F0, 5DEDC0

Subtitle Scroll Fix voice-table hook

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-scroll-fix-site

Subtitle Scroll Fix's hook (mods/subtitle-scroll-fix.md, ui.md#caption-hooks) sits on the voice-table caption lookup 7B17F0 and acts only on the call from the subtitle builder (5DD5CA is the return address after 5DD5C5), so it changes the record that becomes the box's text; the record's +0x30 / +0x38 it reads are the caption string's length and capacity; the float +0x44 it checks is the word after the seconds +0x40 (meaning not read).

Basis: 5DD580's use of the record (5DD5CB..5DD5E8) against the card's description

Addresses (build-specific RVAs unless indicated): 7B17F0, 5DD5CA, 5DD5C5

EDF6 speech subtitle rendering route

Evidence: static · Build: steam-678ccb46 · Fact ID: edf6-subtitle-route

Reading map

  1. Candidate spoken-text source
  2. Display-side UI path
  3. Untested steps and limits
EDF Knowledge Hub record — original wording — expand (1,336 characters)

Route to text over a speaking soldier (display side; untested): (1) hook ShowSubtitle 5DD3E0 (or its call to 5DD580): the key is at group +0x10, the actor in rdx; the actor's slot 2 gives the speaker as a shared pointer (empty for TalkActor_Voice), its slot 4 the style; for an in-person line keep {caption, weak speaker, weak actor} in the plugin and skip or keep the bottom box; radio lines stay in the box. (2) Each frame, from a HUD draw that has the view-projection (the follower-bar call 8042AD, hud.md#follower-bar-walk, hud.md#hud-draw-context), project the speaker's +0x90 plus about 1.9 m (the chat bubble's head offset, hud.md#world-anchored-hud), skip or edge-clamp it off screen, and draw with the HUD text calls (hud.md#hud-text-calls) at a fixed scale (hud.md#glyph-cache); drop the entry when the actor's slot 3 says done. (3) NPC chatter has no caption key and almost no captions (sound.md#edf6-talk-no-captions): showing its words needs a plugin table cue -> text (the vgmstream + Whisper grant waits on novae (ajane)) and a hook at the line start 5DB310, where the cue (+0x20) and speaker (+0x60) are at hand. Open: where the subtitle setting (key subtitles, read at A8EA7) gates the box; who writes mode 1 (Talk_AddSingleAuto's radio flags, not read); the online copy of talk (RTTI eos::Event_TalkManager, not read).

Basis: the lines above; the HUD side from hud.md's lines

Addresses (build-specific RVAs unless indicated): 5DD3E0, 5DD580, 8042AD, 5DB310, A8EA7

Caption keys and per-speaker talk gate

Evidence: static source notes and native callsite/xref inspection for steam-678ccb46. All five records are linked to their exact Knowledge Hub talk-subtitles.md fact IDs; speculative local online synchronization and script trigger completeness remain qualified rather than newly tested.

Single trailing language suffix: caption lookup 7B17F0 checks initialized suffixes _E then _S at the end of the key and strips at most one match before table lookup 55A30. Thus A_E_S resolves as A_E, A_S_E as A_S, an internal _E remains intact, and E115_001_E_B (ends in _B) is looked up whole. A conversion tool that splits at the first _E or _S invents wrong caption keys.

Missing caption fallback: an absent row can display the engine message ＊＊不明な再生キー＊＊ (“unknown play key”) instead of a caption. The contributor encountered it while porting EDF4.1 voice cue tables (24,906 distinct Japanese/English cues) after its installer reduced E115_001_E_B to E115_001. Silent radio-beep rows use the distinct ***no_subtitle*** marker. The source did not verify the exact triggered in-game key for every appearance of the unknown-key message.

Per-speaker gate: TalkManager's single-speaker entry 5DF050 tests GameObjectBase+0x380 bit 0x40000 at 5DF08C; if absent, it returns before sound, captions and speaker class icon. Its event route includes Event_TalkManager receiver 7575D0 and caller 5DAD50. Script native SetCharacterRandomTalk(Object,bool), registered at 1B9F10, toggles this bit. A default-on soldier flag and no additional effects of the native are contributor deductions, not independently established object-construction facts.

Not a universal chatter-off switch: 5DF050 can call random-talk builder 5D7F00 after checking the speaker bit, so its mission-script and chatter paths for that speaker are muted together. But 5D7F00 also has callers at 5DBE45 and 5DC381 outside the gate; the contributor did not determine every route into them. Cue choice happens later at 5D7480 and playback at 5DB310 (line name at +0x20), so the bit cannot selectively suppress one named line at this entry point.

Online scope · static inference: an Event_TalkManager event is processed on each machine, and the speaker bit check reads that machine's local GameObject copy. The source infers +0x380 is not replicated and that updating the bit on each local copy suffices for presentation-only control. Without a paired packet/object-state trace, that is an inferred local-state boundary rather than a verified global networking contract.

Related playback routing and preset resolution: sound ACB/SE records.

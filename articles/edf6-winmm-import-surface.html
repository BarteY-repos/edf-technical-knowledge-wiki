EDF6 native WinMM imports and startup call-path observations

EDF 6Engine RE & NetworkingTroubleshooting
Technical reference · Static import/entrypoint audit of one retained first-party binary set; not an exhaustive OS/runtime trace

A bounded static audit of one EDF6 binary set inspected imports of the Windows multimedia library (WINMM) to determine where the game itself depends on the API.

Studied binary Direct WINMM imports found
EDF6.exe None
EDF.dll waveInGetNumDevs, waveOutGetNumDevs
LaunchGame.exe None
umbra_sandlot.dll None

For this exact set, the audited EDF.dll entrypoint/attach path did not directly call either imported WinMM function. Their examined normal call sites lay outside the entrypoint path.

The result is not a universal guarantee about startup timing: transitive dependencies, OS loader behavior, different builds and third-party DLLs were not exhaustively covered. It also says nothing about whether a particular injected mod loader succeeds. This page records the bounded first-party game-binary fact only.

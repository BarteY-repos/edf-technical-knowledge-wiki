Vehicle runtime class compatibility and online ownership

Friendly-NPC behavior is not independent of its vehicle's native ABI. The EDF4.1 V301 tank, V408 motorcycle and V406 Begaruta case study shows failures caused by missing CAS rest tracks, mismatched drive parameters, hand-IK producers and differing gun mount counts. Registered object authority versus unregistered local-copy ownership is a separate multiplayer requirement for NPC crew and vehicle-owned projectiles.

Another source-to-donor class ABI example: DragonBig401

The giant dragon's timed flame behavior illustrates a parallel issue: target animation files may parse correctly yet the EDF6 donor class can still fire a different projectile and lack the source MAB attack events. This is class-specific gameplay-semantic reconciliation, not a generic file-conversion change.

Animation controller compatibility is independent of friend AI

A compatible EDF6 base class may require anmgroup player names and vcontrol variables missing from EDF4.1's animation file even if the original model, clips and recruitment script are correct. The bounded source method uses trackless donor clips and plain-variable grafting, with validated index/string rebasing; it avoids copying donor motion onto foreign source bones. See CAS players and vcontrols and CANM pose rebasing. This is distinct from deciding whether EDF6 ledge climb should be preserved.

The MissionBundle intentionally uses a hybrid friendly-NPC strategy: preserve mission-authored EDF4.1 semantics and source identity where material, while using EDF6 runtime/base-class behavior when it remains functionally compatible.

Mission semantics preserved by the converter

The maintained conversion path preserves source recruitment/follow intent:

  • CreateFriend preserves source canRecruit;
  • CreateFriendSquad preserves source canRecruit;
  • CreateFriendGroup preserves source canRecruit;
  • SetAiAutoFollow remains direct follow semantics;
  • RecruitObject maps to the corresponding leader/follower relation via SetAiFollow.

The converter therefore does not redesign all friend behavior around a new command menu or one universal recruitment model.

Friendly soldier identity

Ranger / HeavyArmor / PaleWing NPCs preserve source-facing data including:

  • visual identity;
  • appropriate CAS contract;
  • ragdoll/model-related source data;
  • colors;
  • voice/talk behavior;
  • soldier weapon slots;
  • private/source NPC weapon contract;
  • mission-authored role/squad data.

Their base/runtime behavior can remain EDF6-native for surfaces such as steering or minor tuning only while mission-authored gameplay stays functionally equivalent.

Why EDF6 ledge climb is removed

EDF6 ledge climb is deliberately not inherited by EDF4.1 friends:

  • the original EDF4.1 CAS does not contain the corresponding climb states;
  • climb changes traversal semantics;
  • it also appeared in a stuck-NPC failure mode.

Rule: do not restore climb merely because the target engine supports it.

What functional parity means

Do not chase float-for-float movement equality by default.

A modest speed/steering difference can be acceptable if the NPC still performs the authored behavior. A compatibility fix becomes necessary when the target runtime causes an NPC to:

  • fail an authored route;
  • get stuck where source traversal does not;
  • change tactic/formation materially;
  • fail recruitment/follow transfer;
  • break mission progression.

Navigation geometry must be checked before blaming actor AI, because all-16-map donor NAV mismatch is already a known limitation.

Explicit exclusions from the minimal compatibility DLL

The MissionBundle does not install the All Forces gameplay redesign:

  • player Enemy Control;
  • controlled PvP;
  • RTS/support systems;
  • M-menu command/recruitment redesign;
  • automatic vehicle crew/gunner behavior;
  • generalized player-vehicle systems.

Old upstream declarations retained only to compile selected translation units are stubbed/no-op where not mission-required.

Recommended runtime order

A focused friendly-NPC qualification sequence is:

  1. vanilla recruit marker;
  2. approach + recruitment;
  3. non-recruitable squad;
  4. leader death / squad transfer;
  5. SetAiAutoFollow / RecruitObject transitions;
  6. Ranger traversal;
  7. Fencer/HeavyArmor traversal;
  8. PaleWing traversal;
  9. Vehicle402/403/404 role/voice/icon/loadout/AI;
  10. mission restart/state reset.

Do not test the All Forces redesigned command workflow as if it were the target product; it is deliberately outside scope.

Source skeleton axis and climb-state contracts

The retained EDF4.1 R9 source documents a separate spine-aim up-axis issue: sampled EDF6 soldier skeletons put the up-axis on local X and use human_direction_adjust=2, while EDF4.1 models use local Y and mode 1. Using the target mode with source bones makes a soldier bend instead of twist. Source weapon grips also require animated, weapon-dependent IK rather than static wrist offsets, and a retained exact-build analysis explains how EDF6 ledge-climb can deadlock on four missing CAS states. See spine axes, IK and climb-state deadlock.

Vertical FOV constant and zoom divisor

Evidence: static · Build: steam-678ccb46 · Fact ID: vertical-fov

Frame limiter Sleep and poll loop

Evidence: static · Build: steam-678ccb46 · Fact ID: frame-limiter

Frame limiter: a wait loop calls Sleep (call [Sleep] at 11A2F65), then polls 11DAE60 until it returns nonzero (jz back at 11A2F74). Souzooka's FPSUnlimiter NOPs both; Souzooka says the game is then capped by the screen's refresh rate.

Basis: the patch's anchors, decoded; EDF6VR's F5 diagnostic blanks the same bytes (11A2F65 6, 11A2F74 2) "while a mission runs", and its README calls it the in-mission 60 FPS limiter; the loop around it and its step clamp: frame-pacing.md#edf6-game-loop-steps

Addresses (build-specific RVAs unless indicated): 11A2F65, 11DAE60, 11A2F74

EDF Knowledge Hub record — original wording — expand (2,394 characters)

Material shaders and the base color: the material constructor 110F110 takes the UTF-16 shader name from the MDB material header +8 (110F238), copies the shader folder from config +0x28, appends a backslash, the full name and .sgo, and passes the path to the loader 1148E20 at 110F322; the default folder app:\Shader\DX11 is set up by 700F19 -> 10FFC50 -> 1110580, and there is no list of allowed names, so a material naming EDF41_SND_MECH loads app:\Shader\DX11\EDF41_SND_MECH.sgo. In the Deferred pixel shaders of SND_MECH.SGO and SND_CHARA_2COLORCHANGE.SGO the base color output is o0.rgb = b + f * (1 - b), where b = albedo x diffuse (the character shader also applies change_color0/1 and the param_cm0_cm1_occ mask first) and f = reflect.R x saturate((1 - pow(saturate(dot(-view, N)), max(fall_off_amount, 0.01))) x fall_off_scale + fall_off_offset), so a high reflect value pushes the albedo toward white; o0..o4 are written (5 targets), sqrt(f) goes to o3.x and a roughness converted from the old specular power (at least the material's roughness) to o3.y; their RDEF lists metallic as unused and roughness defaults to 0. The deferred combine compute shader (the main variant 1FCB890, file offset 0x1FC9A90, 14872 bytes) binds t0 g_albedoRGB = A, t1 g_specularRGB = S, t2 g_normalXYZ, t3 g_metallic_roughness, t4 g_viewXYZ_id; with m = saturate(t3.x), q = t3.x^2, r = t3.y: directional F0 = S x (0.04 + 0.96 m), directional diffuse scaled by (1 - m), and the ambient core (1 - q) x D + E x [q x AO x A + 0.2 x (1 - r) x (1 - q)], which S does not enter (so changing S cannot offset a tinted base color, and m also changes the diffuse and ambient weights); the shadow combine (1FCF2B0, file offset 0x1FCD4B0) uses the same core, the third variant (1FD3340, file offset 0x1FD1540) applies fog attenuation inside the ambient term. Stock example: VEHICLE502_GROUNDROBOGOLD.MRAB (material groundrobo, snd_Mech, reflect.R about 0.63, fall-off 50 / 2 / 0.5) has base (0.25, 0.13, 0) lifted to about (0.72, 0.68, 0.63), off-white; EDF6's own gold paint (V504_BEGARUTA_GOLD.MRAB, v504_begaruta) is snd_BRDF_Common_Basic with a brown-gold base (123, 93, 57), metallic 0.9, roughness 0.1, specular_color 0.4, blend 0.5, and the combine adds the base-tinted environment reflection weighted by metallic^2. EDF 4.1 and EDF5 write o0 = b in the same shaders (crosswalk/deferred-lighting-reflections.md).

Basis: the author's disassembly of the shaders with D3DDisassemble from each game's DX11.cpk (EDF6 SND_MECH sha256 1256766c15b1c7f8dac0834c3a9ad36d3cc5fad38f3e51122f1b4bd76c807821, SND_CHARA_2COLORCHANGE 352aae5236f38631a82705ce0f5584c64ca1c948f6c0ac5ae236b21ea13c0bf8; main combine blob a041d27e839baded1b88287f29404baf7c63162ffb7c56a7b81e1cdcf238ce73 in EDF.dll 0d5092393a1b9d8f1b75b0c93d8a8f65615a36a92c46e40349c2b66c733d0916) and static reading of EDF.dll; the mod's tests accept its edited shaders on a WARP device; 110F2F0..110F322 re-read with fn.py, matching; RVA = file offset + 0x1E00 for the three blobs; the picture in game not compared

EDF Knowledge Hub record — original wording — expand (1,511 characters)

Visibility is Umbra: umbra_sandlot.dll is Umbra Occlusion Booster (2006-2009) built from source by the game's maker. Each eye's (each view's) renderer loop 11978D0 runs four viewports, shadow, shadow, far, main; 118DFF0 sets each Umbra camera's matrix and frustum inside the loop (a row-vector camera-to-world matrix; 11E3C33..11E3D70 applies a 180-degree turn about Y after its inverse, so screen right is the negated row 0). processVisibility issues the viewport's command begin and end (cmd0, cmd1), so every viewport must run it or what waits on it never finishes (a skipped call froze the loading screen in 111CC20); the shadow viewports' depth clear is cmd0 11E2215 -> 113D390. Occlusion query results (Umbra command 6, 11E41F5..) are read per query by 1631790 with ID3D11DeviceContext::GetData, without DONOTFLUSH, spinning under a time limit when Umbra's wait flag is set: there the CPU waits for the GPU. The game sets Camera::setProperties (import thunk 12D611C) to 0xB at creation (11D4526) and before every resolveVisibility (11B6800, 11B6B14, 11B6FF9, 11B71C4); setProperties maps public bits to internal flags at 2B4B8..2B51A of the DLL: 1 -> 0x800 frustum culling, 2 -> 0x400 occlusion culling, 8 -> 0x1000 depth pass (the game's three), 4 -> 0x10000 (queries for the hierarchy's leaves only: a node with children goes straight to the traversal), 0x10 -> 0x100000, 0x20 -> 0x80000 (a query for every object), 0x40 -> 0x200000 (no queries, last pass's state reused), 0x80 -> 0x400000 (nodes only).

Scene composition, lighting, shadow maps and local environment

Reported seven-target deferred stage

Static, ktaro §6.25.2/13. Map pixel programs reportedly write targets 0 albedo, 1 specular, 2 normal/occlusion, 3 metallic/roughness, 4 view position/ID, 5 light accumulation and 6 emission. A compute pass combines four directional lights, ambient×AO, local cube and fog; a separate compute shader paints the sky. The later chain downscales/high-passes bloom, uses a sigma-3 15-tap Gaussian blur twice, updates exposure, tone maps and composites. Target 5's clear-to-zero is an assumption. This seven-MRT description and the separately contributed guide's “eight logical buffers” refer to different inventories, neither by itself proving actual RTV bindings.

Weather scene type suppresses shadow draw

Verified in contributor's live probes. A shadow depth pass is submitted only when System+0xB00 (_sceneType from the MAE weather DSGO) is 0. Cheat Engine read scene type 1 in two cave scenes, 0 in four other scenes. Further missions 42, 111 (nw_TikaKyoju01) and 100 (nw_Seiyu_night) gave 1 and no character shadows; mission 31 (nw_Seiyu) and EDFROOM601 mission 116 gave 0 and shadows. The source's parser read all 303 MAEs without failure: 19 presets use 1.0 (16 IG_CAVE501–605 weathers, two NW_TIKAKYOJU01 FINE/NOFOG and NW_SEIYU_NIGHT_NIGHT); remaining presets use 0.0.

Two rendered shadow cascades and an unresolved third split

Static. Source reports a 2048×2048×2 R32 depth array, split at 27.5 m (cascade0 0.1–27.5; cascade1 27.5–120), selected by camera view-space absolute Z, without blending. Fade lerp(shadow, 1, saturate((abs(Z)−70)×0.02)) removes it by 120 m; resolution/splits do not depend on graphics options. Another rendering-pass analysis stores three split ranges (0.1–27.5, 27.5–120, 120–200), so the meaning of that third constant remains unresolved rather than asserting three drawn cascades.

Light-view fit and 2048-texel snapping

Static. Eight corners of each camera sub-frustum are transformed into light view, tightly fitting its xy extent. Light-view Z follows the shadow direction, Y normalize(cross(lightDir,cameraForward)), eye at the camera minus 1200 m along the shadow direction (constant at 1FEEEA0). Orthographic near plane is 0.1, far reaches the farthest corner; view translation is adjusted so the projected world origin falls on the 2048-texel grid.

Receiver offset, 2×2 sampling and caster set

Static. Receiver displacement toward light is 0.1 m/0.4 m for cascades 0/1, smoothing radius 0.1 m/0.2 m. Four depth comparisons are bilinearly mixed with saturate((depth−sampledDepth)/radius + 1). Casters intersect the light's box, which starts 1200 m behind the camera—not only visible main-camera objects. Glass and water forward materials do not cast in this description; shadow-camera LOD selection is unknown and terrain casting is an inference.

MAE/RMPA local cubemap bounding boxes

Static, ktaro §6.26.33. Each of 278 MAEs containing an RMPA has exactly one, and all 278 match weather EnvmapArea entries; the source did not derive this from DSGO. Big-endian RMPA root +0x10/+0x14 gives item count/offset; 0x14-byte items have child count/offset at +0xC/+0x10, a name length/offset at +4/+8. Gather groups named local_cubemap; their 0x24-byte rectangle entries have Rectangle type at +4, data pointer +0x18 and center floats 0–2, half-size floats 4–6. Box order is the cube-array index. Box counts among 278 MAEs: 3 boxes/49 maps, 4/10, 5/30, 6/72, 7/75, 8/28, 9/8, 10/6.

Local-cubemap 25³ spatial lookup

Static. Reported functions FUN_181135900 → FUN_1811360F0/FUN_181134FC0 build a grid over the union of box bounds: 25 cells per axis, 26³ vertices. Each box, in order, overwrites vertices within its clamped integer corner range (inclusive; max extent uses an added unit); unassigned vertices choose nearest box by squared point-to-clamped-box distance, earlier box wins ties. A cell x + 25y + 625z gathers its eight corner box indices, de-duplicates them, places the most frequent first (higher index wins a frequency tie), appends others in corner order, and stores each corner's list position and list count. Per-cell GPU record: 20 uints = 80 bytes (8 box slots, 8 corner slots, 4 count/reserved slots), with min, reciprocal unit, unit and division count constants.

Deferred trilinear blending versus forward single-cube indexing

Static, interpretation bounded by shader family. Cell coordinates clamp trunc(max((P−min)/unit,0)) to n−1. Deferred opaque lighting samples the pixel's world position and blends listed cubes with trilinear corner weights (normalized by weight sum), or reads the sole cube if count=1. Seven cited forward families—SND_BRDF_MAP_COMMON_ALPHA, _COMMON_ALPHAOCC, _WATER, _WATERBACKSIDE, SND_MAP_BUILD_SIMPLE_ALPHA, SND_MAP_OBJECT_GLASS, SND_MAP_WATER_TRANSPARENT—receive only the first cube for their object's origin via uninterpolated vertex data. Non-array-cube forward shaders using cube 0 is ktaro's inference. Reflection direction has no X sign flip.

Map sky and menu-model environment are different consumers

Static. Map environment archive <map>_<preset>.MAE is a MARC containing DSGO; local environment is a BC6H cubemap array, sky a BC7 sRGB cubemap. The HQ menu's preview uses UI\MenuModelSetting.sgo (four lights and ambient) and UI\LocalEnv_JyousuiCity_fine_MenuModel.dds (BC6H). No fog, exposure or bloom in the model view is ktaro's impression; no separate-target code proof accompanied it.

Distance views, map objects, FXAA and compositing order

Far-camera forward pass and two frusta

Static, ktaro §6.26.30. Normal projection runs near 0.1 m to weather _farClipZ (usually 1000); distant projection runs _distantNearClipZ (usually 500) to _distantFarClipZ (usually 20000). Far-view-enabled groups contribute only Forward-slot materials to distant pass (FarMap and forwards); Deferred-slot materials still enter the ordinary G-buffer and FarMap is excluded from main passes (source says confirmed/strongly inferred respectively). Following deferred lighting, sky draws to distant color, distant depth clears, far forward geometry draws; translucent forwards then use normal projection.

Far-plane alpha handoff

Static. Embedded compute program at 181FE4ED0 reportedly assigns main composite alpha 1−saturate((distance−(F−50))/50), using fog distance and projection-derived far plane F. Background alpha is 0. Final layer mix is normal.rgb×normal.a + distant.rgb×(1−normal.a), opaque output alpha. A reported stencil-out write of distant depth 0 where main alpha is 1 appears overwritten by an immediate clear; its purpose is unresolved.

Live color/mip experiments on the distant plane

Verified by contributor's in-game tests (2026-11-21). Repainting the HD texture for ig_henden_enkei_plane red kept it red at all distances; .lod.dds appears only briefly at mission start before HD loading. Placed-map inventory and transform validity

Static census. On 45 maps, 620,405 ordinary placed parts (excluding 6,829 objects whose SGO advertises HAS_ANIMATION) had finite rotation/translation matrices of determinant 1. In 14 extracted maps, all 128,317 normal and 73,129 distant-view model references were present in the RABs. IG_CRATER601 alone has 17,857 placements, 395 models and 1,089 meshes. Final world matrix is part-local × placement. Placement and LOD thresholds are different controls

Static, with contributor's in-game non-disappearance check. MAPO table +0x1C and row +0xC, typically 1000 m, are not simple draw cutoffs. Part [7] is a small-object cutoff, 100–250 m in source examples (one report says sqrt(value)+5 m). LOD1 distance is sqrt(max(object[+0x28], part[9])), LOD2 sqrt(max(object[+0x30], part[11])), with second LOD name at part [12]/+0x30. Among 45 maps, 30,311 parts specify LOD2 (also LOD1), 26,965 with positive LOD2 threshold. Part [11] is nonpositive in that census so object table drives LOD2; among 1,035 parts with two positive LOD1 distances, part never exceeds object.

FXAA is a late post effect before UI

Static, ktaro §6.26.32. Anti-aliasing On reportedly uses FXAA 3.11-like Quality, no depth/motion vectors and no MSAA on the 3D screen—not TAA. It runs after lighting, distant layering, tone mapping and final bloom and before UI. RenderToScreenBuffer 1978D0 calls post-processing 12C230 into the player's +0xD0 full-size R16G16B16A16_FLOAT target, then 12C5A0 → 126CE0 → 1785F0 applies FXAA into +0xF0.

FXAA pixel branch and edge search

Static. Embedded shader 181FEC5C0 (linear clamp sampler) uses sqrt(dot(rgb,(0.299,0.587,0.114))) for luminance, early-out if a center/four-neighbor range is below max(0.125,maxLuma×0.125). Horizontal edge strength sums |NW+SW−2W|+2|N+S−2M|+|NE+SE−2E|; vertical |SW+SE−2S|+2|W+E−2M|+|NW+NE−2N|. Horizontal wins on ≥. Search starts a half pixel toward the greater gradient, scans both ways up to 12 one-pixel steps, threshold gradient×0.25; edge offset is 0.5−nearerDistance/(distanceSum) unless endpoint sign disagrees. Subpixel term B=saturate(abs((2(N+S+W+E)+NW+SW+NE+SE)/12−M)/range), H=((3−2B)B²)²×0.75; the final bilinear RGBA sample is displaced perpendicular to the edge by max(H,offset).

FMB, CMPL, MAC and MAD roles

Static. Source reads 46 map-folder FMB terrain files, splitting polygon chunks by binary tree and CMPL/LZSS, with vertex POSITION/NORMAL stride 0x18 and no UV. Each terrain submesh carries mass/ID grid data; material and orientation data live in its FMB header. MAD is collision; MAC holds MAPB/MAPO placements and vegetation settings. Across 45 maps MAPB/MAPO object counts match the older EDF4.1 inventory though record layouts differ. A reported 35,448,679 total triangles decoded from all 46 FMBs.

Map-owned texture arrays, terrain placement and FMEP

Static. A MAC can name multiple FMB terrains through map.mapb FMEP entries. The <map>_color.dds and _normal.dds arrays belong to map RAB (census 23 maps), not necessarily to the FMB basename. Shader family, material count and an unresolved normal-channel conflict

Static, ktaro §6.26.2/9/10/15. 315 variants are named MAP_FIELD_RENDER{materialCount}_{paintCombination}_14_{normalHandling}.SGO. This source's G-buffer interpretation gives specular 0, metallic 0, roughness 0.980133 and normal X 2×(R×A)−1, weight interpolation bilinear and color divided by sumWeight+1e−7 (black if no weights). Terrain normal mode is a global runtime selector

Verified by contributor's Cheat Engine check. Normal handling c∈{0,1,2} chooses one of three equal shader blocks (version=[10]+c×rows/3). In the running PC game the value was 0 regardless of settings; c=1 blends terrain normal toward vertex normal between 100 and 200 m without subsequent re-normalization, c=2 uses vertex normal alone. Terrain's front winding is clockwise (D3D default), opposite the MDB path.

Map material family inventory

Static, 156 material shaders in ktaro's corpus. Of these, 56 BRDF-style and 58 legacy shaders write G-buffers, 7 have no coefficient map and 35 are forward-only. Coefficient texture name tokens encode R/G/B/A roles; TEXCOORDn maps to MDB UV set n, and the material-family normal decode uses R×A for X. Shader defaults or zero when a material omits a parameter is an untested assumption (the suggested verification is removing one param from a material). A shader family's presence in the census is not a measured per-map runtime draw.

Generic BRDF map mask versus exceptions

Static, ktaro §6.26.16/18/21. Most BRDF_MAP_* material outputs mix specular as lerp(specularColor,albedo×specularColor,blend) without metallic multiplication; emission is lightMask×lightColor without albedo tint/darkening. Change-color masks and legacy LOD whitening

Static. Object, Build_Basic, Build_DirtScroll and LOD_CC cm0 masks mix lerp(diffuse,change_color,cm0)×albedoTexture; mask B comes from BRDF param_r_m_cm0_hr, mask G from legacy param_reflect_cm0_spec_hspec. Dirt mask formula and world-height scrolling

Static. Dirt used by Build_Basic(_NC), DirtScroll(_NC), NoOcc and Para: with c=albedo×diffuse, w0=(1−saturate(mean(c.rgb)×dirt_adjust))×dirt.a; defaults adjust 0.8, amount/material-adjust/scale 1. BRDF uses w=saturate(w0×amount), albedo lerp(c,dirt.rgb,w), and w'=saturate(w×material_adjust): roughness lerp(R×A×roughness,1,w'), metallic G×metallic×(1−w'²). Legacy color is lerp(c,dirt,w0) with reflectance/falloff/strength/exponent attenuated by (1−w0). Despite its name, DirtScroll UV is not time scrolling: (UV2.x,−(worldVertexY+worldTranslationX+worldTranslationZ)×dirt_scale), taking instanced translation when relevant.

Parallax applies a single tangent-space UV offset

Static. For BRDF Para_NC and legacy Basic_Parallax_NC, h=(sampledHeight−parallax_dent)×parallax_amount with defaults dent 0.02, amount 1; UV0'=UV0−h×(E·T,E·B) for camera-to-surface E and normalized tangent/binormal. The height is coefficient B in both BRDF param_r_m_h and legacy param_reflect_XXX_height_spec. Albedo, normal and coefficients use the offset; dirt/occlusion retain original UV. There is no multi-step parallax occlusion march in the source.

Window frame/interior randomization

Static. BRDF_MAP_BUILD_WINDOW and MAP_BUILD_WINDOW use window_frame_texture alpha to distinguish frame (1) from glass (0), plus interior and normal textures. Vertex seed a=fm(seed×0.012)×64161.308594+0.218368 (signed fractional fm) selects interior-row offset trunc(n×fm(abs(a)/n))/n on UV1.y, and randomized normal UV offset on UV0. interior_wrap_count is MDB type-4 integer raw bits, usually 4 or 1; nonpositive selects row 0. Per-instance seed origin unverified. Normal interpolates window/mesh normal by frame alpha, no AO. BRDF glass factor e=(G×metallic×falloff)^1.4 drives interior-to-white mix; frame overlays frameColor×diffuse, metallic G×metallic×lerp(falloff,1,frameAlpha) and roughness R×A×roughness.

Seeded signboard tile/mask cycling

Static. BRDF_MAP_SIGNBOARD_PATTERN generates seeded time offset o=fm(abs(fm(seed×0.004)×64161.308594+0.218368)×0.000017)×60000; t=time×animation_speed+o, period P=switch_time+switch_interval, wrapped tc=fm(t/(image_split×P))×image_split×P, tile k=trunc(tc/P) and phase (tc−kP)/switch_time. Water and underside material formulas from second source

Five TEST shaders (BRDF_SIMPLE, INSTANCING_FETCH_BRDF, SGM, SIMPLE, TRANSLUCENT) and SND_UI_SOLID have no texture slot.

Material family is not determined by filename

Of the 156 SND_* materials, 56 Brdf, 58 Legacy and 7 NoCoefficientTexture write G-buffer outputs, while 35 ForwardOnly carry the forward flag; no other family has that flag. Exceptions to naive name-to-family mapping include forward SND_BRDF_CHARA_LIGHTSCROLL2_ALPHA, SND_BRDF_MAP_COMMON_ALPHA and SND_BRDF_MAP_WATER; no-coefficient SND_BRDF_ITEM and SND_BRDF_E614GRANDMOTHER_GATEEFFECT; and ten forward SND_UI_* entries.

1,844 parameter entries and data widths

Across 170 entries the source records 1,844 parameter occurrences and 159 distinct names: float1 1,089, float3 431, float2 184, float4 54, uint 65 (all m_instancing_array_stride), int 14 and bool 7. All float4 parameters are color-oriented: diffuse in 28 shaders, color in 8, prog_control_color in 7, water_color/color0/color1 in 2 each, and five other singleton color names. Other diffuse occurrences are float3. Integer names include interior_wrap_count, image_split, switching_mask_split, pattern_x_dir, pattern_y_dir, random_pattern_x_dir, random_pattern_y_dir and spot_dirt_wrap_count; booleans include is_damage_occlusion_mul, use_damage_max_color_mul, use_scroll and use_scroll_time.

Common material names and shader presence

Most frequent parameters, counted by shader rather than material instance: specular_color 146, diffuse 144, metallic/roughness 130 each, normal_amount 122 (one float generally, two in some map shaders), specular_pow 77, specular_diffuse_blend/light_smooth 66 each, m_instancing_array_stride 65, fall_off_amount/fall_off_scale/fall_off_offset 61 each, damage_test and damage_mask_uv_mul 29 each, damage_normal_amount 26, damage_uv_mul/damage_specular_color/damage_metallic/dirt_adjust 24 each. Presence in the catalog does not mean every material supplies a value.

Default widths, omitted values and examples

Every recorded default has its declared parameter width. Within 156 SND shaders, 377 parameter occurrences have no listed default, including m_instancing_array_stride (64), light_smooth (64), metallic (58) and damage_test (28). Eight shaders have no parameter defaults listed at all: SND_E505_FLARE, SND_UI_HSVHUE, SND_UI_HSVSATURATION, SND_UI_HSVVALUE, SND_UI_MOVIE, SND_UI_SIMPLE, SND_UI_SIMPLE_UVANIM and SND_UI_SOLID. Examples from the table: SND_BRDF_COMMON_BASIC uses diffuse (0.5, 0.5, 0.5), specular (1, 1, 1), blend 0.5, normal 1, metallic 1 and roughness 1; SND_MAP_OBJECT has white diffuse/change_color, specular_pow 100, roughness 0 and falloff amount/scale 1, offset 0. Absent table default ≠ proven runtime zero.

651 texture slots with 81 distinct names

The 170-shader texture table totals 651 entries and 81 names. The most frequent are albedo 144 shaders, normal 122, damage_dist and param_occlusion 30 each, damage_normal 27, damage_diffuse/dirt 25 each, param_reflect_XXX_spec_hspec 15, light0_scroll 13, param_r_m_occ_hr 12, param_r_m_xxx_hr 11 and param_r_m_occ 10. In a coefficient texture name, XXX denotes an unused channel. The six shaders listed in the catalog census lack any texture entry. Within an individual shader, listed texture registers are contiguous; this is not an assertion about unrelated global SRV bindings.

Register 0 versus register 2 and instancing caveat

Among the 156 SND entries, 91 first bind a texture at register 0 and 64 at register 2; the remaining SND_UI_SOLID has no texture. All 64 starting at 2 have m_instancing_array_stride (30 Legacy, 22 Brdf, 10 ForwardOnly and 2 NoCoefficientTexture). The parameter appears in 65 of 170 shaders because TEST_INSTANCING_FETCH_BRDF also names it. What occupies slots 0–1 is not in the extracted tables; interpreting them as instancing fetch inputs remains unverified.

Nonzero UV sets and exceptional texture channels

57 of the 156 SND shaders sample at least one texture outside UV0. The table's reported UV-set entries are UV0 343, UV1 57, UV2 24, UV3 2; these reported UV annotations should not be conflated with the separate 651-slot, 170-shader count. For example, param_occlusion uses UV1 in 28 shaders and param_occ UV1 in 5; dirt is UV2 in 17 or UV1 in 7; light0_scroll uses UV1 in 9, light1_scroll UV2 in 3. Window shaders map interior_texture to UV1 and window_normal to UV2; signboards map switching_mask to UV1. The only UV3 samples are spot_dirt in the two SND_MAP_BUILD_SPOTDIRT* shaders. These are static coordinate-set declarations, not a test of a texture's contents.

EDF6 render-thread post-chain dispatch boundary

Queued bloom/tone block and compute combine

Evidence: static · Fact ID: edf6-post-chain-dispatch · Source: edf6/pause-free-camera-post.md

EDF6 view loop queues post work through 112C230 into command 1126AE0, carrying a 0x48-byte bloom/tone block. The render-thread consumer invokes 1131660 at 1126C07, unbinds targets, runs resize, bright-pass and blur helpers (1176E70, 11768B0, 1176410, 1175BF0, 1177100) then combines scene +0x6A8 with blur inputs +0xC28/+0xC48. It fills constant buffer +0xBB0, binds shader +0xB98 and dispatches (ceil(w/16), ceil(h/16), 1). Setup 1127440 creates the combine resource at post +0xB90. This locates a possible full-screen-pass boundary in the call graph; no injected GPU pass, shader output or resource-lifetime behavior was verified.

EDF6 weather MAE, lighting composite, sky and tone mapping

Evidence: edf6/render-lighting-environment-rules.md, twenty static ktaro source records. These are decoded preset values, shader disassembly readings and contributor preview comparisons; unverified CPU-side values and inferred post paths are called out rather than promoted to independently confirmed gameplay behavior.

Four preset lights and a clear-sky numeric reference

Weather MAE lists four surface-to-light directions (the renderer negates these internally), diffuse and specular colors. IG_TERRACEMOUNTAIN_FINE: light 0 (−1.12,1,0.3), color 1.1, specular 0.380392; light 1 (0,1,0), color (0.224,0.224,0.25), specular 0.113725; light 2 (0.7,−0.5,−0.8), color (0.161292,0.161292,0.180392), specular 0.105882; light 3 (0.5,−0.5,0.8), color (0.295797,0.291488,0.317647), specular 0.113725. Ambient is 0.2; _sky[0] is color 0.4 against cube_sky_sun01_bc7.dds. This is one of 321 surveyed presets, not a universal lighting setup.

MAE clip distances and wind defaults

Weather/renderer settings use default _farClipZ=1000, distant near _distantNearClipZ=500, distant far _distantFarClipZ=20000 and _wind=0.3, which influences tree sway and far tree billboards. ktaro compared five reference scenes—clear IG_TERRACEMOUNTAIN_FINE, night NW_SEIYU_NIGHT_NIGHT, alternate-history bad future NW_DANTI01_HAIKYO_ALTERNATEHISTORY, cave IG_CAVE501_FINE, and fog IG_STEEPCOAST_SUNSET—for their fog, exposure/bloom, weather and lighting settings. Values are source defaults, not evidence that every mission leaves them unchanged.

MAE tone and bloom key structure

_highBloom and _lowBloom each hold [strength, luminanceMax, cutoff, fadeWidth], with the fade ramp starting at cutoff−width. _tone is [target, RGBLengthMax, center, power, lerpRate]. Clear-sky IG_TERRACEMOUNTAIN_FINE lists high bloom [0.4,1.88679,1.2,0.1], low [0.2,1.8239,0.2,0.2], tone [0.415094,5,0.222767,0.45,0.05]. These names agree with another native post-chain source, but matching a default parameter list is not a guarantee of identical frame timings.

Eleven-element sun/halo preset array

The MAE _sun list has: [0] sun DDS, [1] halo DDS, [2] halo color, [3] halo strength, [4] halo size, [5] unread, [6] cloud-mask strength, [7] direction offset, [8] sun color, [9] sun strength and [10] sun size. The weather RAB stores single-channel uncompressed halo textures in TEXTURE. Invalid filenames such as sun02. draw nothing. Clear-sky example uses sun02.dds for both images, white halo at strength 0.3/size 600, cloud mask 0.5 and white sun at strength 1.5/size 20.

Sky-space sun and halo rectangles

Sun direction is normalized light0.direction + _sun[7], projected from camera + direction×1000 to pixel coordinates. Visibility factor is (1−saturate(skyAlpha×_sun[6]))×saturate(dot(viewDir,sunDir)+0.25); thus cloud alpha can hide the disk. Pixel size scales preset sun/halo sizes by 1/tan(verticalFOV/2), independent of display resolution, and each rectangle contributes texture red × preset color × strength × visibility. Sun and halo are added to sky before background fog mixing. The code description does not claim photometric correctness.

Evening-painted sun and directional light disagree

Of 39 sampled evening MAEs using cube_sky_sun02, 34 light-0 vectors (−1,0.45,−0.15) share the painted sun's azimuth but put light about 24° higher than the disk. In IG_2000MCITY and IG_2000MCITY601 evening, light 0 (−1.3,0.25,0.25) is about 20° off in azimuth. These presets set disk size _sun[10]=0, so only the halo is drawn; hiding the mismatch is the source author's interpretation. Actual game-frame visual severity was not measured; a separate contributor suspected bad source data.

Sky cube orientation, mip 0 and black-cube option

The sky shader reads its cube at mip 0 along world view direction, negating the direction's X (mov r2.x,−r0.w in the inspected shader); local environment cube lookups do not apply that negation. Sampled sky color is multiplied by _sky[0]. The sky_system constant buffer is built by native FUN_18017bb90. Presets with _sky[1]=black_cube.dds produce a black cube background. Source mentions shader address 1F544E0 and a different HLSL comment identifier 181f562e0; no claim is made that they are the same hash-pinned program.

Brightness-fog maximum followed by color fog

Lighting composite applies _brightnessFog first and _fog second. Each is [start,RGBA color,curve,width] and computes alpha amount pow(saturate((length(viewPosition)−start)/width),curve)×color.a. Brightness fog takes a per-channel max(currentColor,brightnessColor×amount); ordinary fog then mixes lerp(currentColor,fogColor,amount). End distance is start+width, not a separate independent field. IG_CAVE501_FINE begins fog at −10, illustrating that start need not be nonnegative.

Clear-sky fog values and separate background blend

Clear-sky IG_TERRACEMOUNTAIN_FINE fog: start 1500, width 15000, curve 0.471533, color (0.099977,0.115906,0.129412,0.8); brightness fog: start 100, width 3000, curve 0.3, color (0.0613333,0.070714,0.092,0.898039). Sky background is separately mixed toward fog color by backgroundFogApply×fogColor.a; the sky shader's m_fog_apply is confirmed, but that CPU value is absent from MAE. Inferring mission-script FOG_BG_APPLY from EnvFadeAnimation sets 1 for fog scenes and 0 otherwise remains unverified for every scene.

No sampled gamma post-pass or MSAA in this pipeline

ktaro found no gamma-conversion constants (e.g. 0.4545, 2.2 or 12.92) in 980 examined shader disassemblies; most sampled textures lack an sRGB declaration and are read as stored, while the sky cube BC7-sRGB is decoded to linear before sampling. The final result clamps 0–1 into a UNORM target, so a faithful preview should not silently add a second sRGB output conversion. The sampled 3D rendering uses FXAA rather than MSAA. This is a bounded shader/pipeline survey, not proof that no other code path ever transforms gamma.

G-buffer normals, ambient occlusion and four diffuse lights

Per-pixel compute composite 1FCD4B0 treats view-space |Z|≥65534 as background. If the G-buffer normal length is ≤0.001, the material is unlit: albedo×light_accumulate + specular_accumulate, then fog. Otherwise the normalized normal's original length scales ambient and diffuse contributions (a material-written occlusion factor). Ambient is ambientColor×normalLength×AO; the four directional lights each contribute saturate(dot(N,L))×lightColor, light 0 multiplied by its shadow. Total diffuse irradiance is light_accumulate+(1−metallic)×normalLength×(ambient+directionalDiffuse), multiplied by albedo. AO=1 when its screen-space pass is off.

Directional GGX-like specular and per-light clamp

For each of four lights, ktaro's read uses r=max(roughness,0.04), a2=r^4, distribution D=a2/(π×(NdotH²×(a2−1)+1)²), geometry k=0.5×a2+1e−6 with Gx=NdotX/(NdotX×(1−k)+k) for view/light, and Schlick-like F0=specularColor×(0.04+0.96×metallic), F=F0+(1−F0)×(1−VdotH)^5. Specular scales F×D×Gv×Gl/(4×NdotV×NdotL+1e−6)×π×NdotL. Lights 1–3 are capped per channel by preset _sub_spec_factor_max; light 0 is not and also receives the shadow factor. It is an extracted shader formula, not a statement that every material outputs physically based inputs.

Two unblended cascades for light 0 and far fade

Only light 0 reads the cascaded shadow map in composite 1FCD4B0. Cascade 0 is chosen below m_distance[0], cascade 1 up to m_distance[1], none beyond; there is no transition blending. For light-space position q, projected test depth uses m_proj(q.xy,q.z+m_shadow_adjust). Four neighboring depth samples yield saturate((sampleDepth−testDepth)/width+1), where width comes from a projected q.z−m_shadow_smooth, then bilinear interpolation. Far distance fades shadow toward fully lit; outside-map sampling returns 0 (shadow). Direction is normalized negative of light0.direction+_shadowOffset. CPU values for m_shadow_adjust/m_shadow_smooth were not found.

Local cubemap reflection, metallic² and final sum

Reflection vector is world-space reflect(viewDir,N); the environment transform was identity in the surveyed data. Local cubemap selection uses the world-position grid: one cube per cell or blends adjacent cubes by trilinear corner weights. Sample mip is mipCount×max(0,1−(1−roughness)²). With m2=metallic², the source's final pre-fog sum is lerp(diffuseColor,environment×albedo×normalLength,m2) + environment×((1−m2)×0.2×(1−roughness)) + specular_accumulate + normalLength×directionalSpecular. Brightness fog and fog follow; translucent coverage can blend sky behind the surface. This is a local-grid material path, different from lit-forward single-cubemap sampling.

Lit and unlit forward materials after G-buffer composite

Lit forward materials include BRDF_CHARA_LIGHTSCROLL2_ALPHA and its damage variant, BRDF_E601MARTIANSHIELD2, legacy UFO_LIGHTSCROLL2_ALPHA and SHIELDBEARER_BEAMSHIELD. Their lighting resembles composite but lacks the lights 1–3 specular cap, applies occlusion to everything except emission and uses one environment cube rather than the local grid; light-0 shadow still applies, with brightness fog/fog last. CHARA_VIRTUALDOME is an exception without fog. In the surveyed 1,176 MDB material instances, counts for lit forward groups are 39+6+22 and unlit forward 30 (including BEAMSHIELD, E616_VENUS_SHIELD, COMMON_SIMPLE_NOLIGHT_ALPHA, E505_FLARE, CHARA_VIRTUALDOME). The author found no shadow casting by forward meshes in the sampled path.

Shield additive base color and scrolling UV rules

Forward shield base color adds albedo+diffuse instead of multiplying. Vertex UV0 scrolling differs by family: flame uses uv_scroll0, shield scroll_tex, affecting albedo, normal and coefficient textures. In legacy UFO_LIGHTSCROLL2, the product of two coefficient masks gates the first light-scroll pattern. The author inferred layer, then priority, then far-to-near ordering from a bottle/liquid preview but did not decode the relevant CPU blend descriptors, depth-write flags or exact draw order. Do not promote that experimental ordering to a native guarantee.

Auto-exposure downsample and center-weighted target

ktaro's converged exposure reconstruction downsamples HDR 2×2 three times to 1/8, then 4×4 to 1/32. It averages the central half in width and height (one quarter of area), capping each RGB vector's length at Mmax. Luminance is L=max(0.0001,dot(rgb,(0.298912,0.586611,0.114478))), then mixes L=p×L+(1−p)×2×center×target; desired multiplier T=target/L approaches this value by per-frame factor lerpRate. A static scene converges toward T; the exact native post-chain constants are treated separately in the pause-camera source.

Two bloom resolutions, high-pass and Gaussian convolution

Bloom stage 1 takes 1/8-size image × exposure T; stage 2 uses the 1/32 image × T. Each applies luminance high-pass with m=1/fadeWidth, a=1−cutoff/fadeWidth, multiplying color by saturate(L×m+a) and limiting bright L with Lmax/L. Horizontal and vertical Gaussian blur use exp(−i²/18) normalized for taps i=−7..7 (sigma 3). Blurs are bilinearly stretched over the screen and summed as saturate(T×scene+highStrength×blur1+lowStrength×blur2). These are the source's sampled stages, not an asserted exact GPU instruction sequence for every graphics setting.

Separate menu model SGO lights and ambient

UI/MenuModelSetting.sgo defines four lights via Light_Setting tuples of travel direction, diffuse RGB and specular RGB, plus Ambient_Setting and EnvTexture. Example: light 0 (1.12,−1,−0.3), diffuse (1.5,1.5,1.4), specular 0.8; light 1 (−1,−0.5,−0.3), diffuse (1,0.8,1), specular 0.8; light 2 (0.05,0,1), diffuse 5, specular 0; light 3 (−0.05,0.5,−1), diffuse 0.3, specular 0.2; ambient (0.9,0.9,1). The setting lacks _sub_spec_factor_max; ktaro assumed 1, not verified.

Menu model colors do not track last map exposure

Although game globals under [EDF.dll+0x20B2958]+0x280 retain post settings from the previous map and +0xCE9=1 enables post processing, menu HQ/outfit models displayed near-identical orange averages after maps M12/M15 with very different exposure: (176,82,15) versus (178,82,15). Contributor infers a separate target with exposure 1, no bloom and no sky; this is strong inference, not a traced target creation path. Menu fog fields were directly observed as start 10000, end 20000, white alpha-zero color and zero amount.

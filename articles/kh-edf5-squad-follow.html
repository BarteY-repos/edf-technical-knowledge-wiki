EDF 5 — Squad Follow (community source notes)

EDF 5Community Knowledge HubGameplay & AI
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Where a follower goes

The follow state (SoldierBase slot 75 30DB80, phase 1) drops to guard (thunk 314974) when the leader +0x3A0 i…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-spot

The follow state (SoldierBase slot 75 30DB80, phase 1) drops to guard (thunk 314974) when the leader +0x3A0 is gone, asks for engage (314980) while the weak target +0x1838 lives, and calls move-and-look 30C4A0(soldier, 1.0, 1.0, 0.05, &anchor +0x17A0, &offset +0x17D0, &look) at 30DED4 (1.0 = EE6430, 0.05 = EE6234). 30C4A0 writes anchor + offset to the path controller [soldier+0x690] +0x60 and sets its +0x7C bit 1 when the point changed (30C585..30C5F6): the move target is anchor + offset. The look point is anchor + +0x17F0 (x, z; y = the soldier's own y + +0x17F4). Unlike EDF6 (#edf6-follow-spot, +0x380 bit 26), no ChaseLeader bit is tested.

Basis: fn.py reads of 30DB80 and the head of 30C4A0 (stack arguments 5 to 7 at rbp+0x120 / +0x128 / +0x130)

Addresses (build-specific RVAs unless indicated): 30DB80, 314974, 314980, 30C4A0, 30DED4, EE6430, EE6234, 30C585, 30C5F6

Attribution: KH chat 174 (autorun) · 2026-11-14

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-look-mirror

In the follow state, when the soldier's squared velocity +0xE30 (x, y, z) is at least the square of +0x10A8 and the look point lies behind its way to the spot (dot < 0), the look point is mirrored forward, L - 2(L.d)d with d the unnormalized way (EE7D00 = 2.0; 30DD68..30DEAB), as in EDF6 (#edf6-follow-look-point). The follow state's voice line (走り出す) is #edf5-npc-talk-triggers: the leader's per-frame step +0x1790 over 0.08 m (squared 0.0064, EE61CC) for 90 frames (+0x1864), cooldown +0x1860 = 300 + rand(600).

Basis: fn.py read of 30DB80; constants with rvaval.py

Addresses (build-specific RVAs unless indicated): EE7D00, 30DD68, 30DEAB, EE61CC

The anchor: with a leader the AI update 30B610 writes +0x17A0 = the leader's position +0xA0 every frame (30B9…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-anchor

The anchor: with a leader the AI update 30B610 writes +0x17A0 = the leader's position +0xA0 every frame (30B925..30B92C), with no ChaseLeader condition and no walk up the chain past dead leaders (EDF6 has both, #edf6-follow-anchor); +0x1890 = whether the leader has a route (+0x310 set); +0x1790 = the leader's step this frame, negated (the previous leader position +0x1780 minus the current), then +0x1780 = the current (30B9B3..30B9FE); without a leader +0x1790 is zeroed (30B8DC). A route point replaces the anchor and zeroes both offsets (30BB6D..30BB98, #edf5-route-watchdog), without EDF6's 420-frame timer.

Basis: the KH chat 149 dump of 30B610

Addresses (build-specific RVAs unless indicated): 30B610, 30B925, 30B92C, 30B9B3, 30B9FE, 30B8DC, 30BB6D, 30BB98

The path controller soldier+0x690 gets +0x8C / +0x90 / +0x94 = 1.4 / 1.0 / 1.1 every frame with a leader (30B…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-path-params

The path controller [soldier+0x690] gets +0x8C / +0x90 / +0x94 = 1.4 / 1.0 / 1.1 every frame with a leader (30B8F9..30B91B) and 4.0 / 1.0 / 1.1 without (30B6C1..30B6E3); meaning not read. EDF6 sets 1.4 only when the squad's root is an AI root and also writes +0x88 (#edf6-follow-path-params); EDF5 has neither.

Basis: the KH chat 149 dump of 30B610

Addresses (build-specific RVAs unless indicated): 30B8F9, 30B91B, 30B6C1, 30B6E3

The offset: picked at random, in world space

Joining: SetFollow 51240 calls slot 18 30A410(self, leader, keepOffset), which sets the base offset +0x17C0 =…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-join-offset

Joining: SetFollow 51240 calls slot 18 30A410(self, leader, keepOffset), which sets the base offset +0x17C0 = self minus leader with y = 0 (where the soldier stood) and +0x1891 = 0; without keepOffset it sets the re-pick timer +0x17B0 = 300 + rand(900) frames; with it, 152490 shortens the offset to at most the leader's +0x3B8 (it only shortens, never turns; #edf5-squad-tree says "turned") and copies it to +0x17D0. When a soldier joins a player by walking up, the update's 2 + rand x 3 m write to +0x17D0 (30B824..30B87A, #edf5-recruit-near-player) is overwritten in the same frame by the copy from +0x17C0 (30BAD0, since +0x1891 = 0), so the follower keeps the spot where it stood (up to 10 m); the look offset +0x17F0 = 0 and its timer 180 + rand(120) set there do stay.

Basis: fn.py reads of 30A410, 152490; the flow in the 30B610 dump

Addresses (build-specific RVAs unless indicated): 51240, 30A410, 152490, 30B824, 30B87A, 30BAD0

Re-picking, as in EDF6 (edf6-follow-offset-pick): the update counts +0x17B0 down and at 0 calls 30CF30(self,…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-offset-pick

Re-picking, as in EDF6 (#edf6-follow-offset-pick): the update counts +0x17B0 down and at 0 calls 30CF30(self, 0, 0) (30BA20), which sets +0x17B0 = 900 + rand(900) frames (15 to 30 s at 60 fps), +0x1891 = 1, and +0x17C0 = a random direction (5BEB60 around (0, 1, 0) EE7550, half-angle π EE6560) with y = 0, set to length (95120) +0x1884 + u x (+0x1888 - +0x1884), u = rand(10000) x 0.0001 (EE6178); SetUp writes 3.0 and 10.0 there (30B408, 30B412). With FixAiPosition (+0x280 bit 15, or the call's own arguments) the offset is zero. Online (the mode's +0x5C != 0) the draw comes from a seed kept at +0x1970, and with a zero first argument +0x1978 is counted up and 310630(self, kind 1) sends it (a sync, inferred). The leader's facing is used nowhere: a world-space offset.

Basis: fn.py read of 30CF30; constants with rvaval.py

Addresses (build-specific RVAs unless indicated): 30CF30, 30BA20, 5BEB60, EE7550, EE6560, 95120, EE6178, 30B408, 30B412, 310630

Each frame the update forms the used offset (30BA25..30BAF1): once +0x1891 is set, +0x17D0 = +0x17C0 x s / +0…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-offset-scale

Each frame the update forms the used offset (30BA25..30BAF1): once +0x1891 is set, +0x17D0 = +0x17C0 x s / +0x1888, where s = (for a soldier with +0x32 bit 3) +0x3C0 if >= 0, else +0x3C4 if >= 0, else +0x3BC, and +0x3BC without the bit; else a plain copy. Then, with a leader, 251C00 lengthens a nonzero offset shorter than the leader's +0x3B8 to that length. EDF6 (#edf6-follow-offset-scale) also takes the max with slot 19 and forwards both reads to the vehicle a soldier rides; EDF5 reads the fields inline, so a leader in a vehicle does not push its followers out.

Basis: the 30B610 dump; fn.py read of 251C00

Addresses (build-specific RVAs unless indicated): 30BA25, 30BAF1, 251C00

The scale fields: the GameObject setup writes +0x3B8 = a register value (0 in EDF6's same code, edf6-follow-f…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-formation-radius

The scale fields: the GameObject setup writes +0x3B8 = a register value (0 in EDF6's same code, #edf6-follow-formation-radius; not read here), +0x3BC = 10.0, +0x3C0 = +0x3C4 = -1.0 (2D9DAF..2D9DC9), then reads game_object_formation (EACB18) into +0x3B8 / +0x3BC (2D9FDC, 2DA020). 35 of 344 object SGOs carry it: the Colonist frogs (e503_*) and Cosmonauts (e506_*) [10, 100], The Nameless (e516_biggreyboss) [10, 50], every Barga (v515_retrobalam*) [50.0]; no friendly soldier, so a soldier's s is 10 and its offset stays 3 to 10 m. The base AI step 2DAAE0 writes +0x3C0 = the route's +0x20 (-1 without one) and copies +0x3C0 / +0x3C4 from the leader (2DABC5..2DABFB); a mission native (dispatch low byte 0x4E, case 115CCF, probably 3150 beside 3152 RecruitObject, unnamed in mp-s's list) writes +0x3C4 (115CEC).

Basis: fn.py --writes --grep over the code for +0x3B8..+0x3C4 and +0x1884 / +0x1888; --str EACB18; kh149_natcase.py 115CDE; SGO keys with obj_keys_g.py

Addresses (build-specific RVAs unless indicated): 2D9DAF, 2D9DC9, EACB18, 2D9FDC, 2DA020, 2DAAE0, 2DABC5, 2DABFB, 115CCF, 115CEC

The route's +0x20, which edf5-ai-route-fields calls its speed, is read here as the follow spread s (30BA38)

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-follow-route-spread

The route's +0x20, which #edf5-ai-route-fields calls its speed, is read here as the follow spread s (30BA38); EDF6 uses the route's +0x24 the same way (#edf6-follow-formation-radius). Speed or spread radius, or both, is not settled. A Barga's game_object_formation [50.0] makes a soldier following a Barga (missions where NPCs follow one, recruited through RecruitObject) keep at least 50 m from it, inferred from 251C00.

Basis: the 30B610 dump against the two older lines

Addresses (build-specific RVAs unless indicated): 30BA38

The look offset +0x17F0 is re-picked by 30D150 when +0x17E0 runs out (after 310630(self, kind 2), 30BB09..30B…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-look-pick

The look offset +0x17F0 is re-picked by 30D150 when +0x17E0 runs out (after 310630(self, kind 2), 30BB09..30BB21), as in EDF6 (#edf6-follow-look-point): timer = 150 + rand(450) frames; offset = a random direction x 10 (EE7E20) + the used offset normalized x 3.5 (EE6580), set to length 10 (EE65F4), y = abs(y) x 0.1 (EE6264). While it points away from the follow offset (dot < 0) the timer runs three times as fast (30BB4B).

Basis: fn.py read of 30D150; constants with rvaval.py

Addresses (build-specific RVAs unless indicated): 30D150, 30BB09, 30BB21, EE7E20, EE6580, EE65F4, EE6264, 30BB4B

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-follow-ahead-cause

Why followers run ahead of a player standing still: the same cause as EDF6 (#edf6-follow-ahead-cause), the spot being the player's position plus a random world-space offset of 3 to 10 m, re-drawn every 15 to 30 s and never turned with the player. Inferred from the code.

Orders: none from the player, no stay state

No mission native and no player act unlinks a follower: the callers of Unfollow 2DC0B0 are SetFollow (5125E),…

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-follow-no-orders

No mission native and no player act unlinks a follower: the callers of Unfollow 2DC0B0 are SetFollow (5125E), 2DA540 and 2DA6D0 (not read; delete or release paths, inferred), the leader's death in the update (30B97B) and the network receiver 30F5A0 (from 310CE0, messages 0xB / 0xC). SetFollow's callers are the friend and enemy squad natives (#edf5-friend-natives-join-flag, #edf5-squad-tree), RecruitObject 125FB0, the update's recruiting (30B775), 30F5A0, and four functions not read (56760, which casts an object to HumanBase, sets its +0x398 = 1 and makes it follow, 57BC0, 58CB0, 3C59A0). EDF5 has no ChaseLeader bit: guard goes to follow whenever a leader is set (30DA02) and uses the same move to anchor + offset (30DB59), so there is no ready-made stay state (EDF6's, #edf6-follow-chaseleader-stay).

Basis: fn.py --xref of 2DC0B0, 51240, 30F5A0; fn.py reads of the guard state 30D9E0 and 56C40..56C90

Addresses (build-specific RVAs unless indicated): 2DC0B0, 5125E, 2DA540, 2DA6D0, 30B97B, 30F5A0, 310CE0, 125FB0, 30B775, 56760, 57BC0, 58CB0, 3C59A0, 30DA02, 30DB59

Route and open questions

Route for a follower mod (untested): (a) formation behind the player: rotate the used offset where the update…

Evidence: unverified · Build: steam-5d11de53 · Fact ID: edf5-follow-route

Route for a follower mod (untested): (a) formation behind the player: rotate the used offset where the update stores it (30BADE, before the lengthen at 30BAF1) into the leader's frame (EDF5's leader yaw field not read), or limit 30CF30's draw to the rear half; keep hysteresis. (b) Stay: no flag exists, so either skip the anchor write at 30B92C (7 bytes, movups [rbx+0x17A0], xmm0) for flagged soldiers in a hook (keeps the squad and the HUD bar; the soldier holds around the leader's last spot), or Unfollow 2DC0B0 with +0x398 = 0 (else it re-joins within 10 m) and SetFollow 51240(self, player, 0) to resume (loses the HUD bar meanwhile); FixAiPosition (+0x280 bit 15) for "exactly here". (c) Online: SetFollow needs slot 32 (30FE20) to sync; an anchor hook is local to the AI's owner. Open: +0x10A8, +0x690's fields, 310630's kinds 1 / 2 / 8, what 56760, 57BC0, 58CB0, 3C59A0 spawn, native 0x4E's number.

Basis: summary of this file

Addresses (build-specific RVAs unless indicated): 30BADE, 30BAF1, 30CF30, 30B92C, 2DC0B0, 51240, 30FE20, 310630

EDF6 weapon ownership flags: starting equipment, DLC grants and mission rewards

EDF 6Game technical referencesWeapon progression
Technical reference · Source-scoped static analysis; no R129 gameplay test

The examined EDF6 weapon system keeps a per-row state in its game-save context. Possessing a weapon is not the same as having equipped it, having seen it since acquisition, or having improved its stars.

Four observed flag bits

Bit Meaning in the cited state updater
0 Owned
1 Used / equipped on a sortie
2 Newly obtained, not yet cleared by the normal sortie transition
3 Upgraded

A normal new-game reset grants acquisition-class 1 weapons as owned/new and seeds their star fields from the defined starting policy. Download-content refresh separately checks installed content packs, grants acquisition-class 3 items from eligible packs, and removes ownership for uninstalled pack-specific items. An equipped weapon that is no longer owned is replaced by a SoldierInit default.

Mission rewards and stars

A mission result passes crate acquisitions through the game-data reward handler. The cited route marks a newly granted item owned/new, initializes its star data and may subsequently upgrade it. Zero stars is a valid state. The weapon stat evaluator clamps each stat to its table-defined cap; the weapon display and actual firing state are calculated from the same star inputs but can format them differently.

At the start of a sortie, SetUsedWeapon() marks equipped items as used and clears the new and upgraded presentation flags from the rows it visits. Thus the NEW indicator is a short-lived presentation state; it does not constitute a separate permanent acquisition list.

What installed DLC and the current mode change

The game reads content entitlement separately from table acquisition class. Weapon rows have a physical index in the currently loaded WEAPONTABLE, and the active mode supplies the table context. The mode transition and save-load sequence therefore matter when interpreting ownership, displaying weapons, or applying localized weapon text. A save holding an old row number must not be assumed to map to the same item if the table order changed.

The user interface's weapon count and weapon-acquisition percentage are based on owned records and use their own DLC exclusion rules; those numbers are not identical to the number of rows in the WEAPONTABLE.

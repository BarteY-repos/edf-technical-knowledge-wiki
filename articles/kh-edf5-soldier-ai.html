Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Classes and the state machine

EDF5 soldier AI state-machine classes

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-soldier-ai-classes

EDF5's AI parts by RTTI: StateMachine::Agent<SoldierBase> (vtable EB0060, built by 303A90 at soldier +0x1740 from the SoldierBase constructor 3032E0) runs the AI; StateMachineTable::Agent<SoldierBase> (EB0078, at +0x1658, set up by 1D65D0 with +0xD60) is the action table, whose ActionTable::Function<SoldierBase> entries (EB0020) 304B20 registers (5 actions).

Basis: RTTI names to vtables (scratch rtti_vt.py, kh149_rtti.py), fn.py --xref to their builders

Addresses (build-specific RVAs unless indicated): EB0060, 303A90, 3032E0, EB0078, 1D65D0, EB0020, 304B20

SoldierBase guard, follow and engage AI slots

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-soldier-ai-states

The AI states are SoldierBase virtuals, as in EDF6 (89 / 90 / 91): slot 74 guard 30D9E0, slot 75 follow 30DB80, slot 76 engage 30E050, each state(soldier, phase) with phase 0 enter, 1 update, 2 exit, entered through the thunks 314974 (jmp [vtable+0x250]), 2E8608 (+0x258) and 314980 (+0x260). The machine at +0x1740: elapsed time f32 +0x1740 (+= dt), frame count +0x1744, current state object +0x1748 (its slot 1 called each frame from 30C413), the state record at +0x1750. SetUp (slot 3 30B050) starts guard (30B2E7). Guard -> follow when the leader +0x3A0 is set, guard or follow -> engage when the target +0x1838 is live, engage -> follow when the target getter 2E3360 returns null, follow -> guard when the leader is gone. Guard moves to the home point +0x17A0 plus +0x17F0, follow to the leader's position +0x17A0 plus the offset +0x17D0, both through 30C4A0 (move and look, inferred); both end with 30D2B0.

Basis: fn.py reads of the three states, the thunks and the state switches inside them

Addresses (build-specific RVAs unless indicated): 30D9E0, 30DB80, 30E050, 314974, 2E8608, 314980, 30C413, 30B050, 30B2E7, 2E3360, 30C4A0, 30D2B0

Soldier AI per-frame Think callback

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-soldier-ai-update

The per-frame AI is SoldierBase slot 4 30B610 (EDF6's Think, slot 7 596B50): it counts frames in +0x18A0, runs the base AI step 2DAAE0 (#edf5-ai-route-fields), returns for a dead soldier (+0x1FC <= 0), then does recruiting (#edf5-recruit-near-player), the leader's death, the offsets, the route watchdog (#edf5-route-watchdog), the target search and line of sight (#edf5-target-and-fire), the voice lines (#edf5-npc-talk-lines) and finally the state machine.

Basis: fn.py read of the whole function (File_Storage/Logs/catalog/kh149_30B610.txt)

Addresses (build-specific RVAs unless indicated): 30B610, 2DAAE0

Squads and recruiting

Squad leader and member hierarchy

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-squad-tree

Squads are a tree on the base object, as in EDF6 (#squad-tree-recruit-cover there): +0x3A0 the leader, +0x3A8 the followers' list head (nodes: next +0, prev +8, object +0x10), +0x3B0 its size, byte +0x398 "may join a player". SetFollow 51240(self, leader, keepOffset) calls Unfollow 2DC0B0 (unlinks from the old leader's list, clears +0x3A0), links in, calls slot 18 (+0x90; SoldierBase 30A410: +0x17C0 = the horizontal offset to the leader; with keepOffset it is turned by the leader's +0x3B8 (152490) into +0x17D0, else a re-pick timer +0x17B0 = 300 + rand(900) frames) and releases the route (756F0(+0x308)). Slot 32 (+0x100, 30FE20) syncs it online only: the host (session vtable +0x18 true) sends message 0xB (30FEF0: the leader's net id, the counter +0x1964, flags bit 0 keepOffset, bit 1 from +0x280 bit 17), a guest message 0xC (310190); EDF6 uses 12 / 13. Enemy squads use the same tree: the enemy squad natives 2020 (123C00), 2021 (123DD0), 2030 (124470) and 2200 (124C00) call SetFollow too.

Basis: fn.py reads; the natives' numbers from the interpreter's table (#edf5-native-dispatch-low-byte)

Addresses (build-specific RVAs unless indicated): 51240, 2DC0B0, 30A410, 152490, 756F0, 30FE20, 30FEF0, 310190, 123C00, 123DD0, 124470, 124C00

Walk-up soldier recruitment trigger

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-recruit-near-player

Recruiting by walking up (30B6ED..30B8D6), as in EDF6: a soldier with no leader and +0x398 set runs SearchNearPlayer over team 0 (32C5F0(TeamManager [125AB80], 0, visitor)): the nearest HumanBase (9C8228 cast) that is alive and within 10 m (EE65F4); online ([125AB30] mode +0x5C != 0) a remote copy (+0xD8 bit 0) is skipped. It then calls SetFollow(self, player, 0) and slot 32, plays the talk table "合流" (join), sets the offset +0x17D0 to the direction from the player scaled to 2 + rand x 3 m (95120) and +0x17E0 = 180 + rand(120) frames. When the leader dies (30B8F9..30B9B3; HP +0x1FC <= 0 and neither has +0x280 bit 17, EDF6's auto-revive bit): +0x187C = 300, +0x280 |= 0x40000, Unfollow, route released, slot 32 with no leader, and the cover budget +0x1898 capped at 600; a member with +0x398 set then joins the nearest player the same way.

Basis: fn.py reads; constants with scratch rvaval.py

Addresses (build-specific RVAs unless indicated): 30B6ED, 30B8D6, 32C5F0, 125AB80, 9C8228, EE65F4, 125AB30, 95120, 30B8F9, 30B9B3

Unrecruited squad cover and damage protection

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-unrecruited-squad-cover

An unrecruited squad is hard to spot and nearly unhurt for its first 30 s, as in EDF6 (#squad-tree-recruit-cover there): in SoldierBase slot 2 308AE0 (chunk 3091B3, 3092FA..3093D6), when the soldier's +0x32 bit 3 is set and the root of its leader chain has +0x398 set and +0x32 bit 3, +0x2E8 = 3.0 (else 1.0), and while the budget +0x1898 (1800 frames from SetUp, 30B3EF; capped at 600 when the leader dies or changes, 30B9A9, 30F621) counts down, +0x284 x= 0.01 (EE61E4) and every weapon's +0x5A8 (weapon vector +0x1590, count +0x15A0) = +0x1850 x 0.1 x +0x298 (else without the 0.1). Recruiting ends the chain at a player, whose +0x398 is 0, so both stop. The meanings (sight divisor, damage-taken factor, weapon damage factor) are EDF6's for the same code shape, not read here (unverified).

Basis: fn.py reads; the field meanings by analogy with edf6/soldier-ai.md#squad-tree-recruit-cover

Addresses (build-specific RVAs unless indicated): 308AE0, 3091B3, 3092FA, 3093D6, 30B3EF, 30B9A9, 30F621, EE61E4

Targets, fire and routes

Target-search interval and firing behavior

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-target-and-fire

Target and fire (EDF6 #soldier-ai-think-intent's target and engage rules, same numbers): every 60-119 frames (+0x1840) SearchAttackTarget walks the teams hostile to the soldier's team +0x218 (32C7D0), counts them all (+0x1894) and keeps the nearest whose byte +0x300 is set, with no distance limit and no line of sight, as a weak pointer at +0x1830 / +0x1838. Line of sight comes in bursts: a ray from 1.5 m above the soldier toward the target (capped at 300 m; layer 22; 74F010 on [125AB68]+0x18) runs every frame for 30-44 frames (+0x1848) and sets +0x184C when nothing is hit, then pauses 60-89 frames (+0x1844) with +0x184C cleared; +0x29C != 0 also clears it. The engage state copies +0x184C to the fire byte +0xB50 when no facing order runs (+0x340 = 0), the target is ahead (dot > 0.8, EE63C4) and within max(25, 0.5 x the range +0x1BC of the first weapon set's weapon) (30E2C5..30E335; EDF6: +0x1CEC to +0xD70, the same 25 and 0.5).

Basis: fn.py reads of 30B610 (30BD44..30BE5B, 30BEB3..30C0F3) and the engage state

Addresses (build-specific RVAs unless indicated): 32C7D0, 74F010, 125AB68, EE63C4, 30E2C5, 30E335

Route fields (EDF6 ai-routes-script-waits, there at +0x4A8..): the explorer shared_ptr is +0x308 / +0x310

Route fields (EDF6 #ai-routes-script-waits, there at +0x4A8..): the explorer shared_ptr is +0x308 / +0x310; each frame 2DAAE0 clears the valid byte +0x330, lets the explorer's slot 1 write the next point to +0x320 and set +0x330, releases the explorer (756F0(+0x308)) when its byte +0x24 says done, and copies its speed +0x20 to +0x3C0 (-1 without a route); a facing order counts down in +0x340 and turns toward the weak target at +0x348 (position into +0x360). The route watchdog (30BB52..30BCD7

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-route-watchdog

The route watchdog (30BB52..30BCD7; EDF6's teleports a soldier to its waypoint): while a route gives a point, +0x17A0 = that point and the offsets are zeroed; when the soldier has not come 2 m closer than its best distance +0x18A4 within 3600 frames (+0x18A8, 60 s), and the point did not jump by over 1 m, the soldier is alive, +0x420 bit 0 is clear and it is not a remote copy, it calls 75EF60 with the point (on 7DAD90([+0x4B8])) and 310B80(soldier, point), inferred to place it there (unverified).

Mission native dispatch through low-byte opcode

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-native-dispatch-low-byte

The mission interpreter (114F38) picks a native's case by the number's low byte: case = byte table 117968[number & 0xFF], target = dword table 1176E8[case] (RVAs); numbers sharing a low byte are then told apart by cmp edx, <number> in the case (1010 at 11745F, 1012 at 1174E8, 1013 at 11753B, 2200 at 1164A4). So a native's handler is found from its number without a jump-table guess (scratch kh149_natcase.py).

Basis: fn.py read of the dispatch (114F40..114F57) and the cases

Addresses (build-specific RVAs unless indicated): 114F38, 117968, 1176E8, 11745F, 1174E8, 11753B, 1164A4

Voice lines

NPC random-talk table dispatch

Evidence: static · Build: steam-5d11de53 · Fact ID: edf5-npc-talk-lines

NPC voice lines are named talk tables: TalkManager::RandomTalk 324570(TalkManager [125ABB0], object, table name, params) (its error string EB2040, "table not found") looks the name up (5BDF30) in the talk SGO at object+0x2C8, loaded from the object SGO's game_object_talk_setting path (2DA32A; the Sergeant app:/sound/g_sergent_talk.sgo); it does nothing without one, for a remote copy (+0xD8 bit 0) or team -1, or when the nearest listener (324E30) is beyond params[0] (100 m), and online it also sends it (327380); 324650 plays. The soldier AI's params are {100.0, 2, 400.0, 1.0, .., 1} and it calls only when TalkManager +0x58 is set. 37 call sites in all.

Basis: fn.py reads; strings with scratch kh149_fnstr.py

Addresses (build-specific RVAs unless indicated): 324570, 125ABB0, EB2040, 5BDF30, 2DA32A, 324E30, 327380, 324650

EDF5 squad membership, object removal and recruitable toggle

Dead follower persists until removal, dead leader releases sooner

Evidence: static · Fact ID: edf5-follower-leaves-list · Build: steam-5d11de53

Death by itself does not remove a follower from leader list +0x3A8; the dead soldier's AI update exits before the normal follow check, and HUD may still display an empty follower bar. Removal through GameObjectBase slot 5 2DA6D0 leaves TeamManager, calls Unfollow 2DC0B0, and runs 2DC120 to clear each remaining follower's leader handle +0x3A0 and unlink them without a new follow message. The destructor also follows that cleanup. Members of a dead leader may leave sooner once its HP is zero, from their own updates. Distinguish death, object-removal and leader-change events.

Mission native 3151 controls recruitability

Evidence: static · Fact ID: edf5-recruit-flag-native

Native 3151 (115CF9) takes object ID and integer, finds the object through 12CA60 and writes flag +0x398 as value != 0. Thirty-seven mission-script folders use it with 1 (36 official and DLC dm006_2), often toggling several squad members together. Setup, friend natives and an additional unread native group also write this flag. This differs from EDF4.1's 3111 test value == 1; no guarantee that all 37 scripts execute a given transition at the same difficulty or state.

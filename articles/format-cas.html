CAS — animation players, controllers and embedded clips

File FormatsSource-scoped referenceEDF 4.1EDF 5EDF 6
Reader-oriented technical reference · Existing research only · Version-specific profiles, where documented

CAS is the documented animation wrapper for player/controller/group/state information. Its content may refer into trailing CANM animation and string data. CAS and CANM are connected, but their version words and record layouts must not be treated as one generation number.

Role of the container

The studied CAS resources organize named players and controls around animation data. A target game class can depend on controller variables by name. A missing controller is not necessarily a harmless default: the existing EDF6 case studies include target classes that fail when expected named variables are absent.

Observed wrapper versions

Game CAS wrapper version bytes reported in the corpus
EDF4.1 00020000
EDF5 03020000
EDF6 04020000

The measured cross-generation format work identifies a 0x30-byte CAS header in its examined family. It also contains references into associated channels, tracks and string data. These are sample-scoped structural findings, not a universal promise for every historical CAS variant.

What the measured CAS wrapper points to

The studied 0x30-byte header references several related structures:

Structure Recorded relationship
Embedded CANM Offset at CAS header +0x08; CANM begins at a 16-byte-aligned position
tcontrol and vcontrol Control records used by the animation-state graph
Animation groups Named groups and their associated state/clip references
Bone references Names and relationships needed to address the owning skeleton
String references Signed relative pointers to UTF-16LE names in the measured layout

The header and the embedded animation bytes are two layers. Repositioning records or inserting controller data requires recalculating the relevant relative pointers; a version word alone does not repair them.

The CAS command/data generation difference

Source generation Studied data command-record size
EDF4.1 0x24 bytes
EDF5 0x34 bytes
EDF6 0x34 bytes

The original paired-file research found that command identities changed across generations. Its measured crosswalk relied on same-named controls, states and corresponding slots in paired resources, not on a universal numeric increment. It also rejected unmapped commands rather than silently substituting a nearby ID. These are evidence-bounded conversion observations, not a license to remap unknown opcodes.

Relationship to CANM

An outer CAS wrapper can contain or refer to animation data governed by its own CANM layout. In the studied EDF5/EDF6 profiles, CANM changes its channel record width and rotation representation. Therefore:

  • Reading the CAS wrapper does not prove that trailing CANM bytes have been decoded correctly.
  • Converting the CAS version word does not convert Euler-based animated rotations into the measured target quaternion form.
  • A syntactically valid resource must still satisfy named-player/controller and owning-skeleton expectations.

See CANM — clip and channel encoding for the dedicated channel reference.

Validation and limits

The existing measured conversion recorded an 836-file CAS round-trip and a 230-pair EDF5/EDF6 corpus. Those counts describe a bounded validation set. They are not an unconditional successful-animation guarantee for every resource, nor proof of a universal conversion schema.

Within that 230-pair study, 66 converted files matched the target bytes exactly, 21 were classified as substantially re-authored target resources, and the other 143 differed only in reported quaternion floating-point values and, in 69 of those cases, key-block ordering. For EDF4.1 CAS input, the same study accepted 204 of 205 examined assets and rejected an uncommon unmapped command case. These are specific source-reported results; no new test has been performed for this page.

The EDF6 source cases support retaining required named controller placeholders where appropriate, rather than blindly copying donor-bone animations. These are controller-compatibility findings, not a generic CAS layout rule.

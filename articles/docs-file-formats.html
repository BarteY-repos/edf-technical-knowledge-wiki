Overview

EDF uses different file formats for different consumers. Loading an archive, parsing a model and registering it as the correct resource type are separate checks. A file with a valid magic number can still fail if the engine chooses a different resource loader.

Format directory

Each format below links to its primary reference: what it is, where EDF uses it, the measured structure, generation-specific differences and known unknowns. Specialized studies such as mergers, conversion experiments and crash analyses are linked inside those main references. A listed game version means a studied profile, not general compatibility.

Rules for parsers and converters

  1. Confirm format identity and the consumer, not merely the filename extension.
  2. Validate endian rules, relative offsets, record counts, bounds and alignment against the correct generation.
  3. Preserve unknown fields and exact strings whenever their meaning has not been recovered.
  4. Distinguish round-trip bytes, structural validation and an actual game-runtime test.

Version notes

File extensions recur across EDF generations but do not imply identical binary layouts. Start with the target-specific reference before reusing an EDF5 serializer for EDF6. A common example is MAB pointer-base behavior, and another is the EDF5-versus-EDF6 NVMD record size. Consult MAB v15 — known structure and conversion boundary and NVMD / DMVN — binary format v0x120/v0x130.

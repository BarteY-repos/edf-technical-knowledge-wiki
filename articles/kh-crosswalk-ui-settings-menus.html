Settings menu framework (key: HUiHQGameSetting, HUiLayout)

  • edf5: menu screens are ui::HUiLayout subclasses built from layout SGOs; Game Settings is HUiHQGameSetting | ref: edf5/ui-menus.md#hui-layout-framework, #gamesetting-rows | evidence: static
  • edf6: the same design is now mapped beyond RTTI names, including HUiHQGameSetting::Item, row bounds and five per-id switches. See edf6/ui.md#edf6-gamesetting-rows, #edf6-gamesetting-bounds and #edf6-gamesetting-rowcount | evidence: static (source research).
  • edf41: no HUiHQ* or HUiLayout framework; the options screen is UiHQ_Option, with 3D model panels and no layout file | ref: edf41/ui.md#settings-framework-differs, #edf41-options-screen | evidence: static.
  • Differences noticed: EDF 4.1 has a different framework; EDF5 and EDF6 share both class names and underlying row/dispatcher design. The EDF5-to-EDF6 mapping is now source-rated high for the Item layout and five ID switches, not merely medium by name; EDF4.1 is equivalent only at the user-facing feature level.
  • Added: 2026-10-14 src: novae (ajane)

Settings rows and extension contract

GameNative row modelEvidence
EDF4.1UiHQ_Option: 16 fixed rows, 12 with values; left/right moves values in the current row and writes directly to the save store. Not an HUiLayout subclass.edf41/ui.md#edf41-options-rows, #edf41-option-store, static.
EDF511 or 12 visible rows; IDs 0..11 and five ID-based switches for name, range, read, write and display text. IDs above 11 are no-ops in these dispatchers.edf5/ui-menus.md#gamesetting-rows, #gamesetting-item, static.
EDF620 or 23 visible rows; IDs 0..22 with the same five switches. Item+0x28 value, +0x30/+0x34 bounds and change callback at +0x50. IDs above 22 are unhandled by native switches.edf6/ui.md#edf6-gamesetting-ids, #edf6-gamesetting-store, static.

An additional mod-owned choice for EDF5/EDF6 therefore needs its row count and all five native ID dispatchers extended; its value should be stored separately from unknown native option slots. EDF6 has additional volume, dead-zone, camera, damage and communication settings, and both newer games suppress some rows in keyboard mode. These are source-read extension constraints, not a tested generalized patch.

Callback and mod-menu entry routes

EDF5 layouts name their callbacks, and HUiHQGameSetting is reused from HQ, pause and online lobby. EDF6 uses the analogous registration map; the EDF6VR project demonstrates a modified pause-menu layout plus a callback for a VR settings entry (callback registration around 847990). A new callback still needs a real handler and menu state; a string alone is not sufficient. EDF4.1's 3D options panel does not use these layout files. Source: Knowledge Hub crosswalk/ui-settings-menus.md, EDF5 HUiLayout source and EDF6VR example; no new in-game repro.

Menu-pointer differences

EDF4.1 uses virtual-pad selection steps and ui::CursorBase highlights on 3D ui::FrameBase panels, not a normal free mouse pointer. EDF5 has a free pointer with a reported screen flag suppressing recentering (not independently proven here). EDF6's pointer is source-reported from play experience; its detailed native pointer route remains untraced. Do not transplant a 4.1 cursor patch into HUiLayout without a separate implementation.

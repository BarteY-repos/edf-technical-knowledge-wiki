EDF5 BVM enemy spawns: group, squad, transport and drop-boat call layouts

EDF 5Game technical referencesMissions / spawning
Technical reference · EDF5 source static analysis; no new runtime qualification

Several observed EDF5 custom-call layouts differ from names inferred from older disassemblers. This is important for reading enemy numbers: the leader SGO, follower SGO, count, active flag, spawn point and HP scalar occupy distinct argument positions.

Call Native source meaning (ordered arguments)
2009 Area ground enemy group: shape, SGO, count, HP scale, active, extra float (6)
2011 Enemy at spawn: spawn point, SGO, HP scale, active, extra float (5)
1022 / 1023 Transporter: spawn point, drop route, carrier SGO, string, cargo vehicle SGO, float (6)
1013 Friendly squad: ID, spawn point, radius, semicolon-joined follower SGOs, count, HP scale
2020 / 2021 Start with object ID, then spawn point, radius, SGO, count, HP scale
2030 Enemy squad: spawn point, radius, leader SGO, leader HP, follower SGO, follower count, follower HP, active
2200 Drop-boat crew: drop-boat object ID, leader SGO, leader HP, follower SGO, follower count, follower HP, active

2200 uses the boat as its first argument and the leader's SGO as its second. For example DLC mission DM003 uses one e503_armorfrog_sg_leader and three e503_armorfrog_af followers. The first SGO does not become a spawn point. Similarly M044's 2030 creates one e506_biggrey_sg_leader and three e506_biggrey_af. Mistaking the follower count for a leader count would triple the leader population in that example.

A repeated generator's amount has still different semantics: it can cap live instances in a wave rather than count the total enemies created over the entire mission. Native generator mechanics documents that boundary.

Evidence: EDF5 BVM argument/corpus interpretation bvm-spawn-call-layouts-2, bvm-call-2200-dropboat-squad, bvm-squad-leader-once, bvm-generator-calls-2100-2101. Source static; runtime spawn scheduling also depends on event conditions.

EDF6 enemy eggs: hatch targets, shell models and damage flags

EDF 6Game technical referencesGameplay & AI
Technical reference · Native-data and static code observations; no new in-game runtime test

The examined EDF6 egg objects are data-driven: their SGO entries identify which creature appears and which shell object remains or breaks. These are object definitions, not mission-owned spawn groups or hidden probabilities. The recovered class is GiantAntEgg; a related GiantAntEgg_Break object follows a different model-parameter path.

b variant and friendly damage

The observed b variant differs from the corresponding plain one in is_friendly_damage_activate: plain 0, b 1. This is an SGO field value, not proof of every possible in-game friendly-fire interaction. In particular, do not infer that the monster which hatches is friendly, that all projectiles damage the shell, or that every mission uses the b variant. Those conclusions require a mission placement and runtime hit test.

ChangeModelParam distinction

The native GiantAntEgg path loads a ChangeModelParam entry, whereas GiantAntEgg_Break did not use that path in the examined build. A separately documented KittopiaCreator patch looks up ChangeModelParam and applies it to the break object's animation model. The patch is evidence of a difference in the original routines, not a stock feature of GiantAntEgg_Break.

Where an egg actually appears

The object SGO tells you which creature it could hatch. It does not independently prove the egg's mission position, activation event, health scaling or spawning frequency. These come from mission AC/BVM and mission RMPA or other objects. See mission-owned spawn records and enemy-generator semantics.

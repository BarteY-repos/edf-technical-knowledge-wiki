EDF6 enemy multiplayer: local AI, owner decisions and insect RNG

EDF 6Game technical referencesNetworking
Technical reference · Source-code/static interpretation with explicitly labelled contributor gameplay observations; no new game runtime

EDF6 multiplayer does not transmit every enemy's full AI state at every frame. The examined engine runs enemy AI and physics on each machine, then uses object ownership and selected network messages to reconcile important decisions. This is why two games can show the same enemy model yet gradually disagree on its exact motion or random choices.

Simulation is local; authority is selective

The static survey found that enemy AI/physics updates continue on guests, while selected decisions check an owner/remote-copy bit. Examples include an owner-selected MonsterBase random action and messages for insect hit reactions. A guest's weapon firing can be separately gated: when a shooter is a remote-owned copy, the examined 0x690CC0 path returns without generating its own projectile, so the copy uses replicated owner fire instead of firing the same shot a second time.

Therefore these two statements can both be true:

  1. Each machine updates the enemy's local animation/physics/AI trajectory.
  2. A selected side owns an authoritative shot, random action or network event.

Do not infer "owner sends every movement coordinate" or "clients must all independently generate identical bullets" from either statement alone.

Insect pose update thresholds

The surveyed GiantAnt network-object writer has different thresholds according to state; it does not send a fresh pose every rendered frame. Static constants include 40 or 90 frames in the non-moving-target cases and 12, 3 or at least 9 frames in specific moving/AI-mode branches. Exact branch meanings for some status bytes remain partly inferred. Source investigators corrected an earlier reversal of the 40-versus-90 condition.

At 60 simulation ticks per second, 90 frames are 1.5 seconds and three frames are 0.05 seconds. These are thresholds on particular branches, not a guarantee that a changed pose is sent on that cadence under every condition.

Insects and random-state restoration

The analyzed insect network path sends message 10 with an old seed and current RNG state. The receiver consumes it and advances the state according to the same LCG step. Other surveyed enemy families did not expose this same RNG-resynchronization message; they may rely on shared initial seed and equivalent execution paths.

A missing or additional RNG draw on one peer can therefore change future enemy decisions, even if the player sees a recent pose correction. It would be wrong to claim that "all EDF enemies continuously synchronize RNG" or that a single missing packet explains every persistent aim/HP desync.

A separate observed limitation

An EDF6MultiSlot source report describes ants, spiders, dango and Berserker-type robots not publishing ordinary pose updates during certain blown-away / downed phases, followed by guest-visible correction when standing. That observation is reported but not independently verified here, and the report specifically distinguishes bees. It should not be silently generalized to every insect or to a missing Havok collision body.

Mission RMPA reference tuning: 68 affected missions and script references

ConversionGame technical referencesMissions & ScriptingEDF 5EDF 6
Technical reference · Source-corpus/static reverse-engineering; no new game runtime test

What changed and what did not

In the paired EDF5-source vs reference-EDF6 RMPA corpus, 68 of 141 missions had at least one record tuned in the reference port. The changes comprised 76 route records, 8 shapes and 48 spawn records. These are descriptions of a reference conversion, not proof that native EDF6 always rewrites positions during asset loading.

A position not matching byte for byte is not automatically a gameplay-level discrepancy: 0 vs -0, small rounding and deliberate coordinate shifts require separate interpretation. Conversely, reference-only shape-payload changes may affect a mission trigger even if the rest of the file parses normally.

Which changes actually have mission-script users?

Record family Reference-tuned records Meaningful changes (audit classification) Records named in MISSION.AC Literal occurrences
Spawn 48 37 46 55
Route 76 71 35 38
Shape 8 8 4 5

The literal-name audit proves a script references a named record, not that the reference-port coordinate adjustment was necessary or harmless. For instance, the M005 マザーシップ spawn was shifted by +0.25 in one coordinate in the reference port and is consumed by CreateNeutral; the M007_5 crowd route 群衆ルート01_2 has a +0.25 local route adjustment and is named by CreateMob_Path. These are real differences in a reference asset, not native engine mandates.

Twenty-one additional empty groups in the reference port

The reference comparison found 5 empty route groups, 5 empty shape groups and 11 empty spawn groups not present in the clean source. None of these 21 group names had a matching script reference within the same namespace in the audited MISSION.AC set. That supports a narrow name-reference closure conclusion, not a statement that empty groups can never influence loading or state in other circumstances. Their exact names, missions and type are in data/EDF5_TO_EDF6_MISSION_RMPA_21_EMPTY_GROUPS_R118.csv.

Provenance and runtime boundary

  • The source-only mission RMPA recreation matches the known source semantics and AC literal references for 141/141 files; 6,665 source-script-to-RMPA literal references were checked with no missing generated name.
  • This does not establish that all tuning is optional for correct gameplay. The source audit explicitly left the coordinate/payload effect unresolved without runtime evidence.
  • Mission RMPA, map RMPA, and NAV are separate identities. SetAiPath(...,"navigationmap") does not refer to a mission route named navigationmap.

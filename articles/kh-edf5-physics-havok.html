EDF 5 — Physics Havok (community source notes)

EDF 5Community Knowledge HubCollision & Physics
Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Havok body wrapper

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-wrapper

The game's Havok body wrapper is 0x2C0 bytes: hkpEntity vtable CDE138, with an embedded hkpMaxSizeMotion (the concrete motion) at +0x150. Crates point to it from Unit +0xA0 (drop-items.md#crate-unit-body).

Basis: RTTI; disassembly

Addresses (build-specific RVAs unless indicated): CDE138

Attribution: novae (ajane) · 2026-10-12

Body +0x4C is collisionFilterInfo; the collision layer is value & 0x1F.

Basis: disassembly

Attribution: novae (ajane) · 2026-10-12

Body +0x150 is the embedded hkpMotion, whose vtable (concrete class) is swapped by motion type: Box CE7B38, S…

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-motion

Body +0x150 is the embedded hkpMotion, whose vtable (concrete class) is swapped by motion type: Box CE7B38, Sphere CE7F10, Keyframed CDE038, Fixed CE7E08, ThinBox CE7C28. Body +0x160 is the motion type byte (1 dynamic ... 3 box inertia, 4 keyframed, 5 fixed).

Basis: RTTI; disassembly

Addresses (build-specific RVAs unless indicated): CE7B38, CE7F10, CDE038, CE7E08, CE7C28

Attribution: novae (ajane) · 2026-10-12

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-position

Body +0x1A0 is the position (the translation of the motion transform; a 16-byte vector, y at +0x1A4).

Basis: disassembly

Attribution: novae (ajane) · 2026-10-12

Body +0x214 / +0x216 are the linear / angular damping (hkHalf)

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-damping-and-limits

Body +0x214 / +0x216 are the linear / angular damping (hkHalf); +0x21A / +0x21B the maximum linear / angular velocity (hkUFloat8; crates: 108 = 57.4 m/s, 74 = 6.0 rad/s, hkufloat8-decode).

Basis: disassembly

Attribution: novae (ajane) · 2026-10-12

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-velocity

Body +0x230 / +0x240 are the linear / angular velocity; +0x278 is the saved dynamic-motion pointer (non-null if a fixed or keyframed body could be made dynamic again).

Basis: disassembly

Attribution: novae (ajane) · 2026-10-12

Motion vtable slots, called as call vtable+off with rcx = body+0x150 and rdx a 16-byte-aligned vector: +0x90…

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-motion-vtable-slots

Motion vtable slots, called as call [vtable+off] with rcx = body+0x150 and rdx a 16-byte-aligned vector: +0x90 setLinearVelocity (a plain store to motion +0xE0), +0x98 setAngularVelocity (+0xF0), +0xB0 applyLinearImpulse (v += imp × invMass, invMass = [motion+0xD0].w), +0xC0 applyAngularImpulse. For keyframed and fixed motions +0xB0 / +0xC0 are no-ops.

Basis: disassembly

Attribution: novae (ajane) · 2026-10-12

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-body-wrappers

Thread-safe body wrappers (they queue a world command when the world is locked): 756050 activate (wakes the body; early-out for fixed), 74D0B0(world, body, 0, 1) updateCollisionFilterOnEntity (command 0x13), 75F4B0(body, type, flag, 0) setMotionType (command 4), 75EF60(body, &pos) set position.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 756050, 74D0B0, 75F4B0, 75EF60

Collision filter

The game's collision filter class is CollisionFilter (vtable E93970), built by 0AAA80: all 32 rows start enab…

Evidence: static · Build: steam-5d11de53 · Fact ID: collision-filter-class

The game's collision filter class is CollisionFilter (vtable E93970), built by 0AAA80: all 32 rows start enabled, layers 1-30 are first restricted to layer 0, then pairwise enables follow. The pair test 7155F0 is hkpGroupFilter::isCollisionEnabled: layer = info & 0x1F, row table at filter+0x4C.

Basis: RTTI; disassembly; novae (ajane)

Addresses (build-specific RVAs unless indicated): E93970, 0AAA80, 7155F0

Attribution: novae (ajane) · 2026-10-12

Layer 0 collides with everything

Evidence: static · Build: steam-5d11de53 · Fact ID: collision-layer-matrix

Basis: disassembly of the filter build 0AAA80

Evidence: static · Build: steam-5d11de53 · Fact ID: havok-world-gravity

The game sets the world gravity to (0, −14.7, 0) right after creating the hkpWorld: 6250C7 calls 74E040 = hkpWorld::setGravity (its only caller), vector at EE6B20. The −9.8 constants at CE00C0 / CE89B0 are only the hkpWorldCinfo default.

Basis: disassembly; the vacuum flights' timing in game fit 14.7, not 9.8 (dead_ends.md)

Addresses (build-specific RVAs unless indicated): 6250C7, 74E040, EE6B20, CE00C0, CE89B0

The world cinfo sets the broadphase AABB to ±1000 m (EE6D20 / EE6CA0), border behavior 3 = DO_NOTHING (bodies outside are not removed) and simulation type 3 = multithreaded.

Basis: disassembly

Crate body limits

The DropItemManager descriptor init 198260 (4 categories, stride 0x290, desc = mgr+0x1D0+cat0x290, an hkpRigi…

Evidence: static · Build: steam-5d11de53 · Fact ID: crate-body-descriptor-init

The DropItemManager descriptor init 198260 (4 categories, stride 0x290, desc = mgr+0x1D0+cat*0x290, an hkpRigidBodyCinfo-like block; drop-items.md#dropitem-category-descriptor-code) writes: +0x00 filter info 0x1D (layer 29), +0x94 linear damping 0.01, +0x98 angular damping 0.01, +0xA0 friction 0.8, +0xA8 restitution 0.2, +0xAC max linear velocity 60.0, +0xB0 max angular velocity 6.0, +0xCC quality type 4. 625410 then sets mass and inertia only (+0x90, +0xB4 = 3, box inertia). (Section 2 of the same source said the crate's layer is unknown statically; settled 2026-11-08: the 0x1D is a constant written for all four categories, drop-items.md#dropitem-category-descriptor-code.)

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 198260, 625410

Attribution: novae (ajane) · 2026-10-12

The body constructor 75E8E0 calls the motion constructor 75FC00, which stores the velocity limits as hkUFloat…

Evidence: static · Build: steam-5d11de53 · Fact ID: crate-body-limits-stored

The body constructor 75E8E0 calls the motion constructor 75FC00, which stores the velocity limits as hkUFloat8 at motion +0xCA (linear) / +0xCB (angular), that is body +0x21A / +0x21B; the damping goes as hkHalf to body +0x214 / +0x216.

Basis: disassembly

Addresses (build-specific RVAs unless indicated): 75E8E0, 75FC00

Attribution: novae (ajane) · 2026-10-12

hkUFloat8 decode: a u16 table at CB97F0, value bits = (t+0x3B800)12

Evidence: static · Build: steam-5d11de53 · Fact ID: hkufloat8-decode

hkUFloat8 decode: a u16 table at CB97F0, value bits = (t+0x3B800)<<12; 60 encodes to byte 108 = 57.4 m/s, 6 to byte 74 = 6.0 rad/s. The encoder is 64ECC0(rcx = byte*, rdx = float*) (a leaf, binary search; anchor FnUF8).

Basis: disassembly; novae (ajane)

Addresses (build-specific RVAs unless indicated): CB97F0, 64ECC0

Attribution: novae (ajane) · 2026-10-12

The solver clips |v| to the body's limit, so any crate launch above about 57 m/s is silently scaled down (lau…

Evidence: static · Build: steam-5d11de53 · Fact ID: crate-speed-clip

The solver clips |v| to the body's limit, so any crate launch above about 57 m/s is silently scaled down (launches set to 80 and the early vacuum flights were).

Basis: disassembly; it explains the slow vacuum flights seen in game (dead_ends.md); novae (ajane)

Attribution: novae (ajane) · 2026-10-12

Destroyed scenery: the game's own sink

The CrashModel physics tick D7830 (physics body at this+0x18) applies random initial impulses, detects rest (…

Evidence: static · Build: steam-5d11de53 · Fact ID: crashmodel-sink-tick

The CrashModel physics tick D7830 (physics body at [this+0x18]) applies random initial impulses, detects rest (speed² < 0.1 and the frame counters [this+0x16C], [this+0x178]), then writes [body+0x4C] = 0x1E (layer 30), calls 74D0B0 and applies the impulses (0,−0.02,0,1) (EE7670) then (0,−0.001,0,1) (EE7620) every tick; it sets a finished flag after the lifetime. CF660 is not a timer: it is MapObject_Base's damage slot (+0x128 the durability, +0x124 its maximum, +0x120 collapsed; the collapse posts the record index to 97190; map-objects.md#edf5-mapobject-durability, #edf5-mapobject-collapse).

Basis: disassembly; layer 30 falling through is verified with crates (crate-layer30-falls-through); novae (ajane); the CF660 part corrected by fn.py (KH chat 140)

Addresses (build-specific RVAs unless indicated): D7830, 74D0B0, EE7670, EE7620, CF660, 97190

Attribution: novae (ajane), KH chat 140 (curator) · 2026-11-13

Facts (merged from inbox and from the camera.md conversion, 2026-10-24)

In this build's Havok an hkpCdPoint holds the contact at +0, the normal (w = distance) at +0x10, body A at +0…

Evidence: verified · Build: steam-5d11de53 · Fact ID: cdpoint-cdbody-layout

In this build's Havok an hkpCdPoint holds the contact at +0, the normal (w = distance) at +0x10, body A at +0x30 and body B at +0x38; an hkpCdBody holds shape +0, shape key +8, motion (transform) +0x10, parent +0x18; the root hkpCollidable keeps its owner offset (int8) at +0x20, broadphase type +0x28 and filter info +0x2C; the owner hkpWorldObject keeps its property list at +0xB8 (data) / +0xC0 (count), 16-byte {key u32, value u64} entries, key 0 = the game's SceneObject. The game's TargetCollector add-hit AB890 uses key 1 for a different lookup (camera.md#camera-targetcollector-addhit).

Basis: novae (ajane); the normal at +0x10 and shape / motion at +0 / +0x10 are static (Havok's public layout, consistent with the verified offsets)

Addresses (build-specific RVAs unless indicated): AB890, 713CF0

Attribution: novae (ajane) · 2026-10-07

hkpShape vtable slot +0x20 is getAabb(this, const hkTransform& rdx, hkReal tolerance xmm2, hkAabb& out r9): h…

Evidence: static · Build: steam-5d11de53 · Fact ID: shape-getaabb-slot

hkpShape vtable slot +0x20 is getAabb(this, const hkTransform& rdx, hkReal tolerance xmm2, hkAabb& out r9): hkpSphereShape's 713C70 writes the transform's translation (+0x30) minus and plus (radius + tolerance) to [r9] and [r9+0x10] with movaps, so the output must be 16-byte aligned (hkAabb: min +0, max +0x10). Map collision shapes present (RTTI): hkpMoppBvTreeShape (CD4178), hkpExtendedMeshShape, hkpStaticCompoundShape, hkpListShape, height fields (MapObject_Shf = sampled height field; MapObject_Fmex_Grow* and Shf_Grow* variants exist).

Basis: disassembly of the vtables of hkpSphereShape CCB880, hkpBoxShape CD4228 and hkpShape CCB6C0; novae (ajane)

Addresses (build-specific RVAs unless indicated): 713C70, CCB880, CD4228, CCB6C0, CD4178

Attribution: novae (ajane) · 2026-10-07

EDF6 corpse, severed-part and weapon-debris lifetimes

EDF 6Game technical referencesGameplay & AI
Technical reference · Native-data and static code observations; no new in-game runtime test

EDF6 uses different disappearance timers for different kinds of objects. A corpse timer is not a shared engine-wide constant, and debris persistence is not equivalent to a mission's enemy spawn cap. The following table summarizes values recovered from the specified stock EDF.dll code sites.

Stock object/family Inspected timer What the evidence actually measures
Spinner UFO 30 seconds Float threshold in the death/disappearance path
Shellfish / Nacre 30 seconds Float threshold in the examined path
Giant Ant 15 seconds Float threshold
Giant Spider 15 seconds Float threshold
Giant Bee 15 seconds Float threshold
DragonSmall (Tadpole) 15 seconds Float threshold
HumanoidBase 20 or 30 seconds Two native code values; exact decision context is not fully resolved here
BerserkerBase (androids) 1,800 frames Frame-count threshold, 30 s if the counter advances at 60 Hz
Detached humanoid limbs 1,800 frames Frame-count threshold, 30 s at 60 Hz
HumanoidWeaponBase::Drop 600 frames Frame-count threshold, 10 s at 60 Hz

The distinction between stored seconds and stored frame counts matters. A frame threshold does not guarantee real-time seconds under every variable-rate, paused or modified-timing scenario. A display FPS limit is not automatically the tick rate of these objects.

Why all disappeared objects are not alike

  • A humanoid gun dropped from a destroyed part is its own scene object with physics and a roughly ten-second lifetime in the default path.
  • An insect death body, humanoid limb and a boss state may have entirely separate duration policies.
  • Cleaning up visual corpses does not prove the object was removed from a network scene registry, removed from all navigation blockers or eligible for reward drops. Those are distinct engine systems.
  • A patch that repoints float loads or changes frame comparisons documents the original constants but is not evidence that the patched timeout is stock.

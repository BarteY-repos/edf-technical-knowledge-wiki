The flag bits and activation semantics

For the exact native comparison of flags=8/9/40/520/552, the two independent NO_SUPPORT-capable bits 0x20 and 0x200, and the distinction between red loadout UI versus gameplay activation, see Underground mission flags and WeaponCondition. Three later runtime tests confirmed native-like flags=40 behavior in M000, M001 and DM019. Earlier claims that those missions required injection hacks are superseded.

Current authority: the MissionPack semantic ledger created 2026-09-03 and updated through 2026-09-11. This supersedes older attempts that copied EDF5 OFFLINE/ONLINE list asymmetry directly into EDF6 or normalized progression by target row count.

Audited converted LIST order versus the later shared-index target

A historical EDF5-content converted MissionPack LIST audit (R41) preserves the order derived from original EDF5 mission tables and a previously working converted-list reference. The numbers below are directly verified for that converted package; the source does not independently re-enumerate the original shipping EDF5 OFFLINE LIST.SGO as a separate binary authority.

Audited converted LIST profile Recorded rows Source-order relationship
MissionPack03 OFFLINE 112 Tutorial M000 followed by the studied EDF5 ONLINE mission sequence
MissionPack03 ONLINE 111 No M000; M082 and M083 occur before M098 and M099
MissionPack04 OFFLINE / ONLINE 15 each Matching DLC1 sequence, DM011 to DM015 (not numeric-sorted)
MissionPack05 OFFLINE / ONLINE 14 each Matching DLC2 sequence, DM005_2 to DM016

This historical 112/111 converted profile differs from the later EDF6-compatible 112/112 shared-progress schema below. The latter intentionally unifies both modes' row ordinals. It would be inaccurate to label 112/111 as a universally correct EDF6 target or to assert that the R41 converted OFFLINE file is itself the untouched original EDF5 shipping LIST.

In one historically audited converted LIST build, timeline/style fields 6/7 were changed from a dystopia-associated 2,1 pair (brown menu) to 0,0 for the original EDF5-era blue menu, with flags 8 for ordinary rows. This is an observed bounded menu-profile pairing; it does not mean field6=0 is the universal correct value for every later metadata policy. The maintained target schema below has its own field6 translation and underground flags.

The same audited LIST build regenerated localized TXT rows in exact corresponding ordinal order for EN, JA, KR, CN and SC. An ordinal mismatch can display the wrong mission title and description even when both resources independently parse and all underlying mission scripts exist.

Canonical target allocation

Target pack Content Source gameplay profiles
MissionPack03 EDF5 base campaign EDF5 base OFFLINE / ONLINE
MissionPack04 EDF5 DLC1 EDF5 DLC1 OFFLINE / ONLINE
MissionPack05 EDF5 DLC2 EDF5 DLC2 OFFLINE / ONLINE

EDF6 uses one shared mission-progress/index axis per campaign. Therefore OFFLINE and ONLINE must expose the same target mission sequence inside each converted pack even though their gameplay profile trees remain mode-specific.

Canonical counts:

MissionPack03: 112 OFFLINE / 112 ONLINE
MissionPack04:  15 OFFLINE /  15 ONLINE
MissionPack05:  14 OFFLINE /  14 ONLINE

MissionPack03 uses M000 + full EDF5 ONLINE sequence. This intentionally places offline-only tutorial M000 and online-only M082/M083 on the same EDF6-compatible sequence. Do not remove them merely to make one mode resemble the original EDF5 list: that would change save ordinals and discard content without improving gameplay scaling.

Complete converted LIST reference

The exact historical R41 converted LIST order has a dedicated 141-entry campaign reference, including all 112 base OFFLINE IDs, 111 ONLINE IDs and both DLC sequences, plus the six-profile 281-row CSV. Its converted source-order provenance must remain distinct from untouched EDF5 shipping binaries and from the later 112/112 target progress-index allocation.

Three independent semantic layers

Do not conflate these fields:

  1. Save/progress identity — MissionPack namespace plus the shared zero-based LIST ordinal. OFFLINE and ONLINE must agree.
  2. Mission progression position — LIST field9, copied exactly from the EDF5 source mission's progression float.
  3. Mode/difficulty gameplay profile — CONFIG/ModeList profile tree selected by OFFLINE/ONLINE and difficulty.

This is why a 112-row target list does not stretch EDF5 progression into 112 equal intervals. Never compute LIST field9 as ordinal/(count-1) and never restore the historical bad global value 0.2.

LIST row contract

For the maintained converted packs:

  • root DSGO variable name is table;
  • field0 is the zero-based target row;
  • field1 is the target mission path;
  • field2 retains the EDF5 display/thumbnail key;
  • field3 follows the established next/pointer wrapper semantics;
  • field4 is the native-style zero-based row ordinal;
  • field5 = 0 in the current schema;
  • field6 carries the translated EDF5 player/resource selector;
  • field7 = 0 under the established EDF5/blue menu-timeline policy;
  • field8 uses the established EDF5 HQ BGM key;
  • field9 is the source-exact EDF5 progression float;
  • field10 carries mission flags, normally 8 and 40 for the audited underground set.

The old V1 meta fix that omitted the named LIST root table produced missionCount=0 and an EasyClearRatio divide-by-zero in EDF6. Preserve the complete target container/root structure, not merely the row payloads.

CONFIG profile contract

Target CONFIG remains EDF6-native structurally, but custom ModeList rows receive exact EDF5 gameplay profile families:

MP03 OFFLINE <- EDF5 base OFFLINE
MP03 ONLINE  <- EDF5 base ONLINE
MP04 OFFLINE <- EDF5 DLC1 OFFLINE
MP04 ONLINE  <- EDF5 DLC1 ONLINE
MP05 OFFLINE <- EDF5 DLC2 OFFLINE
MP05 ONLINE  <- EDF5 DLC2 ONLINE

The profile trees include mission scaling, player-count scaling, weapon drops, enemy/NPC/vehicle scaling, online weapon limits and online armor limits. Identical OFFLINE/ONLINE LISTs therefore do not imply identical balance. Do not mutate native EDF6 mode rows 0..5 simply to register the converted packs.

Indexed resource family must move together

A list-order/count change is not a LIST-only edit. The reconciled runtime overlay carried:

  • CONFIG;
  • six LIST files;
  • all localized TXT companions (EN/JA/KR/CN/SC, OFFLINE+ONLINE, all three packs);
  • the indexed mission-image archives.

Title, description and image indices must follow the same shared ordinal. Rebuilding LIST while leaving stale TXT/image companions is an invalid partial migration.

Underground semantic: flags=40

Audited underground missions:

MP03: M000 M001 M014 M027 M028 M029 M056 M057 M062 M072_2 M204
MP04: DM001 DM007 DM019
MP05: DM007_2

Use flags=40 (8 | 0x20) for these; ordinary surface rows use 8.

Runtime correction: vanilla-like EDF6 underground handling still allows red/incompatible Air Raider equipment to be selected before mission start. The restriction is enforced when the support/vehicle action is attempted. Therefore being able to equip it is not a failure. M000, M001 and DM019 were runtime-confirmed with the native-like flags=40 behavior. Earlier proposals for global 512/520/552 or per-mission weapon-condition workarounds are superseded.

M000 compatibility exception

Do not globally change opcode semantics to solve the tutorial.

Source mapping remains:

1001 -> CreatePlayer_NoWeapon
1002 -> CreatePlayer_InitWeapon

But the first M000 player creation is a target-specific compatibility exception: CreatePlayer_NoWeapon("プレイヤー") caused broken first Wing Diver vertical movement in EDF6; changing only that first construction to normal CreatePlayer("プレイヤー") restored normal small-jump and flight behavior at runtime. Visible opening weapons are an accepted compatibility cost. Later NoWeapon/InitWeapon lifecycle calls remain source-authentic.

Keep class-specific tutorial guards, query-expression ordering, polling-loop exit semantics, and the source-authentic Wing Diver sequence (COMMON_JUMP x2 before the flying gate). Current shooting tutorial runtime is positive. Dialogue/event parity work retained 96 Talk_AddSingle + 6 Voice2 executable callsites; do not invent missing dialogue without source evidence.

Runtime evidence boundary

Meta-parity V3 was accepted by the user for campaigns, maps, limits, outfits/resource behavior and drops. The later reconciled metadata/resource overlay received positive menu/runtime smoke. These results validate the semantic model, but they are not an exhaustive replay of every mission/difficulty combination.

Fail-closed rules

Reject or flag builds that diverge from the shared sequence, lose root table, renormalize LIST field9, inherit EDF6 DLC profile trees by accident, desynchronize TXT/image indices, reset the audited underground set to 8, remove M082/M083 only to mimic old OFFLINE, or globally redefine opcode 1001 because of M000.

Retained static parity acceptance fixture

The R4 indexed-resource audit recorded 112/15/14 OFFLINE and ONLINE LIST rows, 30 localized TXT combinations across EN/JA/KR/CN/SC, and shared image RABs expanded from 286 entries to 288 by adding EDF5_M082.dds and EDF5_M083.dds. The source fixture deliberately left CONFIG unchanged because the studied R43 routing was already qualified; other deployments need their own loader/CONFIG evidence. See exact cross-resource audit.

Source-verified early-campaign resource selector (field6 vs field7)

The original metadata generator made two independent mistakes: it emitted an unnamed DSGO root variable instead of the named table root, and it placed the EDF5 civilian/prototype resource selector in target field7 while clearing target field6. The corrected EDF6 target schema preserves the complete named table container, puts the EDF5 source selector in field6, and sets field7=0 for the retained EDF5 blue-timeline profile. A structurally valid DSGO with the wrong root name can produce missionCount=0; a valid-looking LIST with the selector swapped can silently load the wrong player resource.

The exact source-derived early selector 1 applies to MP03 M000, M001, M003, M004, M005, M006, M006_5, M009, M013, M018, M015_2 and M008. The next unified entry M015 is at zero-based index 12, with selector 0, in both OFFLINE and ONLINE. The DLC1/DLC2 source lists were asserted semantically identical across modes rather than assumed.

These are source-corpus and converter invariant checks, not an instruction to copy the same flags to unrelated EDF6 campaigns. The metadata generator's later v5 variant also constructs the unified MP03 list as M000 + EDF5 ONLINE sequence for both modes. The older v4 generator still had 112 OFFLINE / 111 ONLINE, which is invalid for this EDF6 shared-progress target.

Metadata and underground weapon research: later updates supersede the document's opening status

The original META_PARITY_CORRECTION_LEDGER_R1_2026-08-31.json explicitly invalidates two earlier candidate fixes. V1 omitted the named DSGO LIST root table and the EDF6 reader obtained missionCount=0, then faulted while evaluating its EasyClearRatio. V2 proposed forcing LIST field4=1, but native EDF6 uses the zero-based row ordinal there; V2 was rejected before testing. The retained V3 contract preserves the full table, puts EDF5 source resource selector in target field6, clears field7=0, places progression in field9, and preserves target difficulty profile structure with source gameplay values.

The focused underground weapon investigation is not still open simply because its opening paragraphs say unresolved: sections added later on 3 September record direct user runtime PASS for M000, M001 and DM019 with flags=40, and correct the acceptance criterion. Native EDF6 can allow equipment selection before launch yet refuse underground support when used. The earlier 512/520/552 flag alternative, injected diagnostics and global WeaponCondition patches should therefore not be promoted as the tested solution. This resolved underground support-use semantics is separate from the historical DM019 AI-vs-NPC through-wall targeting/pathing concern, which the later 1.0.2 runtime-state ledger still lists as needing current-revision retest.

The broad semantic authority ledger was also appended later with the M014 mission-18 source-derived production behavior: do not infer its current state from only its 3 September opening section. This evidence is about selected modified-game compatibility cases and native schema, not exhaustive multiplayer/mission-clear certification.

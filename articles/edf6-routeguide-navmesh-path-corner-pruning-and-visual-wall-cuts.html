EDF6 route guide arrows: navmesh search, corner pruning and misleading wall crossings

EDF 6Game technical referencesNavigation and interface
Technical reference · Static source and contributor checks, with build and open questions noted; no new R131 EDF runtime

The moving arrow strip drawn by RouteGuide is not the navigation mesh itself. It takes an AI path's corners, simplifies and smooths them, then draws its own world-space line. Thus a guide line that seems to cross a wall does not, on its own, demonstrate an invalid navigation mesh or physically permeable wall.

Native path and renderer

RouteGuide obtains its path through a Havok HUMAN-world ai::Character search, not by reading MISSION.RMPA route names. The line renderer generates vertices and advances a texture phase based on time and accumulated distance; this is why the arrows appear to flow along the path. The separate RouteGuide_Arrow SGO creates one arrow and is a different scene-object class.

The route-guide object has two explicit target modes in the studied sources:

  • Mode 1: follow a target object and stop if that object disappears.
  • Mode 2: follow a fixed area/point location.

A legacy EDF5 BVM entry also reached a mode-0 route path in the studied EDF6 binary, but the target-mode handler did not cover 0. That raised a source-level risk of a zero-origin endpoint in a converted mission. The hub did not report a game demonstration of this anomaly.

Why visually cutting corners is possible

The draw route first prunes near-duplicate corners: in the observed default configuration, corners within approximately 15 m of the start are dropped and subsequent corners within 7 m of the preceding kept point are dropped. It then creates a Hermite-style curve through midpoints rather than requiring every original corner to become an exact vertex. Additional smoothing blends indexed points between frames, with factor 0.04 (or 0.08 in the alternate script condition).

Three distinct transformations can therefore change the visible line:

  1. Dropping a near corner can bridge over the edge of a nearby structure.
  2. The smoothed curve can leave the exact polygonal AI route even when its original corners follow a corridor.
  3. When a path's number of corners changes, index-to-index interpolation can temporarily blend unrelated positions.

The studied code also allows a straight player-to-target line after a failed/missing query result, which may cross obstacles. These are explanations from code and offline geometry reasoning; the original contributors did not perform an exhaustive gameplay qualification of every map and guide mode.

Keep navigation evidence separate

Do not infer that the rendered line is a test of obstacle clearance, enemy attack targeting or the navmesh graph's validity. A mission can have correct physical collision but wrong AI route data, or a correct route graph but inaccurate guide rendering.

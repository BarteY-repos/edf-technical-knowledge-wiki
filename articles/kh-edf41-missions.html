This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Facts

EDF4.1 mission scripts found within EDF5 project

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-bvm-in-edf5-tree

The EDF5 game tree examined by the EDF5-to-EDF6 transpiler project contains an EDF 4.1 subtree with 126 MISSION.BVM files.

Basis: file-tree census (335 BVM files classified)

Attribution: EDF5-to-EDF6 mission transpiler R37 section 4 (Bartey drop) · 2026-08-26

SetEncountReportRadius BVM native 3000

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-set-encount-report-radius

SetEncountReportRadius(object, radius) is EDF 4.1's script native table 1 id 3000 (14B2E5): it pops the radius (float, top) and the object handle (int) and writes the float to the object's +0x240, which the SGO's game_object_encount[0] fills at 28CF66 (re-read). EDF6's BVM executor routes table-1 id 3000 to no handler (../edf6/missions.md#encount-report-radius-bvm); the author says EDF5 has no native for it, while the hub knows an EDF5 custom call 3024 SetEncountReportRadius (../edf5/mission-vm.md, EDF5 +0x2E4), so the author likely means the table-1 form. DLC mission M508 sets it on its 18 Deiroi.

Basis: the author's static reading; 28CF66 re-read with fn.py

Addresses (build-specific RVAs unless indicated): 14B2E5, 28CF66

Attribution: hajisensai, All Forces source src/edf41natives.cpp (round 24) · 2026-11-07

The EDF41-to-EDF6 project translated EDF 4.1 missions M001, M004, M012 and M014 through its semantic engine

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-mission-vm-partial

The EDF41-to-EDF6 project translated EDF 4.1 missions M001, M004, M012 and M014 through its semantic engine; M002 had an event-slot / zero-RegisterEvent ambiguity and M003 one unresolved custom-call family cuscall0 901. Offline only.

Basis: the project's mission engine checkpoint

Attribution: EDF41-to-EDF6 handoff (Bartey), TECHNICAL_HANDOFF_ORIGINAL section 8 · 2026-10-14

Custom call 3019 max-HP percentage

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-call-3019-durability

Custom call 3019 (object, percent) multiplies an object's max HP +0x168 by percent / 100 (AB6884 = 100.0) and sets current HP +0x16C = min(current x percent / 100, the new max), as in EDF5 (../edf5/mission-vm.md#bvm-call-3019-durability): a durability factor on one object after its spawn. The natives switch takes id & 0x7F (byte table 14C9F8, RVA table 14C8A8, head 14B41D); 3019's case 14C097 calls 153E80(script, handle, percent), its only caller. A second native at case 14C2F9 scales only the current HP (capped at max; id not identified). Scripts apply 3019 to the handle a single CreateEnemy returned: 62 calls in 10 of the 98 online-list scripts (tanks and NPCs too, e.g. m113's tanks at 50 % / 20 %).

Basis: fn.py; the switch tables read from EDF41.exe (scratch File_Storage/Logs/catalog/switch_case.py); usage counted over the edftools disassembly (scratch bvm_dis.py --game edf41 all, File_Storage/Logs/catalog/bvm41/)

Addresses (build-specific RVAs unless indicated): 14C097, 153E80, 14C9F8, 14C8A8, 14B41D, 14C2F9, AB6884

Attribution: KH chat 78 (curator) · 2026-11-10

Fallen Flagship Shield Bearer HP call sequence

Evidence: static · Build: steam-57aab039 · Fact ID: edf41-m201-3019-twice

Mission 86 Fallen Flagship (m201) calls 3019 on its first Shield Bearer (shield01, AlienTrailer401_L) twice, once after its own spawn and again after the second Shield Bearer's, whose handle (shield02, AlienTrailer401) gets none: the first is weakened twice (percent x percent: Easy 25 %, Hard 49 %, Hardest 64 %, Inferno 100 %), the second not at all, most likely a script slip. The three extra-large fixed Shield Bearers get the percent once.

Basis: m201 disassembly read (edftools); _tools/bvm_eval.py gives the same

Attribution: KH chat 78 (curator) · 2026-11-10

Mission clear marks (round 10, novae (ajane)'s outside set; source: pickups.md header)

On a clear, 34BAF0 loops over players and classes

Evidence: static · Build: steam-57aab039 · Fact ID: mission-clear-bits

On a clear, 34BAF0 loops over players and classes; the difficulty is [r8+0x44] (34BC73), and vanilla EDF 4.1 sets only the cleared difficulty's bit (mov eax,1 / shl al,cl / or [rdx+8],al at 34BC8E) in the byte [save + 0xEE8 + class*0x200 + mission]: Easy 0x01, Normal 0x02, Hard 0x04, Hardest 0x08, Inferno 0x10. Clearing Inferno does not mark the lower difficulties (EDF5 and EDF6 mark the lower ones for Normal and Hard: ../edf6/missions.md#mission-clear-cascade-v2). FevGrave's InfernoClearsAll_EDF41 ORs a per-difficulty mask instead; FevGrave reports the table version works in game (2026-10-06). Cryswar's ClearCreditsLowerDifficulties (supplied 2026-11-01, written "with Claude") changes the same 7 bytes to B0 02 D2 E0 FE C8 90 (mov al,2 / shl al,cl / dec al / nop), so the stored mask is (2 << difficulty) - 1 (an Inferno clear sets 0x1F); its anchor B8 01 00 00 00 D2 E0 08 42 08 41 8B C1 matches once at 34BC8E; no in-game result is stated.

Basis: FevGrave's disassembly notes; anchor unique; the difficulty load decoded; Cryswar's patch bytes decoded and its anchor checked in EDF41.exe (2026-11-01)

Addresses (build-specific RVAs unless indicated): 34BAF0, 34BC73, 34BC8E

Attribution: FevGrave (InfernoClearsAll_EDF41), novae (ajane)'s EDF 4.1 outside set (ExtraPatches), Cryswar (ClearCreditsLowerDifficulties) · 2026-10-16

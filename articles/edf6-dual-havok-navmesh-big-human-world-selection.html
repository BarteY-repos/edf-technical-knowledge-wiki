EDF6 navigation: two Havok worlds, HUMAN and BIG, and their source mesh differences

EDF 6Game technical referencesNative navigation
Technical reference · Static source and contributor checks, with build and open questions noted; no new R131 EDF runtime

On the studied EDF6 executable and map corpus, each map has two Havok navigation resources, with matching .NVMD metadata:

Resource suffix AI world Native actor examples
.NAVMESH_H.HKT 0 — HUMAN HumanBase allied soldiers, vehicles, RouteGuide and BombBullet01
.NAVMESH.HKT 1 — BIG HumanoidBase, large Berserker/Hector actors, Merman, ShellFish and GiantDango

The suffix _H maps to the HUMAN world, not the BIG world. The original route-building function chooses the names according to the inverse-looking selector in its caller; relying on alphabetical order or filename length would invert the maps.

What these files really store

Each navigation HKT contains section-indexed triplets: NavMesh<n> (hkaiNavMesh), Graph<n> (hkaiDirectedGraphExplicitCost) and Mediator<n> (hkaiQueryMediator). One studied EDFROOM file had 15 sections. Both classes of navmesh were almost entirely upward-facing floor geometry (99.6–100% of measured face area). The _H mesh typically had 5–6× more faces than the BIG version in the reported corpus.

These are not wall-climbing navigation meshes. Enemy wall-climbing and attachment can be handled by a different controller, and the existence of a detailed collision body is not proof it has a traversable navmesh connection. A valid NAVMESH_H.HKT is also not enough to establish that an EDF4.1 port has the correct paths on a different map geometry.

Runtime ownership and open limits

MapRABInit requests both variants, and the map manager creates separate AI worlds. CreateAiCharacter takes a world ID, so actors can end up using different route graphs within the same scene. A contributor tried replacing the HUMAN source mesh with the BIG one and did not observe a clear behavioral difference in that specific test. That was inconclusive: it neither disproves the world separation nor establishes that swapping the files is safe.

Evidence: source-level Havok file inspection, static EDF.dll analysis (+0x18F9A0, +0x121470) and the one inconclusive contributor experiment. Build steam-678ccb46; no new R131 in-game validation.

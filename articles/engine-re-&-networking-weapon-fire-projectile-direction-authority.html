Subsequent RNG and class-internal trajectory evolution

The common final transform is only the beginning of a projectile's lifecycle. Some Bullet implementations derive ongoing motion or detonation state from their constructor RNG seed. Read Weapon RNG, subtype1 reconstruction and per-class effects for the exact LCG, creation-state offsets, Charge/PreCharge counters, and class-specific loss of parity. Dynamic VehicleSwingShoot direction explains why the vehicle's effective per-shot basis can differ from its static config.

EDF6 projectile direction is not governed solely by the networked Soldier facing/orientation fields. The binary exposes a separate weapon-fire → spread → projectile-construction authority chain.

Per-shot fire transform

Weapon fire has its own synchronized transform sourced from the weapon muzzle node.

  • sender 0x694910 carries per-shot entry+0x50;
  • receiver 0x692540 restores the same transform before projectile creation;
  • Weapon+0xBC8 RNG state is conditionally transmitted/restored before spread;
  • common spread builder 0x691560 constructs the final per-projectile transform on both local and remote paths.

Therefore a stale or divergent Soldier presentation orientation is not automatically the cause of a divergent shot. The fire path can carry more specific authority.

Bullet replicated-state handoff

The recovered construction chain:

0x696FD0
 -> 0x181194280
 -> 0x181189C00
 -> 0x22E9C0
 -> 0x231CC0

seeds the Bullet replicated-state subobject at complete-object +0x140.

Inside that subobject:

  • +0xB80 is the projectile position/state-position lane;
  • +0xB90 is the motion/direction state;
  • 0x233450 serializes the same subobject;
  • 0x233400 restores it on receive.

The practical consequence is explicit: Soldier ordinary orientation is not the sole/final authority for actual projectile direction.

Layer identity

Weapon-fire TX is proven as NetworkObject logical type 6. Do not collapse that logical layer into an outer 0x3300/class3 label unless the framing edge is separately proven.

This matters when instrumenting or repairing aim/shot desync: capture the weapon/fire and projectile-creation layers rather than repeatedly forcing a generic Soldier orientation field.

Reliability does not recreate omitted state

Later R17 Engine RE proves NetworkBullet selector0/1/2 normal shipping traffic uses Sandlot retained reliability above EOS. Transient physical packet loss can therefore be recovered for bytes that were actually serialized.

That mechanism cannot restore class-internal state that never enters the selector payload. Current concrete examples are:

  • FlameBullet02 motion scalars;
  • LightningBullet01 per-projectile RNG/path state;
  • SolidExpBullet01 detonation countdown.

This is why a reliable selector can arrive correctly while the reconstructed remote projectile still evolves differently.

Repair principle

The preferred next repair surface is minimal initial seed/state parity at projectile creation, if that proves sufficient. Broad per-frame replication should be a later fallback, not the first assumption.

A valid repair must establish, per affected projectile class:

  1. the minimal sender state/seed required for deterministic local behavior;
  2. whether existing weapon-fire/projectile identity can carry or derive it;
  3. the narrow receiver injection point before class construction/update diverges;
  4. whether one-time creation parity closes the divergence.

Unresolved: exact minimal state for the three named projectile classes and the final runtime outcome of such a narrow repair.

EDF 4.1 navigation: geometry, collision binding and open reconstruction

Source-backed research / case study · Exact native

Current evidence: exact source count, HKT still not byte-exact

The natural reconstructed R32 source-semantic selection does achieve the exact historical 65 group / 1,405 placement / 251 exact-zero / 1,153 yaw / 1 mixed / 4,971 final footprint census. It uses source group-union XZ area, source raw cached-AABB max_xz >= 5.75, 4,994 pre-dedupe instances and 23 naturally scoped FixB semantic removals. This is a reconstructed candidate, not recovered historical executable code.

The historical R1D LOW HKT target remains 381,512 bytes, SHA-256 87f8b3594f081c9dc758e41a7149971061d0bf6dad41867a6d342507507fc5fb; no currently documented R32 natural carve output matches it. The retained R75 best natural candidate is 381,544 bytes (+32); matching face counts and NVMD is insufficient. The older 381,528-byte (+16) candidate uses a non-natural group swap and is only a forensic control.

The selected MAPO rows' quaternion/translation source fields were independently enumerated; eight complete component-transform carving variants preserved 4,971 body instances but yielded no natural 277-face set under the retained R58 predicate family. Audits through R100 excluded placement aliases, shared Havok shape-object aliases, multiple base/collision signatures among 63 MAPO-resolved selected groups, and body-role metadata as alternative 4,971 selectors in the selected corpus. Two of the 65 selected groups had no captured R100 MAPO signature, so the audit cannot assert unique source-pair identity for those two; see the 65-group source census. These are offline negative bounds, not evidence that every possible source-semantic mechanism has been exhausted.

Read the current NAV technical entry point, source selection and exact-oracle rules, MAPO component semantics and identity/deduplication audits. The detailed earlier R19 experiments below remain as historical diagnostics and should not be presented as the current frontier.

Current authority boundary

Evidence level: Exact byte oracles + offline reconstruction evidence. EDF6 runtime qualification for the current R1D reconstruction remains pending.

Implementation rule: Keep four states separate:

  1. R1C baseline — byte-exact and revalidated.
  2. Historical R1D oracle — exact target bytes, hashes and classifier census are known.
  3. R1D resolver/classifier reconstruction — source binding and the 65-group placement/rotation census are now naturally reproduced, but a compatible candidate body population is reconstructed to exact count, but original historical executable eligibility source and exact final carve remain unrecovered.
  4. Current carve candidate — topology and NVMD can match while HKT bytes remain non-exact; it is not authority.

Do not promote a candidate merely because its triangle count, group count or placement count matches the historical target.

The remaining blocker is the historical pre-classifier construction of GroupGeometry.pieces: the active body-level subset that existed before R3 classification_candidates() / evaluate().

Recovered R3 evaluation semantics

The retained R3 logic behaves as follows:

  1. select source-static group candidates;
  2. create rows from placements intersecting selected groups;
  3. activate footprint accounting only for exact_zero placements;
  4. for each selected group present in such a placement, accumulate len(group_geometries[g].pieces).

The current full geometry is too broad. The historical pieces population must already have been reduced to an eligible active-body subset before this evaluation stage.

Body-classifier diagnostics already closed

The following discriminators have already been tested. Do not repeat them as blind sweeps:

  • compatibility/body-local max_xz >= 5.75 over the natural selected population: 4,913 footprints;
  • raw hkpListShape.aabbHalfExtents equivalent: 4,916;
  • body-filter -> motion-state group build -> natural top-65: 4,944 while preserving the exact placement/rotation census;
  • manually adding one convex radius: 4,955 — invalid;
  • manually adding two convex radii: 4,992 — invalid;
  • threshold-change enumeration around 5.75: no 4,971 hit;
  • simple width X >= 5.75 && width Z >= 5.75: recreates the older near-state 59 groups / 1,361 placements / 246 zero / 1,114 yaw / 1 mixed, not the historical classifier;
  • nw_hct_monorailpole1_hk explains +44 placements (+5 zero / +39 yaw) relative to that near-state, but does not recover the complete historical active-body builder;
  • a sparse MILP can force the numerical 65/1,405/251/1,153/1/4,971 target, but requires about 22 group swaps versus the natural top-65 and is diagnostic only, not historical evidence;
  • sk_car_bus01_hk.polymsh3, the remaining parser/body failure, has zero exact-zero placements and sits outside the natural top-65, so it cannot explain the missing footprints.

Known exception: hkpListShape.aabbHalfExtents already includes child convex radius. Adding radius again double-counts geometry and is not a valid reconstruction path.

Earlier inferred two-stage model (not recovered source code)

An earlier evidence-consistent interpretation was a two-stage classifier; R19 found that the executable body-filter builder is not preserved, so this remains a model rather than a recovered algorithm:

  1. a historical pre-classifier active-body builder constructs the eligible GroupGeometry.pieces subset using body-level semantics, with max_xz >= 5.75 retained as fixed historical evidence;
  2. R3-style group metrics/ranking and evaluate() operate on that already-filtered piece population.

This reconciles the retained max_xz >= 5.75 “body classifier” note with the later R3 code, which computes group metrics over whatever pieces population it receives.

Implementation rule: Recover the builder semantics. Do not tune 5.75, substitute MILP-selected groups or redesign the downstream R3 evaluator without source evidence.

Reconstruction rule from the retained source-semantic evidence

Use the R32 reconstructed candidate for comparison, not arbitrary group swaps or thresholds. Preserve raw cached-AABB boundary behavior, 23 FixB deduplication removals, source-identity links and the body-local R58 predicate family. The historical R1D original body filter and exact HKT remain open, so additional probes require a new source-backed discriminator and should first preserve the complete census before any LOW bake. Do not manually delete seam records or infer HKT byte identity from equal topology.

Unresolved: Current R1D reconstruction has no Windows/MSVC, EDF6 runtime, mission-restart, full-138-mission or two-PC PASS. Offline/static equality on counts, group census or NVMD is not runtime parity and is not byte-exact R1D authority.

Newer functional HillyCity pilot is not a historical R1D oracle

The separate EDF4.1→EDF6 functionality branch selected a source-derived NW_HILLYCITY_LIGHT NAV candidate (LOW 381,544 bytes / HIGH 381,544 bytes, NVMD 18,040 bytes), instead of geometrically unrelated EDF6 donor navigation. That candidate follows the 1,562-vertex / 2,928-face R1C raster and a 277-face body-local carve to 2,651 faces. It is not byte-identical to the recovered historical 381,512-byte R1D LOW oracle. These two statements are not contradictory: one is a historical exact-output reconstruction target; the other is a game-functionality experiment with known, structurally consistent source geometry.

A later R12 source audit retained the HillyCity pilot but left Windows compilation and real EDF6 pathing tests pending. Neither the R1D comparison nor pilot's offline output hashes prove the 16-map navigation problem has been fixed. Read donor-vs-source NAV boundary and pilot output identity.

Further original geometry evidence

The bounded original MAD survey of 16 EDF4.1 map families is reported separately at 16-map static-mesh geometry and 3D connectivity. Its 31-body sample and diagnostic component counts do not qualify NPC paths or replace R1D HKT/NVMD authority.

Independent original-source 4 m grid and obstacle-contact research

There is no justified arithmetic shortcut between the HillyCity historical R1D 4,971-footprint oracle and the original SK_HEIGEN02 265 static-MAD placements in the separate 4 m SHFB terrain study. The former reconstructs a particular historical carving/identity pipeline and tests byte-level HKT equivalence; the latter asks whether raw source terrain cells are geometrically close to map objects under an illustrative capsule. They use different maps, predicates, resource scopes and outputs.

The seven original SK map source domains have 2 m raw SHFB spacing and experimental 4 m HKT/NVMD tile feasibility, but no full native NAV policy is recovered for all 16 map families. In the one-map SK_HEIGEN02 R35 survey, 166 source instances were treated as closed geometric solids and 99 as open, with proximity counts varying strongly across a 0.25 / 0.45 / 0.65 m test radius. These are sample agent shapes, not EDF6 Ranger/Fencer/Hector dimensions. In particular, using a closed-mesh proximity mask in place of qualified game collision classification could introduce new stuck-NPC errors.

The bounded 4-tile result demonstrates that existing HKT/NVMD machinery can serialize two different source occupancy hypotheses while keeping tile seams and NVMD structure consistent. It does not justify deploying either hypothesis as a correct source-native navigation mesh. See seven SK contact detail and HKT/NVMD binary compatibility.

Separate source-collision survey through R45 is not an R1D byte-exact fix

The original EDF4.1 non-SK source-geometry series R36–R45 examines collision-body shape categories, MAPB group links, placed-geometry hypotheses and bounded 4 m spatial windows. It is not the same validation target as the historical R1D 381,512-byte LOW HKT oracle above. The survey's 145 originally unmatched explicit MAPO .hkt records were resolved to source compact rigid bodies rather than missing files, and its nine-map group graph contains 17 owners / 169 children. Neither fact recovers R1D's exact historical carve predicate or native EDF6 agent behavior.

The six non-SK city surveys cover only 768 of 8,402 planned 64 m geometry windows. There is no source-backed reason to substitute those survey percentages, the 39,252 MAPB record population or the R1D 4,971 body-level footprints for one another: their denominators and tests are different. The resolved resources are especially valuable when assessing missing collision vs wrong navigation diagnoses, but actual NPC pathfinding remains untested. See source geometry and multilayer columns, MAPB/MAPO named collisions and donor NAV versus source evidence.

Source-backed research / case study · Contributed research; per-claim static, verified, unverified; not independently re-tested

This is a source-attributed research appendix, not a chronology or a replacement for topic reference pages. The observations were contributed in the EDF Knowledge Hub export, snapshot 2026-11-14, revision 54f89cd, compiled by novae (ajane).

Read each statement with its evidence grade and exact build. Verified means a reported game test, static means reverse engineering or source inspection without a reported game test, and unverified is a hypothesis. None of these observations was newly tested for this wiki release.

Structure

EFS is the particle system new in EDF6

Evidence: static · Build: not stated (game data) · Fact ID: efs-overview

EFS is the particle system new in EDF6. Effects are .esb files inside an .efarc (RAB-format) archive, alongside .ssb sprite settings; hash keys in the data choose which EFS component is created. Editing: KittopiaCreator's EFS Tool (Discord only).

Basis: the wiki's EFS category page and Getting Started guide

Attribution: EDF Modding Wiki, Category:EFS (KittopiaCreator, rev 2025-08-26), Guides:GettingStarted/EDF6/EN (ktaro) · 2026-10-29

LineStripObject trail draw transform

Evidence: static · Build: steam-678ccb46 · Fact ID: linestrip-trail-matrix

LineStripObject smoke trails are drawn through the matrix they were created with: the factory 842E0(mgr, out, matrix, InitParam) builds the object, whose base constructor 1189C00 copies the matrix at InitParam+0x08 to obj+0x60 and nothing changes it later; the render task 2F6310 copies obj+0x60 to the renderer's +0x260 each frame and the draw (2F583A) passes it as the world matrix to 11544F0; the vertices (2F5AC0) take each node's +0x00 as is, and nodes are placed (2F6110 -> 2F4C10) at the emitter's core+0x50 in world coordinates. So a trail must be created with the identity matrix, as the game's own world-space trails are (the inline trail at 24B8EC passes the identity at 1FFF3D0; the factory's only stock caller A01A0 passes an unrotated matrix); a nozzle matrix moves and turns every node (the author measured 5785 m off before, 3.16 m after the fix, one frame of flight).

Basis: the author's static reading and their in-game runs with a debug log (static for the hub)

Effects: runtime EFS, ESB, particles, blood and weather

Source and evidence scope: EDF Knowledge Hub revision 5b589ca, EDF6 steam-678ccb46. Technical contributors here include novae (ajane), hajisensai's All Forces primer-plan.md, KittopiaCreator's ESB type-key additions and the mod-making workbook shared by ktaro. The workbook entries are unverified observations or modding experiments, not established native format guarantees. Ten additional records in this source file were already reconciled in the dedicated EFS/ESB reference and EffectGenUtil/particle reference; their source-ID anchors remain there.

EFS runtime, archive lookup, binary nodes and CRC keys

EFS native runtime (static): EDF6's efs namespace has 231 RTTI names covering emitters, singletons, render info classes, transform/color/shape/particle nodes, lights, schedule, archives and renderer utilities. Runtime classes include efs::Emitter and efs::NodeParticle_Particle2D. The examined EDF5 and EDF4.1 binaries lack this EFS/ATF namespace; this does not establish every EDF6 emitter's particle storage or update policy.

Native scope (static census): 225 vtables across efs/atf/spr expose 661 distinct function targets; the main EFS code span 10AFE00..10FE000 is roughly 289 KiB, with calls into the graphics layer, archive interfaces and runtime helpers. This is a build-specific function census, not a public API contract.

Effect texture resolution (static): efs::RenderInfo_Texture follows a MATERIALTEXTURE reference node to a name, resolves it with 10BD080 and stores a texture handle (zero if missing). Archive name search uppercases ASCII a–z before matching; non-ASCII names must still match the source resource exactly. A lookup failure is not evidence the same filename exists in another resource group.

ESB node pointers (static): TRANSFORM carries parent, scale, rotation and translation links at +0x04/+0x08/+0x0C/+0x10; SINGLETON links transform/material/color; LIFE links components plus flags and lifetime; SCHEDULENODE links life and timing. Some labels for scale/rotation slots come from observed type keys, not direct field names.

AnimationCurve shape (static with tangent inference): a tagged record begins at -3, contains type, unknown value, variance and a key count; each key has seven floats including time, value and possible in/out tangent pairs. Four curves form RGBA, while three form XYZ; the exact interpretation of remaining floats was not proven.

CRC-32 node inventory (static): additional type keys cover transform/bone/root/camera/billboard variants, XYZ and fixed translation/rotation/scale, color, vectors, primitive shapes, mesh quad/ring, gravity and UV. KittopiaCreator's supplemental keys include SPOTLIGHT 87C0BCF0, POINTLIGHT B420D6B1, BARLIGHT F7CCA492, plus sprite TRANSLATIONXY and ROTATIONZ. Unnamed type keys remain unresolved rather than being assigned guessed labels.

Worked ESB example (static): get_weapon.esb has one scheduled 30-frame LIFE with a singleton textured WEAPON.DDS. Its Y translation rises from 1 to 2 m by around frame 16, while alpha fades by frame 30. The popup therefore rises then disappears over roughly half a second at 60 fps; it is an asset-specific example, not an all-effects schema.

Workbook-only EFS controls — unverified experiments

Unverified — tool workflow: the workbook describes an .efarc with EFFECT/MODEL/TEXTURE groups, ESB-to-XML conversion via EFS Tool and archive packing through EDF Tools (sometimes yielding a .rab extension). Tool limits and XML unk* fields matter: neither a round-trip nor lossless coverage of all node types is established by this note.

Unverified — scale curve types: workbook tests of NodeCIScale_All suggest type 0 hides, type 1 smooth interpolation, type 2 linear and type 3 stepping; type 4 appeared to hide. Keys specify time, value and five still-unknown values. This is a single-notes behavior map, not a native enum.

Unverified — impact alignment: most tested hit EFS effects aligned with the hit normal, while certain NodeVector_XYZ and 2D scale paths were observed in world coordinates. The inability to force arbitrary horizontal smoke is the author's finding for those tests, not proof of a universal limitation.

Unverified — model shader animation: RenderInfo_Model tests found ChangeParams entries naming a shader parameter (for example diffuse) with four animated RGBA curves. Other int flags were interpreted as blend, depth or fill behavior only from examples; they remain unsettled.

Unverified — texture render modes and depth bias: tests of one Jormungand effect's RenderInfo_Texture parameters distinguished four render modes, a pixel-as-light versus pixel-as-paint interpretation, and a floating depth offset that moves the effect relative to occluders. A flag 1 appeared to stop rotation, but this is the same ktaro experiment as the earlier note, not independent confirmation.

Unverified — root lifetime attributes: 19 combinations of <EFS unk1="..." anim_frames="..."> on one Tempest projectile changed whether emitters, lights or the entire effect vanished after roughly a second. There is no established general formula for these two root attributes.

Unverified — emitter shapes: NodeShape_Plane experiments changed area dimensions and orientation, with one setting crashing; NodeShape_Cylinder tests suggested rotation, diameter, length and emission direction fields while others remained unknown. These findings are unsuitable as universal authoring validation without native tests.

Stock blood generator, limb regrowth and effect pool scope

EffectGenUtil hit splash (static): global 20B2980 exposes routine 2E5680 with position, surface normal, attack direction, owner matrix, RGBA, scale and a packed spray parameter block. The stock giant ant uses BloodSplash_01.dds with scale min(4, damage×0.1) and specific spray flags.

Death spray and tint (static, one signature less certain): burst 2E1090 accepts direction and color, while ground pool 2E5BB0 uses position/color/scale. A giant ant emits three random-bone bursts and a pool scaled by DeathBloodScale; its base RGBA at 17BC080 is (0.675, 0.525, 0.10, 0.125), with hit-splash alpha multiplied by eight.

Native call safety (static): blood routines register objects with the game system and use global RNG, so the research routes them from the game update thread, not a Havok collision worker. Texture lookup can return null and the splash path does not guard it; a mod should only select resident textures and valid utility/manager objects.

Regrowth SGO effects (static): Colonist, Grey, Kruul and Kraken variants use body_revive_effect with HumanoidPartsReviveEffect_Splash and a 再生01.dds texture. Colors are usually [1,2,1.5,1], with a brighter boss variant; Kraken includes a tentacle-revival sound.

Regrowth state machine (static): broken part update 499270 waits for delay, a living owner and a suitable parent part, then regrowth state shrinks/rescales limb bones, restores visibility and refills part HP before returning to normal. Scale pass 490BF0 multiplies bone matrix axes for entries with reduced scale. EDF6 retains a particle regrowth spray and adds an EFS break effect, not a traced EFS regrowth effect.

Unverified — online flag meaning: the GameDataMgr byte at +0x40 governs debris/body pool limits and is plausibly an online-mode discriminator because of a neighboring network-object pattern. Its writer was not traced, so the interpretation remains a hypothesis even though the pool-count changes themselves were mapped elsewhere.

Mission weather, CPU particle stepping and projectile position

EventLightTool (static): mission scripts fade up to 28 groups of light, fog, sky color, sun/halo and tone parameters with EnvFadeAnimation and related calls. This changes colors/vectors/brightness, not the loaded sky texture or local cubemap resource.

Weather effects independent of map weather (static): mission-script natives SceneEffect_Snow/Rain/FugitiveDust/Fog and SceneEffect_StartFade create and animate weather effects during a mission. The source counted 59 direct calls across 36 mission scripts beyond shared wrappers; M023 transitions dust to rain later in the mission.

ExplosionWind smoke (static): 2E4D90 makes one world-space ParticleObject using 煙_01, an initial 400-particle burst, about 220–260 frames of life, damping 0.995 and animated RGBA/size. Exact meanings of two related param pairs were not read.

CPU particle ring (static): the emitter stores 0x80-byte particle records in a ring with capacity/live/oldest counters at core +0x188/+0x190/+0x198. 302EE0 updates position from velocity, size from growth, color from deltas, animation frame and damping/acceleration, then retires expired records. A motion impulse may be applied to particle velocity; rotation was not stepped in this path.

Rocket sample point (static): RocketBullet01 shares the flight-block scheme of GrenadeBullet01: current position bullet+0xCC0, velocity bullet+0xCD0 in m/s, and the current-frame travel segment from position−velocity/60 to position.

November 2026: EDF6 decal manager, projection and receiver routing

These 23 source-ID records reconcile novae (ajane)'s steam-678ccb46 disassembly notes into the existing EDF6 effects reference. Static means source-reported address/code reading, not a new live game test. Two mod concepts (clear-all and id0→id1 patch) remain unverified. The same inheritance and lifetime themes occur in EDF5, but all EDF6 addresses below are independently scoped to this build.

RTTI, vtables, constructors and assets

Static. DecalBase vtable 17A7678 has 13 slots and bases SceneObject, snapshot IRecordable and umbra Object. Derived Splash 17A7110, SplashProjection 17A79A0, BulletMark 17A6F60, ExplosionMarks 17A7270 share the base with FullScreen_Fog 17A7B10, FugitiveDust 17A7C10, Rain 17A7D78, Snow 17A8048. Manager vtable is 17A7700. Constructors: base 2D0680; Splash 2CDE80 (0x390 bytes; factory 2CDE20), BulletMark 2CD000, ExplosionMarks 2CE710, SplashProjection 2D4D60; fullscreen 2D6310/2D7C10/2D97A0/2DCF50. Asset RAB app:/Effect/Decal.rab in Root.cpk includes BloodSplash01_n.dds and BloodSplash01_Hight.dds.

DecalBase +0x70 layout migration

Static. EDF6 adds +0x70 to EDF5's corresponding base fields: manager weak pointer +0x198/+0x1A0; unique flag +0x1A8; drawn byte +0x1A9; seconds undrawn +0x1AC; age +0x1B0; lifetime +0x1B4 (default 20); age/lifetime +0x1B8 (1 when lifetime≤0); eviction strength +0x1BC. InitParamBase vtable 17622B0 stores lifetime/strength at +0x30/+0x34, copied after dynamic cast (EDF5 uses +0x28/+0x2C). Shape has endpoints +0x340/+0x350, radius +0x360 and enabled byte +0x364; fade fields are Splash +0x374, SplashProjection/ExplosionMarks +0x370 and BulletMark +0x378.

Manager lifetime and std::list ownership

Static. Static pair manager/control block at 20B3300/20B3308; getter 2D28C0 lazily constructs via 2CF120 when empty/expired, so inspection mods should read the pair rather than forcing a new manager. manager+0x148 points to a std::list sentinel, +0x150 is count; node fields are next, previous, decal pointer at +0x10. Registration appends to tail (2D2814..2D285A), so the first sentinel-linked element is oldest.

Registration is the constructor chokepoint

Static. All eight derived constructors call RegisterDecal at 2D23A0. It retrieves manager 2D28C0, stores a weak pointer, invokes eviction 2D2580, enforces the single-flagged-decal policy and registers the scene node via 11B27D0 and related operations on the +0x120 sub-object.

FullScreen weather and ordinary decals share a bounded pool

Static. Constructor argument 3 sets +0x1A8. All four FullScreen constructors pass 1, ordinary Splash/Projection/Bullet/Explosion marks pass 0. On flagged registration, 2D23A0 deletes other flagged entries; 2D2580 never evicts a flagged entry by low-rank selection. Nevertheless they inhabit the same std::list and count toward the 100-entry cap.

Rank, stacking and 100-entry cap

Static. For nonflagged, not-yet-expired decals, eviction score is (1−age/lifetime)×strength(+0x1BC)×(1−undrawnSeconds(+0x1AC)) (lifetime≤0 uses large constant [176B03C]). The source chooses lowest-ranked eligible overall and lowest within overlap: both shapes must have +0x364 set, and the distance of points returned by 4F640 for the two +0x340/+0x350 segments must be below radius sum. If count exceeds 100 (at 2D27DB), hard-remove lowest global. For ≥6 overlaps (2D27F7) fade lowest overlapping; for >8 (2D2800) hard-remove. All decals use one pool.

Game constants and unexamined mark timing

Static. The source traces a 20-second default lifetime (also death pool and hit spray), fade multiplier 0.95 per frame until below 0.05, a 100-item shared cap, thresholds 6 overlap/fade and above 8 overlap/hard-delete, and death 1 second after being unseen. Bullet/explosion mark smoulder interval was not decoded; EDF5 timing offsets cannot be copied directly.

Age, per-class fade and expiry

Static. Slot 5 (+0x28) updates are Splash 2CE510, Projection 2D5840, BulletMark 2CDC60, ExplosionMarks 2CEEB0. Each deletes via 118A1B0 below fade 0.05 ([1765A04]); calls 2D4C20 to increment age by dt, update age/lifetime and test expiry; once over lifetime, multiplies fade by 0.95 ([179E100]); calls undrawn handler 2D4BD0 and deletes on its true return. FullScreen updates 2D7200/2D8B70/2DB270/2DE280 age, but do not use the undrawn step.

Single offscreen-lifetime compare site

Static. 2D4BD0 consumes and clears +0x1A9: drawn resets +0x1AC to 0; not drawn accumulates dt and signals deletion after 1 second, constant [1C36994]. Its comiss at 2D4C05 is the sole site for that compare in this source (EDF5 uses four). The 0.95 constant has 28 users and 0.05 many; a mod must not rewrite those shared constants as if decal-only.

Soft versus hard removal are distinct

Static. 2D4A10(decal) unlinks and decrements the manager list, drops its weak pointer, and tail-jumps to object delete 118A1B0. Inherited DecalBase slot 12 (+0x60), 2D4B30, instead sets lifetime +0x1B4 to zero to begin soft fading, for all ordinary and FullScreen variants.

Untested mod idea: clear all decals

Unverified. The source did not find a native game caller for a wholesale clear. A proposed mod traverses [[20B3300]+0x148], saves the next list node before possible deletion, skips entries flagged at +0x1A8 (weather), and calls +0x60 (fade) or 2D4A10 (immediate unlink/delete). It has not been tried; it is not an existing exposed game function.

Projection matrices and Umbra subobject

Static. EDF6 decal pose matrix is +0x60..+0x9F, projection +0x380..+0x3BF. The SplashProjection constructor 2D4D60 calls helper 2D5480 from 2D523A to write world matrix +0x1D0, inverse +0x210, depth +0x274 and stacking segments +0x340/+0x350/radius +0x360. Umbra subobject at +0x120 (vtable 17A7A10) is registered at the constructor's end 2D53C3 via 11B30C0. Other decal kinds tail-jump to this path from their slot 3. The EDF5-equivalent move-on-transform route has not been verified in either game, and EDF6 manager's draw loop was not read.

Map renderer receiver IDs and destructible pieces

ID setter and bounded draw-site census

Static. 112D0F0(sys=2139A90,ctx,id) updates [[sys]+8]+0x15C only on change, then flushes via 112E650; all 516/516 DX11.cpk material pixel shaders with 5–7 MRTs refer to g_xgl_id. Fourteen setter call sites include FieldRender::RenderObject slot1 10EE90 (id1 at 10EEF9, id0 at 10F916); Preload_AnimationModel slot1 14FF50 (only mode1 sets id1); MapRenderer draw 170FC0; TreeSkinningModel slot4 17A170 → 176200 (mode1 reads ID from +0x40, allowed values not inspected); BuildingObject 7C8130 and GridTileObject 7C9240 test scenes. Character/corpse/vehicle/weapon drawing does not set this ID in the cited census. Two direct writes of 1 to +0x15C at 112EFE4 and 1159078 finish blend-state blocks.

MapRenderer splits normal and node render lists

Static. MapRenderer (vtable 178FCF8, slot7 170FC0) sets G-buffer ID 1, draws implementation list +0xD8 or +0xE8 (selected by unknown flag +0x60), then sets ID 0 at 1710A7 and draws list +0xF8. It later sets 1 at 171112 and 0 at 171131. ModelRenderer::RenderObject vtable 176BA08 slot2 queues into +0xD8/+0xE8; RenderObject_Nodes vtable 178FCD8 slot2 into +0xF8. Other pre/post lists at [this+0x78] and [this+0x88] were drawn by 16CA90/169B30, but not identified. Do not infer their materials from this split.

Most decal shaders accept only receiver ID 1

Static. Three decal pixel programs at 1F57490, 1F5A1E0, 1F5CBF0 discard unless g_plane_normal.w == 1; a fourth at 1F5F2B0 lacks that test. This is the EDF5-style receiver policy, not a universal rule for every decal program. The id0 node pieces consequently reject marks under the first three programs.

Broken building pieces render via the id0 node list

Static. Crash-body creation 13AEF0 calls 12F330 at 13B199, allocating a shared mesh block, building RenderObject_Nodes via 16E3D0 and appending to the object's +0x1E0 mesh list. Those node objects go to MapRenderer id0 list, explaining decal loss from rubble. Tree builder 177310 and a no-direct-caller 127FA0 also create node objects. Normal id1 RenderObject constructor 16E360 is reached from map-object layers 13E260/145060/1555A0/157580, tree builders 145AD0/177380 and 156B60.

Proposed five-byte NOP experiment, not a tested fix

Unverified. An experiment would neutralize the five-byte rel32 call at 1710A7 to the ID setter, leaving ID1 on list +0xF8, so decals could project onto broken pieces and tree nodes. The next instruction is at 1710AC; later store 171112 would then be redundant. This is inferred from call routing and was not tried—do not present it as a safe production patch, since it broadens receivers beyond rubble.

Impact, death pool and EfsBullet dispatch

Blood spray uses distance-gated projected decals

Static. Hit handler 2E5680 calls 1194BF0 for on-screen/distance test, exits past 75×8×scale = 600×scale (2E5743), spawns BloodSplash particles through 2E1090 using BloodSplash_01.dds, and builds a projected mark through 2E44B0 (FOV 0.785398 radians, 45°, reach min(enemy cap, 40 or 60×scale)). That helper casts map ray 106100 then creates SplashProjection; alternate caller is 484FE0.

Death pool decals scale with enemy size

Static. EffectGenUtil::SplashDecal at 2E5BB0 builds Decal_Splash with lifetime 20, strength 2×size argument and projected size 9.75×size argument (constant [17A8364] only used at 2E5D27). The source found 24 callers among enemy death paths, not a guarantee that every enemy uses it.

One sampled enemy's configurable blood keys

Static, single-example scope. EDF6_GiantDangoLarge initialization at 36A390 reads a blood_effect block with max_splash_distance, particle_size and decal_size, alongside smoke_effect_name and eye_effect_name. Other enemy classes' parameter keys were not surveyed.

Non-blood decal factories and debug commands

Static. Acid splash 2E0130 makes a SplashProjection and particles, called by AcidBullet01 update 2735B0 and 272F00. Bullet mark 2E13C0 has seven cited impact callers, including EffectGenUtil 2E1C60/2E3D30/2E8C40/2E8F20/2EA080/2EB000 and EfsBullet. Explosion mark 2E7290 is called by CreateExplosion 2E5ED0, GenocideExplosion 2E7A30, 2E79B0/25D370 and EfsBullet. Another projected splash 2E5210 is EfsBullet-only. Debug commands decal_splash, decal_splash_proj, decal_bullet_mark are registered by A1F90 (handlers at 96C00/978C0/97D70).

EfsBullet +0xFE4 chooses impact mark

Static. EfsBullet update 23F5A0 calls hit helper 23C700. For +0xFE4: negative = no mark; 0 = default impact 2E1C60; 1 = explosion mark 2E7290 with size +0x8C8 × 4 × +0xFE8; 2 = SplashProjection 2E5210 size +0xD20 × 2 × +0xFE8; 3 = BulletMark 2E13C0 same size. The source did not trace which EFS or weapon SGO field sets +0xFE4.

Impact can spawn a persistent damage area instead

Static; author novae (ajane), patch noted from KittopiaCreator. When EfsBullet has hit-area descriptor +0xF10, update 23F5A0 takes call 23CCC0 instead of the ordinary 23C700 hit mark, builds EfsBullet_HitAreaEffect::InitParam vtable 179E358 from xgs hit/esb/scale/color at node +0xB98, radius +0x78 from bullet +0x8C8 (default 10), duration +0x7C from [[bullet+0xF10]+0x10] (default 600), and RGBA +0x80 from bullet +0xB80..B8C (default ones). It calls 238A80 with system [20B2958], hit matrix and params, one cited caller at 23D25D. The field names and defaults do not prove native design intent beyond that code path.

Overview

The main families are CANM (keyed animation data), CAS (animation players and controllers) and MAB (animation-related events). The exact meaning of a track depends on the generation and the target model's bones. Moving frames between games can require quantization conversion and bone-axis adaptation.

Cross-version caveats

The documented MAB offset-base flag changes across studied generations: EDF4.1/EDF5 0x03 denotes block-relative offsets, while EDF6 0x83 uses record-relative offsets. This does not eliminate all retargeting and event-semantic work. CANM source quantization may already have discarded precision, so a converted target quaternion is not guaranteed bit-identical to a native EDF6 key.

Skeleton and runtime checks

Keep bind poses, animation tracks, controller variables, IK, child attachments and SHKT physics consistent. A controller name missing from the target's variable table is not harmless: it can be an out-of-bounds access. For direct examples see Soldier spine and IK axes and Constructor/rest pose lifecycle.

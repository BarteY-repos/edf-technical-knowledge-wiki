EDF5 online crates: authority, shared seed and serial, locally simulated copies

EDF 5Game technical referencesNetworking / loot
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R133 test

When an enemy dies, the EDF5 drop system checks whether a drop should occur and, if online, whether this machine has authority to make that decision. The resulting crate is created locally, then enough information is sent for peers to create their own copies. It is not a single physical rigid body continuously synchronized across all computers.

The spawning chain

The investigated death paths pass a game object and location into a drop decision, which reads the object parameter game_object_drop_item. Offline the drop branch executes without the online authority gate. Online there is a session-related authority check; the original researcher inferred it represents the host, but the precise session callback was not exhaustively named in that study.

When the condition succeeds, the manager creates a local crate. The network event includes seed, crate serial, position and two floating parameters. Notably the message contains no killer/attacker field; the attacker can exist on the lethal-hit record, but it is not part of this particular crate creation message.

Receivers dispatch the spawn event to the same local crate-construction routine. As a result, each client can simulate its own crate physics after receiving the original seed and position. The source did not find a continuous per-crate position-sync stream in the inspected path. Slight differences in the movement of local copies therefore do not themselves imply a different crate identity.

The serial is the logical identity

A crate's DropItemManager::Unit+0xB0 holds the serial assigned by the manager's +0xA80. That serial is the key used in later pickup events. The manager pointer at Unit +0xB8 is not itself a network identity. The owning player/attacker, the local physical position and the shared crate serial are distinct fields and must not be conflated.

EDF5 Umbra visibility: animated model bounds, bones and object transforms

EDF 5Game technical referencesRendering / culling
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

In EDF5, an AnimationModel holds an oriented bounding box (OBB) whose three axes/half extents are at model offsets +0xF0, +0x100, +0x110; the center is at +0x120. The post-update builds the box and passes it to umbra::Object::SetTransform. This is not merely a decorative debug box: it is the geometry used by the Umbra occlusion/culling object in the studied code.

The source found two builder cases. A resource mode value equal to 1 uses one selected bone's transform scaled by the resource extents. Other cases collect the transformed local boxes of all flagged bones, calculate their encompassing AABB in the model's coordinate system and store corresponding world-space center and half-extents. A model that has been animated can thus have a changing visibility envelope without changing its mesh file.

The Umbra SetTransform implementation stores the box center and a scalar based on the lengths of its axes. The researcher tentatively interpreted the scalar as a bounding radius but explicitly did not establish the normalized unit-box convention ([-1,1] versus [0,1] or half-units). Treat that interpretation as a hypothesis rather than a confirmed radius formula.

The same source distinguishes owner objects from embedded renderables. Human soldiers, vehicles, weapon objects, insects and humanoid enemies embed AnimationModel at different offsets; SceneObject parent/child links associate attached rigid weapons and wing parts. A renderable's address is therefore not automatically its owning game object's address.

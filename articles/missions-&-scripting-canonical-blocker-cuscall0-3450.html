SetAiSearchRadius (3450) — accepted compatibility omission

UniversalMissions & ScriptingScriptingEDF 5EDF 6
Source-backed research / case study · Runtime

Status: KNOWN / INTENTIONALLY OMITTED in the selected playable compatibility path. Not a blocker for this community wiki or the functional EDF5 → EDF6 port. It remains an acknowledged six-call gameplay-fidelity difference, not a solved generic AngelScript binding.

What the call does

In EDF5 mission bytecode, cuscall0 3450 is SetAiSearchRadius(Object, float). This changes the AI object's search/encounter radius, not its formation radius or the range of an unrelated encounter report. Direct native binary analysis found the float write at:

Native build Observed object field
EDF5 object + 0x2E0
EDF6 object + 0x470

An EDF6 native helper writes the target field, but no safely callable AngelScript equivalent was established by the reviewed binary/registration audit. Similar names SetEncountReportRadius (3024) and SetAiFormationRadius (3150) write to distinct fields and must not be substituted.

The six mission-specific calls

Only the researched shipping DLC/DM006_2 (EDF5 DLC2 #4) contained the following occurrences:

Mission object Source radius
frog01_1 200
frog02_1 250
frog03_1 250
frog04_2 400
frog05_1 250
frog06_1 500

These values are properties of one source mission, not defaults for every frog or a universal radius multiplier.

Why the operation was knowingly omitted

Older research attempted to preserve the effect by introducing four modified source-derived frog SGOs. That route crashed during mission loading, whereas a targeted 3450-OFF build:

  • loaded the mission without the reported crash;
  • spawned the frogs normally;
  • allowed the player to complete the mission.

The historical 27 August 2026 A/B candidate was labeled diagnostic-only because it did not reproduce all EDF5 radius behavior. The current explicitly acknowledged scope choice is to accept that omission for the playable port rather than promote the runtime-negative SGO modification or invent an AngelScript method.

This distinction matters: playable/runtime-positive does not mean full search-radius parity. The observed mission completion qualifies the tested candidate; it is not a universal guarantee for all variants, builds or AI behaviors.

Implementation and documentation policy

  1. In the source/BVM model, recognize 3450 by name and arguments; keep six call-site diagnostics and a documented omitted-with-accepted-fidelity-loss policy.
  2. A compiler can remain strict/fail-closed when exact semantic parity is requested. A separate, explicit compatibility mode may omit these six calls with a visible warning, preserving the user's accepted policy.
  3. Never automatically map 3450 to 3024/3150, inject an unverified native helper call or silently patch arbitrary object SGOs.
  4. If someone later wants exact EDF5 AI search behavior, that is optional future fidelity research: first establish a safe EDF6 binding or a target-native resource transformation and qualify it in runtime.

Classification: known source semantics; known tested playable omission; accepted fidelity waiver; optional precise lowering not proven. It must not be listed as an outstanding blocker for finishing the wiki.

Historical exact-output gate is not the accepted gameplay solution

The older EDF5 source-only pipeline can reproduce four source-derived SGO variants for the six cuscall0 3450 uses in DM006_2, with 141/141 historical AC/RMPA output parity. The historical pipeline deliberately fails closed without --source-object-root when that source call is present. Its optional resource path takes three original E503 armor-frog source SGOs (AF, LC, SG) and emits four radius-specific variants. All four output hashes matched the 4 September 2026 exact-recovery audit.

That result is an offline/historical reproduction result, not proof of a safe current runtime lowering. Later in-game evidence was negative for the SGO-specialization path but positive for the deliberately stripped 3450-OFF mission. The selected playable path therefore keeps the previously stated six-call, explicitly disclosed AI fidelity waiver. An exact-parity tool may still enforce strict failure if the behavior is required; a playable compatibility tool must not silently substitute a different native or AngelScript function.

The recovered R1 code remains a separate reference tool: it must not overwrite the canonical BVM compiler. The one omitted zero-byte checkpoint file in the portable recovery does not invalidate the 141 byte-identical generated mission outputs, but means complete archive byte identity was not shown.

EDF6 native Engine RE: 145 object and subobject fields

EDF 6Engine RE & Networking
Technical reference · Exact build static evidence; not a gameplay runtime qualification

This table preserves the full struct_fields.json subset of the build-specific native Engine RE database. Fields describe in-memory object layouts, not serialized file schemas or network message offsets. An offset is measured from the named object/subobject base. Never add offsets from different types without accounting for embedded-object bases. PROVEN/HIGH are source confidence labels grounded in static evidence; neither is a new game-runtime test.

Cross-object boundary reminders

For example, BulletBase+0x130 is final per-projectile RNG state, whereas Bullet InitParam+0x1A0 is the value transferred during construction. A replicated-state subobject at BulletBase+0x140 has its own relative fields. Likewise, a bitmask for NetworkBullet selectors is not a general declaration that every derived projectile supports each selector. See projectile RNG class consumers and NetworkBullet selector semantics.

Bulletbase

Source record: tkw-struct-bulletbase · Source evidence: static

BulletBase common fields: +0x90 current position (used by derived classes including Lightning, Missile and Rocket), +0x130 the final per-projectile 64-bit RNG/scratch state (copied from InitParam+0x1A0 and used by selected derived classes), +0x140 an embedded replicated-projectile-state subobject (passed to the NetworkBullet subtype-0 receive/send helpers, initialized from the created object's transform), +0x760 the live position that receives the network position from +0xB80, and +0xE8C the bit mask that gates the common NetworkBullet selector transmissions (bit 0x1 selector 1 contact/reference, bit 0x2 selector 0 spatial snapshot, bit 0x4 selector 2). BulletBase::InitParam+0x1A0 carries the RNG-derived seed from the weapon's common creation to the bullet constructor.

Charge subtype1

Source record: tkw-struct-charge-subtype1 · Source evidence: static

Charge weapon subtype-1 state: Weapon_ChargeShoot holds a committed scalar at +0x1A68 and committed auxiliary integer at +0x1A6C (serialized by subtype 1, consumed by the charge parameter apply), and the pending pair at +0x1A70 / +0x1A74 (filled by receive before the monotonic target is accepted, committed only after acceptance); Weapon_PreChargeShoot has the committed state at +0x17D0 and the pending state at +0x17D4.

Collision contact record

Source record: tkw-struct-collision-contact-record · Source evidence: static

The 0x50-byte BulletBase::CollisionContactRecord: +0x00 the world position before contact (stored by the local producer, not sent by selector 2), +0x10 contact point (XYZ sent), +0x20 contact normal (used by the motion response and sent), +0x30 and +0x38 the two halves of the shared reference to the collided external object, +0x40 an auxiliary dword that is sent, +0x44 the local object/collision id that selector 2 uses to resolve the external object.

Effect and caption fields

Source record: tkw-struct-effect-and-caption-fields · Source evidence: static

Effect renderer record pointers: LineComponent+0x158, RibbonComponent+0x158 and ParticleComponent+0x1A8. UiDebugMessageNode+0x90 and +0x94 are the start and end seconds of a long caption's scroll (BarteY's subtitle scroll fix only moves them earlier).

Ghostcamera rows

Source record: tkw-struct-ghostcamera-rows · Source evidence: static

CharacterGhostCamera (the free camera class): +0x490..+0x4C0 four rows of the render worker's projective matrix output, +0x4D0..+0x500 four rows copied from the current camera's +0x220..+0x250, +0x52C the camera update generation (incremented by the fixed writer slot 4), and +0xB00..+0xB30 the render-safe snapshot of the current rows (copied by slot 3 and used later by the render worker; BarteY says it is not proven interpolation history). SceneCamera+0x220..+0x250 hold the four rows of the current renderer-bound transform.

Human downed damageinfo 2

Source record: tkw-struct-human-downed-damageinfo-2 · Source evidence: static

The downed-state and damage-record fields of BarteY's table, re-read (corrected copy of #tkw-struct-human-downed-damageinfo): +0x2E8 is every game object's dead byte (combat.md#object-target-fields; ApplyDamage 547C30 sets it at the first HP <= 0, damage-model.md#death-same-object), so a downed player is a player object with it set. +0x314 is the object's team id (combat.md#team-id; players 0), not a player slot: a nonnegative test of it, as in BarteY's revive path, asks whether the object belongs to a team (-1 = none). In the damage record, +0x24 is the attacking team: 547C30 looks up the relation of record+0x24 to target+0x314 in TeamManager's table (row stride 0x38) and treats relation 1 (friends) as friendly fire, passed only with record flag 0x20 or target +0x380 bit 0x100000. +0x50 is the signed amount (HP minus it, clamped between +0x2F0 and +0x2F4, so a negative amount heals). Flag 0x40 of the u16 at +0x60 forces the change through when the target's own accept slots (vfuncs 0x80 / 0x88) refuse it or +0x380 bit 1 is set, is handed to vfunc 0x110, and afterwards copies the HP into +0x5B0; flag 0x200 skips the whole change.

Humanoid shapes climb

Source record: tkw-struct-humanoid-shapes-climb · Source evidence: static

Humanoid fields: +0x90 the root translation (written by the direct-position state handler), +0xD10 the standing shape (used when the low state is inactive), +0xD18 the low (stooped) shape (chosen when EAC & 0x100 or +0x10F0 > 0), +0xD28 the directional front/climb probe shape, +0xD34 the humanoid climb setting 1 (default 33.0, enters ClimbCollisionCheck input +0x28), +0xD38 the small-climb height (default 12.5), +0xD3C climb setting 0 (default 6.0, used to position the directional probe), +0xEAC the state flags (include the low-state selector bits; the direct-position handler sets 0x224), +0x10F0 the low-state timer (nonzero selects the low shape and skips the D28-to-ClimbCollisionCheck relocation window).

Missile rocket positions

Source record: tkw-struct-missile-rocket-positions · Source evidence: static

Authoritative versus presentation positions of rockets and missiles: MissileBullet01, MissileBullet02, RocketBullet01 and its LowLight variant keep the authoritative current position at +0x90 (written by the native OnUpdate); a presentation-refreshed previous position sits at +0x1350 (Missile01 and 02) or +0x1340 (Rocket and LowLight) and must not be read as fixed-update history; MissileBullet02+0x13F0 is a native state/generation field that advances after the fixed update. SolidExpBullet01+0xF00 is the RNG-initialized detonation countdown (at expiry OnUpdate calls the BlowHit detonation/spawn helper).

Mission loadout

Source record: tkw-struct-mission-loadout · Source evidence: static

The mission loadout record: +0x0 the network player/slot index (sent as a byte), +0x4 the soldier type dword (the Fencer is type 3), +0x24 the selected raw armor dword used by the vanilla min(selectedRaw, cap). NetworkUser+0x48 is the logical mission loadout index (kept 0..7 in BarteY's eight-player work).

Missioncontext playerinfo slots

Source record: tkw-struct-missioncontext-playerinfo-slots · Source evidence: static

MissionContext holds exactly four native weak PlayerInfo slots at +0x100, +0x110, +0x120 and +0x130 (stride 0x10); +0x140 is a different field (it includes an independent 16-int array), not storage for a fifth player.

Missionmgr state

Source record: tkw-struct-missionmgr-state · Source evidence: static

MissionMgr fields: +0x130 the active native Package (passed by SetGameMode into LoadPackage; BarteY says it must not be rewritten by hand), +0x6E90 the current soldier type (read when the network mission loadout is built), +0x6F88 the class-family region used as the selected raw armor source by the loadout-build caller (HIGH confidence), +0x14FD0 the active physical MissionPack slot/index. MissionState+0x14FC8 is the start of a native result/state region that the vanilla fifth-player loadout parser write would overlap, and MissionState+0x14FF8 is the real online participant count used by the online create-players path.

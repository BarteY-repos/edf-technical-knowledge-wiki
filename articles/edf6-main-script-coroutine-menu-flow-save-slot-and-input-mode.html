EDF6 MAINSCRIPT.AS: coroutine menu flow, offline mission launch and input-mode initialization

EDF 6Game technical referencesNative mission scripting
Technical reference · Source-derived; evidence grades and build restrictions described in article; no new EDF runtime

The retail EDF6 MAINSCRIPT.AS contains named routines for starting the title, entering headquarters and launching missions. The native AngelScript registration coRoutine createCoRoutine(const string &in) resolves these function declarations by name, rather than hard-wiring every transition as a compiled C++ scene. This is the same underlying game mechanism for normal menu transitions and the retained debug path.

Native routine graph

Routine Role in the observed script
StartToTitle() Loads system save data and reaches the title route
Title() Presents the title/Press Start stage that also initializes input ownership
SlotSelect() Chooses the save slot through CreateSlotSelectUi2
HQMain() Main HQ/menu route, can return PlayMission_Offline
PlayMission_Offline() Starts the selected offline mission and eventually applies its result
Result_Common(g_is_mission_clear) Processes clear/failure after the mission and returns to HQ
Debug_StartOffline() Retained internal function that omits normal title and slot selection

PlayMission_Offline() ultimately returns the name HQMain, so HQ is reconstructed as the next script state when an offline mission ends. This is a fact about the native state machine, not evidence that chained unattended mission launches are an official gameplay feature.

Slot and mode are separate concerns

The retained Debug_StartOffline() sequence calls initialization, boot-complete network location, title-save load, add-on/save readiness waits, an offline mode selection, then LoadSaveData_ModeSelect(). A failed mode-save load returns to StartToTitle. The debug route relies on the current engine slot index because it skips the usual SlotSelect() stage.

For the studied Steam build steam-678ccb46, the GameDataMgr offline mission row was reported at +0x48 and difficulty at +0x4C (values 0–4). The report maps M001 to row 1 and RM015 to row 13. These offsets come from a contributor's native/plug-in mapping and were not separately retraced in EDF.dll during the Knowledge Hub audit.

A revealing input-mode edge case

A contributor runtime test found that entering via the preserved debug startup left actual gameplay in gamepad mode even without an attached pad: keyboard movement/mouse look did not respond, while some menu navigation keys still worked. Repeating entry through the normal title Press Start using a keyboard initialized keyboard/mouse control; a subsequently observed mode byte read zero.

That difference identifies title input-mode initialization as an important part of the genuine startup lifecycle. It does not by itself prove every detail of an alternative initialization path; a direct mode-byte change was specifically left untested.

Evidence and references

  • Static script line positions in the original source: StartToTitle about 442, HQMain 894, PlayMission_Offline 1087, Debug_StartOffline 1865, ApplyModeNo(int) 1895.
  • Native routine registration: EDF.dll+0x12946F0, overload with second any@ argument at +0x1294B00 (build-specific).
  • All code offsets and line numbers apply only to the retained MAINSCRIPT.AS and binary build.

Overview

An EDF map is not one model. Rendering, object placement, collision, navigation and mission-local routes use different resources. A visually successful import can still fail collisions, AI navigation or triggers.

Data flow

MAC (resource container/identity) → MAPB (registrations) + MAPO (placements) → MDB/field rendering + MAD/Havok + HKT/NVMD navigation. MISSION.RMPA is a separate mission-owned route and spawn resource.

Conversion workflow

Identify the exact target game resources, preserve index/key relationships, match target layout and resource type, then check renderer, collisions, navigation and mission spawn positions independently. Build-time pass and in-game pass are different evidence tiers.

Physical props and HUD are not one system

EDF6 projectile collision layers explain why a tree, terrain tile and breakable building can respond differently to the same query. EDF5/EDF6 radar drawing is independent of navmesh, physics and AI line-of-sight geometry.

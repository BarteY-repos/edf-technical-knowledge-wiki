EDF6 ground and air vehicles: gears, fuel, recoil and AI data

EDF 6Game technical referencesVehicles
Technical reference · Original source reports static binary/file analysis, with separately labelled contributor in-game tests; no new tests this release

EDF6's drivable vehicles do not all share one throttle or resource model. The studied code distinguishes multi-gear ground vehicles, simplified tank gearing, fuel-bearing vehicles, and seat-dependent gun recoil. Their values reside in vehicle SGOs, seat definitions and derived runtime state.

Ground-engine gear records

A CarBase vehicle stores a forward gear vector with 16-byte rows (speed, upshift threshold, downshift threshold, drive force). The source identifies additional neutral and reverse rows. Runtime gear index -1 = reverse, -2 = neutral, 0+ = forward gears. A native SGO can provide car_base_engine_gear (full rows plus reverse data) or car_base_engine_simple_gear (used by tanks, with one basic speed/force and fixed ratio constants). The exact thresholds and control flow are source-derived; a simple-gear tank is not a regular car that merely happens to have one forward gear.

The surveyed build uses a vector beginning at CarBase+0x1758 and a gear index at +0x1B24. These are object-memory offsets for one EDF.dll build, not positions within the SGO byte stream.

Fuel resources

The native fuel object has an enabled flag and three floats: capacity, remaining fuel and consumption per unit of input. Its update consumes a quantity proportional to absolute input × usage coefficient, reducing the effective control input when fuel is exhausted. The source documents fuel-bearing helicopter classes and two bike families; not every vehicle must implement it.

The vehicle_setup example uses [999900, 1.666] as capacity/use values. Those are data examples, not an assertion that every helicopter has that amount of usable fuel. The HUD's v_fuel01 weapon-like gauge reads the vehicle's corresponding resource. A native code census locates the fuel state on helicopters at +0x1690, one bike at +0x29B0, and another at +0x2B00 in the examined build.

Recoil is partly a seat property

A vehicle's gun seat can contain a BodyRecoil or AimRecoil object; the original weapon's SGO FireRecoil is a separate signal. The source characterizes BodyRecoil as push/sway parameters attached to that gun seat, rather than only to its bullet. This matters when comparing a player-summoned vehicle with the NPC mission version.

Concrete native-data comparisons include:

Family Player-facing recoil NPC/mission recoil
Epsilon 403 BodyRecoil [0.1, 0.05] AI [0, 0.05]
Blacker 505 [0.1, 1] AI/mission [0, 2]
Nickelinger 402 [0.025, 0.1] AI [0, 0]

These values come from the source investigator's Root.cpk read, not fresh gameplay measurement. They illustrate why the same vehicle family can appear steadier when driven by mission AI than when used by a player.

Scope

The gear/fuel/recoil details are static code and source-data analysis, largely credited to hajisensai/All Forces. Civilian-car input uses the seat's steering/throttle rather than a universal weapon aim; this was separately reported tested in-game. No handling performance benchmarks were run for this release.

EDF5 Decals, Destructible Map Objects and Debris

EDF 5Community Knowledge HubMaps
Technical reference · Editorial synthesis of contributor static/game observations; per-claim grades below

Overview

Decals and shattered map objects have related visual effects but separate ownership and lifecycle rules. Modifying a decal lifetime alone does not stop its eviction by overlap or manager budget.

Format, API or behavior

DecalBase tracks age, lifetime, strength and undrawn duration; spawners register decals with a manager that may evict them. The report records an in-game overlap case where bullet marks removed longer-lived blood marks. Map destructibles run a separate shared base destruction sequence and may instantiate debris or named effects.

DecalBase fields: +0x138 dead byte, +0x139 drawn-this-frame byte, +0x13C seconds undrawn, +0x140 age, +0x144 lifetime (seconds; every spawner passes 20.0), +0x148 age/lifetime, +0x14C strength (removal rank factor), +0x1E0.. shader parameter blocks, +0x20C dissolve (= 1 - fade value, written each frame), +0x310 bounds (oriented box data used by the overlap test 19F220 -> 5BF340). Fade value: +0x344 (Splash), +0x340 (SplashProjection); BulletMark and ExplosionMarks keep theirs elsewhere (see their update functions 19DA60, 19EF30).

Decal life cycle — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (610 characters)

A spawner builds an InitParam struct (vtable at its start; lifetime at +0x28, strength at +0x2C); the constructor copies it, and every constructor ends with RegisterDecal 1A23E0 (this = decal), which calls the manager's eviction function 1A0860 and then links the decal. Per frame the type's update function runs (19E4E0 Splash, 1A45F0 SplashProjection, 19DA60 BulletMark, 19EF30 ExplosionMarks): age += dt; once age > lifetime the fade value is multiplied by 0.95 per frame until it is below 0.05, then 617B30 (kill) is called. The same functions delete a decal that went undrawn for more than 1.0 s (+0x13C).

Decal stacking in game — verified

The stacking rule erases decals in play: bullet marks erased long-lived wall blood, and fresh wall splats vanished during rifle fire until the stacking overlap limit was raised.

MapObject_FixedCrashModel (vtable E95F88) has no unique overrides beyond constructor and destructor; it relies entirely on MapObject_Base's shared logic.

Mapobject destroy effect spawn — static

This detailed research record is also present in the linked source appendix. Read the original source and evidence context; the literal duplicate is preserved below for comparison.

Full duplicated research record — expand (512 characters)

A function at E55CD (reached from the destroy-sequence area) computes a world-space position by weighted-row matrix math, packs it with the countdown timer value into a new struct, and resolves a two-stage, sequentially numbered resource name through 10D3F0 (looks like FindResourceByName): consistent with spawning a named visual or particle effect at the destruction point. Which class it spawns (ModelDebris or something else) was not confirmed; the thread was left open when session 1 turned to live logging.

Version notes and limitations

A map object that shares base class logic can still reference different asset resources. Tested decal stacking is limited to the contributor’s EDF5 case and must not be generalized to EDF6 without evidence.

EDF6 native Engine RE: 188 unpromoted address and field claims

EDF 6Engine RE & Networking
Technical reference · Exact build static evidence; not a gameplay runtime qualification

The R17 database distinguishes a semantic symbol from a discrete binary or structure-relative evidence claim. This reference contains the 188 claims where promoted_to_symbol=false. Some original status strings still contain PROMOTED_NEW; that is not an instruction to promote the address here. The explicit boolean is preserved and controls this separation. Where a record is BINARY_CONFIRMED, it may name one observed instruction/site within a function, not necessarily a safe function entry point. The complete original 330-row claim set (including separately promoted claims) is exported as reference/EDF6_R17_ADDRESS_CLAIMS_330.csv.

These static records belong to one evidence database (R17 source ZIP SHA-256 93419d55b395c9452e1b23fbccdb37baba3cdb9c4c63f71bac5e31e809e86784). The source includes older EDF5-related loot notes as relative offsets; their pseudo-VA must not be attributed to the EDF6 image. No new in-game test has been conducted. See the separate symbol atlas and structure field atlas.

Negative inference rules

A structure-relative field is not a process-relative address. A mid-function instruction site is not its function start. An exact site in one EDF.dll revision cannot be patched by copying its RVA to an unknown build. Raw source status labels are not proof of game-runtime effect. The source database describes research facts; no source or executable binary is distributed here.

Canonical binary-site findings, not function-symbol promotions

The 21 source records from edf6/native-site-claims.md crosswalk into the existing 184-site R17 table above. They combine exact instruction-local observations with proposed semantics. They are not all function entries, independently tested runtime changes or portable patch RVAs; field offsets below are relative to their named objects.

Reliable protocol DATA, ACK and dedupe-retire words

Parser sites 12CE2A9/12CE2BC/12CE2CA distinguish reliable DATA 0x1200, ACK 0x1300 and receiver-dedupe retire 0x1400. DATA goes to dedupe/ACK handler 12CFCD0; ACK removes a sender-pending ReliableInfo node at 12CE3C8, and retire removes the receiver marker at 12CE30F. DATA processing emits ACK with matching sequence at 12CFDC6 and touches a timestamped receiver entry at 12CFE16; the retained builder writes wrapper 0x401200 at 12D0B96. This identifies the native branch structure, not transport reliability under packet loss.

Reliable send retry schedule and failure flag

ReliableInfo starts with sent_once=0 (12D0D87) and first retry deadline from a 700 ms global (12D0DE0). Scheduler 12CEF24 compares elapsed ms with record +0x28, requeues the retained bytes at 12CF001, extends threshold by 1000 ms (12CF018) and raises ReliableMgr+0x98 when threshold exceeds 7000 ms (12CF03E/12CF047). Receiver dedupe markers age out after about 40 s (12CF153). Physical flush reads sequence at record +0x08, refreshes timestamp +0x30 and retains ownership in the sender-pending map (12D01C7–12D0205).

Unreliable packet path bypasses retained buffer

Mode-1 builder calls non-retained frame builder 12D1040 at 12C307D; direct Sandlot enqueue is at 12D122A, without reliable-retained wrapper. The unreliable wrapper invokes EOS_P2P_SendPacket at 12C90EC. These sites distinguish two submission lanes but do not prove delivery or a particular peer's transport order.

SceneObject receive pending flag and vtable sequence

Wrapper 72F057 hardcodes logical packet type 6; BulletManager mode 1 reads sender context +0x50 at 764816, unlike mode 0. SceneObjectReceiver sets pending byte 1 at 758010, clears it at 75807C before target gating, then invokes target NetworkObject vtable slot +0x20 (gate 7580AA), +0x90 (pre-apply 75810A) and +0x30 (ordinary-state apply 75811E). The pending flag is not itself evidence that the target accepted the update.

SceneObject constructor transform pointer site

Base constructor at 1189CAC loads transform from SceneObject::InitParam+0x08; generic creation writes the transform pointer to that field at 119429A. This is a structure-relative pointer location, not a global address and not evidence of a direct write to every derived object's world matrix.

Three NetworkBullet selector-enable bits

Selection is gated by bits in Bullet+0xE8C: spatial snapshot selector 0 uses 0x2 (22F2A9), external-contact/reference selector 1 0x1 (22F237) and selector 2 0x4 (22F1D0). Constructor 22EA7B initializes flags to 1; receive dispatch sets selector-2 bit at 22F6A8; MissileBullet02 adds bit 0x4 at 26C983 while SolidExpBullet01 clears inherited selector-1 bit at 28E3B8. Flags are availability predicates, not the packet payload layout itself.

Selector-1 local contact vectors and early return

Common bullet update activates external-contact context at 2327A8, writing local vectors Bullet+0xC20 and +0xC30 at 2328F6/232954. Receive sets active 2337ED and restores them 2338EA/2338F5; send tests flag +0xC00 at 233A04 and serializes at 233B02/233B17. Readers reconstruct a world-space normal from +0xC30 at 235BB1 and world anchor from +0xC20 at 236A71 (fallback 236B1E). While active, ordinary collision branch is bypassed at 2342D4 and integration returns early at 234A13.

Bullet collision history vector and reflection constant

Collision records are 0x50-byte entries in a vector at state +0x6C0. Producer 230CA0 appends full records (230F98) from collision branches 23403B/234210; helpers 236C30/2370D0 reserve and append. Motion response reads the final record's normal at +0x20 (23167A) and multiplies the dot product by −2.0 (2316CF) for reflection. Other local sites publish network to active position (2324C5), initialize/update replicated motion (231E04/234ADB) and integrate position (234B11).

Projectile seed stored in InitParam and BulletBase

BulletBase constructor selects complete object's replicated subobject +0x140 at 22EA3E, reads RNG from InitParam +0x1A0 (22EA5F) and zero-extends it into BulletBase+0x130 (22EA66). Common weapon projectile creation advances Weapon+0xBC8 once after spread (69773F/69775A) and stores an upper-derived value at created projectile +0x1A0 (69776D). This is the seed transport mechanism, not proof of identical remote random trajectories for every projectile family.

FlameBullet02 two RNG-derived motion scalars

Constructor reads final +0x130 state at 26102C, writes first RNG-derived scalar at +0x11D0 (261068), persists twice-advanced state (261085) and second scalar at +0x11D8 (2610B7). OnUpdate reads first scalar at 2622D4, accumulates second into phase at 2622F3, and writes replicated motion/direction at +0xCD0 (262412). These are offsets within this subclass's state, not generally shared flame-weapon config.

SolidExpBullet01 random countdown and BlowHit creation

SolidExpBullet01 constructor advances +0x130 RNG (28E015/28E026) and stores a random countdown integer at +0xF00 (28E05D). Update reads and decrements it (28F3B0/28F3B9), calling detonation at expiry (28F3C6). Helper builds BlowHit01::InitParam (28E9E7), copies projectile position (28EA61) and requests SceneObject creation (28EA9A). Countdown is a class-specific source field, not a general explosion lifetime.

Charge and pre-charge pending versus committed sync fields

Charge receive writes pending scalar +0x1A70 (69C0D9) and auxiliary +0x1A74 (69C10D); vtable slot 34 snapshots normalized local scalar to committed +0x1A68 (69C4F8) and derived +0xBE8 into committed +0x1A6C (69C4E6). Pre-charge receive writes pending +0x17D4 (6A7817) and slot 34 commits +0xBE8 to +0x17D0 (6A7916). Both accepted committed-state paths recompute through 6967C0. The pending write precedes the acceptance gate and cannot be treated as fully applied charge state.

Soldier named-node matrices feed weapon descriptor

575820 refreshes named-node hierarchy world matrices. SoldierBase update calls it at 59AC29 before a weapon descriptor stores the same owner hierarchy at 58F558, from which weapon source-node lookup 68AF9E later reads. This is an ownership/transform link, not proof that a weapon refreshes every node every render frame.

WSLRF evaluator calls and common weapon recomputation

WSLRF expression evaluation computes AmmoCount (68C53B → Weapon+0x248), ReloadTime (68C9C0 → +0x20C), FireCount (68CDC2 → +0x368) and FireInterval (68CE19 → +0x36C) with half-away-from-zero rounding; FireAccuracy (68CF16 → +0x378) retains float. Common recompute 6967C0 writes effective FireCount +0x368, damage +0x89C, size +0x8C0, speed +0x894, explosion +0x8B0 and accuracy +0x378 (sites 69684B–696938). These are derived fields, not independent binary-source defaults.

Per-shot transform and burst counter staging

Direction mode defaults 0 (68B8BB), switches to 1 for positive parsed fire_model_direction (68B8D7) and is read from a shot entry's +0xE0 by composer 696B70. Fire setup stores max(FireBurstCount−1,0) to Weapon+0xE18 (690C75), decremented on common update (6940E1). The owner named-node descriptor supplies primary source position (68AF9E), local direct-fire refreshes selected entry (690D1C) and final spread-transform output begins at 691B51. The state is per-shot and per-burst, not a global skeleton offset.

VehicleSwingShoot installs matrix override per shot

Active VehicleSwingShoot callback computes swing progress from remaining burst over FireBurstCount (6B40D0); activation snapshots source transform and installs progress 0 (6B4161). Installer iterates Weapon+0x1E0 entries (6B4242), finds each at base Weapon+0x1D0 with index×0xF0 stride (6B4273) and writes override matrix to entry +0xD0 (6B428E). This is a runtime transform override layered on per-shot storage.

Weapon local LCG state initialization and advances

Weapon constructor sets provisional seed 0x7B9 at Weapon+0xBC8 (68AAB5), advances process-global LCG EDF+0x1F54128 (68ADB6) and stores upper-derived live seed (68ADE4). Update unconditionally advances once each tick (693565/693576); spread types 3 and 1 advance once for random spread (6916FF/691721, 6917F7/691819). Those sites determine sequence consumption; without reproducing the same branch history a replay can diverge even if the initial seed matches.

Selector-0 packet seed optionality and policy bit

Receive tests local fire-policy bit 3 (0x08) at 6929FD and, when active, writes the serialized 64-bit seed into Weapon+0xBC8 before creating projectiles (692A0B). Direct subtype-0 send checks the same bit (694C7F) and reads seed at 694C86; direct fire derives a lower selector from policy bit 0 (6949AF). The common selector-0 builder instead clears its optional-seed flag (6954CF), making that branch inactive (695501); Gatling class/auxiliary senders also clear it before 6952D0. Seed transport is conditional, not a universal field sent in every weapon packet.

Subtype-1 stale gate and non-retained submission

Subtype-1 receive reads current cumulative fire counter at 690460, rejects incoming value only if strictly below current (signed check 690468), and commits via weapon vtable slot 33 at 690546. Sender clears six-update delay (695F4B) and dirty flag (695F55) before non-retained frame submission; the batched variant calls owner NetworkObject vtable slot 14 with send boolean 1 (695FEA). A repeated same-counter value passes the gate; lack of retained retry here should not be confused with reliable packet ACK behavior elsewhere.

Two VFX submit sites and non-function humanoid range

1154F70 and 1155810 are lower VFX submission helpers whose renderer-specific roles differ; the cited hook study rejected moving interpolation there without a deeper lifetime contract. 47143A–471683 is the examined region iterating ready child objects of a generic humanoid, but 47143A is an instruction-range anchor, not a proved function start. These locations belong in a binary-site ledger, not a symbol-name table.

LightningBullet constructor and per-tick randomized path

Constructor sends Bullet+0x130 into randomized-vector wrapper (25A733), stores initial path state +0x1160 (25A80E) and calls common replicated motion updater (25A81F; embedded +0xB90, whole-bullet +0xCD0). Each tick repeats wrapper (25B121), advances and stores state +0x130 (25B132/25B143), writes path position Bullet+0x90 (25B38C) and commits delta through 235540 at 25B3D4. No inference about a platform-independent RNG implementation is made.

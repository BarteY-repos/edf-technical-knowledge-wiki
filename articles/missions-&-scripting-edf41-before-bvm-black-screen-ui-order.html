EDF4.1 BEFORE.BVM scenes in EDF6 — why the dialogue plays behind a black screen

ConversionMissions & ScriptingScriptingEDF 4.1EDF 6
Technical reference · Exact-build UI script ordering and native audit; no fresh game test

The failure can be UI lifecycle, not missing scene data

EDF4.1 has source pre-mission BEFORE.BVM cutscenes. The examined EDF6 mission flow can load such a file using its native Before() function and correctly pause the main mission script until the scene finishes. But because ordinary EDF5/EDF6 missions in the investigated corpus did not ship before.bvm, the game's normal UI lifetime was never exercised along that branch.

EDF6's main script leaves the headquarters menu and its black fade UI active when it enters PlayMission_Offline. The function calls Before() before PlayMission_Common, and it is PlayMission_Common that eventually calls DeleteAllMenuUi(). When a source EDF4.1 BEFORE.BVM exists, the cutscene can play entirely beneath the black menu fade. The user hears the voices and sees subtitles or radio indicators drawn above the fade, but cannot see the scene.

This is not evidence that the BVM script, RMPA, camera tracks or model resources failed to load.

The original source lifetime was different

EDF4.1's own main-script path closed HQ UI and deleted the fade before returning to the offline mission loader, so its pre-mission scene ran with no menu covering it. The semantic repair in the studied EDF6 build performs the relevant native _DeleteAllMenuUi operation only on the control path where Before() has successfully found a scene and is about to load its BVM.

That is more precise than moving all menu deletion earlier globally:

  1. The game checks whether the mission has a before.bvm and whether save state permits playing it.
  2. Only on the actual scene-loading path does the compatibility code close menu UI groups and the black fade.
  3. The native BVM executor loads the scene as before and suspends the main script while it plays.
  4. The ordinary PlayMission_Common menu cleanup later runs safely against already-closed UI.
  5. Missions without a before scene never enter the correction path.

In the studied native implementation, _DeleteAllMenuUi closes UI groups 2, 4 and 3. The hook is guarded by exact instruction bytes and the expected EDF.dll build timestamp. Copying its numeric offsets to another executable would not be sound.

How to diagnose a black BEFORE scene

  • Confirm the file is really BEFORE.BVM and the native Before() branch runs.
  • Check if voice/subtitles continue while geometry stays black; that is compatible with a still-active UI fade.
  • Inspect UI teardown ordering, not solely BVM parser and camera tracks.
  • Verify the normal no-BEFORE mission path remains unchanged.
  • Qualify with save-state logic, because Before() can intentionally skip a scene already marked seen.

Evidence boundary: This is a source-backed exact-build cause and implementation, with a native code-signature audit. This wiki pass did not replay the full EDF4.1 before-scene set or run a fresh EDF6 game test.

Source: EDF4.1 R10 HF4 R9 components/compatibility/src/edf41before.cpp plus source/main-script analysis cited in its comments.

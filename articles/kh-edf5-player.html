Observations

Ranger sprint held-button state

Evidence: static · Build: steam-5d11de53 · Fact ID: ranger-sprint-state

Ranger (AssultSoldier, vtable EAD048) sprint: the held-button state is copied into the byte [rsi+0xB5C] at 2ED3A3 (mov [rsi+0xB5C],al; [rsi+0xB5B] is set alongside by the patch), and [rsi+0x1A40] is nonzero while actually sprinting. metoxys's RangerToggleSprint turns the hold into a toggle there, for Rangers only (vtable check), resetting when the game stops the sprint itself.

Basis: the patch's anchor and code (the vtable is a fixed address in the patch)

Addresses (build-specific RVAs unless indicated): EAD048, 2ED3A3

Attribution: metoxys (RangerToggleSprint), novae (ajane)'s EDF5 outside set · 2026-10-16

Riding soldier seat and vehicle weak pointers

Evidence: verified · Build: steam-5d11de53 · Fact ID: ride-link-fields

A soldier keeps the vehicle it rides as a weak pointer: seat record +0x1160, vehicle object +0x1168, control block +0x1170 (riding while the control block is non-null and [ctrl+8] != 0). Set at 2F5021 from the vehicle's shared pointer (the seat record from 3560D0(vehicle, soldier, ...)), cleared together at 2EFCEA (+0x2B0 also zeroed); the riding update 2F2B3A locks it and leaves when the vehicle's HP +0x1FC <= 0; the camera tests the same control block (9EF8B, 9FFDC). Only the 7 soldier classes have the field (vtables EAD048, EAD420, EADAE8, EAE8A0, EAF0B8, EAF478, EB00C0).

Basis: static; novae (ajane)

Addresses (build-specific RVAs unless indicated): 2F5021, 2EFCEA, 2F2B3A, 3560D0, 9EF8B, 9FFDC

Attribution: novae (ajane) · 2026-10-07

Armor (KH chat 83, 2026-11-10)

Armor maximum HP from boxes and class growth

Evidence: static · Build: steam-5d11de53 · Fact ID: armor-hp-per-box

A soldier's armor (max HP) = base + armor boxes x per box, the pair being DEFAULTPACKAGE/CONFIG.SGO SoldierInit[class][3] = [base, per box]: Ranger 200 / 0.64, Wing Diver 150 / 0.4, Air Raider 200 / 0.64, Fencer 250 / 0.8. The code at 312026 reads the player's box count (#armor-box-counts), converts it to float, multiplies by the row's second value and adds the first; the row is reached through [[125AB30]+0xF8] (the SoldierInit table in memory, rows by class). The EDF5 JP wiki's class pages give the same per-box values (アーマー1個あたりの上昇値: 0.64, 0.4, 0.64, 0.8).

Basis: fn.py 312026; config.sgo read from Root.cpk; atwiki edf5 pages 39, 54, 62, 69 (saved 2026-11-08)

Addresses (build-specific RVAs unless indicated): 312026, 125AB30

Attribution: KH chat 83 (curator) · 2026-11-10

Per-class earned armor box counts in save

Evidence: static · Build: steam-5d11de53 · Fact ID: armor-box-counts

Armor box counts in the save object [125AB30]: +0x6D24 + class*4 the boxes the class has earned (the loot commit 199D50 adds each award, drop-items.md#loot-roll-class-share); +0x6E44 + player*0x3E60 + class*4 each local player's count, which 199D50 raises by the same award but caps at the class total, and only while the player's limit byte +0x6D00 + player*10 + class is 0. The armor-limit editor (built by 508810) writes the pair: PressButtonMax (5099F0) byte 0 and the count set to the slider maximum, PressButtonMin (509A60) byte 1 and count 0 (base armor), PressButtonValue (509B40) byte 1 and the chosen count. So a limited soldier's armor stays fixed as boxes come in; an unlimited one follows the class total.

Basis: fn.py 199D50, 5099F0-509BA0, the menu's --str keys

Addresses (build-specific RVAs unless indicated): 199D50, 199E1B, 508810, 5099F0, 509A60, 509B40

Attribution: KH chat 83 (curator) · 2026-11-10

Evidence: static · Build: steam-5d11de53 · Fact ID: local-player-chain

Eiton's plugin finds the local player as [[[[125AB68]+0x238]+0x290]+0x10] every frame (zero while there is none, e.g. outside a mission) and tests [player+0x1168] != 0 for "in a vehicle" (ride-link-fields). 125AB68 is the global of globals.md#global-havok-world.

Live EDF5 player chain

Ranger object: in-game pointer and measured fields

Evidence: verified (source-reported memory reads) · Build: steam-5d11de53 · Fact ID: edf5-local-player-chain-in-game.

In the source's running Easy M1 mission, [[[[125AB68]+0x238]+0x290]+0x10] resolved to the local soldier. Its first qword was EDF5.exe+EAD048 (the Ranger AssultSoldier vtable, inheriting SoldierBase, HumanBase and GameObjectBase). Floats at +0x1F8 and +0x1FC both read 200, matching HUD Armor, and position at +0xA0/+0xA4/+0xA8 read 173.3218, 0.0495733, 109.8735. The record does not establish experimentally which of the two 200-valued fields is current versus maximum health; the claim remains inferred from pickup/death code paths.

Basis: source's game-memory peek and class RTTI/vtable lookup.

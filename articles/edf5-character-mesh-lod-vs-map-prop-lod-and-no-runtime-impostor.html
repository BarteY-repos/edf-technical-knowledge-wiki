EDF5 LOD systems: animated mesh, map-prop files, texture streaming and no live character impostors

EDF 5Game technical referencesRendering / LOD
Technical reference · Source analysis only (unless a source fact is contributor-verified); no new EDF runtime test

EDF5 distinguishes animated-mesh LOD, map-prop mesh LOD, texture .lod.dds streaming and offline/dev impostor capture. Their formats and selection mechanisms differ.

Animated characters: the AnimationModel draw chooses full detail first, then walks 0xF0-byte LOD records using per-record thresholds. These source distance thresholds are squared at load, then compared against the renderer's squared camera-distance metric. The source did not find a direct FOV, display resolution or graphics-quality factor in this specific mesh-LOD selector. The Umbra distance field includes a commander-owned multiplier whose writer was not established, so no universal world-meter conversion follows.

Map props: MapRenderer selects separate LOD render units using distance ranges stored on the units. The source resolves _lod, _lod2, _lod3 suffixes as meshes inside the corresponding RAB archive. This is a different pipeline from changing the animation-update frequency of a living enemy.

Texture .lod.dds: this name describes texture streaming and does not itself mean a mesh has changed LOD. FarClipZ is a camera far-plane value, not the animated-model LOD threshold.

Character impostors: classes called LODModelObject, LODsgmUmbraObject and LODCaptureCamera are associated with the developer lod_capture operation, not with observed live character rendering. The source found runtime billboards for vegetation, not an equivalent generic character impostor stream. This is a bounded constructor/call-site finding; it does not prove no other visual trick exists anywhere in the engine.

Source: edf5/models.md, animationmodel-lod-select, umbra-object-distance-metric, map-prop-lod, no-runtime-impostor, lod-lookalikes. No new gameplay capture.

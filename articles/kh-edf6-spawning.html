Facts

Player-creation script native thunks

Evidence: static · Build: steam-678ccb46 · Fact ID: createplayer-thunks

The three mission-script natives that create the player are tiny thunks at 1B21E0, 1B21F0 and 1B2200, each setting the third argument (r8d) and jumping to MissionScript_CreatePlayer_Impl (1BCC50): CreatePlayer (xor r8d,r8d, mode 0), CreatePlayer_InitWeapon (mov r8d,2, mode 2) and CreatePlayer_NoWeapon (mov r8d,1, mode 1; the author: used for example by the first mission). Redirecting the three jmp rel32 operands (1B21E4, 1B21F7, 1B2207) to a wrapper that calls 1BCC50 first covers every way a mission can create the player.

Basis: bytes 45 33 C0 E9 68 AA 00 00, 41 B8 02 00 00 00 E9 55 AA 00 00, 41 B8 01 00 00 00 E9 45 AA 00 00 decoded: each rel32 resolves to 1BCC50

Addresses (build-specific RVAs unless indicated): 1B21E0, 1B21F0, 1B2200, 1BCC50

Attribution: FevGrave (NpcSquadOnSpawn_EDF6) · 2026-10-21

MS_CreateFriendSquad entry point

Evidence: static · Build: steam-678ccb46 · Fact ID: createfriendsquad-call

MS_CreateFriendSquad is the function at 1B08D0 (prologue 48 8B C4 55 53 56 57 41 55 41 56 41 57 48 8D A8 38 FE FF FF 48 81 EC 90). The wrapper calls it with: rcx = the native's first argument (script context), rdx = pointer to a local that receives the squad handle, r8 = the point-name argument the mission gave CreatePlayer (the squad appears around the player's start point from Mission.rmpa), xmm3 = radius (f32), stack [rsp+20] = pointer to the leader's std::wstring (an object path), [rsp+28] = pointer to the member std::wstring, [rsp+30] = member count (s32), [rsp+38] = hit-point multiplier (f32), [rsp+40] = follow flag (u8, 1 = recruited, follows the player). The author notes the returned handle is never released: one reference per squad per mission, harmless.

Basis: wrapper bytes at NpcCode+8A..BE decoded (movss xmm3,[r13+40h], stores to [rsp+20..40], call at +BA patched to FSquad); the argument meanings are the author's

Addresses (build-specific RVAs unless indicated): 1B08D0

Attribution: FevGrave (NpcSquadOnSpawn_EDF6) · 2026-10-21

Object paths for friendly AI are UTF-16 strings of the form app:/Object/NAME.sgo

Evidence: static · Build: steam-678ccb46 · Fact ID: friendly-ai-path-wstring

Object paths for friendly AI are UTF-16 strings of the form app:/Object/<NAME>.sgo; the std::wstring the function takes has the MSVC layout: 16 bytes of buffer or pointer, size at +0x10, capacity at +0x18. The patch stores size = the character count without the terminator (39 = 0x27 for app:/Object/AIARMYSOLDIER_AF_LEADER.sgo, checked by hand) and capacity 0x7F (above the small-string limit, so the first 8 bytes are read as a pointer; the wrapper writes the pointer to the text at run time).

Basis: the patch's data lines and wrapper bytes (lea rax,[r13+50h] / mov [r13+0],rax, and +C0 for the member)

Attribution: FevGrave (NpcSquadOnSpawn_EDF6) · 2026-10-21

The wrapper skips the squads when a flag reached through g_pGameDataMgr (20B2890, globals.md

Evidence: static · Build: steam-678ccb46 · Fact ID: friendly-squad-online-gate

The wrapper skips the squads when a flag reached through g_pGameDataMgr ([20B2890], globals.md; then [mgr+0x38] as an index into the array at [mgr+0x20], then a dword at +0x68 of the structure at [...+0x10] indexed by [+8]) is set; the author calls this "online session" and says the skip was confirmed (OFFLINE_ONLY=1). The hub did not trace which flag it is. Chain as decoded: idx = [mgr+0x38] (skip if -1), s = [[[mgr+0x20] + idx*8] + 0x10], test the dword at s + (int)[s+8] + 0x68.

Basis: wrapper bytes NpcCode+22..4F; meaning is the author's

Addresses (build-specific RVAs unless indicated): 20B2890

Attribution: FevGrave (NpcSquadOnSpawn_EDF6) · 2026-10-21

Friendly AI stock object resource inventory

EDF Knowledge Hub record — original wording — expand (1,221 characters)

The game ships 45 friendly-AI object files under Root\OBJECT (the author's list, each with class, hit points 200 and weapon names): AIARMYSOLDIER_* (16, Ranger: AF rifle, FL flamethrower, RL rocket launcher, SG shotgun, SN sniper, each with a _LEADER; S_AF_LEADER, S_FOLLOWER1..3, S_OMG_LEADER and S_OMG_SRANGE_LEADER), AIHEAVYARMOR_* (11, Fencer: GD, SC, SMC, SP, SSG, each with a _LEADER, plus SP_MOBLEADER), AIPALEWING_* (17, Wing Diver: IZN, LANCE, LR, MS, TB, each with a _LEADER, and the ELITE_ IZN, LANCE, LR, MS variants) and AISECURITYGUARD (no weapon). Root.cpk has no Air Raider AI template (all 56 N60* files listed by hajisensai, All Forces docs/feedback-2026-10-09c-bar.md, 2026-11-07); the Wing Diver templates use class PaleWing with EDF6_wingDiver.cas, the Fencer ones HeavyArmor with EDF6HeavyArmor.cas. Weapon object names used: AiSoldierRifle01, AiSoldierFlameThrower01, AiSoldierRocketLauncher01, AiSoldierSniperRifle02, AiSoldierShotgun01, AiSoldierLaserRifle02 (and _SRange), AiHeavyDash01, AiHeavyHammer01, AiHeavyShield01 (Elite), AiHeavyCannon01, AiHeabyMiddleCannon01 (spelled so in the game), AiHeavyPileBanker01, AiHeavyShotGUN01, AiIZNR01/02, AiLaserLance01, AiLAZR01/02, AiMNS01, AiTB01/02.

Basis: the list in the patch file (from the author's Ghidra session), 45 entries counted by the hub; the file names were not checked against Root.cpk

Attribution: FevGrave (NpcSquadOnSpawn_EDF6) · 2026-10-21

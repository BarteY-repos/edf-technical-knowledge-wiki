EDF6 achievement variables, events and TROPHY.DAT save structure

EDF 6Game technical referencesProgress and statistics
Technical reference · Source-scoped static analysis with contributor runtime marked; no new R129 game test

The examined EDF6 build does not save achievements by writing a free-form list of names and values. Its original APP:/ETC/Achievement.sgo declares the available variables and events, then the game loads values and unlock states into a fixed binary TROPHY.DAT representation. The save uses ordered values, not per-entry textual names.

Achievement.sgo defines what can be counted

The SGO includes two collections, AchievementVariable and AchievementEvent. Each variable is identified by a name, type (INT or FLOAT) and initial value. The original source census contains 91 variables and 39 event definitions. Only names present in the loaded registry can be incremented or read successfully; an arbitrary kill-counter name does not automatically create a new slot.

An event has a name, comparison operator (==, !=, >, <, >=, <=) and numeric threshold. The unlocked state is kept separately for the Steam and Epic integration paths. The event checker traverses events associated with a variable whenever its value changes and, where appropriate, invokes the native platform-specific unlock routines.

Runtime in-memory store

The store contains a std::map<std::wstring, variable> and an event array. A variable node carries a key, a type code (0 integer, 1 float), its current value and indexes of events watching it. A lookup of an unknown variable returns the map's head/sentinel node, not an automatically inserted zero-valued counter.

TROPHY.DAT serialization

Byte region Native meaning in the studied build
First 0xC8 (200) bytes Event-unlock bytes, padded with zeros
Next 200 × 4 bytes Variable values, ordered by UTF-16 variable name
Total 0x3F0 (1008) bytes Fixed record buffer used by save/load

On load, the engine reconstructs the registry from the SGO and reads values in that same name order; the file itself does not contain the names. This means changing variable names or their sort order changes how the stored numbers are interpreted. The researcher also identified no count bound when writing additional variable entries beyond the expected 200: that is a format hazard, not a supported way to extend the game.

Scope

This is a build-specific description (steam-678ccb46), not a prescription to modify player saves. No R127 game save was opened or written, and the identified overflow path was not tested as a live crash.

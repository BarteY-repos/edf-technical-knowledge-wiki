What these files are (and are not)

The retained paired source bundle Files.zip contains 517 .BAT files under EDF5/BAT/ and EDF6/BAT/. These are game-side diagnostic scene-command files with instructions such as preview_mode, end_scene, map_no_camera, enemy, friend_squad, player, and db_activate. They are not ordinary Windows batch scripts. The archive is a retained source snapshot of original-game files; this inventory does not independently certify whether every entry ships unchanged in all retail distributions or whether every debug command is active in a public build.

Evidence: direct byte audit and command-token census of archive Files.zip, SHA-256 2ee525f94fc991105d701fdbddaddb5f4bcbd8ec60649d93019a2f650dae6c8a. Scripts were parsed as text only; none were executed in EDF5 or EDF6, and no game binaries or original scenario scripts are bundled into this public wiki. Archive entry SHA-256 and derived metadata are available in the data/EDF5_EDF6_R152_NATIVE_FILES_590_METADATA.csv source index included in the release ZIP.

Script text, directive vocabulary and native test setup

  • Decoded 226 UTF-16LE BOM .BAT scripts, 289 UTF-8/ASCII scripts and 2 CP932-fallback scripts across EDF5/6. The UTF-16LE variant can contain Japanese rem @name, rem @group, rem @note metadata. Those comment tags are not executed scene commands.
  • The 517 scripts contain 4,271 active non-comment command lines, with 55 distinct first-token directive names. Several tokens are debug-only, so these are observed syntax tokens, not a verified public runtime API.
  • The prominent patterns are end_scene and map_no_camera to select test environment, enemy / enemy_group / friend / friend_squad / vehicle / object to request entities, player / set_player_soldier / weapon_reload to prepare a player, and object_team / set_generator / object_action to configure selected cases. The exact argument parser and acceptance of arbitrary values were not independently disassembled here.
  • Debug-only free_camera, ghost_camera, preview_mode, disp_ai_world and NAVMESH fixtures are not evidence of a user-facing retail photo mode. A debug camera or test launcher is a different interface from a player-selectable photography feature.

EDF5 ↔ EDF6 exact same-name reconciliation

There are 161 file basenames present in both games. Across those pairs:

Comparison Pairs
Exact same source bytes and SHA-256 149
Same active command lines after whitespace, comment and case-normalization of command token (including the 149) 152
Different active scene-command content 9
EDF5-only scenario basenames 29
EDF6-only scenario basenames 166

Byte-level difference is not automatically a semantic difference: scripts may differ only in UTF-16/UTF-8 encoding, comments and annotations. Likewise, active command identity does not prove the respective game engines execute them equivalently; handlers, default values and referenced SGOs may differ across generations. Files are paired by identical basename only, not by enemy model name, class or mission.

E507_GOLDUFO_AI.BAT and GIANTSPIDER01_AI.BAT are particularly useful examples of test-fixture authoring changes. A many-line list of enemy spawns in EDF5 becomes a compact grouped-spawn command in EDF6. This does not establish changed AI pathfinding, actual population limits, animation controls, or spawning equivalence in gameplay. For that, test the same entities under comparable engine builds and maps.

EDF5 has direct diagnostic setup names for the older Hector301 / Hector401, DragonBig401, and Vehicle402/403/404 variants, whereas the sampled EDF6 BAT tree has many E602_BERSERKER_*, E601_MARTIAN_* and new V6* cases. This is source-file coverage, not proof that the corresponding EDF4.1/EDF5 enemies or vehicles were removed from the shipped EDF6 engine.

Practical use in AI, collision and animation research

A BAT test entry can specify the same test map, placement and SGO identity, giving concrete repeatable scene inputs for later investigation. Examples:

  • NAVMESH_TEST.BAT under both trees has identical source bytes in the retained archive and references ig_sangaku506; that is valuable scene provenance, not evidence of same navmesh or AI result in both games.
  • DRAGONSMALL401_AI.BAT is an identical paired debug request for a group of DragonSmall401.sgo enemies; it does not directly expose the embedded CAS/CANM motion keys or DragonBig roar-event MAB.
  • EDF6_NPC_AI.BAT references EDF6-friendly NPC SGO identities (n601_common_ranger_af.sgo, n602_professor_af.sgo, n603_colonel_af.sgo). These names help locate candidate object/controller research, but do not imply those actors share the same animations or recruitment state machine.
  • COLLISION_MATERIAL_TEST.BAT appears only in the EDF6 tree in this archive and explicitly describes a test of walking-material audio. That is an intent recorded in source comments, not a new in-game sound-material acceptance result.

Evidence boundaries and outstanding work

Confirmed: file inventory, bytes/encoding, active tokens, command counts, per-file references, same-name comparisons and source metadata. Not confirmed: in-game execution, debug commands in stock builds, arguments' exact engine handler semantics, reliable equivalence between paired entity assets, CAS/CANM channel data, MAB event tracks, NPC pathfinding or multiplayer outcomes. An original retail photo mode must not be inferred from ghost_camera.

See native CAS/CANM structure and conversion, NPC CAS/MRAB dependency graph, EDF5 NPC targeting gates, EDF6 walk controller, and debug camera evidence. These are different evidence families and must not be collapsed into one claim.

EDF6: seven source-record routes into the paired BAT audit

The seven edf6/bat-debug-scenario-files.md records below attach exact source identities to the pre-existing retained-archive audit. All counts refer to the static snapshot described above, not a tested executable command interface or retail feature.

EDF6-specific inventory and file-family boundary

EDF6 has 366 non-directory files: 327 BAT/*.BAT scenario scripts, 33 locale-specific NETWORK/*.SGO files, and 6 MAINSCRIPT/ files including MAINSCRIPT.AS and headers. The two games together contribute 517 BAT scripts (EDF5 190 + EDF6 327). Merely inventorying the main-script files does not establish that any specific test scene executes their contents.

EDF6 directive line frequency

The exact paired command census includes EDF6 line counts: enemy 428, db_activate 287, end_scene 279, map_no_camera 236, preview_mode 183, player 177, object and object_team 136 each, set_player_control 100, ghost_camera 92, weapon_reload 66, vehicle and enemy_group 47 each, set_generator 44, build_test_scene 30, friend and mission 29 each, set_invincible 23, set_player_soldier 22, friend_squad 21, and object_action 19. These are line counts, not distinct script counts or evidence of commands succeeding at runtime.

EDF6-only tokens and cross-generation count differences

Only the sampled EDF6 BAT tree uses begin_scene (2 lines), hui_dbg_chg_mesh_grp (3), db_console_filter (1, F6.BAT) and hui_disp_wire (1). free_all_resource occurs 6 times versus 1 in EDF5, main_script 3 versus 1, and mission 29 versus 5. In the other direction, set_object_path (5) appears only in EDF5's sampled scripts. Exclusivity is limited to the analyzed archive, not all possible engine builds.

Debug camera fixture is not a player photo mode

EDF6 BAT files contain ghost_camera on 92 lines, free_camera on 3, preview_mode on 183, and disp_ai_world on 2. This establishes test-fixture command tokens only; it does not document a player-selectable photo mode. See the separate camera evidence comparison and the Knowledge Hub's edf6/pause-free-camera-post.md#edf6-photo-mode-route boundary for paused-camera research.

Paired basenames and exact-versus-active equivalence

Pairing by basename only, the two trees share 161 BAT filenames: 149 have byte-identical content, 152 have the same active commands after whitespace/comment/token-case normalization, and 9 differ in active commands. Another 29 basenames appear only in EDF5 and 166 only in EDF6. The normalized 152 include the byte-identical 149; the figures are not disjoint categories and say nothing about equivalent engine behavior.

Nine differing same-name test fixtures

The nine-row comparison specifies: E503_FROG_AIMTEST changes actor/object SGOs (10 lines each); E507_GOLDUFO_AI and GIANTSPIDER01_AI replace many explicit enemies (55 and 45 lines respectively) with six-line enemy_group scenes; E509_DEIROI_ALL_AI (11 versus 11) uses build_test_scene; E510_FORTRESS_AI grows 6 to 8 lines with a generator and SGO; F6 grows 3 to 4 with db_console_filter; PLAYER_SIMPLE grows 6 to 7 with begin_scene. GIANTANTQUEEN_AI (7 versus 6) and WATERAREATEST (5 versus 5) have differing arguments/scene details, without a supported finer gameplay interpretation here.

EDF6-only fixture names and source-comment intent

EDF6-only fixture families include E602_BERSERKER_*, E601_MARTIAN_* and newer V6* cases. EDF6_NPC_AI.BAT names n601_common_ranger_af.sgo, n602_professor_af.sgo and n603_colonel_af.sgo. EDF6-only COLLISION_MATERIAL_TEST.BAT has a comment describing walking-material audio testing. That comment records a test intent, not a passing walking-sound acceptance result.

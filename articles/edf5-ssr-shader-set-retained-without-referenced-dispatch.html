EDF5 has unused SSR shaders: Hi-Z ray march, resolve, blur and composite

EDF 5Game technical referencesRendering / DXBC
Technical reference · Source static evidence with unverified behavior labelled; no new in-game R132 test

The examined EDF5.exe contains a coherent group of shaders whose resource bindings fit a screen-space reflections (SSR) pipeline. These are not merely shaders with a word like reflection in their file name: the RDEF data identifies Hi-Z depth, intersection textures, a ray-march output, a resolve phase, blur phases and a final composite.

Detected stage Function of the retained shader
Hi-Z ray march Samples high/low depth (m_hi_z) and color (m_hi_color) and writes m_out_reflection; can fall back to m_cube_map_array
Resolve Combines intersection data and color into reflection
Two blur passes Blur reflection using source texture/depth and blur parameters
Reflection + color composite Combines m_reflection and m_color into output
Cubemap array pass Samples a texture array and cubemap parameters

The source supplies exact RVAs for these stages, including Hi-Z at 0x115AF80 and 0x115BFD0, resolve at 0x115AA80, blurs at 0x115FFA0/0x1161630, and composite at 0x11562F0 in the examined build. These are for identification only, not stable offsets across game builds.

Why “dormant” is the appropriate label

The researcher scanned all executable sections for recognized RIP-relative lea/mov references into the DXBC data and for absolute 8-byte pointers. Other live lighting shaders were referenced; the SSR block was not. This is strong evidence that the observed SSR suite is unreferenced by the identified native call paths, and is consistent with a cut feature. It does not rule out every possible computed/indirect reference and does not prove the suite can be enabled through an ordinary settings toggle.

EDF6's examined EDF.dll has no equivalent SSR binding family among its 490 DXBC blobs, while its local cubemap lighting remains. EDF5's normal reflective appearance should therefore not be attributed to a confirmed live SSR renderer simply because the EXE contains dormant shader bytes.

Evidence: static RDEF and executable reference census, no in-game SSR toggle test. Source edf5/shaders.md fact dormant-ssr-shaders, edf6/rendering.md fact lighting-cs-local-cubemaps.
